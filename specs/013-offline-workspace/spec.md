# 本地离线工作台

**Level**: full
**Status**: accepted
**Created**: 2026-11-24
**Decision**: Web 0.2.40 和桌面客户端 0.2.41 已能通过直接地址恢复少量缓存文档。用户确认新版从联网打开的文档开始收录，后端不可达时从首页「最近编辑」进入，并要求本地停机恢复验收通过后发布。浏览器持久格式、会话边界和制品发布采用 full 级别。

## Scope

桌面端使用内置前端，浏览器使用已经缓存的同源 Web 前端。已登录的账号可在停机时从首页「最近编辑」打开本地文档，也能直接访问文档地址。覆盖富文本、Markdown、表格、画板和演示文稿。新版联网打开并完成本地正文缓存的文档可进入目录。服务端生成的知识册、远程附件、评论和权限管理仍依赖后端。发布范围包括同一提交的 GitHub Release、Docker Hub amd64/arm64 镜像、macOS 与 Windows 桌面安装包。

## Acceptance

- **AC-001**: 在服务不可达时重启桌面工作台或重开已离线缓存的 Web 前端，首页「最近编辑」显示当前账号用新版联网打开并成功缓存的文档。可按文档或文库名称查找并打开。打开第 13 篇后，最早缓存的文档仍可打开。
- **AC-002**: 目录和文档直达地址都能打开现有正文副本。只读资源保持只读。可以编辑时，界面在编辑区附近提示离线编辑和恢复连接后自动同步。
- **AC-003**: 离线编辑在关闭或刷新后仍能恢复。重连重新检查授权和文档谱系，按原消息 ID 和字节同步，只有服务端持久确认后出队。联网时不重置编辑器或焦点。
- **AC-004**: 退出、换账号、会话拒绝或明确的资源拒绝会停止展示对应缓存。不同账号或站点不共享目录。旧数据采用单独批准的处理方式，原正文和待同步队列保留。
- **AC-005**: Web 应用壳离线缓存仅含构建的静态资源。服务端生命周期、文档权限和既有在线登录流程继续可用。
- **AC-006**: 本地隔离服务停机恢复验收通过后，从同一提交发布并验证 GitHub Release、Docker Hub 固定版本和 latest 多架构镜像、macOS 和 Windows 桌面安装包及校验文件。

## Architecture and contracts

Web 启动和文档加载位于 `apps/web/src/app/`。桌面 loopback 代理已能提供本地静态资源，远程故障时返回网关错误。文档正文继续由五种宿主适配器、`offline-replica.ts` 和原有 ACK 队列负责。见 [桌面端](../../docs/desktop-client.zh-CN.md)、[本地副本](../../docs/access-offline-events.md)和[协作契约](../../docs/collaboration-sdk-contract.zh-CN.md)。

## Compatibility decision

2026-11-24 用户明确选择只收录新版联网打开的文档。Web 0.2.40 和桌面 0.2.41 的 `doca.document-startup.v1` 原样留在设备上，新版从独立的会话键和目录数据库开始收录。旧版打开过的文档需使用新版联网再打开一次；已有 `doca-offline-v1` 正文、baseline、谱系和待同步消息继续由原协作协议管理。验证需使用带旧标题及正文的隔离浏览器数据，确认旧记录仍在，在线重开后才进入目录。

浏览器应用壳按构建生成。回退客户端前可结束新版会话并移除新版应用壳的 Service Worker 与 `doca-web-shell-v1-` 静态缓存，保留站点会话以外的目录记录、正文和待同步队列。新版目录与服务端数据库、资源 API、编辑器协议独立，常规发布无需数据迁移。
