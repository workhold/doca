## Scope

为 Doca 建立统一的变更流程，覆盖应用、公共包、脚本、测试和文档。采用与 LightMoni 相同版本的 GitHub Spec Kit，并按风险区分完整规格、简短规格和 PR 内记录。现有技术契约继续描述当前行为；存量模块通过索引接入，在后续真实变更中逐步补充规格。

本次交付仅涉及研发流程、工具和文档。应用运行路径、公开 API、数据库和用户存储格式均无变更。工作区已有的 MCP/AI 变更属于其他工作项，其验证与兼容决定不由本规格追认。

## Acceptance

- **AC-001**：仓库包含固定为 Spec Kit 1.0.4 的 Codex skills、共享脚本、模板和 MIT 许可证，来源与本地覆盖方式可查；新会话可从 AGENTS.md 找到流程入口。
- **AC-002**：完整、普通、轻量三类变更有明确适用条件及最小记录；数据库、权限、协同、SDK 和持久化格式变化使用完整流程，既有兼容性事先同意规则继续适用。
- **AC-003**：模块索引将现有主要模块关联到真实源码、权威契约及可复用检查，明确索引不构成重新验收。
- **AC-004**：规格、计划、任务和验收能够互相追溯；PR 模板记录级别、规格、架构/契约影响和验证范围。检查能够拒绝缺少必要资料及无效 PR 关联，并允许无需规格目录的轻量变更。
- **AC-005**：流程在本次变更中实际使用，工具路径及模板选择经隔离检查；文档链接、双语发布、现有契约副本和构建检查通过，原始报告仅保存在 artifacts/。
- **AC-006**：提供接下来 3–5 次真实变更的观察方式，记录调查成本、审查遗漏、返工和流程负担，不声称已经证明长期收益。

## Architecture and contracts

研发流程新增入口与检查，应用架构不受影响。权威文档、兼容决策和专项 skill 继续遵守 [AGENTS.md](../../AGENTS.md)。本次不新增在线设计副本或在线同步依赖。SDD 中的设计描述不代表接口已经导出，也不代表方案已获兼容性批准。

## Preservation and verification boundary

采用新增工具文件与流程记录，保留现有契约路径、历史设计、验收资料及其他未提交改动。工具升级需要比较上游版本和本地覆盖，重新验证后再更新；本次不建立旧工具配置的转换路径。验证使用 artifacts/ 下的隔离目录，不启动应用、不访问用户数据。
