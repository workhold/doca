# 0.2.30 发布计划

**Spec**: [spec.md](spec.md)

1. 核对全部差异、原对话同意记录及已发行基线，保留当前工作区所有受管改动。AC-001、AC-002。
2. 更新版本、Compose 和双语发行入口；GitHub 附件提供本次 SDK 编译包供旧插件重建，不额外向 npm 发布。AC-002、AC-005。
3. 运行全量本地检查及 MCP 专项验证；PR 运行 PostgreSQL 17/18 和 SDD/文档 CI，已发行 0.2.29 数据升级保持隔离。AC-003。
4. 功能分支提交全部候选并经 GitHub PR 合入。使用既有原生镜像 workflow 从合并提交构建/验收/发布两种架构，临时 registry secrets 通过受保护内存传递，发布后删除并复核。AC-001、AC-004。
5. 从同一提交推送不可变 tag，等待 GitHub 附件发布，独立下载验证；通过后续 PR 记录发布回执，不移动已发行 tag。AC-005。

不新增数据库演进策略、不转换历史数据；恢复边界遵守已获同意的合同。所有执行日志和下载放在 `artifacts/verification/release-0.2.30/`。

候选全量回归发现：图片批次升级的“其他运行执行器”检查误用了仅包含较早任务的来源读取范围，漏掉较晚启动的同会话执行器。发布前恢复按当前真实会话检查全部同会话执行器，独立任务仅绑定自身；沿用既有阻止升级与保留记录规则。另将跨会话拒绝断言对齐已批准的“执行范围”错误文本，并为本地 PDF 验证配置仓库要求的固定渲染依赖。
