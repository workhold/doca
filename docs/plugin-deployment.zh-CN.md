# 插件安装与部署

0.1.26 使用与核心库分开的[插件共享业务数据库](plugin-database-isolation.zh-CN.md)，自动创建插件命名空间，取代 0.1.25 的每插件独立库。升级须先在旧宿主正常卸载，再重装，不迁移插件数据。

[English](plugin-deployment.md)

已确认的[托管存储规范](plugin-horizontal-scaling.zh-CN.md)要求 `doca.storage: "host"`，持久化归宿主。静态拒绝、托管 SQL 与内部对象已实现；托管凭证已在 SDK 源码 0.1.8 实现；临时工作区与集群业务任务排空仍待实现。插件不选择本地/远端后端，也不接收业务数据目录。

管理员通过「管理 → 插件商店」浏览官方插件、上传本地 ZIP、安装、升级、启用、禁用和卸载。操作先保存为全站期望配置，每个实例重启后生效。页面分别显示全站目标版本与响应当前请求的实例运行版本，不代表全站所有实例均已更新。

```dotenv
DOCA_PLUGIN_STORE_URL=https://store.smartdoca.cc
DOCA_PLUGINS_DIR=/data/plugins
```

商店地址必须是 HTTP(S) origin，不带路径、查询参数或凭据。远端服务可用性需单独确认；连接失败不影响本地上传和已有插件。插件安装目录留空时使用 `${DOCA_DATA_DIR:-./data}/plugins`，相对路径基于工作目录。数据库和对象存储仅由宿主配置，不提供插件业务数据目录环境变量；插件 API 不暴露宿主存本地还是远端。

仓库的 Docker Compose 部署，在部署目录执行：

```sh
docker compose restart doca
```

这里的 `doca` 是 `compose.yaml` 中 `services` 下的服务名，容器名可能不同。若修改了服务名，请将命令中的 `doca` 替换为实际服务名。

多实例需逐个重启；其他部署使用对应进程管理器。页面不执行重启。滚动重启期间若插件 API 新旧版本不兼容，应摘除流量或使用会话亲和，不承诺跨版本零停机。

## 已实现存储修订（2026-10-03，SDK 源码 0.1.8）

`@smartdoca/plugin-sdk/storage` 已导出安装身份绑定的 `pluginDatabaseToken`（`storage.sql.v1`）和 `pluginObjectStorageToken`（`storage.objects.v1`）。关系库支持显式 version 1 结构声明、text/int32/双精度列、主键/唯一约束、结构化查询/写入/删除，以及回调只执行一次的事务。SDK 源码 0.1.8 另导出 `pluginCredentialToken`（`storage.credentials.v1`），提供服务端加密凭证 CRUD、元数据与修订号检查，见[凭证接口](plugin-credentials.md)。联表、外键、通用 SQL、upsert 和临时工作区尚未导出。业务 SQL 使用与核心库分开的宿主管理共享数据库：SQLite 一个文件、按插件加表名前缀；PostgreSQL 一个 URL／账号、自动创建插件 schema，共用连接池。进程隔离仍未实现，见[存储配置与先卸载再升级约定](plugin-database-isolation.zh-CN.md)。

逻辑库为 `plugin:<pluginId>`，用户文件归属及私有对象使用 `plugins/<pluginId>`，发行包使用 `host/plugin-releases/<sha256>.zip`。ZIP 字节进入环境变量配置的文件存储，共享数据库只保存 version 2 清单、归档引用和可信文件哈希索引。有效缓存无需重新下载 ZIP。全部实例由运维逐个重启。新宿主基线拒绝旧数据库/格式/SDK 包，原数据保留，不提供迁移或 fallback。详见[准确实现与限制](unified-storage-implementation.md)。

## 多实例分发

所有实例连接同一个宿主数据库，分布式部署使用 PostgreSQL。数据库保存全站期望清单、不可变归档引用与逐文件哈希索引；完整 ZIP（包括本地上传包）保存到统一文件存储。每个实例使用独立可写缓存目录：

```text
/data/plugins/
  .releases/<sha256>/       已校验插件文件
  .staging/                解压暂存
  .imports/                已导入的手动安装目录
```

启动时对照数据库归档逐文件校验，缺失或损坏就自动补齐，然后加载插件。禁用插件也会同步。无需访问官方商店、安装依赖或编译源码。共享归档缺失或损坏时明确拒绝启动。宿主数据库是安装分发的事实来源，应备份；托管插件记录、内部对象、用户文件引用与凭证同样由宿主备份。多实例持久后端必须共享，同一目录名不是分布式数据库。

不要让多个运行中的实例共享同一个插件缓存目录。在一个实例安装后，其他实例重启会自动获取，不需要手工复制。历史版本的浏览器资源也可以按需从共享归档补齐，以适应负载均衡路由。

手动目录安装：先停机，将完整发行目录放到 `<DOCA_PLUGINS_DIR>/<plugin-id>/`。启动时会打包并发布到全站清单，再将原目录移入 `.imports/`，避免重复安装。日常推荐管理员上传 ZIP。没有根目录 npm 依赖清单或旧源码加载兼容逻辑。

## 升级、卸载与故障

安装包的 `doca.storage` 必须为 `"host"`，缺失/其他值于导入代码前拒绝；已安装升级要求 `doca.dataVersion` 相同，并验证实际结构，不自动迁移。当前卸载先调用必需的业务清理钩子，成功后清结构标记；失败保持安装。钩子不能删除磁盘目录。托管私有状态清理由宿主负责，集群协调器尚未实现。禁用/停机不删持久数据；用户附件、文档载荷、其他业务引用与文件回执不自动删除。旧缓存和归档为运行实例保留，首版不自动回收。 当前清单事务执行 generation 隔离并记录私有库/对象清理意图，业务表在提交后清理并支持重试；业务任务集群排空仍未实现，所有实例需人工重启。

所有写操作检查清单修订号，避免多个管理员互相覆盖；操作记录进入安全审计。取消待应用变更会以响应实例的启动配置更新全站目标，并不会立即回滚其他实例。

实际插件初始化失败仍拒绝启动。SDK 和依赖兼容性故障按下文隔离，插件管理保持可用。没有热卸载、全站完成状态面板或原生移动端动态代码安装。

ZIP 必须包含完整依赖，不能依赖 pnpm 软链接树。包大小、路径、SDK、插件依赖、前后端版本和哈希均校验。业务数据不得写入代码包内。协议、打包命令及远端商店交接见 [插件商店协议](plugin-store-protocol.md)。

## 兼容性故障隔离

SDK 不兼容或必需依赖不可用只隔离受影响的业务插件，宿主与其他插件继续启动；管理页显示不可用原因和升级提示。原安装意愿、归档、业务数据和凭据保留，不转换旧包或执行旧 SDK 代码。新在线安装仍拒绝不兼容包。停机放入的完整安装目录按原始身份保存后做相同隔离。

旧包不能静态声明其全部业务策略，因此本实例存在启用但不可用的插件时，已有插件策略检查覆盖的写操作返回 503；登录、读取和插件管理仍可用。管理员升级兼容版本，或明确停用相关插件，再重启每个实例后解除保护。插件权限来源缺席仍拒绝授权，不自动放开原约束。SDK 不兼容插件不可执行卸载钩子；应先升级。待升级包必须保持 dataVersion，不修改插件业务结构。

隔离状态属于实例运行诊断，不写入安装清单或数据库结构。损坏归档、非法元数据、核心插件失败及实际生命周期错误继续明确失败。本轮不提供自动数据迁移或应用降级。
