# Doca 0.2.38 — Upload limits banner and desktop tree drag

[中文](0.2.38.zh-CN.md)

This release fixes two regressions reported against 0.2.37. The administration "Upload limits" page no longer shows the generic invalid-request-parameters banner as soon as it opens: the page's user picker sent its initial search with an empty `q`, which the admin user-search route rejects, so the failed request surfaced as an error below the form. The empty request is no longer sent; searching by name still filters the picker, and limits editing, the unlimited shortcut, per-user overrides and the revision-checked save are unchanged.

In the desktop client, documents in a library tree can again be dragged to a new position. Workspace webviews were created with Tauri's default native drag-drop handler enabled; on macOS that handler claims the view's dragging callbacks and never forwards them to WKWebView, so the page never received dragover/drop and the reorder could not complete. Workspace webviews now disable the native handler — nothing in the desktop shell listens to native drag-drop events — and page-internal HTML5 drag and drop works again; as a side effect, files dragged from the system onto a workspace page are now delivered to the page as ordinary HTML5 drop events, like in a browser, instead of being swallowed. The connection manager keeps its previous drag behavior.

The feature documentation for the desktop client (guides, FAQ, feature table, README screenshots) is refreshed in this release. No database structure, persisted format, public API or permission changes are included; upgrade requirements are unchanged since [0.2.37](0.2.37.md) — keep the existing database, files, configuration and original master key when upgrading.

Publication targets GitHub Release `v0.2.38` — web assets, deployment bundle, plugin SDK, and the Windows and macOS desktop installers — and `smartdoca/doca:0.2.38` plus `latest` for Linux amd64 and arm64. Publishing artifacts does not upgrade running installations.
