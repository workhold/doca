# Doca 0.2.31 — Isolate incompatible plugins during startup

[中文](0.2.31.zh-CN.md)

Installed plugins with an incompatible SDK range or unavailable required dependency are excluded together with their required dependents. The host, unrelated plugins, login and administration continue to start. Admin → Plugins reports the reason, installed SDK and required range, and asks for an upgrade. Unavailable plugins are distinct from pending restarts; restarting alone cannot repair a version mismatch.

Installed selection, archives, business data and credentials are preserved. Old SDK code is not executed, sdkRange is not rewritten, and data is not automatically migrated. Compatible replacements can be staged individually through the existing upload or marketplace flow with unchanged dataVersion. Other incompatible plugins do not block repair. Upgrade an SDK-incompatible package before uninstalling it, so its old cleanup code cannot execute.

Old packages cannot statically prove which business policies they register. While an enabled plugin is unavailable, host writes covered by existing policy checks conservatively return 503. Reads, login and plugin management remain available. Upgrade or explicitly disable the affected plugins, then restart every instance to lift protection. Missing plugin permission sources still deny access. Corrupt archives, invalid metadata, core failures and actual lifecycle errors remain explicit failures.

No database structure changes are introduced. SDK remains 0.2.0 with ai.v2 / ai.continuations.v2; no old API adapter or application downgrade is added. Existing MCP upgrade requirements remain in the [0.2.30 release notes](0.2.30.md). Preserve databases, attachments, plugin business storage, archives and the original master key before upgrading.

Docker Hub targets `smartdoca/doca:0.2.31` and `latest` for Linux amd64/arm64. Artifact publication and running deployments are verified separately. See the [change specification](../../specs/003-plugin-startup-isolation/spec.md).
