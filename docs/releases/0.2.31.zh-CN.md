# Doca 0.2.31 — 插件不兼容不再阻塞宿主启动

[English](0.2.31.md)

已安装插件的 SDK 范围或必需依赖不兼容时，只隔离受影响的业务插件及其必需依赖方，宿主、无关插件、登录和管理入口继续启动。管理 → 插件商店显示不可用原因、当前 SDK 与要求范围，引导升级。不可用状态不再误报为“待重启”；反复重启无法替代插件升级。

保留插件安装意愿、归档、业务数据与凭据，不执行旧 SDK 代码、不改写 sdkRange、不自动迁移。兼容插件可经原上传或商店通道逐个升级，dataVersion 必须保持一致；其他未升级的插件不会卡住修复。SDK 不兼容插件先升级再卸载，避免执行旧清理代码。

旧包无法静态证明其业务策略范围。因此存在启用但不可用的插件时，既有策略检查覆盖的宿主写操作保守返回 503；读取、登录和插件管理继续可用。管理员升级或明确停用相关插件，再重启各实例后解除保护。缺席插件的资源授权仍拒绝。损坏归档、非法元数据、核心插件失败和实际生命周期异常仍明确失败。

本次不修改数据库结构，SDK 仍为 0.2.0、AI 服务仍为 ai.v2 / ai.continuations.v2；不增加旧接口适配或应用降级。既有 0.2.30 的 MCP 数据升级要求仍见 [0.2.30 发行说明](0.2.30.zh-CN.md)。升级前保留数据库、附件、插件业务库、归档及原主密钥。

Docker Hub 目标为 `smartdoca/doca:0.2.31` 与 `latest`，Linux amd64/arm64。制品发布与运行中部署分开记录。专项范围见 [SDD 记录](../../specs/003-plugin-startup-isolation/spec.md)。
