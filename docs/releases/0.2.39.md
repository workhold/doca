# Doca 0.2.39 — Spreadsheet column resize guard

[中文](0.2.39.zh-CN.md)

This release upgrades the embedded spreadsheet package to `@smartdoca/sheet` 0.2.20 and fixes a reported regression: on workbooks containing one degenerate rich-text cell (an ordered-list bullet paragraph whose document skeleton produces no pages), dragging a column header boundary could not resize that column — reported on the first column. The sheet engine measures the anchor column before applying a width change, the measurement crashed on that cell, and the whole command failed silently: no error, no toast, no resize. Because the cell looks empty in the UI (the formula bar does not echo rich text), users had no way to discover the cause. The package now guards the single measurement entry: failed measurements fall back to each caller's own default, so the resize applies and rendering continues. The same crash also broke the first paint and other columns' resize bookkeeping; both paths are covered.

A silent command failure is no longer invisible: an unhandled rejection correlated with a local sheet command is reported once as a warning toast with the full stack in the console. The public package API, declarations, CSS and the model/Yjs/XLSX/preferences entrypoints are unchanged from 0.2.19; see the [editor integration contract](../editor-integration.md#spreadsheet-auto-height-measurement-guard--2026-11-23).

No database structure, persisted format, public API or permission changes are included; upgrade requirements are unchanged since [0.2.38](0.2.38.md) — keep the existing database, files, configuration and original master key when upgrading.

Publication targets GitHub Release `v0.2.39` — web assets, deployment bundle, plugin SDK, and the Windows and macOS desktop installers — and `smartdoca/doca:0.2.39` plus `latest` for Linux amd64 and arm64. Publishing artifacts does not upgrade running installations.
