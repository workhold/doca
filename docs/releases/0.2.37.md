# Doca 0.2.37 — Desktop client first release

[中文](0.2.37.zh-CN.md)

This release publishes the first public desktop clients for Windows and macOS. The desktop app packages the Doca Web frontend and connects to your own Doca service: workspace windows carry independent tabs, several backends can stay connected at once, sign-in completes in the system browser, and desktop credentials live in a local encrypted file. Windows, tab order and in-app routes are saved per backend and restored on relaunch while the matching credential remains. Plugins keep running on the selected server and load through the authenticated desktop proxy. Current installers are unsigned and not notarized: right-click → Open on the first macOS launch, and Windows may show a SmartScreen prompt. The desktop client requires this server release; see the [desktop client guide](../desktop-client.md).

The desktop installers were re-published on the same day with a fix for the macOS connection manager: a missing keychain item no longer blocks the first browser sign-in with a credential-library error; fresh endpoints start at the signed-out state as intended. Re-download the attached installers if you took them before this fix.

The server adds the desktop handoff routes behind it. Desktop authorization uses distinct hashed bearer credentials without time expiry; explicit desktop sign-out, password change/reset, account disablement and administrator revocation invalidate them, and re-enabling an account does not revive a revoked credential. The schema adds empty `desktop_auth_flows` and `desktop_sessions` tables in the current compatibility generation; existing browser, mobile and browser-assistant logins are untouched. An older server may refuse the new tables after an upgrade; keep the full database and return to a matching new server instead.

Administration moves upload-limit management into an independent "Upload limits" tab. It edits the same versioned policy through the existing admin API, and the copy now states that the single-file limit applies to AI attachments and Files uploads. The AI administration page drops its uploads sub-tab.

The rich-text editor keeps the first line directly below the fixed toolbar: the floating comment toggle no longer reserves vertical space when the comments panel is closed. A local-workspace share-link hint is now catalogued copy.

## Upgrade and recovery

Existing installations must read [0.2.36](0.2.36.md) and the earlier requirements linked from it, then keep the existing database, files, configuration and original master key. The desktop tables are declared additions that startup reconciliation applies automatically; no stored row is converted, backfilled or deleted, and fresh creation uses the same target DDL. Desktop clients from this release reject older servers without the desktop routes; installing them does not change the server. Rollback of the server to an earlier release requires removing the two desktop tables from a copy first — do not downgrade a live database in place.

## Publication

Publication targets GitHub Release `v0.2.37` — web assets, deployment bundle, plugin SDK, and the Windows and macOS desktop installers — and `smartdoca/doca:0.2.37` plus `latest` for Linux amd64 and arm64. Publishing artifacts does not upgrade running installations.
