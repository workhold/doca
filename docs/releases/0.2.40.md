# Doca 0.2.40 — Desktop files and workspace startup

[中文](0.2.40.zh-CN.md)

## Desktop and files

- PDF preview loads the worker that matches the PDF.js build selected for the WebView. The built viewer rendered PDFs in WebKit 26.5 and Chromium. An older WebKit test runtime still fails to extract the PDF text layer.
- The file list stays visible while upload and parsing status refresh. Drop local files onto a writable folder and check the destination in the upload dialog. To download several files together, select at least two and choose **Download ZIP**.
- External links opened in a new tab use the system browser. The desktop proxy normally reuses the same loopback origin for the same backend and account, so the WebView can reopen local preferences and offline state written at that origin. If the port is occupied, that launch may use another origin and show a different set of local data. Older random-origin data remains in place.

## Workspace startup

The sign-in screen loads less code, and the main workspace can open while Web plugins load. Going directly to a plugin page shows its loading status. Background desktop tabs pause navigation, notifications, and presence requests until selected. Document editing and saves continue.

## Downloads and upgrades

The [GitHub Release](https://github.com/workhold/doca/releases/tag/v0.2.40) provides the macOS and Windows installers, Web assets, deployment files, and the plugin SDK archive. The Docker Hub image `smartdoca/doca:0.2.40` targets Linux amd64 and arm64.

This release uses the same database schema and server formats as [0.2.39](0.2.39.md). Keep the deployment's database, file storage, configuration, and original master key when upgrading.
