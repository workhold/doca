# 單例項與水平擴充套件部署

[English](horizontal-scaling.md)

Doca 保留零額外依賴的單例項模式。SQLite、本地上傳目錄和程序內實時匯流排適合個人、小團隊及開源體驗；只有需要多個應用副本時，才配置 PostgreSQL、共享物件儲存和 Redis。兩種模式使用同一套業務協議；沒有內建的 SQLite 到 PostgreSQL 資料轉移或雙寫路徑。受支援的資料庫升級遵守[資料庫升級規範](database-schema-evolution.zh-Hant.md)。

<a id="能力矩阵"></a>

## 能力矩陣

| 能力                     | 單例項預設           | 多例項要求                                   |
| ------------------------ | -------------------- | -------------------------------------------- |
| 資料庫                   | SQLite 或 PostgreSQL | PostgreSQL；所有副本連線同一資料庫           |
| 正文協作與通知           | 程序內廣播、線上狀態 | Redis Pub/Sub 廣播，Redis 線上狀態           |
| 登入/上傳/公開機器人限流 | 程序內計數           | Redis 全域性計數                               |
| 檔案                     | 本地持久目錄         | S3 相容物件儲存或所有副本真正共享的檔案系統  |
| CDN                      | 可選                 | 可選，只負責讀取加速，不能替代共享物件儲存   |
| 後臺任務                 | 資料庫租約           | 同一資料庫租約；任一副本可領取，失敗可重試   |
| 移動推送                 | 資料庫 outbox        | 同一 outbox 與租約，避免僅存在某個程序記憶體中 |
| 建表                     | 首次啟動建立當前基線 | 首次部署前由一個例項建立空庫基線             |
| 健康檢查                 | `/live`、`/ready`    | `/ready` 同時檢查資料庫和 Redis              |

<a id="单实例默认"></a>

## 單例項預設

不設定 `DOCA_REDIS_URL` 時，實時事件、presence 和限流自動使用本機實現；不需要安裝 Redis。`pnpm dev`、`pnpm start` 和單容器 Compose 首次連線空庫時直接建立當前基線，之後按最新 DDL 對賬受支援的已有結構。

該模式不應啟動兩個副本。負載均衡器的 WebSocket 粘性會暫時掩蓋問題，但通知、許可權失效、線上使用者和全侷限流仍會被分割。

<a id="多实例最小配置"></a>

## 多例項最小配置

所有副本至少使用以下共同配置：

```dotenv
DOCA_DATABASE=postgres
DOCA_DATABASE_URL=postgresql://user:password@postgres:5432/doca
DOCA_DATABASE_POOL_MAX=10
DOCA_REDIS_URL=redis://redis:6379
DOCA_REDIS_PREFIX=doca-production
DOCA_TRUST_PROXY=10.0.0.10/32
```

`DOCA_INSTANCE_ID` 可由編排平臺設定為 Pod/容器名；未設定時每個程序生成隨機 ID。`DOCA_REDIS_PREFIX` 必須在共享 Redis 中區分環境。`DOCA_TRUST_PROXY` 只列出實際反向代理的 IP 或 CIDR，否則客戶端可偽造 IP，破壞審計和限流。

釋出順序：

1. 首次部署使用一個應用例項連線空資料庫，建立當前基線併成功啟動；不要讓多個副本併發初始化空庫。
2. 用相同版本和配置啟動其餘副本。已批准的結構變化在 schema 鎖內對賬；不支援或需複核的差異在持久修改前停止啟動。
3. 負載均衡器以 `/ready` 決定是否接收流量，以 `/live` 判斷程序是否存活；WebSocket 必須允許升級和正常排空。
4. 先摘除 readiness，再等待 HTTP 請求和 WebSocket 在停止寬限期內關閉。按發行要求安排停機和啟動順序；滾動釋出不代表不同宿主版本可以相容混跑。

Redis 一旦配置就是必需依賴：啟動連線失敗、執行期不可用或 readiness 失敗時，不會靜默切回本機廣播。這樣可避免叢集在故障時分裂成多個看似正常的單例項。

<a id="一致性边界"></a>

## 一致性邊界

協作更新先在 PostgreSQL 事務中持久化並生成提交回執，再透過 Redis 通知其他副本。Redis 不是正文日誌；重複事件由協議去重，短暫丟失會在重連後透過資料庫權威狀態恢復。presence 有過期時間，例項異常退出後會自動消失。

檔案識別、正文抽取、知識冊編排和移動推送使用資料庫任務與租約。計劃任務的 occurrence key 保證多個副本同時掃描時只建立一個業務發生項。任務處理器必須保持冪等，因為租約超時後允許其他副本重試。

<a id="容量与运维卡点"></a>

## 容量與運維卡點

- 資料庫連線總量約為“副本數 × `DOCA_DATABASE_POOL_MAX`”，必須小於 PostgreSQL 或連線代理的可用額度，並預留運維和後臺任務連線。
- 本地磁碟不能用於多主機上傳。CDN 只快取讀取結果；源物件仍必須位於 S3 或共享檔案系統。歷史 `storage_profile` 指向的儲存配置必須繼續可用。
- Meilisearch、S3、訊息閘道器等外部服務必須讓所有副本看到同一配置和同一資料。憑據存於共享資料庫，但網路連通、白名單和金鑰仍由部署環境保證。
- 共享資料庫記錄目標外掛版本，安裝 ZIP 位於共享儲存；每例項需要獨立可寫的 `DOCA_PLUGINS_DIR` 安裝與快取目錄，啟動時從歸檔校驗恢復。操作需人工重啟全部例項生效，見[外掛部署](plugin-deployment.zh-Hant.md)。
- Redis 建議啟用認證、TLS/私網、記憶體上限與可觀測告警；資料庫和物件儲存仍需獨立備份。Redis 資料丟失不應造成正文丟失，但會中斷實時傳播、線上狀態和全侷限流。
- `/ready` 只證明當前副本能訪問資料庫和實時叢集，不代替端到端協作、物件儲存、搜尋與訊息通道監控。

<a id="仍需外部验收"></a>

## 仍需外部驗收

程式碼已覆蓋雙應用例項的文件更新、游標/presence、共享限流，以及資料庫租約/outbox。正式上線前仍需在目標基礎設施完成 PostgreSQL、託管 Redis、S3、反向代理 WebSocket 排空和滾動釋出演練，並做故障注入：暫停 Redis、終止任務執行副本、撤權同時編輯、資料庫基線不匹配和物件儲存超時。
