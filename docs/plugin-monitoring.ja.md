## インストールとアクセス

使用している各サービスを明記する `injections.required` 例えば、0.1.11から始まるSDKの範囲です。 `sdkRange: "^0.1.11"`欠落しているサービスや古いSDKの範囲は明確に失敗します。新しいサービスには古いホストアダプターがありません。既存のメソッドも同様です。 `events.v1`データベースの構造と保存形式は、以前の動作を維持します。

インストールされたサーバープラグインは信頼できるコードであり、管理者によってインストールされます。必要なモニタリングインジェクションにより、サーバープラグインはサイトの運用情報にアクセスし、バックグラウンドでの収集が可能になります。このインジェクションは、通常のユーザーにそのデータへのアクセス権を与えません。プラグインは自身のルート、ジョブ、AIツールを認可する必要があり、通常のユーザーやモデルプロンプトにグローバルログや監査データを自動的に送信してはなりません。

マウント時に監視を注入し、プラグインのWebアクセスを有効にする。 `host.platform.monitoring` 同じ固定メソッドセットを呼び出す `/api/v1/plugin-platform/<pluginId>/monitoring.<method>`ホストはライブモニタリング範囲を確認し、各ブラウザ呼び出し時にアカウントのアクティブ管理者の状態を再確認する。存在しない/非アクティブなインストールは、既存のプラットフォームゲートによって拒否される。一般的なサービス配布やブラウザテレメトリ記述エンドポイントは提供されない。廃棄処理では範囲と保持されたサービスハンドルが無効化される。テレメトリ記述はインストールIDに結び付けられる。

```ts
import { definePlugin } from "@smartdoca/plugin-sdk";
import { monitoringServiceToken, telemetryServiceToken } from "@smartdoca/plugin-sdk/monitoring";
import { httpServiceToken } from "@smartdoca/plugin-sdk/platform";
import manifest from "../manifest.json" with { type: "json" };

export default () => definePlugin({
  manifest, // sdkRange: "^0.1.11"; package.json also declares doca.storage: "host"
  injections: { required: [monitoringServiceToken, telemetryServiceToken, httpServiceToken] },
  async uninstall() {},
  async mount(context) {
    const monitoring = context.inject(monitoringServiceToken);
    const telemetry = context.inject(telemetryServiceToken);
    telemetry.log(manifest.id, { level: "info", module: manifest.id, message: "Collector started" });
    await context.inject(httpServiceToken).register(manifest.id, [{
      method: "GET", path: "/metrics", admin: true,
      handle: request => monitoring.metrics({ scope: "cluster", windowSeconds: 60 }, { signal: request.signal }),
    }]);
  },
});
```

Webバンドルは読み取ることができます `await host.platform.monitoring.stats({})` または `await host.platform.monitoring.logs({cursor})`コーティングされたDTOを受け取り、それにはカバレッジやギャップも含まれます。SDKの呼び出しオプションではAbortSignalを受け入れます。クエリでは、I/Oの前後でキャンセルをチェックしますが、既に送信されたデータベースステートメントのキャンセルは保証されません。

## 読み方方法

| 方法 | 事実と限界 |
| --- | --- |
| `stats({})` | 共有データベースの数：削除されていない文書、ライブラリ、ファイル；全てのアカウント/アクティブアカウント；論理ファイルのバイト数；登録済みファイルストレージオブジェクトとバイト数。論理ファイルのバイト数は、同じオブジェクトへの参照を数える場合があります。登録済みオブジェクトのバイト数はインベントリであり、ファイルシステム/バケットの容量ではありません。プライベートプラグインオブジェクト、リリースアーカイブ、未登録オブジェクトはこの合計から除外されます。 |
| `online({offset?,limit?})` | 新鮮なリアルタイム接続；ユーザーID、接続数、アクティブドキュメント数、ユーザーID/ドキュメントIDのページによって人々が重複なく分類されます。デフォルトは100、最大は200です。範囲はローカル存在の場合はインスタンス、Redisの場合はクラスターです。古いハートビート方式は一切使用されず、リアルタイムが利用できない場合はエラーが発生します。 |
| `metrics({scope?,windowSeconds?})` | HTTPのリクエスト完了、4xx、5xx、中止されたリクエスト、インフレーム中のリクエスト、QPS、5xxエラーレートおよび持続時間のヒストグラム；ルートテンプレートグループとプラグインメトリクスシリーズ。デフォルトは60秒、1～300まで対応。デフォルトのスコープクラスター；設定されたRedisがない場合、実際に返されるスコープはインスタンスです。 |
| `logs({scope?,cursor?,limit?,level?,pluginId?,module?,requestId?,since?})` | バッファードされた構造化された操作ログ。各エポックの順序を保持し、時間によってインスタンスのヘッドをマージする。クロックの逆転は、未処理のエントリを超えて進むことはない。デフォルトは100、最大は200。フィルターは正確で、レベルは最小閾値ではない。カーソルの最大サイズは64 KiB。空のページでも、常に返されたカーソルを保存する。 |
| `audit({source,...})` | 既存の持続可能なセキュリティやリソースの監査。必要。 `source: "security" \| "resource"`; オプションの正確なアクション/actorId、ソース固有のuserId/resourceId、ISO日付/日時、カーソル、制限値。ソースに適用されないフィルターは失敗する。セキュリティに関する詳細は隠されている；読めない/非オブジェクトの詳細は `null` と共に `detailsValid:false`記録は書き換えられない。 |
| `jobs({})` | 共有データベースのAI/プロジェクション/ファイル抽出ステータスグループ、有効期限が切れたAI/プロジェクションリース、および削除待ちのプライベートオブジェクト。プロジェクションの種類には、すでにそのキューを使用しているタスクも含まれます。これは、すべてのビジネスプラグインがホストキューを使用していることを意味するものではありません。 |
| `jobErrors({source,limit?})` | 最新の制限付きAI/プロジェクション/ファイル抽出エラー；プロンプト、ペイロード、結果はありません。これは最近の診断サンプルであり、完全なページングされたエラーアーカイブではありません。 `nextCursor` 常にnullです。プロジェクションレコードには信頼できるエラー更新時刻がないため、 `updatedAt` nullであり、順序付けはavailable_atを使用する。 |
| `aiUsage({...})` | 共有レジャーのスナップショットページ、正確なユーザーID/モデルID/状態、ISO日付/日付。呼び出し/ジョブ/モデルID、状態、評価済みトークン、および元のプロバイダの数値メトリクス。不明な使用状況はnullであり、古いSQLの数値列からは決して推定されない。現在の表現と一致しない確認済みエントリは `usageStatus:"invalid"`、変更なしで保持される。秘密情報、ベンダーの生の回答、モデルのスナップショットは省略される。 |
| `health({scope?})` | バージョン、インスタンス、プロセス、RSS/ヒープ/累積CPU/イベントループP95、データベース読み取りプローブ、リアルタイム/キャッシュの準備状態。ストレージ/検索/AIネットワークプローブも明確に記載されている。 `not-probed`ヘルス読みは有料モデルを呼び出したり、ストレージテストオブジェクトを作成したりしません。 |

監査および使用ページングはデフォルトで100に設定され、200件のレコードを許可します。カーソルは上限時間境界を設定し、クエリフィンガープリントを含み、created_at、次にIDで順序付けされます。不正な/一致しないカーソルは失敗します。これらの読み取りはインベントリであり、変更フィードではありません。耐久性のあるAI決済消費のためには、既存のものを使用してください。 `events.v1` / `ai.usage.recorded`以前に保留されていた通話は、作成時のページが読まれた後に解決することができます。すべての元の監査や使用インターフェースは、元の動作で利用可能です。

## リクエストメトリクスとカスタムメトリクス

HTTPメトリクスには、管理者やプラットフォーム、健康状態に関するリクエストを含むすべての通常のHTTPルートが計上されます。WebSocketのハンドシェイクやメッセージは除外され、その接続にはリアルタイムプレゼンスを使用します。中止されたリクエストは、完了したレスポンスとは別に計数されます。エラー率は5xxレベルの完了したレスポンスの数であり、ウィンドウが空の場合は0です。QPSは、実際にカバーされる時間帯におけるインスタンスのリクエスト率を合計し、起動時の範囲に制限されます。スナップショットレポートにはサンプリング時間と起動時が記載されているため、消費者はサンプリングの遅れを評価できます。

持続時間は、1、5、10、25、50、100、250、500、1000、2500、5000、10000、そして無制限のミリ秒単位のバケットを使用する。P50/P95/P99はバケットの上限推定値であり、観測された最大値に制限される。クラスターのパーセンタイルは、平均インスタンスのパーセンタイルではなく、バケット数を合計する。空の分布には最小値、最大値、パーセンタイルが存在しない。ルートラベルは登録されたルートテンプレートを使用し、クエリ文字列や動的リソースURLは使用されない。各プロセスエポックごとに最初の64のルート/メソッドグループが保持される。その他のグループは共有される。 `[other-routes]`.

```ts
telemetry.record(manifest.id, {
  name: manifest.id + ".sync.completed", kind: "counter", value: 1,
  labels: { source: "mail" },
});
telemetry.record(manifest.id, {
  name: manifest.id + ".sync.duration_ms", kind: "histogram", value: 120,
});
```

メトリクスの名前は、所有するプラグインIDとドットで始まります。種類には、カウンター（非負の増分）、ゲージ（最新の有限値）、ヒストグラム（同じ数値のバケットを使用した非負の観測値）があります。同じ名前の下での種類やラベルキーの変更は409エラーで失敗します。最大6つのラベル、100文字/値、200シリーズ/プラグイン、1,000カスタムシリーズ/インスタンスまで可能です。新しい過剰シリーズは429エラーで失敗し、増分が拒否されます。秘密のようなラベルや数値のオーバーフローも失敗します。ユーザー/リクエスト/文書IDの代わりに制限付きカテゴリを使用してください。カスタムシリーズはインスタンス/エポックごとに返されます。カウンターのリセットやゲージの集計は、明示的な消費者決定です。その値は開始以来の累積/最新値であり、HTTPローリングウィンドウとは無関係です。プラグイン制作者は、カスタムメトリクスを通じて自身の依存関係/ジョブ情報を公開できます。

## ログ、保持期間、クラスターカバレッジ

ホストログには、ホストログが有効な場合の構造化されたFastifyアプリケーションログが含まれます。また、stdoutログが有効かどうかに関わらず、HTTPエラー、中止、2秒以上かかったリクエストも記録されます。通常の成功したリクエスト行はメトリクスとして表されます。プラグインログには、ホストに関連するpluginId、エポック、インスタンスId、シーケンス、作成時間、および任意のリクエストIdが含まれます。機密なキー、リクエストボディ、プロンプト、ペイロード、モデルスナップショット、エラースタックは削除または編集されます。URLのuserinfo/query/hashや一般的な認証文字列も処理されます。任意の秘密情報をログに記録しても、パターンマッチによって安全にすることはできません。著者は、メッセージ/モジュール/リクエストId/fieldsに秘密情報や文書ボディを含めるべきではありません。

各インスタンスは最大2,000件の記録と2MiBのシリアル化されたログデータを保持します。Count/byteのエビジョメントにより、シーケンスウォーターフォールドとドロップ数が増加します。そのウォーターフォールドの後ろに保存されたカーソルは、失われた数も含む明確なエビジョメントギャップを報告します。インスタンスは再起動時に新しいエポックを持ちますが、instanceIdが再利用されても同様です。以前のエポックが欠けている場合は、インスタンスが利用できないギャップを報告します。形態が不適切な新しいキャッシュ表現は利用できないとマークされ、有効期限まで保持され、決して適応されたり内容として返されることはありません。

設定されたRedisを使用すると、ホストは5秒ごとに別途バージョン1のスナップショットを公開する `monitoring:v1` キー名前空間。15秒以上経過した閉じたインスタンスやスナップショットは古くなっており、現在のメトリクスの合計から除外されますが、保持されているログは引き続き削除されます。スナップショットや既知のインスタンス記録は1時間後に期限切れとなります。古くなった/欠落した/不正なインスタンスは… `complete:false`クラスターリードにより応答するインスタンスが更新され、他のスナップショットも読み取られる。最大128個の保持されたエポックと16MiB/スナップショット；より大きなインベントリでは明示的に失敗する。Redisの障害では、設定されたクラスターリクエストがローカルデータに降格されることはない。ローカル範囲は明示的な診断選択肢である。このキャッシュは一時的なものであり、耐久性のある配信や混合バージョンのフリートの発見を保証するものではない：新しいパブリッシャーを持たないホストはそのインベントリに含まれない。

モニタリングプラグインは、ホスト管理によるストレージを通じて歴史的集計値、ログ記録、カーソル、ギャップマーカー、アラート状態を保存します。IDによってログを重複排除し、カーソルと共に1つのプラグイントランザクション内で記録をコミットし、ギャップをギャップとして認識/報告します。サンプリングでは失われたリクエストウィンドウを再構築することはありません。ホストはセキュリティ監査と元のAI使用状況の事実を保持します。プラグインはこのSDKを通じてそれらを削除することはできません。

<a id="upgrade-rollback-and-verification"></a>

## アップグレード、ロールバック、検証

この追加は、ホストデータベースのテーブル、ベースライン、監査形式、AIレジャー形式、または既存のプラグインデータ構造に変更はありません。既存のonline-heartbeatおよびAI歴史読み取りの代替手段は、元のパスに留まります。新しい実行時事実はアップグレードされたプロセスの起動時に開始され、歴史的stdoutはインポートされません。新しいプラグインはSDK 0.1.11が必要であり、古いホストでは動作しません。コードのロールバックにより、既存の永続データとプラグインの歴史記録が保持されます。古いホストを起動する前に新しいサービスを必要とするプラグインは無効化します。監視キャッシュは、権威あるデータに影響を与えずに期限切れになる可能性があります。

テストでは、独立したデータベース/文書と一意のRedis名前空間が使用される。受け入れテストには、リクエスト/ヒストグラムのマージ、ユーザーの重複削除、フィルター/ページング/カーソルの削除、秘密情報の隠蔽、通常ユーザーおよび廃止された管理者の拒否、名前空間/バージョン/ライフサイクルの制御、古い/欠落した/無効なキャッシュおよび再起動エポック、さらにSDKビルドと独立したJavaScript/宣言消費者が含まれる。npmの公開、生産環境モニタリングプラグイン、生産環境のデプロイは別々の提供物である。
