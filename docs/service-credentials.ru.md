# Ключи доступа к платформенным услугам

[中文](service-credentials.zh-CN.md)

Откройте «Администратор» → «Настройки платформы» → «Криптографические данные сервиса». Текущий запис о платформе, управляемой хостом, охватывает:

- Идентичность: названы секреты клиента SSO и разрешенные источники HTTP(S). Поставщики идентичности относятся к именам учетных данных.
- Гейтинг-гейт: HTTP(S) эндпоинт, секрет bearer и каналы телефона/электронной почты.
- Поиск документов: ключ API Meilisearch и разрешенные источники.

Ключи доступа к файлу backend и ключи подписи CloudFront конфигурируются только в `DOCA_FILE_STORES_JSON`Страница управления хранением доступна только для чтения. На этой платформе её нельзя редактировать. [Криптографические данные плагина](plugin-credentials.ru.md) Используйте отдельное зашифрованное сервисное решение, предназначенное только для сервера, и его главный ключ развертывания.

<a id="persistence-and-configuration-precedence"></a>

## Постоянство и приоритет конфигурации

Настройки платформы сохраняются под этим именем. `account_settings`, ID `service-credentials`Существующий код загружает настройки идентификации/сообщений из среды выполнения только в случае отсутствия этого записи; затем приоритет имеет сохраненная запись. Изменение переменных окружения не перезаписывает сохраненные настройки. Это существующий путь инициализации, который сохранен и документирован здесь без использования нового адаптера или миграции. Сохраненная запись, содержащая устаревший формат хранения, явно отклоняется текущим хостом.

Соединения с базой данных, источник сайта, порты приема сообщений и хранение файлов остаются в конфигурации запуска. База данных должна быть подключена, прежде чем можно прочитать сохраненные настройки. Первый администратор все еще использует явный команду bootstrap.

<a id="api-and-secret-handling"></a>

## API и обработка секретов

`GET` / `PUT /api/v1/admin/service-credentials` Требуется системный администратор; операции валидации Origin. GET заменяет настроенные секреты на null. При операции PUT null сохраняет существующий секрет, а пустая строка удаляет его. Не отправляйте фальшивую строку маскировки. Проверки ревизии предотвращают одновременные изменения. Аудиторский реестр хранит действия, а не значения секретов; ограничения по протоколу endpoints, origin и перенаправлению остаются.

Сервер сохраняет пригодные учетные данные третьих сторон. Базу данных и резервные копии следует считать конфиденциальной конфигурацией. Сохраненные секреты не возвращаются обычным пользователям, публичному bootstrap-коду, логам ошибок или ответам администратора через GET-запросы. Шифрование учетных данных плагина не автоматически повторно шифрует эти платформенные настройки.

Каждый процесс обслуживания проверяет изменения настроек перед запросами API и обновляет адаптеры после изменений без перезапуска. Переключение секрета проверки делает ожидающие проверки недействительными. Изменения ключей хранения происходят в рамках процесса развёртывания. [правила хранения](storage.ru.md), включая сохранение стабильных идентификаторов хранилищ и указанных байт.
