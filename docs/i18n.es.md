# Idiomas de interfaz

Doca 0.3.0 admite ocho idiomas de interfaz. Cada idioma tiene su propio catálogo de mensajes y todos comparten claves estables en inglés. Consulta el [contrato original en inglés](https://github.com/workhold/doca/blob/main/docs/i18n.md) para conocer las reglas del proyecto y de los editores.

<a id="language-codes"></a>

## Códigos de idioma

| Código | Idioma | `html lang` |
| --- | --- | --- |
| `zh` | Chino simplificado | `zh-CN` |
| `en` | Inglés | `en` |
| `zh-Hant` | Chino tradicional | `zh-Hant` |
| `ja` | Japonés | `ja` |
| `fr` | Francés | `fr` |
| `ko` | Coreano | `ko` |
| `es` | Español | `es` |
| `ru` | Ruso | `ru` |

El chino simplificado es el idioma inicial del sitio. El administrador puede cambiar el idioma predeterminado. Los visitantes y los usuarios sin preferencia `ui.locale` usan el idioma del sitio. La selección guardada en la cuenta tiene prioridad.

Para escribir un valor mediante la API, usa un código canónico de la tabla. Al resolver etiquetas regionales o del sistema, `zh-TW`, `zh-HK`, `zh-MO` y `zh-Hant` se asignan al chino tradicional. Los demás idiomas admitidos coinciden por su etiqueta principal. Si no se reconoce un valor guardado, el espacio de trabajo usa el idioma predeterminado del sitio.

La preferencia de la cuenta se guarda como estado de página en `ui.locale`. El cliente web también guarda `doca.locale` en `localStorage`, y el cliente móvil la guarda en el dispositivo. El asistente puede cambiar `ui.locale` mediante la función existente `page_state`.

Al cargar la pantalla de inicio de sesión web, se muestra primero el idioma del sitio que ha elegido el administrador. El selector de esa pantalla aplica el idioma de inmediato para la visita actual. Una vez iniciada la sesión, el espacio de trabajo usa la preferencia de la cuenta y el idioma predeterminado del sitio.

<a id="host-catalog"></a>

## Catálogo de anfitriones

Los catálogos están aquí. `packages/i18n`. El catálogo en inglés `en` Es la fuente de las claves. Cada otro idioma debe cubrir exactamente las mismas claves.

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

- Las claves son letras inglesas en minúsculas con puntos, agrupadas por área, por ejemplo `nav.trash` y `settings.language`.
- Los placeholders son `{name}`No divida la oración y no conecte los fragmentos.
- Uso de plurales `files.count.one` y `files.count.other`La llamada aún está en progreso. `t("files.count", { count })`El inglés utiliza `one` cuando `count === 1` y `other` De lo contrario. Los chinos pueden usar la misma oración para ambos.
- Una traducción faltante utiliza inglés, y luego la clave en sí.
- Usa el nombre propio de cada idioma en los selectores. Los etiquetas nativas provienen de `localeNames`.
- Fechas y clasificación `Intl` Para la etiqueta de idioma activo.
- Los títulos de documentos, el texto del cuerpo, los comentarios, los correos, los nombres de archivos y la entrada del usuario no se traducen.

La aplicación web utiliza `useI18n()` para `locale`, `t`, y `setLocale`Ant Design y Ant Design X siguen esa línea. `locale`. El uso en escritorio y móvil utiliza los catálogos del host. La extensión del navegador guarda su idioma para ese navegador. Las contribuciones que utilizan el contrato de complemento bilingüe usan su campo en inglés en los seis nuevos idiomas.

Los errores del servidor visibles para el usuario, sin código, siguen siendo frases en chino. Los nuevos errores de validación utilizan un código estable, como `invalid_locale`Y la interfaz lo traduce. Los errores de la API existentes no se convierten en esta versión.

La nueva generación de imágenes con IA, la conexión de modelos y los errores de los trabajadores utilizan un envoltorio de presentación explícito, serializado en los campos de texto de error existentes:

```ts
{ type: "system_error", version: 1, code: "image_edit_failed", data: { status: 422 } }
```

Solo los errores de sistema recién producidos y explícitamente codificados utilizan este formato. El texto de error histórico, los mensajes, los resultados de las herramientas, el razonamiento y el contexto del prompt almacenado se leen literalmente; no los escaneen, traduzcan, conviertan ni migren. Los errores sin etiquetar permanecen sin cambios. La web y los dispositivos móviles comparten… `systemErrorMessage` lector en `@doca/i18n`Los errores en los trabajos etiquetados. `useI18n().t`Los nuevos errores HTTP utilizan el idioma seleccionado por el mismo proveedor. Los códigos desconocidos muestran un error genérico catalogado, mientras que los envoltures mal formadas o no soportadas se dejan sin cambiar.

`AppError.message` Y la serialización de errores orientada al modelo permanece sin cambios. Los metadatos de presentación se almacenan fuera del objeto de error en un WeakMap. Los puntos de control de fallo de imagen llevan una razón estructurada separada, de modo que el fallo posterior de la tarea pueda mostrarse sin modificar la retroalimentación canónica del herramienta. El lenguaje de interfaz nunca se añade al prompt del sistema, a las definiciones de herramienta o a la historia de reproducción, preservando el prefijo del modelo almacenado cuando el usuario cambia de idioma.

Esta es la política de lectura acordada para el texto plano antiguo y los errores codificados nuevos; no hay migración de datos históricos ni de esquemas de base de datos. Un rollback debe detener las escrituras en el sobre nuevo, manteniendo al lector de sobres y todos los datos almacenados.

<a id="persisted-system-state"></a>

## Estado del sistema persistido

Bases de datos, puntos de control de trabajos, flujos de eventos y respuestas de API almacenan códigos estables en inglés y parámetros estructurados. No almacenan una oración de presentación en ningún idioma. Las aplicaciones web y móviles convierten el código en un título, descripción y nombre de fase según el catálogo actual.

```ts
{ code: "folder_available", data: { name: "Research" } }
t("ai.progress.event.folderAvailable", { name: event.data.name })
```

Fases, eventos, aprobaciones y razones de error almacenados como estado siguen esta regla. Compare los códigos, por ejemplo `phase === "completed"`No compare el resultado. `t(...)` O bien una etiqueta en chino o en inglés. La entrada del usuario, las respuestas del modelo, los títulos de documentos, los nombres de archivos y las fuentes web se mantienen tal como están. No reescriba el contenido natural en códigos.

<a id="editor-subpackages"></a>

## Subpaquetes de editor

Un subpaquete de editor mantiene su propia copia de interfaz. No importa el catálogo de Doca ni lee el estado de las páginas de Doca.

El presentador pasa:

```tsx
<RichTextEditor locale={locale} />
```

`locale` Es una cadena de texto. Los editores instalados aceptan los ocho códigos de la tabla. Una localización de paquete no reconocida se reemplaza por el inglés.

1. Añada un opcional `locale?: string`. Cuando se omite, muestra `zh`, que se adapta a la interfaz china actual.
2. Las claves son identificadores en inglés estables, como `toolbar.bold` y `find.replaceAll`.
3. Proporcione un catálogo completo de las mismas claves para cada idioma soportado.
4. Los placeholders son `{name}`Los contadores se usan `key.one` y `key.other`, seleccionado por `count`.
5. Cambiar `locale` Actualiza los botones, menús, espacios en blanco y indicaciones. No reconstruye el documento, Y.Doc, el adaptador de colaboración o la lista de complementos.
6. Opcional `messages?: Record<string, string>` Puede anular las claves individuales. Las claves ausentes todavía utilizan la traducción integrada.
7. El texto, las fórmulas y los valores de celda que el usuario escribió en el documento no se traducen.

Después de que los tipos del paquete instalado incluyan `locale`, el anfitrión pasa la corriente `locale` en el lugar del monte. No lo pongas `locale` En una dependencia que reconstruye el documento, Y.Doc, adaptador de colaboración o lista de complementos.

<a id="add-a-language"></a>

## Añadir un idioma

1. Agrega el código a `locales`, y el `html lang` valor.
2. Añada un catálogo de hosts con exactamente las claves en inglés.
3. Añade el nombre del idioma en sí, por ejemplo `locale.ja`.
4. Agrega el locale de Ant Design correspondiente en la aplicación web.
5. Añada el mismo catálogo de idiomas en cada subpaquete de editor.
6. `ui.locale` Acepta el nuevo código, ya que la validación muestra lo mismo. `locales` lista.
