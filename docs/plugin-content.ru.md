# Поставщики контента: content.v1

[中文](plugin-content.zh-CN.md)

Публичный вход `@smartdoca/plugin-sdk/content`Хозяин определяет контракт и границы вызова; плагины реализуют бизнес-поведение. Встроенные документы/файлы регистрируются через один и тот же интерфейс. Регистрация источника не автоматически делает все источники доступными для ИИ.

<a id="contract"></a>

## Контракт

- `sources(context, purpose)` открывает источники деклараций.
- Источники требуют `list`, `read`и `resolve`. Опционально `search` Должно точно соответствовать декларации возможностей.
- `list(context, {config, cursor, limit})` возвращает легкий вес `{items,nextCursor,snapshot}`Каждый элемент включает `ref:{sourceId,resourceId,blockId}`, `fingerprint`и `title`, по желанию `order`, `anchor`и короткое `excerpt`Тело `text` запрещено.
- `read(context, {config,ref,fingerprint})` возвращает список полей плюс выбранный блок `text`Или null, если текущим образом нечитаемо. Измененный отпечаток пальца вызывает конфликт и требует повторного перечисления.
- `resolve(context,ref)` повторно утверждает и возвращает `{path,fingerprint}` Или null. Пути должны находиться внутри приложения.
- `search(context, {config,cursor,limit,query})` Возвращает ту же легкую список. Источники выполняют поиск; хост не выполняет полный сканирование тела.

Звонки для просмотра/поиска списка услуг также передаются `sourceId` и `purpose`Кallback-обработчики получают реальный результат. `principalId`, `purpose`и `signal`Каждое вызывание проверяет аккаунт, настроенный объем доступа и текущие разрешения; идентификаторы пользователей, предоставленные в теле сообщения, не вызывают доверия. Хост проверяет жизненный цикл пользователя/источника перед и после вызовов и применяет таймаут в 20 секунд.

```ts
const content = context.inject(contentServiceToken);
content.register({
  id: "example.tasks.content", pluginId: "example.tasks", version: 1,
  title: { zh: "待办", en: "Tasks" }, contentTypes: ["task"],
  purposes: ["analysis", "knowledge"], capabilities: { search: false },
  configSchema: { type: "object", additionalProperties: false, properties: {} },
  list: listAuthorizedTaskBlocks,
  read: readAuthorizedTaskBlock,
  resolve: resolveAuthorizedTaskBlock,
});
```

Плагин реализует все три возвратные вызовы. Он не должен читать приватные таблицы хоста/источник или базу данных другого плагина.

<a id="reconciliation"></a>

## Расширение доверия

Потребители хранят ссылки/отпечатки ключей под текущей конфигурацией идентификации и подписки. После полного перебора неизменные блоки не требуют чтения/анализа с помощью ИИ, в то время как измененные блоки читаются напрямую. Только успешное полное прохождение позволяет добиться исчезновения. Таймауты, неудачные страницы, измененные снимки и неопределенные разрешения не могут рассматриваться как пустой набор или использованные отпечатки ключей.

`cursor=null` начинается; `nextCursor=null` Конец. Снимок прохождения должен оставаться последовательным. Курсоры перечисляют страницы; они не являются долговечными позициями в логе. Отклоняются старые курсоры, когда содержимое, область или права нарушают полноту информации. Разделяйте `listChanges`/`readChanges` не требуются.

Ограничения: 100 элементов на страницу, 2 миллиона символов в блоке, 100 000 блоков в полном инвентаре. Хост проверяет ссылки, дубликаты, курсоры и возможность отмены. Специальные помощники анализа собирают общее измененное тексто и явно выдают ошибку при переполнении, вместо того чтобы обрезать текст и утверждать его полноту.

Встроенные источники используют адресирование параграфов. Вставка параграфа перед неизмененным параграфом не меняет его идентичности. Редактирование текста удаляет старый блок и создает новый. Это не стабильные уникальные идентификаторы узлов редактора. Правила дублирующего блока, контекста заголовка и срезания длинных параграфов находятся в [запись отпечатков пальцев](content-fingerprint-reconciliation.md).

<a id="host-apis-and-consumers"></a>

## Хосты API и потребители

HTTP: `GET /api/v1/content/sources?purpose=analysis`; POST `/api/v1/content/list`, `/read`, `/resolve`, `/search`Идентификация происходит из сессии хоста, а ответы не используют стандарт “store”.

Глобальный поиск вызывает только источники, объявляющие поиск. Фильтры документов/библиотек, которые не могут применяться к бизнес-областям плагинов, исключают эти результаты плагинов. Нажатие снова разрешает доступ.

Нативные библиотеки сохраняют регистрацию исходного кода. `knowledge_subscriptions` и `knowledge_source_groups.config`Они не создают рабочих мест в области кураторства, не формируют производные элементы или не используют зеркала отпечатков данных. POST `/api/v1/knowledge/libraries/:id/content-subscriptions` принимает `{sourceId,config,title}` И требует знаний и цели. Только автор может изменить объем обслуживания поставщика.

Книги знаний независимо фиксируют полные авторизованные инвентарные списки в момент исполнения и переактуализируют их перед публикацией. Доказательства сохраняются `contentRef`Источник версии, хеш содержимого и точные цитированные фрагменты. Доступ к данным прекращается, когда поставщик, связка, участник или разрешение оригинального источника становится недоступным; сохраненные данные не предоставляют доступа. Не существует дополнительного полного хранилища текста поставщика.

Инструмент выбора источника предоставляет базовые формы схемы; сложная вложенная конфигурация требует использования страницы самого плагина. `PUT /api/v1/knowledge/libraries/:id/content-source-groups/:groupId` Принимает параметры создания. Только подписывающий субъект может изменить область действия. Изменения влияют на последующие чтения из источника.

`knowledge.sources.v1` не адаптируется автоматически `content.v1`Бизнес-плагины реализуют общепринятый стандарт. Книги знаний используют новую базу; не предоставляется никакого исторического преобразования или адаптера старого протокола.
