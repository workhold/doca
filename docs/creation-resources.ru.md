# Шаблоны и материалы для плагинов

[中文](creation-resources.zh-CN.md)

Базовый уровень контракта: SDK `0.1.9`, контракты `0.1.7`Создание документов, публичные клиенты плагинов, устройства выбора хоста и использование ИИ используют одни и те же ресурсные сервисы. Перед интеграцией необходимо проверить реальные экспорты пакетов и версии развёртывания. Внешние сервисы и устройства требуют отдельного утверждения.

## Обработка существующих данных

Реализованная модель ресурсов удаляет запись управления шаблонами администратора. `/api/v1/templates` и `/api/v1/admin/templates`старое поле создания templateId и функции CRUD для таблицы old-table. Таблица document_templates, индексы, определения и записи остаются неизменными. Нет миграций, удалений, конверсий, двойного чтения/записи или автоматического регистрации этой таблицы в качестве поставщика. Неизвестные старые поля отклоняются. Существующие документы сохраняют свой сохраненный контент и ресурсы. Предыдущая версия может прочитать старую таблицу после возврата к исходному состоянию; документы, созданные новым сервисом, все еще используют текущие нативные модели.

Хост не устанавливает стандартные шаблоны или поставщиков материалов. `doca.documents.create` Это потребители документов; потребители электронной почты или публикаций относятся к бизнес-плагинам. Хранилища, корпоративные библиотеки, удаленные сервисы и оболочки папок требуют установленных ресурсных плагинов. Этот сервис сам по себе не реализует протокол удаленного ресурсного хранилища, администрирование ресурсного хранилища или официальный контент.

<a id="provider-contract"></a>

## Контракт с поставщиком

Поставщики шаблонов объявляют версию:1. Поставщики материалов объявляют версию:2 и коллекции. Другие объявления включают id/pluginId/title, поддерживаемые контракты/contentTypes/sorts, а также реализации тегов/search/describe, плюс чтение шаблонов или импорт материалов. Каждое вызвание получает хост-праймьер, requestId и сигнал отмены.

Ввод поиска состоит из полей contract/contentType/query/tags/providerIds/sort/cursor/limit. Длина query не превышает 1000 символов. Провайдеры выполняют поиск по ключевым словам, фильтрацию всех тегов, проверку доступности ресурсов и заданный порядок отображения, возвращая легкую метаданные без содержимого. Для скрытых/удаленных ресурсов возвращается null. Теги должны приходить только из ресурсов, которые могут быть обнаружены запрашивающим.

Карты требуют перерисовки. `{providerId,id,revision}`, название, описание, теги, время обновления, контракт, тип содержимого, параметры и лицензия. Необходимо предварительное просмотр шаблона; предварительное просмотр материала, использование и популярность — опциональные. Предварительный просмотр шаблона показывает реальный стиль, а не общий иконку. Выборщик отображает его на карточке; нажатие увеличивает изображение, а при необходимости загружается нативный просмотр. Просмотр принимает только данные URL формата PNG/JPEG/WebP, не более 180000 кодированных символов. Дистанционные поставщики получают и проверяют предварительные просмотры, а не выводят произвольные удаленные изображения напрямую в браузеры. Параметры используют подмножество ObjectConfigSchema SDK, а не произвольный JSON Schema. Хост отклоняет неизвестные поля и проверяет требуемые значения, типы, энумераторы и пределы. Базовый интерфейс использует простые вводы или JSON для сложных параметров; бизнес-плагины могут создавать свой собственный интерфейс.

Теги имеют стабильные идентификаторы `{zh,en}` Названия. Общие идентификаторы используются `doca.tag.…`Например, doca.tag.report/proposal; приватные идентификаторы используют пространство имён плагинов. Хост дублирует идентификаторы, а не имена отображения. Используйте однозначные метки public-tag, не раскрывая невидимые метки.

<a id="sorting-and-pagination"></a>

## Сортировка и пагинация

Каждый поставщик поддерживает обновленные данные по имени и может указать количество использования/ популярность. Между поставщиками обновленные данные отсортированы по времени, а по имени — по имени поставщика; providerId/id используется в качестве стабильного критерия для сравнения. Хост объединяет отсортированные потоки данных. Для показа количества использования/ популярности необходимо выбрать ровно одного поставщика. Эти данные не отражают сопоставимую популярность между поставщиками или глобальное использование на хосте.

Квизы UI по умолчанию включают 24 элемента, максимум 48; каждый поставщик может загрузить не более 24 элементов. Тела загружаются после выбора. Изменение ключевого слова/тега/типа/порядка/источника приводит к перезапуску квиза. Хост не загружает полный каталог для локальной фильтрации.

Хост-курсоры — это непрозрачное состояние локально для экземпляра, связанное с пользователем, нормализованным запросом и поставщиками. Они действуют в течение 15 минут; истечение срока, перезапуск или изменение поставщика приводят к ответу 410 и требуют нового запроса, без гарантий продолжения работы между экземплярами. Ограничения: 500 неискорченых курсоров, 100 поставщиков, 10000 элементов, пройденных по каждому поставщику, и 100 запросов на каждую агрегацию. Каждый вызов поставщика длится 15 секунд, а поиск — 30 секунд. Перед возвратом кэшированных кандидатов необходимо описать доступ к повторной проверке и возможность изменения результата. Повторные курсоры/ресурсы, неправильная последовательность и ошибки источника приводят к ошибкам или результату “false”, а не к пустому успеху.

Этот протокол просмотра не является замороженным инвентарем, системой синхронизации удаления или постоянным журналом изменений. Поставщики, нуждающиеся в этих возможностях, определяют отдельные контракты. Хост не сохраняет отражения ресурсного каталога, таблицы использования или миграции по улучшению ресурсов.

## Чтение, импорт и применение шаблонов

Шаблон read принимает `{ref,parameters}` и возвращается `{contract,contentType,content,assets}`Максимум 768 КиБ; хост добавляет источник. Измененная версия представляет собой конфликт и не может возвращать новый контент под старой версией.

Принимается импорт материалов `{ref,operationKey}`Провайдер перепроверяет доступ и использует файл v1 для импорта или выбора авторизованного файла, возвращая `{fileId}`Дистанционные импорты используют operationKey в качестве ключа идентичности создания файла и протокол contentIdentity/upload-receipt. Повторные попытки сохраняют тот же ключ; временные URL не являются постоянными ссылками. Хост снова проверяет текущие ACL файла и возвращает fileId/name/mime/size/source.

Ассеты шаблона содержат не более 100. `{key,ref}` Записи, указывающие на поставщиков материалов. Контент использует точные данные. `material:<key>` строки; Изображения в Markdown используются `](material:<key>)`Создание документа запрашивает/проверяет ресурсы вне транзакции записи, потому что плагины могут вызывать другие сервисы базы данных. Внутри транзакции проверяется, действительно ли регистрация экземпляра активна, создаются привязки хоста/ссылки на файлы для нового документа, заменяются плейсхолдеры на локальные идентификаторы активов, проверяются права, упоминания, размер и текущий формат, а также инициализируется сохранение данных. В случае ошибки новый документ и его ссылки откатываются. Пользовательские файлы, импортированные поставщиком, остаются, без неявного удаления, и сохраняют свой обычный жизненный цикл.

Шаблонная приложение инициализирует только новые ресурсы, не перезаписывая документы и не изменяя функцию сотрудничества. Удаление поставщика не устраняет активированные ресурсы, управляемые хостом, и созданные документы. Нативный предпросмотр поддерживает шаблоны без зависимостей от ресурсов; зависимые шаблоны используют изображения предпросмотра поставщика без неявного импорта ресурсов.

`POST /api/v1/resources` принимает `template:{ref,parameters}`Это взаимоисключающее отношение с markdown/initialContent; для создания пустого документа необходимо пропустить шаблон. Шаблоны потребителя документа принимают входные данные в виде названия с возможным родительским ID/ID библиотеки (не указывать при создании корневого документа), возвращая ID, название и формат. При обычном создании сохраняется эндпоинт resource-create. Бизнес-потребители могут использовать функции чтения или потребления, а также имеют возможность использовать ID импедентности бизнес-операций.

Создание документа всегда предполагает создание пустого документа, затем соответствующие шаблоны плагинов, фильтры источника/ключевого слова/тега/порядка, функция загрузки больше, предпросмотр и параметры. Диалоговые окна загрузки/папок предоставляют библиотеку материалов и передают выбранные материалы в существующий процесс загрузки/вставки.

Создание шаблонов требует одобрения ИИ, определения объема ресурсов и сохранения документов. Бизнес-шаблоны используют соответствующие инструменты плагинов. Хост не реализует поисковую систему или семантическую модель; поиск относится к поставщикам.

## Область проверки

Изолированные проверки охватывают нулевых поставщиков и сохранение старых таблиц, отклонение старых путей, инициализацию в пяти форматах, материальные ACL/связи, удаление дубликатов меток, объединение/пагинация, сбой поставщика, неактивные учетные записи, конфликты ревизий, параметры/потребители, право собственности на плагин/разработчики, изоляция во время выполнения, и идентификация по HTTP. <a id="multiple-providers-and-retrieval"></a>

## Множество поставщиков и процессы извлечения

Внедренная правка от 2026-10-02 заменяет поле query providerId на providerIds. Старое одночисленное поле query отклоняется сервисами, HTTP-клиентами и инструментами ИИ без адаптации или неявной конвертации. Указатели ресурсов `{providerId,id,revision}` Они остаются неизменными. Параметры шаблонов, файлы, документы, бизнес-данные и документные шаблоны не мигрируют/удаляются. Не вводится никакое преобразование данных в соответствии с предпочтениями поставщика. Работа с клиентами запросов также должна быть откатана; локальные курсоры инстансов требуют нового запроса после перезапуска или изменения поставщика.

Каждый поставщик — это один источник с стабильным идентификатором и названием, указанным в плагине; опциональное двуязычное описание не превышает 1000 символов на язык. Плагин может регистрировать несколько источников. Doca не выводит реализацию источника из категорий сети/магазина/генерации. Параметр providerIds выбирает все соответствующие источники; &#91;&#93; выбирает ничего. Множество идентификаторов используют оператор OR, в сочетании с типами/тегами — оператор AND. Неизвестные/незагруженные идентификаторы возвращают 404 без расширения диапазона. Параметры discovery/list/tags/retrieval используют один и тот же выбор; курсоры связывают дублированные отсортированные идентификаторы. Параметры usage/popular требуют одного явного источника.

Список и описание возвращаемого значения CreationResourceResult: оригинальная карта плюс карта, созданная хостом `source:{id,pluginId,title,description?}`Плагины не могут подделывать источник. Результаты чтения/импорта хоста также включают источник; контракты, возвращаемые поставщиками, остаются неизменными. Метаданные источника отражают текущую регистрацию и не записываются в содержимое ресурса/документа. Управляющий интерфейс отображает названия источников, описания и принадлежность карточек.

`templates.retrieve` / `materials.retrieve` принимает:

```ts
{
  query: "找一份适合向管理层汇报季度经营情况的模板", // 非空，最多 1000 字符
  providerIds: ["example.templates.web", "example.templates.company"], // 可省略
  contract: {id: "doca.document.rich_text", version: 1}, // 可选
  contentType: {id: "doca.native.rich_text", version: 1}, // 可选
  tags: ["doca.tag.report"], // 可选，AND
  mode: "auto", // auto | keyword | semantic | hybrid，默认 auto
  topK: 8, // 默认 8，最多 20
}
```

Поставщики заявляют `retrieval:{modes:["keyword","hybrid"]}` И реализовать метод retrieve(context, input). Для автоматических систем они выбирают объявленный режим и возвращают реальный режим; явный режим не может бездумно ухудшать ситуацию. Не объявленные возможности возвращают неподдерживаемый результат вместо того, чтобы провести поиск. Поставщики контролируют базу данных/Meilisearch/vector/remote, а также их индексы, модели, ключи и синхронизацию.

Провайдер возвращает результаты `{items,mode,hasMore}` Сортировка по локальной релевантности. Кандидаты содержат поля ref/title/summary/tags/contract/contentType и опциональное поле matchText (максимум 500 символов), за исключением текста, изображения и параметров схемы. Хост проверяет источник/тип/теги/дубликаты/текущий доступ/ревизия, затем добавляет источник и локальный рейтинг. Краткие описания и объяснения совпадений являются данными, а не инструкциями ИИ.

Каждый выбранный источник получает не более одного запроса на извлечение данных, без перемещения курсора. Один источник возвращает не более topK элементов; несколько источников возвращают не более min(topK,5) элементов каждый. Ограничения: 4 одновременных источника, 15 секунд в общем времени, 100000 байт ответов на один источник. Представление данных между источниками учитывает локальный рейтинг и стабильные идентификаторы, без сравнения оценок движка или утверждения глобальной значимости. Окончательный результат не превышает topK источников. Результаты включают информацию о успешных запросах, реальных режимах, количестве кандидатов и оставшихся кандидатах. Ошибки обрабатываются с использованием кодов stable unsupported/failed/timeout. “complete” означает, что все выбранные источники успешно работают; “truncated” означает, что кандидаты были опущены. Пустые результаты не расширяют область исследования.

Базовые пикеры показывают строки источников/тегов внутри экрана с параметром «Все выбрано по умолчанию». Источники поддерживают множественное выбор, а теги — однократное выбор; переполнение скроллирует горизонтально. Иконка фильтра расширяет возможность поиска по ключевым словам и сортировки. Закрытие окна закрывает панель и показывает вводную запрос, расположенный рядом с названием результата. Пустые запросы сохраняют пагинацию просмотра. Интеллектуальный поиск возвращает ограниченное количество кандидатов и загружает предпросмотры карточек по требованию, без импорта активов. Ошибки и лимиты результатов указаны явно. Источники можно очистить; теги приходят только из выбранных источников. Пикеры принимают начальные значения providerIds и на событии onSourcesChange (undefined=все, &#91;&#93;=нет), что позволяет плагинам передавать выбранные значения в собственные интеллектуальные/бизнес-запросы.

ИИ преобразует имена в идентификаторы источников через creation_resource_providers, затем отправляет ключевые слова или полный запрос в creation_resource_retrieve. Оба типа ресурсов используют одни и те же инструменты и текущую идентификацию. В процессе извлечения нет миниатюр; инструменты просмотра также удаляют схемы параметров. После выбора описание/чтение/импорт предоставляют детали. Проверки включают исключения, пустые результаты, неподдерживаемые/неисправные источники, отмену, повторную проверку доступа, связанные указатели, каналы плагинов, а также вызовы реальных инструментов ИИ.

## Сборка материалов

Внедренная ревизия от 2026-10-03 использует `materials.v2` / MaterialsServiceV2. Поставщики должны использовать версию 2 и коллекции. Старые материалы версии v1, версия 1, не имеющие коллекций, а также старый единичный курсор материала отклоняются без адаптеров, параметров по умолчанию, двойного чтения или конвертации. Шаблоны остаются шаблонами версии v1. Файлы, содержимое документов и ссылки на ресурсы не изменяются. Никакая миграция или удаление таблиц материалов или данных не вводится. Роллбэк должен координироваться между хостом, SDK, пикерами и инструментами ИИ, а также перезапускать локальные запросы инстанса.

Материалы принадлежат нулю или нескольким коллекциям из одного источника, без копирования файлов. Коллекции/элементы имеют отдельные метки, без наследования. Провайдеры управляют массовыми загрузками, управлением коллекциями, членством, авторизацией и сохранением данных через публично управляемые SQL/объект/файловые сервисы; они не могут выбирать независимые базы данных или обходить процесс загрузки в директории установки. Коллекции, объединенные из разных источников, не подпадают под это протокол.

Материальные карты/кандидаты на извлечение требуют `collections: CreationResourceRef[]`&#91;&#93; означает «ничего». Поставщики возвращают только коллекции, видимые вызывающему программе. Метаданные коллекции включают ref/title/summary/tags/updatedAt/contracts/contentTypes, а также опциональные параметры preview/count/usage/popularity. Параметр count должен отражать видимые элементы, а не общее количество предметов. Коллекции не содержат содержимого, параметров, лицензии или встроенных предметов. Кандидаты для поиска исключают параметры preview/updatedAt/usage/popularity и могут включать matchText. Хост добавляет информацию о источнике и, для поиска, локальный рейтинг.

`collections: null` Явно указываются поставщики, предоставляющие только элементы. Поставщики коллекций реализуют `{tags,search,describe,retrieval?,retrieve?}` С использованием идентификатора/сигнала. Поддержка списков и поиска материалов независима; поиск материалов не может заменить поддержку списков. Контракты коллекций и типы контента описывают типы членов, которые можно использовать. Фильтры по типу соответствуют любым объявлениям; метки используют оператор AND, а ссылки на коллекции – оператор OR. Изменения членства обновляют ревизию коллекции и ссылки на материалы в коллекции. Описание коллекции обеспечивает доступ/версию; хост снова проверяет данные перед и после запросов членов, а также при продолжении работы.

Пример:

```ts
const page = await host.platform.materials.search({
  query: "夏日配色", providerIds: ["example.palette.library"],
  tags: ["doca.tag.color"],           // 只筛素材
  collectionTags: ["doca.tag.theme"], // 只筛素材集
  target: "all",                    // all（默认）| materials | collections
  limit: 24,                        // 各组独立上限，最多 48
  cursors: { materials: null, collections: null },
});
// { materials: {items,nextCursor,complete,failures}, collections: {...} }
const members = await host.platform.materials.collectionItems({
  ref: page.collections.items[0].ref, limit: 24, cursor: null,
  query: "红色", tags: ["doca.tag.color"],
}); // 单一素材分页，不内嵌后续成员
const related = await host.platform.materials.retrieve({
  query: "适合夏日海报的暖色背景", target: "materials",
  collectionRefs: [page.collections.items[0].ref], topK: 8,
});
```

Поиск/получение возвращает фиксированные группы материалов и коллекций, каждая из которых имеет свои состояния завершения/неудач и состояние курсора/обрезки, без смешивания или повторного встраивания членов. При одном целевом объекте другая группа является пустой/завершенной, и ее поиск не вызывается. Курсоры не могут пересекать группы; целевой объект может быть только один. Ограничения/topK применяются отдельно для каждой группы. Опустив коллекцииRefs — выбираются все материалы, &#91;&#93; — ничего не выбирается; коллекцииRefs требует явного указания целевого объекта и материалов. Явные providerIds не могут исключить источник отсылываемой коллекции (400); неизвестные источники возвращают 404. теги возвращают отдельные данные. `{materials,collections}` groups.collectionDescribe(ref) возвращает только метаданные; collectionItems({ref,...}) возвращает одну страницу материала с использованием базового запроса/tags/contract/contentType/providerIds/sort/cursor/limit contract.

Отображение данных поддерживает параметры источник/тип/элемент и метки коллекций, а также параметры запрос/режим/topK/цель/коллекцииRefs. Каждая группа использует один источник, максимум 4 параллельно для одной группы (8 для обоих), при этом максимум 20 окончательных результатов для каждой группы. Кандидаты с обновленными данными из одного источника также подчиняются ограничению в 100000 байт. Общий бюджет составляет 15 секунд, включая проверки коллекций. Отображение данных неподдерживаемых коллекций невозможно без указания пути по коллекции. Пагинация по поиску/членам занимает 30 секунд. Группы имеют независимые сессии/бюджеты без единого объединенного требования к релевантности разных типов данных.

У устройства для сбора материалов есть вкладки «Материалы» и «Коллекции». Внутри коллекции отображается источник/название, страницы, в которых содержатся элементы коллекции, поддержка ключевых слов/интеллектуальных запросов, а также возможность возврата к коллекциям. Просмотр/предварительное просмотр не импортирует файлы; выбор элемента запускает процесс импорта. В деталях отображается количество участников коллекции. Интеллектуальный поиск возвращает оба типа данных: коллекции помогают в создании целостных тем, элементы коллекции помогают в точных запросах, без необходимости двойного запроса. Доступны функции material_collection_describe и material_collection_items; связанные элементы в коллекции используют метод поиска с использованием collectionRefs вместо сканирования всех элементов.

Изолированные проверки охватывают множество/нет членства, независимые указатели/теги, исключение источников, фильтрацию членов, доступ к коллекциям/изменения в ревизиях, некорректные декларации, повторные проверки членства, получение данных без обхода, как диспозиторы директорий, инструменты ИИ, как HTTP-каналы, а также независимые артефакты SDK. Изолированная страница браузера, проверенные карточки коллекций, просмотр членов, интеллектуальные запросы к коллекциям и возвратная навигация без редактирования документов пользователя.
