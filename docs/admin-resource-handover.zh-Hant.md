# 管理員資源交接

[English](admin-resource-handover.md)

系統管理員在「後臺管理 → 使用者管理」找到已停用賬號，點選「資源交接」。選擇接收人和資源，預覽實際變更後確認。接收人必須是另一個正常使用的賬號，原賬號交接後保持停用。普通使用者沒有此入口，三個交接介面也獨立校驗管理員當前身份。

<a id="资源范围"></a>

## 資源範圍

清單來自現有資源、資料夾、檔案及授權記錄，僅顯示名稱、型別、歸屬和回收站狀態等管理後設資料，不讀取正文或私有憑據。

| 類別 | 行為 |
| --- | --- |
| 文件、知識庫、知識冊 | 轉移所選資源及其後代中原賬號擁有的資源；其他人的所有權保留，關聯內容在預覽中單列。知識庫所有者的現有管理範圍適用於接收人。 |
| 文件圖片和附件 | 文件對應的 assets 及檔案目錄項隨文件轉移，檔案不能脫離文件單獨交接。上傳者和歷史作者不變。 |
| 普通資料夾、檔案 | 轉移所選目錄中原賬號擁有的後代及檔案。所選子目錄或獨立檔案的父目錄未交接且不屬於接收人時，移至接收人的個人根目錄；預覽會標明。 |
| 文件、知識庫保留的授權 | 可以單獨勾選。將選中節點的有效授權授予接收人，並移除原賬號在該節點的有效授權來源。繼承範圍保留，連結令牌不會轉交。 |
| 共享資料夾授權 | 合併為接收人的資料夾授權，保留接收人已有的較高角色，移除原賬號的該項授權。 |
| 回收站中的資源 | 可以交接，繼續保留回收站狀態。 |

個人 AI 檔案、私有會話、憑據及外掛業務資料不在交接範圍。現有 AI/知識會話檔案繫結和普通鎖定檔案仍受原業務限制；無法識別的後設資料也不自動改寫。文件附件本身的檔案管理鎖定不阻止其隨文件交接。清單會說明不能選擇的檔案；所選目錄包含受保護的檔案時，整批阻止執行。

<a id="预览与权限冲突"></a>

## 預覽與許可權衝突

預覽展示實際所有權、授權、附件變化，位置調整，以及保留其他人所有權的關聯內容。父級選擇自動展開，不必重複勾選子項。每批最多選擇 500 個清單項，展開的後代可能更多；清單和預覽按每頁 50 項顯示。

接收人的較高授權不降級。原賬號的本節點和後代角色無法無損合併、原賬號子級存在限制而交接會擴大許可權，或者接收人已有明確限制時，預覽列出衝突並禁止確認。管理員需要先按現有許可權流程複核，或調整選擇。不會以管理員身份跳過這些許可權限制，也不會複製無關的繼承許可權。

所選文件或資料夾上，原賬號和接收人的待接受邀請會取消，避免稍後接受舊邀請覆蓋交接結果。文件邀請保留歸檔及工單，資料夾邀請保留取消狀態及工單；其他人的邀請不變。取消數量在預覽中展示。公開範圍、分享連結定義及其他協作者保持原設定；公開訪問也不會因交接變為使用者黑名單。

<a id="一致性和审计"></a>

## 一致性和審計

清單、預覽使用資料庫一致性快照；提交時重新計算預覽指紋。相關賬號、資源、授權、附件或目錄內容發生變化後，舊確認返回 409，必須重新整理並重新預覽。兩位管理員同時提交同一批次，只能成功一次。

一次確認在一個資料庫事務中完成所有歸屬、授權、邀請、索引任務和安全審計變更。接收人的現有接納/配額策略仍會執行；任一步失敗則整批迴滾。檔案實體不搬運或刪除，正文、版本歷史、上傳者和原始作者均保留。提交後重新整理線上許可權並通知涉及賬號。

安全審計動作是 `user.resources_handed_over`，記錄實際管理員、原賬號、接收人、預覽指紋、變更和變更前的相關後設資料。原賬號審計記錄不包含接收人的無關私有授權。當前使用同步批次，沒有跨程序續跑的後臺任務；瀏覽器斷開或響應丟失後先重新掃描清單，避免把已成功的批次當成失敗重做。

本功能沿用現有表及資料格式，無資料庫結構或歷史資料轉換。不提供自動反向交接或自動恢復舊許可權；需要糾正已確認的業務決定時，應根據審計記錄重新核實資源及授權後操作。

<a id="接口和验证"></a>

## 介面和驗證

- `GET /api/v1/admin/users/:id/resource-handover`：資源清單。
- `POST /api/v1/admin/users/:id/resource-handover/preview`：`targetUserId`、`keys`。
- `POST /api/v1/admin/users/:id/resource-handover/execute`：相同選擇加上預覽返回的 `fingerprint`。

核心及介面迴歸：`pnpm exec vitest run tests/resource-handover.test.ts`。真實後臺流程：`pnpm exec tsx scripts/qa-resource-handover.mts`，使用隔離 SQLite、賬號、文件和檔案儲存，輸出到 `artifacts/verification/resource-handover/`。這不代表已完成 PostgreSQL 的執行驗證。
