# MCPサービス

[简体中文](mcp.zh-CN.md)

Docaは、外部の顧客に対して自社のアシスタントツールやSKILLマニュアルを公開している `POST /api/v1/mcp`個人設定 → MCPはログインしたユーザーとして機能するサービスを管理する。管理者 → 企業用MCPサービスは、有効な名前を明確に指定したインテグレーションを管理する。 `userId` すべての操作において。企業トークンには活動中の管理者作成者が必要であり、他のユーザーとして操作する際には、その作成者のリソース権限を継承することはありません。

各サービスには、独立したベアラートークン、有効化スイッチ、オプションの有効期限があります。 `all` または `selected` 許可。 `all` 利用可能なツール/スキルカタログに従い、後から追加されるものも含まれる。 `selected` 記録されたツールとSKILL IDのみを表示します。ツールのグレード付与は、その操作を実行するための承諾であり、リソースのACL、ストレージ制限、ダウンロード制限、アカウントの状態、ホスト/プラグインのアクセスポリシーを拡大するものではありません。SKILLはツールの権限を付与することはありません。公式の、インストール済みプラグイン、有効化された個人マニュアルは、有効なユーザー向けにフィルタリングされます。

<a id="connect-a-client"></a>

## クライアントを接続する

すべてのサービスでCodexコマンドが表示されます。 `config.toml`HTTPの初期化/検出の例、およびAIがそれをインストールするためのコピー可能な指示。トークンは作成/リセット後にのみ表示され、リストには最終的な8文字のみが含まれる。データベースにはSHA-256トークンハッシュが保存される。URLにトークンを含めたり、設定ファイルにコミットしたりしないでください。

```toml
[mcp_servers.doca]
url = "https://docs.example.com/api/v1/mcp"
bearer_token_env_var = "DOCA_MCP_TOKEN"
```

設定 `DOCA_MCP_TOKEN` クライアントを起動する環境で。CLIの場合は：

```sh
codex mcp add doca --url 'https://docs.example.com/api/v1/mcp' --bearer-token-env-var DOCA_MCP_TOKEN
```

AIのための一文：「docaというStreamable HTTP MCPをインストールする」 `https://docs.example.com/api/v1/mcp`、そのBearerトークンを読み取る `DOCA_MCP_TOKEN`次に初期化を確認し、利用可能なツールやSKILLをリストアップします。企業向けサービスには、「対象ユーザーの…を通過させる」と追加してください。 `userId` すべての `doca_*` 「操作」

Codexには独自のツール承認ポリシーがあります。UIもそれを提供しています。 **任意** 無人設定： `[mcp_servers.doca.tools.doca_call]` と共に `approval_mode = "approve"`この機能は、そのクライアントがサービスで提供される機能を事前承認する意図がある場合にのみ使用してください。デフォルトの接続例ではこの機能は有効になりません。詳細は [公式MCP設定](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) そして [ツール承認設定](https://learn.chatgpt.com/docs/config-file/config-reference).

## 発見し、実行する

1. 電話する `doca_tools` 完全なタスクが完了した `purpose`. オプション `resources`, `files`, `currentResourceId` そして `currentFolder` 既存のドキュメント/ファイルのUUIDを使用して明示的なコンテキストを提供する。ファイル参照には、アシスタントが使用する同じ承認済み入力スナップショットが与えられる。結果には… `contextId`、独立した `taskId`そして、簡潔なカタログです。会話は生まれません。
2. 電話する `doca_describe_tools` それで `contextId` 完全な入力スキーマを取得するために、最大4つのツールIDが必要です。次の操作に必要なスキーマのみを取得します。
3. 対応するマニュアルを読み終えなさい `doca_skills`/`doca_load_skill`、または標準のもの `doca_skill` MCPプロンプト。これらは現在のカタログを読み取ります。無効になったプライベートSKILLは利用できなくなります。
4. 電話する `doca_call` 順次に `contextId`新しいUUID `requestId`, `tool` そして `input`ネイティブの編集では現在のものを使用する `seq`, `epochId`通常のドキュメントツールによって返されるIDやコマンドです。これは同じアシスタント実装であり、同じネイティブコーデック、トランザクション、通知、およびDocaプロバイダが実際に呼び出された時のオリジナルのAI利用帳簿も含まれます。外部クライアントモデルの使用はDocaの帳簿には含まれていません。
5. 電話する `doca_context_close` 完了したら。保存された文書やファイルは残ります。保留中のアップロードバッファとローカルでの視覚検査状態が解放されます。

個人操作は省略される `userId`それを提供することは拒否される。企業は、毎回アクティブなターゲットユーザーのUUIDを提供しなければならない。コンテキストはサービスや実際のユーザーを変更することはできない。検索、読み取り、書き込み、ダウンロードは、そのユーザーの権限を確認する。監査では、入力情報の秘密は記録せず、サービス作成者、実際のユーザー、コンテキスト、リクエストID、ツール、結果が記録される。

`requestId` そのコンテキスト内では、最大一度の実行を提供します。繰り返されるIDは、記録された状態とHTTP/ツールの衝突を引き起こし、異なるパラメータでは再使用できません。キャッシュされたプライベートコンテンツを再再生したり、完了した可能性のある書き込みを盲目的に再試行したりすることはありません。不確かな結果の後、新たな書き込みを行う前に保存されたリソースを確認してください。通常のネイティブやファイルワークフローは、既存の耐久性のある記録を保持します。

## ファイル

ネイティブ `file_browse`, `file_manage`, `file_folder_manage`, `file_read` そして `file_create` ツールは引き続き利用可能です。 `file_download` アシスタントを保持するという意味：公開されているウェブファイルを取得する **中に** ドカ。

実際の顧客の送金については：

- `file_upload_begin`ファイル名、MIMEタイプ、宣言されたサイズ、オプションのSHA-256。最大20MiB、またはより厳格なユーザー制限が設定されている場合もあります。
- `file_upload_chunk`：標準的なBase64、連続的なバイトオフセット；最大解読可能なチップは128KiB。
- `file_upload_complete`完了したアップロードをユーザーフォルダのUUIDに保存する、または `folderId:null` ユーザーのルート用です。アップロードはサービスコンテキストと有効なユーザーに結び付けられます。
- `file_upload_abort`保留中のアップロードを解放する。
- `file_content`Base64による承認されたバイト範囲のダウンロード、完全ファイル/チャンクのSHA-256、ファイルバージョン `nextOffset`同じバージョンを次のファイルにも適用する。変更されたファイルは拒否し、バージョンを統合しない。

これらの方法はホストファイルサービスを再利用します。ブラウザのクッキーやサーバーのファイルシステムパスは必要なく、コンテンツを読み取ったURLをダウンロード許可の回避手段にすることもありません。

## 輸送と寿命

エンドポイントはSDK 1.30.0におけるステートレスでStreamable HTTPを使用しており、明示的に受け入れられているプロトコルバージョンがある `2025-11-25`, `2025-06-18` そして `2025-03-26`初期化ではサポートされているバージョンを指定する必要があります。その後のリクエストでは必ずそれを含める必要があります。 `MCP-Protocol-Version`GET/DELETEは認証済みの405応答を返します。既存のホストチェックが適用され、有効でないOriginは拒否されます。廃止されたHTTP+SSEや古いトークンアダプターは提供されません。

実行コンテキストには15分間のアイドル期間があり、サービスあたり最大16個、インスタンスあたり128個のアクティブ/保留中のコンテキストがあります。1つのコンテキスト内での呼び出しは順序立てて行われます。ツール/スキルの権限、トークン、アクティブユーザーは再確認されます。トークンのリセットや取り消し、サービスの無効化、個人用MCPのオフスイッチは、そのコンテキストの有効性を無効にします。ホストレート制限器を使用するサービスあたりのHTTPリクエスト制限は、1分あたり600件です。リクエストボディのサイズは1MiBに制限されます。

コンテキスト実行と視覚的証明はインスタンス局所的です。アクティブなコンテキストを同じインスタンスにルーティングします。再起動後、有効期限が切れたり別のインスタンスにルーティングされた場合、新しいコンテキストを開き、既存のアーティファクトを確認します。自動的な継続や視覚的証明の復元は行われません。ネイティブの文書データは通常の持続可能なストレージに保持されます。プロバイダの認証情報、秘密値、ブラウザセッション、任意の以前のチャット履歴はMCP設定としてエクスポートされません。

## 実行履歴とアップグレード

MCPとチャットは、タスクのリース、キャンセル、リソース承認、ツールの実装、操作受領書、プロバイダの使用状況情報、セキュリティ監査を共有する。MCPは、 `ai_jobs` NULLでの実行 `session_id` そして `model_id`; それは生成しません `ai_sessions` 行、チャットメッセージ、またはメモリスレッド。実際のプロバイダー呼び出しは、その実際のモデルと使用状況を記録しています。 `ai_calls`.

個人設定 → MCP → 実行履歴には、そのユーザーが実行した企業サービスタスクを含む有効なユーザーのタスクが表示されます。承認されたリソースリンク、通話状況、閉じられた実行履歴の停止や削除がサポートされています。履歴を削除しても、保存された文書、生成されたファイル、操作受領書、元のプロバイダの使用状況、セキュリティ監査の事実は保持されます。生成された画像はAI出力ディレクトリの制限を保持し、明示的な情報を含みます。 `aiTaskId` 会話フォルダなしでバインドされる。タスクは自分の受領書のみを読みます。NULLの会話関連性は、無関係な実行をグループ化しません。

所有者は2026-11-01に直接分離を承認しました。現在のDDLは以下の通りです。 `ai_jobs.session_id`, `ai_jobs.model_id` そして、保持されたもの `mcp_contexts.session_id` 既存のネイティブ列調整機能を通じて空の値を処理する。新しい `ai_task_resources` レジャーは空の状態から始まり、宣言される `schemaEvolution`バックファイルや互換性生成の変更はありません。過去のMCP会話、コンテキスト、ファイル、承認情報、監査行は全く変わらず保持され、チャットエントポイントから除外され、変換や再開もされません。以前にインストールされたフィールド/テーブルは、既存のインストールファイルによって保護され続けます。

プラグインSDKソース0.2.0が公開される `ai.v2` / `ai.continuations.v2`: `jobId` 必要であり、 `sessionId` 会話ベースの実行のためのみ存在する。プラグインパッケージを再構築する `sdkRange: "^0.2.0"`ホスト、Web、プラグインは一緒に更新する必要があります。古いサービス契約やSDK範囲は拒否され、古いインターフェースアダプターや自動ダウングレードはありません。アップグレード前にデータベース/ファイルのバックアップを保持し、アプリケーションバイナリを復元する前に別途審査される復元処理のために後続のタスク/ファイルの書き込みを保持してください。参照してください。 [検証](verification/mcp-execution-decoupling-2026-11-01.md).

## ストレージおよび退役したMCP

オーナーは2026年10月20日に使用されていない古い実装を廃止することに同意しました。 `/ai/mcp-keys` そして、古い4つのツールアダプターが取り除かれる。 `doca_mcp_…` 認証情報が拒否され、新しいトークンが使用される `doca_mcp_v1_…`。不活性 `ai_mcp_keys` table/rowsは、保存されたデータを保持するためにのみ存在する。実行時にはそれらを読み込まず、認証情報や権限も変換されない。

`mcp_user_settings`, `mcp_services`, `mcp_contexts` そして `mcp_tool_calls` 現在のDDLで宣言されている空の追加要素テーブルがある `schemaEvolution`既存のユーザーは、新しい設定行が存在しないため、個人用MCPが無効の状態で開始されます。企業向けサービスの利用は、その設定とは独立しています。既存の文書、ファイル、ACL、AIセッション、設定された値、互換性生成内容は保持されます。構造的なレビューによる拒否や合意形成の失敗は、部分的な永続的な変更はありません。以前にインストールされていたMCPテーブルが削除されると、データ損失が発生し、無意識に再作成されることはありません。

プレアップグレード前のバックアップを保持し、サーバー/Webのアップグレードを同時に行う。古いバイナリは新しいトークン/グラント/コンテキスト契約を適用しない。自動的なアプリケーションのダウングレードやデータの削除はない。新しい記録を保持し、古いデプロイメントに戻る前に回復状況を確認する。詳細は…を参照してください。 [データベースアップグレード契約](database-schema-evolution.ja.md) そして [受容証拠](verification/mcp-2026-10-20/README.md).
