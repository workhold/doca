# 使用者組與組授權

[English](user-groups.md)

使用者組入口位於側欄「共享資料夾」下方。列表展示自己加入的有效組，包含頭像、組名稱和所有者；組內展示全部成員及角色。內部 ID 不作為頁面資訊展示。頭像可上傳並裁剪為 PNG。

<a id="成员与角色"></a>

## 成員與角色

所有者和管理員可以搜尋使用者傳送邀請，或生成七天有效的邀請連結。新成員必須登入並主動接受，始終以普通成員加入。名稱邀請沿用現有使用者目錄校驗；在「相關許可權使用者」範圍下，同一有效組成員也構成關聯。組內成員列表按組成員身份可見，獨立於全站候選使用者搜尋範圍。

| 操作 | 所有者 | 管理員 | 普通成員 |
| --- | --- | --- | --- |
| 檢視全部組成員 | 是 | 是 | 是 |
| 編輯名稱、頭像；邀請成員；撤銷邀請連結 | 是 | 是 | 否 |
| 移除普通成員 | 是 | 是 | 否 |
| 設定或取消管理員、移除管理員 | 是 | 否 | 否 |
| 交接所有者、解散組 | 是 | 否 | 否 |
| 退出組 | 先交接 | 是 | 是 |

所有者僅可交接給組內正常使用的成員。管理員不能操作其他管理員或所有者。邀請接受時重新校驗邀請人當前身份、賬號狀態、有效期及組狀態。邀請連結只存雜湊，重建或撤銷後舊連結失效。

<a id="资源权限与邀请制"></a>

## 資源許可權與邀請制

文件、知識庫、知識冊共用宿主資源許可權；共享資料夾及其下檔案也支援組許可權。在「邀請協作者」內選擇「個人」或「使用者組」，上方輸入名稱搜尋並選擇，下方授予許可權。協作者頁只展示和管理已有個人、組授權，不展示新增授權的搜尋表單。外掛自有許可權介面卡不自動獲得新的組介面。

每條已生效組授權預設只展示前 3 位正常成員的頭像，懸停或啟用頭像可檢視現有使用者卡片。「更多（+人數）」在浮層內展開更多頭像，可繼續分頁，不增加授權行高度。成員讀取沿用當前資源的管理許可權，並重新檢查該組授權仍有效；未接受的新組邀請不展示名單。成員介面只返回顯示所需身份與頭像，卡片複用現有使用者資料介面，不開放外部組管理頁。

個人與組授權共用兩行的公共授權行元件：第一行左側頭像、名稱，右側許可權選擇和刪除圖示；第二行放賬號、來源或組成員頭像，右側放「包含子文件」。個人另有許可權來源入口。刪除使用按鈕旁的氣泡二次確認，取消不寫入，失敗保留氣泡與當前位置。知識庫及其文件可單獨調整「包含子文件」，修改角色時預設保留該範圍。知識庫管理許可權下限在子文件中只讀，需要回到知識庫調整；資源管理者不能修改管理授權。

個人授權和使用者組授權按使用者確認繼續獨立計算，取最高生效許可權。只有組來源的個人行仍可新增個人授權；沒有個人來源時，個人刪除按鈕不可用，應在對應組行撤銷組來源。個人角色低於其他來源時顯示生效許可權，資訊入口列出所有權、個人、繼承、連結和組來源。普通繼承的個人授權可在當前文件覆蓋或取消，庫管理下限保持原規則。共享資料夾沿用現有個人共享聚合記錄，連結加入標記展示在該個人來源上，組來源單獨列出；不會憑空拆分歷史個人/連結授權。只有資源管理者可列舉組來源的協作者。

文件類資源支援閱讀、評論、編輯、管理；共享資料夾支援閱讀、管理。只有資源所有者可授予或調整管理許可權。組角色與資源角色獨立：普通組成員也會獲得組已被授予的資源角色。

組授權獨立儲存，執行時按當前有效成員關係計算，不復製為個人授權。個人授權、各個組授權、連結和公開訪問分別計算；移除個人許可權不會自動撤銷組來源。組許可權遵守資源繼承邊界和下級範圍，庫管理許可權沿用現有管理下限。

沿用資源邀請策略：直接模式即時生效；邀請模式的新授權、升級或擴大下級範圍，需組所有者或管理員接受。接受時重新校驗邀請人當前資源許可權、授權能力和當前組成員准入限制。退出、移除成員或解散後，對應組來源立即失效；使用者仍可能透過其他獨立來源訪問。已連線協作會話重新鑑權；搜尋和知識索引重建，知識查詢返回前也檢查當前許可權。

資源所有權交接不改寫組授權。舊所有者選擇不保留個人管理授權後，仍可能透過組訪問，介面會提示。後臺停用賬號的資源交接清單包含其擁有的組；接收人必須已是該組有效成員，預覽後成員變化會使執行失效。

<a id="用户组搜索范围"></a>

## 使用者組搜尋範圍

管理員在後臺「許可權與可見性 → 使用者目錄」配置獨立組搜尋策略，可設站點預設並按使用者覆蓋，初始為「僅自己所在的使用者組」。

| 範圍 | 可以搜尋的組 |
| --- | --- |
| 僅所在組 | 自己當前加入的組 |
| 所在組和有許可權交集的組 | 所在組，以及與自己對同一文件、知識庫或共享資料夾擁有顯式許可權的組；包含有效繼承，公開可見不算關聯 |
| 所有有效組 | 所有未解散組 |

搜尋只返回組 ID（內部選擇用）、名稱、頭像和所有者名稱，不開放外部組成員頁。組獲得資源許可權後，成員成為資源協作者；資源管理者可在許可權頁檢視有效協作者，使用者目錄也會按已有顯式許可權交集規則建立關聯。這與直接檢視外部組成員頁是不同入口。後端重新校驗新授權的組範圍，不能透過提交越界 ID 繞過。收窄範圍不撤銷已有授權和邀請，資源管理者仍可移除已有組授權。分頁遊標繫結使用者、查詢條件和策略版本。

<a id="解散与清理"></a>

## 解散與清理

解散事務先標記組失效並重新整理關聯資源許可權。服務啟動時及每小時清理一次：清理超過 24 小時的已解散組關聯，單批最多 100 個。刪除成員、邀請、連結與組授權行，保留組失效記錄及安全審計。關聯正文、個人授權和其他連結保留；`cleaned_at` 防止重複處理。

<a id="已批准的升级"></a>

## 已批准的升級

按最新 DDL 與 `schemaEvolution` 新增八張表，相容代際不變。組、成員、邀請、連結、兩類組授權和資源邀請七張表從空開始；獨立策略表首次安裝明確寫入 `system/member/revision=1`，使用者覆蓋從空開始。原有個人/連結授權、邀請、公開設定、使用者目錄策略及資料不轉換。已安裝後的策略行丟失會報衝突，不靜默重設預設。

部署前備份資料庫、檔案卷與原配置，所有服務例項及 Web 同步更新。舊二進位制可能拒絕新結構；降級須另行評審保全與恢復方案，不透過刪表、重置或丟棄新寫入降級。見[驗證記錄](verification/user-groups-2026-10-30.md)。
