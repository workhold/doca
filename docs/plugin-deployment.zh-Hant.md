# 外掛安裝與部署

0.1.26 使用與核心庫分開的[外掛共享業務資料庫](plugin-database-isolation.zh-Hant.md)，自動建立外掛名稱空間，取代 0.1.25 的每外掛獨立庫。升級須先在舊宿主正常解除安裝，再重灌，不遷移外掛資料。

[English](plugin-deployment.md)

已確認的[託管儲存規範](plugin-horizontal-scaling.zh-Hant.md)要求 `doca.storage: "host"`，持久化歸宿主。靜態拒絕、託管 SQL 與內部物件已實現；託管憑證已在 SDK 原始碼 0.1.8 實現；臨時工作區與叢集業務任務排空仍待實現。外掛不選擇本地/遠端後端，也不接收業務資料目錄。

管理員透過「管理 → 外掛商店」瀏覽官方外掛、上傳本地 ZIP、安裝、升級、啟用、禁用和解除安裝。操作先儲存為全站期望配置，每個例項重啟後生效。頁面分別顯示全站目標版本與響應當前請求的例項執行版本，不代表全站所有例項均已更新。

```dotenv
DOCA_PLUGIN_STORE_URL=https://store.smartdoca.cc
DOCA_PLUGINS_DIR=/data/plugins
```

商店地址必須是 HTTP(S) origin，不帶路徑、查詢引數或憑據。遠端服務可用性需單獨確認；連線失敗不影響本地上傳和已有外掛。外掛安裝目錄留空時使用 `${DOCA_DATA_DIR:-./data}/plugins`，相對路徑基於工作目錄。資料庫和物件儲存僅由宿主配置，不提供外掛業務資料目錄環境變數；外掛 API 不暴露宿主存本地還是遠端。

倉庫的 Docker Compose 部署，在部署目錄執行：

```sh
docker compose restart doca
```

這裡的 `doca` 是 `compose.yaml` 中 `services` 下的服務名，容器名可能不同。若修改了服務名，請將命令中的 `doca` 替換為實際服務名。

多例項需逐個重啟；其他部署使用對應程序管理器。頁面不執行重啟。滾動重啟期間若外掛 API 新舊版本不相容，應摘除流量或使用會話親和，不承諾跨版本零停機。

## 已實現儲存修訂（2026-10-03，SDK 原始碼 0.1.8）

`@smartdoca/plugin-sdk/storage` 已匯出安裝身份繫結的 `pluginDatabaseToken`（`storage.sql.v1`）和 `pluginObjectStorageToken`（`storage.objects.v1`）。關係庫支援顯式 version 1 結構宣告、text/int32/雙精度列、主鍵/唯一約束、結構化查詢/寫入/刪除，以及回撥只執行一次的事務。SDK 原始碼 0.1.8 另匯出 `pluginCredentialToken`（`storage.credentials.v1`），提供服務端加密憑證 CRUD、後設資料與修訂號檢查，見[憑證介面](plugin-credentials.zh-Hant.md)。聯表、外來鍵、通用 SQL、upsert 和臨時工作區尚未匯出。業務 SQL 使用與核心庫分開的宿主管理共享資料庫：SQLite 一個檔案、按外掛加表名字首；PostgreSQL 一個 URL／賬號、自動建立外掛 schema，共用連線池。程序隔離仍未實現，見[儲存配置與先解除安裝再升級約定](plugin-database-isolation.zh-Hant.md)。

邏輯庫為 `plugin:<pluginId>`，使用者檔案歸屬及私有物件使用 `plugins/<pluginId>`，發行包使用 `host/plugin-releases/<sha256>.zip`。ZIP 位元組進入環境變數配置的檔案儲存，共享資料庫只儲存 version 2 清單、歸檔引用和可信檔案雜湊索引。有效快取無需重新下載 ZIP。全部例項由運維逐個重啟。新宿主基線拒絕舊資料庫/格式/SDK 包，原資料保留，不提供遷移或 fallback。詳見[準確實現與限制](unified-storage-implementation.md)。

## 多例項分發

所有例項連線同一個宿主資料庫，分散式部署使用 PostgreSQL。資料庫儲存全站期望清單、不可變歸檔引用與逐檔案雜湊索引；完整 ZIP（包括本地上傳包）儲存到統一檔案儲存。每個例項使用獨立可寫快取目錄：

```text
/data/plugins/
  .releases/<sha256>/       已校验插件文件
  .staging/                解压暂存
  .imports/                已导入的手动安装目录
```

啟動時對照資料庫歸檔逐檔案校驗，缺失或損壞就自動補齊，然後載入外掛。禁用外掛也會同步。無需訪問官方商店、安裝依賴或編譯原始碼。共享歸檔缺失或損壞時明確拒絕啟動。宿主資料庫是安裝分發的事實來源，應備份；託管外掛記錄、內部物件、使用者檔案引用與憑證同樣由宿主備份。多例項持久後端必須共享，同一目錄名不是分散式資料庫。

不要讓多個執行中的例項共享同一個外掛快取目錄。在一個例項安裝後，其他例項重啟會自動獲取，不需要手工複製。歷史版本的瀏覽器資源也可以按需從共享歸檔補齊，以適應負載均衡路由。

手動目錄安裝：先停機，將完整發行目錄放到 `<DOCA_PLUGINS_DIR>/<plugin-id>/`。啟動時會打包併發布到全站清單，再將原目錄移入 `.imports/`，避免重複安裝。日常推薦管理員上傳 ZIP。沒有根目錄 npm 依賴清單或舊原始碼載入相容邏輯。

## 升級、解除安裝與故障

安裝包的 `doca.storage` 必須為 `"host"`，缺失/其他值於匯入程式碼前拒絕；已安裝升級要求 `doca.dataVersion` 相同，並驗證實際結構，不自動遷移。當前解除安裝先呼叫必需的業務清理鉤子，成功後清結構標記；失敗保持安裝。鉤子不能刪除磁碟目錄。託管私有狀態清理由宿主負責，叢集協調器尚未實現。禁用/停機不刪持久資料；使用者附件、文件載荷、其他業務引用與檔案回執不自動刪除。舊快取和歸檔為執行例項保留，首版不自動回收。 當前清單事務執行 generation 隔離並記錄私有庫/物件清理意圖，業務表在提交後清理並支援重試；業務任務叢集排空仍未實現，所有例項需人工重啟。

所有寫操作檢查清單修訂號，避免多個管理員互相覆蓋；操作記錄進入安全審計。取消待應用變更會以響應例項的啟動配置更新全站目標，並不會立即回滾其他例項。

實際外掛初始化失敗仍拒絕啟動。SDK 和依賴相容性故障按下文隔離，外掛管理保持可用。沒有熱解除安裝、全站完成狀態面板或原生移動端動態程式碼安裝。

ZIP 必須包含完整依賴，不能依賴 pnpm 軟連結樹。包大小、路徑、SDK、外掛依賴、前後端版本和雜湊均校驗。業務資料不得寫入程式碼包內。協議、打包命令及遠端商店交接見 [外掛商店協議](plugin-store-protocol.zh-Hant.md)。

<a id="兼容性故障隔离"></a>

## 相容性故障隔離

SDK 不相容或必需依賴不可用只隔離受影響的業務外掛，宿主與其他外掛繼續啟動；管理頁顯示不可用原因和升級提示。原安裝意願、歸檔、業務資料和憑據保留，不轉換舊包或執行舊 SDK 程式碼。新線上安裝仍拒絕不相容包。停機放入的完整安裝目錄按原始身份儲存後做相同隔離。

舊包不能靜態宣告其全部業務策略，因此本例項存在啟用但不可用的外掛時，已有外掛策略檢查覆蓋的寫操作返回 503；登入、讀取和外掛管理仍可用。管理員升級相容版本，或明確停用相關外掛，再重啟每個例項後解除保護。外掛許可權來源缺席仍拒絕授權，不自動放開原約束。SDK 不相容外掛不可執行解除安裝鉤子；應先升級。已準備好的相容更新不能取消回舊 SDK 包。待升級包必須保持 dataVersion，不修改外掛業務結構。

隔離狀態屬於例項執行診斷，不寫入安裝清單或資料庫結構。損壞歸檔、非法後設資料、核心外掛失敗及實際生命週期錯誤繼續明確失敗。本輪不提供自動資料遷移或應用降級。
