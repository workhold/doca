# 文書およびライブラリの権限継承

[中文](permission-inheritance.zh-CN.md)

このページでは現在の許可モデルについて説明しています。個人グレードの許可はここにあります。 `grants`; グループは別々に存在する `resource_group_grants` そして、個人レコードを作成せずにアクティブグループメンバーシップと比較して評価されます。公開リンクの定義はそこに存在します。 `share_links`; リンクの取り消しイベントはリアルタイムで発生する `share_link_revocations`。参照 [ユーザーグループ](user-groups.ja.md) グループ招待、ディレクトリの範囲、所有権、およびクリーンアップについて。

各グループには独立した最寄りの授与/継承境界があります。個人ブロックはグループのソースを破壊しません。ローカルの無効化されたグループの授与は、そのグループからの継承をブロックします。ライブラリグループマネージャーは、含まれる文書に対する既存の管理権を保持します。メンバー削除や解散は、そのソースを即座に無効にします。所有権の移転は、グループの授与を保持し、以前の所有者が依然としてグループを通じてアクセスできることも含まれます。

<a id="public-reading"></a>

## 公開読書

公共図書館（`public` または `authenticated`)は、その中の各ページの読み取り範囲を設定します。ページは、自身の可視性によって、または協力者の継承機能をオフにすることによって、そのベースラインを無効にすることはできません。編集、コメント、権限管理は依然としてページと継承に基づいて計算されます。ライブラリが公開状態でない場合、ページは自身の設定と祖先の設定を再び使用します。リストクエリや単一リソースの照会も同じ規則が適用されます。

リソースの種類によって異なる発見、探索、収集規則があります。 [公共資源、発見、およびコレクション](public-resource-discovery.ja.md).

<a id="one-grant-table"></a>

## 1つの助成表

`grants` リソース、ユーザー、承認元ごとに行を保存する：

- `direct`管理ページからの招待や許可です。リソースあたり、ユーザーあたり最大1つです。
- `link`シェアIDによって区別される、シェアリンクから受け取った助成金。
- `parent_override`このノードは、継承された親の結果を上書きまたはブロックします。

各行には、子孫が含まれるかどうか、ソースID、および `active` または `disabled`管理ページでは、ユーザーごとにソースを集計し、最終的な権限を表示します。ソースの詳細は特定の行で操作されます。直接付与を削除すると、無効になります。 `parent_override` したがって、許可は元に戻りません。そのオーバーライドを削除すると、親の継承が復元されます。リンクを取り消すと、その共有ソースのみが削除されます。

「役割」と「子孫を含む」は別物です。子孫の許可は木の構造に沿って確認されます。各フィールドの最大値を取り出して、存在しないような権限を作り出してはいけません。

<a id="collaborators-and-inheritance"></a>

## 協力者と継承

ライブラリは文書権限ツリーの根です。ライブラリの文書は、親文書、または親がない場合はライブラリを継承します。個人文書にはそれらがなく、独自の権限を使用します。

名前が指定されたユーザーの場合、最も近い明示的な決定に向かって上に進む。現在のノード上のグリッドは、その上のグリッドのグリッドを無効にする。無効化されている `parent_override` 親のグローバルな許可をブロックする。このノードに決定がない場合のみ、継承が続く。 `include_descendants` 与えられた資金が子孫に届くかどうかを決定する。 「このノードのみ」という決定により、同じユーザーの資金は上のレベルから遮断される。しかし、子孫は自分の資金を受け取ることができる。

公開許可と名前付きユーザー許可は別々に計算され、そのうち高い方が使用されます。協力者を削除しても、そのユーザーは公開リソースのブロックリストに含まれません。匿名の公開アクセスはせいぜい読者レベルです。

<a id="permission-settings"></a>

## 許可設定

`permission_overrides` このノードが明示的に上書きするフィールドはいくつかあります：public scope、public role、access requests、public discovery、reader history、そしてリンク共有用のmaster switchです。上書きされないフィールドは祖先から引き継がれるものです。継承を復元すると、それらのビットがクリアされます。

遺産のオフにすると、親の設定はコピーされません。既存のオーバーライドは保持されます。他のフィールドはこのノードのデフォルト値が使用されます。オンにすると、オーバーライドされていないフィールドが解決されます。具体的な共有リンク、招待状、チケットはコピーされたり遺産として受け継がれたりしません。マスターリンクスイッチのみが遺産として受け継がれます。

リンクを交換すると、書き込みが行われる `link` シェアIDで付与されます。リンクの変更、無効化、または有効期限の切れは、後のリデュエーションを制御します。既に付与された付与は、メンバーソースを通じて調整または取り消されます。

文書やライブラリのリンクにより、読者、コメント者、エディター、またはマネージャーのアクセスが可能になります。マネージャーのリンクを作成、変更、または解除できるのは所有者のみです。

<a id="approval-notifications-and-immediate-effect"></a>

## 承認、通知、即時効力

アクセスチケット上で要求されたロールは変更できません。承認者は実際に付与されたロールと範囲を選択できます。管理リクエストはリソース所有者のみが承認し、管理権限は所有者のみが付与できます。

このチケットは制限された利用が可能です `resource.grant` 一つのトランザクションで。リソース、ハンドラー、リクエスタを再確認し、ロール、スコープ、結果、イベントを記録する。データベースのトランザクションとステータス条件が、チケットに最終的な結果を与える。

検索やリストの処理では、同じ最も近い決定、許可範囲、フィールドのオーバーライドが使用されます。継承では許可のコピーは一括で行われません。権限が変更された後、影響を受けるオンラインルームが更新されます。読み取りアクセス権を失うと、接続が即座に切断されます。書き込み操作は各操作時にチェックされます。

<a id="shared-permission-components"></a>

## 共有権限コンポーネント

Webモジュール `apps/web/src/shared/components/permission-grant-row.tsx` そして、そのスタイルシートには、自己の助成行、役割選択、ソースエントリー、子孫スコープ、確認バブルがあります。文書、ライブラリ、ナレッジブックが使用します `PermissionDialog`共有フォルダやグループの権限も同じものが使用されます `PermissionGrantRow`発信者はID、許可される役割オプション、読み取り専用/忙しい状態、および永続性コールバックを提供します。このコンポーネントはレイアウト、コピー、キーボードのフォーカス、および確認処理を制御します。 `permissionRoleChoices` ホストリソースと共有フォルダの役割カテゴリを集中管理する。カスタム権限アダプターは、それぞれサポートしている役割を引き続き提供する。

各行は2行で構成されています：上の部分がIDとアクション、下の部分がメタデータ/メンバーのアバター、および子孫スコープです。グループメンバーのプレビューは `UserBadge` アバターのみのトリガーやプロフィールカードの場合、Moreを押すとアバターのポップオーバーが開きます。ポップオーバーの所有権はトリガーに従います。 `aria-controls`ですから、パーティションされたカードと相互作用すると、許可パネルが開いたままになります。

ソース詳細エントリも使用される `PermissionGrantRow`ソースラベルは左に残り、許可や削除のコントロールは右に表示されます。読み取り専用のソース境界は変わりません。 `PermissionEffectiveAccess` グループアクセスが個人アクセスを上回る際のブランドブルーの有効な役割を強調し、ラベル内のグループソースを特定する。

変更コールバックは成功または失敗を返します。失敗の場合は確認状態が開いたままであり、成功の場合のみ確認状態が閉じます。ソースの削除や継承オーバーライドの解除には、異なる確認コピーが存在します。オーバーライドの解除は親の評価を再開するものであり、単にアクセスを取り消すと説明されるべきではありません。サーバー側の所有権、管理フロア、招待の同意、範囲チェックは依然として有効です。
