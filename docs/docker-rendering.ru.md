# Представители документов Docker

[简体中文](docker-rendering.zh-CN.md)

Восстановленное изображение экспортирует текстовые/Markdown PDF-файлы с помощью WeasyPrint 70.0 и создает PNG-файлы с canvas в формате AI с использованием Node, native Canvas и resvg. В установке отсутствует Chromium или Playwright runtime, а также не требуется JSON для seccomp, дополнительной совместной памяти браузера или настройки пользовательного пространства браузера. Соберите новое изображение перед использованием измененного файла Compose; ранее опубликованные изображения не получают этот рендерер автоматически.

Чтение PDF-файлов, текст и изображения на странице, а также возможность редактирования импорта все еще используют PDF.js. LibreOffice Writer, Calc, Impress и Math сохраняют возможность визуальной конвертации. `.docx`, `.xlsx` и `.pptx`Оставлены шрифты CJK и Liberation. Проверьте формулы, диаграммы, встроенные изображения, длинные таблицы и пагинацию CJK через реальные экспорты; медицинский контроль не может подтвердить визуальную точность.

В PDF-работах используется зафиксированная среда Python. `DOCA_PDF_PYTHON=/opt/doca-pdf/bin/python`. Доступны только встроенные ресурсы данных; чтение сети и файлов хоста отклоняется. Неразборчивые/поврежденные изображения или шрифты не обрабатываются, вместо этого возвращается неполный PDF. Ограничение входных данных 32 МиБ, двойная параллельность задач, срок выполнения 60 секунд и возможность повторного проверки после рендеринга остаются. Задания на холсте сохраняют экспортер SDK, разрешенные активы, выбор/кропирование, предупреждения, очередь и возможность отмены. Оба рендерера работают в одноразовых процессах, которые останавливаются при отмене или наступлении срока.

`DOCA_PDF_CHROMIUM` Это явно отклоняется, без альтернативы для браузера. Существующие документы, базы данных, приложения, ключи и объемы сохраняются нетронутыми. Исторические читатели SDK сохраняют свои существующие пути без конвертации хранимых данных. Роллбэк восстанавливает предыдущий код, блокировки зависимостей, изображения и конфигурацию развертывания, сохраняя при этом последующие записи. Старый `docker/chromium-seccomp.*` Файлы сохраняются только для проверки происхождения и сравнения с старым драйвером; новые пакеты развертывания их исключают.

## Размер изображения и обновления скачиваний

Удаление браузера сэкономит место, в то время как Python/Pango/resvg добавляют зависимости. Оставаются LibreOffice, шрифты, зависимости приложений и веб-ресурсы. Сравните сжатые версии/архитектуры; локальное использование множественных архитектур в Docker Desktop не является оценкой загрузки.

Веб-ресурсы, общие зависимости и редакторы сохраняют отдельные слои, пути и права доступа. Смотрите [проверка слоя](verification/image-web-layers-2026-10-23.md).

<a id="optional-sam-runtime"></a>

## Опциональная время работы SAM

Обычные изображения Doca не включают работающую среду SAM2/PyTorch, рабочую программу для сегментации или веса модели. Чтение PDF/Office-файлов не требует использования SAM. Включение сегментации — это отдельная установка, контролируемая администратором, а не процесс загрузки, выполняемый ИИ-системой.

Используйте надежную пользовательскую образовую среду, основанную на точно утвержденном релизу Doca, чтобы добавить интерпретатор/системные библиотеки, необходимые для вашего предварительно созданного рунтинга. Для рунтинга Bookworm Python 3.11 CPU Dockerfile, созданный для развертывания, может содержать:

```dockerfile
ARG DOCA_IMAGE
FROM ${DOCA_IMAGE}
USER root
RUN apt-get update \
    && apt-get install --yes --no-install-recommends python3 python3-venv libgomp1 \
    && rm -rf /var/lib/apt/lists/*
USER node
```

Строить с одобренным изображением digestа, например `docker build --build-arg DOCA_IMAGE=docker.io/smartdoca/doca@sha256:YOUR_APPROVED_DIGEST -t doca-sam-runtime:local .`Детализация – это факт выпуска, выбранный администратором; в примере такого факта нет. Подготовьте среду для Python. **внутри этой Linux-образа и для его архитектуры**, в то же время `/opt/doca-segment` Путь, используемый во время выполнения программы. Никогда не копируйте виртуальную среду macOS в этот путь. На Linux/amd64… [Официальные инструкции по использованию колеса CPU](https://pytorch.org/get-started/previous-versions/#v251) Предоставьте PyTorch 2.5.1 и torchvision 0.20.1; другие архитектуры требуют отдельно проверенных доступных версий и соответствующих профилей.

Доверенная пакетная сборка должна содержать точную версию рабочего процесса, установленные закрепленные зависимости, копию времени выполнения без симлинка от официального пакета SAM2, предварительно развернутую контрольную точку и строгую профиль. **Реальные пути в Linux, версии и хеши байт/древа**. Смотрите [Рецепт подготовки профиля Linux](ai-image-segmentation.md#linux-docker-profile) И существующий строгий контракт на установку/работу рабочих процессов. Сохраняйте пакет, принадлежащий администратору, и позвольте контейнеру иметь UID 1000 для чтения; файлы/директории не должны быть записываемыми группой или другими пользователями. Входные данные модели не могут выбирать или изменять эти пути.

Создать `compose.segmentation.yaml` с Docker Compose 2.24.4 или новее. `!reset` Предотвращает сборку приложения основного файла, чтобы она не перезаписывала ваш отдельно собранный образ рабочего процесса:

```yaml
services:
  doca:
    build: !reset null
    image: doca-sam-runtime:local
    pull_policy: never
    environment:
      DOCA_AI_IMAGE_SEGMENT_PROFILE: /opt/doca-segment/profile.json
    volumes:
      - type: bind
        source: /srv/doca-segment-linux
        target: /opt/doca-segment
        read_only: true
        bind:
          create_host_path: false
```

Эта опора независима от `/data`документы и ключи, загруженные. Не добавляйте ключи модели, состояние аутентификации QA или фотографии семьи в пакет выполнения. Установка переменной в `.env` Одиноко он не передаёт его через базовый файл Compose, не предоставляет этот монтаж. Проверьте установленный профиль в одноразовом контейнере без базы данных приложения перед его активацией; некорректная конфигурация приводит к нестабильной работе, а недоступные/несоответствующие файлы выполнения делают инструмент недоступным. Используйте все предусмотренные отключения при повторной создании приложения:

```sh
docker compose -f compose.yaml -f compose.segmentation.yaml config --quiet
docker compose -f compose.yaml -f compose.segmentation.yaml up -d
```

Проверка времени выполнения и хэша подтверждает идентичность установки, но не качество маски или финального изображения. Каждый реальный кандидат, маска и доставка все еще требуют текущих визуальных проверок, а также разрешений и связей с источником. Повышение веса требует нового проверенного профиля и скоординированного перезапуска; старый профиль или сохраненная маска не конвертируются автоматически.

<a id="build-privacy"></a>

## Создать конфиденциальность

`.dockerignore` не включает `.cache`, `.local`базы данных, файлы окружения, тесты и скрипты из контекста сборки приложения. Сохраняйте пакеты выполнения развертывания, контрольные точки, приватные артефакты приемки и учетные данные вне этого контекста. Исключение не удаляет локальные файлы. Сборка пользовательского изображения SAM должна использовать отдельный минимальный контекст, содержащий только одобренные файлы развертывания.


Веб-выход также имеет независимые слои CAD, шрифтов и ввода, а также восемь групп больших файлов (не менее 512 КиБ) и 16 меньших групп кода, назначенных по стабильным именам файлов. Хеш содержимого блока Vite сохраняется в своей существующей группе; все распределенные пути, байты и права остаются неизменными. В эксперименте с компилированным Web OCI после одной обновки/переименования блока ввода используется 25 из 27 слоев, что приводит к добавлению 334,554 сжатых байт. При реструктуризации CSS с помощью Vite используется 13 из 27 слоев, и добавляется 4,489,097 сжатых байт (примерно на 77,2% меньше, чем в случае полного Web-слоя). Это измеренные случаи, а не фиксированный размер для каждой обновки; полные Web-слои имеют небольшую дополнительную стоимость заголовка. Смотрите… [Доказательства слоя ревью](verification/image-web-layers-2026-10-23.md).
