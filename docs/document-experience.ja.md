# 文書、共有、そして歴史

[中文](document-experience.zh-CN.md)

ホスト0.2.23のソースについて説明しています。初期の開発段階および一時的なパッケージ記録があります。 [研究](research.ja.md).

<a id="create-and-edit"></a>

## 作成と編集

作成メニューにはリッチテキスト、Markdown、スプレッドシート、スライド、キャンバスが用意されています。これら5つすべてにはエディターと独立した共同編集コーデックがあります。テンプレートにはインストール済みのプロバイダが必要です。空白文書の作成はデフォルトで利用可能です。個人文書は独立したページですが、ライブラリ文書はライブラリツリーを使用します。

画像や添付ファイルはホストのアップロード、アセットID、承認されたダウンロードを使用します。編集にはエディターの許可が必要で、保存確認はデータベースのコミット後に行われます。ブラウザのストレージが成功した場合、元のチェックポイントや認可されていない編集内容はIndexedDBに保持されます。再開には利用可能なローカルレプリカとアプリケーションアセットが必要です。 [オフライン制限と回復](collaboration.ja.md#save-reconnect-and-history) また、ストレージエラーに関するフィードバックもあります。ツール、検索/置換、存在情報、コメントはフォーマットによって異なります。詳細は [エディター統合](editor-integration.ja.md).

オフラインワークスペースソースが追加されます **アカウントメニュー → オフライン文書** Docaフロントエンドがダウンロードされたデスクトップクライアントやブラウザに送信されます。ホームページはサーバーに接続できない場合にこのリストを表示します。最後の認可情報の下でレプリカを開き、編集した後、接続とアクセスチェックが回復した後に同期します。参照してください。 [オフライン文書を有効にする方法](access-offline-events.md#离线文档入口).

ドキュメントページでは、粘着フィルターの下で最近の訪問履歴がスクロール表示されます。ライブラリページやオフラインドキュメントディレクトリも、リストが視野範囲を超えると最終項目までスクロールできます。

<a id="sharing-and-permissions"></a>

## 共有と権限

共有パネルは、可視性、招待、メンバーの認可源、リンクを管理します。変更はバージョンまたは修正をチェックし、409の衝突が発生した後で更新します。管理と所有権の操作は、それぞれ独自の認可ルールに従います。詳細は [権限](permission-inheritance.ja.md).

リンクを使用する `#/s/{token}` ログイン済みのプレビューや承認のためです。グローバルリンクの切り替え、個別リンクの無効化/有効期限の設定、メンバーソースの取り消しは異なる操作です。一つのソースを削除しても、他の有効なソースは保持されます。公開読書、検索、コレクション、お気に入りは別々です。コレクションを行ってもアクセス権は得られず、システム管理者も自動的にプライベートコンテンツへのアクセス権を得ることはありません。

<a id="history-and-restore"></a>

## 歴史と修復

- ドキュメントメニューには、履歴、スナップショットのプレビュー、手動スナップショットが提供されます。履歴は通常、エディターの許可が必要です。読者履歴を有効にすると、リソースの読み取り許可に応じてアクセスが可能になります。
- 最近の復元ポイントは詳細なままです。長期的な履歴では、古いスナップショット10個ごとに1つのポイントが保持されます。同じリストやプレビュー/復元操作が、保存場所を明らかにすることなく、保持されているすべてのポイントに対して機能します。サンプリングによって、他の9つのポイントが除外されます。詳細は [ストレージ操作](storage.ja.md#history-storage-and-offline-upgrade).
- 復元可能なリッチテキストおよびMarkdownのスナップショットは、マネージャーやオーナーが復元できます。 `expectedSeq` 現在の内容をチェックする。衝突が発生した後で更新することで、古いプレビューが新しい編集内容を上書きすることがない。
- スプレッドシート、スライド、キャンバスにはスナップショットと読み取り不可のプレビューがあります。現在はそれらを返します `canRestore: false` そして、復元操作は行われない。
- ビジネス履歴と共同編集のチェックポイントは別々に保存されます。復元機能はスナップショットの形式、系譜、およびアセットを使用します。欠落した履歴は現在のコンテンツで置き換えられることはありません。
- 訪問とアクションの記録を確認し、現在の権限を再確認します。これらはバックアップではなく、保存されていない履歴を復元することはできません。

<a id="move-copy-and-trash"></a>

## 移動、コピー、削除

移動する前に、宛先および子孫の権限を確認し、承認のリセットを確認する必要があります。所有権の移転には所有者が必要です。コピーは独立したリソースとコンテンツのアイデンティティを作成し、アセットを再バインドし、グレード、コメント、元の履歴を除外します。削除はゴミ箱に入り、復元は削除バッチと親の状態を尊重します。永続的な削除は明示的な承認されたクリーンアップであり、すべての共有ストレージオブジェクトを削除することを意味するわけではありません。

<a id="routes-and-source"></a>

## ルートとソース

これらのパスには `/api/v1` 接頭辞：

| ルート | 目的 |
| --- | --- |
| `GET /resources/:id/versions` | 歴史一覧 |
| `POST /resources/:id/versions` | マニュアルスナップショット |
| `GET /resources/:id/versions/:versionId` | プレビューと現在のコンテンツシーケンス |
| `POST /resources/:id/versions/:versionId/restore` | `{expectedSeq}`サポートされている形式を復元する |
| `POST /share/redeem` | `{token, accept?, consume?}`リンクのプレビュー/受け入れ |
| `GET /resources/:id/info` | 統計、訪問数、またはアクション記録 |

見てください [experience.ts](../apps/server/src/routes/experience.ts), [歴史サービス](../packages/core/src/modules/history/service.ts)、そして [エディター派遣](../apps/web/src/features/documents/document-editor.tsx)。走り `/api/openapi.json` そして、サーバー検証が完全にデプロイされたAPIを定義する。
