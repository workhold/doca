# ファイル交換統合契約

[中文](editor-file-exchange-contract.zh-CN.md)

この契約は、Docaエディターを通じたファイルのインポート/エクスポートおよびコンバージョンパッケージのアップグレードに適用されます。基本的なコンテンツと許容されるスタイリングが、完全なOfficeの忠実性よりも優先されます。記録された損失は許容されますが、重要なコンテンツが静かに消えることは許されません。責任と受け入れ要件は、すべてのパッケージがすべてのインターフェースを実装していることを意味するものではありません。

<a id="responsibilities"></a>

## 責任

- パッケージはフォーマットを識別し、モデルを解析・シリアル化・変換し、アセットを列挙し、構造化された警告やエラーを報告し、ファイルや圧縮/画像のサイズ制限を適用します。独立したエントリポイントを通じて純粋なコンバータを提供し、Nodeやブラウザの要件を宣言します。
- ホストはファイルを選択し、リソースを作成し、アップロード/ダウンロードを許可し、フィードバックを提供し、ファイル名を選定し、ブラウザでのダウンロードを実行します。パッケージはプラットフォームAPIを呼び出したり、ビジネス文書を作成したり、別の保存チャネルを設立したりしてはなりません。
- インポート結果にはネイティブモデル、保留中のアセット、および警告が含まれます。エクスポート結果にはBlob、ファイル名、MIMEタイプ、および警告が含まれます。統一されたメソッド名を仮定するのではなく、インストールされたバージョンの実際の型に従ってください。
- サポートされる形式は、提供される機能に従います。ファイル名の受け入れフィルターはヒントに過ぎず、パーサーが内容を確認します。製品のUIではJSONのアップロード/ダウロード機能は提供されていません。内部モデルや復元コピーは、移植可能な形式とは別です。

<a id="collaboration-assets-and-security"></a>

## 共同編集、アセット、セキュリティ

- 通常、インポートによって新しいリソース、エポック、安定したアイデンティティが作成され、アクティブに編集されたY.Docを置き換えたり、コメントや権限、履歴、outboxを再利用したりすることはありません。全身の置換には、別途明確なプロトコルが必要です。
- アップロードにリソースが必要な場合は、その記録を作成し、アセットをアップロードした後、一度限りの初期化を行います。サーバーは初期化された/開かれた/変更されたリソースを拒否します。このエンドポイントは、共同編集を回避する完全保存の手段にはなりません。
- 再アップロードされたアセットには、新しい文書の安定したIDが付与されます。インポートされたファイルから得られるブロブ/データ/一時的な署名されたURLや、ユーザー/リソース/権限IDを永続化させてはいけません。外部アセットは自動的に取得されません。ホストがサポートする取得機能には、SSRF、サイズ、オリジンの制御が必要です。
- SVGなどのアクティブコンテンツを消毒する。Docaは、キャンバスパッケージによってすでに消毒されたSVGをラスタライズし、既存の画像アップロードサービスを使用するが、任意の同じオリジンSVGの実行は行わない。
- ビジネス履歴は共同編集契約の保持規則に従います。履歴行を削除しても資産が参照されていないとは言えず、添付ファイルを削除する根拠にはなりません。エクスポートでは現在の内容または保持された要求されたバージョンが読み込まれます。削除されたバージョンは、履歴として偽装された現在の内容ではなく「not-found」を返します。
- エクスポートは現在のリソースアクセスを強制する。変換には、ボディ、選択、元に戻す操作、存在状態、または保存状態の変更はなく、ACKの待ちも生成もしない。パッケージが先にネイティブ編集が必要な場合、ホストは純粋なコンバータではフラッシュを隠すのではなく、エクスポートを呼び出す前に明示的に処理を完了する。
- キャンセル、エラー、遅延のコールバックは、別の文書/選択肢に挿入することはできません。サーバーがアクセスを再確認します。中止されたアップロードは、サーバーのアセットがロールバックされたことを意味するものではありません。文書の一時的なリソースのクリーンアップが行われます。

## PDF形式で表示可能で、編集可能なインポート

リッチテキストPDFエクスポートは、ホストの既存のロケール/プラグイン環境の下で、読み取り専用のポータルとしてクローンされたネイティブ値をマウントします。共同編集は付与されず、ライブエディターが置き換えられず、編集が完了することもなく、チェックポイントが作成されることもありません。Markdownエクスポートは、同じエディターの書体でパッケージのプレビューをマウントします。どちらも画像、数式、図表の待機、計算されたスタイルのコピー、承認されたプラットフォームの画像やフォントの埋め込み、編集制御の削除、そして独立したビューを送信することを待ちます。 `POST /api/v1/resources/:id/pdf`ビデオ/オーディオは、許可されたダウンロードリンク付きの読みやすいラベルになります。添付ファイルや引用ラベルは依然として読みやすい状態です。PDFテキストは選択可能のままです。ページは測定された文書の幅を保持し、√2の紙のアスペクト比を使用し、24pxの垂直印刷マージンを設けています。ページ番号は、ページ数のない画面とは異なる場合があります。

ホストレンダラーは、一時的なPythonプロセス内でピンインされたWeasyPrint 70.0を使用しており、スクリプトの実行はなく、埋め込みデータリソースのみが使用されている。ネットワークやホストファイルの読み込みは拒否され、欠落または破損した画像リソースはエクスポートに失敗する。再検査が行われる。 `read_content` レンダリング後、読み取り専用/公開アクセスポリシーが保持され、32 MiBの入力、2つの同時作業、60秒の締め切りがあります。AIキャンバス画像は、バンドルされたCJKフォントを含む、ネイティブのテキスト測定機能とresvgラスタリゼーションを備えた、ホストに適応した隔離されたNode DOM内で、インストールされたCanvas SDK SVGエクスポーターを再利用します。これは新しいNode APIではなく、ホストアダプターです。PDF.jsの読み取り/インポートとLibreOfficeの変換は別途行われます。再構築されたDockerランタイムは使用されます。 `node`Python/Pango/CJKフォントを含み、ブラウザは不要で、ホストのseccompファイルも必要ありません。 `DOCA_PDF_CHROMIUM` 拒否される；ソースインストールはピンされたPython環境を設定する `DOCA_PDF_PYTHON`既存のSDKの歴史的リーダーは元のパスを保持する。データベース/文書の変換やブラウザのフォールバックは導入されない。ロールバック時にはコード/ロック/画像を復元し、デプロイ設定と後続の書き込みは保持される。ブラウザのレイアウトを保つため、HTMLでラベル付けされた図はPNGとして保存される。通常の本文テキストは選択可能である。JISコード化文字フォントは、ジョブごとにWOFF2デコードを行わないためTTF形式で提供される。計算されたcolgroupの幅は、個々の列の最小幅として再適用されない。

PDFインポートでは編集可能なネイティブコンテンツが優先されます。配布されるMarkdownパーサーは、ファイル/ページ/画像の制限を引き続き検証し、アセットや警告を抽出します。その後、PDF.jsアダプターがフォントサイズ、基本フォントファミリー、太字/斜体、テキスト色、安全なリンク、サイズベースのヘッドニング階層、簡単なリストマーカー、定期的に配置された表、ページ順序の画像を再構築します。リッチテキストはそのネイティブモデルを直接受け取り、Markdownはそのポータブルなシリアル化形式を受け取ります。既存のアセット再バインドや一度限りの新文書初期化が保存の境界となります。PDFの背景塗りつぶし、下線、ベクター図、複雑な列/表、数学の再構築は近似値であり、スキャンはOCRなしの画像のままです。パーサーの警告が表示されます。保存モデル、スキーマ、旧形式の変換や移行変更は導入されません。

Slate 0.4.25は、ESM/CJS変換項目において、直接Wordフォント/サイズ/色/背景、段落の配置、明示的なオフマークとテーブルセルマーク、オンラインヘッダーサイズ、1.6行間隔、A4デフォルトを含む、以前のホストDOCXパッチを公開します。任意の継承されたWordスタイル、複雑なセクション、正確なページ番号は、検証済み範囲外のままです。Markdown 0.4.4は、以前のKaTeX/lazy-PDF修正を公開します。Docaは、エディターパッチなしでこれらの公式パッケージをインストールします。歴史的なパッチファイルは、前のGitリビジョンから復元可能であり、それらの削除は保存された文書を変更したり、共同編集フォーマットを変更したりしません。

受け入れ： `tests/document-pdf.test.ts` 実際のWeasyPrint PDF、選択可能な中国語テキスト、ネイティブなPDF再構築、実際のDOCX XML/再インポート、およびブロックされたスクリプト/リモート画像機能。 `tests/document-pdf-access.test.ts` 読み取り専用アクセス、取り消し、およびゼロソースチェックポイントの変更をカバーします。 `node --import tsx scripts/qa-document-pdf.mts` 孤立したブラウザ環境で実行、ホストのコンテキスト保持とY.Docの更新がないことを確認、画像のエクスポート/再インポート、Mermaid/mathおよび3ページの表のチェック、そして視覚的アーティファクトの作成 `artifacts/verification/document-pdf/`Popplerを使って生成されたPDFとオンラインスクリーンショットを同時に確認してください。ユーザーデータや生産用データベースは開かれません。

<a id="acceptance-evidence"></a>

## 受領証明

クリップボード操作は同じアセット境界に従います。パッケージはファイル/テキストとキャプチャされた挿入ターゲットを報告し、ホストは画像/添付ファイルをアップロードし、内部リンク/アクセスをチェックした後、パッケージが通常の編集トランザクションを通じて挿入します。非同期完了では、新しい現在の選択肢を使用したり、閉じられた/読み取り専用の文書に書き込んだりすることはできません。ネイティブのスプレッドシートのマルチライン/タブペースト機能は残ります。ハイパーリンクは安全なプロトコルのみを受け入れ、内部文書は安定したIDを保存し、デプロイドメインなしで相対的なURLを生成します。現在のスプレッドシートのビジネスオブジェクトは全セルを占め、インラインリッチテキストのサポートは混合されていません。XLSXのラウンドトリップは、警告が表示される読みやすいラベルに低下する可能性があります。

孤立したデータと実際のファイルを使用して、基本的な中国語テキスト、スタイル、表、グラフィックをカバーし、インポート後の編集と再読み込み、エクスポートファイルの再開や再インポート、エディターインスタンス間の同期、エクスポート時のボディ増分のゼロ、読み取り専用のエクスポート/編集ガード、破損した/過大な/キャンセルされたファイル、アセットの再バインド/無許可の読み取り、および可視化された警告を実施する。通過したケース、損失のあるケース、未検証のケースを個別に記録する。成功したビルドは、ファイル交換が正しいことを証明するものではない。

## 3つのエディターアップグレード — 2026-10-17

Docaは今、実際のレジストリアーティファクトを固定している `@smartdoca/slate` 0.4.22および `@smartdoca/slides` 0.3.0-alpha.3.キャンバスは不変性を利用している `vendor/smartdoca-canvas-0.5.0-75e637df1a75.tgz`レジストリ0.5.0ライブラリのビルドツリーがSlate/プレーンテキスト内部エディターの登録モジュールを動かした。AidCanvasのソース修復は両モジュールを副作用とマークしており、ホストは再構築されたアーティファクトを消費する。このアーティファクトとソース修復はnpmに公開されていない。

Slateは5ページの要素色プリセットを追加し、編集が開始されると全体の図表ラベルを選択する。Codec/Yjs/headlessのバイト数は0.4.20と一致する。変更されていないDOCXパッチは0.4.22にリセットされる。キャンバスは変わらない。 `aidcanvas-yjs` スキーマ1。画像と添付物のコールバックは安定したアセットIDを保存し、実際の進捗状況やキャンセルを伝達し、読み取り専用の履歴/ゴミ箱/監査面を含むホスト所有の承認済みプレビューを開きます。サーバーは、現在の文書のアセットに対して新しいインラインメディア参照を検証します。一時的なキャンバス存在は、検証済み相対的なテキスト位置とシーン座標ポインタをサーバ所有のID/色と共に伝達し、ポインタのみのメッセージをサポートし、永続的なコメントアンカーを決して再利用しません。

Slidesではコーデックバージョン6の修正が必要です。クライアントとサーバーが現在交渉しています。 `eppt-yjs-v6` ドキュメントスキーマ2/プロトコル1を使用。ユーザーが明示的に選択した **新しい文書のみ**：既存の `eppt-yjs-v5` 文書や古いクライアントは拒否され、元のチェックポイント、更新ログ、エポック、履歴、保留中のメッセージ識別子は変更されない。旧コーデックリーダー、メタデータ再ラベリング、自動変換、マイグレーション、SQL構造の変更は導入されない。ホストは現在のネイティブテキストインセットとテーブルフィールドを受け入れ、AIテーブルコマンドはネイティブコントローラを通じてマージ/分割、スタイル、サイズ変更、クリア、ペースト、バッチ軸の削除を提供する。テーブルセルは全セルフォーマットを維持したままのプレーンテキストである。

サーバーとWebを同時に更新する。以前のデプロイ、パッケージピン、パッチ、ロックファイル、アーティファクトを保持する。旧コードに戻ることは新しいコードの読みやすさを保証できない。復旧前に後続のデータを保持する。ユーザーデータベースは変更されておらず、デプロイも行われていない。孤立した受け入れ、ハッシュ、スクリーンショット、制限が記録されている。 `docs/verification/three-editor-upgrade-2026-10-17/`.

## キャンバス0.5.6とシート0.2.4の連携 — 2026-10-20
