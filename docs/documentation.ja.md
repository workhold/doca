# ドキュメントのメンテナンス

[中文](documentation.zh-CN.md)

ドキュメントはDocsify 5.0.0を使用しています。Markdownソースはそのままです。 `docs/`; `docs/site/navigation.json` 公開ページとその読み方の順序を定義する。技術的な契約ソースパスは、リポジトリおよびエディタースキルの参照において安定を保つ。

<a id="layout"></a>

## レイアウト

| グループ | コンテンツ |
| --- | --- |
| 始め方 | 迅速な起動、設定、ユーザーガイド、トラブルシューティング |
| ユーザーガイド | 文書、共有、権限、メモ、知識 |
| デプロイと運用 | Docker、ストレージ、スケーリング、認証、サービス認証情報、ウェブハック |
| 開発 | ソース設定、アーキテクチャ、エディター、共同編集、インターフェース言語 |
| プラグイン | 開発、設置、公共サービス、寄付 |
| 参照 | API、データベース、SDK、エディターの契約 |
| リリース | バージョンごとの変更、要件、および検証 |
| プロジェクト | 文書の管理および原研究/受け入れ記録 |

現在の公開ページには8つの言語版があります。デフォルトのソースは `name.md`言語接尾辞、パス、ナビゲーションテキストはここで定義されている。 `docs/site/languages.json`0.3.0以前のリリース、研究、受け入れ記録は、元の版と検証範囲が保持されます。ソースファイルの上部には、廃止された実装や代替された提案が記載されます。実装インベントリでは、エクスポートされたAPI、提案、未検証の外部サービス/デバイス動作が区別されます。

新しい変更が行われる [階層式SDDワークフロー](sdd.ja.md)。 それ [モジュールインデックス](sdd-module-index.ja.md) ソース、権威ある契約、再利用可能なチェックを結合する。仕様書では個々の変更が記述されている。現在の技術的契約は既存のソースパスを維持し、動作が変更される際に同じPRで更新される。

## 確認とプレビュー

```sh
pnpm install --frozen-lockfile
pnpm docs:check
pnpm docs:dev
```

開く `http://127.0.0.1:39140/#/en/` または `http://127.0.0.1:39140/#/zh-cn/`プレビューはドキュメントのみを表示し、Docaを起動したりデータベースに接続したりすることはありません。ソースが変更された後、コマンドを再実行して出版ディレクトリを再生成してください。

`pnpm docs:build` 準備する `.cache/docs-site/` フォルダのようなものと共に `en/getting-started/` そして `zh-cn/operations/`Markdownリンクをコピーし、再書き換えます。Docsifyはブラウザ内でコンテンツを表示します。アプリケーションコードをコンパイルしたり、MarkdownをHTMLとして事前にレンダリングしたりはしません。生成されたディレクトリはGitによって無視されます。

公開ページのリンクは現在の言語で保持されます。言語リンクは、その版が利用可能な場合に該当するページを表示します。ソースコード、例、研究に関するリンクは、対応するGitHubファイルを開きます。ページには編集ソースリンクや利用可能な版へのリンクが付けられます。翻訳がない場合は、別の言語に置き換えるのではなく、チェックに失敗します。

`docs:check` Gitを通じてMarkdownの在庫を管理する、無視されていない新しいファイルも含む、除外するものも含む `tests/fixtures/`このツールは、このリポジトリへのメインブランチへのリンクを含む、リポジトリドキュメント全体のMarkdown/HTMLリンクやヘッダーターゲットをチェックします。無視されたアーティファクトや日付付きの外部/タグ付きURLは取得されません。公開されたヘッダーアンカーは、Docsifyの規則にも照らし合わせられます。また、現在のリリースエントランス、エディターパッケージマトリックス、すべてのデータベーステーブル/フィールド行（継承されたSchemaインターフェースを含む）、および5つのポータブルスキルリファレンスも、元の文書と比較されます。このツールはアプリケーションデータベースを開くことなくTypeScript型を読み取ります。外部ウェブサイトの利用可能性やすべての主張のセマンティック正確性は、まだレビューが必要です。

実行する `pnpm test:docs` チェッカー回帰のケースについて。契約を編集した後、実行する。 `node scripts/sync-docs-skills.mjs`ソースの文章を保持し、チェックアウト外での使用のために相対リンクを書き直します。オプションのinstalled-skillsディレクトリ引数を使用すると、インストールされた参照も更新されます。例えば： `node scripts/sync-docs-skills.mjs /absolute/path/to/installed/skills`インストールされたコピーを、該当するスキルのメンテナンス規則に従って同期状態に保ちましょう。

## GitHub Pages

それ `.github/workflows/docs.yml` ワークフローがプルリクエスト上のドキュメントをチェックし、変更内容を公開する `main`下のレポジトリを設定する **設定 → ページ → ビルドとデプロイ → ソース → GitHub Actions**このワークフローは、 `github-pages` デプロイ環境とその承認ルール。また、Actionsから手動で実行することも可能です。

予定されている入口は以下の通りです：

- [English](https://workhold.github.io/doca/#/en/)
- [简体中文](https://workhold.github.io/doca/#/zh-cn/)
- [繁體中文](https://workhold.github.io/doca/#/zh-hant/)
- [日本語](https://workhold.github.io/doca/#/ja/)
- [Français](https://workhold.github.io/doca/#/fr/)
- [한국어](https://workhold.github.io/doca/#/ko/)
- [Español](https://workhold.github.io/doca/#/es/)
- [Русский](https://workhold.github.io/doca/#/ru/)

これらのアドレスはワークフローが正常にデプロイされた後に利用可能になります。READMEのリンクは、それぞれの言語の入り口を指しています。このサイトはデフォルトのGitHub Pagesドメインを使用しており、カスタムドメインのDNSやリポジトリCNAMEファイルは不要です。

中身を提供しなさい `.cache/docs-site/` 他の場所に公開するため。Hashルーティングはリポジトリのサブパスや、サーバーのルートを書き換えなく直接更新をサポートする。生成されたもの `.nojekyll` Pagesを通じてホストされる際、強調されたナビゲーションファイルを保持します。

## 資産と更新

検証要約と文書添付ファイルを確認した。 [`docs/verification/`](verification/README.md)受け入れケースまたはリリースによってグループ分けされる。再利用可能なスクリプト入力は含まれる。 `tests/fixtures/`生成されたログ、スクリーンショット、レポート、キャッシュが保存されます。 `artifacts/`これはGitによって完全に無視されている。新しい証拠を保持するには、無視ルールの変更は不要だ。

Docsifyランタイム、検索プラグイン、ライト/ダークスタイル、MITライセンスは付属されている `docs/site/assets/vendor/docsify/`. `README.txt` バージョンを記録し、アップストリームのnpm tarballの整合性を確認する。これらのリソースはドキュメントサイト自体から読み込まれる。Mermaidダイアグラムは、固定されたMermaid ESMバージョンを遅延して読み込む。 `site.js`それにはCDNへのアクセスが必要です。

公開ページを追加する際は、8つのエディションをすべて作成し、そのページを追加してください。 `navigation.json`、そして実行する `pnpm docs:check` そして `pnpm docs:build`非公開の技術/デザイン記録をリンクする [研究](research.ja.md)、そしてレビューされた検証概要が含まれる [検証指数](verification/README.md)コード例とバージョン要件を一致させておくこと。契約を更新する際は、関連するリポジトリの手順に従い、必要に応じてパッケージ化された参照を更新する。実行時アセットや追加のプラグインには、明確なバージョン選択とブラウザの検証が必要である。

リリースのナビゲーションエントリにおける4番目の値は `true` 8種類の言語版がすべて揃ったら、その価値を後続のリリース後に保持しておきましょう。レビューされたスクリーンショットを言語サブディレクトリに置いてください。 `docs/images/` したがって、サイトとREADMEは対応するインターフェースを参照できます。
