# 플러그인 아키텍처

[中文](plugin-architecture.zh-CN.md)

그것 [SDK 계약](plugin-sdk-contract.ko.md) 코어 플러그인과 비즈니스 플러그인 사이의 경계를 정의합니다. [개발 가이드](plugin-development.ko.md) 현재 존재하는 인터페이스를 나열합니다.

`plugin-contracts` 매니페스트와 라이프사이클을 정의합니다. `plugin-sdk` 주입, 이벤트, 기여, 효과를 제공합니다. `plugin-host` 종속성을 확인하고 플러그인을 시작한 후, 역순으로 해제합니다. 컴포지션은 코어 파일, 문서, 검색 및 AI 기능을 조합한 후, 별도의 설치 디렉터리에서 비즈니스 플러그인을 로드합니다.

비즈니스 플러그인은 공개 파일, 사용자, 권한, HTTP, 정책, 이벤트, AI 서비스를 통해 호스트와 통신합니다. 등록은 플러그인 인스턴스에 속합니다. 플러그인은 호스트의 비공개 데이터베이스 유형이나 전체 프로세스에 적용되는 브리지에 접근할 수 없습니다. 웹 플러그인은 자체 빌드를 제공하며, 활성 매니페드가 이를 로드합니다.

호스트는 인증, 권한 부여, 파일, 문서 공동 작업, 보안 감사, 원본 AI 사용, 모델에 의해 평가된 토큰 사용을 유지합니다. 회원권, 포인트, 가격, 콘텐츠 모니터링, 메일은 핵심 테이블, 도구, 페이지가 아닙니다. 미래의 메일 플러그인은 자체 서버, 데이터, 수락 테스트를 소유합니다.

일반적인 트리 슬롯, 추가적인 비즈니스 서비스, 그리고 펀드 예약 프로토콜이 계약서에 구현 상태로 명시되어 있습니다. 제안된 API는 호출할 수 있는 수출이 아닙니다.

모든 내구성 있는 플러그인 상태는 호스트가 관리합니다. 패키지는 명시해야 합니다. `doca.storage: "host"`플러그인은 드라이버, 저장 경로 또는 로컬/원격 설정이 아닌 모델/인증 기능을 가지고 있습니다. 관리되는 SQL 및 개인 객체는 SDK 0.1.7에서 내보내집니다; 서버 전용 암호화된 자격 증명은 SDK 0.1.9에서 내보내집니다. 자세한 내용은 참조하세요. [저장 계약](plugin-horizontal-scaling.ko.md).
