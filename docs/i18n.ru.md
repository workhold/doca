# Языки интерфейса

В Doca 0.3.0 доступно восемь языков интерфейса. У каждого языка есть собственный каталог сообщений, а ключи на английском общие для всех каталогов. Правила реализации для проекта и редакторов изложены в [английском оригинале](https://github.com/workhold/doca/blob/main/docs/i18n.md).

<a id="language-codes"></a>

## Коды языков

| Код | Язык | `html lang` |
| --- | --- | --- |
| `zh` | Упрощённый китайский | `zh-CN` |
| `en` | Английский | `en` |
| `zh-Hant` | Традиционный китайский | `zh-Hant` |
| `ja` | Японский | `ja` |
| `fr` | Французский | `fr` |
| `ko` | Корейский | `ko` |
| `es` | Испанский | `es` |
| `ru` | Русский | `ru` |

Исходный язык сайта — упрощённый китайский. Администратор может изменить язык по умолчанию. Его видят гости и пользователи без настройки `ui.locale`. Сохранённый выбор в аккаунте имеет приоритет.

При записи через API указывайте канонический код из таблицы. Региональные и системные теги `zh-TW`, `zh-HK`, `zh-MO` и `zh-Hant` соответствуют традиционному китайскому. Другие поддерживаемые языки определяются по основному языковому тегу. Если сохранённое значение неизвестно, рабочее пространство отображается на языке сайта по умолчанию.

Настройка аккаунта хранится в состоянии страницы `ui.locale`. Веб-клиент также сохраняет `doca.locale` в `localStorage`, а мобильный клиент — на устройстве. Помощник может изменить `ui.locale` через существующий инструмент `page_state`.

При каждой загрузке веб-страницы входа сначала используется язык сайта, выбранный администратором. Переключатель языка действует сразу для текущего посещения. После входа язык рабочего пространства определяется настройкой аккаунта и языком сайта по умолчанию.

## Каталог хостов

Каталоги находятся… `packages/i18n`Английский каталог `en` Это источник ключей. Все другие языки должны включать точно те же ключи.

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

- Ключи – строчные английские буквы с точками, группированные по области, например `nav.trash` и `settings.language`.
- Представители — это `{name}`Не разделяй предложение и не соединяй его части.
- Причастие используется `files.count.one` и `files.count.other`Звонок все еще идет. `t("files.count", { count })`Английский используется `one` когда `count === 1` и `other` В противном случае китайцы могут использовать одно и то же предложение для обоих случаев.
- Отсутствующий перевод использует английский язык, а затем сам ключ.
- Используйте собственные имена каждого языка в Selectors. Нативные метки происходят из `localeNames`.
- Даты и сортировка `Intl` Для активного языкового тега.
- Названия документов, текстовые поля, комментарии, электронные письма, имена файлов и ввод пользователя не переводятся.

Веб-приложение использует `useI18n()` для `locale`, `t`и `setLocale`Ant Design и Ant Design X следуют этому принципу. `locale`На компьютере и на мобильных устройствах используются каталоги хоста. Расширение браузера сохраняет свой язык для этого браузера. Вклады, использующие двуязычный плагин, используют английское поле в шести новых языках.

Некодированные ошибки сервера, видимые пользователю, все еще представляют собой китайские предложения. Новые ошибки валидации используют стабильные коды, такие как `invalid_locale`И интерфейс переводит его. Некоторые ошибки API не преобразуются в этой версии.

Новые функции генерации изображений с помощью ИИ, соединения моделей и ошибок работников используют явную формулировку, которая сериализуется в существующие поля текста для отображения ошибок:

```ts
{ type: "system_error", version: 1, code: "image_edit_failed", data: { status: 422 } }
```

Только новосозданные, явно кодированные системные ошибки используют этот формат. Тексты исторических ошибок, сообщения, результаты работы инструментов, логические рассуждения и сохраненный контекст запросов читаются буквально; не сканировать, переводить, конвертировать или переносить их. Ошибки без меток остаются неизменными. Веб и мобильные устройства используют один и тот же формат. `systemErrorMessage` читатель `@doca/i18n`Ошибки в тегированных задачах `useI18n().t`Новые HTTP-ошибки используют локаль, выбранный тем же провайдером. Неизвестные коды отображают каталогизированную общую ошибку, в то время как некорректные или неподдерживаемые данные остаются без изменений.

`AppError.message` И сериализация ошибок, связанных с моделью, остается неизменной. Метаданные представления хранятся вне объекта ошибки в WeakMap. Пункты контроля неудачи при работе с изображениями содержат отдельное структурированное причина, чтобы позже при неудаче задачи можно было отобразить её без изменения канонического отчета инструмента. Язык интерфейса никогда не добавляется в системный запрос, определения инструментов или историю повторных запусков, что сохраняет кэшированный префикс модели при переключении пользователем языка.

Это согласованная политика чтения для старого простого текста и новых кодированных ошибок; нет миграции исторических данных или схем базы данных. Ролл-оф не должен приводить к новым записям в контейнере, при этом должен сохраняться читатель контейнера и все хранящиеся данные.

## Сохранённое состояние системы

Базы данных, точки контроля за работой, потоки событий и ответы API хранят стабильные английские коды и структурированные параметры. Они не хранят текстовое описание на любом языке. Веб- и мобильные приложения преобразуют код в название, описание и название этапа в соответствии с текущим каталогом.

```ts
{ code: "folder_available", data: { name: "Research" } }
t("ai.progress.event.folderAvailable", { name: event.data.name })
```

Фазы, события, утверждения и причины ошибок, хранящиеся в виде статусов, соответствуют этому правилу. Сравните коды, например. `phase === "completed"`Не сравнивайте результат. `t(...)` Или китайское или английское название. Ввод пользователя, ответы модели, названия документов, имена файлов и веб-источники остаются такими, какие они есть. Не переписывайте естественный контент в код.

## Подпакеты редактора

Подпакет редактора сохраняет собственную копию интерфейса. Он не импортирует каталог Doca и не читает состояние страницы Doca.

Ведущий проходит:

```tsx
<RichTextEditor locale={locale} />
```

`locale` Это строка. Установленные редакторы принимают восемь кодов, указанных в таблице. Неразрешенный пакетный локал переключается на английский.

1. Добавить опционально `locale?: string`Когда это опускается, показать `zh`Соответствует текущему китайскому интерфейсу.
2. Ключи – это стабильные английские идентификаторы, такие как `toolbar.bold` и `find.replaceAll`.
3. Предоставьте полный каталог тех же ключей для каждого поддерживаемого языка.
4. Представители — это `{name}`Количество использует `key.one` и `key.other`, выбранный `count`.
5. Меняться `locale` Обновляются кнопки, меню, полей ввода и подсказки. Оно не пересоздаёт документ, Y.Doc, адаптер для совместной работы или список плагинов.
6. Опционально `messages?: Record<string, string>` Может переключать отдельные ключи. Если ключи отсутствуют, используется встроенное переводческое программное обеспечение.
7. Текст, формулы и значения ячеек, которые пользователь ввел в документ, не переводятся.

После этого типы установленных пакетов включают `locale`Хозяин передает текущий. `locale` На месте установки. Не ставьте. `locale` В зависимости от того, каким является документ, Y.Doc, адаптер совместной работы или список плагинов.

## Добавь язык

1. Добавьте код `locales`и `html lang` ценность.
2. Добавьте каталог хостов с точно такими же английскими клавишами.
3. Добавьте название языка, например `locale.ja`.
4. Добавьте соответствующий регион Ant Design в веб-приложение.
5. Добавьте тот же каталог языков в каждую подпакетную версию редактора.
6. `ui.locale` Принимает новый код, потому что валидация показывает одно и то же `locales` список.
