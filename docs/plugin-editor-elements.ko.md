# 플러그인 문서 요소들 (SDK 0.1.6 소스)

2026-10-02에 호스트 소스 0.1.8, SDK 0.1.6, contracts 0.1.6, Web registry 0.1.3에서 구현되었습니다. 이 기능은 npm 배포, 생산적 설치 또는 네이티브 기기 수용이 아닌 소스 내보내기와 격리된 수용을 기록합니다. 합의된 저장 정책은 정확한 버전 지원입니다: 알 수 없는 유형과 버전은 오류 플래그를 표시하고 원본 JSON을 그대로 유지합니다. 어댑터, 자동 변환, 마이그레이션 또는 데이터 재설정은 도입되지 않습니다. 기존의 내부 문서 참조 리더는 변경되지 않습니다.

## 공공 등록

수입 `PluginElementContribution`, `PluginElementPayload`, `createPluginElementPayload`, `pluginElementState`, `isPluginElementPayload` 그리고 `validatePluginElementPayload` 부터 `@smartdoca/plugin-sdk/editor-elements`. 선택적 반환 `elements` 기본 설치된 웹 플러그인 번들에서. 호스트는 각 기여를 등록합니다. `WebPluginRegistry.elements` 소유한 플러그인 네임스페이스 아래에 있으며, 번들과 함께 해제됩니다. 중복된 ID와 유효하지 않은 선언은 등록 실패를 초래하며 번들의 등록을 되돌립니다.

```ts
import type { PluginElementContribution } from "@smartdoca/plugin-sdk/editor-elements";

// Return this contribution from the injected Web plugin factory.
const element: PluginElementContribution = {
  id: "example.elements.countdown", pluginId: "example.elements",
  title: { zh: "倒计时", en: "Countdown" }, dataVersion: 1,
  formats: ["rich_text", "spreadsheet"],
  validate: data => typeof data.targetAt === "string" &&
    Number.isFinite(Date.parse(data.targetAt)),
  text: data => `Countdown: ${data.targetAt}`,
  renderEditor: context => /* injected React configuration form */ null,
  render: (payload, context) => /* injected React inline view */ null,
  renderCell: context => { /* draw within context.rect using context.canvas */ },
  refreshIntervalMs: 1000,
};
```

이 선언문은 출력된 서명을 보여줍니다. [독립적인 예시](../examples/plugin-elements/README.md) 작업 형식, 렌더러 및 설치 파일을 포함합니다. 플러그인은 주입된 호스트 React를 사용하고 자신만의 의존성들을 묶습니다. 호스트 소스 경로를 임포트하거나 전역 편집기 브리지를 사용해서는 안 됩니다.

모든 기여는 지역화되어야 합니다. `title`양의 정수 `dataVersion`적어도 하나의 지원되는 형식이 있습니다. `validate`, `text` 그리고 `renderEditor`. `rich_text` 필요로 함 `render`; `spreadsheet` 필요로 함 `renderCell`. 선택적 `onCellClick` 페이로드와 공개 컨텍스트를 받습니다. 선택적 `refreshIntervalMs` 1000에서 60000 사이의 정수이며 캔버스 보기를만 새로고칩니다.

문맥에는 `documentId`, `format`, `locale` (`zh` 아니면 `en`), `readOnly` 그리고 하나 `AbortSignal`. 형태 컨텍스트는 추가로 클론된 값을 제공합니다. `initialData` 또는 null, `submit(data)` 그리고 `cancel()`캔버스 컨텍스트는 복제된 객체를 제공합니다. `payload`, 캔버스와 잘라진 셀 직사각형. 설정은 호스트를 통해 전송되며, 플러그인은 변경 가능한 편집기 핸들, 개인적인 런타임 또는 독립적인 지속성 채널을 받지 않습니다. 렌더링 오류는 지역화된 플레이스홀더를 생성합니다. 플러그인은 자체 이벤트/비동기 실패를 처리하고 신호가 중단될 때 작업을 취소합니다.

## 저장된 콘텐츠

```json
{
  "version": 1,
  "pluginId": "example.elements",
  "type": "example.elements.countdown",
  "dataVersion": 1,
  "data": { "label": "Launch", "targetAt": "2026-10-04T00:00:00.000Z" },
  "text": "Launch · 2026-10-04T00:00:00.000Z"
}
```

`version` 엽서 버전입니다. `dataVersion` 이것은 기여물의 정확한 데이터 버전입니다. `data` 순수 JSON 설정이 포함되어 있습니다. `text` 텍스트 기반 사용자에게 적용되는 제한된 정적 프로젝션입니다. 렌더링 함수, 인증 정보, 임시 URL, 타임스탬프 값 또는 타이머는 저장되지 않습니다. 불투명한 페이로드는 단순한 JSON 객체여야 하며, 최대 32 KiB의 UTF-8 형식, 깊이 20, 노드 수 4096이어야 합니다. 안전하지 않은 프로토타입 키나 무한/비-JSON 값은 저장 전에 거부됩니다.

현재의 봉투 인식기는 지정된 6개의 필드만을 인식합니다. 구조적으로 유효하지 않은 미지정된 봉투, 설치되지 않거나 비활성화된 제공자, 알 수 없는 유형, 지원되지 않는 형식 또는 일치하지 않는 버전은 지원되지 않는 대체 값을 생성합니다. 현재 제공자가 설정 거부 시에는 무효한 대체 값이 생성됩니다. 어느 경우든 데이터를 수정하거나 삭제하지 않습니다. 호스트는 일치하지 않는 제공자의 렌더러나 설정 편집기를 호출하지 않습니다. 사용자는 기본 편집 기능을 통해 지원되지 않는 요소를 명시적으로 제거하고 그 제거 작업을 취소할 수 있습니다. 정확한 제공자를 다시 활성화하면 보존된 설정을 다시 표시할 수 있습니다.

<a id="native-editor-integration"></a>

## 원시 편집기 통합

- 서식 있는 텍스트는 하나의 영구적인 호스트 원자 인라인 확장을 사용합니다. `custom:plugin-element`그리고 공유되는 코덱도 있습니다. 이 코덱은 비즈니스 플러그인이 로드되지 않아도 전체 불투명한 페이로드를 저장합니다. 삽입 기능은 실시간 Slate 범위를 캡처하며, 편집 기능은 ID로 노드를 찾습니다. 삽입/설정/제거는 네이티브 작업 및 네이티브 취소 기능을 사용합니다. 이 릴리스는 인라인 애트먼트를 지원하며, 임의의 블록 레이아웃은 내보내지 않습니다.
- 스프레드시트는 공개된 형태를 사용합니다. `cellRenderers` 캔버스 확장 기능 `custom.docaElement` 원어민으로 `ICellData`. 세포의 `v` 이것은 정적 텍스트 프로젝션입니다. 삽입/구성 커밋은 현재 셀 스타일을 유지하며 네이티브 텍스트 감쌍을 CLIP로 설정하여 프로젝션이 인접 셀을 넘어가지 않도록 합니다. 삽입은 대화상자에서 명시적으로 표시된 대로 선택된 전체 셀의 값/공식/서식 있는 텍스트/사용자 정의 데이터를 대체합니다. 셀 텍스트 내에는 부동 객체나 인라인 위치가 없습니다. 폼이 열려 있는 동안 행/열 편집에 따라 안정적인 단일 셀 앵커가 유지되며, 삭제되거나 동시에 변경된 대상은 제출에 실패합니다. 네이티브 범위 명령어는 복사, 삭제, 취소 및 공동 작업을 제공합니다.
- 대화상자를 닫거나 편집기 컨텍스트를 변경하거나 편집 모드를 떠나면 세션이 취소됩니다. 제출 과정에서는 활성 제공자, 핸들, 읽기 전용 상태 및 대상을 다시 확인합니다. 렌더링/레지스트리 변경은 문서 편집기를 다시 마운트하지 않습니다. 플러그인 보기 새로고침은 문서 작성을 발생시키지 않습니다.

기존의 리치 스키마 3과 스프레드시트 스키마 6은 자체 체크포인트와 신뢰할 수 있는 공동 작업 기능을 유지합니다. 요소 콘텐츠를 위한 두 번째 JSON 자동 저장, 전송, Yjs 재생 경로 또는 비즈니스 플러그인 데이터베이스는 존재하지 않습니다. 자체 체크포인트와 동일 모델 클립보드는 페이로드를 보존하지만, 기존의 텍스트/마크다운/오피스 변환 제한은 여전히 적용됩니다. 리치 원자적 내보내기는 기존의 변환 경고와 함께 라벨로 저하되며, 스프레드시트 소비자는 셀의 정적 값을 읽을 수 있습니다. 순수 텍스트를 내보내는 것은 손실 없는 플러그인-요소 백업이 아닙니다.

## 생명주기, 설치 및 롤백

기본적으로 어떤 요소 제공자도 설치되어 있지 않습니다. 플러그인은 기존 설치 디렉터리/ZIP 메커니즘을 통해서만 발견할 수 있습니다. 현재 예제 매니페드에는 SDK가 필요합니다. `^0.1.7`독립적인 생산 사용 전에 이 업데이트된 SDK와 호스트를 배포/설치합니다. 해당 서버 공장은 어떠한 비즈니스 데이터도 보유하지 않으며, 제거 기능으로도 문서 내용이 삭제되지 않습니다.

플러그인은 렌더러를 해제/제거하지만, 영구적으로 저장된 요소는 등록하지 않습니다. 정확히 동일한 제공자를 다시 설치할 때 데이터 변환이 필요하지 않습니다. 영구적인 네이티브 코덱이 없는 더 오래된 호스트로 되돌리는 것은 이러한 문서를 편집하는 데 지원되지 않습니다; 데이터베이스/체크포인트 백업을 보존하고 해당 호스트를 사용하여 접근하십시오. 다운그레이드 재작성이나 파괴적인 청소 작업은 제공되지 않습니다.

## 수락

분리된 테스트들 `tests/plugin-editor-elements.test.ts` 레지스트리 소유권/폐기/롤백 처리, 엄격한 버전 및 JSON 제한, 풍부한 원자적 클립보드/삭제/undo 기능 및 불투명한 CRDT 라운드트립, 네이티브 지속성/ACK 재생/두 복제본 무음 동작, 스프레드시트 기반 안정적인 앵커/행 삽입/복사/삭제/undo/재로드/수렴 기능, 읽기 전용 권한 부여 및 원자적 과다 크기 페이로드 거부. 이들은 격리된 데이터베이스와 문서를 생성합니다. SDK 검증 스크립트는 호스트 경로가 없는 포장식 독립적인 JavaScript 및 NodeNext 선언 소비자를 확인하기도 합니다.

브라우저 수용 과정에서는 격리된 데이터베이스와 독립적인 카운트다운/뉴스 예제의 임시 설치가 사용됩니다. 실제 네이티브 컨테이너와 서드파티 플러그인은 각각 별도의 수용 과정을 필요로 합니다. 일반적인 블록 요소, 교차 형식 무손실 내보내기, 공개적인 임의 편집기 변경 명령은 향후 작업으로 남아 있습니다.

검증된 브라우저 작업에는 풍부한 삽입/설정/undo/redo/재로드/읽기 전용 기능, 시트 설정/삽입/undo/redo/재로드 기능, 그리고 제거만 가능한 설정이 있는 알 수 없는 유형의 플레이스홀더가 포함됩니다. 저장 및 재로드 후 시트 프로젝션 클립이 확인되었습니다. 최종 종합 검증 결과: TypeScript는 통과되었으며, 171개의 테스트 파일이 통과되었습니다(1,066개의 테스트 중 3개는 건너뛰었음); SDK 빌드 및 독립적 사용도 통과되었으며, 웹 프로덕션 빌드 및 공백 검사도 통과되었습니다.

## 성능 인증 (2026-10-02)

실행하기 `node --import tsx scripts/benchmark-plugin-elements.mts`Node 24.15.0을 사용하는 이 macOS arm64 머신에서, 1,000개의 일반 단락에 대한 중앙값 네이티브 프로젝션은 두 가지 원본 인라인 코덱으로는 0.513 ms, 추가된 엘리먼트 코덱으로는 0.515 ms였습니다. 켤레 중앙값 델타는 측정 노이즈 범위 내에 있었습니다. 10,000개의 차지된 일반 셀에 대한 추가된 스파스 엘리먼트 검사는 0.039 ms가 소요되었으며, 100개의 구성된 엘리먼트를 사용할 경우 0.111 ms가 소요되었습니다. 100개의 카운트다운 페이로드에 대한 첫 번째 검증은 0.188 ms가 소요되었고, 100개의 예제 캔버스 콜백을 복제하고 호출하는 작업은 0.101 ms가 소요되었습니다. 이 콜백 벤치마크는 모의 캔버스를 사용하며 네이티브 그림 작업을 측정하지 않습니다.

일반 셀은 커스텀 속성을 확인한 후 출력됩니다. 풍부한 검증은 메모화되며, 캔버스 검증은 각 페이로드/프로바이더마다 캐시되고 레지스트리 변경 시 무효화됩니다. 단일 합쳐진 뷰 타이머는 가시적인 타임드 셀을 그리는 경우에만 재설정되며, 최소 1초의 기간이 적용됩니다. 숨겨진 페이지는 이를 취소합니다. 가시적인 타임드 셀이 없는 시트는 반복적인 새로고침 타이머가 없습니다. 스케줄러 테스트는 무소유 타이머, 100개 요소의 합쳐짐, 뷰포트 이탈, 숨기기 및 폐기 등을 포함합니다. 브라우저가 60초 이상 무소유 상태의 문서를 관찰한 결과 새로운 콘텐츠 시퀀스/기록이 없었으며, 타이머는 결코 지속성 아웃박스에 들어가지 않았습니다.

이 측정 결과에 따르면 테스트된 경우들에서 호스트 CPU 작업량의 증가는 거의 없었습니다. 이는 임의의 제3자 렌더링, 외부 데이터 조회, 대량의 보이지 않는 요소 수, 또는 모든 장치에 대해 비용이 0이 되는 것은 아니라는 것을 의미합니다. 생산 제공업체는 자체 렌더링/비동기 작업량을 검증해야 합니다.
