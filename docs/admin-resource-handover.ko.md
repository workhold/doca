# 관리자 리소스 이관

[中文](admin-resource-handover.zh-CN.md)

에 **관리자 → 사용자**활동적인 시스템 관리자가 열다 **자원을 전달하다** 장애가 있는 계정의 경우, 활성 수신자와 리소스 항목을 선택한 다음 실제 변경 사항을 검토하고 확인합니다. 소스 계정은 여전히 장애 상태로 유지됩니다. 일반 사용자는 세 가지 엔드포인트 중 어느 것도 사용할 수 없습니다.

<a id="scope"></a>

## 범위

인벤토리는 기존 리소스, 폴더, 파일 및 권한 기록에서 관리 메타데이터를 읽습니다. 문서 본문이나 개인 정보는 읽지 않습니다.

- 문서, 도서관 및 지식 북: 선택된 자원과 소유자 소유의 후속 자산을 전달합니다. 다른 사람들은 소유권을 유지하며, 관련 내용은 별도로 기재됩니다. 기존 도서관 소유자의 권한은 수령자에게 적용됩니다.
- 문서 이미지와 첨부파일: 문서와 함께 전송된 자산 및 디렉터리 항목입니다. 이들은 별도로 선택될 수 없습니다. 원본 업로드자와 기록 작성자는 그대로 유지됩니다.
- 일반 폴더/파일: 소유자 소유의 하위 폴더와 파일을 전송합니다. 선택된 중첩된 폴더나 독립적인 파일은 부모가 전송되지 않거나 수신자 소유가 아닐 경우 수신자의 개인 루트로 이동됩니다. 미리보기 화면에서는 이러한 이동 과정을 확인할 수 있습니다.
- 보존된 문서/도서관 보조금: 명시적으로 선정된 활성 지역 보조금 소스는 직접 보조금 수령자가 되며, 해당 소스에서 제거됩니다. 하위 범위는 유지되며, 링크 토큰은 복사되지 않습니다.
- 공유 폴더 보상: 기존의 더 높은 역할을 하향 조정하지 않고 수신자의 폴더 보상으로 병합한 후 선택된 소스 보상을 제거합니다.
- 파괴된 리소스: 소유권은 삭제된 상태가 유지되는 동안 이전될 수 있습니다.

개인 AI 파일, 비공개 대화, 자격 증명 및 플러그인 비즈니스 기록은 제외됩니다. 기존의 AI/지식 세션 파일 바인딩, 일반적으로 잠긴 파일 및 인식되지 않는 메타데이터는 보호됩니다. 문서 첨부 파일의 파일 관리자 잠금은 해당 문서와의 전송을 방해하지 않습니다. 보호된 항목은 왜 선택할 수 없는지 설명하며, 선택된 디렉터리 내의 보호된 파일은 전체 배치를 차단합니다.

<a id="preview-and-permission-checks"></a>

## 미리보기 및 허가 확인

미리보기에는 소유권, 권한 및 첨부 파일 변경 사항, 이동 사항, 그리고 소유권이 변경되지 않은 관련 항목들이 표시됩니다. 부모 항목을 선택하면 해당 부모의 자식 항목들도 확장됩니다. 각 배치는 최대 500개의 선택된 재고 항목을 허용하며, 확장 시 더 많은 자식 항목이 포함될 수 있습니다. 재고 및 변경 사항은 50행 페이지를 사용합니다.

기존의 고급 수신자 권한은 그대로 유지됩니다. 비교할 수 없는 노드/후손 역할, 액세스를 확대할 수 있는 소스 자식 제한 조건, 명시적인 수신자 제한 조건 등이 충돌을 일으키고 확인 기능을 비활성화합니다. 이러한 권한을 기존의 권한 워크플로우를 통해 검토하거나 선택을 변경해야 합니다. 전달은 그러한 제한 조건을 무시하거나 관련이 없는 상속된 권리를 복사하지 않습니다.

선택된 문서/폴더의 소스 또는 수신자에게 보내는 초대가 취소되면, 이후의 수락으로 인해 전달이 무효화되지 않습니다. 문서 초대는 티켓과 함께 보관되며, 폴더 초대는 취소된 행과 티켓은 그대로 유지됩니다. 다른 사람의 초대는 그대로 유지됩니다. 미리보기에는 취소 수가 표시됩니다. 공개성, 링크 정의 및 기타 협업자는 기존 설정을 그대로 유지하며, 공개 접근은 사용자 차단 목록이 되지 않습니다.

<a id="consistency-and-audit"></a>

## 일관성과 감사

인벤토리 및 미리보기에는 일관된 데이터베이스 스냅샷이 사용됩니다. 실행 과정에서는 관련 계정, 리소스, 보조금, 첨부파일 및 디렉터리 내용을 포함하는 지문을 다시 계산합니다. 변경된 상태는 확인 정보가 유효하지 않게 되고 409를 반환합니다. 다시 새로고침 및 미리보기를 해야 합니다. 동일한 배치에 대한 동시 확인은 단 한 번만 성공합니다.

하나의 트랜잭션으로 소유권이 확정되고, 권한, 초대 결정, 인덱스 작업 및 보안 감사가 이루어집니다. 기존의 수신자 허용/할당량 정책은 여전히 작동합니다. 어떤 실패가 발생하더라도 전체 배치가 되돌아갑니다. 저장된 객체는 이동되거나 삭제되지 않습니다. 문서 내용, 기록, 업로드자 및 원본 작성자들은 그대로 유지됩니다. 커밋 후 활성 권한이 갱신되며 관련 계정에 알림이 전송됩니다.

그것 `user.resources_handed_over` 보안 감사는 실제 관리자, 출처, 수신자, 지문, 변경 사항 및 관련 이전 메타데이터를 기록합니다. 관련이 없는 개인 수신자에 대한 정보는 제외됩니다. 실행은 동기식으로 이루어지며, 다시 시작할 수 있는 백그라운드 작업이 아닙니다. 브라우저가 연결이 끊겼거나 응답이 손실된 경우, 다른 배치 작업을 시도하기 전에 재스캔해야 합니다.

이 기능은 스키마 변경이나 과거 변환 없이 기존 테이블과 유지되는 형식을 사용합니다. 자동적인 역전환 또는 권한 롤백 기능은 없습니다. 확인된 비즈니스 결정에 대한 수정은 감사 및 현재 소유권/권한을 검토해야 합니다.

<a id="api-and-verification"></a>

## API 및 인증

- `GET /api/v1/admin/users/:id/resource-handover`: 재고.
- `POST /api/v1/admin/users/:id/resource-handover/preview`: `targetUserId`, `keys`.
- `POST /api/v1/admin/users/:id/resource-handover/execute`: 동일한 선택과 미리보기 `fingerprint`.

실행하기 `pnpm exec vitest run tests/resource-handover.test.ts` 서비스/API 회귀 테스트를 위해 실행합니다. `pnpm exec tsx scripts/qa-resource-handover.mts` 독립된 SQLite/계정/문서/스토리지에 대한 실제 관리자 UI에 관한 결과입니다. 결과는 여기에 있습니다. `artifacts/verification/resource-handover/`이러한 검사는 PostgreSQL 실행 시간 검증을 보장하지 않습니다.
