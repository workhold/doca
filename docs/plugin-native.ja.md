# ネイティブプラグインキャッシュと添付ファイル

[中文](plugin-native.zh-CN.md)

ネイティブプラグインコンテナ内で `host.ai.open` 使用する `assistant.open` ネイティブのパーソナルアシスタントを起動する。パラメータとエラーは以下の通りです。 [発注契約](plugin-assistant.ja.md)プロンプトやコンテキストはナビゲーションURLには含まれず、アカウント認証情報もWebViewには含まれない。プレフィルドリクエストは現在のアカウントと一度限りの起動識別子の下でメモリ上で使用される。

公開型型はそこから来る `@smartdoca/plugin-sdk/native`露出された `PluginWebHost.native`このプロパティはWeb上ではnullです。Appプラグインコンテナは以下の機能を提供します：

- `storage.get(key)` / `set(key, value)` / `remove(key)` / `clear()`文字列キャッシュ。各値あたり最大200万文字、各プラグインあたり最大2000万文字。
- `attachments.save({path,name,mime})` / `share(...)`: `path` 例えば、プラグインAPIに関連しています。 `/mailboxes/123/attachments/456?download=true`.

ネイティブホストは、キャッシュ名前目スペース、オンラインで確認されたユーザーID、プラグインIDをサーバーに結合します。プラグインは別のアイデンティティを選ぶことはできません。データはアプリの永続ディレクトリに保存され、再起動後も保持され、アカウントをログアウトしたり削除したりすると対応するサーバーでクリアされます。書き込みはシリアル化され、新しいスナップショットが以前のものを置き換える前に完了します。WebViewは一時的で孤立したものであり、ログインクッキーは永続的なキャッシュメカニズムではありません。

ネイティブホストは、プラグインを読み込む前にオンラインでサインインされたアイデンティティを確認する。既存のプラグインのIndexedDBコードは自動的に移行されたり採用されたりすることはない。プラグインは明示的に使用される。 `native.storage`完全オフラインの冷启动はサポートされていません。アプリの削除やシステムのストレージのクリーニングによってキャッシュが削除される可能性があります。

添付ファイルのダウンロードには内部の認証されたホスト経由での送信が使用される。外部のオリジンへのリダイレクトは禁止されており、ネイティブのセッショントークンはWebViewに提供されることはない。添付ファイルのサイズは最大32MiBである。一時ファイルは保存・共有後に削除される。

Androidの保存機能はシステムのディレクトリピッカを使用して返します `completed` または `canceled`iOSの保存と共有機能では、システム共有シートが表示され、戻ります。 `presented`システムAPIは最終的な保存/キャンセル結果を正確に報告できないため、 `presented` 成功した保存が行われない。

ページの削除やアカウントの切り替えは、現在のネイティブリクエストを無効にします。メールアカウントのリンクはWeb上で行われ、ネイティブなOAuthフローは存在しません。

記録された実装では、型チェックやプロトコル/ホストダウンロードテストが成功した。キャッシュの永続性、システム共有、保存については、iOS/Androidデバイスの受け入れがまだ必要である。
