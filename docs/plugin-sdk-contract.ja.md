## 3. インストールと発見

共有ホストデータベースには必要なレジストリおよびアーカイブメタデータが保存されています。完全な不変なZIPファイルは設定されたホストファイルストレージに保存されています。各インスタンスはプライベートなデータも同期します。 `DOCA_PLUGINS_DIR` デフォルト `<data-root>/plugins`ロードする前に。すべてのキャッシュされたファイルをチェックし、共有アーカイブ内の欠落したり破損したりしたファイルを修復します。起動時にはストアに接続せず、npm installを実行したりTypeScriptをコンパイルしたりします。

Admin → 公式のHTTPSストアまたはローカルアップロードからプラグインをインストールし、ステージのアップグレード、有効化、無効化、アンインストールを行う。デフォルトのストアは `https://store.smartdoca.cc`、上書きされる `DOCA_PLUGIN_STORE_URL`操作では修正が行われた後での書き込みが使用され、各インスタンスの再起動後に有効になります。UIは、グローバルな希望される選択肢と、回答するインスタンスの実行中の選択肢を区別します。Fastifyルートの即時削除は保証されていません。

プレビルド版リリースは宣言する `doca.manifest`, `doca.server`、オプション `doca.web`必須 `doca.dataVersion` そして `doca.storage: "host"` package.jsonにおいて、すべてのインストールソースや起動時の復元の前に、静的ストレージの検証が行われます。欠落したり異なるストレージ宣言がある場合、変換が行われずに失敗します。SDKの範囲、パス、グラフ、ハッシュ、正確な構造もチェックされます。インストールされたアップグレードには、データVersionが変わらない必要があります。現在のアンインストールでは、必要なビジネスクリーンアップフックが呼び出され、成功時にはマーカーがクリアされます。レジストリのトランザクションにより、生成が制御され、コミット後に実行される永続的なプライベートデータベース/オブジェクトのクリーンアップが記録されます。クラスタータスクの消費はまだ進行中です。

オフラインフォルダー `<install-root>/<plugin-id>/` 起動時に共有レジストリに公開され、そこに移動される `.imports/`ランタイムファイルはそこに存在する `.releases/<sha256>/`root npmマニフェスト、ソースリンク、またはレガシー検出パスはサポートされません。プログラムファイルとプラグインのビジネスデータは別々に保持されます。ホストソース、package.json、Vite設定はインストールによって変更されることはありません。

## 4. ライフサイクル

```text
scan static metadata → check dependencies → import code
→ discover → required service check → initialize → mount → ready
→ stop accepting work → dispose in reverse dependency order
```

サービスはトークンオブジェクトの識別ではなく、安定した文字列IDとバージョンによって識別されます。ホストはまずプラットフォームサービスを提供します。ビジネスプラグインは自身の名前空間内でのみサービスを登録します。プライベートホストサービスを注入することはできません。 `doca.server.*`各サービスIDには1つのプロバイダが存在します。マルチコントリビューション機能はレジストリを使用します。

各登録は、コンテキスト効果が所有するディスポーズャーを返します。サービス、ジョブ、イベントサブスクリプション、UI登録は、1つのホストインスタンスに属します。これらを保存しないでください。 `globalThis` または `Symbol.for`1つのプロセス内で実行される2つのテストアプリは、互いに影響を与えてはいけない。

ターゲット機能の一部はまだエクスポートされていない：files.v1、documents.v1、users.v1、permissions.v1、http.v1、ai.v2、ai-usage.v1、search.v1、content.v1、activity.v1、notifications.v1（エクスポート済み）、events.v1、ホスト管理型プラグインリレーショナルストレージ（SDK 0.1.7でエクスポート済み）、およびpolicies.v1。実際のIDは現在のエクスポート内容に従う。名前変更にはバージョン管理が必要である。この表は、実装されていないインターフェースを既存のプラグインに渡すための権限ではない。

## 5. ユーザー情報とリクエストコンテキスト

HTTPリクエスト、AIツール、バックグラウンドジョブは、requestId、principal、pluginId、signal、およびオプションでsessionId、turnId、jobId、callIdという一つの信頼できる実行コンテキストを共有します。アイデンティティはホスト認証や保存されたジョブ認可から得られます。プラグインはHTTPボディからユーザーアイデンティティを構築することはできません。

サーバ上に存在する完全なユーザーレコードには、安定したID、公開ID、ログイン情報、表示名、アバター、ステータス、管理者フラグ、認証済み連絡先、プロフィールフィールド、カスタムビジネスフィールド、およびIDリンクのメタデータが含まれており、呼び出し側が読み取ることができます。通常の検索結果は最小限の情報のみです。該当オブジェクトにはパスワードハッシュ、セッショントークン、認証コード、OAuthトークン、モデルAPIキー、またはストレージシークレットは含まれていません。ブラウザに完全なサーバプロフィールを返したり、モデルプロンプトに自動的に追加したりしないでください。

ユーザーの作成、プロフィールの更新、ステータスの変更などのイベントが保持されます。ユーザー削除の記録はまだありません。バックグラウンドジョブがユーザーのステータスとリソース権限を再確認します。無効化されたユーザーは、古いジョブスナップショットからアクセスを維持できません。

将来の削除フローはホストによって記録される：削除とアクセス権の取り消しをマークし、プラグインはインデプソナスにクリーニングを行い確認し、その後ホストが削除を完了する。これには無効、インストールされていない、および利用できないプラグインが含まれ、再試行と監査済みの手動パスが必要である。タイムアウトは成功とはならない。クロスデータベースの二段階コミットは使用されない。ユーザー削除エントリが開かれる前に受け入れられなければならない。

## 6. 権限とユーザーの重複

リソース参照は `(pluginId, resourceType, resourceId)`プラグインは自身のアクセス権者を登録します。ホストがそれを呼び出します。ファイルおよび文書サービスは独自のACLを保持します。プラグインを登録しても、ユーザーのファイルを読む権利は与えられません。

プラグインは、メールボックス・リードなどのビジネスアクションやロールマップを定義します。プラグインのアクションは、必ずドキュメントエディターと同じであるとは限りません。アトリビューターが存在しない、プラグインが無効になっている、または結果が不明確な場合はアクセスが拒否されます。本文の読み込み、添付ファイルのダウンロード、AIツール、検索機能により再確認が行われます。

ホストは、管理者のすべて、関連するもの、およびなしのルール、およびユーザーごとのオーバーライドを保持します。関連する候補は、内蔵ドキュメントおよびファイルソース、およびアクティブなプラグインの交差ソースの組み合わせです。ホストは依然としてユーザー状態、フィールドの可視性、およびページングをフィルタリングします。「なし」はプラグインにルールを拡大するよう要求しません。

承認されたビジネス関係により、どのサイトユーザーが発見されるかを示す交差点ソースがあります。共有メールボックスやカレンダーのメンバーが交差点となり得ます。他人のメール、同じメールドメイン、またはメッセージ本文の名前はそうではありません。プラグインは管理者ディレクトリポリシを定めません。

ソースプロトコルは、ソースID、スキーマバージョン、候補バッチとカーソル、関係IDとバージョン、および現在の事実再確認をサポートします。プラグインは大規模な関係インデックスとそのアウトボックスを維持します。ユーザー検索はプラグインデータベースをスキャンしません。期限切れの候補は返信される前に再確認されます。ソースの障害は検索範囲を広げることはありません。プラグインを無効にすると、そのソースは即座に削除されます。再有効にすると、まずバージョンと有効な関係が調整されます。

検索可能であるということは、ビジネス権限を与えるものではなく、全プロフィールを公開するものでもありません。複数の情報源からの重複ユーザーは、ページング前に重複を排除します。事前フィルターによる合計数は、隠されたユーザーを漏らしてはなりません。

## 7. ファイル、プラグインデータ、およびトランザクション

プラグインはインジェクテッドファイル.v1を使用し、安定したIDを保存します。アタッチメントバインディングは `(ownerPlugin, ownerType, ownerId, role)`プライベートのアタッチメントストアを構築したり、一時的な署名されたURLを永続的な参照として保存したりしないでください。オーナーバインディングとはアクセス権ではなく所有権です。メールを通じてアタッチメントを読むと、メールボックスとバインディングが再確認されます。元のファイルを開くと、そのファイルのACLが引き続き適用されます。

すべてのビジネス永続化はホストが管理します。プラグインはテーブル、インデックス、ジョブ/アウトボックスのセマンティクス、認可を定義しますが、ストレージサーバーを選択したり、直接データベースに接続したり、システムディレクトリに永続化したりすることはありません。論理データベースは `plugin:<pluginId>`インストールアイデンティティに結びついています。ユーザーファイルはfiles.v1を使用し、プライベートバイナリ、認証情報、一時的な作業はそれぞれのホスト機能を利用します。管理されたデータベース/プライベートオブジェクトAPIはplugin-sdk/storageを通じてエクスポートされ、認証情報はSDKソース0.1.9でエクスポートされます。ワークスペースAPIやdata.v1/data.v2は利用できません。欠如している機能は自己管理型ストレージで代替できません。構造は完全に一致し、暗黙の変換や古いデータのフォールバックはありません。ホストが管理されたストアのクリーンアップを担当し、インスタンス間で協調して行われる点が、プラグインファイルシステムの削除とは異なります。

データベースやファイルサービスにおいては、イデムポネス、補償、およびキャリブレーションを使用してください。共有トランザクションは存在しません。

### 7.1 耐久性のあるファイル作成

`files.v1.folders.create` そして `files.v1.files.create` 任意に受け入れる `idempotencyKey`空でない、最大200文字、制御文字なし。範囲はインジェクトされたプラグインID、現在のユーザー、操作タイプです。同じキーと同じパラメータで最初の結果が返されます。同じキーで異なるパラメータでは409が返されます。ファイルまたはフォルダの行と完了したレシートのコミットが一緒になります。レシートは有効期限がありません。無効化やアンインストールでは削除されません。結果が削除された後に再プレイすると404が返され、ファイルは再作成されません。再プレイとクエリではアカウントと書き込み権限を再確認します。

アップロード完了の返信 `contentIdentity: {sha256, size, mime}`イデミポテントのアップロードはそれを通過しなければならない。ホストはアップロードされたバイトをチェックする。リクエストフィンガープリントには一時的なアップロードIDではなく、デスティネーションディレクトリ、名前、コンテンツIDが含まれる。コピーはsourceFileIdを使用し、contentIdentityは不要である。プラグインは操作キー、ビジネスパラメータ、コンテンツIDを自身のoutboxに保存する。

`files.receipts.get(context, {operation, key})` nullまたはを返す `{status: "pending" | "completed", operation, result}`「pending」とは、元のパラメータを再試行できることを意味します。作業がまだ進行中であるという意味ではありません。「completed」は歴史的状況を返します。応答が不明な場合は、受信内容を読み、元のcreate操作を再実行します。失敗は成功の受信として作為されることはありません。

ホストはオブジェクトIDとストレージ設定を保持し、その後バイトを書き込みます。ローカルでの書き込みは原子的な置換を使用します。S3での書き込みでは完全なオブジェクトが作成されます。起動時や1時間ごとのスキャンにより、完了したインテントから余分なオブジェクト、24時間以上未完了のインテントからのバイト、および一時ファイルが回収されます。回収とアップロードの再試行はデータベースユーザーロックを共有し、オブジェクト参照を確認します。登録されたオブジェクトはゴミとして削除されることはありません。

### 7.2 検索と外部知識

使用する `@smartdoca/plugin-sdk@^0.1.9`. 輸入 `contentServiceToken` そして、 `ContentSource` type from `@smartdoca/plugin-sdk/content`; トークンを宣言する `injections.required` マウント時にソースを登録する。ソースは登録するプラグインに属する。内蔵ドキュメントやファイルも同じ契約を使用する。

| メンバー                                        | 契約                                                                                                                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 宣言                                   | `id`, `pluginId`, `version: 1`、局所化 `title`, `contentTypes`, `purposes`, `capabilities: {search}`, `configSchema`                                                                                     |
| `list(ctx, {config, cursor, limit})`          | 必要。返す `{items, nextCursor, snapshot}`各項目には含まれています `ref: {sourceId, resourceId, blockId}`, `fingerprint`, `title`、オプション `order`, `anchor`, `excerpt`; ここでは全身を返さないでください。 |
| `read(ctx, {config, ref, fingerprint})`       | 必要です。権限を再確認し、商品を返送してください。 `text`利用できない場合は、またはnullです。変更された指紋は衝突であり、古い指紋の下に新しいテキストは決してありません。                                       |
| `resolve(ctx, ref)`                           | 必要です。アクセス権を再確認し、返却してください。 `{path, fingerprint}` またはnull。 `path` アプリ内の現在位置です。                                                                                                     |
| `search(ctx, {config, cursor, limit, query})` | オプション；一緒に宣言し、実装する。軽量なページを返す。サポートされていない検索は完全なスキャンに遷移しない。                                                                                  |

`ctx` 認証済みである `principalId`, `purpose` (`knowledge`, `analysis`、または `search`) とキャンセル `signal`プロバイダは各通話において現在のビジネス許可を適用する。分析をサポートするソースは、メール特有のAPIなしで将来のタスクプラグインを提供できる。消費者はそれを使用する。 `sources(ctx, purpose)`、それからサービス `list/read/search` と共に `sourceId` そして `purpose`；サービス `resolve` 取る `{ref, purpose}`そのソースが指定した目的のみを要求してください。

ページネーションはnullで始まり、終わります。トラバース中のすべてのページは一貫したスナップショットを共有しなければなりません。異なるデータを使い続けるのではなく、期限切れ時にエラーが発生するようにします。このカーソルは、完全な承認済み在庫をページネーションするためのものであり、耐久性のある変更ログではありません。 `listChanges` そして `readChanges` この契約によって必要とされること、または輸出されることはありません。ソースは内部で自社のビジネスシステムを同期させることができますが、Docaはその実施を要求していません。

知識は既存のサブスクリプションおよびスケジューリングシステムを利用する。ユーザーが明確にソース、ライブラリ、設定を選択する。ホストは参照情報やブロックの指紋を保存し、全体的な在庫を比較し、新しいまたは変更されたブロックのみを読み取り/分析する。追加の完全なソース本体のミラーを保持する必要はない。変更されていないブロックは再読み込みする必要はない。完全で一貫した在庫のみが削除の根拠となる。失敗したり部分的な実行があった場合は、それを認識しない。安定したブロックの識別情報は、文書の全レビューや位置付けされた段落のインデックスに依存してはならない。

削除、解除、撤回、または利用できないソースの場合、派生知識は新しい通常読み取り、リスト、検索、回答検索から隠されます。手動で編集された結果を含む、管理者の処理のためにコンテンツは保持されます。既に配信されたコンテンツや既に開かれた共同編集接続は、このチェックによって遡及的に撤回されません。設定UIはプリミティブフィールド、列挙型、文字列配列をサポートします。複雑な設定はプラグイン自身のUIに属します。この統合により、データベーススキーマの移行、二重読み取り/書き込み、旧ソースアダプターは追加されません。SDKは依然としてエクスポートを行います。 `knowledge.sources.v1`しかし、これは新しい統合機能のサブスクリプション情報ではなく、自動的に適応されるものではありません。 `content.v1`.

制限：1ページあたり100件の在庫品、10万件の探索、200万文字の本文、分析実行時120,000文字の変更された本文、そして20秒のソースコールの締め切り。巨大すぎる、または不完全な作業は明確に失敗する。切り捨てずに「完了」とすることはできない。HTTPエンドポイントは `/api/v1/content/sources` そして `/api/v1/content/{list,read,resolve,search}`。参照 [正確なプロトコルと制限](plugin-content.ja.md) リクエスト形状とサブスクリプションルートのため。

## 8. AIツール、スキル、および利用方法

SDKソース0.2.0がサーバーをエクスポートする `ai.continuations.v2`インストール範囲のソース登録、認証されたツールの待機、持続性のあるチェックポイント、重複のないウォーク通知と再起動の調整。ビジネスジョブと承認権限はプラグインが管理し続け、ホストは待機中にモデル実行を解放する。明示的なバージョン1の待機記録のみが参加し、データベースの移行や歴史的変換は行われない。詳細は…を参照してください。 [継続契約](plugin-ai-continuations.ja.md).

現在のソースWeb SDKがエクスポートされる `PluginWebHost.ai.open` プロンプト/コンテキスト、承認済みの文書/ファイル、オプションの自分所有のセッション/モデル、明示的な自動送信を利用した個人アシスタントの起動のため。ストレージの移行や旧ホストアダプターなしで、既存のホストセッション/メッセージ、実行ポリシーフローを使用する。詳細は [発売契約](plugin-assistant.ja.md)これはクライアントのUI機能であり、サーバーのAI実行サービスではありません。npmやネイティブの生産環境での利用可能性はまだ確認されていません。

プラグインは、ツール、スキル、インテント、ワークフロー、結果レンダラー、チェッカーを登録することができる。ツールには名前スペース付きのID、入力および出力スキーマ、実行者、および権限要件がある。スキルとは、パッケージ内のバージョン化されたコンテンツである。これはツールの認可を回避する手段ではない。

プラグインツールは、承認されたユーザープロファイルとAI通話コンテキストを受け取ります。これにはセッション、ターン、ジョブ、ツール呼び出し、モデルID、パラメータ、キャンセルシグナル、許可された資料参照が含まれます。任意の履歴やすべてのプロンプトはデフォルトのツールコンテキストではありません。ChatとMCPは認可とツール実行を共有します。

MCPは、インストールされたツールを公開する `mcp` 同じ実行者と現在のユーザー/アクセスチェックを通じた露出。公式のインストール済みプラグインと有効な個人SKILLは、サービスグrantと有効ユーザーによってフィルタリングされる。個人および企業のサービス設定はホスト所有であり、新しいSDKエクスポートやプラグインソースパスへのアクセスはない。詳細は [MCPサービス](mcp.ja.md).

コアには会員レベル、ポイント、価格、ギフトクオータ、レベルによるモデルフィルタリングはありません。ホストはモデル設定、技術的なタイムアウト、並行処理、コンテキスト制限、およびユーザー、モデル、プラグイン、ジョブ、コールによる生の使用量を確認可能にします。各モデルには入力と出力のトークン率があります。画像生成では、成功した画像ごとにトークンが発生します。これらの率はベンダーの使用量を累積トークンに変換します。これらは通貨や最終価格ではありません。

各プロバイダーの試行には、それぞれ独自のcallIdとattemptIdがあります。不明な値はnullです。0を作り出さないでください。キャッシュや推論トークンは、入力や出力の合計にすでに含まれている可能性があります。それらを二度追加しないでください。決済処理では、呼び出しの開始時点からレートのスナップショットが凍結されます。UIおよび `ai.usage.recorded` 評価された使用量を表示します。レジャーには生のベンダーメトリクスが保持されます。推定値と実際値は別々に保持されます。リプレイでは2回計測されません。

ホストAIエクスペクタを通じて実行される呼び出しのみが統一メーターに含まれます。プロバイダを直接呼び出すプラグインはその制約外です。

コントロールプラグインは、自身のトランザクション内で原子的に予約を行い、インデペンデントな予約IDを返す必要がある。完了または失敗は、耐久性のあるイベント再試行を通じて解放または解決される。残高をチェックし、呼び出しを行った後、差し引くことは並行処理のクォータ制御ではない。失敗した使用イベントはホストレジャーを破壊しない。再プレイではCallIdとAttemptIdによって重複を排除する。

policies.v1は、文書の作成、ファイルのアップロード、共有も対象としています。許可または拒否と安定した理由コードを返します。デフォルトでは商業的な制限はありません。ポリシープラグインはリソースのACL、アカウントの状態、リクエストサイズ、実行安全制限を拡大することはできません。ポリシー例外は許可に含まれません。必要な制御プラグインが欠けている場合、操作は利用できず、エラーは明確に表示されます。

## 10. 会員資格と管理機能の解除

メンバーシップの削除には、管理ページ、レベル表示、プランおよびグレードAPI、IDプロバイダーレベルのマップ、リソース割当、AIポイント、レベルによるモデルフィルタリングが含まれます。レベル制限を維持しながらページを隠すだけでは不十分です。生のAI使用記録は残ります。このプロジェクトには、古い商業フィールドやマイグレーション層は含まれていません。

- 公開ID、テーブル、イベント、ツールにはプラグイン名前空間があります。SDKのバージョン範囲は明確です。

## 13. 配達の等級

- ホストコンテンツ、ファイルサービス、公共統合フックは既存の境界を保持します。ビジネスモデル、権限、再試行、アウトボックスセマンティクスはプラグインが所有し、永続性は常にホストが管理します。
- 必要なパッケージ宣言 `doca.storage: "host"` ZIP/npm/storeのインストール、オフラインディレクトリのインポート、起動復元の前にサーバーコードのインポート時にチェックされます。欠落した/異なる値は失敗します。プラグインのデータディレクトリ環境変数、サーバー選択子、レガシーアダプター、暗黙のデータ移行はサポートされていません。
- 管理された関係データストレージとプライベートオブジェクトはSDK 0.1.7でエクスポートされます。認証情報はSDKソース0.1.9でエクスポートされますが、一時的な作業が残っています。サーバーの選択や共有デプロイメントはホストに属します。プラグインはローカル/リモートを区別しません。その正確なエクスポート状況はストレージ契約と第12節に記載されています。
- 新しい管理型ストアは、指定された構造形式のみを受け入れます。一致しない場合は起動が拒否されます。既存の自己管理型インストールに対して空のストアを開設したり、移行計画を回避するためにアンインストールを使用したりしないでください。古いパッケージやデータは変更されず、変換には別途契約が必要です。
  管理されたプライベートデータベース/オブジェクトのクリーンアップはホストが担当する。ビジネスアンインストールが成功した場合、レジストリトランザクションが現在の世代をフェイスシールドし、プライベートテーブル/オブジェクトのクリーンアップを耐久性のある再試行でキュー化する。認証情報のクリーンアップと生成フェイスシールドが実装されており、クラスター内のビジネスタスクの排出は利用できない。ユーザーファイルやその他のビジネス参照情報は保持される。Hookの失敗はインストールを無傷のままにするが、外部Hookの効果は元に戻すことができない。すべてのインスタンスは依然として手動の再起動が必要である。
- 健康状態、編集されたログ、最近のジョブエラーやバックログは、ホストのストレージパスを読み取るプラグインではなく、公開されたステータスインターフェースを通じて要約される。

提供されていない：任意のSQL、クロスプラグイン/ホスト間の分散トランザクション、自動的な旧データストアのインポート/デュアル書き込み、すべてのソースへのデフォルトAIアクセス、またはネイティブプロセスによって動的に実行されるnpmプラグインコード。

## 14. プラグイン所有の最近の活動

`activity.v1` 輸出されています `activityServiceToken` 中に `plugin-sdk/platform`。供給源が供給する `list` そして `get`ローカライズされたタイプラベル、サポートされているアイコン。ホストはプラグインの訪問情報を保持しません。既存のコア訪問データはそのまま保持されます。登録はインスタンススコープであり、プラグインと共に破棄されます。リスト表示や開く操作には現在の状態が必要です。 `activity.read` 認可。 [活動契約](plugin-activity.ja.md) 厳格なキーセットの順序、制限されたクエリ、障害の分離、カーソルの動作、およびデータ移行なしでのロールバックを定義する。

## 15. コンテンツとネイティブ実装

ソースSDKがエクスポートされる `content.v1` 通して `plugin-sdk/content`必要なリスト/読み取り/解決機能、オプションの検索機能、完全な在庫チェック機能、および内蔵の文書/ファイルリーダー機能。知識サブスクリプションでは、既存のストレージやスケジューリングを再利用し、ブロック指紋を比較し、変更されたデータのみを読み取り/分析する。設定UIやライブ派生コンテンツ保護機能により、新しい読み取り、リスト、回答の検索が可能になる。knowledge.sources.v1アダプタ、データベース変換、スキーママイグレーションは追加されない。独立したメール連携やネイティブデバイス対応は依然として必要である。 [契約および実施の制限](plugin-content.ja.md).

ネイティブコンテナは、現在、各オリジン/ユーザー/プラグインごとに永続的なストレージ機能と、認証された添付ファイルの保存・共有機能を提供しています。 `PluginWebHost.native`ネイティブの検証と、独立して再構築されたメールクライアントが依然として必要です。 [ネイティブ契約](plugin-native.ja.md).

## 作成リソース（SDK 0.1.5）

[テンプレート/材料契約書](creation-resources.ja.md) 実装されているゼロデフォルトプロバイダ登録システム、バージョン化された消費者マッチング、タグ/検索/ページネーション、資料のインポート、文書の初期化、公開クライアント、注入されたピッカーなどが定義されている。廃止されたテンプレートテーブルは、マイグレーションやデフォルト登録なしで保持される。旧テンプレートAPIやテンプレートIdの作成は、合意された計画に基づき削除される。外部プロバイダやストアリソースの管理は、別途行われる。

0.1.6のソースリビジョンでは、名前付きソース説明やマルチソースが追加されます。 `providerIds`制限されたプロバイダ所有の `retrieve`結果におけるソースメタデータやピッカーのコールバック、そしてAIソース探索/検索ツールについてです。合意されたクエリ変更により、前者の単一形は廃止されます。 `providerId`; リソース参照はそのまま保持される `providerId` そして、保存されたデータは変わりません。サポートされていない検索は、ページをスキャンすることはありません。現在の状況をご確認ください。 [リソースプロトコル](creation-resources.ja.md)ソースの確認がnpmの公開を意味するわけではない。
