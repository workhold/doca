# プラグインからAIアシスタントを起動する

[中文](plugin-assistant.zh-CN.md)

SDKソース0.1.7が導入されました。 `PluginWebHost.ai.open(input)`ウェブは完全なパーソナルアシスタントを開き、アプリプラグインのWebViewはネイティブ会話を開きます。ソース検証ではnpmの公開や更新されたアプリは確認できません。これはクライアント起動APIであり、サーバーバックグラウンド実行には別の契約があります。

```ts
import type { PluginAssistantOpenInput } from "@smartdoca/plugin-sdk/web";

const input: PluginAssistantOpenInput = {
  prompt: "Summarize this email and list action items",
  context: mail.plainText,
  documentIds: [document.id],
  attachmentFileIds: [attachment.fileId],
};
const { sessionId } = await host.ai.open(input);
```

| パラメータ | 行動と制限 |
| --- | --- |
| `prompt` | 編集可能な初期入力テキスト |
| `context` | 後ろに平文が付いている `prompt`ユーザーメッセージとして、最大20,000文字までの組み合わせが可能 |
| `documentIds` | 最大20個の異なるホスト文書UUIDがあり、ホストは現在許可されたタイトル/形式を読み取り、参照チップを表示する。 |
| `attachmentFileIds` | 最大8個の異なるホストファイルUUID、各々最大20MiB、合計で25MiB；承認されたAPIを通じてAI添付ファイルにコピーされる |
| `sessionId` | 現在のユーザーに属する既存の会話UUIDです。省略すると会話が作成されます。アーカイブされた会話は、まず復元する必要があります。 |
| `modelId` | 利用可能なモデルです。省略時は会話モデル、ユーザーデフォルト、そしてサイトデフォルトを使用します。 |
| `autoSend` | デフォルトでは事前入力されます；明示的 `true` メッセージを送信し、空でない必要がある `prompt` または `context` |

`host.ai.open()` 空の会話を開始できます。返信されます。 `Promise<{sessionId: string; jobId?: string}>`. `jobId` 即時送信がジョブを送信した場合にのみ存在し、モデルが完了したという意味ではありません。同一クライアント内での同時重複の起動は拒否されます。成功した新しい呼び出しは別々の起動であり、メッセージを自動的に再試行することはありません。

```ts
const { sessionId, jobId } = await host.ai.open({
  prompt: "Draft a reply",
  context: mail.plainText,
  autoSend: true,
});
```

参照情報、ファイル、会話、モデル、送信はすべて現在のホストの認可を必要とします。アイデンティティはセッションから得られます。入力情報は提供できません。 `userId`トークン、またはシステムプロンプトです。不明なフィールド、重複するID、有効でないUUID、過度な入力は拒否されます。プラグインは、自身のビジネスコンテンツがそのユーザーやAIに提供されることを確実にする必要があります。起動はリソース権限の拡大や、モデル実行ポリシー、ツール承認、または使用記録の回避にはなりません。

権限が拒否された場合、利用できないモデル、アーカイブされた/他ユーザーの会話、添付ファイルの制限、ネットワークエラー、アカウント切り替えはプロミスを拒否します。解析中の添付ファイルは事前入力可能で、即時送信は明確なエラーを示します。プラグインは後で再試行するか、事前入力された会話を開始できます。失敗時はユーザーデータは削除されません。作成された通常の添付ファイルや空の会話は、既存のホストの保持規則に従います。

プレフィルは現在のUIプロセスのメモリ内にのみ存在し、リフレッシュや退出時に失われる。URLには会話IDとアプリ内部の一時的な起動識別子のみが含まれ、本文や添付ファイルのパラメータは含まれていない。ネイティブ `assistant.open` プラグイン名前空間を使用し、固定アカウント認証情報を使用する。プラグインを解除するかアカウントを切り替えると、保留中のリクエストがキャンセルされる。認証情報はWebViewには決して入らない。参照情報や添付ファイルは、ウェブやアプリで送信する前に削除可能である。

このインクリメントにより、データベーススキーマ、旧形式のリーダー、マイグレーション、または旧ホストアダプターは追加されませんでした。既存の対話はホストの通常の形式を維持します。ソースを復元する際には、変換や削除の必要はありません。この機能がないホスト、またはネイティブコンテナでは `assistant.open`その機能を提供することはできません。対応するアーティファクトを展開する必要があります。独立したnpmの公開とデバイスの受け入れには、別途検証が必要です。
