## 0.1.24 啟動自動升級

部署前停止全部舊宿主並備份 SQL、私有儲存和配置。0.1.24 對已釋出 0.1.22 的 `doca-2026-10-09-history-storage-v1` 自動以最新 DDL 對比整個結構；檢查透過後，在 schema 鎖事務中對齊宣告的新增結構並記錄目標代際。全部業務行及釋出指標原樣保留，包括舊 SQL 成果、執行及人工待辦；已有 0.1.23 物件儲存資料保持完整，無需手工知識冊命令。不新增單獨清理、自動正文轉換或舊正文執行時適配。殘留舊成果可能需要人工處理後才能使用相應知識冊。

結構或代際寫入失敗整體回滾，重複／併發啟動保留每條記錄。未知、更早或轉換中斷代際不改資料並停止；其他未知表仍需審查。備份恢復時保留全部資料及後續寫入，所有宿主和 Web 構建一起更新。

下方既有維護命令保留為需將舊成果繼續保留為可用原生格式時的可選無損方案，須在首次啟動前執行，因為結構對齊會改變轉換所需的源代際。下方歷史驗收證明可選無損轉換，不代表自動適配殘留舊 SQL JSON。

自動結構對齊驗收：實際 0.1.22 映象的 SQLite、PostgreSQL 17/18 隔離樣本均保留 114 張業務表的每一行及 20 份 SQL 正文，重複／併發啟動後新原生物件可讀。PostgreSQL 17/18 各透過 91 項迴歸，包括事務回滾和原生讀取器拒絕舊正文。見[驗證記錄](verification/book-schema-startup-2026-10-13/verification.json)。

<a id="执行步骤"></a>

## 執行步驟

使用包含本次改動的新宿主程式碼及原部署環境。已釋出 `smartdoca/doca:0.1.22` 是轉換來源版本，未包含新命令。保留原主金鑰、儲存 ID、後端配置與物件；停止全部宿主後備份資料庫（SQLite 包括 WAL）、私有儲存和配置。所有例項和 Web 構建一起更新。

命令讀取現有資料庫，不建立新庫。預設執行完整預檢，不寫入資料庫或上傳物件；`--apply` 和 `--hosts-stopped` 才開始。恢復清單必須是新的路徑，許可權為 0600，清單儲存原 footprint、記錄身份、長度與雜湊，不映象正文。

```sh
pnpm knowledge-books:storage upgrade
pnpm knowledge-books:storage upgrade --apply --hosts-stopped --manifest /secure/book-upgrade.json
```

只接受 `doca-2026-10-09-history-storage-v1`。更早代際先完成其準確支援的歷史升級。發現執行中知識冊任務、未知正文格式、損壞內容或待審結構差異時停止；需要先處理具體原因，不能強制清庫、取消未知任務或填補舊欄位。

中斷後，普通宿主拒絕轉換中代際。使用同一清單路徑重新執行原命令繼續，已轉換正文仍須與清單一致；不能換一份清單來忽略變化。完成後普通啟動只接受 `doca-2026-10-12-book-payload-storage-v1`。上線後重啟會掃描仍待處理的通知，已結束任務不補發；歷史輸出與錯誤保留。

當前回退在修改前拒絕非空的 `knowledge_book_batch_checkpoints`：這些引用須另行確認保全與恢復方案。不能刪除檢查點或繞過代際、結構檢查，見[檢查點保留與恢復](knowledge-book-generation-performance.zh-Hant.md)。下列歷史往返驗收早於批次檢查點，不證明任意當前庫均可降級到 0.1.22。

符合條件的回退前再次停掉所有宿主，保留新備份和新的回退清單。回退預檢讀取全部物件並驗證原始位元組；應用回退恢復升級後的新寫入，雲物件及回退清單保留，不恢復舊備份來丟棄後續成果。

```sh
pnpm knowledge-books:storage rollback
pnpm knowledge-books:storage rollback --apply --hosts-stopped --manifest /secure/book-rollback.json
```

中斷回退使用同一回退清單繼續。還原全部 JSON 並複驗後，僅撤銷四張儲存後設資料表，恢復舊代際和已檢查的 footprint。目標是升級前 0.1.22 宿主；要繼續回退文件歷史儲存，必須先完成此知識冊回退。SQLite 釋放頁不自動縮小檔案，不自動 VACUUM。

## 隔離驗收

實際來源映象 `smartdoca/doca:0.1.22`，映象 ID `sha256:a5316eb01bf25b0d89801139de85d34a35528be376699c4981ab8a09fd14f04c`。使用合成使用者和來源，由舊版真實執行器生成成功、失敗和待發布任務；未訪問使用者文件或生產資料庫。

SQLite、PostgreSQL 17 和 18 各有 20 份非空舊正文。全部執行顯式升級、兩次普通啟動及顯式回退；20/20 原始 JSON 位元組與雜湊一致，狀態、錯誤、配置與人工待辦保留。結果記錄於倉庫 `docs/verification/knowledge-book-storage-plan-2026-10-12/actual-roundtrip*.json`。

| 新 SQL 引用位元組 | 7,170 | 7,170 |

後設資料數字是物件、引用、操作及依賴邊的 JSON 序列化大小，不等於資料庫頁、索引、WAL 或備份大小。文字重複度很高，不能用該壓縮比例承諾生產節省率；真實資料庫物理檔案需單獨測量。

迴歸覆蓋分片邊界、轉義與 Unicode、同冊去重/跨冊隔離、併發競爭、租約中斷與續轉、損壞物件、未知格式無部分 DDL、新寫入完整回退、SQL 摘要零物件讀取、許可權撤銷及快取、回收站與永久刪除、遲到上傳的持續清理。CI 的資料庫矩陣加入知識冊與正文儲存測試。

瀏覽器驗證記錄於 `lazy-candidate.json`：展開前讀取 0 次、展開後 1 次、再展開復用快取，許可權撤銷移除正文，無瀏覽器異常。流程圖穩定性另見 `docs/verification/knowledge-book-reliability-2026-10-12/preview-result.json`。

<a id="运维边界"></a>

## 運維邊界

複用宿主私有 local/S3 儲存配置；未新增公開下載地址或模組憑據。必須將資料庫與物件儲存作為一致的備份集合保留。物件缺失或校驗失敗時讀取明確失敗；保留成果引用，不返回空正文來掩蓋損壞。

清理只刪除不可達物件。回收站保留引用，永久刪除釋放引用；活躍上傳依賴受保護，失敗和遲到上傳保留持久化鍵以便重試。操作記錄不存正文，完成後只保留競爭產生的多餘上傳鍵，已安裝依賴由物件與邊表記錄。沒有新增歷史 TTL。

最終檢查：SQLite 相關全套 126 項透過；補充介面及最終許可權檢查的知識冊/儲存 60 項透過。PostgreSQL 17/18 各 68 項相關全套透過，最終儲存介面套件各 11 項透過。型別檢查、Web 構建、文件連結及差異空白檢查透過。完整記錄為 `docs/verification/knowledge-book-storage-plan-2026-10-12/verification.json`。心跳與物件清理使用獨立排程，雲請求不會佔用心跳掃描。
