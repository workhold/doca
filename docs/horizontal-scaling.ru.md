# Одно экземпляр и горизонтальное масштабирование

[中文](horizontal-scaling.zh-CN.md)

Doca использует режим одиночного экземпляра без дополнительной инфраструктуры. SQLite, локальный директория для загрузки, и процессорный реального времени-буш подходят для одного человека, небольшой команды или тестов. Настройка PostgreSQL, объектного хранения и Redis требуется только в случае работы более одного примера приложения. Оба режима используют один и тот же бизнес-протокол. Не существует встроенного пути передачи данных от SQLite к PostgreSQL или двойного записи. Поддерживаемые обновления базы данных выполняются по следующему сценарию. [Контракт на обновление базы данных](database-schema-evolution.ru.md).

<a id="capability-matrix"></a>

## Матрица способностей

| Способность | Одно экземпляр | Множество реплик |
| --- | --- | --- |
| База данных | SQLite или PostgreSQL | PostgreSQL; каждый репликат использует один и тот же базу данных |
| Документы о сотрудничестве и уведомлениях | Передача и присутствие в процессе | Redis Pub/Sub и Redis presence |
| Логин, загрузка и ограничения скорости использования публичных ботов | Контроллеры в процессе | Контейнеры Redis |
| Файлы | Локальный постоянный директорий | Хранилище совместимое с S3, или файловая система, действительно общая для всех реплик |
| CDN | Необязательно | Необязательно. Она только ускоряет чтение и не заменяет общую память. |
| Фоновые задачи | Аренда баз данных | Те же самые аренды; любая копия может претендовать на работу, а неудачу можно повторно попробовать. |
| Мобильное push-уведомление | База данных на выходе | Тот же способ вывода и аренды; не хранить очередь только в одном процессе |
| Схема | Первый запуск создает текущую базовую линию. | Один экземпляр создает пустую базу перед первым развертыванием |
| Здоровье | `/live` и `/ready` | `/ready` также проверяет базу данных и Redis |

<a id="single-instance"></a>

## Одно экземпляр

Когда `DOCA_REDIS_URL` Не установлено; события в реальном времени, присутствие и ограничения скорости остаются в процессе. Redis не требуется. `pnpm dev`, `pnpm start`Один контейнер Compose создает текущую базовую структуру на пустом базе данных, а затем сопоставляет существующие структуры с текущим DDL.

Не запускайте две реплики в этом режиме. Sticky WebSockets на балансере на время скрывают проблему. Уведомления, отмена прав, активные пользователи и глобальные ограничения все еще разделены.

<a id="minimum-multi-replica-configuration"></a>

## Минимальная конфигурация множества реплик

Каждый копирующий устройству должен иметь одинаковые настройки:

```dotenv
DOCA_DATABASE=postgres
DOCA_DATABASE_URL=postgresql://user:password@postgres:5432/doca
DOCA_DATABASE_POOL_MAX=10
DOCA_REDIS_URL=redis://redis:6379
DOCA_REDIS_PREFIX=doca-production
DOCA_TRUST_PROXY=10.0.0.10/32
```

Оркестратор может установить `DOCA_INSTANCE_ID` К имени поды или контейнера. В противном случае каждый процесс генерирует случайный идентификатор. `DOCA_REDIS_PREFIX` Необходимо разделить окружения, которые используют один Redis. `DOCA_TRUST_PROXY` Перечисляются только адреса реверсивных прокси или CIDRs. Более широкий список позволяет клиентам создавать фальшивые IP-адреса и обходить ограничения по аудиту и лимитам использования ресурсов.

Порядок выпуска:

1. Начните создание одного экземпляра на пустом базе данных, чтобы получить базовую конфигурацию. Не позволяйте нескольким репликам одновременно инициализировать пустую базу данных.
2. Начните запуск других реплик с тем же релизом и конфигурацией. Утвержденные структурные изменения согласуются с ограничениями схемы; неподдерживаемые или требующие проверки различия прекращают запуск без частичных записей.
3. Балансер нагрузки использует `/ready` для движения транспорта `/live` Для здоровья процесса должны быть разрешены обновления WebSocket и нормальное откачивание.
4. Готовность к сбросу и разрешение закрытия соединений HTTP/WebSocket в течение периода остановки. Соблюдайте требования к порядку остановки/запуска; поэтапное развертывание не обеспечивает совместимость между различными версиями хостов.

После настройки Redis он необходим. Неудачное подключение при запуске, последующее отключение или неудачная проверка готовности не переключаются на локальный бизнес-модуль. Это предотвращает разделение кластера на несколько отдельных инстансов, которые все еще выглядят здоровыми.

<a id="consistency"></a>

## Согласованность

Обновление о сотрудничестве хранится в транзакции PostgreSQL и подтверждается, затем Redis сообщает о нем другим репликам. Redis не является журналом документов. Дублирующие события удаляются по протоколу. Краткий сбой восстанавливается из базы данных после снова подключения. Наличие исчезает, поэтому сбитая инстанция исчезает.

Распознавание файлов, извлечение текста, рабочие процессы, связанные с знаниями и книгами, а также передача данных по мобильным каналам используют базы данных и аренды. Ключовые элементы гарантируют, что несколько копий, сканирующих данные вместе, создают только один бизнес-опыт. Обработчики должны быть идемпотентными, так как другая копия может повторно попытаться выполнить операцию после истечения срока аренды.

<a id="capacity"></a>

## Производительность

- Общее количество соединений с базой данных составляет примерно реплики × `DOCA_DATABASE_POOL_MAX`Соблюдайте лимит PostgreSQL или Pooler, оставляя место для операций и фоновых задач.
- Локальный диск не может хранить загрузки для нескольких хостов. CDN хранит только чтение. Объекты остаются в S3 или на общем файловом системе. Хранилище названо по существующему имену... `storage_profile` Должно оставаться доступным.
- Meilisearch, S3 и шлюзы сообщений должны показывать каждому реплике одинаковую конфигурацию и одинаковые данные. Криптографические данные хранятся в общем базе данных. Доступ в сеть, списки разрешений и ключи по-прежнему являются задачей развертывания.
- Общий база данных записывает выходные версии желаемых плагинов и содержит неизменяемые ZIP-файлы в общем хранилище. Каждый репликату нужна своя записываемая директория установки/каша (`DOCA_PLUGINS_DIR`; старт-сервис проверяет и восстанавливает его из архива. Операции вступают в силу после ручного перезапуска каждого реплика. Соблюдайте однородность работающих версий; см. [развёртывание плагина](plugin-deployment.ru.md).
- Redis должен использовать аутентификацию, TLS или приватную сеть, ограничение объема памяти и уведомления. База данных и объектное хранилище все еще нуждаются в собственных копиях. При потере Redis не должно пропадать текст документов, но это нарушает возможность реального времени доставки, состояние присутствия и глобальные ограничения.
- `/ready` Это только доказывает, что копия может достичь базы данных и реального времени. Она не заменяет полную проверку процессов сотрудничества, хранения объектов, поиска и сообщений.

<a id="still-needs-an-external-rehearsal"></a>

## Ещё нужен внешний репетиционный процесс.

Код покрывает обновление документов, курсоры, состояние присутствия пользователей, общие ограничения, а также аренду баз данных или использование внешних устройств в двух приложениях. Перед внедрением проведите тренировки с использованием PostgreSQL, управляемого Redis, S3, WebSocket и процедур обновлений в целевой инфраструктуре. Включите ситуации с ошибками: приостановите работу Redis, остановите реплику, выполняющую какую-либо задачу, отмените доступ во время редактирования, создайте несоответствие в базе данных, а также приведите к таймауту хранение объектов.
