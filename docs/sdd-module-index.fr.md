# Index du module SDD

Le [client de bureau](desktop-client.fr.md) S'étend sur le shell de Tauri, authentification d'hôte distant, transport Web intégré et session de fenêtre. L'acceptation et la validation des fonctionnalités se déroulent en temps réel. [`specs/006-desktop-client`](../specs/006-desktop-client/spec.md) et [`specs/007-desktop-workspace-tabs`](../specs/007-desktop-workspace-tabs/spec.md).

[中文](sdd-module-index.zh-CN.md) · [Processus de travail](sdd.fr.md)

Cet index relie les modules existants aux sources, aux contrats actuels et aux vérifications réutilisables. Il ne certifie pas les fonctionnalités existantes ni ne réexécute les acceptations historiques. Vérifiez les exportations réelles et les versions des fichiers de verrouillage avant de travailler ; consultez… [architecture](architecture.fr.md) et les notes de sortie applicables pour les limites actuelles. Ajoutez un nouveau SDD lors du changement d’un module, et mettez à jour son contrat autoritaire dans le même PR.

Les tests de liens constituent des points d’entrée, mais ne constituent pas un plan de test suffisant pour chaque modification. Il faut choisir des vérifications en fonction des critères d’acceptation et des limites réelles : les résultats de SQLite seuls ne prouvent pas les mises à jour de PostgreSQL ; les mocks ne prouvent pas les fournisseurs externes ; les tests locaux ne prouvent pas les appareils natifs ou le déploiement en production. Consultez les compétences applicables avant de modifier ces domaines. Les paquets d’éditeur et les plugins métier existants, versionnés indépendamment, nécessitent leurs propres vérifications de dépôt et des enregistrements d’intégration et de version explicites.
