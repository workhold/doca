# Продолжение фоновой задачи

Текущий источник SDK **0.2.0**, возможности сервера `ai.continuations.v2`экспортировано из `@smartdoca/plugin-sdk/ai`Публикация и развёртывание npm не предусмотрены. Это характерно для всех установленных серверных плагинов; книги знаний используют тот же механизм хостинга.

Объявить `aiContinuationsServiceToken` как необходимая инъекция `sdkRange: "^0.2.0"`Хост без этой возможности отклоняет процедуру инициализации. Не существует адаптера для версий отключенных сервисов ИИ или автоматической регистрации исторических бизнес-задач.

Контексты инструментов MCP не имеют `sessionId`; использовать `jobId` для корреляции задач. Их `wait` Запросы могут возвращать разрешенные снимки, но не запускать внутренний чат или продолжение модели. Внешний клиент остается ответственным за последующие запросы.

Плагины имеют собственные бизнес-задания, текущую авторизацию, долговечные результаты, стабильные идентификаторы работы и отправку уведомлений/данных в очередь. Эти данные хранятся через публичное хранилище, управляемое хостом. Хост имеет идентичность помощника, сохраняет заявки на ожидание, возможность отмены, продолжение работы модели и технические ограничения. Утреннее пробуждение не авторизует бизнес-действие или одобряет человеческую задачу.

1. Зарегистрируйте источник во время монтажа. Его `id` должно начинаться с `<pluginId>.` и его `pluginId` Должно совпадать с идентификационным номером установки. Регистрация автоматически удаляется при выбытии.
2. `read(context, {operationId})` Перепроверяет текущую разрешение на работу и возвращает снимок версии 1, или null для отказанных/недоступных задач. Он получает свежо прочитанный идентификатор хоста и сигнал об отмене; не возвращает секреты. Идентификатор операции обозначает одну долговременную задачу, а не пользовательски предоставленный принцип.
3. В текущем исполняемом регистрированном ИИ-инструменте вызовите `wait(pluginId, context, {sourceId, operationId})` С учетом точного контекста, предоставленного хостом. Копированные, подделанные или сохраненные контексты отклоняются. Начните бизнес-задачу импедентно перед ожиданием. Инструмент возвращает квитанцию.
4. Сделайте результат перед вызовом `wake(pluginId, {sourceId, operationId})`Повторные уведомления позволяют использовать один хранящийся помощник контрольная точка только один раз. Уведомление перед парковкой безопасно: периодическая реконцилировка и восстановление после запуска снова читают долговременный источник.

Снимок имеется. `version: 1`, `state`, `revision`, `summary` и опциональный JSON `result`Государства `running`, `waiting_input`, `completed`, `failed`, `cancelled`. Изменение `revision` Когда действие или решение человека меняется. Пульсация сердца не пробуждает модель. Переход к человеческому вводу пробуждает её один раз; помощник может объяснить ожидающую задачу и продолжает ожидать дальнейшего решения. Терминальные снимки возобновляют оригинальную задачу с фактами результата. Результаты терминальных задач должны оставаться стабильными; новое выполнение бизнес-задачи требует нового идентификатора операции.

Хост сохраняет только полные обмены инструментов. Во время ожидания он освобождает слот выполнения, сохраняет оригинальную задачу/контрольную точку и не предпринимает необычных попыток восстановления. Чтение данных повторно разрешено при регистрации, уведомлении и выполнении. Отмена разрешения, отключение пользователей, удаление источников и недействительные записи прекращают продолжение с видимой ошибкой и сохраняют контрольную точку. Отмена помощника лишает его возможности возобновить работу; отмена бизнес-задачи — это отдельное действие плагина.

Ограничения: 20 зависимостей за каждый обмен со слугой, идентификаторы источников длиной 120 символов, идентификаторы операций/ревизии длиной 200 символов, краткие описания длиной 2,000 символов, сериализованный снимок длиной 24,000 символов и срок выполнения 20-секундного вызова источника. Согласование использует страницы ключевого набора и ограниченные параллельные чтения; один медленный источник не занимает обычные слоты выполнения модели. Начальное согласование ожидает завершения сборки плагинов.

## Пример интеграции

Это `jobs` Подпись ниже — собственный репозиторий плагина, поддерживаемый `storage.sql.v1`, **Не экспорт SDK**. `startOnce` нужно использовать прочную ключевую комбинацию для обработки запросов; `readAuthorized` Проверяет разрешения на доступ к ресурсам в реальном времени и возвращает текущий снимок. Уведомление рабочего процесса происходит в соответствии с зафиксированной бизнес-транзакцией

```ts
import { aiServiceToken, aiContinuationsServiceToken } from "@smartdoca/plugin-sdk/ai";

// Inside mount(context):
const pluginId = "example.reports";
const sourceId = `${pluginId}.jobs`;
const ai = context.inject(aiServiceToken);
const continuations = context.inject(aiContinuationsServiceToken);
continuations.registerSource({
  id: sourceId, pluginId,
  read: (request, { operationId }) => jobs.readAuthorized(request, operationId),
});
ai.registerTool({
  id: `${pluginId}.generate`, description: "Generate a report",
  inputSchema: { type: "object", properties: { reportId: { type: "string" } }, required: ["reportId"], additionalProperties: false },
  async execute(input, request) {
    const operationId = await jobs.startOnce(request, input.reportId);
    return continuations.wait(pluginId, request, { sourceId, operationId });
  },
});

// In the plugin worker, after its durable result commit:
await continuations.wake(pluginId, { sourceId, operationId });
```

## Постоянство и возврат к исходному состоянию

Только новые явные ожидания записывают строгую версию 1 контрольную точку. Существующие `ai_jobs` Государственные ограничения остаются неизменными: зависимости используют свое состояние «застывания» и выявляют его. `awaiting_dependency` В API/UI. Нет миграции схем, двойного записи, вычисления старых заявок, преобразования отсутствующих полей или пробуждения исторических задач. Неправильно составленные новые заявки отклоняются и сохраняются для диагностики.

Роллбэк останавливает новые регистрации/записи и сохраняет контрольные точки, результаты бизнеса и записи аудита. Старый хост не возобновляет этот новый протокол; не запускайте его через активные сервера версии 1, не отменяя соответствующих помощников или останавливая рабочих, и не восстанавливая соответствующего хоста. Рестарт данных не является частью роллбэка.

Прогресс работы с знаниями-книгами использует существующую систему хранения данных, с компактными счетчиками узлов/батчей/моделей/повторных попыток. В эти логи не копируется содержимое моделей. Интерфейс выполнения обновляет статус, сердцебиение, текущую ошибку и последние 200 зафиксированных событий. Исторические события не создаются насправді; более старые события остаются в хранилище.
