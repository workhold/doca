# Ключи входа в плагин, управляемые хостом

[中文](plugin-credentials.zh-CN.md)

Опубликовано: хост 0.1.10 и SDK 0.1.9, включая API для учетных данных, ранее добавленные в исходный код SDK 0.1.8. SDK 0.1.7 не экспортирует его. Плагины для электронной почты должны объявлять `^0.1.9` И использовать токен публичного сервера, а не импортировать источник хоста или самые пароли.

```ts
import { pluginCredentialToken } from '@smartdoca/plugin-sdk/storage';

// Declare pluginCredentialToken in injections.required.
const credentials = ctx.inject(pluginCredentialToken);
const created = await credentials.create({value: JSON.stringify({password: 'example'})});
// Store created.id in the plugin database with the business account and grants.
const metadata = await credentials.inspect(created.id); // No plaintext.
const stored = await credentials.get(created.id); // Server plaintext or null.
if (stored) {
  const refreshed = await credentials.update({
    id: stored.credential.id,
    expectedRevision: stored.credential.revision,
    value: JSON.stringify({accessToken: 'new', refreshToken: 'new-refresh'}),
  });
  await credentials.remove({id: refreshed.id, expectedRevision: refreshed.revision});
}
```

Метаданные — `{id, revision, createdAt, updatedAt}`Хост генерирует идентификаторы; плагины не могут предоставлять идентификаторы, диапазоны, имена баз данных или конфигурацию сервера. `get` возвращает `{credential: metadata, value: string} | null`; `inspect` Возвращает метаданные или null. Значения — это непустые корректные строки Unicode, максимум 64 КиБайт UTF-8. Плагины явно сериализуют объекты OAuth; нет неявной конвертации формата.

Обновления и удаления требуют положительного целого числа. `expectedRevision`Подходит только один одновременный обновление. Старый вариант версии возвращается. `conflict`Перечитайте и применяйте бизнес-правила, а не перезаписывайте новый токен обновления. Удаление отсутствующей записи является идемпотентным действием. Недействительные входные данные возвращаются `invalid-input`Некорректные установки, поврежденные записи, сбой сервиса/базы данных, или обновление отсутствующей записи приводят к возникновению ошибок. `unavailable`Ошибки включают отсутствие входных данных, ошибки в SQL, настройки соединения или проблемы с шифрованием.

Аутентифицированное шифрование AES-256-GCM связывает записи с `plugin:<pluginId>`Генерация установки, UUID и ревизия. База данных хранит зашифрованные записи, и каждое запись вводятся с использованием нового случайного номера. Другие плагины не могут читать, обновлять или удалять эти записи. Отключение или завершение работы со стеком сохраняют их. Явное удаление удаляет учетные данные той генерации из транзакции реестра и аннулирует старые обработчики; повторная установка использует новую генерацию. Для выполнения любых внешних отменных действий необходимо использовать чистый текст перед завершением удаления. SDK не решает вопросы авторизации бизнес-аккаунтов: плагины проверяют разрешения пользователя/аккаунта перед чтением и никогда не возвращают чистый текст браузерам, контексту ИИ, логам или обычным API для конфигурации.

Операции с кредентиями и бизнес-транзакции плагинов осуществляются отдельно. Если сохранение бизнес-реферата после создания кредентия не удается, необходимо удалить кредентий. Плагины восстанавливают внешние обновления OAuth, коммиты базы данных и потерянные ответы в соответствии со своими правилами. Нет межсервисных транзакций, ключа импедентичности, общей координатора задач или автоматического обновления ключей. См. также [Пример хранения](../examples/plugin-storage/README.md)Плагины работают в надежном процессе Node.js; API с ограничениями не являются суммарным средам для работы операционной системы.

## Среда развертывания

`DOCA_CREDENTIAL_MASTER_KEY` Должно быть 32 случайных байта, кодированных в виде 64 шестнадцатеричных символов; сгенерируйте их. `openssl rand -hex 32`Установите его один раз, сохраните при повторных запусках и сделайте резервную копию отдельно. Ключ необходим для запуска каждого хоста, даже без плагинов; отсутствие, пустой или некорректно сформированный конфигурационный файл приводит к отказу от запуска. Примерные файлы содержат публичное значение для иллюстрации только; замените его при новой установке, а оригинальный ключ сохраните для существующего развёртывания. База данных сохраняет отпечаток ключа; несоответствующий ключ приводит к отказу от запуска без перекодировки данных. Удаление последнего плагина не устраняет этот ключевой идентификатор. Каждый процесс, использующий базу данных, использует один и тот же ключ.

Операторы выбирают базу данных и хранилище файлов: SQLite/локальные файлы для одного экземпляра; настройка общей базы данных и облачного хранилища для нескольких экземпляров. API плагина не выбирает топологию развёртывания. Составляйте настройки базы данных Compose, пул, базы данных Webhook, Redis и экземпляров; см. [docker.env.example](../docker.env.example).

Хранение файлов настроено только через `DOCA_FILE_STORE_ID` и строгая версия 1 `DOCA_FILE_STORES_JSON`включая учетные данные S3/CDN. Страница администрирования хранилища доступна только для чтения; старые запросы на конфигурацию хранилища отклоняются. См. также [запись реализации](unified-storage-implementation.md) Для примеров. Ключ-мастер плагина и учетные данные для соединения с облачным хранилищем независимы. Существующая конфигурация платформы идентификации, сообщений и поиска не конвертируется и не перешифровывается этим изменением.

Базовый уровень базы данных `doca-2026-10-03-credentials-v2`Согласно ранее согласованной политике перевода, хост-базы данных версии 0.1.9 и более старые отклоняются. Сохраняются старые базы данных, объекты и развертывания; не предусмотрено автоматическое исправление таблиц, миграция, импорт или сброс. Используется новая пустая база данных. Роллбэк использует оригинальное развертывание/данные и отдельно сохраняет данные нового развертывания. Отсутствующий сервис учетных данных SDK 0.1.7 не должен обходиться с помощью локальных файлов, управляемых самим пользователем.
