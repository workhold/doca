# Границы архитектуры и реализации

[中文](architecture.zh-CN.md)

Базовый уровень: хост 0.2.23 / SDK 0.1.11, документация проверена по исходнику 28.10.2026. Это описывает реализованные ассемблеры и границы; сервисы и поведение устройства, специфичные для развертывания, требуют отдельного одобрения. Начать с [способности и ограничения](features.ru.md).

<a id="application-and-modules"></a>

## Приложения и модули

Doca — это модульный монолит на TypeScript. Разработка осуществляется с использованием React/Vite и Fastify на отдельных портах за пределами одного браузерного источника. В производстве веб-приложение и API предоставляются через Fastify. Cordis управляет сервисами в процессе и жизненным циклом; публичный SDK определяет границы плагинов.

```text
Browser: React + five document editors
  │ same-origin HTTP / WebSocket; host-authenticated sessions
Fastify: Host/Origin validation, routes, security, static files
  │
Host composition: accounts, documents, files, search, AI, knowledge
  │ trusted business plugins discovered in the installation directory
Core domain rules / Kysely database access
  │
SQLite single instance, or shared PostgreSQL + Redis + file backend
```

Обычный хост содержит форматированный текст, Markdown, электронные таблицы, слайды, холст, разрешения на документы, инструменты обнаружения, файлы, подписки на источники и книги знаний, аутентификацию, проверку регистрации, аудит безопасности и факты использования чистой ИИ. Краткие заметки, электронная почта, календарь, членство, расчеты, бизнес-квоты и модерация — это независимые бизнес-задачи; такой провайдер не установлен по умолчанию. Шаблоны/материалы/элементы предоставляют интерфейсы без каких-либо по умолчанию предоставляемых провайдеров.

<a id="directories"></a>

## Директории

| Путь | Ответственность |
| --- | --- |
| `apps/server/src/main.ts` | Стартап, прослушивание, отключение |
| `apps/server/src/bootstrap/config.ts` | Происхождение, база данных, прокси, конфигурация Redis |
| `apps/server/src/app/create-app.ts` | HTTP маршруты, сессии и границы безопасности |
| `apps/server/src/plugins/composition.ts` | Встроенные сервисы и установленные плагиновые компоненты |
| `apps/server/src/routes` | Хост HTTP- endpoints |
| `apps/server/src/services` | Realtime, поиск, ИИ и другие приложения услуг |
| `apps/web/src/app/app.tsx` | Роутинг рабочего пространства и сборка функций |
| `apps/web/src/features/documents/document-editor.tsx` | Отправка пяти установленным пакетам редактора |
| `packages/core/src` | Правила домена, авторизация и транзакции |
| `packages/db/src/create-schema.ts` | Текущая целевая структура данных для создания новых ресурсов и сопоставления начальных данных |
| `packages/plugin-sdk` | Публичные интерфейсы серверов/веб/плагинов |
| `tests` | Изолированные единицы и проверки интеграции |

Веб-код использует HTTP DTO, а не импортирует внутренности базы данных или паролей. Бизнес-плагины используют опубликованные сервисы SDK и никогда не импортируют исходный код хоста или создавать глобальные мосты выполнения. См. также [архитектура плагинов](plugin-architecture.ru.md) и [инвентарь реализации](plugin-sdk-contract.ru.md).

<a id="identity-and-security"></a>

## Идентичность и безопасность

Один развертывание содержит один система учетных записей, без таблиц организации, пространства и арендатора. Регистрация и внешние поставщики начинают работать отключены; не существует по умолчанию администратора. Пароли используют scrypt и случайные соли; база данных хранит сессионные дигесты. Сессии браузера, QR-входа и WebView по умолчанию имеют срок действия 24 часа; сессии для мобильных устройств — 180 дней. Оба срока действия можно настроить. [налаживание сессии](configuration.ru.md#login-lifetime)Изменение пароля и отключение аккаунта отменяют сессии.

Каждый запрос проверяет настроенный хост. Мутации также проверяют Origin того же источника. Куки сайта имеют атрибуты HttpOnly, SameSite=Strict и Secure через HTTPS. Адаптеры аутентификации поддерживают внешние OIDC и социальные провайдеры; реализованы процедуры проверки и восстановления учетных данных, для чего требуются проверочные шлюзы. Управление утверждением регистрации имеет специальную процедуру рассмотрения. Doca как провайдер OIDC, SAML и logout на уровне IdP недоступны. Смотрите [аутентификация](authentication.ru.md).

Администрация не предоставляет доступ к приватному контенту. Отсутствие возможности чтения обычно приводит к возврату кода 404; авторизованный читатель, не предпринимающий никаких действий, получает код 403. ACL, наследуемые разрешения, публикации, коллекции и совместное использование имеют отдельные правила. Скрытые предки не раскрываются. Смотрите [права](permission-inheritance.ru.md) и [откровение](public-resource-discovery.ru.md).

<a id="persistence-and-collaboration"></a>

## Постоянство и сотрудничество

Метаданные документа используют HTTP и проверку версий. Все пять форматов редактора используют один жизненный цикл WebSocket на хосте с специфическими кодеками Yjs для формата. Сервер проверяет содержимое, повторно проверяет авторизацию и коммитит перед подтверждением; версия метаданных, последовательность содержимого, эпоха, схема и идентификаторы истории — это разные параметры. История доступна для всех форматов, но восстановление в настоящее время поддерживает только форматы форматированного текста и Markdown. Смотрите [Сотрудничество](collaboration.ru.md) и [история документов](document-experience.ru.md).

SQLite, ИИ и Webhook-базы данных плюс локальные файлы работают в одной инстансе. PostgreSQL использует отдельную базу данных Webhook и схему ИИ. Для множества реплик требуется общая база данных, локальный backend файлов и Redis для событий, присутствия и ограничений. Без Redis эти реализации являются процессно-локальными. Проблемы с настроенным Redis не работают в тишине. Задания базы данных используют аренды/outboxes, а не только память процесса. Смотрите [конфигурация](configuration.ru.md) и [горизонтальное масштабирование](horizontal-scaling.ru.md).

Объекты сохраняют стабильные идентификаторы хранилищ и ссылки на объекты. Конфигурация окружения выбирает физические хранилища; страница управления хранением доступна только для чтения. Через частные скачивания повторно проверяется доступ. CDN предоставляет истекающие разрешенные URL и никогда не заменяет хранилище. Бэкапы включают все базы данных, используемые серверы, архивы плагинов и защищенные конфигурации. Смотрите [хранение файлов](storage.ru.md).

Установленные плагины используют общие реестровые записи и неизменяемые архивы, а также записываемый кэш для каждой инстанции, восстанавливаемый при запуске. Ручной перезапуск активирует желаемые версии. Управляемая приватная SQL, объекты и учетные данные реализованы; вытеснение задач, временные рабочие пространства и более строгая изоляция процессов остаются проблемами. Валидация точной версии отклоняет неподдерживаемые базовые структуры или конфигурации; здесь не добавляется никакой миграции или адаптера совместимости. Существующие данные должны быть сохранены. Смотрите [требования к выпуску](releases/0.2.23.md) и [Контракт на обновление базы данных](database-schema-evolution.ru.md).

<a id="current-limits-and-acceptance"></a>

## Текущие ограничения и приемлемость

В комментариях и уведомлениях есть специальные пагинационные endpoints; детальная информация о документах не является полным экспортом комментариев. Реализованы постоянные локальные копии и внешние почтовые ящики; полноценный оффлайн-аппаратный шелл недоступен. Интеграция с нативными устройствами, провайдеры личности/ИИ, производственные S3/CDN и механизмы отказоустойчивости критической инфраструктуры требуют отдельного согласования. Автоматизированные изолированные тесты подтверждают свою целевую функциональность; сборка не доказывает, что все внешние сервисы работают корректно.
