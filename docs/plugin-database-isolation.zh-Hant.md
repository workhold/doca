# 外掛共享業務資料庫

[English](plugin-database-isolation.md)

所有外掛共用一個宿主管理的業務資料庫，與核心資料庫分開。PostgreSQL 只需為整套部署配置一次資料庫和賬號，宿主自動建立每個外掛的 schema 和業務表。SQLite 無需配置，自動建立一個共享檔案。外掛繼續使用原有 `storage.sql.v1` SDK、version 1 結構宣告和 `dataVersion`，不接觸連線串、驅動或檔案路徑。

<a id="配置与隔离"></a>

## 配置與隔離

SQLite 預設使用 `<DOCA_SQLITE_PATH>.plugins.db`，可用 `DOCA_PLUGIN_DATABASE_PATH` 指定其他持久化本地檔案，許可權為 0600。物理表增加 `plugin_<插件 ID 的 SHA256 前 56 位十六进制>__` 字首，SDK 表名不變。記憶體宿主在每個宿主連線內共用一個外掛記憶體庫。共享檔案須與核心庫、私有檔案儲存一起備份。SQLite 仍適用於單宿主。

PostgreSQL 由部署者預先提供一個業務資料庫和登入賬號。賬號許可權由部署者決定；普通賬號、超級使用者、具有管理屬性或角色成員關係的賬號，以及核心庫使用的同一個賬號均可配置。賬號須實際具備該業務庫的 `CONNECT`、`CREATE` 許可權以建立外掛 schema，並有該庫 `public` schema 的 `USAGE`、`CREATE` 許可權以初始化共享標記。資料庫級 `CREATE` 不包含 schema 級 `CREATE`；PostgreSQL 17/18 預設不會把後者授予普通非所有者角色，見 [PostgreSQL schema 許可權說明](https://www.postgresql.org/docs/18/ddl-schemas.html#DDL-SCHEMAS-PRIV)。啟用 SQL 外掛前配置一次：

```dotenv
DOCA_PLUGIN_DATABASE_URL=postgresql://doca_plugins:replace-me@postgres:5432/doca_plugins
DOCA_PLUGIN_DATABASE_POOL_MAX=4
```

以下是新部署在 `psql` 中建立專用賬號的可選示例（替換密碼），也可以直接配置已有且授權合適的賬號：

```sql
CREATE ROLE doca_plugins LOGIN PASSWORD 'replace-me';
CREATE DATABASE doca_plugins;
REVOKE ALL ON DATABASE doca_plugins FROM PUBLIC;
GRANT CONNECT, CREATE ON DATABASE doca_plugins TO doca_plugins;
\connect doca_plugins
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE, CREATE ON SCHEMA public TO doca_plugins;
```

已有部署保留原角色、資料庫和資料。若初始化提示缺少 `public` 的 `USAGE`／`CREATE`，由資料庫所有者連線到**外掛業務庫**，按配置的角色名執行 `GRANT USAGE, CREATE ON SCHEMA public TO doca_plugins;`。若建立外掛 schema 提示缺少資料庫 `CREATE`，由所有者執行 `GRANT CREATE ON DATABASE doca_plugins TO doca_plugins;`。修正授權後重新啟動即可重試，無需解除安裝、重置或轉換資料。宿主不自動授權；這些授權僅作用於專用外掛業務庫。已有共享標記不再要求 `public` 的 `CREATE` 許可權。連線串、密碼及原始 SQL 異常仍不向外掛響應暴露，上述固定的宿主配置診斷會明確返回。

首次宣告時，宿主自動建立 `plugin_<插件 ID 的 SHA256 前 56 位十六进制>` schema。每個宿主例項中的所有外掛共用一個連線池；`DOCA_PLUGIN_DATABASE_POOL_MAX` 為 1–20 的整數，預設 4。連線預算須計入外掛池、核心／AI／webhook 池和例項數量。所有副本必須使用同一個共享業務庫。以後新增外掛不再需要建立資料庫、角色或單獨配置連線。不使用 SQL 的外掛不要求此 URL。

配置的業務庫仍須與核心庫分離，即使兩個 URL 使用同一個賬號。宿主不檢查賬號的高許可權屬性、角色成員關係或核心表訪問許可權，也不修改資料庫賬號許可權；是否透過 PostgreSQL 授許可權制賬號，由部署者決定。宿主不建立資料庫或角色，也不回退到核心庫。PostgreSQL 事務使用事務區域性 schema，歸還連線後不保留其他外掛的作用域。解除安裝只檢查和刪除目標外掛宣告的表及安裝標記，其他外掛 schema、資料和共享庫保留。

賬號許可權由部署者管理的規則於 2026-10-16 獲得確認，取代已釋出 0.1.26–0.1.29 的賬號許可權拒絕檢查。已有格式 3 宣告、標記、安裝代次和資料版本原樣保留，不做格式轉換；升級不修改任何資料或賬號許可權。回退宿主會恢復舊賬號限制，管理員賬號可能再次被拒絕，規劃回退時須保留現有資料庫、資料和配置。下文格式 2 的升級流程不變。

這是透過宿主 SDK 服務實現的隔離。外掛仍執行在受信任的 Node.js 程序中；共享業務賬號不構成程序或作業系統沙箱。

核心庫仍儲存使用者、文件、許可權、安全審計、原始 AI 用量、外掛註冊／歸檔引用、名稱空間記錄、加密憑證、私有物件引用和持久化物件垃圾意圖。檔案／憑證歸屬與許可權、核心 DDL 和 `schema_baseline.id` 均不變。

<a id="精确存储格式与生命周期"></a>

## 精確儲存格式與生命週期

宿主宣告使用格式 3，初始為 `storageVersion: 3`、`schema: null`。共享庫根標記 `_doca_shared_plugin_database` 記錄格式 3；每個外掛的 `_doca_plugin_store` 記錄精確的外掛 ID、安裝代次、資料版本和規範化結構。標記驗證及限定作用域的結構檢查防止接管無關資料。共享檔案、名稱空間或已宣告的表丟失時明確拒絕，不會靜默重建。更換 URL／檔案不遷移資料；已有結構宣告後，空替代庫會被拒絕。

首次宣告鎖住核心名稱空間，在同一個業務事務中建立外掛名稱空間、表及標記，再在核心事務記錄宣告。核心提交中斷後的重試只接受精確匹配的已提交業務標記及實際結構。不同結構定義、型別／預設值／可空性、主鍵／唯一約束或額外表均拒絕。使用者事務回撥僅執行一次，完成後控制代碼失效。業務提交後核心提交失敗屬於結果不確定，須透過業務冪等／讀回處理，不重放回撥。

核心名稱空間鎖保持到業務提交結束，解除安裝須等待已獲准的寫入完成。業務解除安裝鉤子先執行；成功後，核心註冊事務封禁舊代次、清除安裝選擇及憑證，並排隊清理私有物件。普通使用者檔案、許可權、回執和釋出歸檔保留。鉤子失敗保留安裝，外部鉤子副作用不能回滾。

業務清理在核心提交之後執行，以保留的宣告作為持久化意圖。啟動、定時清理、解除安裝和安裝嘗試都會重試。清理驗證已移除代次及標記，只刪除宣告的表。未知表或標記不符時拒絕且不部分刪表。PostgreSQL 保留空名稱空間以便冪等重試，SQLite 保留共享檔案。重灌等待清理完成，增加代次並建立空業務表。不承諾分散式原子提交或自動叢集任務排空；每個例項仍須重啟。

<a id="从-0125-升级的已确认方案"></a>

## 從 0.1.25 升級的已確認方案

使用者已確認：**舊版正常解除安裝後重灌，不遷移外掛資料**。已釋出的 0.1.25 使用每外掛獨立檔案／資料庫及格式 2。有效的格式 2 安裝（包括無狀態外掛）會在核心結構核對寫入前被拒絕。舊配置 `DOCA_PLUGIN_DATABASE_DIR` 和 `DOCA_PLUGIN_DATABASES_JSON` 明確拒絕。沒有舊庫讀取、自動資料轉換、雙寫或自動刪除舊庫／檔案。

1. 備份原核心庫、全部舊外掛庫／檔案、私有檔案儲存、配置和原憑證主金鑰。
2. 在舊宿主正常解除安裝全部外部業務外掛，並處理完待清理項。此操作明確丟棄外掛私有業務記錄、加密憑證和私有物件；重灌後重新配置並繫結外部賬號。核心資料和普通使用者檔案保留。
3. 停止全部例項，移除舊的每外掛配置。PostgreSQL 提供一個新的空共享業務庫和部署者選擇的登入賬號；SQLite 使用自動共享檔案或指定路徑。舊庫及備份保留作為恢復依據。
4. 新宿主繼續使用原核心庫、普通檔案和原主金鑰。重灌外掛並重啟每個例項，宿主自動將外掛加入共享業務庫，私有業務資料從空開始。

解除安裝失敗須在舊版解決。啟動拒絕殘留安裝時，回到舊版完成解除安裝，不得重置核心庫。已移除的名稱空間歷史保留，顯式重灌增加代次。現有對 0.1.25 之前已清理名稱空間歷史的處理保持不變，不讀取舊業務資料。更早版本殘留的同庫 `plugin_<56 位十六进制>` 表仍需人工審查，不自動刪除。

新寫入之前，恢復到解除安裝前狀態須使用相互匹配的原核心／外掛／檔案備份及舊程式碼／配置。已撤銷的外部授權可能需要重新繫結。新寫入之後須保留新資料庫／檔案並另行確認恢復方案；直接恢復舊備份會丟失後續資料。舊宿主不能讀取格式 3，不支援新舊宿主混跑。

<a id="验证"></a>

## 驗證

`scripts/verify-plugin-database-isolation-upgrade.ts` 使用實際釋出的 `smartdoca/doca:0.1.25` 映象建立合成核心資料和格式 2 外掛私有資料，驗證拒絕時核心行／宣告不變、舊版正常解除安裝、同一核心庫重新開啟並重灌到空共享庫。在隔離 SQLite 和 PostgreSQL 17/18 上執行。託管儲存測試還覆蓋外掛同名邏輯表、共享物理儲存／連線池、重啟、併發作用域、回滾、舊代次封禁、庫丟失及可重試清理。這不代表已生產部署或支援新舊版本混跑。
