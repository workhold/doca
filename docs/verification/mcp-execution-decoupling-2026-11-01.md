# MCP 独立执行验证（2026-11-01）

本次按所有者同意的方案直接解耦。MCP 创建独立任务，不创建聊天、消息或记忆线程；权限、租约、取消、工具实现、操作回执和原始用量继续共用。历史 MCP 对话保留存储，从聊天入口排除，不转换、不续跑。

## 已验证的边界

- 新任务的 `ai_jobs.session_id`、`model_id` 和 `mcp_contexts.session_id` 为 NULL；原生五种文档格式和文件分块传输可正常使用，不需要配置 Doca 聊天模型。
- 同用户的不同独立任务不能互读图片回执和候选；NULL 会话关联不合并任务。文档 ACL、工具授权、账号状态、撤销和请求去重继续生效。
- 取消中的图片调用不能写出新交付文件，调用声明保持 interrupted；实际已完成的模型请求仍保存真实用量。停止任务使租约失效，后续工具调用拒绝执行。
- 任务资源使用独立账本。图片使用 `aiTaskId` 归属，保留 AI 输出目录的操作限制；批量交付校验真实任务及文件绑定。
- 独立执行记录仅由实际执行用户读取和管理，包括公司 MCP 服务代其执行的任务。资源链接重新检查当前权限。清理关闭任务保留文档、文件、操作回执、原始用量和安全审计。
- 插件 SDK 源码为 0.2.0，AI 服务为 `ai.v2` / `ai.continuations.v2`，工具上下文仅在真实聊天中提供 `sessionId`；普通聊天和背景续跑的回归通过。旧接口不提供适配。

## 数据库与升级

`scripts/verify-mcp-execution-decoupling.mts` 从实际发布标签 `v0.2.29` 提取源码，在隔离环境使用旧版数据库、账户、文档和 MCP runtime 创建历史数据，再由当前版本打开。SQLite、PostgreSQL 17、PostgreSQL 18 均通过：138 张原有业务表的行哈希一致，新任务资源账本为空；重复及并发启动、NULL 任务写入、未知结构拒绝后数据与 footprint 保持均已验证。

`tests/mcp-execution-schema.test.ts` 另验证：未知表阻止本次列属性调整和新表创建，不产生部分修改；已安装任务资源表丢失时报告可能的数据损失，不静默重建。PostgreSQL 矩阵同时运行 MCP 和原生列属性协调回归。

本次不改变兼容代际，不回填旧值。已有图片回执多版本校验、历史格式拒绝规则与停用的旧 MCP 凭据存储均保留，没有增加历史对话转换器或放宽来源授权。
