# エディターの共同編集契約

[中文](collaboration-sdk-contract.zh-CN.md)

リッチテキスト、Markdown、スプレッドシート、キャンバス、スライド、および今後登場する文書タイプに適用されます。2026-09-11に制定されました。実装の増分は、自身の日付とバージョンを保持します。使用してください。 [現在のエディターマトリックス](editor-integration.ja.md) インストールされたパッケージのため。

このプラットフォームには、1つの接続、権限、インクリメントストレージ、コミット確認、再接続、オンラインセッションが存在します。各コンポーネントはそれぞれのデータモデルとレンダリングを管理します。共有される動作とは、スプレッドシートをリッチテキスト構造に変換することを意味するわけではありません。

現在のサービスプロトコルも説明されています。 [共同編集と検索](collaboration.ja.md)この文書は次の共有契約です。ここにあるフィールドは自動的に公開されたAPIではありません。

## 1. レイヤーとバージョン

| 層またはフィールド | 共通の義務 | コンポーネントの違い |
| --- | --- | --- |
| 輸送 | 同じオリジンのWebSocket、1つのエンベディング、サーバー認証 | なし |
| 保存 | ローカルインクリメント、アウトボックス、データベースコミット、ACK | なし |
| フォーマット / コーデック / schemaVersion | 種類と、その構造が互換性があるかどうかを特定する | リッチテキストノードCRDT；スプレッドシートの安定した行、列、セルコマンド |
| エポックID | 1つのCRDT系。互換性のない再構築が起こった時にのみ変更される | スプレッドシートには、エポックに結びついた不変のワークブックベースラインも必要です |
| seq | 現在のエポックにおける有効なコミット数が単調である | なし |
| チェックポイントSeq | コミットシーケンスは、完全なYjsチェックポイントをカバーしている | コンポーネントがまだ再実行する必要がある論理コマンドは削除しないでください。 |
| resource.version | ビジネスメタデータのオプティミスティックロック | Yjsをマージするのに慣れていない |
| 歴史バージョンID | ユーザーが閲覧する、または取り消すことができるビジネススナップショット | すべてのネットワーク更新がそうではない |
| 状態ベクトル | 同期差の要約 | 完全な保存確認ではない、特に削除設定の確認についてはそうだ |

各フォーマットはepochIdを系譜として使用します。定期的なYjsチェックポイントはepochを変更しません。スプレッドシートは現在のYjsセッションとチェックポイントの順序を使用します。

## 2. プラットフォームとコンポーネント

このプラットフォームでは、1ページあたり1つのリアルタイムセッションがあります。それは、ソケット、ACL、インクリメントキュー、ACK、再接続、ビジネススナップショット、コメント、通知、アセット権限です。あるコンポーネントは、2回目のHTTP自動保存やソケットを開きません。

コンポーネントは、ドキュメントセッションごとにY.Docとエディターを一度作成します。ローカル編集はYjsにマッピングされ、リモートトランザクションはビューにプロジェクトされます。準備状態、エラー、フォーマット状態、選択肢、アンカーが公開されます。プロパティの変更、readonly、カーソル、サイズ、または保存ヒントを変更する場合、共有ドキュメントを再構築してはなりません。

サーバーはコーデックプラグインを介してフォーマットの違いを隠すことがあります：初期化、マージの検証、ビジネスプロジェクションの構築、インポートとエクスポート、および履歴のロールバックです。汎用的なルーム、権限、ストレージパスはツールバーやセルDOMを理解しません。

## 3. メッセージとライフサイクル

推奨されるエンベデッド情報：protocolVersion 1、type、id、room（リソースUUID）、epochId。最初の参加時はepochIdを省略してもよい。サーバーがそれを返した後は、後の書き込みでは必ずepochIdを含める必要がある。Identity、sessionId、name、colorはサーバーが決定する。

1. joinは、サポートされているコーデックとschemaVersion、既知のエポック、そしてベクトルを送信します。
2. sync-responseは、epochId、コーデック、schemaVersion、seq、checkpointSeq、rank、update、およびvectorを返します。スプレッドシートは、その応答に結びついた不変のベースラインも返します。
3. ベースラインがチェックされ、Yjsが完了し、プロジェクションが完了した後にのみ、このビューが利用可能になります。編集可能な空の文書を表示した後でそれを置き換えることはしないでください。
4. 更新にはid、room、epochId、およびYjsバイト（現在のJSONチャネル上でのBase64形式）が含まれます。実際のローカルコンテンツの増分のみを送信します。
5. ACKは、同じID、epochId、そしてコミット後のseqを使用し、必要に応じて変更されたビジネスメタデータも含まれます。これはトランザクションがコミットされた後に送信されます。
6. 有効な更新は、まだ権限を持っている他のセッションにブロードキャストされます。リモート更新を適用する際には、ローカルでの書き込みを生じさせてはなりません。
7. sync-requestとsync-responseは、差異を埋めるだけです。それらはACKではありません。未承認のキューをクリアしたり、毎回の追跡後に無条件にアップロードしたりしてはいけません。
8. ログアウトし、このセッションの選択を解除する。認可、エポック、スキーマのエラーは異なるものです。それらはすべて普通のネットワークリトリートではありません。

認識されない書き込みの再試行により、元のバイトとメッセージIDが保持される。Yjsのマージはイデメンタントである。重複の配信はシーク番号、監査、通知、または履歴を増加させない。Docaはエディターや、リソースID、エポックID、メッセージIDでキー付けされたマークダウン記録と共に重複を削除する。異なるペイロードを持つ同じIDは拒否される。

## 4. 状態を保存する

接続状態は、読み込み中、同期中、準備完了、そして失敗時の切断またはエラーとなります。保存状態は別にあり、クリーン、ダーティ、保存中、エラーです。

- ローカルコンテンツトランザクションのみがアウトボックスに入ります。初期化、選択、スクロール、フォーカス、サイズ、オンライン数、ハートビート、リモート再再生、および読み取り専用スイッチはコンテンツ更新を生じさせません。
- 「クラウドに保存」するには、空のアウトボックスと完了した同期が必要です。「保存」するには、承認を待つ書き込みが必要です。
- キューはシリアルに送信される。ヘッドIDと一致するACKのみがキューから削除される。不明な、遅れた、または重複したACKは、後続の入力を失われることはない。
- 切断時はバイトデータとIDを保持します。再接続時にはリモート側からデータを取得し、認識されなかった増分を再試行します。
- クライアントのオフラインイベントは、即座にリアルタイム接続を切断し、再試行を停止します。オンラインイベントでは再接続し、通常のドキュメント参加処理が実行されます。
- ブラウザがオフライン状態であるか、共同編集接続が失敗した場合、編集可能なレプリカにオフライン通知が表示されます。最初のオンライン接続と文書同期時には、その通知は隠れます。切断後、文書の同期が完了すると通知は消えます。
- 扱わないでください `encodeStateAsUpdate(doc, vector).length` とても汚れている。同じ状態でも歴史的な削除セットを返すことがある。2より長い長さは新しい書き込みではない。
- 時代の不一致により、古いキューが一時停止します。エクスポートや別の復元コピーが許可されます。古い増分は新しい文書に強制されません。
- 現在のホストアダプタは、元のチェックポイントと保留中のメッセージIDを保持します `offline-replica.ts`オフライン編集には、承認されたレプリカと正常なローカル保存が必要です。デスクトップバンドルやダウンロードしたWebフロントエンドは、ローカルの文書リストから開始できます。

両方のホストが使用する `apps/web/src/features/documents/update-outbox.ts`キューは文書の種類に依存しません。実際のローカル取引の増分を保持します。Sync-応答は無条件のアップロードを引き起こしません。

## 5. 推奨されるコンポーネントAPI

各コンポーネントは、区別可能なエラーコードを持つconnect、setReadOnly、dispose、onSelectionChange、renderRemoteSelections、clearRemoteSelections、onErrorといったメソッドを提供します。リッチテキストでは、マーク、ブロックタイプ、整列、canUndo、canRedoといったフォーマット状態も提供されます。固定ツールバンとフローティングツールバンはこの状態を共有します。DOMからフォーマットを推測しないでください。

トランザクションの起源は、ローカル、リモート、ブートストラッピングです。ローカルのみがユーザーによる書き込みです。リモートトランザクションを適用する際には、コマンドを再包装しないで、新しい操作IDを生成してください。

## 6. ライブセレクション

選択ユニオンはテキスト（相対的なアンカーとフォーカス）、セル（シートID、ゼロベースの閉じた行と列の範囲、編集）、またはnullです。

セッションIDは接続ごとに設定されます。オンライン数はユーザIDを重複排除します。描画では現在のセッションは除外され、同じアカウントの他のページが含まれます。編集がtrueの場合、ユーザが入力中であることを意味します。入力していない選択はfalseです。スプレッドシートの変更や編集の開始・終了はイベントを送信します。セル値、数式、キー入力は送信されません。公開は100～150msに制限され、重複排除されます。データベースに書き込んだり、バージョンを更新したり、元に戻す操作は行われません。両方の編集モードでこのセッションの選択が公開されます。注意散漫のない編集では、現在の文書ビュー内で他のセッションのカーソルや選択肢が隠れます。エディターを離れる、文書を離れる、接続を切断、または撤回により選択がクリアされます。サーバーは各メッセージでACLをチェックします。ブラウザタブを切り替えると、オンラインのセッションの最後の編集位置が保持されます。スプレッドシートは現在のシートに色付きの境界線と名前ラベルのみを表示します。数値座標は一時的なものであり、行や列が挿入される間、一時的に古くなることがあります。長期にわたるコメントアンカーは安定した行と列IDを使用します。

スプレッドシートエディターは、その選択状態とリアルタイムAPIを通じて、情報を公開、受信、そして存在感を生み出します。その機能が別のスプレッドシートパッケージに移行した場合は、この選択の結合とライフサイクルを維持してください。ホストは、ファサシッドの詳細に永遠に依存してはなりません。

## 7. スナップショット、ロールバック、地域コメント

Yjsチェックポイントは元のCRDTエンコーディングを保存します。JSONプロジェクションから再構築したり、アイデンティティを削除しないでください。スプレッドシートは同じエポック内の不変なベースラインとコマンドを保存します。最新のワークブックの保存をベースラインとして使用したり、古いコマンドを再実行したりしないでください。

定期的なチェックポイントによってエポックが維持される。ユーザー履歴は意味のある時点で作成される。履歴記録は独自のフォーマット、コーデック、エポック、ベースライン、およびアセット依存関係を保持する。現在のベースラインと古いバージョンを混同してはいけない。ロールバックでは現在のエポックにおける新しい変更を優先し、ロールバック前の履歴を保持する。コンポーネントが再構築できる場合は、明示的にエポックを切り替え、認識されていない書き込みを処理し、新しい系譜を読み込む必要がある。

メンバーシップに関係なく、成功した書き込みのコアレコードスナップショットが独立して存在する。自動的、手動的、AI、および前回回復スナップショットは永続性とトランザクション境界を共有する。失敗した書き込みは回復される。明確に合意されたホスト保持ポリシーにより、最新の20個の完全なスナップショットがデータベースに保持され、10個の古いスナップショットからなる完全なグループに対しては、最新のスナップショットをプライベートファイルバックアップの復元ポイントとして保持する。検証された不変のアップロードのみが、そのインデックスを原子的に記録し、そのグループをデータベースから削除することを許可する。他の9個のポイントは意図的にサンプリングされる。不完全なグループやストレージ障害の場合は、データベースのオリジナルが保持される。ユーザーは、IDが変わらず、ストレージ位置フィールドがない通常のページングされたスナップショットリストを受け取る。スナップショットのバイト数、独立した復元メタデータ、添付ファイルは変わらない。ライブチェックポイントや明らかになっていない共同編集の増分はサンプリングされない。ビジネスポリシーは、この合意された保持ポリシー外で暗黙の削除を追加することはできない。既存の回復機能はフォーマット固有のままである。参照 [ストレージ操作](storage.ja.md#history-storage-and-offline-upgrade).

コメントの著者、本文、返信、解決情報はプラットフォームデータベースに保存されます。このコンポーネントにはcaptureAnchor、resolveAnchor、renderAnchors、onAnchorClickが提供されます。リッチテキストでは相対的なテキスト位置が使用されます。スプレッドシートでは、挿入や削除によって変更される安定した行と列の範囲が必要です。完全に削除されたり解決されたアンカーはハイライトされません。

現在のスプレッドシートパッケージおよびホストは、安定した行/列の識別、APIのキャプチャ/解決/表示、マーカーレンダリング、エポック検証、削除対象の処理を実装しています。行/列の挿入、ソート、シートの変更については、独立したテストで対応しています。 `tests/editor-sessions.test.ts`, `tests/sheet-axis-sizes.test.ts` そして `tests/sheet-collection.test.ts`この永続的なプロトコルは、一時的な細胞の存在とは別物です。

## 8. 共有された受容

1. 既存のデータを開き、60秒待ってから選択、スクロール、サイズ変更を行います。新しいコンテンツや履歴は一切追加されません。
2. Aが編集し、Bが受け取る。Bはコミットをエコーしないが、プロジェクションは一致する。
3. 1つのアカウントの2ページが異なる色と名前を持っています。テキストの選択やセル編集の状態が正確です。読み取り専用モードでは公開や表示は行われません。
4. 失われた、重複した、遅延したACK、再接続中の入力作業、データの損失なし、事前に保存されることもない。
5. 純粋な削除後に繰り返し同期を行っても、削除されたセットを再びアップロードしません。
6. 一致しないベースライン、エポック、またはスキーマは拒否される。繰り返し初期化は新しいコンテンツを生成しない。
7. スプレッドシートの行と列の挿入・削除、セル編集、数式、マージ、ソート・フィルター、および元に戻す操作は、一つずつ受け付けられます。サポートされていない操作は宣言または無効化されます。すべてが正常に動作するとは限りません。
8. 再起動後、チェックポイントプラスの増分は、ログ圧縮後も含めてオンラインプロジェクションと一致します。
9. 編集時には、撤回、無効化、匿名アクセス、外国の部屋、偽造された身分証明書、および範囲外の選択が孤立状態になります。
10. 固定ツールバーとフリーフォーミングツールバーはフォーマットが一致します。保存状態の更新によってエディターが再構築されたり、フォーカスが失われたりすることはありません。

## 9. 何が実装されているか

現在のホストは、リッチテキスト、Markdown、スプレッドシート、キャンバス、スライドを、共有された信頼性の高いコミットキューと耐久性のあるACKを使用して統合しています。アイドル同期ではコンテンツがエコーされません。選択や名前はフォーマットアダプターを使用します。5つのフォーマットすべてで履歴の読み取りが可能です。マネージャーの復元はリッチテキストとMarkdownのみに対応しています。スプレッドシート、キャンバス、プレゼンテーションのプレビューが報告されます。 `canRestore:false`これは、すべてのフォーマットに対して統一されたコンポーネントロールバックAPIを確立するものではない。

このプラットフォームはエポック、プロトコルチェック、コミット受領書、および履歴復元メタデータを実装しています。Redisがなければ、ブロードキャストとプレゼンスは一つのプロセスでした。Redisを使うと、ドキュメントの更新、サーバーの更新、権限の無効化、通知、プレゼンスが異なるインスタンス間で行われます。データベースのコミットは依然としてACKの境界であり、ドキュメントの真実の源です。Redisが再接続すると、サーバーはこのインスタンス上のアクティブなルームに権威ある状態を再送信します。Pub/Subは耐久性のあるログではなく、Redisの障害が発生しても静かにローカルバスに切り替わることはありません。

正式な選択APIや各フォーマット間での統一されたロールバックは、コンポーネントとプラットフォーム間で共有される作業です。ホストはオフライン文書の起動や永続的なキューを管理します。コンポーネントの機能については、インストールされたパッケージのエクスポートが有効かどうかの確認が必要です。

オフラインホームでは、認可された文書を一覧表示します。 **最近の編集**新しいクライアントで実際に開いた後、ローカルレプリカが利用可能な場合、文書はディレクトリに追加されます。デスクトップはバンドルされたフロントエンドを提供します。Webワークスペースはサインイン後にsame-originのビルドアセットを自動的にキャッシュします。編集可能なレプリカは、接続が途切れたことをクライアントが検出した後、オフライン編集メッセージを表示します。再接続では、既存のダイナミックACKパスを通じてキュー化された変更を送信する前にアクセスと系譜を検証します。閉じた文書は再開時に同期を再開します。詳細は… [オフライン文書と復元](access-offline-events.md#离线文档入口).

ネイティブエディターは、保持された選択肢に対して操作を行う前にイベントの所有権を確認する必要がある。ホストのコメント/AI入力は、文書の書き込みを行わずにキーボード、クリップボード、コンポジションの動作を保持する。Canvas 0.5.12はネイティブパスを修正し、ホストは隣接するAI/レイアウトの変更を通じてコメントの下書きを保持し、ダッワーとは独立して承認された永続的なマーカーを読み込む。新しいアンカー、コーデック、モデル、コマンド、またはプレゼンスフォーマットは存在しない。公式アーカイブはテストされたC3キーボード/コメント候補と一致し、古い0.5.11の完全なインタラクション記録はその正確な範囲を保持する。

承認されたリッチテキスト/Markdownブラウザクイックメモは、明示的に指定されたプレーンテキストを、明示的に選択された承認済み既存の追加対象に追加します。既存のネイティブエポック、コンテンツトランザクション、受信/配信パスを使用します。失敗した応答は元のチケット/リクエストIDとペイロードを再試行します。受け入れられた再送信では、2回追加したりシーク番号を増やしたりしません。対象の選択、入力、プロセスローカルの5分間のチケットは一時的であり、永続的な拡張ドロウキューやクロスプロセス復元の約束はありません。元の文書と後続の編集は保持されます。サポートされていない対象は変換せずに失敗します。詳細は [即時契約](browser-quick-note.md) そして、分離された2ページ分の実際のMV3受領書です。

## 承認済みAI保留送信ストレージ — 2026-10-22

これは、文書の共同編集とは別のホストAI送信キューです。ユーザーは具体的な保存/ロールバック計画を2回承認しました。新しい準備完了メッセージは独立したIndexedDBを使用します。 `doca-ai-pending` バージョン1、ストア `entries`キーによって制御される `[docaOrigin,userId,connectionId,messageId]`明示的な拡張プロファイルID/リビジョンが含まれている。条件付き遷移は、短い読み書きトランザクションがコミットされた後にのみ完了する。Web Locksはストレージの書き込みではなく、ネットワークの配信をシリアル化する。受け入れられた/拒否されたソースのトムストーンは保持される。不明なバージョン/レコードや拒否された/失敗したストレージは保存され、localStorageやメモリのみのフォールバックなしで拒否される。

元の0.2.7版のlocalStorageキューは読み取り専用のままであり、自動再プレイは行われない。認識された各項目には、明示的な継続または撤回と現在の設定が必要である。完全なペイロードは元のIDとソースハッシュを保持し、受け入れられたジョブは再送信せずに調整される。アップグレードまたはロールバック前に、送信を停止し、すべての古いウェブサイトページ/拡張機能を閉じる：古い送信者が新しいトンブストンを見ることができないため、古新型の送信者はサポートされていない。ロールバックでは新しい送信者を停止し、両方のストレージ、トンブストン、後続のデータを保持する。古い送信をコピー戻すことや自動再起動は行われない。サーバーテーブル、チャット/文書履歴、権限、エディターのチェックポイントは変換されない。正確なルール、2ページ/リフレッシュ/失敗/レガシー証拠が存在する。 [承認されたキュー記録](verification/issue-tracker-2026-10-21/ai-pending-idb.md).

## 承認されたスプレッドシートのサイズと個人用ズーム — 2026-10-23

所有者は21.78 CSSピクセルのデフォルト行高と87.12 CSSピクセルのデフォルト列幅を明確に承認し、これは10％の増加となります。新しいホストワークシートはこれらの値を使用します。保存されていないデフォルト寸法を持つ歴史的な追加ワークシートや仮想復元ワークシートも新しい表示デフォルトを使用します。明示的なベースラインデフォルト、行/列のオーバーライド、元のベースラインバイト、ワークシートシード、チェックポイント、エポック、保留中の更新は保持されます。歴史的フィールドのバックフィルド作成、保持データの変換、スキーマの変更は許可されません。前のパッケージに戻ることで、以前の欠けているフィールドの表示デフォルトが復元され、後からの編集も保持されます。既存のネイティブの手動行/列のサイズ調整は引き続き協力性があり、元に戻すことができます。

フッターは依然として100%に設定されています。ホストは、オリジン、アカウント、文書によって範囲が定められた独立したバージョン1ブラウザ記録内での明示的なネイティブズーム選択のみを保存します。これはワークシートの切り替えを含む文書全体の表示比率であり、行/列サイズのオーバーライドではありません。記録なしで開くと、1つも記録されません。不明なバージョン、構造が崩れた記録、認識できないフィールドは保持され、上書きされません。失敗した保存では、明示的な選択はマウントされたビュー内にのみ保持されます。匿名ビューは記録を保持しません。ロールバックでは新しい記録の読み書きが停止され、それらとその後のすべてのコンテンツがそのまま残ります。

パッケージはネイティブのズームレンダリングとコールバックを有し、ホストはブラウザストレージとアイデンティティを有する。設定を適用し、フッターをドラッグしたり、プラス/マイナスを使用したり、ワークシートを切り替えたり、読み取り専用の変更、サイズ変更、リモート投影を行う際には、文書のundo、outbox、コンテンツ更新、履歴に影響を与えてはならない。個人用ズームは、エクスポートされたスナップショットやXLSXに漏れ出してはならない。このポリシーは合意された境界であり、インストールされたパッケージが必要なプロパティをエクスポートする証拠ではない。統合には、公開されたアーティファクトと隔離された2ページ/ブラウザの領収書を確認する必要がある。

## 承認されたスプレッドシートフィルター拡張 — 2026-10-23

所有者は、開いている状態で保存されたフィルター範囲を保持すること、活動条件が確認された場合に既存の列の最後の内容行まで下に拡張すること、そしてその直下に追加される連続するレコードを自動的に含めることを明確に承認しました。ヘッダー、列の境界、選択された条件は変わりません。スタイル、他の列の内容、クリア条件は範囲を拡大しません。ネイティブの範囲拡張は、追加される内容を一つの共有トランザクション内で作成し、元に戻すステップが必要です。リモート投影や回復では、隠された行を生成する前に作成された範囲を適用する必要があり、ローカルエコーは発生しません。

公式のSheet 0.2.12は、既存のスキーマ6セルと安定した機能レジストリを使用してこのポリシーを実施します。エディタースキーマ、公開API、歴史的アダプター、保存データの変換、DDL、ベースライン/エポックの置換、または保留中の更新リウェイトは導入されません。以前承認された歴史的リーダーとデフォルトは変更されません。既存の短い範囲は、文書を開くことなく、明示的な確認によってのみ修正されます。ロールバックでは、保存されたネイティブ範囲とすべての後続コンテンツが保持されます。前のパッケージはその範囲を読み取ることができますが、後続の暗黙の拡張を永続的に作成することはできません。

Doca 0.2.11は公式のnpmシート0.2.12を搭載している。パッケージと隔離されたホストの承認は、プロダクションデプロイメントとは別物である。詳細は [フィルター検証](verification/sheet-filter-range-2026-10-23.md).

## コメント背景の実行時間境界 — 2026-10-28

シート 0.2.14 `commentHighlightAnchor` およびSlides 0.3.0-alpha.5 `activeCommentId` ホストが制御するビュープロパティです。ホストは、明示的にクリックされた承認済み現在のコメントのみを提供します。引き出しを開いたり、リンクナビゲーションやネイティブコンテンツマーカーのクリックを行っても、コメントの背景は起動されません。他の場所をクリックしたり、解像度を変更したり、引き出しを閉じたりすると、それは消去されます。コメントを切り替えると新しいものが置き換えられ、再開しても元のものは復元されません。SDKは、モデルを書き込んだり、永続的なアンカー、トランザクション、undo、presence、outboxes、ストレージを使用せずに、非インタラクティブな背景のために既存のアンカー解像度/現在のジオメトリを使用します。Canvas 0.5.16のtable-portの可視性もビュー状態です。この境界変更は、アンカーフォーマットや既存の削除されたターゲット解像度ポリシーには影響を与えません。未知のスキーマは依然として正確な交渉に失敗し、古いフォーマットのリーダーや変換もありません。
