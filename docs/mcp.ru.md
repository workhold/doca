# Сервисы MCP

[简体中文](mcp.zh-CN.md)

Doca предоставляет свои инструменты и руководства по навыкам для внешних клиентов `POST /api/v1/mcp`Личные настройки → MCP управляет сервисами, которые выступают в роли зарегистрированного пользователя. Администратор → Сервисы MCP компании управляют интеграциями, в которых явно указан эффективный… `userId` При каждой операции. Компанияные токены требуют активного администратора-создателя; они не наследуют полномочия администратора при работе в роли другого пользователя.

Каждый сервис имеет независимый токен, переключатель активации, возможность отмены срока действия и… `all` или `selected` разрешение. `all` собирается из доступного каталога инструментов/навыков, включая последующие добавления. `selected` Раскрывает только зарегистрированные идентификаторы инструментов и навыков. Предоставление прав инструментом — это простое согласие на выполнение действия; оно не расширяет ACL ресурсов, лимиты хранения, ограничения скачивания, статус учетной записи или политику доступа хоста/инструмента. Навык никогда не предоставляет права на инструменты. Официальные, установленные-инструменты и активированные личные руководства фильтруются для эффективного пользователя.

<a id="connect-a-client"></a>

## Подключить клиента

Каждый сервис отображает команду Codex. `config.toml`Примеры инициализации/определения HTTP-сервиса, а также инструкция для ИИ по установке. Токены появляются только после создания/перезапуска; списки содержат только их последние восемь символов. База данных хранит хеши токенов по алгоритму SHA-256. Не добавляйте токен в URL или сохраняйте его в файл конфигурации.

```toml
[mcp_servers.doca]
url = "https://docs.example.com/api/v1/mcp"
bearer_token_env_var = "DOCA_MCP_TOKEN"
```

Установить `DOCA_MCP_TOKEN` В окружении, в котором запускается клиент. Для CLI:

```sh
codex mcp add doca --url 'https://docs.example.com/api/v1/mcp' --bearer-token-env-var DOCA_MCP_TOKEN
```

Одно предложение для ИИ: «Установите Streamable HTTP MCP под названием doca». `https://docs.example.com/api/v1/mcp`читайте свой токен bearer `DOCA_MCP_TOKEN`Затем проверьте процедуру инициализации и перечислите доступные инструменты и навыки. Для компании-поставщика услуг добавьте: «Прошли тест на целевого пользователя» `userId` на каждом `doca_*` операция.

Codex имеет собственную политику утверждения инструментов. УИ также предоставляет… **необязательно** Неотладочная конфигурация: `[mcp_servers.doca.tools.doca_call]` с `approval_mode = "approve"`Используйте это только в случае, когда вы планируете предварительно разрешить клиенту использование предоставленных сервисом возможностей. Примерами по умолчанию не предусмотрено такое разрешение. Смотрите [официальная конфигурация MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) и [Настройки утверждения инструмента](https://learn.chatgpt.com/docs/config-file/config-reference).

<a id="discover-and-execute"></a>

## Откройте и выполните

1. Позвонить `doca_tools` с полным выполнением задачи `purpose`. Опционально `resources`, `files`, `currentResourceId` и `currentFolder` Предоставляется явный контекст с использованием существующих UUID документов/файлов. Ссылки на файлы получают тот же авторизованный снимок данных, который использует помощник. Результат содержит `contextId`, независимый `taskId`И краткий каталог. Не создается никакой конversation.
2. Позвонить `doca_describe_tools` с этим `contextId` И до четырех идентификаторов инструментов для получения их полных входных схем. Искать только схемы, необходимые для следующей операции.
3. Прочитайте руководство по использованию. `doca_skills`/`doca_load_skill`или стандартный `doca_skill` МПК-пrompt. Они читают текущий каталог; приостановленный частный навык больше не доступен.
4. Позвонить `doca_call` серийно с `contextId`, новый UUID `requestId`, `tool` и `input`Нативные правки используют текущий вариант. `seq`, `epochId`ID-ы и команды, возвращаемые обычными инструментами для работы с документами. Это та же самая реализация помощника, с теми же нативными кодеками, транзакциями, уведомлениями и системой учета использования ИИ при вызове провайдера Doca. Использование модели внешнего клиента не было введено в систему учета Doca.
5. Позвонить `doca_context_close` Когда будет завершено. Сохраненные документы и файлы остаются. Буферы для ожидающего загрузки и состояние локальной визуальной проверки освобождаются.

Личные операции не учитываются `userId`Предоставление этого отклоняется. Операции компании должны каждый раз предоставлять UUID активного целевого пользователя. Контекст не может изменить сервис или эффективного пользователя. Поиск, чтение, запись и загрузка проверяют права пользователя. Аудит записывает создателя сервиса, эффективного пользователя, контекст, ID запроса, инструмент и результат, не записывая вводные секреты.

`requestId` Обеспечивает максимум один выполнение в своем контексте. Повторный ID вызывает конфликт с HTTP/tool в соответствии с зафиксированным статусом, и разные параметры не могут использовать его повторно. Оно не пересчитывает кэшированное приватное содержимое и не повторно пытается выполнить возможно завершенное запись. Проверьте сохраненный ресурс перед выполнением новой записи при неопределенном результате. Нормальные нативные и файловые рабочие процессы сохраняют свои существующие долговечные записи.

<a id="files"></a>

## Файлы

Коренной `file_browse`, `file_manage`, `file_folder_manage`, `file_read` и `file_create` Инструменты остаются доступными. `file_download` Сохраняет значение помощника: получить публичный веб-файл **внутрь** Дока.

Для фактических переводов клиентов:

- `file_upload_begin`Имя файла, MIME-тип, объявленный размер и опциональный SHA-256; максимум 20 МиБ, а также любой более строгий настроенный лимит для пользователя.
- `file_upload_chunk`Канонический формат Base64, непрерывный ориентир байт; максимальный размер декодированного блока – 128 КиБ.
- `file_upload_complete`Сохраните завершеный загрузочный файл в папку пользователя с UUID, или `folderId:null` Для корневого пользователя. Загрузки связаны с контекстом сервиса и эффективным пользователем.
- `file_upload_abort`Отправить ожидающий загрузку.
- `file_content`Авторизованный скачивание диапазона байт с использованием формата Base64, полный файл/частицы по коду SHA-256, версия файла и `nextOffset`Передавайте ту же версию для последующих файлов; отклоняйте измененные файлы, а не объединяйте версии.

Эти методы используют сервис хост-файлов. Им не требуются куки браузера или путь файловой системы сервера, и они никогда не превращают URL с прочитанным контентом в способ обхода разрешения на скачивание.

<a id="transport-and-lifetime"></a>

## Транспортировка и срок службы

Конечный пункт использует статический Streamable HTTP из SDK 1.30.0, с явно принятыми версиями протокола. `2025-11-25`, `2025-06-18` и `2025-03-26`Инициализация должна указывать поддерживаемую версию; последующие запросы должны содержать `MCP-Protocol-Version`GET/DELETE возвращают ответы 405 с авторизацией. Применяются правила для существующих хостов, а неверный Origin отклоняется. Устаревшие HTTP+SSE и старые адаптеры токенов не предоставляются.

Контексты выполнения имеют 15-минутный временной период ожидания, максимум 16 активных/запланированных контекстов на сервис и 128 на экземпляр. Запросы внутри одного контекста выполняются последовательно. Предоставленные инструменты/навыки, токены и активные пользователи перепроверяются; сброс/отмена токена, отключение сервиса или отключение личного MCP аннулируют его активные контексты. Лимит HTTP-запросов составляет 600 в минуту на сервис при использовании лимитатора скорости хоста. Тело запроса ограничено 1 МБ.

Выполнение контекста и визуальные доказательства являются локальными для конкретного экземпляра. Активный контекст направляется к тому же экземпляру. После перезапуска, при истечении срока или перенаправлении на другой экземпляр, необходимо создать новый контекст и проверить существующие артефакты; автоматическое продолжение или восстановление визуальных доказательств не предусмотрено. Национальные данные документа остаются в обычном долговременном хранилище. Криптографические данные поставщика, секретные значения, сессии браузера и любые предыдущие истории чата не экспортируются в виде конфигурации MCP.

<a id="execution-history-and-upgrade"></a>

## История выполнения и обновление

MCP и чат делятся информацией о аренде задач, отмене, авторизации ресурсов, реализации инструментов, документах о выполнении операций, фактах использования ресурсов от поставщиков и результатах аудита безопасности. MCP создает… `ai_jobs` Выполнение с NULL `session_id` и `model_id`Оно не создает `ai_sessions` строки, сообщения чата или поток памяти. Вызовы реальных провайдеров все равно записывают свой реальный модель и использование. `ai_calls`.

Личные настройки → MCP → История выполнения отображает задачи эффективного пользователя, включая задачи компании-поставщика, выполненные этим пользователем. Она поддерживает связи с разрешенными ресурсами, статус звонков, а также возможность остановки и удаления закрытой истории выполнения. Удаление истории сохраняет сохраненные документы, созданные файлы, квитанции о выполнении операций, данные использования оригинального поставщика и факты аудита безопасности. Сгенерированные изображения сохраняют ограничения директории выходных данных ИИ и содержат явное... `aiTaskId` Обязательно, без папки для диалогов. Задача читает только свои записи; NULL связи с диалогами никогда не группируют несвязанные выполнения.

Владелец одобрил прямое разделение 2026-11-01. Текущие правила DDL… `ai_jobs.session_id`, `ai_jobs.model_id` и оставленное `mcp_contexts.session_id` может быть заменено с помощью существующего регулирующего устройства нативной колонки. Новое `ai_task_resources` Леджер начинается с пустоты и объявляется… `schemaEvolution`Не происходит никаких изменений в процессе восстановления или совместимости. Исторические разговоры, контексты, файлы, гранты и строки аудита остаются неизменными, не включаются в точки входа в чат и не конвертируются или восстанавливаются. Ранее установленные поля/таблицы остаются защищенными от изменений.

Источник SDK для плагинов версии 0.2.0 раскрыт `ai.v2` / `ai.continuations.v2`: `jobId` необходимо и `sessionId` Существует только для выполнения на основе диалога. Пересоберите пакеты плагинов. `sdkRange: "^0.2.0"`Хост, веб-сервисы и плагины должны обновляться одновременно. Старые контракты на обслуживание и диапазоны SDK отклоняются; нет адаптера для старых интерфейсов или автоматического снижения уровня обслуживания. Сохраняйте резервные копии базы данных и файлов перед обновлением, а также сохраняйте последующие записи задач и файлов для отдельного рассмотрения при восстановлении приложения перед возвратом бинарных файлов. Смотрите. [проверка](verification/mcp-execution-decoupling-2026-11-01.md).

<a id="storage-and-retired-mcp"></a>

## Хранение и отказ от использования MCP

Владелец согласился отменить неиспользуемую старую реализацию 20 октября 2026 года. `/ai/mcp-keys` И старый адаптер для четырех инструментов удален. `doca_mcp_…` Подписи отклонены; используются новые токены `doca_mcp_v1_…`Инертный `ai_mcp_keys` Строки таблицы сохраняются исключительно для сохранения хранимых данных; никакие операции чтения происходят во время выполнения программы, а ни учетные данные, ни разрешения не преобразуются.

`mcp_user_settings`, `mcp_services`, `mcp_contexts` и `mcp_tool_calls` пустые добавочные таблицы, объявленные в текущем DDL `schemaEvolution`Существующие пользователи начинают с отключенным личным MCP, так как нет новой строки настроек; использование сервиса компании не зависит от этого параметра. Существующие документы, файлы, ACL, сессии AI, настроенные значения и результаты совместимости сохраняются. Отказ в структурном анализе и неудачная реконцилировка не вызывают каких-либо частичных постоянных изменений. Удаление ранее установленной таблицы MCP может привести к потере данных, и она не создается снова без согласования.

Сохраняйте резервные копии до обновления и обновляйте сервер/Веб одновременно. Старые бинарники не соблюдают новый контракт токенов/разрешений/контекста. Нет автоматического снижения приложения или удаления данных; сохраняйте новые записи и проверьте восстановление перед возвратом к более старой версии развертывания. Смотрите [Контракт на обновление базы данных](database-schema-evolution.ru.md) и [Доказательства приемки](verification/mcp-2026-10-20/README.md).
