# Развертывание Doca

Пакет десктопа Tauri включает веб-фронтенд и соединяется с отдельно развернутым хостом с путями авторизации на десктопе. В нем нет включенного хоста Node. Собирайте и проверяйте каждый пакет для ОС/архитектуры независимо. Смотрите [десктопный клиент](desktop-client.ru.md).

[中文](deployment.zh-CN.md)

Один сервер может запустить изображение, указанное... `compose.yaml` Основное. Один контейнер использует SQLite и не требует PostgreSQL или Redis. Используйте их только в случае работы с более чем одним репликой приложения. Смотрите [Одно экземпляр и горизонтальное масштабирование](horizontal-scaling.ru.md).

<a id="requirements"></a>

## Требования

- Движок Docker и плагин Docker Compose.
- HTTP(S) источник, доступный пользователям. Публичный HTTPS требует DNS и сертификата TLS; поддерживается также внутренний HTTP, признанный доверенным.
- Обратный прокси на той же машине, что и контейнер. Compose публикует Doca только на… `127.0.0.1:39120`.

Прокси должен пересылать HTTP и путь WebSocket. `/api/v1/ws`Оставьте оригинал. `Host` Заголовок.

Не удаляйте базу данных, в которой уже есть пользователи.

<a id="reverse-proxy"></a>

## Реверсивный прокси

Завершить TLS в Caddy или Nginx на том же хосте и переслать на `127.0.0.1:39120`.

```caddyfile
docs.example.com {
	reverse_proxy 127.0.0.1:39120
}
```

Прокси Caddy по умолчанию поддерживают обновления WebSocket. Сервер Nginx необходим `Upgrade` и `Connection` Заголовки `/api/v1/ws`.

`DOCA_TRUST_PROXY` По умолчанию пусто: никакие пересыланные заголовки не считаются достоверными, включая соединения от loopback. Чтобы сохранить IP-адреса клиентов для аудита и ограничений, настройте только IP/CIDR прокси, который видит приложение. Docker bridge может заставить прокси хоста выглядеть как шлюз bridge, а не `127.0.0.1`Проверьте сеть развертывания перед выбором этого значения. Без нее пользователи, обслуживаемые прокси, могут разделять квоту прокси-IP.

Если балансер на другом устройстве подключается к этому хосту, публикуйте порт контейнера на приватном интерфейсе, а не только на loopback, и установите `DOCA_TRUST_PROXY` В диапазон IP-адресов балансера нагрузки. Не доверяйте публичной сети.

Для надежного внутреннего HTTP-сайта установите `DOCA_ORIGIN=http://doca.internal` И обслуживайте этот адрес через HTTP-реверсивный прокси. Вы также можете опубликовать порт контейнера на выбранном приватном интерфейсе и включить этот порт в значение Origin. Предоставленное маппингование Compose привязывается только к loopback. Не требуется изменения в режиме разработки; сохраняйте режим производства. Поддержка HTTP не изменяет проверку Host или Origin.

<a id="create-the-administrator"></a>

## Создать администратора

Нет стандартного аккаунта или пароля. После того как контейнер будет в состоянии здоровья, выполните этот запуск в директории, где находится `compose.yaml`:

```sh
bash scripts/bootstrap-admin.sh
```

Скрипт запрашивает логин и пароль. Пароль должен иметь не менее 12 символов. Он передается только в этот одноименный командный вызов. База данных хранит хеш. Если администратор уже существует, команда останавливается и не меняет текущий пароль.

<a id="change-a-password"></a>

## Изменить пароль

Авторизованный пользователь открывает `#/account` и выбирает **Изменить пароль**Новый пароль должен иметь не менее 12 символов. После сохранения он приводит к выходу из каждой сессии для этого аккаунта.

Когда администратор не может войти, сбросьте существующий аккаунт из директории развёртывания:

```sh
bash scripts/reset-admin-password.sh
```

Это не создает учетную запись и не доступно через HTTP. Если файл базы данных заблокирован, выполните `docker compose stop`сбросить пароль, затем `docker compose up -d`Не вводите логин или пароль. `.env`.

## Статические ресурсы

Страница HTML и API остаются на месте. `DOCA_ORIGIN`. `DOCA_ASSET_BASE` изменения только `/assets/...` URLы внутри этого HTML.

Сервер ведет переговоры о использовании Brotli.`br`), gzip, или оригинальные байты с использованием `Accept-Encoding` и отправляет `Vary: Accept-Encoding`URLы и сгенерированные файлы остаются неизменными, включая существующие директории сгенерированных файлов. URLы HTML-ресурсов переписываются перед компрессией. Сервер использует ограниченный кэш размером 32 МиБ на процесс для кодированных публичных статических ресурсов; он не добавляет сжатые копии в изображения или сжимает ответы от частных API/файлов по этому пути. Прокси/CDN должны сохранять процедуру кодирования. `Vary`Или управлять сжатием сами. Это влияет на передачу данных через браузер; Docker использует собственное сжатие и кэширование изображений.

Строительство `/cad/` Файлы рабочих процессов и WASM используют один и тот же метод нормализации кодировки и сохраняют его. `no-cache` Потому что их имена не были хешированы. Пути, находящиеся за пределами объявленных CAD-активов, остаются недоступными.

Оставьте его без изменений, чтобы использовать JavaScript, CSS и другие собранные файлы из контейнера. `/assets`Когда его устанавливаете, используйте префикс HTTP(S) без userinfo, query, hash или третьего слеша:

```text
DOCA_ASSET_BASE=https://cdn.example.com/doca/0.1.11
```

Страница, содержащая ссылку `/assets/index-abc.js` затем загружается:

```text
https://cdn.example.com/doca/0.1.11/assets/index-abc.js
```

Опубликовать всё `apps/web/dist/assets` директория с таким префиксом и оставить `assets` Сегмент пути. Имена файлов содержат хеш содержимого и должны совпадать с HTML-кодом в той же изображении. Запросы API остаются… `DOCA_ORIGIN`.

Официальная метка, например `v1.2.3` Создает веб-приложение и прикрепляет его `doca-web-assets-v1.2.3.tar.gz` для выпуска на GitHub. Извлеките его, сохраните. `assets` директорию, и разместите эту директорию на CDN, который отправляет заголовки cross-origin для модулей ES. Не используйте `github.com/.../releases/download` URL: `DOCA_ASSET_BASE`Принудительное движение `main`или предварительный тег, такой как `v1.2.3-rc.1`не создает этот выпуск.

Контейнер сохраняет свою собственность. `/assets` Файлы. Фоны и изображения, указанные в стиллсхеттах с корневой путем, все равно загружаются из Doca.

`index.html` отправляется вместе с `Cache-Control: no-cache`Поэтому новый визит после выпуска приводит к появлению новой страницы. Хешенные файлы… `/assets/` отправляются вместе с `Cache-Control: public, max-age=31536000, immutable`Их имена меняются при изменении содержимого, поэтому кэш, действующий в течение года, не сохраняет старый скрипт после загрузки нового HTML. CDN перед этим… `DOCA_ASSET_BASE` Необходимо использовать такой же длинный кэш для этих хешированных файлов.

<a id="configure-static-cdn-response-headers"></a>

### Настройка заголовков ответа статического CDN

`DOCA_ASSET_BASE` Изменяются URL-адреса; не настроено CDN. Установите загружаемые объекты build S3. `Cache-Control: public, max-age=31536000, immutable` и сохранять тип контента (`text/javascript` для JS, `text/css` Для обработки существующих объектов без изменения метаданных добавьте CloudFront. **Политика заголовков ответа** только к статическому состоянию `*/assets/*` Поведение: добавить указание Cache-Control **Пользовательские заголовки** с **Переопределение**Модули ES с разными источниками также требуют `Access-Control-Allow-Origin: https://doca.example.com`Эти публичные файлы сборки могут использоваться `*` Без учетных данных. Не прикрепляйте эту политику к HTML, API или частным файлам.

Установите статический хеш-файл **Политика кэширования** Отдельно: Минимальное TTL – 0 секунд, стандартное/максимальное TTL – 31536000 секунд. Политика заголовков ответа изменяет заголовки браузера, а не TTL edge; см. [Политики заголовков ответа AWS](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/modifying-response-headers.html)Опубликуйте новые имена файлов, а старые версии сохраните для последующего загрузки на уже открытых страницах.

Статический Nginx CDN может обслуживать директорию релиза следующим образом, с использованием стандартных параметров. `mime.types` Загружено сервером:

```nginx
location /doca/0.2.12/assets/ {
    alias /srv/doca/0.2.12/assets/;
    add_header Cache-Control "public, max-age=31536000, immutable";
    add_header Access-Control-Allow-Origin "https://doca.example.com";
}
```

Когда проксировать Doca `/assets/`Скрыть существующий заголовок-источник `proxy_hide_header Cache-Control;` до добавления его замены. В примере пропущено `always` Поэтому отсутствующие файлы не получают годичный кэш 404. Проверьте последний ответ CDN:

```sh
curl -I https://cdn.example.com/doca/0.2.12/assets/<actual-hashed-JS-filename>.js
```

Проверьте параметры Cache-Control, Content-Type и CORS. HTML сохраняется на Doca с повторной проверкой. Для изображений документов и защищенных файлов используйте [Хранение: кэширование изображений браузером и CDN файлов](storage.ru.md#browser-image-caching-and-the-file-cdn).

## Преобразование полезной нагрузки знаний-книги

0.1.25 согласовывает поддерживаемые старые версии через обычное сравнение схем, сохраняя все бизнес-данные без автоматической очистки книг или использования адаптеров во время выполнения программы. Существующие объекты целевой версии остаются неизменными. [необязательная процедура без потерь](knowledge-book-storage-verification.ru.md) Необходимо выполнить это действие перед первым запуском, чтобы старые результаты SQL оставались доступными. Прерванные конвертации все еще требуют их оригинального манифеста. Сохраняйте все данные и последующие записи при восстановлении резервных копий; обновляйте все хосты и веб-сборки одновременно.
