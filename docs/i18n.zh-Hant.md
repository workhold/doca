# 介面語言

Doca 0.3.0 支援八種介面語言。每種語言都有自己的訊息目錄，各語言共用穩定的英文訊息鍵。來源契約及編輯器套件的實作規則請參閱[英文規範](https://github.com/workhold/doca/blob/main/docs/i18n.md)。

<a id="语言代码"></a>

## 語言代碼

| 代碼 | 語言 | `html lang` |
| --- | --- | --- |
| `zh` | 簡體中文 | `zh-CN` |
| `en` | 英語 | `en` |
| `zh-Hant` | 繁體中文 | `zh-Hant` |
| `ja` | 日語 | `ja` |
| `fr` | 法語 | `fr` |
| `ko` | 韓語 | `ko` |
| `es` | 西班牙語 | `es` |
| `ru` | 俄語 | `ru` |

站台的初始預設語言是簡體中文，管理員可以變更。訪客與尚未設定 `ui.locale` 的使用者使用站台預設語言，已儲存的帳號選擇優先。

API 的寫入值必須是表中的正式代碼。解析地區或系統標籤時，`zh-TW`、`zh-HK`、`zh-MO` 和 `zh-Hant` 會對應到繁體中文。其他受支援語言以主要語言子標籤比對。工作區讀到無法識別的值時，會使用站台預設語言。

帳號選擇儲存在頁面狀態 `ui.locale`。網頁端也會將 `doca.locale` 儲存在 `localStorage`，行動裝置將偏好保存在裝置上。助手可以透過既有的 `page_state` 工具變更帳號偏好。

每次載入網頁登入畫面，會先使用管理員設定的站台預設語言。登入畫面的選擇會立即套用至本次造訪。登入後，工作區依帳號偏好與站台預設語言決定顯示語言。

<a id="宿主字典"></a>

## 宿主字典

字典在 `packages/i18n`。英文目錄 `en` 是 key 的來源，其他語言必須正好覆蓋同一組 key。

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

約定：

- key 用小寫英文和點號，按介面區域分組，例如 `nav.trash`、`settings.language`。
- 佔位符寫成 `{name}`。不要把句子拆開再拼接。
- 需要單複數時，字典寫 `files.count.one` 和 `files.count.other`，呼叫仍是 `t("files.count", { count })`。英文按 `count === 1` 选 `one`，其餘選 `other`。中文可以讓兩份文案相同。
- 找不到譯文時先用英文，再退回 key 本身。
- 語言選擇器使用 `localeNames` 中的各語言自稱。
- 日期和排序使用當前語言對應的 `Intl` 標籤。
- 文件標題、正文、評論、郵件、檔名、使用者輸入不翻譯。

網頁透過 `useI18n()` 取 `locale`、`t` 和 `setLocale`。Ant Design 與 Ant Design X 的元件語言跟隨 `locale`。桌面和移動端共用宿主字典，瀏覽器擴充套件在當前瀏覽器單獨記住語言。使用雙語外掛契約的提交內容，在六種新增語言中顯示其英文值。

未標註錯誤碼的服務端使用者可見錯誤目前仍是中文句子。新的校驗錯誤使用穩定程式碼，例如 `invalid_locale`，由介面翻譯。已有介面錯誤不在這一版改完。

新產生的圖片生成、模型連線和後臺 AI 任務錯誤使用明確的展示信封，序列化後寫入現有錯誤文字欄位：

```ts
{ type: "system_error", version: 1, code: "image_edit_failed", data: { status: 422 } }
```

只有新產生且明確標註錯誤碼的系統錯誤使用這個格式。歷史錯誤文字、訊息、工具結果、推理和已儲存的提示詞上下文全部原樣讀取，不掃描、翻譯、轉換或遷移；未標註錯誤碼的錯誤仍保持原樣。網頁和移動端共用 `@doca/i18n` 的 `systemErrorMessage` 讀取函式；任務錯誤使用 `useI18n().t` 展示，新的 HTTP 錯誤使用同一個 Provider 選定的語言。未知錯誤碼顯示字典中的通用提示；格式無效或版本不支援的信封保持原樣。

`AppError.message` 和傳送給模型的錯誤序列化結果保持不變，展示引數透過錯誤物件之外的 WeakMap 傳遞。圖片失敗檢查點另外攜帶結構化錯誤原因，用於任務失敗展示，不改變原始工具反饋。介面語言不加入系統提示詞、工具定義或重放的歷史訊息，避免切換語言改變模型快取字首。

舊文字原樣讀取、新錯誤碼按字典展示是已獲同意的相容方案，不遷移歷史資料或資料庫表結構。回滾時停止新信封寫入，保留信封讀取能力和所有已儲存資料。

<a id="持久化系统状态"></a>

## 持久化系統狀態

資料庫、任務檢查點、事件流和介面響應中的系統狀態只儲存穩定的英文程式碼與結構化引數，不儲存任何語言的展示句子。網頁和移動端收到程式碼後，使用當前介面的字典生成標題、說明和階段名稱。

```ts
// 存储和传输
{ code: "folder_available", data: { name: "Research" } }

// 展示
t("ai.progress.event.folderAvailable", { name: event.data.name })
```

階段、事件、審批，以及作為狀態欄位儲存的錯誤原因都遵守這條規則。狀態判斷只能比較程式碼，例如 `phase === "completed"`，不能比較 `t(...)` 的結果或中文、英文展示文案。使用者輸入、模型回答、文件標題、檔名和網頁來源仍儲存原文，不把自然內容改寫成程式碼。

<a id="给子包的要求"></a>

## 給子包的要求

編輯器子包自己儲存自己的介面文案，不要引用 Doca 的字典，也不要讀取 Doca 的頁面狀態。

宿主會傳入：

```tsx
<RichTextEditor locale={locale} />
```

`locale` 是字串。已整合的編輯器支援上表中的八種語言，未知子包程式碼回退到英文。

子包需要做到：

1. 元件 props 增加可選的 `locale?: string`。預設時按 `zh` 顯示，和現在的中文介面一致。
2. 字典 key 使用穩定的英文標識，例如 `toolbar.bold`、`find.replaceAll`。不要用中文，也不要用會隨文案修改的整句英文。
3. 每個支援的語言都提供完整字典，使用相同的 key 集合。
4. 佔位符使用 `{name}`。需要數量區分時提供 `key.one` 和 `key.other`，由 `count` 選擇。
5. 切換 `locale` 只更新子包自己的按鈕、選單、佔位符和提示。不要因此重建文件、Y.Doc、協同介面卡或外掛列表。
6. 可以額外接受 `messages?: Record<string, string>`，用來覆蓋個別文案。沒有這份 prop 也可以。覆蓋項只替換對應 key，其餘仍用子包內建譯文。
7. 使用者寫進文件的文字、公式、單元格內容不翻譯。

宿主在安裝包的型別宣告包含 `locale` 之後，在對應編輯器的掛載處傳入當前 `locale`。不要把 `locale` 放進會重建文件、Y.Doc、協同介面卡或外掛列表的依賴裡。

<a id="增加一种语言"></a>

## 增加一種語言

1. 在 `locales` 里加入程式碼，並補上 `html lang`。
2. 增加一份與英文 key 完全相同的宿主目錄。
3. 補上該語言在介面上的自稱，例如 `locale.ja`。
4. 網頁補上 Ant Design 對應的 locale 物件。
5. 每個編輯器子包增加同一語言的目錄。
6. `ui.locale` 會自動接受新程式碼，因為校驗讀的是同一份 `locales`。
