# Архитектура плагинов

[中文](plugin-architecture.zh-CN.md)

Это [Контракт SDK](plugin-sdk-contract.ru.md) определяет границу между ядром и бизнес-плагинами. [руководство по разработке](plugin-development.ru.md) Перечисляет существующие интерфейсы.

`plugin-contracts` Определяет манифест и жизненный цикл. `plugin-sdk` Предоставляет инъекции, события, вклады и эффекты. `plugin-host` Проверяет зависимости и запускает плагины, затем отключает их в обратном порядке. Композиция собирает основные файлы, документы, поиск и ИИ, а затем загружает бизнес-плагины из отдельного директория установки.

Бизнес-плагин взаимодействует с хостом через публичные файлы, пользователей, права доступа, HTTP, политику, события и сервисы ИИ. Регистрация принадлежит экземпляру плагина. Плагин не доступен к приватной базе данных хоста или к процессному мосту. Веб-плагин сам создает свою версию, и активный манифест загружает её.

Хост сохраняет проверку аутентификации, авторизации, файлы, совместную работу документов, аудит безопасности, использование ИИ и токенов, оцененные моделью. Членство, баллы, цены, контроль содержимого и электронная почта не являются основными таблицами, инструментами или страницами. Будущий плагин электронной почты имеет свой сервер, данные и тесты приемки.

Универсальный слот для деревьев, дополнительные бизнес-услуги и протокол резервирования фондов все еще указаны по статусу реализации в контракте. Предложенный API не является экспортным ресурсом, который можно использовать.

Все долговечные состояния плагинов управляются хостом. Пакеты должны объявлять `doca.storage: "host"`; модели/авторизация плагинов, а не драйверы, пути хранения или локальная/дистанционная конфигурация. Менеджерский SQL и приватные объекты экспортируются в SDK 0.1.7; зашифрованные учетные данные, доступные только серверу, экспортируются в SDK 0.1.9. См. также [контракт хранения](plugin-horizontal-scaling.ru.md).
