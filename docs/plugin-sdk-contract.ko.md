# 플러그인 SDK 및 핵심 경계

현재 소스는 SDK를 사용합니다. **0.2.0**, 함께 `ai.v2` / `ai.continuations.v2`도구 컨텍스트는 항상 포함되어 있습니다. `jobId`; `sessionId` 실제 대화에서만 존재합니다. 플러그인을 재구축하세요. `sdkRange: "^0.2.0"`이전 SDK 범위와 AI 서비스 계약은 어댑터 없이 거부됩니다. 이 소스 변경은 npm 출시나 배포가 아닙니다. 참조하세요. [MCP 실행 분리](mcp.ko.md#execution-history-and-upgrade).

불호합하는 SDK 범위나 사용할 수 없는 필수 종속성으로 인해 영향을 받는 비즈니스 플러그인이 격리됩니다. 호스트 플러그인과 관련 없는 플러그인들이 시작되며, Admin → Plugins에서 이유를 설명하고 업그레이드를 요청합니다. 설치된 선택 항목, 아카이브, 비즈니스 데이터 및 자격 정보는 보존됩니다. 기존 패키지는 변환되지 않고 기존 SDK 코드는 실행되지 않습니다. 새로운 온라인 설치도 여전히 불호합하는 패키지를 거부합니다. 완전한 오프라인 설치 폴더는 원래의 정체성을 유지하며 동일한 격리를 받습니다.


0.1.26는 사용합니다. [공유 플러그인 비즈니스 데이터베이스](plugin-database-isolation.ko.md)핵심 부분과는 분리된 형태로, 자동 네임스페이스가 제공됩니다. 이는 0.1.25에서 출시된 플러그인별 데이터베이스를 대체합니다. 업그레이드를 위해서는 이전 호스트에서 일반적인 제거 후 재설치가 필요하며, 플러그인 데이터는 마이그레이션되지 않습니다.

[中文](plugin-sdk-contract.zh-CN.md)

문서화 기준: 호스트 0.2.23 / SDK 0.1.11, 2026-10-28에 확인됨. SDK 0.1.11 출시 내용은 아래에 기록되어 있음; 생산 배포와 네이티브 기기 인수는 별도로 진행됨. 모든 플러그인의 지속성은 호스트가 관리함; 플러그인은 비즈니스 모델과 권한을 소유함. 이 문서는 리팩토링에 대한 인수 기준입니다. 모든 인터페이스가 구현된다는 의미는 아닙니다. 격차는 12절에 있습니다. 개발 튜토리얼은 오늘날 존재하는 엑스포트로 목표 인터페이스를 제시해서는 안 됩니다.

SDK 소스 0.1.11은 사이트 통계, HTTP 지표, 수정된 운영 로그, 감사 기록, 큐/사용량 진단 및 건강 상태에 대한 모니터링.v1 및 텔레메트리.v1을 제공하며, 관리자용 웹 전송 기능도 포함됩니다. 자세한 내용은… [접근 모니터링, 보관, 클러스터 커버리지 및 롤백](plugin-monitoring.ko.md)기존의 인터페이스와 지속 가능한 형식은 변경되지 않습니다.

그것 [공개된 기능 및 UI 확장 리팩토링 계획](plugin-sdk-expansion.md) 합의된 추가 기능 방향, 현재 구현된 자산 목록, 제안된 인터페이스 및 수락 배치를 기록합니다. A–D는 현재 구현되었습니다; [구현된 메서드와 슬롯](plugin-extensions.ko.md) 정확한 수출 및 제한 사항을 기록합니다. E/F는 향후 작업입니다.

## 관리형 스토리지를 구현함

`@smartdoca/plugin-sdk/storage` 현재 설치용 제품을 수출하고 있습니다. `pluginDatabaseToken` (`storage.sql.v1`) 그리고 `pluginObjectStorageToken` (`storage.objects.v1`). 데이터베이스 하위 집합은 명시적 스키마 버전 1이며, 텍스트/int32/double 컬럼, 기본/유일 제약 조건, 구조화된 select/insert/update/remove 작업 및 한 번 실행되는 콜백을 포함하는 트랜잭션이 있습니다. `pluginCredentialToken` (`storage.credentials.v1`SDK 소스 0.1.8)은 수정된 값이 확인된 갱신 및 삭제 기능을 갖춘 서버 전용 암호화된 자격 증명을 제공합니다. 참여, 외래 키, 일반적인 SQL, 업사이드 및 작업 공간은 내보내지 않습니다. 자세한 내용은 참조하세요. [자격 증명 API 및 배포](plugin-credentials.ko.md)비즈니스 SQL은 핵심 시스템과는 별개의 공유 호스트 관리 데이터베이스를 사용합니다. 테이블 프렌지가 있는 SQLite 파일이거나, 자동 플러그인 스키마와 공유 연결 풀이 있는 PostgreSQL URL/계정이 있습니다. 프로세스 격리 기능은 아직 구현되지 않았습니다. 자세한 내용은 참조하세요. [저장 설정 및 업그레이드 전 삭제 계약](plugin-database-isolation.ko.md).

논리적 데이터베이스는 사용 `plugin:<pluginId>`, 사용자 파일의 소유권 및 개인 객체 사용 `plugins/<pluginId>`, 그리고 ZIP 파일을 풀어주는 것 `host/plugin-releases/<sha256>.zip`완전히 불변인 ZIP 바이트는 환경에 설정된 파일 저장소에 존재합니다. 공유 데이터베이스에는 레지스트리 버전 2, 아카이브 참조 및 신뢰할 수 있는 파일 해시 인덱스가 저장되어 있습니다. 확인된 캐시 히트는 ZIP 파일을 다시 다운로드하지 않습니다. 모든 인스턴스는 수동으로 재시작됩니다. 지원되지 않는 플러그인 패키지/저장 형식은 자동 변환 없이 거부되며, 기존 데이터는 보존됩니다. 핵심 데이터베이스 업그레이드는 별도로 진행됩니다. [데이터베이스 업그레이드 계약](database-schema-evolution.ko.md). 보기 [정확한 구현 및 제한 사항](unified-storage-implementation.md).

## 1. 결정

승인된 [수평 확장 및 관리된 스토리지 계약](plugin-horizontal-scaling.ko.md) 데이터베이스 소유권, 네임스페이스 격리, 사용자/개인/임시 저장 및 다중 인스턴스 실행을 정의합니다. 패키지는 반드시 선언해야 합니다. `doca.storage: "host"`; 다른 또는 누락된 선언은 코드 임포트 전에 거부됩니다. 호스트가 로컬/원격 저장소를 선택합니다. 관리형 SQL 및 개인 객체는 SDK 소스 0.1.7에서 내보내집니다; 자격 증명은 SDK 소스 0.1.9에서 내보내집니다; 작업 공간은 여전히 부족한 부분입니다.

도카는 문서 제품의 핵심 기능과 일반적인 플랫폼 서비스를 유지합니다. 설치 디렉터리에서 독립적인 비즈니스가 발견됩니다. 메일, 캘린더, 멤버십, 결제, 사용량 제어, 콘텐츠 모니터링은 필요하지 않은 호스트 제품입니다.

플러그인은 별도로 배포된 SDK와 기능 계약에 의존합니다. 호스트는 실행 시간에 구현을 주입합니다. Doca 작업 공간 경로, 개인 호스트 모듈, 글로벌 브리지 또는 개인 호스트 테이블에 의존하지 마십시오. 호스트는 비즈니스 플러그인 소스를 임포트하거나 특정 비즈니스 플러그인 ID를 요구하지 않고 공개 흐름을 완료할 수 없습니다.

플러그인은 신뢰할 수 있는 서버 프로세스 내에서 실행됩니다. 이는 Node.js 샌드박스가 아닌 확장 경계입니다. 설치 디렉터리는 프로그램 디렉터리와는 별개입니다. 호스트는 현재 SDK 범위를 명시하고 현재 기준과 일치하는 데이터베이스를 가진 플러그인만 로드합니다.

## 3. 설치 및 발견

공유 호스트 데이터베이스에는 원하는 레지스트리 및 아카이브 메타데이터가 저장되어 있습니다. 완전한 불변 ZIP 파일들은 설정된 호스트 파일 저장소에 저장됩니다. 각 인스턴스는 개인적인 데이터를 동기화합니다. `DOCA_PLUGINS_DIR` 기본값 `<data-root>/plugins`로드하기 전에 이 작업이 수행됩니다. 모든 캐시된 파일을 확인하고 공유 아카이브에서 누락되거나 손상된 파일을 수리합니다. 시작 시에는 스토어와 연락하지 않으며, npm install을 실행하거나 TypeScript를 컴파일하지도 않습니다.

관리자 → 공식 HTTPS 스토어나 로컬 업로드를 통해 플러그인을 설치하고, 업그레이드를 진행하며, 활성화, 비활성화 및 제거할 수 있습니다. 기본 스토어는 `https://store.smartdoca.cc`, 무시됨 `DOCA_PLUGIN_STORE_URL`운영은 검토된 내용이 반영된 저장을 사용하며, 각 인스턴스가 재시작된 후에 효과가 나타납니다. UI는 전역적으로 원하는 선택과 해당 인스턴스에서 실행 중인 선택을 구분합니다. Fastify 경로의 즉시 제거는 제공되지 않습니다.

사전 빌드 릴리스는 명시합니다 `doca.manifest`, `doca.server`, 선택적 `doca.web`, 의무적 `doca.dataVersion` 그리고 `doca.storage: "host"` package.json에서 정적 저장소 검증은 모든 설치 소스와 시작 복구 과정에서 서버에 데이터를 등록하거나 가져오기 전에 이루어집니다. 누락되거나 다른 저장소 선언은 변환 없이 실패합니다. SDK 범위, 경로, 그래프, 해시 및 정확한 구조도 확인됩니다. 설치된 업그레이드는 데이터Version이 변경되지 않아야 합니다. 현재 제거 작업은 필요한 비즈니스 정리 작업을 수행하고 성공 시 마커를 지웁니다; 레지스트리 트랜잭션은 데이터 생성 과정을 제어하며, 커밋 후에 실행되는 지속적인 개인 데이터베이스/객체 정리를 기록합니다; 클러스터 작업의 소진은 아직 진행 중입니다.

오프라인 폴더 `<install-root>/<plugin-id>/` 시작 시 공유 레지스트리에 게시되어 이동됩니다. `.imports/`런타임 파일들은 그곳에 있습니다. `.releases/<sha256>/`루트 npm 매니페드, 소스 링크 또는 레거시 발견 경로는 지원되지 않습니다. 프로그램 파일과 플러그인 비즈니스 데이터는 별도로 유지됩니다. 호스트 소스, package.json 및 Vite 설정은 설치 과정에서 변경되지 않습니다.

그것 [스토어 프로토콜](plugin-store-protocol.ko.md) 패키지 레이아웃, 원격 엔드포인트, 제한 사항 및 멀티인스턴스 의미론을 정의합니다. 참조 [배포](plugin-deployment.ko.md) 재시작 및 장애 복구를 위해.

## 4. 생명주기

```text
scan static metadata → check dependencies → import code
→ discover → required service check → initialize → mount → ready
→ stop accepting work → dispose in reverse dependency order
```

서비스는 토큰 객체의 정체가 아닌 안정적인 문자열 ID와 버전으로 식별됩니다. 호스트는 먼저 플랫폼 서비스를 제공합니다. 비즈니스 플러그인은 자신의 네임스페이스에만 서비스를 등록합니다. 호스트의 개인적인 서비스를 주입할 수 없습니다. `doca.server.*`각 서비스 ID는 하나의 제공자를 가집니다. 다중 기여 기능은 레지스트리를 사용합니다.

각 등록은 컨텍스트 효과에 속하는 disposer를 반환합니다. 서비스, 작업, 이벤트 구독, UI 등록은 하나의 호스트 인스턴스에 속합니다. 이를 저장하지 마세요. `globalThis` 아니면 `Symbol.for`한 프로세스에서 실행되는 두 개의 테스트 앱은 서로 영향을 주어서는 안 됩니다.

목표 기능 중 일부는 아직 내보내지지 않았습니다: files.v1, documents.v1, users.v1, permissions.v1, http.v1, ai.v2, ai-usage.v1, search.v1, content.v1, activity.v1, notifications.v1 (내보내짐), events.v1, 호스트 관리형 플러그인 관계적 저장소 (SDK 0.1.7에서 내보내짐), 그리고 policies.v1. 실제 ID는 현재 내보내진 내용에 따라 결정됩니다. 이름 변경 시 버전을 관리해야 합니다. 이 표는 구현되지 않은 인터페이스를 기존 플러그인에 전달할 권한이 없습니다.

## 5. 사용자 정보 및 요청 맥락

HTTP 요청, AI 도구, 그리고 백그라운드 작업은 requestId, principal, pluginId, signal, 그리고 선택적으로 sessionId, turnId, jobId, callId와 같은 하나의 신뢰할 수 있는 실행 컨텍스트를 공유합니다. 식별 정보는 호스트 인증이나 저장된 작업 권한에서 제공됩니다. 플러그인은 자신의 HTTP 본문으로 사용자 식별 정보를 생성할 수 없습니다.

서버에 저장된 전체 사용자 정보에는 안정적인 ID, 공개 ID, 로그인 정보, 표시 이름, 아바타, 상태, 관리자 플래그, 인증된 연락처, 프로필 필드, 맞춤형 비즈니스 필드, 그리고 사용자가 읽을 수 있는 신원 연동 메타데이터가 포함됩니다. 일반 검색 결과는 최소한의 정보만 제공됩니다. 해당 정보에는 비밀번호 해시, 세션 토큰, 인증 코드, OAuth 토큰, 모델 API 키, 또는 저장 비밀번호는 포함되어 있지 않습니다. 브라우저에 전체 서버 프로필을 반환하거나 자동으로 모델 프롬프트에 추가하지 마세요.

사용자가 생성, 프로필 업데이트, 상태 변경 등의 이벤트를 지속적으로 발생시킵니다. 아직 사용자 삭제 관련 기록은 없습니다. 백그라운드 작업이 사용자 상태와 리소스 권한을 다시 확인합니다. 비활성화된 사용자는 이전 작업 스냅샷에서 접근 권한을 유지할 수 없습니다.

미래의 삭제 흐름은 호스트에 의해 기록됩니다: 삭제 및 접근 권한 취소를 표시하고, 플러그인은 중복 작업 없이 정리하고 확인한 후, 호스트가 삭제를 완료합니다. 이는 비활성화된, 제거된, 및 사용 불가능한 플러그인까지 포함해야 하며, 재시도와 감사된 수동 경로가 필요합니다. 타임아웃은 성공으로 간주되지 않습니다. 교차 데이터베이스 2단계 커밋을 사용하지 않습니다. 사용자 삭제 항목이 열리기 전에 이를 승인해야 합니다.

## 6. 권한 및 사용자 교차

리소스 참조는 `(pluginId, resourceType, resourceId)`플러그인은 자신의 권한 설정자를 등록합니다. 호스트가 이를 호출합니다. 파일 및 문서 서비스는 각자의 ACL을 유지합니다. 플러그인을 등록해도 사용자의 파일을 읽을 권한은 주어지지 않습니다.

플러그인은 mailbox.read와 같은 비즈니스 작업 및 역할 맵을 정의합니다. 플러그인 작업은 문서 편집기와 반드시 같아야 하는 것은 아닙니다. 권한 부여자가 없거나 플러그인이 비활성화되었거나 결과가 불확실하면 접근이 거부됩니다. 본문 읽기, 첨부파일 다운로드, AI 도구 및 검색 기능은 다시 확인을 요구합니다.

호스트는 관리자의 모든, 관련 및 무관 규칙과 사용자별 우회 설정을 유지합니다. 관련 후보는 내장된 문서 및 파일 소스와 활성 플러그인 교차 소스의 합성물입니다. 호스트는 여전히 사용자 상태, 필드 가시성 및 페이징을 필터링합니다. 무관은 플러그인에 규칙을 확장하도록 요청하지 않습니다.

승인된 비즈니스 관계로 인해 어떤 사이트 사용자가 발견될 수 있는 교차점 소스가 있습니다. 공유 사서함 또는 캘린더 멤버들이 교차점이 될 수 있습니다. 낯선 사람의 메일, 동일한 이메일 도메인, 또는 메시지 본문의 이름은 그렇지 않습니다. 플러그인은 관리자 디렉터리 정책을 작성하지 않습니다.

소스 프로토콜은 소스 ID, 스키마 버전, 후보 배치 및 커서, 관계 ID 및 버전, 그리고 현재 사실 재검토를 지원합니다. 플러그인은 대규모 관계 인덱스와 그 아웃박스를 유지합니다. 사용자 검색은 플러그인 데이터베이스를 스캔하지 않습니다. 만료된 후보는 반환되기 전에 재검토됩니다. 소스 장애는 검색 범위를 넓히지 않습니다. 플러그인을 비활성화하면 그 소스가 즉시 제거됩니다. 다시 활성화하면 버전과 유효한 관계를 먼저 조정합니다.

검색 가능하다는 사실은 비즈니스 권한을 부여하지 않으며, 전체 프로필 정보를 공개하지도 않습니다. 여러 출처에서 온 중복 사용자들은 페이징 전에 중복 제거됩니다. 사전 필터링된 총계는 숨겨진 사용자를 노출해서는 안 됩니다.

## 7. 파일, 플러그인 데이터, 및 트랜잭션

플러그인은 인젝트된 files.v1 파일을 사용하며 안정적인 ID를 저장합니다. 첨부 파일 바인딩은 `(ownerPlugin, ownerType, ownerId, role)`개인적인 첨부파일 저장소를 만들거나 임시로 생성된 서명된 URL을 영구적인 참조로 저장하지 마세요. 소유자 바인딩이란 접근권이 아니라 소유권입니다. 우편을 통해 첨부파일을 읽으면 우편함과 바인딩이 다시 확인됩니다. 원본 파일을 열면 여전히 그 파일의 ACL이 적용됩니다.

모든 비즈니스 지속성은 호스트가 관리합니다. 플러그인은 테이블, 인덱스, 작업/아웃박스 의미론 및 권한을 정의하지만, 저장소 서버를 선택하거나 직접 데이터베이스에 연결하거나 시스템 디렉터리에 지속성을 저장하는 것은 없습니다. 논리적 데이터베이스는 `plugin:<pluginId>`설치 식별자에 바인딩되어 있습니다. 사용자 파일은 files.v1을 사용하며, 개인용 바이너리, 자격 증명 및 임시 작업은 각각의 호스트 기능을 사용합니다. 관리되는 데이터베이스/개인 객체 API는 plugin-sdk/storage를 통해 내보내지며, 자격 증명은 SDK source 0.1.9에 내보내집니다. 작업 공간 API와 data.v1/data.v2는 사용할 수 없습니다. 누락된 기능은 자가 관리 스토리지로 대체할 수 없습니다. 구조는 정확히 일치하며, 암시적 변환이나 오래된 데이터 fallback이 없습니다. 호스트가 관리되는 스토어 정리 작업을 담당하며, 이는 플러그인 파일 시스템 삭제가 아닌 인스턴스 간에 조율됩니다.

데이터베이스와 파일 서비스 모두에서 동등성, 보상, 보정을 사용하세요. 공유 트랜잭션은 없습니다.

### 7.1 내구성 있는 파일 생성

`files.v1.folders.create` 그리고 `files.v1.files.create` 선택적으로 받아들임 `idempotencyKey`비공백이며 최대 200자, 제어 문자는 포함되지 않습니다. 범위는 삽입된 플러그인 ID, 현재 사용자, 작업 유형입니다. 동일한 키와 동일한 매개변수로 첫 번째 결과가 반환됩니다. 동일한 키와 다른 매개변수는 409를 반환합니다. 파일 또는 폴더 행과 완료된 수락은 함께 처리됩니다. 수락은 만료되지 않습니다. 비활성화 및 제거는 파일을 삭제하지 않습니다. 결과가 삭제된 후 재생 시 404를 반환하며 파일을 다시 생성하지 않습니다. 재생 및 쿼리는 계정 및 작성 권한을 다시 확인합니다.

업로드 완료됨 `contentIdentity: {sha256, size, mime}`이empotent 업로드는 이를 통과해야 합니다. 호스트는 업로드된 바이트를 확인합니다. 요청 피어싱트에는 임시 업로드Id가 아닌 대상 디렉터리, 이름, 콘텐츠 식별자가 포함됩니다. 복사는 sourceFileId를 사용하며 contentIdentity는 필요하지 않습니다. 플러그인은 작업 키, 비즈니스 매개변수, 콘텐츠 식별자를 자체의 아웃박스에 저장합니다.

`files.receipts.get(context, {operation, key})` null 또는 반환 `{status: "pending" | "completed", operation, result}`대기 중이라는 것은 원래의 매개변수를 다시 시도할 수 있다는 뜻입니다. 작업이 아직 진행 중이라는 의미는 아닙니다. 완료된다는 것은 역사적 상태를 반환합니다. 응답이 알 수 없다면 수신 내용을 읽은 후 원래의 create 작업을 다시 수행해야 합니다. 실패는 성공으로 변환된 수신 내용이 되지 않습니다.

호스트는 객체 ID와 저장 설정을 저장한 후 바이트를 쓰게 됩니다. 로컬 쓰기는 원자적 교체 방식을 사용합니다. S3은 전체 객체를 씁니다. 시작 시와 시간 단위로 실행되는 스캔 작업을 통해 완료된 intent에서 남은 여분의 객체, 24시간 이상 진행되지 않은 intent에서 남은 바이트, 그리고 임시 파일을 회수합니다. 회수 및 업로드 시 재시도 과정에서는 데이터베이스 사용자 잠금을 공유하고 객체 참조를 확인합니다. 등록된 객체는 쓰레기로 삭제되지 않습니다.

### 7.2 검색 및 외부 지식

사용하기 `@smartdoca/plugin-sdk@^0.1.9`. 수입 `contentServiceToken` 그리고 `ContentSource` 타입 from `@smartdoca/plugin-sdk/content`; 토큰을 선언합니다. `injections.required` 마운트하는 동안 소스를 등록합니다. 소스는 등록된 플러그인에 속합니다. 내장 문서와 파일은 동일한 계약을 사용합니다.

| 회원                                        | 계약서                                                                                                                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선언                                   | `id`, `pluginId`, `version: 1`, 지역화된 `title`, `contentTypes`, `purposes`, `capabilities: {search}`, `configSchema`                                                                                     |
| `list(ctx, {config, cursor, limit})`          | 필요. 반환 `{items, nextCursor, snapshot}`각 항목에는 `ref: {sourceId, resourceId, blockId}`, `fingerprint`, `title`, 선택적 `order`, `anchor`, `excerpt`; 여기서는 전체 몸을 반환하지 마세요. |
| `read(ctx, {config, ref, fingerprint})`       | 필요합니다. 권한을 다시 확인한 후 아이템과 함께 반환하세요. `text`사용할 수 없을 경우는 null입니다. 변경된 지문은 충돌이며, 오래된 지문 아래에 새로운 텍스트는 없습니다.                                       |
| `resolve(ctx, ref)`                           | 필요. 접근 권한을 다시 확인하고 반환하세요. `{path, fingerprint}` 또는 null. `path` 이것은 앱 내 위치입니다.                                                                                                     |
| `search(ctx, {config, cursor, limit, query})` | 선택적; 선언하고 함께 구현합니다. 가벼운 페이지를 반환합니다. 지원되지 않는 검색은 전체 스캔으로 전환되지 않습니다.                                                                                  |

`ctx` 인증된 내용이 포함되어 있음 `principalId`, `purpose` (`knowledge`, `analysis`, 또는 `search`) 및 취소 `signal`공급업체는 모든 요청에 현재의 비즈니스 허가를 적용합니다. 분석을 지원하는 소스는 메일 전용 API 없이 미래의 할 일 플러그인을 제공할 수 있습니다. 사용자들은 이를 사용합니다. `sources(ctx, purpose)`그런 다음 서비스 `list/read/search` 와서 `sourceId` 그리고 `purpose`; 서비스 `resolve` 가지다 `{ref, purpose}`그 출처가 명시한 목적만 요청하세요.

페이지 번호는 null로 시작하고 끝납니다. 탐색 과정에서의 모든 페이지는 일관된 스냅샷을 공유해야 하며, 만료가 되면 무시하지 않고 다른 데이터를 계속 사용하는 대신 실패해야 합니다. 이 커서는 전체 허가된 재고를 페이지화하는 용도이며, 지속적인 변경 로그는 아닙니다. `listChanges` 그리고 `readChanges` 이 계약에 따라 요구되거나 수출될 필요는 없습니다. 소스는 내부적으로 자신의 비즈니스 시스템을 동기화할 수 있지만, Doca는 그러한 구현을 요구하지 않습니다.

지식 시스템은 기존의 구독 및 일정 관리 시스템을 활용합니다. 사용자는 출처, 도서관 및 설정 설정을 명시적으로 선택합니다. 호스트는 참조 정보와 블록 지문을 저장하고, 전체 재고 목록을 비교하며, 새로 생성되거나 변경된 블록만을 읽고 분석합니다. 추가적인 전체 출처 본문 복사본을 보관하지 않습니다. 변경되지 않은 블록은 다시 읽을 필요가 없습니다. 완전하고 일관된 재고 목록만이 삭제를 결정할 수 있으며, 실패하거나 부분적인 실행 결과는 이를 인정하지 않습니다. 안정적인 블록 식별은 문서의 전체 수정본이나 위치별 단락 인덱스에 의존해서는 안 됩니다.

삭제, 해제, 취소 또는 사용할 수 없는 소스가 발생할 경우, 파생된 지식은 새로운 정상적인 읽기, 목록, 검색 및 답변 검색에서 제외됩니다. 수동으로 편집된 결과를 포함하여 관리자 처리용으로 콘텐츠가 보존됩니다. 이미 전송된 콘텐츠와 이미 열린 공동 작업 연결은 이 검사로 인해 후회 없이 취소되지 않습니다. 설정 UI는 기본 필드, enums 및 문자열 배열을 지원합니다. 복잡한 설정은 플러그인 자체 UI에 속합니다. 이 통합 기능은 데이터베이스 스키마 마이그레이션, 이중 읽기/쓰기 또는 기존 소스 어댑터를 추가하지 않습니다. SDK는 여전히 내보내집니다. `knowledge.sources.v1`하지만 이는 새로운 통합 기능에 대한 구독 정보가 아니며 자동으로 적용되지도 않습니다. `content.v1`.

제한 사항: 페이지당 재고 항목 100개, 전체 검색 시 100,000개의 항목, 본문 2백만 자, 분석 실행 시 120,000개의 변경된 본문 자료, 20초의 소스 호출 마감 시간. 과도하게 크거나 불완전한 작업은 명시적으로 실패하며, 잘라내고 완료된 것으로 처리하지 마세요. HTTP 엔드포인트는 `/api/v1/content/sources` 그리고 `/api/v1/content/{list,read,resolve,search}`. 보기 [정확한 프로토콜과 제한 사항](plugin-content.ko.md) 요청 형태와 구독 경로를 위한 것입니다.

## 8. AI 도구, 기술, 사용법

SDK 소스 0.2.0은 서버를 내보냅니다. `ai.continuations.v2`설치 범위의 소스 등록, 인증된 도구 대기, 지속적인 체크포인트, 중복 제거된 웨이크 알림 및 재시작 조정. 비즈니스 작업과 권한은 플러그인에 속하며, 호스트는 대기 중에 모델 실행을 해제합니다. 명시적인 버전 1 대기 기록만 참여하며, 데이터베이스 마이그레이션이나 역사적 변환은 없습니다. 자세한 내용은...을 참조하십시오. [계속 계약](plugin-ai-continuations.ko.md).

현재의 소스 Web SDK를 내보냅니다. `PluginWebHost.ai.open` 프롬프트/컨텍스트, 승인된 문서/파일, 선택적 소유 세션/모델, 명시적인 자동 전송 기능을 갖춘 개인 비서 서비스 출시를 위해 사용됩니다. 이는 저장소 마이그레이션이나 기존 호스트 어댑터 없이 기존 호스트 세션/메시지 및 실행 정책 흐름을 사용합니다. 자세한 내용은... [발사 계약](plugin-assistant.ko.md)이것은 클라이언트 UI 기능이며, 서버 AI 실행 서비스는 아닙니다. npm/native의 생산 환경 가용성은 아직 확인되지 않았습니다.

플러그인은 도구, 기술, 의도, 워크플로우, 결과 렌더러, 체크러를 등록할 수 있습니다. 도구는 이름 스페이스 ID, 입력 및 출력 스키마, 실행자, 그리고 권한 요구사항을 가지고 있습니다. 기술은 패키지 내의 버전 관리된 콘텐츠입니다. 이는 도구 권한 부여를 피하는 방법이 아닙니다.

플러그인 도구는 승인된 사용자 프로필과 AI 통화 컨텍스트를 받습니다: 세션, 턴, 작업, 도구 통화, 모델 ID, 매개변수, 취소 신호, 그리고 허용된 자료 참조입니다. 임의의 역사와 모든 프롬프트는 기본 도구 컨텍스트가 아닙니다. 채팅과 MCP는 권한 부여와 도구 실행을 공유합니다.

MCP는 현재 설치된 도구들을 공개합니다. `mcp` 같은 실행자와 현재 사용자/등록 검사를 통해 노출됩니다. 공식적인, 설치된 플러그인 및 활성화된 개인 SKILL은 서비스 보조금과 유효 사용자에 의해 필터링됩니다. 개인 및 회사 서비스 구성은 호스트 소유이며, 새로운 SDK 내보내기나 플러그인 소스 경로 접근은 없습니다. 참조하세요. [MCP 서비스](mcp.ko.md).

핵심 기능에는 멤버십 등급, 포인트, 가격, 선물 할당량, 또는 등급 기반 모델 필터링이 없습니다. 호스트는 모델 설정, 기술적인 시간 제한, 동시성, 컨텍스트 제한, 그리고 사용자, 모델, 플러그인, 작업, 호출에 의해 확인 가능한 원시 사용량을 유지합니다. 각 모델에는 입력 및 출력 토큰 비율이 있습니다. 이미지 생성에는 성공한 이미지당 토큰이 있습니다. 이러한 비율은 공급업체의 사용량을 누적 토큰으로 변환합니다. 이는 통화나 최종 가격이 아닙니다.

각 제공자 시도마다 고유한 callId와 attemptId가 있습니다. 알 수 없는 값은 null입니다. 0을 만들어서는 안 됩니다. 캐시나 추론 토큰은 이미 입력 또는 출력 총계에 포함되어 있을 수 있습니다. 이를 두 번 추가해서는 안 됩니다. settlement은 호출 시작 시점의 요금 스냅샷을 동결합니다. UI와 `ai.usage.recorded` 평가된 사용량을 표시합니다. 레지스터에는 원본 공급업체 지표가 저장됩니다. 추정치와 실제 값은 별도로 유지됩니다. 재생 기능은 두 번 측정되지 않습니다.

호스트 AI 실행기를 통과하는 호출만이 통합 메터에 포함됩니다. 제공자를 직접 호출하는 플러그인은 그 약속에서 벗어납니다.

제어 플러그인은 자체 트랜잭션 내에서 atomically 예약을 해야 하며, idempotent 예약 ID를 반환해야 합니다. 완료 또는 실패는 내구성 있는 이벤트 재시도를 통해 해제되거나 해결됩니다. 잔액을 확인하고 호출한 후 차감하는 것은 동시에 이루어지는 할당량 제어가 아닙니다. 실패한 사용 이벤트는 호스트 레지스트를 삭제하지 않습니다. 재생은 callId와 attemptId를 기준으로 중복을 제거합니다.

policies.v1은 문서 생성, 파일 업로드, 공유도 포함합니다. 허용 또는 거부 결과와 안정적인 이유 코드를 반환합니다. 기본값은 상업적 제한이 없습니다. 정책 플러그인은 리소스 ACL, 계정 상태, 요청 크기, 실행 안전 제한을 확장할 수 없습니다. 정책 예외는 허용으로 처리되지 않습니다. 필요한 제어 플러그인이 없으면 작업이 불가능하며 오류는 명확하게 표시됩니다.

## 9. 페이지, 내비게이션, HTTP

비즈니스 플러그인은 글로벌 네비게이션, 자체 트리 또는 사이드바, 페이지, 관리자 기능, 개인 설정, 문서 메뉴 동작, 검색 결과, 그리고 AI 결과 표시 기능을 제공할 수 있습니다. 위치는 안정적인 슬롯, 순서, 및 ID를 사용합니다. 비즈니스를 추가하기 위해 호스트 경로 분기에 수정하지 마세요.

웹 타겟은 브라우저 ESM, 스타일, 그리고 플러그인으로 만들어진 자산입니다. 호스트는 활성 매니페드에서 버전이 지정된 URL을 로드합니다. 빌드는 임포트하지 않아야 합니다. `@web/*`로컬 호스트 소스 또는 해결되지 않은 베어 임포트. 호스트는 전체 npm 패키지가 아닌 선언된 정적 디렉터리를 제공합니다. 서버와 클라이언트 버전 불일치로 인해 해당 플러그인 페이지가 사용할 수 없게 됩니다. 누락된 렌더러는 일반적인 역사적 표시를 유지합니다. 웹 등록 오류는 플러그인 경계 내에 남아 있습니다. 코어 작업 공간은 브라우저 번들이 로드되는 동안 렌더링할 수 있습니다. 직접적인 플러그인 페이지는 경로가 발견되는 동안 로딩 상태를 표시합니다.

http.v1 등록 `/api/v1/plugins/<plugin-id>/...` 호스트 인증, 원산지 및 호스트 확인, 요청 스키마, 오류 형식, 속도 제한, 취소 기능을 재사용합니다. 공개 웹호크는 외부 신원이 어떻게 확인되는지 명시해야 합니다. 네이티브 코드는 여전히 앱 빌드와 함께 제공됩니다. 모바일 기능이 있는 플러그인은 이메일 통합 v1 가이드에 설명된 스코프 WebView 셸을 사용합니다.

## 10. 회원 자격 및 관리 기능 제거

회원 자격을 제거하면 관리 페이지, 레벨 표시, 플랜 및 보조 API, 신원 제공자 레벨 맵, 리소스 할당량, AI 포인트, 그리고 레벨별 모델 필터링 기능이 포함됩니다. 레벨 제한을 유지하면서 페이지를 숨기는 것만으로는 충분하지 않습니다. 원시 AI 사용 기록은 그대로 남습니다. 이 프로젝트에는 기존 상업적 기능이나 마이그레이션 계층이 포함되어 있지 않습니다.

콘텐츠 모니터링 기능을 제거하면 보고서 입력 지점, 리뷰 관리자, 공급업체, 스캔 작업, 호스트 흐름 내의 전용 리뷰 통화 등이 포함됩니다. 등록에 대한 관리자의 승인은 계정 정책에 따릅니다. 보안 감사는 필수입니다. 콘텐츠 모니터링 기능이 제거되더라도 이들은 삭제되지 않습니다.

메일, 캘린더, 멤버십, 모니터링은 비즈니스 플러그인입니다. 간단한 메모는 핵심 기능에서 제거되었으며, 향후 독립적인 플러그인으로 다시 등장할 가능성이 있습니다. 티켓, 제3자 동기화, 인식기, 알림 채널은 동일한 SDK, 데이터, 클라이언트 수용이 이루어진 후에 분리될 가능성이 있습니다. 비공개 호스트 구현을 여전히 불러오는 래퍼를 남겨두지 마세요.

## 11. 개발과 수용

- 공개 ID, 테이블, 이벤트, 도구에는 플러그인 네임스페이스가 있습니다. SDK 버전 범위는 명확하게 지정되어 있습니다.
- 이 패키지에는 JavaScript가 포함되어 있습니다. `.d.ts`정적 매니페스트와 선언된 클라이언트 아티팩트입니다. Doca 저장소 별명에 의존하지 않습니다.
- 단위 테스트는 capability 가상화를 사용합니다. 통합 테스트는 별도의 Doca, 격리된 데이터베이스, 그리고 임시 설치 디렉터리를 사용합니다.
- 수락 과정에서는 실제 호스트 빌드, SDK, 그리고 저장소 외부의 플러그인 tarball을 의존성 클로저와 함께 사용합니다. 설치 및 시작 과정에서는 레지스트리를 가져오거나 소스 링크를 따르지 않습니다.
- 빈 플러그인 디렉터리, 하나의 플러그인, 여러 개의 플러그인, 누락된 의존성, 중복된 ID, 버전 충돌, 맞지 않는 데이터베이스 기준선, 그리고 종료 시 정리 작업을 확인하세요.
- 두 호스트 인스턴스가 플러그인 서비스, 사용자 이벤트, 또는 도구 등록을 공유하지 않는지 확인하세요.
- 관련 및 비관련 정책, 관계 해지, 플러그인 비활성화, 소스 장애, 파일 바인딩, 그리고 검색 및 AI에서의 동일한 권한을 확인하세요.

## 13. 배달 등급

- 호스트 콘텐츠, 파일 서비스 및 공개 통합 히프는 기존의 경계를 유지합니다. 비즈니스 모델, 권한, 재시도 및 아웃박스 세마틱은 플러그인이 소유하며, 영속성은 항상 호스트가 관리합니다.
- 필요한 패키지 선언 `doca.storage: "host"` ZIP/npm/store 설치, 오프라인 디렉터리 임포트 및 시작 복구 전에 서버 코드 임포트 시 확인됩니다. 누락되거나 다른 값은 실패합니다. 플러그인 데이터 디렉터리 환경 변수, 서버 선택자, 레거시 어댑터 또는 암시적 데이터 마이그레이션은 지원되지 않습니다.
- 관리되는 관계형 스토리지와 개인 객체는 SDK 0.1.7에서 내보내집니다. 자격 증명은 SDK 소스 0.1.9에서 내보내지며, 임시 작업이 남아 있습니다. 서버 선택과 공유 배포는 호스트에 속하며, 플러그인은 로컬/원격을 구분하지 않습니다. 그들의 정확한 내보내기 상태는 스토리지 계약 및 12항에 명시되어 있습니다.
- 새로운 관리형 스토어는 명시된 구조만을 허용합니다; 일치하지 않는 경우 시작이 거부됩니다. 기존의 자가 관리 설치에 빈 스토어를 생성하거나 마이그레이션 계획을 우회하기 위해 제거 기능을 사용하지 마세요. 오래된 패키지/데이터는 변경되지 않으며, 변환에는 별도의 계약이 필요합니다.
  관리되는 개인 데이터베이스/객체 정리 작업은 호스트가 담당합니다. 비즈니스 프로그램을 성공적으로 제거할 때, 레지스트리 트랜잭션이 현재 세대를 마감시키고 개인 테이블/객체 정리를 지속적인 재시도로 처리합니다. 자격 증명 정리 및 생성 방지 기능이 구현되었지만, 클러스터 비즈니스 작업의 소비는 여전히 불가능합니다. 사용자 파일 및 기타 비즈니스 참조 정보는 보존됩니다. 호크 기능이 실패해도 설치는 그대로 유지되며, 외부 호크의 효과는 되돌릴 수 없습니다. 모든 인스턴스는 여전히 수동 재시작이 필요합니다.
- 건강 상태, 수정된 로그, 최근 작업 오류 및 대기 목록은 공개 상태 인터페이스를 통해 요약되며, 플러그인이 호스트 저장소 경로를 읽는 방식으로는 아닙니다.

제공되지 않음: 임의의 SQL, 크로스플러그인/호스트 분산 트랜잭션, 자동 오래된 저장소 가져오기/이중 쓰기, 모든 소스에 대한 기본 AI 접근, 또는 네이티브 프로세스에 의해 동적으로 실행되는 npm 플러그인 코드.
