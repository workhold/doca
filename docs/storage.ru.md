Десктопный клиент Tauri использует хранилище выбранного удаленного хоста. Любой предыдущий пробный вариант `local-v1` Профиль сохраняется без его открытия или перемещения. Смотрите [десктопный клиент](desktop-client.ru.md).

Этот модуль хранит аватары, обложки библиотек, изображения документов и приложения. Страницы редактора и администратора используют один и тот же API для загрузки. ## Настройка окружения

Выбран хранение файлов, необходимое. `DOCA_FILE_STORE_ID` и `DOCA_FILE_STORES_JSON`Оба примера окружения используют `/data/storage`Соответствует опубликованному контейнеру постоянного тома. Для разработки источника скопируйте `.env.example` и установите локальный корень в абсолютный записываемый директорий на вашем компьютере. Compose использует `docker.env.example`База данных хранит идентификаторы стабильного хранения и ссылки на объекты, а не учетные данные сервера. Страница управления доступна только для чтения.

```dotenv
DOCA_FILE_STORE_ID=local
DOCA_FILE_STORES_JSON='{"version":1,"stores":{"local":{"provider":"local","root":"/data/storage"}}}'
```

Используйте специальный постоянный директорий, доступный только пользователю сервиса и за пределами статической веб-дерева. Множество экземпляров должны использовать один физический сервер. Бэкапы включают базу данных, все хранилища файлов, упомянутые в документации, и защищенную конфигурацию развертывания. ID хранилища, упомянутый в документации, должен оставаться настроенным; изменение его физического пути или бакета не изменит его размер.

Текущая запускная процедура сопоставляет поддерживаемые версии баз данных с последним DDL. Неподдерживаемые версии и устаревшие форматы серверов, управляемые базами данных, остаются закрытыми без автоматической конвертации. Существующие развертывания должны следовать… [Контракт на обновление базы данных](database-schema-evolution.ru.md) и [требования к выпуску](releases/0.2.23.md)Сохраняя их запасы, ряды и оригинальный мастер-ключ ключа.

## S3 и CDN

Магазин с `provider:"s3"` требует `bucket`, `region`, `forcePathStyle` и `credentials:{accessKeyId,secretAccessKey,sessionToken?}` В JSON-формате окружения. Опционально `endpoint` Это HTTP(S) корневой источник без учетных данных, подпути, запроса или фрагмента. HTTP предназначен для явно настроенного конечного пункта на надежной внутренней сети; приложение не решает DNS, чтобы классифицировать пункт назначения как приватный. Оператор контролирует эти пункты назначения и сетевой выход; ни учетные данные, ни конечный пункт не настроены через интерфейс администрирования. Бак остается приватным; разрешены только необходимые операции чтения/записи/удаления для префиксов хоста и плагина. Валидация конфигурации не подтверждает реальной связи.

Для RustFS в сети общих контейнеров создайте приватный бакет и настройте его слушатель S3 API (порт по умолчанию `9000`, порт консоли `9001`) с адресацией по пути. Соответствие `region` для `RUSTFS_REGION`, которое по умолчанию `us-east-1`:

```dotenv
DOCA_FILE_STORE_ID=cloud
DOCA_FILE_STORES_JSON='{"version":1,"stores":{"cloud":{"provider":"s3","bucket":"doca-files","region":"us-east-1","endpoint":"http://rustfs:9000","forcePathStyle":true,"credentials":{"accessKeyId":"replace-me","secretAccessKey":"replace-me"}}}}'
```

Используйте хост-имя или внутренний адрес, доступный из контейнера Doca. Сайт, активы и источники CDN также принимают HTTP(S). Смотрите [Документация RustFS S3](https://docs.rustfs.com/zh/administration/protocols/s3)Этот пример относится к новой установке; изменение endpoints существующего магазина не заставляет перемещать его объекты.

Необязательно `cdn:{domain,keyPairId,privateKey}` Используется протокол подписанного URL CloudFront. Настройте приватный источник S3 с OAC и группой доверенных ключей, требующей подписанных URL; CDN должен сохранять полные ключи объектов, тип контента и его состояние. В окружении присутствует источник распространения HTTP(S) и ключ подписи PEM. После проверки последних ACL хост выдает URL, действующий в течение 60 секунд. Отмена подписи предотвращает создание новых ссылок; существующая ссылка может оставаться используемой до истечения срока действия. Скачанные байты не могут быть возвращены.

Без CDN хосты проксируют приватные файлы облака. Секреты хранения никогда не возвращаются в браузер. Для использования другого протокола подписи CDN требуется адаптер; не предусмотрена возможность откатки на постоянный публичный URL. Необходимо правильно настроить все идентификаторы магазинов, на которые ссылались, и сохранять доступ к их данным во время переключения учетных данных. Переключение не является миграцией данных.

## Кэширование изображений в браузере и CDN файлов

Изображения документов/комментариев, изображения помощника и аватары/обложки, управляемые хостом, используют стабильную версию. `/api/v1/assets/:id/content` URL. Успешные ответы с изображениями внутри текста, включая миниатюры, отправляются:

```http
Cache-Control: private, max-age=3600, must-revalidate
Vary: Cookie, Authorization
ETag: W/"object-and-variant-identity-digest"
```

Браузер может использовать свою локальную копию в течение часа. Как только она становится устаревшей, `If-None-Match` Пересоздаёт его: хост проверяет текущий доступ перед возвратом `304` Без байт изображения. Оригиналы и миниатюры имеют разные ETags. Ключи объектов неизменяемы; замена изображения требует создания нового активного файла. Изменения в куки/авторизации приводят к выбору отдельного кэшированного ответа при смене учетных записей. Отмена не проверяется при проверке актуальности; скачанные байты не могут быть возвращены. Браузеры могут удалять записи и заставлять перезагрузку/использование DevTools. **Отключить кэш** Можно обойти их. Это использует HTTP-кашинг без дополнительного использования IndexedDB или Service Worker. Смотрите [MDN HTTP кэширование](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching) для повторной проверки против `no-store`.

Аттакции AI без изображений, `download=1`Предварительные просмотры и ошибки остаются `no-store`Неавторизованный запрос не может получить доступ. `304` С известным ETag. Изображения документов имеют resourceId и в настоящее время остаются за прокси хоста, даже когда настроен CDN файлов S3. Изображения помощника также остаются за прокси хоста. Карты генерированных изображений и встроенные изображения помощника требуют существующий 480-пиксельный WebP тумблер; нажатие на них открывает оригинальное изображение, а загрузка сохраняет оригинальные байты. Пока асинхронная работа с тумблером находится в очереди или недоступна, встроенное изображение может отображать оригинальное изображение.

Перенаправления подписанных файлов через CDN продолжают работать `no-store` Таким образом, браузер не использует истекшую 60-секундную подпись. Финальные заголовки ответа файла должны находиться в CDN или в источнике S3; заголовки перенаправления не передаются. Новые объекты S3 в настоящее время используют… `Cache-Control: private, max-age=60`Это изменение не перезаписывает существующие объекты.

Для поведения private-file в CloudFront сохраняйте приватный источник S3/OAC, группу доверенных ключей и окно подписи длительностью 60 секунд. Установите **Политика заголовков ответа → Пользовательские заголовки** для `Cache-Control: private, max-age=60, must-revalidate` с **Переопределение** Для стандартизации ответов браузера для существующих и новых объектов. Используйте **CachingDisabled** Если только кэширование экрана не было предусмотано отдельно; пользовательская политика должна иметь минимальное значение TTL равное 0. Положительное минимальное значение может заменить значение из источника. `private/no-store`Политики заголовков ответов влияют на ответы, предоставляемые браузерам, независимо от TTL на уровне edge. Для получения информации см. документацию AWS. [Политика заголовков ответа](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/modifying-response-headers.html), [TTL для политик кэша](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cache-key-understand-cache-policy.html) и [подписанные URL-адреса](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-signed-urls.html)Никогда не использовать общественный долгосрочный кэширование для сайта. `/api/*`.

## Хранение истории и оффлайн-обновление

База данных хранит последние 20 полных бизнес-снимков. Каждая группа из десяти старых снимков сохраняет свой самый свежий снимок в настроенном файловом хранилище (хранение в облаке при настройке S3). Снимок – это gzip JSON-файл, содержащий контрольную точку и независимые метаданные восстановления, а также небольшой индекс базы данных. Только успешный иммутативный загрузка и чтение с помощью SHA-256 позволяют осуществить атомарное привязывание индекса и удаление десяти строк базы данных; остальные девять снимков намеренно удаляются и не могут быть восстановлены. Недостаточные группы и сбои хранения сохраняют оригиналы базы данных. Один обычный список с странированием объединяет оба источника без раскрытия типов хранения, ключей объектов или подписанных URL.

Активные контрольные точки, обнаруженные увеличения и приложения для совместной работы не подвергаются выборке. "Trash" сохраняет историю; очевидные постоянные очереди удаления ресурсов архивируют восстановление после часа и повторный проверку. Нет старого recovery_json, который декодируется в новую схему или заполняется из текущего базового уровня. Отсутствующая метаданная восстановления и неизвестные версии восстановления все еще отклоняют предварительные просмотры. Файлы требуют envelope v1, соответствующего хэша, ограниченного разгрузки и соглашения о индексе. Фоновые долговечные задачи повторно пробуют успешность без блокировки коммитов контента.

Нынешнее поколение `doca-2026-10-12-book-payload-storage-v1`Следующий этап исторического обслуживания применим только к точным `doca-2026-10-08-knowledge-books-v2` Базы данных (версия 0.1.13): сначала записывается `doca-2026-10-09-history-storage-v1`После этого текущий запуск может выполнить утвержденное структурное сопоставление. Остановить все хосты, сделать резервную копию базы данных, хранилища файлов и конфигурации, сохранить главный ключ, а затем выполнить:

```sh
pnpm history:upgrade                 # Show requirements; no mutation
pnpm history:upgrade --apply         # Add structure, update baseline and queue work; no immediate sampling
```

Не восстанавливайте базу данных вместо обновления. Неудачная транзакция обновления сохраняет оригинальную базу данных. Прямое откат истории допускается только. `doca-2026-10-09-history-storage-v1` Или его специальный маркер прерванного возврата, а не текущая генерация данных базы данных. Для базы данных текущей généции сначала проверьте. [Восстановление хранения книг](knowledge-book-storage-verification.ru.md)Хранящиеся ссылки на контрольные точки могут блокировать ранее выполненное возврат к исходному состоянию. Не переименовывайте базовый уровень, чтобы обойти проверку. Для базы данных, подходящей для генерации истории, остановите каждый экземпляр перед импортом сохраненных точек:

```sh
pnpm history:rollback --apply --manifest /backup/history-cloud-references.json
```

Манифест должен быть новым файлом и записывается с режимом 0600. Роллбек сохраняет ссылки на облако, проверяет и импортирует сохраненные точки, а затем возвращается к предыдущему базовому состоянию; файлы в облаке остаются сохраненными. Прерванный роллбек использует специальный маркер, который запрещает запуск хоста, предотвращая повторное отборка импортированных точек. Нужно устранить проблему с хранением и повторно выполнить роллбек с новым путем манифеста. Восстановление для пользователя все еще применяет текущую эпоху, разрешения и проверки expectedSeq; восстановление в формате rich text и Markdown, в то время как другие форматы остаются только для предварительного просмотра.

## Проверки и разрешения

- Аватары и обложки имеют размер не более 5 МБ. Файлы в форматах PNG, JPEG, WebP и GIF распознаются по заголовку файла и декодируются. Ограничение составляет 25 миллионов пикселей. Метаданные удаляются, а изображение сохраняется в формате WebP. Аватары имеют квадратную форму, размер не более 512 пикселей. Обложки имеют ширину не более 1600 пикселей. В GIF сохраняется первый кадр.
- Подключаемые документы/файлы AI имеют размер не более 20 МиБ и сохраняют оригинальные байты; распознанные растерные изображения проверяются с ограничением в 25 миллионов пикселей. Пути к изображениям аватара/обложки/комментариев нормализуют изображения в формате WebP с специфическими ограничениями. Обычные пользовательские файлы используют отдельный API для потокового загрузки с ограничением в 2 ГиБ. SVG и HTML не инлайнируются в виде исполняемых изображений. Обычные файлы предоставляются в качестве приложений. `nosniff` И также сандбэк. Нет сканирования вирусов.
- Максимум 4 одновременные загрузки, 60 попыток на пользователя за 10 минут. API также проверяет последние записи о загрузках. Обратный прокси должен указывать собственные ограничения по размеру данных, подключению и хранению. Пока нет квоты на диск для каждого пользователя.
- Проект образа можно прочитать только автором загрузки. После привязки он становится доступным для зарегистрированных пользователей сайта. Анонимные пользователи не могут его прочитать. Обложка подчиняется правилам ACL библиотеки. Не привязанный проект обложки можно прочитать только автором загрузки. Приложение подчиняется правилам ACL документа. Системный администратор не имеет дополнительных права на чтение. Для создания обложки требуется руководитель. Для создания приложения требуется редактор.
- Объект сначала записывается. Затем транзакция перепроверяет разрешения пользователя и ресурса и записывает актив. Если запись не проходит, некоммитированный объект удаляется, если это возможно. При редактировании для защиты используется версия ресурса. При редактировании аватара используется версия профиля.
- Завершены, но не связанные аватары и черновики обложек пока сохранены. Планируется очистка черновиков активов, установка квот на одного пользователя и сканирование от вирусов — эти задачи не выполнены. Для загрузки файлов обычных пользователей поддержка S3 multipart начинается с размеров 32 МиБ, причем части имеют размер 8 МиБ; это отдельно от endpoint для ограниченных активов. Падение программы может привести к сохранению незарегистрированного объекта. При очистке необходимо проверить каждый ссылка на актив. Не удаляйте общий объект только потому, что один документ был удален.

## Проверка

Автоматизированные тесты охватывают локальные загрузки, приватные разрешения, проверку изображений, связывание данных, конфликты, стабильные идентификаторы хранения, пространства имён плагинов и целостность неизменяемого архива. Прошли изоляированная интеграция с PostgreSQL и проверки локального браузера с двумя экземплярами. Симулированы вызовы SDK для S3 и подписи CDN; реальные ключи облака не использовались. Реальные загрузки/загрузки бакетов, принудительное соблюдение приватного источника, истечение срока действия подписи, отмена, сетевые сбои и восстановление резервной копии все еще требуют приемки, соответствующей конкретной службе. Смотрите [Отчет о приемлемости браузера](storage-browser-acceptance.md).
