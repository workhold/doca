# 편집기 공동 작업 계약

[中文](collaboration-sdk-contract.zh-CN.md)

서식 있는 텍스트, 마크다운, 스프레드시트, 캔버스, 슬라이드 및 향후 문서 유형에 적용됩니다. 2026-09-11에 제정되었으며, 구현 단계가 진행될 때 아래에 있는 것들은 각자의 날짜와 버전을 유지합니다. 사용하세요. [현재 편집기 매트릭스](editor-integration.ko.md) 설치된 패키지들에 대해.

이 플랫폼은 하나의 연결, 권한, 증분 저장, 커밋 확인, 재연결, 온라인 세션을 갖추고 있습니다. 각 구성 요소는 자체 데이터 모델과 렌더링을 담당합니다. 공유된 동작이 스프레드시트를 서식 있는 텍스트 구조로 변환하는 것을 의미하지는 않습니다.

현재의 서비스 프로토콜도 설명되어 있습니다. [협력과 검색](collaboration.ko.md)이 문서는 다음 공유 계약입니다. 여기 있는 필드는 자동으로 공개된 API가 아닙니다.

## 1. 레이어와 버전

| 층 또는 필드 | 공동의 의무 | 컴포넌트 차이 |
| --- | --- | --- |
| 운송 | 동일 원본의 WebSocket, 하나의 포장, 서버 인증 | 아무것도 없음 |
| 저장 | 로컬 증가, 아웃박스, 데이터베이스 커밋, ACK | 아무것도 없음 |
| 포맷 / 코덱 / schemaVersion | 유형과 구조가 호환되는지 여부를 파악합니다. | 서식 있는 텍스트 노드 CRDT; 스프레드시트의 안정적인 행, 열, 셀 명령 |
| 에포크ID | 한 가지 CRDT 계통입니다. 호환되지 않는 재구축이 발생할 때만 변경됩니다. | 스프레드시트는 에코파에 연결된 불변한 워크북 기준선도 필요합니다. |
| seq | 현재 에포크에서 유효한 커밋의 수가 단조 증가하는 형태입니다. | 아무것도 없음 |
| 체크포인트시퀀스 | 커밋 시퀀스는 이미 완전한 Yjs 체크포인트를 포함하고 있습니다. | 컴포넌트가 여전히 재생해야 하는 논리적 명령어는 삭제하지 마세요. |
| resource.version | 비즈니스 메타데이터를 위한 낙관적 잠금 | Yjs를 병합하는 데 익숙하지 않음 |
| 역사 버전 ID | 사용자가 보는 비즈니스 스냅샷 또는 되돌리기 | 모든 네트워크 업데이트가 아닙니다. |
| 상태 벡터 | 동기화 차이 요약 | 완전한 저장 확인이 아니며, 특히 삭제 설정 확인에는 그렇지 않습니다. |

각 형식은 계통을 epochId로 사용합니다. 주기적인 Yjs 체크포인트는 epoch을 변경하지 않습니다. 스프레드시트는 현재 Yjs 세션과 체크포인트 순서를 사용합니다.

## 2. 플랫폼과 구성 요소

이 플랫폼은 페이지당 하나의 실시간 세션을 제공합니다: 소켓, ACL, 증가 큐, ACK, 재연결, 비즈니스 스냅샷, 댓글, 알림, 그리고 자산 권한입니다. 특정 컴포넌트는 두 번째 HTTP 자동 저장 또는 소켓을 열지 않습니다.

컴포넌트는 문서 세션마다 Y.Doc과 편집기를 한 번만 생성합니다. 로컬 편집은 Yjs에 매핑되며, 원격 트랜잭션은 뷰에 프로젝트됩니다. 준비 상태, 오류, 형식 상태, 선택 및 앵커 정보가 노출됩니다. 프로퍼티 변경, readonly, 커서, 크기 또는 저장 힌트를 변경할 때는 공유 문서를 다시 생성해서는 안 됩니다.

서버는 코덱 플러그인을 통해 형식 차이를 숨길 수 있습니다: 초기화, 병합 검증, 비즈니스 프로젝션 생성, 가져오기 및 내보내기, 그리고 역사 롤백. 일반적인 룸, 권한, 저장 경로는 툴바나 셀 DOM을 이해하지 못합니다.

## 3. 메시지와 생명주기

제안된 엔베로펜: protocolVersion 1, type, id, room (resource UUID), 그리고 epochId입니다. 첫 번째 참여 시 epochId는 생략될 수 있습니다. 서버가 epochId를 반환한 후에는 이후의 작업에서는 반드시 epochId를 포함해야 합니다. ID, sessionId, 이름, 색상은 서버가 결정합니다.

1. join은 지원되는 코덱과 schemaVersion, 알려진 에포크, 그리고 벡터를 전송합니다.
2. sync-response는 epochId, 코덱, schemaVersion, seq, checkpointSeq, rank, update, 및 vector를 반환합니다. 스프레드시트는 또한 해당 응답에 연결된 불변 기준값도 반환합니다.
3. 기준선이 확인되고, Yjs가 완료되며 프로젝션이 완료된 후에야 보기가 준비됩니다. 편집 가능한 빈 문서를 표시하지 말고 그냥 넘어가세요.
4. 업데이트에는 id, room, epochId, 그리고 Yjs 바이트(현재 JSON 채널에 따른 base64 형식)가 포함됩니다. 실제 로컬 콘텐츠의 증분만을 전송합니다.
5. ACK은 커밋 후에 동일한 ID, epochId, 그리고 시퀀스를 사용하며, 필요에 따라 변경된 메타데이터와 비즈니스 메타데이터도 포함됩니다. 이는 트랜잭션이 커밋된 후에 전송됩니다.
6. 유효한 업데이트는 여전히 권한이 있는 다른 세션들에게 전송됩니다. 원격 업데이트를 적용할 때는 로컬 쓰기 작업을 발생시키지 않아야 합니다.
7. sync-request과 sync-response는 단지 차이점만을 채워줍니다. 이들은 ACK가 아닙니다. 아크되지 않은 큐를 비우거나 매번 추적 후 무조건 업로드해서는 안 됩니다.
8. 종료하고 이 세션의 선택을 해제하세요. 권한, 에포크, 스키마 오류는 서로 다릅니다. 이들은 모두 일반적인 네트워크 재시도가 아닙니다.

인식되지 않은 쓰기 작업을 다시 시도하면 원본 바이트와 메시지 ID가 유지됩니다. Yjs 병합은 중복 작업에도 무효화되지 않습니다. 중복 전송은 시퀀스, 감사 기록, 알림 또는 역사에 영향을 주지 않습니다. Doca는 편집기와 함께 리소스ID, 에포크ID, 메시지ID로 키가 지정된 마크다운 인증서를 사용하여 중복을 제거합니다. 동일한 ID에 다른 페이로드가 포함된 경우는 거부됩니다.

## 4. 상태 저장

연결 상태는 로딩, 동기화, 준비 중, 실패 시 분리되거나 오류 상태로 변합니다. 저장 상태는 별도로, 깨끗, 더러운, 저장 중, 오류 상태입니다.

- 로컬 콘텐츠 트랜잭션만 출력됩니다. 초기화, 선택, 스크롤, 포커스, 크기, 온라인 수, 하트비트, 원격 재생, 읽기 전용 스위치는 콘텐츠 업데이트를 생성하지 않습니다.
- “클라우드에 저장”은 빈 아웃박스와 완료된 동기화가 필요합니다. “저장”은 확인을 기다리는 쓰기 작업이 필요합니다.
- 큐는 순서대로 전송됩니다. 헤드 ID와 일치하는 ACK만 큐에서 제거될 수 있습니다. 알 수 없는, 늦은, 또는 중복된 ACK는 이후의 입력 데이터를 삭제해서는 안 됩니다.
- 디스커넥트는 바이트와 ID를 유지합니다. 재커넥트는 원격에서 데이터를 받아오고, 아직 인식되지 않은 증가값을 다시 시도합니다.
- 클라이언트 오프라인 이벤트는 즉시 실시간 연결을 종료하고 재시도를 중단합니다. 온라인 이벤트는 다시 연결하여 일반적인 문서 참여 과정을 수행합니다.
- 브라우저가 오프라인 상태이거나 공동 작업 연결이 실패할 때는 수정 가능한 복사본에 오프라인 알림이 표시됩니다. 초기 온라인 연결 및 문서 동기화 시 알림은 숨겨집니다. 연결이 끊기면 문서가 동기화를 완료하면 알림이 사라집니다.
- 치료하지 마세요 `encodeStateAsUpdate(doc, vector).length` 매우 더러운 상태입니다. 같은 상태에서 역사적 삭제 집합을 다시 반환할 수 있습니다. 2보다 큰 길이는 새로운 쓰기 작업이 아닙니다.
- 시대적 불일치로 인해 기존 큐가 중단됩니다. 내보내기 또는 별도의 복구 사본을 사용할 수 있습니다. 기존의 증분 데이터는 새로운 문서에 강제로 적용되지 않습니다.
- 현재의 호스트 어댑터는 원본 체크포인트와 대기 중인 메시지 ID를 유지합니다. `offline-replica.ts`오프라인 편집을 위해서는 승인된 복사본과 성공적인 로컬 저장이 필요합니다. 데스크톱 번들과 다운로드된 웹 프론트엔드는 로컬 문서 목록에서 시작할 수 있습니다.

두 호스트 모두 사용함 `apps/web/src/features/documents/update-outbox.ts`줄은 문서 유형에 관계없이 작동합니다. 실제 현지 거래 증가량을 유지합니다. 동기화 응답은 무조건적인 업로드를 유발하지 않습니다.

## 5. 추천되는 컴포넌트 API

모든 컴포넌트는 구별 가능한 오류 코드와 함께 connect, setReadOnly, dispose, onSelectionChange, renderRemoteSelections, clearRemoteSelections, onError 기능을 제공합니다. 서식 있는 텍스트는 format state도 제공합니다: 마크, 블록 유형, 정렬 방식, canUndo, canRedo 등입니다. 고정 도구바와 부동 도구바는 같은 format state를 공유합니다. DOM에서 형식을 추측하지 마세요.

거래의 출처는 로컬, 원격, 그리고 부트스트랩입니다. 로컬은 사용자가 직접 작성한 것입니다. 원격 거래를 적용할 때는 명령을 다시 감싸지 말고 새로운 작업 ID를 생성해야 합니다.

## 6. 라이브 선택

선택 연합은 텍스트(상대적 앵커 및 포커스), 셀(시트ID, 0부터 시작하는 폐쇄 행 및 열 범위, 편집), 또는 null입니다.

세션ID는 연결당입니다. 온라인 수는 userId를 중복 제거합니다. 그림 작업은 현재 세션을 제외하고 동일 계정의 다른 페이지를 포함합니다. 편집이 true이면 사용자가 입력하고 있는 것을 의미합니다. 입력하지 않는 선택은 false입니다. 스프레드시트 변경 및 편집 시작 또는 종료는 이벤트를 전송합니다. 셀 값, 공식, 키입력은 전송되지 않습니다. 게시는 100–150 ms로 제한되며 중복 제거됩니다. 데이터베이스에 저장되지 않고 버전을 업데이트하거나 취소 기능에 영향을 주지 않습니다. 두 가지 편집 모드 모두 이 세션의 선택을 게시합니다. 주의 분산 없는 편집은 현재 문서 보기에서 다른 세션의 커서와 선택을 숨깁니다. 편집기에서 나가거나 문서를 떠나거나 연결을 끊거나 취소하면 선택이 해제됩니다. 서버는 모든 메시지에 대한 ACL을 확인합니다. 브라우저 탭을 전환하면 여전히 온라인인 세션의 마지막 편집 위치를 유지합니다. 스프레드시트는 현재 시트에 색상 테두리와 이름 라벨만 그립니다. 숫자 좌표는 일시적인 존재이며 행과 열이 삽입되는 동안 잠시 유효하지 않을 수 있습니다. 오래 지속되는 코멘트 앵커는 안정적인 행과 열 ID를 사용합니다.

스프레드시트 편집기는 선택 상태와 실시간 API를 통해 게시, 수신, 그리고 존재성을 표현합니다. 만약 그 기능이 별도의 스프레드시트 패키지로 이동한다면, 이 선택 연합과 생명주기를 유지해야 합니다. 호스트는 영원히 파사드 세부 사항에 의존해서는 안 됩니다.

## 7. 스냅샷, 롤백, 및 지역 코멘트

Yjs 체크포인트는 원본 CRDT 인코딩을 저장합니다. JSON 프로젝션으로부터 재구성하거나 신원을 삭제하지 마세요. 스프레드시트는 동일한 에포크에 불변한 기준값과 명령을 저장합니다. 최신 워크북을 기준값으로 삼고 그 위에서 오래된 명령을 다시 실행하지 마세요.

주기적인 체크포인트가 에포크를 유지합니다. 사용자 기록은 의미 있는 지점에서 생성됩니다. 기록은 자체 형식, 코덱, 에포크, 기준값, 및 자산 의존성을 저장합니다. 현재 기준값과 함께 오래된 버전을 해석하지 마세요. 롤백은 현재 에포크의 새로운 변경 사항을 선호하며, 롤백 이전의 기록을 유지합니다. 구성 요소가 재구축할 수만 있다면 명시적으로 에포크를 전환해야 하며, 인식되지 않은 쓰기 작업을 처리한 후 새로운 계통을 로드해야 합니다.

핵심 레코드는 멤버십과 무관하게 성공적인 쓰기 작업의 스냅샷을 생성합니다. 자동, 수동, AI, 및 롤백 전 스냅샷은 지속성과 트랜잭션 경계를 공유합니다. 실패한 쓰기 작업은 롤백됩니다. 명시적으로 합의된 호스트 보존 정책에 따라 최신 20개의 전체 스냅샷이 데이터베이스에 보존되며, 10개의 오래된 스냅샷으로 구성된 각 완전한 그룹에 대해 가장 최신 스냅샷을 개인 파일 기반 복구 지점으로 보존합니다. 검증된 불변 업로드만이 인덱스를 원자적으로 기록하고 해당 그룹을 데이터베이스에서 제거할 수 있게 하며, 나머지 9개 지점은 의도적으로 샘플링됩니다. 불완전한 그룹과 저장 장치 장애는 데이터베이스 원본을 보존합니다. 사용자는 변경되지 않은 ID와 저장 위치 필드가 없는 일반적인 페이지화된 스냅샷 목록을 받습니다. 스냅샷 바이트, 독립적인 복구 메타데이터 및 첨부파일은 변경되지 않은 상태로 유지되며, 실시간 체크포인트와 드러난 공동 작업 증가치는 샘플링되지 않습니다. 비즈니스 정책은 이 합의된 보존 정책 외에 암시적 삭제를 추가할 수 없습니다. 기존의 롤백 기능은 형식에 특정합니다. 참조 [저장 작업](storage.ko.md#history-storage-and-offline-upgrade).

댓글 작성자, 본문, 답변, 해결 내용은 플랫폼 데이터베이스에 저장됩니다. 이 컴포넌트는 captureAnchor, resolveAnchor, renderAnchors, onAnchorClick 기능을 제공합니다. 서식 있는 텍스트는 상대적인 텍스트 위치를 사용합니다. 스프레드시트는 삽입 및 삭제로 변경되는 안정적인 행과 열 범위를 사용해야 합니다. 완전히 삭제되거나 해결된 앵커는 강조되지 않습니다.

현재의 스프레드시트 패키지와 호스트는 지역별 주석을 안정적인 행/열 식별 정보와 함께 처리하며, API 캡처/해결/공개, 마커 렌더링, 에포크 검증 및 삭제 대상 처리 기능을 지원합니다. 행/열 삽입, 정렬 및 시트 변경 기능도 격리된 테스트를 통해 지원됩니다. `tests/editor-sessions.test.ts`, `tests/sheet-axis-sizes.test.ts` 그리고 `tests/sheet-collection.test.ts`이 영구 프로토콜은 일시적인 세포 존재와는 별개입니다.

## 8. 공동 수용

1. 기존 데이터를 열고 60초를 기다린 후 선택, 스크롤, 크기 조정을 수행합니다. 새로운 콘텐츠나 역사는 전혀 추가되지 않습니다.
2. A가 편집하고, B가 수신하며, B는 커밋에 반응하지 않고, 프로젝션이 일치합니다.
3. 한 계정의 두 페이지가 서로 다른 색상과 이름을 가지고 있습니다. 텍스트 선택 및 셀 편집 상태가 정확합니다. 읽기 전용 모드에서는 게시하거나 표시하지 않습니다.
4. 잃어버린, 중복된, 지연된 ACK, 재연결 중 입력 작업, 데이터 손실 없음, 미리 저장된 내용도 표시되지 않음.
5. 순수한 삭제 후 반복적인 동기화는 삭제된 집합을 다시 업로드하지 않습니다.
6. 맞지 않는 기준선, 에포크, 또는 스키마는 거부됩니다. 반복적인 초기화는 새로운 콘텐츠를 생성하지 않습니다.
7. 스프레드시트의 행과 열 삽입 및 삭제, 셀 편집, 공식, 병합, 정렬 및 필터링, 그리고 취소 기능은 하나씩 허용됩니다. 지원되지 않는 작업은 표시되거나 비활성화됩니다. 모든 작업이 정상적으로 진행된다고 주장하지 마세요.
8. 재시작 후, 체크포인트 플러스의 증가량은 로그 압축 후를 포함하여 온라인 예측과 일치합니다.
9. 수정 시 취소, 비활성화, 익명 접근, 외국인 방, 위조된 신분, 그리고 범위를 벗어난 선택은 격리됩니다.
10. 고정 및 플로팅 도구바는 형식이 동일합니다. 저장 상태 업데이트는 편집기를 재구성하거나 포커스를 잃지 않습니다.

## 9. 무엇이 구현되었는가

현재 호스트는 서식 있는 텍스트, Markdown, 스프레드시트, 캔버스, 슬라이드를 공유된 신뢰할 수 있는 커밋 큐와 지속적인 ACK를 통해 통합합니다. 대기 상태 동기화는 콘텐츠를 반영하지 않습니다; 선택 및 이름은 형식 어댑터를 사용합니다. 모든 다섯 가지 형식은 역사 정보 읽기를 제공하며, 관리자 복원은 서식 있는 텍스트와 Markdown에만 지원됩니다. 스프레드시트, 캔버스, 프레젠테이션 미리보기는 보고됩니다. `canRestore:false`이것은 모든 형식에 대한 통합 컴포넌트 롤백 API를 제공하지 않습니다.

이 플랫폼은 에포크, 프로토콜 검사, 커밋 인증서, 그리고 역사 복구 메타데이터를 구현합니다. Redis가 없다면 브로드캐스트와 존재는 하나의 프로세스에 불과합니다. Redis가 있으면 문서 업데이트, 서버 리프레시, 권한 무효화, 알림, 그리고 존재는 여러 인스턴스를 넘나듭니다. 데이터베이스의 커밋은 여전히 ACK 경계이자 문서의 진실의 원천입니다. Redis가 다시 연결되면 서버는 이 인스턴스의 활성룸에 권위 있는 상태를 다시 전송합니다. Pub/Sub는 내구성 있는 로그가 아니며, Redis가 실패하면 지역 버스로 조용히 전환되지 않습니다.

формаль적인 선택 API와 다양한 형식 간의 통합 롤백 기능은 컴포넌트와 플랫폼 간에 공동으로 진행해야 하는 작업입니다. 호스트는 오프라인 문서 시작 및 지속적인 큐를 담당합니다. 컴포넌트의 기능은 설치된 패키지의 출력물이 정확한지 확인해야 합니다.

오프라인 홈에서는 허가된 문서 목록을 보여줍니다. **최근 수정**새 클라이언트에서 실시간으로 열린 후, 해당 문서의 일치하는 로컬 리플로이가 사용 가능해지면 디렉터리에 문서가 추가됩니다. 데스크톱은 포함된 프론트엔드를 제공합니다. 웹 작업 공간은 로그인 후 동일 원본의 빌드 자산을 자동으로 캐시합니다. 편집 가능한 리플로이는 클라이언트가 연결 손실을 감지하면 오프라인 편집 메시지를 표시합니다. 재연결 시 기존의 견고한 ACK 경로를 통해 예약된 변경 사항을 전송하기 전에 접근 권한과 계통을 확인합니다. 닫힌 문서는 다시 열면 동기화를 재시작합니다. 자세한 내용은...을 참조하세요. [오프라인 문서 및 복구](access-offline-events.md#离线文档入口).

## 플러그인 요소가 증가함 — 2026-10-02

호스트는 이제 선택적 SDK 0.1.6 웹 요소 등록기를 구현합니다. 서식 있는 텍스트는 한 번만 사용되는 불투명한 JSON 포장을 저장합니다. `custom:plugin-element` 기존 풍부한 스키마를 활용한 인라인 코덱 3. 스프레드시트는 익명 JSON을 네이티브 형태로 저장합니다. `ICellData.custom.docaElement` 기존 스키마 6과 공용 범위 명령 경로를 사용합니다. 전송 방식, 프로토콜 버전, 에포크, 체크포인트 식별자, ACK 수신 또는 신뢰할 수 있는 아웃박스에는 변경이 없습니다. 두 번째 JSON 자동 저장 또는 비즈니스 소유 콘텐츠 데이터베이스는 없습니다.

알 수 없는 유형과 정확한 봉투/데이터 버전은 지원되지 않는 플레이스홀더를 표시하며 원본 범위가 지정된 JSON을 유지합니다. 어떤 어댑터, 마이그레이션, 변환 또는 삭제도 제공되지 않습니다. 기존의 내부 참조 리더는 변경되지 않습니다. 네이티브 삽입/설정/삭제는 클립보드, 취소 및 공동 작업에 참여합니다. 설정 형태는 실시간 풍부한 범위나 안정적인 스프레드시트 단일 셀 앵커를 다시 확인하지만, 제거되거나 동시에 변경된 대상에서는 실패합니다. 캔버스 타이머는 보기 전용으로, 초당 최대 한 번만 실행되며 눈에 보이는 시간 지정된 셀이 그려진 후에만 예약됩니다; 숨겨진 페이지는 일시 중지됩니다. 렌더링/선택/잠재적 변경은 콘텐츠 시퀀스나 역사를 증가시키지 않아야 합니다.

독립형 자동화된 수락 기능은 기본적인 지속성 및 재로드, 불투명한 알 수 없는 페이로드, 풍부한 애트머스 삭제/undo/클립보드 기능, 시트 행 삽입/앵커/복사/삭제/undo 기능, 중복 ACK 재전송, 원격 에코 없이 두 개의 복제본이 통합되는 기능, 읽기 전용 거부 및 과도한 페이로드 롤백 기능을 포함합니다. 테스트에서는 사용자 문서를 편집하지 않습니다. 이 업그레이드는 보편적인 블록 지원, 모든 스프레드시트 작업, 형식 간 무손실 내보내기, 영구적인 오프라인 큐 또는 기본 장치 수용 기능을 제공하지 않습니다. 정확한 요소 필드와 한계는 저장소 소스에 있습니다. `docs/plugin-editor-elements.md`.

## 마크다운 부트스트랩 수정 — 2026-10-03

호스트는 전송된 Markdown 세션 팩토리를 호출하기 전에 권위 있는 체크포인트를 빈 리플렉스에 복원합니다. 더 이상 로딩 리플렉스에 로컬 메타데이터를 표시하지 않습니다: 미제출된 CRDT 클록 때문에 첫 번째 텍스트 업데이트가 서버에 없는 항목에 의존하게 되었습니다. 세션 상태 스냅샷은 동일한 문서/텍스트/인지/undo 객체를 유지합니다. 스키마, 에포크 또는 유지되는 포맷 어댑터의 변경 사항은 없습니다; 기존 대기 중인 편집은 보존되며 무음으로 변환되거나 삭제되지 않습니다.回归 수용에는 첫 번째 편집의 내구성 복원, 원격/bootstrap 에코 없음, 안정적인 상태 처리가 포함됩니다; 브라우저 검증은 격리된 문서에 대한 입력, 크로스인스턴스 업데이트, 재로드 및 대기 상태 검사까지 포함합니다.

## 리치 텍스트 다이어그램 앵커 — 2026-10-10

설치된 상태로 `@smartdoca/slate` 0.4.13에서는 호스트가 기존의 전체 블록 앵커를 사용하여 원본 플로우차트와 마인드맵을 캡처합니다.`kind:"block"`, 안정적 `blockId`, 그리고 현재 `epochId`). 서버 인용문은 승인된 노드 라벨이나 루트 주제에서 가져옵니다. 코멘트와 AI 참조는 전체 다이어그램을 대상으로 하며, 네이티브 스타일 수정 및 체크포인트 복구 후에도 유효하게 유지되며, 블록 삭제 후에는 해석을 중단합니다. 다이어그램 노드/엣지 ID는 영구적인 서브 다이어그램 코멘트 앵커가 아닙니다. 캡처, 선택, 하이라이팅 및 AI 참조는 문서 내용에 대해 읽기 전용으로 제공되며, 스키마나 계통 변화 없이 현재의 아웃박스와 전송을 사용합니다. 저장된 문서나 역사적 코멘트 변환은 도입되지 않습니다.

원본 0.2.7 localStorage 큐는 읽기 전용 상태로 유지되며 자동 재생되지 않습니다. 인식된 각 항목은 명시적인 연속 또는 철회 및 현재 설정이 필요합니다; 완전한 페이로드는 원본 ID와 소스 해시를 유지하며, 승인된 작업은 재전송 없이 조정됩니다. 업그레이드나 롤백 전에 전송을 중단하고 모든 오래된 웹사이트 페이지/확장 프로그램을 닫으세요: 혼합된 오래된/새로운 발신자들은 지원되지 않습니다. 왜냐하면 오래된 발신자들은 새로운 톰본스톤을 볼 수 없기 때문입니다. 롤백은 새로운 발신자를 중단시키고 두 개의 저장소, 톰본스톤 및 이후 데이터를 유지합니다; 오래된 전송을 복사하거나 자동으로 재시작하지 않습니다. 서버 테이블, 채팅/문서 기록, 권한 또는 편집기 체크포인트는 변환되지 않습니다. 정확한 규칙과 두 페이지/리프레시/실패/레거시 증거가 있습니다. ## 승인된 스프레드시트 크기 및 개인용 줌 — 2026-10-23

소유자는 기본 행 높이 21.78 CSS-pixel과 기본 열 너비 87.12 CSS-pixel을 명시적으로 승인했으며, 이는 10% 증가한 수치입니다. 새로운 호스트 워크시트는 이러한 값을 사용합니다. 저장된 기본 크기가 없는 역사적 첨부 워크시트와 가상 복구 워크시트도 새로운 표시 기본값을 사용합니다. 명시적인 기준선 기본값, 행/열 우회 설정, 원래 기준선 바이트 수, 워크시트 씨드, 체크포인트, 에포크 및 대기 중인 업데이트는 보존됩니다. 역사적 필드 백필링, 유지된 데이터 변환 또는 스키마 변경은 허용되지 않습니다. 이전 패키지로 돌아가면 이전에 누락된 필드 표시 기본값이 복원되며, 이후 수정 사항도 보존됩니다. 기존의 원본 수동 행/열 크기 조정 기능은 여전히 협업 가능하고 취소 가능합니다.

푸터는 여전히 100%로 기본 설정됩니다. 호스트는 원산지, 계정 및 문서에 따라 분리된 버전-1 브라우저 기록에 명시적인 네이티브 확대 설정을만 저장합니다. 이는 워크시트 전환을 포함한 전체 문서 범위의 표시 비율이며, 행/열 크기 재설정이 아닙니다. 기록이 없는 상태에서 열기하면 기록이 생성되지 않습니다. 알 수 없는 버전, 잘못된 기록 및 인식되지 않는 필드는 보존되며 덮어쓰지 않습니다; 저장에 실패하면 명시적인 설정은 마운트된 보기에만 남습니다. 익명 보기는 기록을 유지하지 않습니다. 롤백은 새로운 기록의 읽기/쓰기를 중단하고, 그 기록과 이후의 모든 콘텐츠를 그대로 유지합니다.

패키지는 기본적인 줌 렌더링과 콜백 기능을 갖추고 있으며, 호스트는 브라우저 저장소와 식별 정보를 갖추고 있습니다. 설정값 적용, 푸터 드래그, 플러스/마이너스 사용, 워크시트 전환, 읽기 전용 변경, 크기 조정 및 원격 프로젝션은 문서의 취소, 아웃박스, 콘텐츠 업데이트 또는 기록에 영향을 주어서는 안 됩니다. 개인용 줌은 내보낸 스냅샷이나 XLSX에 누출되어서는 안 됩니다. 이 정책은 설치된 패키지가 필요한 속성을 내보내는 증거가 아니라 합의된 경계일 뿐입니다; 통합 과정에서는 게시된 아티팩트와 격리된 두 페이지/브라우저 기록을 확인해야 합니다.

## 승인된 스프레드시트 필터 확장 — 2026-10-23

소유자는 열려 있는 상태에서 저장된 필터 범위를 유지하는 것을 명시적으로 승인했으며, 활성 조건이 확인될 때 기존 열의 마지막 콘텐츠 행까지 그 범위를 확장하고, 바로 아래에 추가된 연속적인 레코드도 자동으로 포함시킨다. 헤더, 열 경계선, 선택된 조건은 변하지 않는다. 스타일, 다른 열의 콘텐츠, 그리고 지우기 조건은 범위를 확장하지 않는다. 기본적인 범위 확장은 추가된 콘텐츠와 함께 하나의 공유 트랜잭션에서 작성되어야 하며, 되돌리기 단계도 필요하다. 원격 프로젝션 및 복구에서는 숨겨진 행을 생성하기 전에 작성된 범위를 적용해야 하며, 로컬 에코는 발생하지 않는다.

공식적인 Sheet 0.2.12은 기존의 schema-6 셀 및 안정적인 기능 레지스터를 사용하여 이 정책을 구현합니다. 편집기 스키마, 공개 API, 역사적 어댑터, 저장된 데이터 변환, DDL, 기준/에포크 교체 또는 대기 중인 업데이트 재작성은 포함되지 않습니다. 이전에 승인된 역사적 리더와 기본값은 변경되지 않습니다. 기존의 짧은 범위는 명시적인 확인을 통해서만 수정되며, 문서를 열어서 수정하는 것은 없습니다. 롤백은 저장된 네이티브 범위와 이후의 모든 콘텐츠를 보존합니다; 이전 패키지는 해당 범위를 읽을 수는 있지만 이후의 암시적 확장을 영구적으로 추가할 수는 없습니다.

Doca 0.2.11은 공식 npm Sheet 0.2.12를 배포합니다. 패키지 및 격리된 호스트의 승인은 프로덕션 배포와는 별개로 진행됩니다. 참조하세요. [필터 검증](verification/sheet-filter-range-2026-10-23.md).

## 댓글 배경의 실행 시간 경계 — 2026-10-28

시트 0.2.14 `commentHighlightAnchor` 그리고 Slides 0.3.0-alpha.5 `activeCommentId` 호스트가 제어하는 뷰 속성입니다. 호스트는 명시적으로 클릭된 권한이 부여된 현재 댓글만 제공합니다. 서랍을 열거나 링크 네비게이션, 네이티브 콘텐츠 마커를 클릭해도 댓글 배경이 활성화되지 않습니다. 다른 곳을 클릭하거나 해상도를 변경하거나 서랍을 닫으면 댓글 배경이 지워집니다. 댓글을 전환하면 기존 댓글 배경이 대체되며 다시 열어도 복원되지 않습니다. SDK는 모델을 작성하거나 영구적인 앵커, 트랜잭션, 취소, 존재, 아웃박스, 저장 기능을 사용하지 않고 비인터랙티브 배경에 기존 앵커 해상도/현재 지오메트리를 사용합니다. 캔버스 0.5.16의 table-port 가시성도 뷰 상태에 해당합니다. 이 경계는 앵커 형식이나 기존 삭제된 타겟 해상도 정책을 변경하지 않습니다. 알려지지 않은 스키마는 여전히 정확한 협상에 실패하며, 기존 형식의 리더나 변환 기능도 없습니다.
