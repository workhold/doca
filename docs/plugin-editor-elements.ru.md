# Элементы документации плагина (источник SDK 0.1.6)

Реализовано 2026-10-02 в хосте source 0.1.8, SDK 0.1.6, contracts 0.1.6 и Web registry 0.1.3. Это отслеживает экспорты из источника и изолированное приемление, а не публикацию через npm, установку в производстве или прием на нативном устройстве. Условленная политика хранения — поддержка точных версий: неизвестные типы и версии отображаются с placeholder-значением ошибки и сохраняются в своем оригинальном JSON-формате. Не вводится никаких адаптеров, автоматиченых преобразований, миграций или сброса данных. Существующие внутренние считатели документов остаются неизменными.

<a id="public-registration"></a>

## Общественная регистрация

Импорт `PluginElementContribution`, `PluginElementPayload`, `createPluginElementPayload`, `pluginElementState`, `isPluginElementPayload` и `validatePluginElementPayload` от `@smartdoca/plugin-sdk/editor-elements`. Возврат необязателен `elements` Из обычного установленного набора веб-плагинов. Хост регистрирует каждый вклад. `WebPluginRegistry.elements` Под именем пространства имен плагина-владельца и удаляет его с бандлом. Дублирующиеся и некорректно объявленные идентификаторы приводят к неудачной регистрации и отмене регистраций бандла.

```ts
import type { PluginElementContribution } from "@smartdoca/plugin-sdk/editor-elements";

// Return this contribution from the injected Web plugin factory.
const element: PluginElementContribution = {
  id: "example.elements.countdown", pluginId: "example.elements",
  title: { zh: "倒计时", en: "Countdown" }, dataVersion: 1,
  formats: ["rich_text", "spreadsheet"],
  validate: data => typeof data.targetAt === "string" &&
    Number.isFinite(Date.parse(data.targetAt)),
  text: data => `Countdown: ${data.targetAt}`,
  renderEditor: context => /* injected React configuration form */ null,
  render: (payload, context) => /* injected React inline view */ null,
  renderCell: context => { /* draw within context.rect using context.canvas */ },
  refreshIntervalMs: 1000,
};
```

Это заявление иллюстрирует экспортируемые сигнатуры; [независимый пример](../examples/plugin-elements/README.md) Включает рабочие формы, рендеры и файлы установки. Плагины используют вставленный хост React и собирают свои собственные зависимости. Они не должны импортировать пути исходного кода хоста или использовать глобальные соединители редактора.

Каждый вклад требует локализации. `title`положительное целое число `dataVersion`по крайней мере один поддерживаемый формат `validate`, `text` и `renderEditor`. `rich_text` требует `render`; `spreadsheet` требует `renderCell`. Опционально `onCellClick` получает полезную нагрузку и публичный контекст. Опционально `refreshIntervalMs` Это целое число от 1000 до 60000, и оно только обновляет видео на холсте.

Контекст содержит `documentId`, `format`, `locale` (`zh` или `en`), `readOnly` и один `AbortSignal`Форма контекста также предоставляет клонированные данные. `initialData` или ноль, `submit(data)` и `cancel()`Контекст холста предоставляет клонированный объект. `payload`Холст и обрезанный прямоугольник ячейки. Настройки передаются через хост; плагины не получают изменяемый управляющий объект редактора, личный рантайм или независимый канал сохранения данных. Ошибки рендеринга создают локализованный заменитель. Плагины самостоятельно обрабатывают свои события/асинхронные ошибки и отменяют работу, когда сигнал прекращается.

<a id="stored-content"></a>

## Хранящийся контент

```json
{
  "version": 1,
  "pluginId": "example.elements",
  "type": "example.elements.countdown",
  "dataVersion": 1,
  "data": { "label": "Launch", "targetAt": "2026-10-04T00:00:00.000Z" },
  "text": "Launch · 2026-10-04T00:00:00.000Z"
}
```

`version` это версия в конверте; `dataVersion` Это точная версия данных вклада. `data` Содержит простую конфигурацию в формате JSON. `text` Это ограниченная статическая проекция для текстовых потребителей. Не сохраняйте функции рендеринга, учетные данные, временные URL-адреса, значения, изменяющиеся с таймером или таймеры. Непрозрачные полезные данные должны представлять собой простые объекты JSON, максимум 32 КиБайт UTF-8, глубина 20 и 4096 узлов. Небезопасные ключи прототипа и нефинальные/не-JSON значения отклоняются перед сохранением.

Текущий распознаватель конверта принимает только шесть объявленных полей. Структурно корректный неизвестный конверт, неустановленный/отключенный поставщик, неизвестный тип, неподдерживаемый формат или несоответствующая версия создают неподдерживаемый placeholder. Текущий поставщик, отклоняющий конфигурацию, создает недействительный placeholder. Любое из этих условий не изменяет или не удаляет данные. Хост не вызывает рендерера или редактора конфигурации несоответствующего поставщика. Пользователи могут явно удалить неподдерживаемый элемент через нативное редактирование и отмену этого удаления. Повторное активация точного поставщика может снова отобразить сохраненную конфигурацию.

<a id="native-editor-integration"></a>

## Интеграция с родным редактором

- Форматированный текст использует одно постоянное внутристроковое расширение атомного формата. `custom:plugin-element`И его общий кодек. Его кодек хранит весь непрозрачный полезный набор данных даже без загрузки плагинов. Вставка захватывает живой диапазон Slate, а редактирование находит узел по идентификатору. Вставка/конфигурация/удаление используют нативные операции и нативный отмена. В этом релизе поддерживаются встроенные атомы; произвольные разметки блоков не экспортируются.
- Электронная таблица использует публичный ресурс `cellRenderers` расширение холста `custom.docaElement` на родном языке `ICellData`Клетка `v` Это статическое проектирование текста. Коммиты вставки/конфигурации сохраняют текущий стиль ячейки и устанавливают встроенное оборачивание текста на CLIP, чтобы проектирование не перекрывало соседние ячейки. Вставка заменяет значение/формулу/форматированный текст/пользовательские данные выбранной ячейки, как это явно указано в диалоговом окне. В тексте ячейки нет плавающих объектов или встроенных позиций. Стабильный анкер одной ячейки сохраняется при изменении строк/столбцов, пока форма открыта; удаленная или одновременно изменяемая целевая ячейка не может быть отправлена. Встроенные команды диапазона предоставляют копирование, удаление, отмену и совместную работу.
- Завершение диалога, изменение контекста редактора или выход из режима редактирования отменяют сессию. Подача снова проверяет активного поставщика, обработку, состояние читабельности и целевой объект. Изменения в рендеринге/регистре не перезагружают редактор документа. Обновление видимости плагина не вызывает записи документа.

Существующий слой Rich 3 и слой электронной таблицы 6 сохраняют свои встроенные контрольные точки и надежную совместную работу. Не существует второго автоматического сохранения JSON, транспортировки, линии повторного воспроизведения Yjs или базы данных бизнес-плагина для содержимого элементов. Встроенные контрольные точки и клипборд того же типа сохраняют полезные данные; ограничения преобразования текста/Markdown/Office по-прежнему действуют. Экспорты Rich Atomic ухудшаются до меток с существующим предупреждением о преобразовании; пользователи электронных таблиц могут читать статическое значение ячейки. Экспорт чистого текста не является без потерь резервной копией плагин-элемента.

<a id="lifecycle-installation-and-rollback"></a>

## Цикл жизни, установка и возврат к предыдущему состоянию

Ни один поставщик элементов не установлен по умолчанию. Плагины можно обнаружить только через существующий директорий установки или механизм ZIP. Текущий пример manifestа требует SDK. `^0.1.7`Опубликовать/установить SDK и хост, содержащий этот улучшение, перед независимым использованием в производстве. Серверный фабрикат не владеет данными бизнеса, а удаление не удаляет содержимое документов.

Отключение/удаление плагина отменяет регистрацию рендеров, но не элементов, сохраненных в базе данных. Перезапуск поставщика, совпадающего точно с первоначальным, не требует конвертации данных. Возврат к более старому хосту, не имеющему постоянного нативного кодека, не поддерживается для редактирования этих документов; необходимо сохранить резервные копии базы данных/контрольной точки и использовать хост-сервер для доступа к ним. Не предусмотрено никаких изменений, снижения уровня или разрушительной очистки.

## Принятие

Изолированные тесты `tests/plugin-editor-elements.test.ts` Обработка владения реестром, его удаления или возврата, строгие версии и ограничения JSON, полноценный атомарный буфер клиппинга/удаления/обратного действия, непрозрачные циклы CRDT, нативная сохранность данных/пересдача ACK/поведение без эхо в двух репликах, стабильные анкеры таблицы/вставка строк/копирование/удаление/обратное действие/перезагрузка/конвергенция, читабельное авторизация и атомарное отклонение перегруженных данных. Они создают изолированные базы данных и документы. Скрипт проверки SDK также проверяет независимого потребителя деклараций JavaScript и NodeNext в пакетном стиле без хост-путей.

Приемка браузера использует изолированную базу данных и временное установление независимого примера отсчета/новостей. Реальные нативные контейнеры и плагины третьих сторон требуют своей собственной приемки. Общие блоковые элементы, без потерь экспорт в различные форматы и публичные произвольные команды модификации редактора остаются задачей на будущее.

Проверенные операции браузера включают в себя вложенные вставки/конфигурацию/отмену/перезагрузку/чтение только в режиме чтения, конфигурацию листа/вставку/отмену/перезагрузку/чтение, а также placeholder неизвестного типа с возможностью только удаления. Проекция листа была проверена после сохранения и перезагрузки. Окончательная комбинированная проверка: TypeScript прошел; 171 тестовый файл прошел (1,066 тестов пройдено, 3 пропущено); сборка SDK и независимое использование прошли; сборка для веб-продакшена и проверки пробелов прошли.

## Приемка результатов работы (2026-10-02)

Бегать `node --import tsx scripts/benchmark-plugin-elements.mts`На этой машине macOS arm64 с Node 24.15.0 среднее время проекции 1,000 обычных абзацев составило 0,513 мс с использованием двух оригинальных встроенных кодеков, а 0,515 мс — с добавлением элементного кодека. Сопоставимый средний разница находилась в пределах шума измерений. Проверка элементов для 10,000 занятых ячеек стоила 0,039 мс; при 100 настроенных элементах — 0,111 мс. Первое тестирование 100 пейлайнов с отсчетом времени заняло 0,188 мс, а клонирование и вызов 100 примеров кallbackов холста — 0,101 мс. Бенчмарк с использованием callbackа использует макет холста и не измеряет нативное рисование.

Обычные ячейки выходят после проверки пользовательской свойства. Расширенная валидация сохраняется в памяти, а валидация холста сохраняется для каждого полезного наклада/провайдера и отменяется при изменениях реестра. Один таймер видимой ячейки слияния активируется только при рисовании видимой ячейки с таймером, с минимальным периодом в 1 секунду. Скрытые страницы отменяют его. Лист без видимых ячеек с таймером не имеет периодического таймера обновления. Тестирование планировщика охватывает нулевые таймеры ожидания, слияние 100 элементов, покидание окна просмотра, скрытие и уничтожение. Наблюдение браузером за документами с тиком в течение более 60 секунд ожидания не показало нового содержимого или истории; таймеры никогда не попадают в область сохранения.

Эти измерения показывают, что добавляемая нагрузка на процессор хоста незначительна для протестированных случаев. Они не гарантируют нулевой затраты для произвольного третьестранного рендеринга, внешнего получения данных, большого количества видимых элементов или любого устройства. Провайдер продукции должен проверить собственную нагрузку рендеринга/асинхронного выполнения задач.
