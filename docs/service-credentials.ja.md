# プラットフォームサービス認証情報

[中文](service-credentials.zh-CN.md)

管理画面 → プラットフォーム設定 → サービス認証情報を開きます。現在のホスト管理型プラットフォーム記録には以下が含まれます：

- アイデンティティ：SSOクライアントシークレットと許可されたHTTP(S)オリジンを指定する。アイデンティティプロバイダーとは認証情報の名前を指す。
- 検証ゲートウェイ：HTTP(S)エンドポイント、ベイヤーシークレット、および電話/メールチャネル。
- 文書検索：Meilisearch APIキーと許可されたオリジン。

ファイルのサーバー認証情報とCloudFront署名キーは、単に設定されるだけです。 `DOCA_FILE_STORES_JSON`ストレージ管理ページは読み取り専用です。このプラットフォームレコードでは編集できません。 [プラグイン認証情報](plugin-credentials.ja.md) 個別のサーバー専用暗号化サービスとそのデプロイメントマスターキーを使用する。

<a id="persistence-and-configuration-precedence"></a>

## 持続性と設定優先順位

プラットフォーム設定は下に保存されます `account_settings`、ID `service-credentials`既存のコードは、このレコードが存在しない場合にのみ実行環境からアイデンティティ/メッセージング設定をセットします。その後は保存されたレコードが優先されます。環境変数を変更しても保存された設定は上書きされません。これは既存の初期化手順であり、新しいアダプターやマイグレーションなしでここに保持・記録されています。廃止されたストレージ形状を含む保存されたレコードは、現在のホストによって明示的に拒否されます。

データベース接続、サイトのオリジン、リスニングポート、ファイルストレージは起動設定として残っています。永続化された設定を読み取る前に、データベースが接続されている必要があります。最初の管理者は依然として明示的なブートストラッピングコマンドを使用しています。

<a id="api-and-secret-handling"></a>

## APIとシークレットの管理

`GET` / `PUT /api/v1/admin/service-credentials` システム管理者が必要です。変更はOriginを検証します。GETメソッドでは、設定されたシークレットがnullに置き換えられます。PUTメソッドでは、nullは既存のシークレットを保持し、空文字列はそれを消去します。偽のマスキング文字列を送信しないでください。レビューチェックにより、同時の上書きが防がれます。監査データにはシークレット値ではなくアクションが保存され、エンドポイントプロトコル、Origin、リダイレクトの制限は保持されます。

サーバーは利用可能なサードパーティの認証情報を保持する。データベースとバックアップを重要な設定として扱う。保存されたシークレットは、一般ユーザー、公開のブートストラッピング、エラーログ、または管理者のGET応答には返されない。プラグインの認証情報暗号化は、これらのプラットフォーム設定を自動的に再暗号化するものではない。

各サービスプロセスはAPIリクエスト前に設定のバージョンを確認し、変更後は再起動せずにアダプターを更新します。検証シークレットを変更すると、保留中の検証チャレンジが無効になります。ストレージ認証情報の変更はデプロイメントによって行われます。 [保管規則](storage.ja.md)安定したストアIDと参照されるバイトの保持を含む。
