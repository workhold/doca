# Doca 外掛 SDK 與核心邊界

當前原始碼使用 SDK **0.2.0**，AI 服務為 `ai.v2` / `ai.continuations.v2`。工具上下文始終提供 `jobId`，只有真實聊天執行才提供 `sessionId`。外掛須重新構建並宣告 `sdkRange: "^0.2.0"`；舊 SDK 範圍和舊 AI 服務契約直接拒絕，不提供適配。本次原始碼變更不代表 npm 釋出或部署。參見 [MCP 執行隔離](mcp.zh-Hant.md#执行记录与升级)。

SDK 不相容或必需依賴不可用只隔離受影響的業務外掛，宿主與其他外掛繼續啟動；管理頁顯示不可用原因和升級提示。原安裝意願、歸檔、業務資料和憑據保留，不轉換舊包或執行舊 SDK 程式碼。新線上安裝仍拒絕不相容包。停機放入的完整安裝目錄按原始身份儲存後做相同隔離。


0.1.26 使用與核心庫分開的[外掛共享業務資料庫](plugin-database-isolation.zh-Hant.md)，自動建立外掛名稱空間，取代 0.1.25 的每外掛獨立庫。升級須先在舊宿主正常解除安裝，再重灌，不遷移外掛資料。

## 已實現的託管儲存

`@smartdoca/plugin-sdk/storage` 已匯出安裝身份繫結的 `pluginDatabaseToken`（`storage.sql.v1`）和 `pluginObjectStorageToken`（`storage.objects.v1`）。關係庫支援顯式 version 1 結構宣告、text/int32/雙精度列、主鍵/唯一約束、結構化查詢/寫入/刪除，以及回撥只執行一次的事務。SDK 原始碼 0.1.8 另匯出 `pluginCredentialToken`（`storage.credentials.v1`），提供服務端加密憑證 CRUD、後設資料與修訂號檢查，見[憑證介面](plugin-credentials.zh-Hant.md)。聯表、外來鍵、通用 SQL、upsert 和臨時工作區尚未匯出。業務 SQL 使用與核心庫分開的宿主管理共享資料庫：SQLite 一個檔案、按外掛加表名字首；PostgreSQL 一個 URL／賬號、自動建立外掛 schema，共用連線池。程序隔離仍未實現，見[儲存配置與先解除安裝再升級約定](plugin-database-isolation.zh-Hant.md)。

邏輯庫為 `plugin:<pluginId>`，使用者檔案歸屬及私有物件使用 `plugins/<pluginId>`，發行包使用 `host/plugin-releases/<sha256>.zip`。ZIP 位元組進入環境變數配置的檔案儲存，共享資料庫只儲存 version 2 清單、歸檔引用和可信檔案雜湊索引。有效快取無需重新下載 ZIP。全部例項由運維逐個重啟。不支援的外掛包和儲存格式拒絕自動轉換，原資料保留。核心資料庫升級另遵守[資料庫升級規範](database-schema-evolution.zh-Hant.md)。詳見[準確實現與限制](unified-storage-implementation.md)。

## 1. 決策

外掛資料庫託管、名稱空間隔離、使用者/內部/臨時檔案儲存與多例項執行按已確認的[水平擴充套件規範](plugin-horizontal-scaling.zh-Hant.md)執行。安裝包必須宣告 `doca.storage: "host"`，缺失或其他值於匯入程式碼前拒絕；本地/遠端後端僅由宿主選擇。託管 SQL 與內部物件已匯出；憑證在 SDK 原始碼 0.1.8 匯出，臨時工作區仍列為實現缺口。

Doca 保留文件產品核心和通用平臺服務；獨立業務透過安裝目錄發現。郵件、日程、會員、收費、用量控制、內容稽核不作為宿主必裝業務。

外掛開發時依賴獨立釋出的 SDK/能力契約包，執行時注入宿主實現。禁止依賴 Doca 工作區路徑、宿主私有模組、全域性變數橋接或宿主私有表。宿主也不得匯入業務外掛原始碼或識別特定業務外掛 ID 才能完成公共流程。

外掛執行在可信服務端程序內。這是擴充套件介面邊界，不是 Node.js 安全沙箱。安裝目錄獨立於程式釋出目錄；宿主只載入宣告當前 SDK 範圍、且資料庫符合當前基線的外掛。

## 3. 安裝與發現

共享宿主資料庫儲存全站外掛期望清單、不可變歸檔引用和逐檔案雜湊索引；完整 ZIP 位元組儲存在環境變數配置的統一檔案儲存。每個例項啟動時同步獨立的 `DOCA_PLUGINS_DIR`（預設 `<data-root>/plugins`），逐檔案校驗並從共享歸檔補齊缺失或損壞檔案，再載入外掛。啟動不訪問商店、不安裝依賴、不編譯 TypeScript。

「管理 → 外掛商店」支援官方源、本地上傳、升級、啟用、禁用和解除安裝。預設商店為 `https://store.smartdoca.cc`，透過 `DOCA_PLUGIN_STORE_URL` 覆蓋。寫操作檢查修訂號，每個例項重啟生效。頁面區分全站目標與當前響應例項的執行狀態，不承諾熱解除安裝。

預構建包在 package.json 宣告 `doca.manifest`、`doca.server`、可選 `doca.web`、必填 `doca.dataVersion` 和 `doca.storage: "host"`。所有安裝來源和啟動歸檔恢復在解析/匯入服務端入口前檢查儲存宣告，缺失或其他值直接拒絕，不轉換。SDK 範圍、路徑、依賴圖、雜湊和精確結構也須校驗。已安裝升級要求 dataVersion 不變。當前解除安裝呼叫必需的業務清理鉤子，成功後清標記；宿主已清理託管私有狀態並使舊代次失效；叢集業務任務排空仍待實現。 當前私有庫/物件解除安裝已在清單事務中執行 generation 隔離與持久化物件清理；業務任務叢集排空仍未實現，所有例項需人工重啟。

停機後放入 `<install-root>/<plugin-id>/` 的本地目錄，在啟動時釋出到全站清單並移入 `.imports/`。執行檔案位於 `.releases/<sha256>/`。不支援舊的根目錄 npm 清單或原始碼連結載入。程式檔案與業務資料分開；安裝不修改宿主原始碼、package.json 或 Vite 配置。

包佈局、遠端介面、限制與多例項語義以 [商店協議](plugin-store-protocol.zh-Hant.md) 為準，重啟和故障處理見 [部署說明](plugin-deployment.zh-Hant.md)。

## 4. 公共 SDK 與生命週期

現有 `@smartdoca/plugin-sdk`、`@smartdoca/files-capability`、`@doca/documents-capability` 等作為公共契約的基礎。契約包必須能獨立打包、釋出和安裝，禁止 `../../other-package/src` 形式的跨包匯入。消費者不依賴 Provider 實現包；服務 token 與型別放在對應公共契約的匯出中。

生命週期保持：

```text
扫描静态元信息 → 校验依赖 → 导入代码
→ discover → 必需服务检查 → initialize → mount → ready
→ 停止接收请求/排空任务 → 逆依赖顺序 dispose
```

服務按穩定字串 ID 和版本識別，不依賴 token 物件引用相等。宿主預先提供平臺服務；業務外掛只能註冊自己名稱空間的服務，不允許注入 doca.server.* 等私有宿主服務。每個服務 ID 只能有一個 Provider，多貢獻能力使用 registry。

每次註冊返回 disposer，由 context effect 管理。服務、任務、事件訂閱和 UI 註冊屬於具體宿主例項，禁止 `globalThis`、`Symbol.for` 儲存業務例項。一個程序建立兩套測試應用必須互不影響。

## 5. 使用者資訊與請求上下文

HTTP 請求、AI 工具和後臺任務使用同一來源可信的執行上下文。目標欄位包括 requestId、principal、pluginId、signal，以及可選 sessionId、turnId、jobId、callId。身份由宿主認證或持久任務授權生成，不能從外掛 HTTP body 直接構造使用者身份。

“完整使用者資訊”定義為服務端可用的業務資料：穩定 ID、公開 ID、登入名、暱稱、頭像、狀態、管理員標記、已驗證聯絡方式、資料欄位、自定義業務欄位和允許讀取的身份關聯元資訊。欄位是否返回遵循顯式的服務端讀取用途與許可權。普通搜尋結果仍採用最小展示投影。

使用者物件不包含密碼雜湊、會話 token、驗證碼、OAuth token、模型 API key 或儲存金鑰。需要呼叫外部服務時注入對應能力，不把憑據塞入使用者 DTO。服務端能讀取的完整資料也不得直接返回瀏覽器或自動加入模型提示詞。

提供持久使用者建立/資料更新/狀態變更事件。當前無使用者刪除業務入口，使用者刪除生命週期與非同步清理協議屬於後續設計。外掛後臺任務執行時重新檢查使用者狀態和資源許可權，使用者停用後不能靠舊任務快照繼續獲得訪問權。

未來刪除流程由宿主持久記錄刪除請求和參與外掛：標記刪除中並撤銷訪問 → 外掛冪等清理及確認 → 彙總結果並完成刪除。必須覆蓋停用、已解除安裝或不可用外掛，支援重試、錯誤展示及有審計的人工處理；超時不能記為清理成功，也不能僅向當前載入外掛廣播。該流程不使用跨資料庫兩階段提交，不阻塞當前郵箱首版；在開放使用者刪除入口前必須完成驗收。

## 6. 許可權複用與使用者交集

<a id="_61-资源授权"></a>
<a id="61-资源授权"></a>

### 6.1 資源授權

統一資源引用為 `(pluginId, resourceType, resourceId)`。外掛註冊自己的資源授權器，宿主統一呼叫。檔案服務和文件服務始終保留自身 ACL，外掛註冊成功不產生讀取使用者檔案的特權。

外掛定義業務動作及角色對映，例如 mailbox.read、mailbox.send、calendar.edit；不能把所有外掛動作強制等同文件 editor。資源授權器缺失、外掛停用或授權結果不確定時拒絕訪問。正文讀取、附件下載、AI 工具、搜尋 hydrate 均需複核。

<a id="_62-用户目录"></a>
<a id="62-用户目录"></a>

### 6.2 使用者目錄

宿主保留管理員配置的 all / related / none 規則以及現有管理員設定的單使用者覆蓋。related 的候選集合由內建文件/檔案來源與活動外掛交集來源合併，之後仍由宿主過濾使用者狀態、欄位可見性和分頁。none 不呼叫外掛放寬規則。

交集來源提供“哪些站內使用者因何種受權業務關係可被發現”的事實。共享郵箱成員、共享日曆成員可以構成交集；收到陌生郵件、同域郵箱、郵件正文出現使用者名稱不自動構成交集。外掛不能自行寫管理員目錄策略。

來源協議須支援 source ID、schema version、候選批次/遊標、關係 ID、版本，以及針對候選的當前事實複核。宿主不得為擴充套件一個業務而給 directoryIds 增加郵件/日程專用 SQL。

需要記錄的關係含 ownerPlugin、relationId、參與使用者、型別、有效狀態/有效期。對於“曾經互動”的持久關係與“當前共享”的可撤銷關係，來源須明確語義；當前共享撤銷必須失效，歷史關係只能在管理員策略允許且確有成功許可權互動時參與。預設採用當前有效關係，不能把撤銷共享永久變成可搜尋關係。

大量關係由外掛自己的索引和 outbox 維護，不在使用者搜尋中全表掃描外掛資料庫。過期候選返回前複核；來源故障不擴大搜尋範圍。停用外掛立即移除其來源，保留的歷史投影不再參與查詢。重新啟用時先校準版本與有效關係。

可搜尋到使用者不授予任何業務資源許可權，也不自動暴露使用者全部資料。相同使用者多來源去重後再分頁，不能依靠過濾前的總數洩露隱藏使用者。

## 7. 檔案、外掛資料與事務

外掛透過注入的 files.v1 操作 Doca 資料夾和檔案，儲存穩定 ID。附件繫結使用 `(ownerPlugin, ownerType, ownerId, role)`，禁止私建與 Doca 隔離的附件儲存或儲存臨時簽名連結為永久引用。

owner binding 是資源歸屬事實，不等於訪問授權。透過郵箱讀取附件時必須複核郵箱及繫結許可權；直接訪問原檔案仍遵循原檔案 ACL，不能透過繫結公開他人的私有檔案。

業務持久化全部由宿主管理。外掛定義表、索引、任務/outbox 語義和授權，不選擇後端、不直連資料庫、不向系統目錄持久化。邏輯庫名為可信安裝身份繫結的 `plugin:<pluginId>`。使用者檔案走 files.v1，內部二進位制、憑證和臨時工作使用對應宿主能力；託管 SQL/內部物件/憑證/工作目錄 API 中 SQL/內部物件已匯出，憑證在 SDK 原始碼 0.1.8 匯出，工作目錄未匯出；data.v1/data.v2 不可用。能力缺失不能以自管儲存替代。實際結構精確匹配，不隱式轉換或回退舊資料。託管儲存清理由宿主跨例項協調，不由外掛刪除磁碟目錄。 當前私有庫/物件解除安裝已在清單事務中執行 generation 隔離與持久化物件清理；業務任務叢集排空仍未實現，所有例項需人工重啟。

跨資料庫和檔案服務採用冪等、補償和校準，不承諾共同事務。關係投影亦由外掛儲存，目錄來源只提交有效交集事實。

<a id="71-文件创建持久幂等"></a>

### 7.1 檔案建立持久冪等

`files.v1.folders.create` 和 `files.v1.files.create` 已支援可選 `idempotencyKey`（非空、最多 200 字元，不含控制字元）。作用域為安裝邊界注入的外掛 ID、當前使用者和操作型別；外掛不能透過請求欄位指定其他外掛身份。同鍵同引數返回第一次建立的結果快照，同鍵異參丟擲 409。檔案/資料夾記錄與 completed 回執在同一資料庫事務提交。回執不自動過期，禁用、解除安裝不刪除回執；刪除結果後重放返回 404，不重建檔案。重放與查詢均重新校驗當前賬號和結果的寫許可權。

上傳完成返回 `contentIdentity: {sha256, size, mime}`。上傳方式的冪等建立必須傳此欄位，宿主校驗實際上傳位元組；請求指紋包含目標目錄、名稱和內容身份，不包含臨時 uploadId。上傳狀態仍在記憶體，重啟後可重新上傳相同內容，以新 uploadId 和原操作鍵繼續。複製方式用 sourceFileId 標識來源，不需要 contentIdentity。外掛必須把操作鍵、業務引數和內容身份存入自己的 outbox，不能用每次變化的請求 ID 替代。

`files.receipts.get(context, {operation: "file.create" | "folder.create", key})` 返回 null（沒有持久回執）或 `{status: "pending" | "completed", operation, result}`。pending 的 result 為 null，表示可使用原引數重試，不表示仍有任務執行；completed 返回歷史結果快照。響應未知時先查回執，再重放原建立請求。失敗不偽造成功回執；資料夾失敗隨事務回滾，上傳建立可能保留 pending 意圖。

宿主先持久預留物件 ID 和儲存配置，再寫位元組；資料庫提交前失敗後使用同一路徑恢復。本地寫使用原子替換，S3 使用完整物件寫入。啟動及每小時分批迴收已完成意圖的備用物件、超過 24 小時未完成意圖的位元組及臨時檔案。回收與上傳重試持有同一資料庫使用者鎖，並校驗物件引用；已註冊物件不作為預留垃圾刪除。回執及 pending 物件位置保留，重試可以重新上傳。郵件傳送冪等和業務補償由外掛定義，透過宿主能力持久化；託管資料庫清理歸宿主。

### 7.2 搜尋與外部知識

使用 `@smartdoca/plugin-sdk@^0.1.9`。從 `@smartdoca/plugin-sdk/content` 匯入 `contentServiceToken` 与 `ContentSource` 型別，在 `injections.required` 宣告服務，並在 mount 中註冊來源。來源歸屬註冊它的外掛；內建文件和檔案也使用這套契約。

| 成員                                          | 契約                                                                                                                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 來源宣告                                      | `id`、`pluginId`、`version: 1`、中英文 `title`、`contentTypes`、`purposes`、`capabilities: {search}`、`configSchema`                                                       |
| `list(ctx, {config, cursor, limit})`          | 必需。返回 `{items, nextCursor, snapshot}`。每項含 `ref: {sourceId, resourceId, blockId}`、`fingerprint`、`title`，可選 `order`、`anchor`、`excerpt`；此處不返回完整正文。 |
| `read(ctx, {config, ref, fingerprint})`       | 必需。重新鑑權後返回清單項及 `text`，不可用返回 null；指紋變化報衝突，不能在舊指紋下返回新正文。                                                                           |
| `resolve(ctx, ref)`                           | 必需。重新鑑權並返回 `{path, fingerprint}` 或 null；path 是當前可開啟的站內位置。                                                                                          |
| `search(ctx, {config, cursor, limit, query})` | 可選，宣告與實現必須一致。返回輕量分頁結果；不支援時宿主不會自動全量掃描代替。                                                                                             |

`ctx` 包含宿主認證的 `principalId`、`purpose`（knowledge、analysis、search）和取消訊號 `signal`。來源每次呼叫都檢查當前業務許可權。宣告 analysis 的來源可供未來待辦外掛分析，不需要郵箱專用查詢介面。消費方先呼叫 `sources(ctx, purpose)`，再呼叫服務的 list/read/search 並傳入 sourceId、purpose；服務 resolve 接受 `{ref, purpose}`。只能使用來源已宣告的用途。

分頁從 null 開始，以 nextCursor=null 結束；同一輪所有頁必須屬於一致的 snapshot，過期就失敗，不能靜默切換資料繼續。這是遍歷當前有權訪問的全量清單所用的分頁遊標，不是持久增量日誌。本契約不要求、也不匯出 listChanges/readChanges。外掛可自行同步業務系統，但宿主不規定它的內部同步實現。

知識庫複用現有訂閱與排程體系，由使用者明確選擇來源、知識庫和配置。宿主儲存引用與分塊指紋，完成清單核對後僅拉取和分析新增、變化的正文，不額外存一份完整來源正文映象；未變化的塊不重複讀取。只有完整、一致的清單才能認定刪除，失敗或不完整的遍歷不能確認刪除。塊身份不能依賴整篇文件的修訂號或段落位置序號。

原內容刪除、解綁、撤權或來源不可用時，派生知識暫停普通使用者的新讀取、列表展示、搜尋及回答檢索，保留內容供管理員處理，人工編輯過的結果也遵循此規則。已送達的內容不會被追回，已開啟的協同連線也不在即時斷開的承諾內。配置介面支援基礎欄位、列舉和字串陣列；複雜配置由外掛介面處理。本次沒有資料庫結構遷移、雙讀雙寫或舊來源適配。SDK 仍匯出 knowledge.sources.v1，但新接入使用 content.v1，舊註冊不會自動變成新訂閱。

限制：每頁 100 項、每輪清單 100,000 項、單塊正文 200 萬字元、每輪分析變化正文 120,000 字元、來源呼叫 20 秒超時。超限或不完整時明確失敗，不能截斷後宣稱完成。HTTP 入口為 `/api/v1/content/sources` 与 `/api/v1/content/{list,read,resolve,search}`；詳細請求及訂閱路由見[內容協議](plugin-content.zh-Hant.md)。

## 8. AI 工具、skill 與用量

當前原始碼 Web SDK 的 `PluginWebHost.ai.open` 支援攜帶提示詞/普通文字上下文、授權文件/檔案、可選已有會話和模型啟動個人助手，僅顯式指定時立即傳送。複用宿主現有會話、訊息和執行策略，不新增儲存遷移或舊宿主適配。詳見[啟動契約](plugin-assistant.zh-Hant.md)。這是客戶端介面能力，不是服務端 AI 執行服務；npm 和原生生產可用性尚未核實。

外掛可註冊 tool、skill、intent、workflow、結果 renderer 和驗收器。工具有名稱空間 ID、輸入/輸出 schema、執行器和許可權要求；skill 是外掛包內的版本化內容，不是繞過工具授權的執行通道。

外掛工具獲得受權使用者資料和 AI 呼叫上下文，包括 session/turn/job/toolCall、模型標識、引數、取消訊號與允許使用的資料引用。任意使用者歷史會話和全部提示詞不作為預設工具上下文。Chat 與 MCP 複用同一授權和工具執行管線。

MCP 已透過同一執行器及當前使用者/准入校驗開放宣告 `mcp` exposure 的已安裝工具，官方、外掛及已啟用個人 SKILL 按服務授權和目標使用者過濾。個人與公司服務配置屬於宿主，不新增 SDK 匯出，也不允許外掛引用宿主原始碼路徑。詳見 [MCP 服務](mcp.zh-Hant.md)。

### 8.1 宿主只記事實

核心取消會員等級、積分、貨幣價格、贈送額度和按等級篩選模型。宿主保留模型可用配置、技術性超時/併發/上下文上限，以及按使用者、模型、外掛、任務、呼叫維度查詢的原始用量。每個模型同時配置輸入、輸出 Token 折算速率；圖片生成配置每張圖片折算的 Token。該速率用於把不同廠商和模態統一為可累計的 Token 用量，不表示幣種或最終售價。

每次實際 provider 嘗試具有獨立 callId 和 attemptId。記錄輸入、輸出、快取讀取、快取寫入、推理、音訊/影象等 provider 支援的細分 token，以及影象張數等非 token 單位。未知值為 null，並儲存脫敏原始 usage；不能編造為 0。

標準化賬本必須說明 provider 各欄位的包含關係：快取或推理可能已包含在輸入/輸出總量中，彙總不能重複相加。結算時把呼叫開始時的速率快照固化；對話按輸入量 × 輸入速率與輸出量 × 輸出速率分別折算，圖片只按成功張數 × 每張 Token 折算，不再疊加廠商返回的影象輸入/輸出 Token。使用者介面與 `ai.usage.recorded` 對外事件展示折算後的用量，同時賬本保留廠商原始指標供審計。取消、失敗、重試、流中斷和用量缺失都有明確狀態；預估與實際量分開，持久記錄冪等，外掛重放不重複計量。

僅經過宿主 AI 執行服務的呼叫能保證統一計量；外掛自行直接請求 provider 的行為不計入宿主完整性承諾。外掛需要模型能力時應複用宿主執行服務。

<a id="_82-用量控制属于插件"></a>

### 8.2 用量控制屬於外掛

提供執行前和執行後的擴充套件：呼叫前提供使用者、模型、任務、預估上限並允許策略拒絕或預留；呼叫完成後提交實際 usage 與結果。會員外掛負責餘額、額度、週期、定價及扣費。

控制外掛必須能在自己的事務中原子預留，返回冪等 reservation ID；完成/失敗釋放或結算透過持久事件重試。單純“先查餘額、呼叫後再扣”不能作為併發額度控制。外掛接收用量事件失敗不抹去宿主賬本，重放依據 callId/attemptId 去重。

通用 policies.v1 同時覆蓋文件建立、檔案上傳、分享等操作，返回允許/拒絕及穩定原因碼；預設無商業約束。資源 ACL、賬號狀態、請求大小和執行安全上限不能被策略外掛放寬。策略異常不能被吞掉後放行；被配置為必需的控制外掛缺失時，相關操作應不可用並明確報錯。

## 9. 頁面、導航及後端擴充套件

業務外掛可以貢獻全域性導航項、自己的目錄樹/側欄、獨立頁面、管理頁、個人設定、文件選單/側欄動作、搜尋結果和 AI 結果展示。導航位置使用穩定 slot、order 和 ID；不能修改宿主路由分支來接入一個新業務。

動態 Web 已實現：外掛自行產出瀏覽器 ESM、樣式和資源，宿主透過活動外掛清單載入版本化 URL。構建產物不能引用宿主 `@web/*`、本地原始碼或未解析 bare imports。宿主需明確 browser SDK 和 React 等共享依賴的解析/單例方案，提供構建工具驗證；不能把當前 Vite eager glob 稱為執行時載入。宿主工作臺可在瀏覽器包載入期間顯示。直達外掛頁會在發現對應路由期間顯示載入狀態。

宿主從外掛宣告的靜態資源目錄提供版本化資源，不開放整個 npm 包目錄。服務端和客戶端版本不匹配時該外掛頁面不可用；缺失 renderer 保留通用歷史事實展示。Web 註冊錯誤要隔離到外掛邊界，不能使核心文件工作臺白屏。

後端透過 http.v1 註冊 `/api/v1/plugins/<plugin-id>/...` 名稱空間路由，複用宿主認證、Origin/Host 校驗、請求 schema、錯誤格式、限流和取消。公開 webhook 必須顯式宣告外部身份驗證方式，不能以整個業務路徑跳過安全邊界。外掛可自行實現郵件、日程等完整後端和任務。

原生 Mobile 程式碼仍需隨 App 構建；目錄掃描僅發現可構建的外掛目標。要在已釋出 App 中動態提供新業務，需另行採用受限 Web 頁面/API 能力，不能承諾任意 npm 原生模組安裝後立即生效。

動態 WebView shell 已實現，真機驗收仍待完成；僅在產品承諾已釋出 App 無須重新發版即可接入外掛時提升為交付前提。目標 ticket 必須短期、一次性、繫結使用者/外掛/用途，並兌換為服務端強制限制範圍的會話，不能兌換完整宿主會話。限制頁面來源與導航，原生橋僅允許明確列出的能力，不向頁面暴露原生登入憑證。需驗收重放、越權、登出、外掛停用和客戶端版本不相容；本輪已實現外掛專屬短期票據及受限會話，具體介面與未完成的真機驗收見郵箱外掛對接手冊 v1。

## 10. 會員與稽核的移除標準

會員移除包含管理頁、使用者等級展示、會員跳轉、套餐/授權介面、身份源等級對映、資源額度判斷、AI 積分及按等級模型過濾。不得只隱藏頁面而保留等級限制。保留原始 AI 用量記錄。專案未上線，不保留舊商業欄位、介面或遷移相容層；測試使用隔離資料庫。

內容稽核移除包含舉報入口、稽核後臺、稽核供應商、掃描任務和宿主業務流程裡的專用稽核呼叫。登入註冊的管理員審批屬於賬號接入策略，安全操作審計屬於核心，兩者不因“解除安裝內容稽核”一起刪除。

專案未上線，不保留歷史稽核狀態或相容限制欄位。未來業務外掛如需限制資源，應透過明確的通用許可權契約實現，不得繞過私有內容訪問控制。

郵件、日程、會員、稽核作為業務外掛對待。隨手記已從核心移除，未來獨立外掛另行實現。票據、第三方同步、內容識別器、通知渠道等列為可拆分業務候選；每個候選達到相同 SDK/資料/客戶端驗收後再移出，不能留下包裝層繼續匯入宿主私有實現。

## 11. 開發規範與驗收

- 所有公開 ID、資料表、事件和工具有外掛名稱空間；SDK 版本範圍明確。
- 包提供 JS、d.ts、靜態 manifest 和宣告過的客戶端產物；不依賴 Doca 倉庫別名。
- 單元測試用能力替身，整合測試使用獨立 Doca、隔離資料庫和臨時安裝目錄。
- 必須用實際宿主交付物、SDK 與業務外掛 tgz 在倉庫外安裝測試；依賴閉包必須隨驗收材料提供，安裝及啟動不訪問包倉庫，不依賴原始碼連結或未宣告快取。驗收包括髮現、啟動、Web 資源與頁面載入、實際業務流程、許可權撤銷、故障重試和重啟恢復。外部郵件服務可用測試服務替代；SDK 匯入成功不能替代外掛端到端驗收。
- 驗證空外掛目錄、僅單外掛、多外掛組合、缺失依賴、重複 ID、版本衝突、資料庫基線不匹配和關閉清理。
- 驗證兩個宿主例項互不共享外掛服務/使用者事件/工具註冊。
- 驗證 related/none 策略、關係撤銷、外掛停用、來源故障、檔案繫結以及搜尋/AI 許可權一致。
- 驗證併發 AI 呼叫、失敗/取消、實際用量缺失、結算重放和外掛控制失效，不重複計量。
- 驗證升級宿主不修改外掛安裝鎖檔案、業務資料及附件；禁用外掛仍能執行核心文件/檔案功能。

## 13. 接入需求分級與運維邊界

- 現有內容、檔案服務和公共接入鉤子保持各自邊界；外掛負責業務模型、授權、重試和 outbox 語義，持久化全部由宿主管理。
- 安裝包必填 `doca.storage: "host"`，ZIP/npm/商店、離線目錄和啟動歸檔恢復都在匯入服務端程式碼前校驗，缺失/其他值拒絕。不提供外掛業務資料目錄環境變數、後端選擇、舊儲存適配或隱式遷移。
- 託管關係庫與內部物件已實現；託管憑證在 SDK 原始碼 0.1.8 實現，臨時工作尚待實現。後端選擇和共享部署由宿主負責；外掛不區分本地/遠端。精確匯出狀態見儲存規範和第 12 節。
- 託管庫實際結構精確匹配，拒絕不匹配；不能為舊自管安裝開啟空庫或借解除安裝繞開遷移方案。舊包和舊資料保持原樣，任何轉換另行確認。
- 禁用/dispose 不刪除持久資料。當前業務解除安裝鉤子成功後，清單事務隔離安裝代次、失效憑證並持久化私有庫/物件清理意圖；業務表在提交後清理，失敗會重試。叢集業務任務排空尚未實現，全部例項仍需人工重啟。使用者檔案、回執和其他業務引用繼續保留。
- 健康、脫敏日誌、最近任務錯誤與 backlog 透過公開狀態介面彙總，外掛不能讀取宿主儲存路徑。

不提供：任意 SQL、跨外掛/宿主分散式事務、自動匯入舊儲存或雙寫、預設將所有來源交給 AI、原生程序動態執行 npm 外掛程式碼。

<a id="app-持久缓存与附件"></a>

## App 持久快取與附件

Web 與受限移動 WebView 複用外掛 Web 產物。`@smartdoca/plugin-sdk/web` 的 `PluginWebHost.native` 在 Web 中為 null，App 中提供原生能力；型別從 `@smartdoca/plugin-sdk/native` 匯出。

- `native.storage` 提供 get/set/remove/clear，字串快取按伺服器、登入使用者和外掛隔離；單值 200 萬字元、每外掛 2000 萬字元。退出或移除賬號會清理該賬號快取。外掛主動接入，不遷移 IndexedDB，不承諾離線冷啟動。
- `native.attachments.save/share` 接收外掛 API 相對路徑，由原生側帶認證下載，不向 WebView 暴露原生憑證；禁止重定向，最大 32 MiB，並清理臨時檔案。
- Android 儲存可返回 completed/canceled；iOS 儲存和系統分享的 presented 僅表示展示系統面板，不代表操作完成。切換賬號或頁面銷燬會取消進行中的請求。
- 郵箱繫結作為 Web 能力，當前不實現原生 OAuth。

當前 SDK 版本是 0.1.11，npm 釋出記錄見下文。宿主測試和構建不能替代獨立郵箱包聯調、iOS/Android 真機驗收，這兩項仍待完成；詳細契約見[原生能力](plugin-native.zh-Hant.md)。
