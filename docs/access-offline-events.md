# 权限申请、本地副本与事件同步（2026-09-11）

## 文档访问与待办

当前 visibility 语义为：public=公开、authenticated=登录可读，requestable=可申请，invited=仅受邀。继承模式仍遵从上级 ACL；申请开关只在独立设置时开放未授权申请入口。

可申请只暴露标题和申请入口，不授予正文/附件/搜索权限。不可见的未授权访问与不存在均为 404。已可读用户可申请更高权限。用户必须登录且 active 才能申请；匿名用户始终不能评论。

- GET /api/v1/resources/:id/access-preview：最小申请预览。
- POST /api/v1/resources/:id/access-requests：role=reader/commenter/editor/manager。
- GET /api/v1/me/access-requests：自己的申请及当前有管理权的待处理申请。
- POST /api/v1/me/access-requests/:id：decision=approved/rejected/cancelled。
- 原 me/invitations 接口继续处理协作邀请，并统一显示在 #/todos。

申请创建与决定均在短事务内串行，去重待处理申请。审批重新检查当前管理权和申请人状态；不能自己审批、越权审批或重复决定。通过直接产生已接受授权，不再次邀请；不降低已有直接授权。拒绝/撤回不会改变权限。退出可见范围后，申请记录不再暴露原文标题。

## 富文本本地副本

之前仅有页面内存队列，现在富文本接入原生 IndexedDB `doca-offline-v1`。不是把 JSON 重建为新 Y.Doc：缓存保留原始 Yjs checkpoint 和实际本地增量及原消息 ID。

缓存按浏览器 origin、用户 ID、文档 ID、codec 隔离。一次读写事务合并 checkpoint 与 pending 队列，因此同账号多页不会相互覆盖本地副本。只有本地内容事务进入待同步队列；远端增量只更新副本。先提交本地持久事务再发到服务器；精确匹配的服务器 ACK 到达并清理 IndexedDB 后才完成出队。服务器拒绝或存储失败会暂停编辑，保留恢复文件入口。

已通过资源元数据授权检查后，编辑器先从本地副本初始化，再 join/vector 同步，不等待首个 sync-response 才渲染缓存内容。断线已打开文档可继续文字编辑；网络失败不再把当前编辑器卸载。重连补拉远端变化后按原 ID 重放未确认增量。历史回滚仍是在原 CRDT 谱系产生编辑，不重建缓存。

边界：

- 此轮只接入富文本；Excel 的不可变 baseline/epoch 缓存还需单独接入，不能套用正文缓存。
- 不是完整 PWA：未部署 Service Worker 离线应用壳。2026-10-12 的页面缓存增量允许已缓存文档刷新时先显示并离线编辑，详见下文；首次访问或应用静态资源不可用时仍需要网络，不能宣称完整离线冷启动。
- 上传、评论、@用户查询、权限设置需网络，不进入正文离线队列。
- 本地缓存是已授权下载副本，不是服务器最新 ACL；重连后服务端重新校验权限，不能靠本地缓存获得服务器授权。用户 ID 隔离而非设备级加密，共用设备应清理浏览器站点数据。
- 当前富文本协议尚无完整 epoch 协商；不支持服务器重建/恢复到不相关谱系后盲目同步。
- 浏览器可能清理站点数据，存储不足会报错，不能承诺无限期本地持久性。

## 页面缓存先展示 — 2026-10-12

按用户确认的方案，新增 `localStorage` 页面缓存 `doca.document-startup.v1`，精确格式版本为 1，保存当前账号的公开启动信息以及最近 12 个文档的展示元数据和所属文库信息。缓存不包含登录凭证、正文投影、评论或授权名单；正文、原始 CRDT 身份和未确认消息继续由既有 IndexedDB 副本负责。新版本第一次联网打开文档后才建立这层缓存，旧版本的正文缓存不转换、不迁移；未知或损坏的页面缓存不使用、不覆盖、不清除。回退代码不修改原正文和提交队列。

刷新已缓存的文档时，应用壳和编辑器立即读取当前账号的元数据及原 Yjs 副本，不等待插件发现、`/bootstrap` 或文档详情。按上次权限允许离线编辑；启动和详情请求在后台校验，失败自动重试，联网后复用同一编辑器合并远端变化并重放原消息 ID，精确服务器 ACK 后才清理对应待提交更新。暂时网络故障不卸载编辑器。

明确退出、会话拒绝或文档详情返回 401/403/404 时停止展示对应缓存。切换账号和其他标签页退出会使旧页面失效；仅删除可重建的页面元数据，不删除原 Yjs checkpoint、epoch、baseline 或未同步修改。谱系、codec 和 schema 继续按原协议精确校验，不把旧修改强行应用到替换文档。上传、评论、权限设置等仍需网络；匿名页面不保存启动缓存。

自动回归与隔离浏览器脚本见 `tests/document-startup-cache.test.ts` 和 `scripts/qa-document-startup.mts`。构建成功不代表离线刷新或协作验收；具体结果以脚本生成的报告为准。

2026-10-12 本次验证：48 项相关回归通过（另有 1 项既有跳过），类型、生产构建和文档检查通过。隔离 Chrome 在挂起启动/详情请求时约 1 秒恢复富文本；离线输入与再次刷新保留原消息 ID 和字节；后端恢复后无需刷新自动合并两页修改，精确 ACK 清空队列，同一编辑器和焦点保持；随后 60 秒空闲无正文回写。Markdown、表格、画板、演示文稿验证原副本/baseline 的断网刷新恢复，明确拒绝和另一标签页退出验证元数据失效且原副本保留。其他格式全部编辑操作的收敛、真机和生产部署不属于本次验收。

## 离线文档入口

桌面内置前端和生产 Web 工作台均提供**账号菜单 → 离线文档**。浏览器中在线选择**下载前端以离线使用**，等页面显示下载完成。支持 Service Worker 的安全站点会保存当前构建的页面、核心编辑器代码和配套样式。后端不可达时，在同一浏览器配置打开同站点，或在桌面版进入已连接的后端账号，从首页**最近编辑**点开文档。首次连接和下载需在线完成。

目录收录当前会话中使用新版联网打开、且已有同格式正文副本的文档。支持按标题或文库名搜索。旧版打开过的文档需要在新版联网打开一次才进入目录。现行会话使用 `doca.offline-session.v1`，目录元数据使用独立的 `doca-offline-catalog-v1` IndexedDB，本地正文和待同步修改仍由 `doca-offline-v1` 管理。站点、账号和桌面工作区地址需匹配。浏览器静态缓存只包含构建资源，附件、评论和插件服务需要连接。

富文本、Markdown、表格、画板和演示文稿在副本就绪且最后一次授权允许编辑时显示**正在离线编辑，连接恢复后会自动同步修改**。打开着的文档会重连并同步，关闭后可重开该文档继续同步。服务端重新验证账号、资源权限和谱系，确认持久化后才移除相应待提交更新。退出、账号切换或收到明确的访问拒绝会隐藏对应缓存条目，原正文副本和待同步修改仍留在本地。实施范围和验证见[本地离线工作台](../specs/013-offline-workspace/validation.md)。

## Hook 事件同步

投递正文、请求头和各事件字段见 [Webhook 投递](webhooks.zh-CN.md)。

业务事务把事件写入 outbox，提交后才发布为单调序号。`GET /api/v1/admin/integration-events?after=0` 仍可供管理员或插件按 cursor 拉取，每次最多 100 条。事件包含类型、资源/用户标识与通知跳转路径，不包含正文和密钥。

管理员可以在 Hook 页面登记多个回调地址，并为每个地址选择事件和额外请求头。匹配事件由后台 POST 到该地址，请求头按登记内容原样发送，不占用业务事务。暂停的回调不再接收新事件。回调地址使用 HTTP(S)，可以指向公网、本机或内网的其他程序。

订阅和投递记录在独立的 webhook 数据库中。SQLite 部署为数据目录下的 `webhooks.db`；PostgreSQL 部署为 `<主库名>_webhooks`，或由 `DOCA_WEBHOOK_DATABASE_URL` 指定。`capabilities.hooks=true`，`integrationEventStream=true`。
