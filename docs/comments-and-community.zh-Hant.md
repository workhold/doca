# 評論、使用者可見範圍與通知

[English](comments-and-community.md)

<a id="数据"></a>

## 資料

當前基線同時支援 SQLite / PostgreSQL：

- `users.public_id`：獨立於內部 UUID 的唯一使用者標識，建立時歸一化為小寫，3–160 位，允許英文字母、數字和 `._@+-`。資料庫唯一索引約束。註冊和管理員建立可指定 `publicId`，省略則使用 login。建立後不隨暱稱變化。
- SSO 資料按身份源配置對映；缺少合適的唯一使用者名稱或其他必填資料時，`/auth/complete` 返回 `needs_profile`，由使用者補全，不生成身份源名稱空間下的使用者名稱。絕不因同名、同郵箱、同 public_id 合併賬號；認證關聯仍由 provider + subject 唯一確定。繫結新登入方式不修改原使用者標識。
- `users.directory_mode`：可空，空表示跟隨站點 `settings.directory_mode`。
- `comments.body_json`：當前富評論 JSON；`body` 是用於檢索、摘要和通知的派生純文字。未刪除評論必須具有合法的 `body_json`。
- `notifications` 增加 actor_id、comment_id、dedupe_key。事件與業務修改在同一事務落庫；dedupe_key 唯一索引抵禦重複事件。

富評論結構：

```json
{
  "version": 1,
  "blocks": [
    {
      "type": "paragraph",
      "children": [
        { "type": "text", "text": "请确认 " },
        {
          "type": "mention",
          "userId": "内部UUID",
          "label": "昵称",
          "publicId": "alice"
        }
      ]
    },
    { "type": "image", "assetId": "附件UUID", "alt": "图片名称" }
  ]
}
```

後端從使用者表填充提及名稱和標識，不信任客戶端 label。單條評論最多 5,000 字、9 張圖片、50 個塊；圖片必須屬於當前資源，且是有效的 comment_image 或 image attachment。上傳後仍走原有私有儲存、圖片清洗和鑑權下載流程。評論者可以上傳評論圖片，但不能因此上傳/修改正文附件。

## 使用者可見範圍

管理員 → 使用者可見範圍，支援站點預設和單使用者覆蓋：

| 模式    | 新使用者候選                                                                       |
| ------- | -------------------------------------------------------------------------------- |
| all     | 本站正常使用者                                                                     |
| related | 雙方共同擁有文件或知識庫顯式許可權，包括繼承、知識庫擁有者、有效連結成員及有效組授權；同一有效使用者組的正常成員也算關聯 |
| none    | 無候選，不允許繞過介面直接填寫使用者 UUID 新增新許可權或新提及                       |

公開可見、登入可見不構成關聯。許可權撤銷後關聯消失。已有許可權仍可修改/撤銷，已有評論和正文提及不會因策略收緊而消失。管理員的使用者管理列表不受該搜尋策略限制。

介面（均以 `/api/v1` 為字首）：

- `GET /users/lookup?q=`：按當前操作者範圍查詢正常使用者，返回 id、public_id、display_name、頭像資訊。賬號/標識字首匹配，暱稱模糊匹配；最多 20 項，搜尋萬用字元按普通文書處理。
- `GET /admin/directory-policy` → `{mode, revision}`。
- `PUT /admin/directory-policy`：`{mode, revision}`，版本衝突返回 409。
- `PUT /admin/users/:id/directory`：`{mode: "all" | "related" | "none" | null}`，null 恢復跟隨站點。
- `GET /me`、`GET /users/:id/profile`、管理員使用者列表包含 public_id。

## 內容評論互動

- 編輯模式在原編輯器浮動選區工具欄末尾追加評論圖示；只讀模式獨立顯示評論圖示，無格式修改工具。需要 commenter 或更高許可權才能提交。
- 原生瀏覽器選區對映為 Slate 範圍，再使用編輯器提供的 Yjs 相對位置錨點。當前包的錨點是**單段落/塊內**，跨塊選擇會提示重新選擇，不把不支援的範圍靜默截斷。
- 未解決且原文仍存在的根執行緒各自呈現為獨立卡片。預設黃色下劃線，點選原文/卡片雙向聯動黃色背景和卡片邊框。滾動、縮放和協同更新時重新測量位置。
- 原文被刪空、錨點失效、根評論刪除或解決後，卡片和高亮隱藏；資料庫保留評論。撤銷文字刪除而恢復有效錨點時可重新顯示未解決評論。
- 全文評論和內容評論共用富評論輸入器：@ 搜尋、圖片上傳、編輯、回覆、刪除、解決等圖示操作。編輯版本檢查保留，提交失敗不清除輸入。
- 刪除圖示先顯示氣泡確認，取消不會傳送刪除請求。回覆採用緊湊間距，仍保留作者、時間和提及資訊。
- 五種編輯器的內容評論欄頂部均提供「已解決的評論」圖示，彈框展示已解決根評論與回覆。作者或有管理許可權的使用者可「恢復為未解決」；恢復繼續檢查當前許可權和評論版本，失敗時保留列表並顯示錯誤。可繼續載入分頁；已刪除的根評論不列入已解決記錄。有效錨點恢復為未解決後重新顯示卡片與標記。

介面：

- `POST /resources/:id/comments`：`{richBody, parentId, anchor?}`。回覆繼承根評論所屬執行緒。
- `PATCH /resources/:id/comments/:commentId`：`{version, richBody?, deleted?, resolved?}`。
- `POST /assets?purpose=comment_image&resourceId=...&filename=...`：二進位制上傳，最多 5MB；後端執行圖片驗證和訪問校驗。

正文 @ 使用編輯器 mentions 擴充套件，候選同樣來自範圍受限的 lookup。使用者提及節點保留使用者 UUID，而非僅存顯示名字。


五種格式各有永久評論錨點；上面的 Slate 選區說明僅適用於富文字。表格透過原生評論 API 捕獲穩定行列 ID，結構變化後解析當前範圍，服務端檢查目標是否仍存在，見[實時協同](collaboration.zh-Hant.md)。

五種編輯器點選評論時只高亮該條關聯內容；開啟側欄或跟隨評論連結不恢復上次背景。點選另一條時替換高亮，點選其他位置、解決執行緒或關閉側欄時清除。高亮僅屬檢視狀態，不寫單元格樣式、圖形填充、Yjs 更新或永久錨點。評論圖片透過共享檢視器縮放、複製和下載，見 [0.2.23 驗收](verification/editor-comments-2026-10-28.md)。

## 通知

支援 comment.created、comment.mentioned、document.mentioned、resource.permissions_changed（新增邀請）、like.added、favorite.added 以及已有所有權轉移事件。

- 不通知操作者自己；同條評論中被提及的擁有者/被回覆人只收到提及通知，不再疊加普通評論通知。
- 提及不授予訪問許可權。接收者必須是正常使用者，並且在提交時具有當前文件讀取許可權，否則跳過通知。
- 正文新增提及按穩定的 mention 節點標識判斷。同一使用者在另一新節點再次被 @ 會有新通知；舊更新重放、普通文字修改不重複通知。
- 檢視通知列表時再次校驗當前文件許可權；撤銷許可權、文件刪除後，相關通知不再展示，也不計入未讀數。
- WebSocket 推送 `notifications.changed` 失效通知，前端重新獲取自己的列表；不會廣播通知正文。離線使用者的事件已在資料庫中，重新連線後補拉。
- `GET /notifications?offset=0` → `{items, unread, nextOffset}`，每頁 50 項；包含操作者和文件標題。
- `POST /notifications/read`：`{ids:[]}`，最多 100 項，僅更新操作者自己的通知。
- `POST /notifications/read-all`：`{}`，將操作者自己的通知全部標為已讀。

當前通知是站內通知，不傳送郵件、簡訊或第三方推送。單例項使用本地 WebSocket；多副本需按[水平擴充套件](horizontal-scaling.zh-Hant.md)配置共享 PostgreSQL、Redis 與檔案儲存，不能僅增加應用副本。

## 驗證

測試覆蓋使用者標識衝突、SSO 標識、可見範圍/單使用者覆蓋、公開文件非關聯、許可權繞過、結構化評論、圖片資源隔離與評論者上傳、通知去重、無許可權跳過、撤銷訪問後的通知隱藏、只更新自己已讀狀態、協同更新重放和重複 @。

瀏覽器使用記憶體文件和模擬使用者做隔離驗收，不向真實文件寫入測試評論。確認工具欄末尾按鈕、只讀按鈕、富評論提及、雙向黃色高亮、解決隱藏和原文刪空隱藏。
