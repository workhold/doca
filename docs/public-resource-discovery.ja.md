# 公共資源、発見、コレクション

<a id="administrator-policy"></a>

## 管理者ポリシー

権限と可視性、コンテンツの権限、公開検索の項目で、管理者は文書、ライブラリ、フォルダを別々に設定します：

| モード | 発見カタログ | 収集前の全文検索 | 収集後の個人検索 |
| --- | --- | --- | --- |
| リンクのみ | 隠された | 除外される | 含まれている |
| 収集後に検索可能、発見可能 | 表示されました、タイトルクエリ | 除外される | 含まれている |
| 検索可能で、サイト全体で探索可能なサイト | 表示されました、タイトルクエリ | 含まれている | 含まれている |

このポリシーは、すでに公開されているリソースの配分方法のみを変更するものです。プライベートなリソースは公開されません。3種類のすべてがリンクのみの場合、公開エントリーと「Visited」および「Collected」タブは残り、「Discover」タブは非表示になります。APIは発見できないリソースを返しません。

新しいポリシーが保存されるまで、古い配布設定は以前の意味を保持します。保存時には3つの独立したデータが記録されます。 `publicModes`歴史の記録が保持されている。

<a id="personal-scope"></a>

## 個人範囲

訪問は訪問記録を作成するだけで、リソースは収集しない。古い自動機 `source=opened` 行はコレクション検索の対象にならず、コレクションリストにも表示されません。直接の助成金、受け入れられた招待、所有権はそれぞれ独自の規則に従います。

3種類のリソースタイプすべてが使用される `resource_collections`ユーザーごと、リソースタイプ、リソースIDによって一意に識別されます。パブリックカタログでは、自分が所有している、またはすでにアクセスできるパブリックリソースは隠されません。収集されるとリストに追加されます。以前の承認によってフィルタリングされることはありません。

検索候補は、以前の範囲、お気に入り、コレクションリストの組み合わせです。結果は再び現在のアクセス状況と照合されます。コレクションを削除すると、そのリスト行のみが削除され、メンバーシップや招待状は変更されません。すでに検索可能だったリソースは引き続き検索可能です。

現在のスキーマでは空のコレクションテーブルが作成され、起動時には歴史的なエントリーがその中にコピーされません。既存のコレクション行はそのまま保持されます。自動的な結合、招待、または訪問記録はコレクションとして扱われません。

検索は、検索可能なすべてのもの、私の検索範囲、そしてサイト全体の公開テキストの間で切り替えが可能です。サイト全体のテキストには、管理者がサイト全体で検索を許可したリソースのみが含まれます。ディスカバリーカタログのタイトルクエリは、ボディ検索やベクトル検索を呼び出しません。ファイル検索やAIファイル検索も、コンテナコレクションと公開検索ポリシーをチェックします。

<a id="containers"></a>

## コンテナ

ライブラリやフォルダを収集する際には、現在存在するコンテンツと後で追加されるコンテンツが含まれます。クエリがこれを動的に決定します。各子項目にメンバーシップ行をコピーするわけではありません。

公共図書館は、ページの閲覧範囲を設定します。協力者からの継承機能を無効にしても、公共の閲覧機能は無効になりません。そのページは、編集、コメント、権限管理機能を設定することができます。ポイント照会やリストSQLは、同じ公共閲覧継承機能を使用します。図書館内のページは、図書館の検索・探索ポリシーに従います。独立した文書は、文書ポリシーに従います。

フォルダの公開情報は保存されている `folder_publications`ログインしたユーザーは、現在および将来のコンテンツを閲覧できます。管理機能は受け取れません。ファイルの管理やダウンロードにはログインが必要です。匿名でのファイルアクセスはできません。公開が停止された後は、アクセスは現在の会員資格に基づきます。コレクション自体はアクセス権を与えません。

ページ権限パネルでは、公共図書館をソースとして表示されます。フォルダ共有パネルでは、公共範囲には現在のものと将来のものが含まれると表示されます。公共コンテナに移動すると、そのコンテナと共に公開されます。新しい場所に移動すると、新しい場所が使用されます。

<a id="discovery-ui"></a>

## ディスカバリーUI

公共リソースページには、文書、ライブラリ、フォルダによってフィルタリングされた訪問済み、発見済み、収集済みのリソースがあります。訪問済みには、ユーザーが開いて現在もアクセス可能なリンクのみの公共リソースが含まれます。訪問履歴は検索資格を生み出しません。ビジネスリストにはもはや公共リソースのショートカットはありません。

家にいる `/home` 文書、ライブラリ、フォルダ、ファイル全体の最近の訪問情報、および保留中のチケットやライブラリの決定事項をまとめた。文書が移動されました。 `/documents` 私が所有する最近の訪問記録、共同編集、お気に入り、コレクションも保持します。ライブラリのデフォルトの「All view」は、所有、共同編集、お気に入り、コレクションを組み合わせます。サイト全体の公開カタログは自動的に表示されません。共有フォルダにはお気に入りはありません。それらは、私が共有したもの、私と共有したもの、収集したものをすべて提供します。

公開リストには「収集」と「非収集」のオプションがあります。文書のメニューには、「収集」、「非収集」、そしてユーザーが削除できる「削除」の項目も含まれています。お気に入りやピン留めはショートカットとして残ります。リソースの詳細ページには、新たな「収集」項目は追加されません。

ホームの統計は、現在のユーザーがアクセスできるデータを使用します。チケットは、唯一の承認と受け入れステップを再利用します。ライブラリの決定は、メンテナンス権限と保留中のキャリブレーションを再利用します。処理が終了すると、それらはホームから離れます。ソースの障害は別途表示され、ゼロの保留項目として提示されません。最初のバージョンでは内蔵ソースが使用されます。外部のプラグインやホームSDKはまだありません。

文書や図書館が使用する `resource_visits`ファイルとフォルダは使用される `workspace_activity`最近の訪問は再び許可され、その後時間順にまとめられ、ページが表示されます。ファイルのプレビューを開くことも訪問とみなされますが、リストのサムネイルはそうではありません。

第1フェーズでは、タイトルクエリ、更新時刻順序、安定したページング、収集、バッチ収集機能が提供されます。ライブラリはコンテナとして表示され、そのページはリストに展開されません。クエリはデータベースカタログを使用します。新しいMeilisearchの依存関係や推薦フィードはありません。
