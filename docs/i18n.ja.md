# インターフェース言語

Doca 0.3.0 は 8 言語に対応しています。各言語は独立したメッセージカタログを持ち、共通の安定した英語キーを使います。実装規約の原文は[英語版](https://github.com/workhold/doca/blob/main/docs/i18n.md)をご覧ください。

<a id="language-codes"></a>

## 言語コード

| コード | 言語 | `html lang` |
| --- | --- | --- |
| `zh` | 簡体字中国語 | `zh-CN` |
| `en` | 英語 | `en` |
| `zh-Hant` | 繁体字中国語 | `zh-Hant` |
| `ja` | 日本語 | `ja` |
| `fr` | フランス語 | `fr` |
| `ko` | 韓国語 | `ko` |
| `es` | スペイン語 | `es` |
| `ru` | ロシア語 | `ru` |

サイトの初期言語は簡体字中国語です。管理者が既定の言語を変更できます。訪問者と `ui.locale` を設定していない利用者にはサイトの既定値を使い、利用者が言語を保存済みの場合はその選択を優先します。

API に書き込む値には、表に記載した正規のコードを指定します。地域やシステムの言語タグを解決するときは、`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` を繁体字中国語として扱います。他の対応言語は先頭の言語サブタグで照合します。保存済みの値を認識できない場合、ワークスペースにはサイトの既定言語を使います。

アカウントの選択はページ状態の `ui.locale` に保存されます。Web では `localStorage` に `doca.locale` を保持し、モバイルでは端末に保存します。アシスタントは既存の `page_state` 機能でアカウントの言語を変更できます。

Web のサインイン画面を読み込むたびに、最初はサイトの既定言語で表示されます。サインイン画面での選択は、その訪問の間にすぐ反映されます。サインイン後のワークスペースはアカウントの言語設定とサイトの既定言語に従います。

<a id="host-catalog"></a>

## ホストカタログ

カタログがあります `packages/i18n`. 英語のカタログ `en` キーの源泉です。他のすべての言語は、正確に同じキーをカバーしなければなりません。

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

- キーは小文字の英語で、点が付いており、地域別にグループ化されています。例えば `nav.trash` そして `settings.language`.
- プレースホルダーは `{name}`文を分割して部分を繋げないでください。
- 複数形の使い方 `files.count.one` そして `files.count.other`通話はまだ続いている `t("files.count", { count })`英語は使用される `one` 時々 `count === 1` そして `other` そうでなければ、中国語では同じ文を両方に使うことがある。
- 欠落の翻訳では英語が使われ、その後キー自体が示される。
- セレクターには各言語の固有の名前を使用してください。ネイティブのラベルはそこから来ます。 `localeNames`.
- 日付とソートの使い方 `Intl` アクティブ言語タグのため。
- 文書のタイトル、本文、コメント、メール、ファイル名、ユーザー入力は翻訳されません。

このウェブアプリは使用する `useI18n()` ためには `locale`, `t`、そして `setLocale`Ant DesignとAnt Design Xもそれに従っています。 `locale`デスクトップとモバイルではホストカタログが使用されます。ブラウザ拡張機能はそのブラウザの言語を記憶します。バイリンガルプラグインを使用した貢献内容は、6つの新しい言語で英語の欄を使用します。

コード化されていないユーザーが見えるサーバーエラーは依然として中国語の文です。新しい検証エラーは、例えば安定したコードを使用します。 `invalid_locale`そして、インターフェースがそれを翻訳します。このバージョンでは、既存のAPIエラーがすべて変換されるわけではありません。

新しいAI画像生成、モデル接続、およびワーカーエラーは、既存のエラーテキストフィールドにシリアル化された明示的な提示エンベデッドを使用する。

```ts
{ type: "system_error", version: 1, code: "image_edit_failed", data: { status: 422 } }
```

新しく生成された、明示的にコーディングされたシステムエラーのみがこの形式を使用する。歴史的なエラーテキスト、メッセージ、ツールの結果、推論、および保存されたプロンプトのコンテキストはそのまま読み取られる。スキャンしたり、翻訳したり、変換したり、移行したりしてはならない。タグが付けられていないエラーは変更されない。ウェブとモバイルは共通する `systemErrorMessage` 読者 `@doca/i18n`タグ付けされた作業エラーが使用される `useI18n().t`新しいHTTPエラーは、同じプロバイダが選択したロケールを使用します。不明なコードはカタログ化された一般的なエラーとして表示され、形式が間違っているかサポートされていないエンドポイントは変更されません。

`AppError.message` モデルに向けたエラーシリアルタイズは変わらない。プレゼンテーションメタデータはエラーオブジェクトの外側のWeakMapに存在する。画像の失敗チェックポイントには独立した構造化された理由が含まれているため、後続のタスク失敗時でも正規のツールフィードバックを変更せずにそれを表示できる。インターフェース言語はシステムプロンプト、ツール定義、または再プレイ履歴に決して追加されず、ユーザーが言語を切り替える際にキャッシュされたモデルプレフィックスが保持される。

これは、古いプレインテキストと新しい暗号化されたエラーのための合意された読み取りポリシーです。歴史データやデータベーススキーマの移行はありません。ロールバックでは、封筒リーダーとすべての保存されたデータを保持しながら、新しい封筒の書き込みを停止する必要があります。

<a id="persisted-system-state"></a>

## 保存されたシステム状態

データベース、ジョブチェックポイント、イベントストリーム、API応答は安定した英語コードと構造化されたパラメータを保存します。どの言語でも表示文を保存することはありません。ウェブおよびモバイルアプリは、コードを現在のカタログに基づくタイトル、説明、ステージ名に変換します。

```ts
{ code: "folder_available", data: { name: "Research" } }
t("ai.progress.event.folderAvailable", { name: event.data.name })
```

ステータスとして保存されるフェーズ、イベント、承認、エラー原因はこの規則に従います。例えば、コードを比較してください。 `phase === "completed"`結果を比較しないでください。 `t(...)` 中国語または英語のラベルでも可です。ユーザーの入力、モデルの回答、文書のタイトル、ファイル名、ウェブソースはそのまま保持します。自然な内容をコードに書き直さないでください。

<a id="editor-subpackages"></a>

## エディターサブパッケージ

エディターサブパッケージは自身のインターフェースコピーを保持します。Docaのカタログをインポートしたり、Docaのページ状態を読み取ったりはしません。

司会者が通過する：

```tsx
<RichTextEditor locale={locale} />
```

`locale` 文字列です。インストールされたエディターは表に記載されている8つのコードを受け入れます。認識されないパッケージロケールの場合は英語に切り替わります。

1. オプションで追加する `locale?: string`省略される場合は、表示する `zh`現在の中国語インターフェースに合わせて。
2. キーは、Stablyな英語識別子です。 `toolbar.bold` そして `find.replaceAll`.
3. 各サポートされている言語に対して、同じキーの完全なカタログを提供する。
4. プレースホルダーは `{name}`数え方 `key.one` そして `key.other`選ばれた者 `count`.
5. 変更する `locale` ボタン、メニュー、プレースホルダ、ヒントを更新します。文書、Y.Doc、共同編集アダプター、またはプラグインリストを再構築することはありません。
6. オプション `messages?: Record<string, string>` 個々のキーを無効化することができます。欠落したキーについては、内蔵の翻訳機能が使用されます。
7. ユーザーが文書に書き込んだテキスト、数式、セル値は翻訳されません。

インストールされたパッケージのタイプが含まれる後 `locale`司会者が現在を伝える `locale` マウント現場で。置かないでください。 `locale` ドキュメントを再構築する依存関係、Y.Doc、共同編集アダプター、またはプラグインリスト。

<a id="add-a-language"></a>

## 言語を追加する

1. コードを追加する `locales`、そして `html lang` 価値。
2. 正確に英語のキーを持つホストカタログを追加する。
3. 言語の名前を加える、例えば `locale.ja`.
4. Webアプリに適切なAnt Designのロケールを追加します。
5. すべてのエディターサブパッケージに同じ言語カタログを追加する。
6. `ui.locale` 新しいコードを受け入れる。なぜなら、検証が同じように読み取れるからだ。 `locales` リスト。
