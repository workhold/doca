# Установите и разверните плагины.

0.1.26 использует [Общая бизнес-база данных плагинов](plugin-database-isolation.ru.md)Отдельно от ядра, с автоматическими пространствами имен. Он заменяет базы данных для каждого плагина, выпущенные в версии 0.1.25. Для обновления необходимо обычно удалить приложение на предыдущем хосте и переустановить; данные плагинов не мигрируют.

Утверждено [Контракт на управление хранением](plugin-horizontal-scaling.ru.md) требует `doca.storage: "host"` И хост-владеющая устойчивость. Реализованы статическое отклонение, управляемый SQL и приватные объекты. Криптографические данные экспортируются в исходнике SDK версии 0.1.8; временные рабочие пространства и расходование задач кластером остаются проблемами. Плагины не выбирают локальные/дистанционные серверы или не получают директории бизнес-данных.

Администраторы используют **Админ → Плагины** Чтобы просмотреть официальный магазин, загрузить локальный ZIP-файл, установить, обновить, активировать, отключить или удалить плагины. Изменения сохраняются в виде желаемой установки и вступают в силу при следующем перезапуске каждой инстанции. Страница отображает работающую версию инстанса отдельно от глобального целевого объекта. При текущем удалении вызывается необходимый хук очистки бизнеса, после чего структурирование сбрасывается. Если хук не работает, установка остается нетронутой. Очистка приватного магазина, управляемого хостом, использует ферментацию генерации и долговечные записи объектов мусора; задачи бизнеса для деградации остаются не реализованными; удаление файловой системы плагинов запрещено. Обновления установленного плагина все еще требуют того же. `doca.dataVersion`Плагины проверяют свою реальную структуру базы данных во время инициализации.

```dotenv
DOCA_PLUGIN_STORE_URL=https://store.smartdoca.cc
DOCA_PLUGINS_DIR=/data/plugins
```

Адрес магазина — это configurable HTTP(S) origin. Проверьте доступность удаленного сервиса отдельно; если магазин недоступен, локальное загрузка и установка плагинов остаются возможными. Пусто `DOCA_PLUGINS_DIR` возвращается к `${DOCA_DATA_DIR:-./data}/plugins`, относительно каталога работы. Только хост конфигурирует долговременное хранение базы данных/объектов. Не существует переменной окружения plugin business-data-directory; API плагинов никогда не сообщают о том, хранит ли хост данные локально или удаленно.

Для предоставленного развертывания Compose выполните его в директории развертывания:

```sh

```

Здесь, `doca` Это название услуги. `services` в `compose.yaml`Название контейнера может отличаться. Если вы переименовали сервис, замените `doca` В команде указывайте имя вашего сервиса.

Перезапустите каждый экземпляр в многоконфигурационном развертывании; для других типов развертываний используйте соответствующий надзорщик. Управляющий интерфейс не перезапускает процессы. Во время поэтапного перезапуска снижайте нагрузку или используйте аффинитету, если изменились API плагинов. Версия V1 не гарантирует работу API смешанных версий без снижения производительности.

## Внедрена ревизия хранилища (2026-10-03, источник SDK 0.1.8)

`@smartdoca/plugin-sdk/storage` Теперь экспортируются устройства для установки `pluginDatabaseToken` (`storage.sql.v1`) и `pluginObjectStorageToken` (`storage.objects.v1`). Подмножество базы данных представляет собой версию схемы 1, с колонками text/int32/double, первичными/уникальными ограничениями, структурированными операциями select/insert/update/remove, а также транзакциями с выполнением кallback-функций один раз. Источник SDK версии 0.1.8 также экспортирует… `pluginCredentialToken` (`storage.credentials.v1`): зашифрованный CRUD, метаданные и проверки ревизий, доступный только серверу. Смотрите [API для кредентирования](plugin-credentials.ru.md)Связи, идентификаторы, общий SQL, upsert и рабочие пространства не экспортируются. Бизнес-SQL использует один общий база данных, управляемый хостом, отдельный от основного: один файл SQLite с префиксами таблиц, или один URL/аккаунт PostgreSQL с автоматическими схемами плагинов и общим пулом соединений. Изоляция процессов остается не реализованной. Смотрите [Настройка хранения и условия удаления перед обновлением](plugin-database-isolation.ru.md).

Логические базы данных используют `plugin:<pluginId>`Принадлежность пользовательских файлов и использование приватных объектов `plugins/<pluginId>`и выпуск ZIP-файлов `host/plugin-releases/<sha256>.zip`Полные неизменяемые байты ZIP хранятся в файловом хранилище, настроенном в среде; общая база данных содержит реестр версии 2, ссылки на архивы и индексы доверенных хешей файлов. Проверенные кэш-данные не скачивают ZIP-файлы снова. Все экземпляры перезапускаются вручную. Новый базовый уровень хоста отклоняет старые базы данных/форматы/пакеты SDK и сохраняет их данные без миграции или альтернативы. Смотрите [точная реализация и ограничения](unified-storage-implementation.md).

<a id="distribution-and-filesystem"></a>

## Распределение и файловая система

Все инстансы используют один и тот же хост-базу данных. PostgreSQL является оптимальным выбором для распределенного развертывания. База данных хранит атомарный реестр желаемых данных и неизменные ссылки на архивы; полные ZIP-файлы, включая локальные загрузки, находятся в настроенном общем хранилище файлов. Каждый инстанс имеет приватный записываемый кэш.

```text
/data/plugins/
  .releases/<sha256>/          verified immutable releases
  .staging/                   temporary extraction
  .imports/                   retained offline folder imports
```

Стартап проверяет каждый файл в соответствии с общим архивом, восстанавливает отсутствующие или поврежденные файлы, а затем импортирует плагины. Он никогда не устанавливает зависимости npm, не компилирует исходный код и не связывается с магазином. Отсутствующий или поврежденный общий архив препятствует запуску. Сделайте резервную копию как метаданных общей базы данных, так и настроенных хранилищ файлов, содержащих неизменяемые версии. Хост также создает резервные копии записей управляемых плагинов, приватных объектов, ссылок на пользовательские файлы и учетных данных. Многопроцессные постоянные серверы должны быть общими; имя директории не является распределенной базой данных.

Не разделяйте директорию кэша плагинов между живыми инстансами. Установка на один инстанс не требует ручного копирования плагина на другой. Исторические версионные ресурсы браузера также можно восстановить по требованию из общих архивов для обработки маршрутизации load-balancer.

Оффлайн-установка: когда инстанс остановлен, выполните полную релизировку. `<DOCA_PLUGINS_DIR>/<plugin-id>/`При запуске он упаковывается и публикуется в общем реестре, затем перемещается в `.imports/`Другие экземпляры синхронизируются при перезапуске. Рутинное управление должно использовать загрузку через ZIP. Не существует manifestа npm для root-уровня или пути совместимости с загрузкой исходного кода.

Местные ZIP-каталоги и каталоги магазинов имеют одинаковый структурирование и проверки. Используйте [Протокол хранения и спецификация пакета](plugin-store-protocol.ru.md)Файлы программ, записываемые бизнес-данные и учетные данные должны находиться отдельно. Во время экспорта не запускаются скрипты. Все зависимости во время выполнения должны быть представлены в виде реальных файлов; ссылки pnpm не являются распространяемыми файлами.

<a id="lifecycle-and-retention"></a>

## Цикл жизни и хранение

Хост проверяет диапазон SDK, дублирующие идентификаторы, версию данных и зависимости плагинов перед импортом кода. Конфигурация является глобальной; идентификация запросов и права остаются в ведении хоста. Управление использует проверки ревизий, чтобы конфликтующие администраторы повторно пытались выполнить действия вместо того, чтобы перезаписывать друг друга. Операции создают события аудита безопасности.

Отключение и удаление применяются при перезапуске. До этого момента старый процесс продолжает обслуживать старый плагин. Старые кэширования кода и неизменные архивы сохраняются для рабочих экземпляров и повторной установки; в версии 1 нет автоматической очистки архивов. Отключение/отключение работы сохраняет долговременное состояние. Пользовательские прикрепления, данные документов, другие бизнес-ссылки и подтверждения файлов не удаляются автоматически; очистка управляемого частного состояния находится в ведении хоста и все еще требует координатора кластера. Отмена восстанавливает выбор начальной настройки рабочего экземпляра; это новое глобальное изменение желаемого состояния, а не мгновенное возвращение к другим процессам.

Фактические ошибки инициализации плагина все еще приводят к остановке запуска. Ошибки совместимости SDK и зависимостей изолированы, как описано ниже, что позволяет использовать управление плагинами. Нет функции горячего удаления, панели отслеживания завершения кластера или установки динамического кода на мобильных устройствах.

Валидация использует изолированные базы данных и временные директории. Смотрите [приемка магазина](plugin-store-protocol.ru.md#cross-repository-acceptance).

<a id="compatibility-failure-isolation"></a>

## Изоляция несовместимости

Несовместимый диапазон SDK или отсутствующая необходимая зависимость изолируют затронутый бизнес-плагин. Хост и несвязанные плагины запускаются, и в меню Admin → Plugins объясняется причина, после чего требуется обновление. Установленные файлы, архивы, бизнес-данные и учетные данные сохраняются. Старые пакеты не конвертируются, а старый код SDK не выполняется. Новые онлайн-установки все еще отклоняют несовместимые пакеты. Полные офлайн-файлы установки сохраняют свою первоначальную идентичность и подвергаются той же изоляции.

Старые пакеты не объявляют статически все бизнес-политики, которые регистрируют. В данном экземпляре есть активированный, но недоступный плагин, а записи, охраняемые существующими проверками политики плагинов, возвращают 503. Вход, чтение и управление плагинами остаются доступными. Перейдите на совместимый пакет или явно отключите затронутые плагины, а затем перезапустите все экземпляры, чтобы снять эту защиту. Отсутствующие источники прав на плагин продолжают отказывать в авторизации. Несовместимый код SDK не может запустить функции удаления; сначала произведите обновление. Стадийное совместимое обновление не может быть отменено и возвращено в пакет с несовместимым SDK. Заменяемые пакеты должны сохранять dataVersion и существующую бизнес-структуру.

Изоляция – это локальное состояние диагностики в экземпляре, а не изменение схемы реестра или базы данных. Поврежденные архивы, некорректные метаданные, сбои в основном процессах и ошибки в жизненном цикле все еще приводят к отказам. Не происходит никакой миграции данных или снижения уровня приложения.
