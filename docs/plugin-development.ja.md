# プラグイン開発

TauriデスクトップクライアントはリモートのDocaホストに接続します。プラグインは、そのホスト上のインストールディレクトリとパブリックSDKを通じて実行され、クライアントはデスクトップ専用のソースパスブリッジを追加しません。詳細はこちら [デスクトップクライアント](desktop-client.ja.md).

現在のソースはSDKを使用している **0.2.0**、と共に `ai.v2` / `ai.continuations.v2`ツールのコンテキストは常に含まれている `jobId`; `sessionId` 実際の会話でのみ存在します。プラグインを再構築する `sdkRange: "^0.2.0"`; 以前のSDK範囲とAIサービス契約はアダプターなしで拒否される。このソース変更はnpmの公開やデプロイではない。詳細は [MCP実行分離](mcp.ja.md#execution-history-and-upgrade).

互換性のないSDK範囲や利用できない必要な依存関係により、影響を受けるビジネスプラグインが孤立する。ホストプラグインと関連のないプラグインが起動し、Admin → Pluginsで理由が説明され、アップグレードが求められる。インストールされた選択項目、アーカイブ、ビジネスデータ、認証情報は保持される。古いパッケージは変換されず、古いSDKコードも実行されない。新しいオンラインインストールでも互換性のないパッケージは拒否される。完全なオフラインインストールフォルダは元の識別子を保持し、同じ孤立状態が維持される。


外部のAIクライアントが使用する [MCPサービス](mcp.ja.md)ツールはMCPへの露出を明確に宣言し、通常の承認/アクセスチェックを維持する必要がある。SKILLは承認の付与ではなく、手動によるものである。

0.1.26はaを使用しています [共有プラグインビジネスデータベース](plugin-database-isolation.ja.md)コアから分離され、自動的な名前空間を持つ。0.1.25でリリースされたプラグインごとのデータベースを代替する。アップグレードには、以前のホストで通常のアンインストールと再インストールが必要であり、プラグインデータは移行されない。

```json
{
  "name": "@example/attachments",
  "version": "1.0.0",
  "type": "module",
  "doca": {
    "dataVersion": "1",
    "storage": "host",
    "manifest": "./manifest.json",
    "server": "./dist/server.js",
    "web": { "directory": "./web", "entry": "./index.js" }
  }
}
```

`manifest.json` 静的なJSONです。バージョンが一致しています。 `package.json`:

```json
{
  "schemaVersion": 1,
```

<a id="sdk-and-host-services"></a>

## SDKとホストサービス

公共契約に依存する。輸入しないでください。 `@server/*`, `@core/*`, `@web/*`, `@db/*`ドカ・ソースの兄弟、またはグローバルブリッジです。サービスIDはインストール間で安定しています。ホストが実装を注入します。

```ts
import { definePlugin } from "@smartdoca/plugin-sdk";
import { filesServiceToken } from "@smartdoca/plugin-sdk/files";
import {
  httpServiceToken,
  usersServiceToken,
} from "@smartdoca/plugin-sdk/platform";
import manifest from "../manifest.json" with { type: "json" };

export default () =>
  definePlugin({
    manifest,
    async uninstall() {},
    injections: {
      required: [filesServiceToken, httpServiceToken, usersServiceToken],
    },
    async mount(context) {
      const files = context.inject(filesServiceToken);
      const users = context.inject(usersServiceToken);
      await context.inject(httpServiceToken).register(manifest.id, [
        {
          method: "GET",
          path: "/folders",
          async handle(request) {
            const user = await users.get(request, request.principal.id);
            const folders = await files.folders.list(
              { principalId: request.principal.id, signal: request.signal },
              { parentId: null },
            );
            return { user, folders };
          },
        },
      ]);
    },
  });
```

そのルートは `/api/v1/plugins/example.attachments/folders`IDはホストセッションから取得されます。ファイル操作では再び権限をチェックします。ローカルディスクパスではなく、安定したファイルIDと所有者バインドを保存します。 `users.get` ログインしたユーザー、または管理者が閲覧許可されているユーザーの情報を返します。連絡先情報やカスタムプロファイルフィールドも含まれます。パスワードハッシュや認証秘密は返されません。ブラウザのレスポンスを画面で必要なものに切り捨てます。

<a id="host-managed-persistence"></a>

## ホスト管理による永続性

`doca.storage` 正確にでなければならない `"host"`ステートレスでないプラグインを含む。マネージドストレージ契約への準拠を宣言しており、データベース名やサーバー選択子ではない。静的検査はサーバーコードの解決/インポート前にこれをチェックする。ZIP、npm/storeのインストール、オフラインディレクトリのインポート、共有アーカイブの復元、パッケージツールングでこのチェックが使用される。欠落フィールドのデフォルトやレガシーアダプターは提供されない。宣言は信頼できるプラグイン作成者のコミットメントであり、Node.jsサンドボックスやコード監査ではない。

プラグインのビジネスデータディレクトリ環境変数やプラグイン選択可能なデータパスは存在しません。 `DOCA_PLUGINS_DIR` ホストの再構築可能なインストールキャッシュであり、ビジネスストアではない。ホストのみがローカル/リモートの永続性を設定し、水平展開のための共有データベース/オブジェクトストレージを保証する。プラグインはどちらの場合も同じSDKメソッドを使用し、ホストサーバーベースで分岐してはならない。

ユーザーがアップロードしたもの、添付ファイル、エクスポートされた成果物が使用される `files.v1` 安定したIDを持つフォルダ/ファイル、バインディング、権限。構造化された記録、設定、ジョブ、カーソル、アウトボックスは、ホストが管理するリレーショナル機能に属する。その論理的なデータベース名は `plugin:<pluginId>` 信頼できるインジェクションによって制限される。プライベートな持続可能なバイナリはホスト管理のプライベートオブジェクト機能を使用し、認証情報はホスト管理の認証情報機能を使用する。プライベートオブジェクトはSDK 0.1.7でエクスポートされ、管理された認証情報はSDKソース0.1.8で提供される。一時的な作業では、将来のホスト管理のタスクワークスペースやストリームを使用することができ、制限やクリーンアップがあり、以前のインスタンスのパスへの持続可能な依存はない。必要なインターフェースとステータスについては、ストレージ契約を参照してください。

<a id="data-structure"></a>

## データ構造

`doca.dataVersion` 正確なプラグインのビジネス構造識別子であり、順序付きのバージョンや、新しいストアを通じて古いファイルを読み取れるという証拠ではありません。インストールされたアップグレードも同じ識別子が必要です。実際の構造はまだ検証が必要です。不一致は明確に失敗します。自動的にマイグレーションしたり、ダウングレードしたり、古いフィールドに値を入れたり、古いディレクトリをインポートしたり、二重の読み取り/書き込みを行ってはいけません。既存の自己管理データは変更されず、空の管理データベースとして使用されることはありません。今後の構造/サーバー変換には、別途承認された計画、検証、ロールバックが必要です。

<a id="uninstall"></a>

## アンインストール

インストールされたプラグインは実装する必要があります `uninstall(context)`スタートアップはそれなしでは工場を拒否する。ホックはビジネスの解除や外部の撤回を処理し、公共のホストサービスのみを使用する。イデムポテントである必要があり、ホストストレージパスを開いたり再帰的に削除したりすることはない。ステートレスなプラグインは空のホックを実装することができる。

管理されたプライベートデータベース/オブジェクトのクリーンアップはホストが担当する。ビジネスアンインストールが成功した場合、レジストリトランザクションが現在の世代をフェイスシールドし、プライベートテーブル/オブジェクトのクリーンアップを耐久性のある再試行でキュー化する。認証情報のクリーンアップと生成フェイスシールドが実装されており、クラスター内のビジネスタスクの排出は利用できない。ユーザーファイルやその他のビジネス参照情報は保持される。Hookの失敗はインストールを無傷のままにするが、外部Hookの効果は元に戻すことができない。すべてのインスタンスは依然として手動の再起動が必要である。

無効化、プロセスのシャットダウン、および `dispose` 永続データを削除せずにリリース登録、タイマー、接続を解除する。ユーザーファイル、文書ペイロード、他の企業が使用するバインディング、永続ファイルの受領書は、プラグインの削除によって自動的に削除されない。任意のファイルクリーンアップはファイルサービスを使用し、所有権、承認、残存参照を確認する。

## 背景情報の確認と通知

`users.status(userId)` 返却 `{id, status}` 信頼できるサーバーでの作業の場合はnullです。ステータスがアクティブでない場合は業務作業を停止します。アクティブなアカウントがあるからといって、ユーザーが業務リソースを読むことができるわけではありません。

`notificationsServiceToken` 輸出 `notifications.v1`: `publish(pluginId, {recipientId, key, title, body, path, resource: {type, id}})` そして `withdraw(pluginId, {recipientId, key})`ホストはプラグイン自身のpluginIdのみを許可する。 `key` 空でないこと、最大200文字以内であること。プラグインと受信者ごとに独立していること。同じパラメータを再再生すると同じ結果が得られる。 `{id}`異なるパラメータでは409が返される。取り消されたキーでは410が返される。プラグインのoutboxは取り消される前に公開される。

リソースタイプはpermissions.v1に登録されており、実装されています。 `notification.read`公開、リスト表示、未読数、および現在の権限を再確認するボタンをクリックします。存在しない、無効な、失敗した、またはタイムアウトしたソースは拒否されます。タイトルと本文は平文形式で、最大200文字、2000文字です。 `path` これはアプリ内のパスです。例えば `/mail/<id>?message=...`起源もハッシュもない。リンクはナビゲーション前にホスト認可エンドポイントを通過する。プラグインページとAPIは依然として自己認可を行う。

このインスタンスで公開すると、Webアプリが即座に更新されます。Webアプリは30秒ごとに他のインスタンスと同期します。これらはアプリ内通知です。SMTP、モバイルプッシュ、デスクトップ通知ではありません。

HTTPの登録では、デフォルトでボディのサイズが1MiBに制限されます。添付ファイルのような、より大きなボディが必要なルートでは、それを設定することができます。 `bodyLimit` バイト数では、最大32MiBです。プラグインは依然として添付ファイルの数、デコードされたサイズ、およびビジネス総計をチェックします。

## 統一されたコンテンツ：読書、検索、知識サービスの購読

使用する `@smartdoca/plugin-sdk@^0.1.9`. 輸入 `contentServiceToken` そして、 `ContentSource` type from `@smartdoca/plugin-sdk/content`; トークンを宣言する `injections.required` マウント時にソースを登録する。ソースは登録するプラグインに属する。内蔵ドキュメントやファイルも同じ契約を使用する。

| メンバー                                        | 契約                                                                                                                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 宣言                                   | `id`, `pluginId`, `version: 1`、局所化 `title`, `contentTypes`, `purposes`, `capabilities: {search}`, `configSchema`                                                                                     |
| `list(ctx, {config, cursor, limit})`          | 必要。返す `{items, nextCursor, snapshot}`各項目には含まれています `ref: {sourceId, resourceId, blockId}`, `fingerprint`, `title`、オプション `order`, `anchor`, `excerpt`; ここでは全身を返さないでください。 |
| `read(ctx, {config, ref, fingerprint})`       | 必要です。権限を再確認し、商品を返送してください。 `text`利用できない場合は、またはnullです。変更された指紋は衝突であり、古い指紋の下に新しいテキストは決してありません。                                       |
| `resolve(ctx, ref)`                           | 必要です。アクセス権を再確認し、返却してください。 `{path, fingerprint}` またはnull。 `path` アプリ内の現在位置です。                                                                                                     |
| `search(ctx, {config, cursor, limit, query})` | オプション；一緒に宣言し、実装する。軽量なページを返す。サポートされていない検索は完全なスキャンに遷移しない。                                                                                  |

`ctx` 認証済みである `principalId`, `purpose` (`knowledge`, `analysis`、または `search`) とキャンセル `signal`プロバイダは各通話において現在のビジネス許可を適用する。分析をサポートするソースは、メール特有のAPIなしで将来のタスクプラグインを提供できる。消費者はそれを使用する。 `sources(ctx, purpose)`、それからサービス `list/read/search` と共に `sourceId` そして `purpose`；サービス `resolve` 取る `{ref, purpose}`そのソースが指定した目的のみを要求してください。

ページネーションはnullで始まり、終わります。トラバース中のすべてのページは一貫したスナップショットを共有しなければなりません。異なるデータを使い続けるのではなく、期限切れ時にエラーが発生するようにします。このカーソルは、完全な承認済み在庫をページネーションするためのものであり、耐久性のある変更ログではありません。 `listChanges` そして `readChanges` この契約によって必要とされること、または輸出されることはありません。ソースは内部で自社のビジネスシステムを同期させることができますが、Docaはその実施を要求していません。

知識は既存のサブスクリプションおよびスケジューリングシステムを利用する。ユーザーが明確にソース、ライブラリ、設定を選択する。ホストは参照情報やブロックの指紋を保存し、全体的な在庫を比較し、新しいまたは変更されたブロックのみを読み取り/分析する。追加の完全なソース本体のミラーを保持する必要はない。変更されていないブロックは再読み込みする必要はない。完全で一貫した在庫のみが削除の根拠となる。失敗したり部分的な実行があった場合は、それを認識しない。安定したブロックの識別情報は、文書の全レビューや位置付けされた段落のインデックスに依存してはならない。

削除、解除、撤回、または利用できないソースの場合、派生知識は新しい通常読み取り、リスト、検索、回答検索から隠されます。手動で編集された結果を含む、管理者の処理のためにコンテンツは保持されます。既に配信されたコンテンツや既に開かれた共同編集接続は、このチェックによって遡及的に撤回されません。設定UIはプリミティブフィールド、列挙型、文字列配列をサポートします。複雑な設定はプラグイン自身のUIに属します。この統合により、データベーススキーマの移行、二重読み取り/書き込み、旧ソースアダプターは追加されません。SDKは依然としてエクスポートを行います。 `knowledge.sources.v1`しかし、これは新しい統合機能のサブスクリプション情報ではなく、自動的に適応されるものではありません。 `content.v1`.

制限：1ページあたり100件の在庫品、10万件の探索、200万文字の本文、分析実行時120,000文字の変更された本文、そして20秒のソースコールの締め切り。巨大すぎる、または不完全な作業は明確に失敗する。切り捨てずに「完了」とすることはできない。HTTPエンドポイントは `/api/v1/content/sources` そして `/api/v1/content/{list,read,resolve,search}`。参照 [正確なプロトコルと制限](plugin-content.ja.md) リクエスト形状とサブスクリプションルートのため。

## ネイティブキャッシュとアタッチメント

Webとスコープ付きモバイルWebViewの両方で同じWebバンドルを使用します。 `PluginWebHost` から `@smartdoca/plugin-sdk/web` 暴露する `native`Web上ではnullです。ネイティブ型はエクスポートされます `@smartdoca/plugin-sdk/native`.

- `native.storage` 供給物 `get`, `set`, `remove`, `clear`文字列値はサーバー、ログインしたユーザー、プラグインによって隔離されます。制限は2百万文字/値、20百万文字/プラグインです。ログアウトまたはアカウント削除によりアカウントのキャッシュがクリアされます。プラグインはオプトイン方式です。IndexedDBは移行されず、オフラインでの冷启动は保証されません。
- `native.attachments.save/share({path, name, mime})` 認証されたネイティブディスパッチを通じて関連するプラグイン-APIパスをダウンロードする。ネイティブ認証情報はWebViewに入らない。リダイレクトは拒否され、サイズは32 MiBに制限される。一時ファイルはクリアされる。
- Androidの保存操作は完了またはキャンセルされることがあります。iOSの保存やシステム共有では表示されることがあるが、ユーザーが操作を完了したことを証明するものではありません。アカウント切り替えやページの削除により、未処理のリクエストがキャンセルされます。
- メールアカウントの結合はWeb上で行われます。ネイティブOAuthはこの提供範囲外です。

現在のSDKバージョンは0.1.11です。そのnpm公開情報は下記に記載されています。ホストテストやビルドは、独立したメールパッケージの統合やiOS/Androidデバイスの受け入れを代替するものではありません。これらはまだ進行中です。詳細は [ネイティブプロトコル](plugin-native.ja.md).

`@smartdoca/plugin-sdk@0.1.11` npm上で公開されています。レジストリの依存関係コンシューマーは、全16のパブリックエントリポイントをインポートし、モニタリング/テレメトリトークンと正確なSDKバージョンを検証します。これは、プロダクション用モニタリングプラグインやネイティブデバイスへの対応を確立するものではありません。
