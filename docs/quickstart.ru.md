# Быстро начать

[中文](quickstart.zh-CN.md)

Этот руководство устанавливает изображение, указанное в compose.yaml, на главном сервере, SQLite и локальном файловом хранилище. Необходимы Git, Docker Engine, плагин Docker Compose и домен, обращающийся к серверу. Обратный прокси на этом сервере может обслуживать HTTPS или надежный внутренний HTTP. Для запуска изображения не требуется Node.js или pnpm.

Это новая установка. Существующие развертывания должны читать… [требования к выпуску](releases/0.2.38.md) В первую очередь: добавочные изменения автоматически обновляются в поддерживаемом режиме совместимости; несовместимые базовые параметры и семантические изменения требуют отдельного обработки. Необходимо сохранить существующие базы данных, файлы и конфигурации.

Если сервер не может связаться с GitHub, передайте Compose, пример окружения, политику безопасности и скрипты администратора без клонирования исходного кода. Смотрите [Развертывание без доступа к GitHub](deployment-without-github.ru.md) для копируемого Compose и `.env` файлы, оффлайн доставка изображений и инициализация.

<a id="1-clone-the-repository"></a>

## 1. Клонировать репозиторий

Клонируй основной файл, чтобы получить текущую файл Compose и скрипты администратора вместе:

```sh
git clone --branch main --depth 1 https://github.com/workhold/doca.git
cd doca
```

<a id="_2-configure-env"></a>
<a id="2-configure-env"></a>

## 2. Настройка файла .env

```sh
cp docker.env.example .env
```

Для новой установки сначала сгенерируйте главный ключ учетных данных:

```sh
openssl rand -hex 32
```

Результат – 32 случайных байта, кодированных в виде 64 шестнадцатеричных символов. Редактировать `.env`Заменяя примерный домен на свой собственный HTTP(S) оригинальный домен `DOCA_CREDENTIAL_MASTER_KEY` с созданной стоимостью:

```dotenv
DOCA_ORIGIN=https://doca.example.com
DOCA_CREDENTIAL_MASTER_KEY=7a52d29ab6db9a08292b9585d0dc5551f4156c2d02953b4262611bc1ad82f9ab
DOCA_FILE_STORE_ID=local
DOCA_FILE_STORES_JSON='{"version":1,"stores":{"local":{"provider":"local","root":"/data/storage"}}}'
```

`DOCA_CREDENTIAL_MASTER_KEY` Необходимо для запуска даже без плагинов; отсутствующее, пустое или некорректно формматированное значение приводит к неудаче запуска. В примерах файлов содержится публичный, правильно форматированный образ; замените его на свой ключ для новой установки. Сделайте безопасную и отдельную копию, и используйте одно и то же значение при репликации и перезапуске. Существующие развертывания должны сохранять свой оригинальный ключ; не генерируйте его для обновления. Замененный ключ отклоняется проверкой отпечатка базы данных; существующий шифрованный текст не конвертируется автоматически. Смотрите [Управляемые учетные данные](plugin-credentials.ru.md).

Используйте только начальную точку, без подпатрона, запроса или фрагмента. Корневой символ с третьей точкой нормализуется. Сохраняйте `/data/storage` Внутри постоянного тома контейнера. `docker.env.example` для Docker; `.env.example` для [Разработка источника](development.ru.md).

Настройте реверсный прокси на том же сервере. Например, с использованием Caddy:

```caddyfile
doca.example.com {
    reverse_proxy 127.0.0.1:39120
}
```

Caddy завершает работу с TLS и передает трафик HTTP и WebSocket. DNS должен указывать на этот сервер, а прокси должен иметь возможность получить свой сертификат. Другие прокси должны сохранять… `Host` и передача улучшений WebSocket `/api/v1/ws`. Смотрите [развертывание](deployment.ru.md).

## 3. Снять изображение

```sh
docker compose pull
```

Compose использует изображение, указанное… `compose.yaml` На основном этапе скачивается готовая образовая файла; не выполняется сборка исходного кода.

<a id="_4-start-doca"></a>
<a id="4-start-doca"></a>

## 4. Начни Doca

```sh
docker compose up -d
docker compose ps
```

Подождите, пока контейнер станет здоровым. Реакция на здоровье:

```json
{"status":"ok","version":"<image version>"}
```

Если старт не прошел, проверьте. `docker compose logs --tail=100 doca`Порт Compose связан с `127.0.0.1`Доступ через браузер осуществляется через конфигурированное HTTP(S) источник через прокси.

<a id="_5-initialize-the-administrator-password"></a>
<a id="5-initialize-the-administrator-password"></a>

## 5. Инициализировать пароль администратора

В той же директории, что и `compose.yaml`, запустить:

```sh
bash scripts/bootstrap-admin.sh
```

Введите логин администратора, пароль длиной не менее 12 символов, и снова пароль. Скрипт отображает информацию на китайском языке; ввод пароля скрыт. У Doca нет стандартного аккаунта или пароля. Скрипт запускает один разовый контейнер для работы с той же базой данных и сохраняет хеш пароля. Если администратор уже существует, инициализация останавливается без изменения этого аккаунта.

Открыть `https://doca.example.com` и введите учетные данные. Не вводите логин администратора или пароль. `.env`Чтобы восстановить существующий аккаунт администратора, используйте [Сброс пароля](deployment.ru.md#change-a-password).
