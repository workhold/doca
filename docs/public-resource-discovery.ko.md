# 공공 자원, 발견물, 컬렉션

[中文](public-resource-discovery.zh-CN.md)

<a id="administrator-policy"></a>

## 관리자 정책

권한 및 가시성, 콘텐츠 권한, 공개 발견 설정에서 관리자는 문서, 라이브러리, 폴더를 개별적으로 설정할 수 있습니다:

| 모드 | 발견 카탈로그 | 수집 전 전체 텍스트 검색 | 수집 후 개인 검색 |
| --- | --- | --- | --- |
| 링크만 | 숨겨진 | 제외됨 | 포함됨 |
| 수집 후 검색 가능, 발견 가능 | 보여짐, 제목 검색 | 제외됨 | 포함됨 |
| 검색 가능하고 찾을 수 있는 전체 사이트 | 보여짐, 제목 검색 | 포함됨 | 포함됨 |

이 정책은 이미 공개된 리소스의 분배 방식을만 변경합니다. 비공개 리소스는 공개하지 않습니다. 세 가지 유형 모두 링크로만 연결된 경우, 공개 항목과 Visited 및 Collected 탭은 유지되며 Discover 탭은 숨겨집니다. API는 발견할 수 없는 리소스를 반환하지 않습니다.

새로운 정책이 저장되기 전까지는, 더 오래된 배포 설정은 이전의 의미를 유지합니다. 저장 시 세 개의 독립적인 값이 기록됩니다. `publicModes`역사적 방문 기록이 보관되어 있습니다.

<a id="personal-scope"></a>

## 개인 범위

방문은 방문 기록을 작성할 뿐, 리소스를 수집하지 않습니다. 오래된 자동 장치 `source=opened` 행들은 컬렉션 검색에 참여할 수 없으며 컬렉션 목록에도 나타나지 않습니다. 직접 제공된 지원금, 수락된 초대, 소유권은 각각 자체 규칙을 따릅니다.

세 가지 리소스 유형 모두 사용됩니다. `resource_collections`사용자별로 고유한 리소스 유형과 리소스 ID입니다. 공개 카탈로그는 자신이 소유하거나 이미 접근할 수 있는 공개 리소스를 숨기지 않습니다. 수집 과정에서 해당 리소스가 목록에 추가됩니다. 이는 이전의 할당에 의해 필터링되지 않습니다.

검색 후보는 이전의 범위, 선호 항목, 그리고 컬렉션 목록의 합성물입니다. 결과는 다시 현재 접근 권한과 비교됩니다. 컬렉션을 삭제하면 해당 목록 행만 삭제되며, 회원 자격이나 초대장은 변경되지 않습니다. 기존에 검색 가능했던 리소스는 여전히 검색 가능 상태로 유지됩니다.

현재의 스키마는 빈 컬렉션 테이블을 생성합니다. 시작 시에는 과거의 항목이 그 테이블로 복사되지 않습니다. 기존의 컬렉션 행은 그대로 유지됩니다. 자동 연결, 초대, 방문 기록은 컬렉션으로 처리되지 않습니다.

검색은 검색 가능한 모든 항목, 내 범위, 그리고 사이트 전체 공개 텍스트를 비교할 수 있습니다. 사이트 전체 텍스트는 관리자가 사이트 전체에서 검색이 가능하도록 허용한 리소스만 포함됩니다. 디스커버리 카탈로그의 제목 검색은 본문 검색이나 벡터 검색을 포함하지 않습니다. 파일 검색 및 AI 파일 검색도 컨테이너 컬렉션과 공개 검색 정책을 확인합니다.

<a id="containers"></a>

## 컨테이너

라이브러리나 폴더를 수집할 때는 현재 존재하는 내용과 나중에 추가된 내용이 포함됩니다. 쿼리는 이를 동적으로 결정합니다. 모든 자식 항목에 멤버십 행을 복사하지는 않습니다.

공공 도서관은 페이지의 읽기 범위를 설정합니다. 협력자 상속 기능을 비활성화한 페이지는 공공 읽기 기능은 여전히 활성화됩니다. 해당 페이지는 수정, 댓글, 권한 관리 기능을 설정할 수 있습니다. 점 참조와 목록 SQL은 동일한 공공 읽기 상속을 사용합니다. 도서관 내의 페이지는 도서관 발견 및 검색 정책을 사용합니다. 독립적인 문서는 문서 정책을 사용합니다.

폴더 게시물은 저장됩니다. `folder_publications`로그인한 사용자들은 현재 및 미래의 콘텐츠를 읽을 수 있습니다. 관리 기능은 제공되지 않습니다. 파일 관리 및 다운로드는 현재 로그인이 필요합니다. 익명 파일 접근은 불가능합니다. 게시가 비활성화된 후에는 현재 회원 자격에 따라 접근이 가능합니다. 컬렉션 자체는 접근 권한을 부여하지 않습니다.

페이지 권한 패널에서는 공공 도서관을 소스로 표시합니다. 폴더 공유 패널에는 공공 범위가 현재 및 미래의 콘텐츠를 포함한다고 나와 있습니다. 공공 컨테이너로 이동하면 해당 컨테이너와 함께 게시됩니다. 다른 위치로 이동하면 새로운 위치를 사용합니다.

<a id="discovery-ui"></a>

## 디스커버리 UI

공공 자원 페이지에는 문서, 도서관, 폴더별로 필터링된 방문한 자원, 발견한 자원, 수집한 자원이 있습니다. 방문한 자원에는 사용자가 열고 여전히 접근할 수 있는 링크만 포함됩니다. 방문 기록은 검색 자격을 생성하지 않습니다. 비즈니스 목록에는 더 이상 공공 자원 바로가기가 없습니다.

집에 돌아가다 `/home` 문서, 라이브러리, 폴더, 파일에 대한 최근 방문 기록을 요약하며, 미결제 티켓과 라이브러리 결정 사항도 포함됩니다. 문서가 이동되었습니다. `/documents` 내가 소유한 최근 방문 기록, 공동 작업, 선호 항목, 그리고 내 컬렉션을 유지합니다. 라이브러리의 기본 '모든 보기'는 소유권, 공동 작업, 선호 항목, 컬렉션을 결합합니다. 사이트 전체 공개 카탈로그는 자동으로 표시되지 않습니다. 공유 폴더에는 선호 항목이 없습니다. 이 폴더는 내가 공유한 것, 나와 공유한 것, 그리고 수집한 모든 것을 제공합니다.

공개 목록에는 수집 및 미수집 기능이 있습니다. 문서의 메뉴에는 수집, 미수집, 그리고 사용자가 삭제할 수 있는 삭제 기능도 포함됩니다. 선호 항목 및 핀은 단축키로 유지됩니다. 리소스 상세 페이지에는 추가적인 수집 항목이 추가되지 않습니다.

홈 통계는 현재 사용자가 접근할 수 있는 데이터를 사용합니다. 티켓은 유일한 승인 및 수락 단계를 재사용합니다. 라이브러리 결정은 유지 관리 권한과 대기 중인 캘리브레이션을 재사용합니다. 처리된 후에는 홈을 떠납니다. 소스 장애는 별도로 표시되며 0개의 대기 항목으로 제시되지 않습니다. 첫 번째 버전은 내장 소스를 사용합니다. 아직 외부 플러그인 홈 SDK는 없습니다.

문서와 도서관은 사용됩니다. `resource_visits`파일과 폴더는 사용됩니다. `workspace_activity`최근 방문은 다시 허가되며, 시간에 따라 결합되고 페이지로 나뉩니다. 파일 미리보기를 열는 것은 방문으로 간주됩니다. 목록 미리보기는 그렇지 않습니다.

첫 번째 단계에서는 제목 검색, 업데이트 시간 기준 순서, 안정적인 페이징, 데이터 수집, 배치 데이터 수집 기능이 제공됩니다. 라이브러리는 컨테이너 형태로 표시되며, 그 페이지들은 목록으로 평면화되지 않습니다. 검색은 데이터베이스 카탈로그를 사용합니다. 새로운 Meilisearch 종속성이나 추천 피드는 없습니다.

## 확인

`tests/public-discovery.test.ts` 타입별 분배를 위한 격리된 데이터베이스를 사용하며, 데이터를 수집하지 않는 방문, 새로운 컨테이너 내용, 취소, 카탈로그와 전체 텍스트 비교, 폴더 관리, 페이징, 그리고 HTTP 설정 검사가 이루어집니다. 권한 상속 테스트는 공개 컨테이너 읽기 규칙에 따라 진행됩니다.
