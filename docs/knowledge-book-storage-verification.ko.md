# 지식북 저장소 검증 및 운영

[简体中文](knowledge-book-storage-verification.zh-CN.md)

전체 계획은 2026-10-12에 명시적으로 승인되었습니다. 구현 및 격리 검증은 2026-10-13에 완료되었으며, 그 검증 과정에서 사용자 데이터베이스가 변경되거나 프로덕션 환경에 배포되지 않았습니다. 참조하세요. [실행 계획](knowledge-book-payload-storage-plan.md).

<a id="automatic-startup-upgrade-in-0124"></a>

## 0.1.24에서 자동 시작 업그레이드 기능이 추가됨

모든 오래된 호스트를 중단하고 SQL, 개인 저장소 및 설정 정보를 백업하세요. 0.1.22 버전이 출시된 이후 0.1.24부터 적용됩니다. `doca-2026-10-09-history-storage-v1` 전체 스키마를 현재 DDL과 자동으로 비교합니다. 계획이 검토를 통과하면 스키마 잠금 트랜잭션이 명시된 추가 내용을 조정하고 목표 생성 내용을 기록합니다. 기존의 SQL으로 생성된 결과물, 실행 및 인간 작업을 포함한 모든 비즈니스 행과 출판 포인터는 변경되지 않은 상태로 유지됩니다. 기존의 0.1.23 객체 저장 데이터는 바이트 정확하게 유지됩니다. 수동적인 책 명령이 필요하지 않으며, 별도의 정리, 자동 변환 또는 레거시 런타임 리더가 추가되지 않습니다. 남아있는 오래된 책 결과물은 사용할 수 있게 되기 전에 수동 처리가 필요할 수 있습니다.

모든 구조/생성 변경 사항은 실패 시 원상복구됩니다. 반복적/동시 시작 시 모든 행이 유지됩니다. 알 수 없는, 이전의 및 중단된 생성 과정은 데이터를 변경하지 않고 중단됩니다; 관련이 없는 알 수 없는 테이블은 여전히 검토가 필요합니다. 모든 데이터를 보존하고 업그레이드 후 백업 복구 과정에서 저장합니다. 모든 호스트 및 웹 인스턴스를 함께 업데이트합니다.

아래의 기존 유지보수 명령은 오래된 생성된 결과를 사용 가능한 네이티브 형식으로 보존해야 할 경우 선택적입니다. 첫 번째 시작 전에 업그레이드를 실행하세요; 스키마 정렬은 소스 생성 방식을 변경합니다. 아래의 역사적 검증 결과는 남은 SQL JSON의 자동 적응이 아닌 선택적 변환임을 보여줍니다.

자동 정렬 증거: SQLite/PostgreSQL 17/18에서 실제로 배포된 0.1.22 장치는 114개의 비즈니스 테이블과 20개의 SQL 객체의 모든 행을 유지했습니다. 새로운 네이티브 객체는 반복적/동시 시작 후에도 읽을 수 있었습니다. PostgreSQL 17/18은 롤백 및 엄격한 레거시 객체 거부를 포함한 91개의 회귀 테스트를 통과했습니다. 보기 [확인](verification/book-schema-startup-2026-10-13/verification.json).

<a id="maintenance-commands"></a>

## 유지 관리 명령

이러한 변경 사항과 기존 배포 환경이 포함된 새로운 호스트 빌드를 사용하세요. 배포되었습니다. `smartdoca/doca:0.1.22` 변환 소스이며 새로운 명령어는 포함되어 있지 않습니다. 모든 호스트를 중지하고 SQL(SQLite WAL 포함), 개인 객체 및 설정 파일을 백업합니다. 원본 마스터 키를 보존하고 ID와 백엔드 설정을 저장합니다. 모든 호스트와 웹 빌드를 함께 업데이트합니다.

이 명령은 초기화 없이 기존 데이터베이스를 열어줍니다. 기본 모드에서는 전체 읽기 전용 프리플라이트가 수행됩니다. 적용하기 위해서는 `--apply --hosts-stopped` 새로운 복구 매니페스트 경로도 있습니다. 매니페스트는 0600 모드를 사용하며, 본체 미러링 없이 원래의 파일 크기, 소유자 정보, 크기 및 해시를 그대로 유지합니다.

```sh
pnpm knowledge-books:storage upgrade
pnpm knowledge-books:storage upgrade --apply --hosts-stopped --manifest /secure/book-upgrade.json
```

단지 `doca-2026-10-09-history-storage-v1` 승인됩니다. 이전 세대는 먼저 정확한 지원된 역사 변환을 완료해야 합니다. 책 작업 실행, 알 수 없는 파일 형식, 손상된 데이터 및 검토가 필요한 구조적 차이 블록 변환을 부분적 작성 없이 수행합니다. 알 수 없는 작업을 취소하거나 역사적 필드를 생성하거나 SQL을 지우는 대신 특정 조건을 해결합니다.

중단 후, 일반 시작 과정은 진행 상황 생성을 거부합니다. 동일한 매니페스트 경로로 같은 명령을 다시 실행하세요. 변환된 바이트는 여전히 그 매니페스트와 일치해야 하며, 매니페스트를 바꾸는 것은 변경된 데이터를 무시할 수 없습니다. 완료되면 시작 과정은 그대로만 인식합니다. `doca-2026-10-12-book-payload-storage-v1`독립적인 심장 박동 기능은 시작 후 남아 있는 알림을 조정합니다; 완료된 역사적 작업은 다시 채워지지 않습니다. 역사적 결과물과 오류는 그대로 보존됩니다.

현재 롤백은 비비어널을 거부합니다. `knowledge_book_batch_checkpoints` 수정 전: 그들의 참조는 별도로 승인된 보존/복구 계획이 필요합니다. 체크포인트를 삭제하거나 생성/구조 검사를 우회하지 마세요. 참조하세요. [체크포인트 보존 및 복구](knowledge-book-generation-performance.ko.md#deployment-retention-and-recovery)아래의 역사적 왕복 과정은 배치 체크포인트 이전의 것으로, 임의적인 현재 버전에서 0.1.22로의 하향판정을 확인하지 않습니다.

적합한 롤백을 위해 모든 호스트를 중단하고 새로운 백업 및 복구 매니페드를 보존합니다. 모든 객체를 사전 검사하여 원본 바이트를 확인합니다. 업그레이드 후의 작업도 복구하며 클라우드 객체와 복구 자료도 보존합니다.

```sh
pnpm knowledge-books:storage rollback
pnpm knowledge-books:storage rollback --apply --hosts-stopped --manifest /secure/book-rollback.json
```

중단된 롤백이 원래의 매니페스트로 다시 시작됩니다. 모든 JSON이 복원되고 검증된 후, 저장소 확장 테이블 4개만 제거되며 검토된 파운틴/구버전 데이터가 기록됩니다. 목표는 이전 버전의 0.1.22 호스트입니다. 선택적 더 오래된 문서 기록 롤백이 이루어지기 전에 전체 책 롤백이 완료됩니다. 해제된 SQLite 페이지는 자동으로 파일을 축소하지 않으며, 자동 VACUUM 작업도 수행되지 않습니다.

## 단독 증거

실제 소스 이미지는 `smartdoca/doca:0.1.22`, 이미지 ID `sha256:a5316eb01bf25b0d89801139de85d34a35528be376699c4981ab8a09fd14f04c`실제 실행자는 출판된, 실패한, 그리고 출판 대기 중인 합성 작업을 생성했습니다. 생산 데이터베이스나 사용자 문서는 접근되지 않았습니다.

각 SQLite/PostgreSQL 17/PostgreSQL 18 환경에서는 20개의 비비공백 원본 객체가 포함되어 있었습니다. 명시적인 업그레이드, 두 번의 일반적인 시작 과정, 그리고 명시적인 롤백 작업을 통해 모든 20개의 원본 JSON 바이트 시퀀스와 해시가 확인되었으며, 상태, 오류, 설정 및 인간 작업도 그대로 보존되었습니다. 기록들은… `docs/verification/knowledge-book-storage-plan-2026-10-12/actual-roundtrip*.json`.

| 원본 SQL 본문 바이트 수 | 3,698,834 | 3,698,834 |
| 새로운 SQL 참조 바이트 | 7,170 | 7,170 |
| 연속화된 메타데이터 JSON 바이트 | 403,190 | 404,294 |

메타데이터는 객체, 참조, 작업 및 의존성 엣지를 시퀀스화합니다. 이는 물리적인 SQL 페이지/인덱스/WAL 또는 백업 측정값이 아닙니다. 이러한 합성된 문장은 과도하게 반복되며, 실제적인 절감 효과를 입증할 수 없습니다.

회귀 사례에는 제한된 부분, 이탈/유니코드, 책 내부 공유 및 책 간 격리, 경쟁적인 업로드, 중단/재시작, 손상, 부분적인 DDL 없이 알 수 없는 형식에 대한 거부, 더 새로운 작성 내용의 롤백, SQL만을 사용한 요약, 캐시 권한 철회, 휴지/삭제 및 늦은 업로드 정리가 포함됩니다. CI PostgreSQL 매트릭스에는 지식 책 및 페이로드 테스트도 포함됩니다.

브라우저 증거 `lazy-candidate.json` 아무런 급한 바디 읽기도 없고, 확장 시 한 번의 읽기, 다시 열 때 재사용, 취소 후 바디 제거, 브라우저 오류도 없습니다. Mermaid의 안정성은 별도로 기록되어 있습니다. `docs/verification/knowledge-book-reliability-2026-10-12/preview-result.json`.

<a id="operational-boundaries"></a>

## 운영 경계

프라이빗 로컬/S3 설정은 공개된 바디 URL이나 모듈 소유의 자격증명 없이 재사용됩니다. SQL 및 객체를 일관된 집합으로 백업합니다. 누락되거나 손상된 객체는 참조를 유지하면서 명시적으로 실패하며, 비어 있는 바디는 사용할 수 없는 콘텐츠를 대체할 수 없습니다.

정리 작업은 접근할 수 없는 객체만 삭제합니다. 휴지통은 참조를 유지하며, 영구 삭제는 그 참조를 해제합니다. 실시간 업로드에 필요한 종속성은 보호되며, 실패하거나 지연된 업로드도 재시도를 위해 지속적인 키를 유지합니다. 완료된 저널은 동시에 발생하는 물리적 업로드를 제외한 객체만 유지하는 반면, 설치된 종속성은 객체/엣지에 남아 있습니다. 역사적 TTL은 추가되지 않습니다.

마지막 검사: 126개 사례에 대한 SQLite 관련 스위트가 통과되었고, 최종 엔드포인트/권한 검사 후 60개 사례에 대한 책/페이로드 스위트도 통과되었습니다. PostgreSQL 17/18에 관련된 68개 사례의 스위트도 모두 통과되었으며, 두 엔진에서 최종 11개 사례의 페이로드 스위트도 통과되었습니다. 타입 검사, 웹 빌드, 문서링크 및 diff 공백 검사도 통과되었습니다. 확인하세요. `docs/verification/knowledge-book-storage-plan-2026-10-12/verification.json`하트비트와 객체 정리는 독립적인 스케줄링을 사용하므로 클라우드 요청이 하트비트 조정에 영향을 주지 않습니다.
