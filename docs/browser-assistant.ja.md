# ブラウザアシスタント

アカウントメニューを開く → **ブラウザアシスタント**、または `/#/browser-assistant`選択したウェブコンテンツや、画像が含まれるページ全体をキャプチャし、拡張機能のサイドバーでDoca AIアシスタントを利用しましょう。

## インストールしてログインする

Docaでキャプチャプロファイルを作成する：選択したデスティネーションの下で新しい文書を作成するか、既存のリッチテキスト/Markdown文書に追加する。デフォルトプロファイルやタイトルルールを設定する。`{title}`, `{date}`）とAIの指示。生成された知識ブックのページは、直接追加対象にはできません。

設定タブの上にあるボタンを使って、設定された拡張機能をダウンロードして解凍します。Chrome/Edgeで開発者モードを有効にし、解凍したフォルダを読み込みます。Manifest V3にはChromium 116以上が必要です。自己ホスト型のZIPファイルはクリックでインストールできる形式ではなく、配布やエンタープライズ署名のサポートも提供されていません。インストール前に開いたページを再読み込みして右側のツールバーを表示し、拡張機能からのキャプチャは必要に応じてスクリプトを実行します。

このアーカイブには、アカウントの認証情報やアクティベーションの期限は含まれておらず、Docaアドレスのみが記載されています。拡張機能を開く際には、このブラウザの既存のDocaサインインを使用します。ログアウトされている場合は、通常のDocaログインページが表示され、ログインして拡張機能に戻ります。Docaタブを閉じてもログアウトは行われません。ウェブサイトのログアウト、有効期限切れ、またはセッションの無効化により、関連するブラウザアクセスが無効になります。アカウントを切り替えると、そのアカウントのプロファイルが再読み込みされ、未完了のデータやAIの状態が接続によって隔離されます。

この拡張機能は、ウェブサイトのクッキーを読み取ったりコピーしたりすることはありません。同じオリジンを持つDocaページは、SHA-256のチャレンジとランダムな検証器を用いて、60秒間の一時的な認可コードを提供します。交換される制限付きトークンは10分間有効で、信頼できる拡張機能のセッションストレージに保存され、自動的に再認可されます。サーバーはハッシュ値を保存し、各操作時に元のウェブサイトのセッションをチェックします。クッキーの制限により拡張機能側の調査ができない場合、同じオリジンのページがログインを検証します。受動的なポーリングでは、証明を最大30秒間再利用でき、ユーザーキャプチャやAI操作では再チェックが行われます。

## キャプチャ、AI、サーバーアドレス

ためには **新しい文書を作成する**目的木内で「個人文書」や「ライブラリのルート」、または特定の文書を選択します。選択方法は文書の移動ダイアログに従います。ライブラリは最近の文書とは別にページングされ、さらに多くのライブラリを読み込む機能を利用できます。保存されたプロファイルを再開すると、その目的が拡大され表示されます。読み取り専用の文書は無効な祖先として表示されます。読み込み失敗は選択内容を変更せずに再試行できますが、利用できない目的では保存ができません。既存のライブラリの概要の制限は10,000ノードで、制限に達した場合は警告が表示されます。知識ブックで生成されたコンテンツは読み取り専用のままです。追加対象は引き続き文書検索機能を利用できます。

通常のウェブページには、5個の右側に固定されるアイコンが表示されます。 **このページをキャプチャする、選択範囲のキャプチャ、Docaアシスタント、Docaウェブサイトと設定を開く**Docaウェブサイトを開くと、ログアウト状態であっても、現在設定されたサイトが新しいタブで開きます。サイトの設定が欠落または無効な場合は、拡張機能の設定画面が開きます。トップのハンドルを垂直に動かすことで、ツールバーをウェブページのコントロールから離すことができます。この位置は再読み込み、新しいウェブページ、ブラウザの再起動でも保持されます。ハンドルがフォーカスされている状態では、矢印キー、ホームキー、エンドキーも機能します。設定の下にある下の矢印はツールバーを折りたたんだり広げたりできます。折りたたまれたハンドルは引き続き動かすことができます。ツールバーは表示される前に、自分の位置のキャッシュを読み取ります。テキストを選択しても、別のアイコンやツールバーは表示されません。

キャプチャアイコンをクリックすると、確認バブルのカスタムドロップダウンでそのルールと送信先を確認し、確認を実行します。選択したテキストを先に選択してキャプチャを行います。全ページキャプチャでは、ビューポートを超えるトップレベルDOMも含まれます。デフォルトのルールは既に選択されており、他のルールも利用可能です。各開封時にはサインインと現在のプロファイルを再確認します。一時的な失敗は再試行可能で、プロファイルが欠けている場合は設定ページにリンクされます。バブルや拡張機能のポップアップから再試行すると、元のデータとリクエストIDを再利用でき、コミットされたコンテンツが重複することはありません。送信されていないデータは現在のブラウザセッションに保持され、ブラウザを閉じた後に再度選択する必要がある場合があります。拡張機能を更新または再ロードした後、古いページスクリプトがそのページを再ロードするよう求めます。

Docaアシスタントアイコンをクリックすると、ブラウザの右側のパネルが開き、同じDocaチャットUI、モデル選択器、Markdown、進捗状況、承認情報が表示されます。このパネルを開くとモデルが呼び出されません。新しいメッセージを送信すると、最新のアクティブページが読み込まれ、タブの切り替えやナビゲーション、ページ内のルートによって参照が更新されます。メッセージを再試行すると、元の内容が保持されます。サポートされていない、または利用できない画像であっても、AIがテキストを読むことを妨げることはありません。利用できない画像の場合も、アーカイブ時にはソースのプレースホルダが保持されます。歓迎メッセージには、保存、要約、重要点の抽出、ウェブコンテンツの整理に関する情報が含まれています。添付ページのチェックボックスはありません。AIはDocaのモデル、計測、承認フローを使用します。Doca内で会話を続行できます。接続は最初はAIが利用でき、Docaで接続を編集することで名前を変更したり、AIを切り替えたりできます。アカウントやモデルのポリシーは依然として適用されます。

最初の受け入れられたメッセージは、ページ名、リクエスト、ホスト名から新しい会話を指し、ブラウザのアイコンでその出所を識別します。新しく追加されたページは、両方の画面の操作リソースに表示され、URLごとに1件のエントリが新しいタブで開きます。これらのリンクは文書へのアクセスを提供しません。ルール編集後、アシスタントを再開すると、記憶されている会話が古いバージョンに属している場合、現在選択されているルール用のコンポーザーが開始されます。元の会話と保留中のメッセージは保持され、古いタスクは新しいルールに静かに復元されることはありません。既存のタイトルや会話は埋め戻されたり書き直されたりしません。

現在の拡張バージョンは **0.2.11**拡張機能を開くと、設定されたDocaサイトが提供するパッケージバージョンがチェックされます。接続が更新されると、開いている間少なくとも5分ごとに再チェックが行われます。設定では手動でチェックすることも可能です。新しいパッケージの場合、ポップアップやAIサイドバーに通知が表示され、そのサイトのダウンロードページにリンクが付けられます。Docaではバージョンと完全なファイル名が表示されます。 `doca-browser-assistant-<version>.zip`、拡張機能からのもの `manifest.json` サーバーバージョンとは独立しています。Docaを更新した後、Chrome/Edgeで拡張機能をダウンロードして再読み込みしてください。サーバー更新はインストールされている拡張機能を置き換えることはありません。通常のキャプチャにはAIモデルは不要です。AIサイドバーには、サイトが許可するモデルが設定されている必要があります。

バージョンチェックは新しいサイトパッケージのみを報告するだけです。プロトコルの互換性を判断したり、操作を制限したりすることはありません。エンドポイントが欠落している、有効でない応答、またはネットワークエラーが発生した場合、互換性や最新バージョンであることを示すのではなく、チェックが失敗したと表示されます。設定、認可、保留中のデータフォーマットは変更されず、歴史的データは移行されたり削除されたりしません。既存の拡張機能は、これらの通知が表示されるためには1回の手動更新が必要です。

通常のHTTP(S)ページがナビゲーション後にキャプチャ受信器が存在しない、またはインストール前に開かれた場合、キャプチャはバンドルされたスクリプトを自身のトップフレームに読み込み、ページを再読み込みせずに一度再試行します。この拡張機能は宣言しています。 `scripting` この復元のために、既存のHTTP(S)サイトアクセスも利用されている。ブラウザ制限されたページやサイトアクセス拒否は依然として明確に機能しない。

新しいAIからの送信内容は、入力が処理される前にIndexedDBにトランザクションとして保存され、Docaサイト、アカウント、接続、選択されたプロファイルに基づいてスコープが設定されます。送信されたメッセージ、失敗したメッセージ、受け入れられたメッセージは、会話内で一度だけ表示されます。送信待ちのメッセージのみが保留リストに表示され、AIが返信するまでそこに残ります。リフレッシュ操作により、元のメッセージIDを再開できます。サーバーがすでに受け入れた作業は、新しいページのキャプチャや送信が行われる前に調整されます。以前のlocalStorageの保留メッセージは変更されず、現在のモデルとスコープを選択した上で「Continue」または「Withdraw」を明示的に実行する必要があります。

右側の設定アイコンを使って、独立した設定ページを開き、Docaでのキャプチャルールを管理したり、編集したりします。 **Docaサーバーアドレス**例えば `https://doca.example.com`、なしで `/api/v1`他のパスやクエリパラメータです。拡張機能のポップアップにも設定項目が保持されます。また、Doca内の公開サイトの設定をコピーし、拡張機能の拡張可能な設定セクションに貼り付けることもできます。 production環境ではHTTPSが必要ですが、開発時にはループバックHTTPも許可されます。厳格なフォーマットです。 `{ "version": 2, "origin": "https://doca.example.com" }`切り替えサイトでは、ログインしているアカウントを確認し、以前のサイトの保留中のデータは送信しません。

## 撤回し、復元する

Doca内の1つまたはすべてのブラウザ接続を無効にする。アクセスキーや未処理のコードは機能しなくなり、関連するブラウザAIの処理もキャンセルされる。ウェブサイトにサインインしても無効になった接続は復元されない。Docaで「接続を復元する」を選択し、その後拡張機能を再接続する。自動認可機能はインストールのバインドを再利用するため、無効化を回避するために別の接続を作成することはできない。

保存された文書、元の画像、会話内容は残ります。撤回やログアウトでは、既に実行されたトランザクションは元に戻せません。同じ会話内のウェブサイト由来のAI処理は独立して続きます。ブラウザのツールやコミットの境界が現在のウェブサイトセッションを検証し、ログアウト後にはその処理がキャンセルされます。一方、他の実行者はハートビートや操作の境界で再び承認を確認します。

## 制限とアップグレード

アップグレードやロールバックを行う前に、キュー送信を停止し、すべての古いDocaページと拡張機能を閉じてください。古い送信器と新しい送信器を同時に実行しないでください。localStorage、IndexedDB、保持されたトムストーン、およびその後のすべてのデータを保持してください。ロールバックではキュー送信が無効になります：新しいストアをlocalStorageにエクスポートしたり、古い送信器を再有効にしたりしません。安全な送信器無効化機能がない古いバージョンでは、キュー送信を再開することはできません。詳細は…をご覧ください。 [承認された保存およびロールバック契約](verification/issue-tracker-2026-10-21/ai-pending-idb.md).

キャンバスはセマンティックなテキスト、見出し、リスト、コード、リンク、通常のテーブル、出典情報、画像を保持します。任意のCSSやインタラクション、ロードされていないデータ、ページネーション、iframes、閉じられたシャドウルート、仮想リスト、キャンバス、ビデオは再現されません。静的SVG画像やインラインスVGは、透明なPNG形式に変換され、スクリプトやイベントハンドラーは削除されます。外部リソースを必要とするSVG、埋め込みされたHTML、アニメーション、またはサポートされていないレンダリングを必要とするSVGは、プレースホルダでマークされます。

新しい静的PNG、JPEG、WebP画像が追加されました **4MBまたは2500万ピクセル** アップロード前に圧縮され、最大4MiBに収まる。最長辺は4096ピクセル、ピクセル数は1600万ピクセル。ソースエンコーディング、PNG/WebPのアルファチャンネル、EXIFの表示向きも保持される。小さな画像は元のバイト数のままである。GIF、アニメーション付きWebP、APNGは決して平らにされない。既存の20MiBまたは2500万ピクセルの制限を超えるアニメーションは、ラベル付きのプレースホルダに置き換えられる。再試行時に既に保存された画像やアップロードされた画像は再処理されない。ソースデータは64MiBに制限され、静的デコーディングは1000万ピクセルに制限される。SVGソースの転送は32MiBに制限され、拡張メッセージを管理する。SVG出力は最長辺が4096ピクセル、全体で1600万ピクセルに制限され、その後PNGの圧縮制限に従う。

サーバーの制限は、1枚の画像あたり20MiB/2500万ピクセル、合計100枚の画像で100MiBとなります。Markdownのサイズは512KiBまでです。新しいキャプチャ処理は、タスクを作成する前に画像を処理します。サポートされていない、読み取り不可能、または変換不可能な画像は、元の位置に理由と元のHTTP(S)ソースリンクと共に読み取り可能なプレースホルダになります。他の画像やテキストは引き続き保存されます。Blob/データURLはプレースホルダリンクとして保持されません。認可、クォータ、ストレージエラーは保存を停止します。ステージングが完了すると、正確なマニフェストとリクエストIDは再試行用に固定され、アップロード中に発生した画像処理エラーはコミット時にプレースホルダになります。ネットワーク、認可、クォータ、ストレージ書き込みエラーは提出を停止します。保留中のタスクは24時間後に期限切れになり、クリーンアップは未バウンドオブジェクトのみを削除します。

Extension 0.2.6は、データベースの変更なしで、既存のv1キャプチャプロトコルとラスターアセット形式を使用します。所有者は、保存された文書、アップロードされた画像、過去の失敗したタスクを変更せずにそのままにすることを承認しました。拡張機能とソースページを更新/再読み込みした後、古い失敗に対して新たなキャプチャを開始します。古いタスクは自動的に変換されたり再送信されたりせず、通常の有効期限が保持されます。ロールバックにはデータ変換は不要で、既存の文書やタスクはそのまま保持されます。ステージングされたペイロードや歴史的文書は自動的に書き換えられません。
