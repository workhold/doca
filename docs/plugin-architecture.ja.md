# プラグインアーキテクチャ

[中文](plugin-architecture.zh-CN.md)

それ [SDK契約](plugin-sdk-contract.ja.md) コアプラグインとビジネスプラグインの境界を定義する。 [開発ガイド](plugin-development.ja.md) 現在存在するインターフェースをリストしています。

`plugin-contracts` マニフェストとライフサイクルを定義する。 `plugin-sdk` 注入、イベント、貢献、効果を提供する。 `plugin-host` 依存関係をチェックし、プラグインを起動した後、逆順で終了させる。コンポジションはコアファイル、ドキュメント、検索、AIを組み立て、その後、別のインストールディレクトリからビジネスプラグインを読み込む。

ビジネスプラグインは、パブリックファイル、ユーザー、パーミッション、HTTP、ポリシー、イベント、AIサービスを通じてホストと通信します。登録はプラグインインスタンスに属します。プラグインはホストのプライベートデータベースタイプやプロセス全体にわたるブリッジにはアクセスできません。ウェブプラグインは自身のビルドを提供し、アクティブなマニフェストがそれを読み込みます。

ホストは、認証、承認、ファイル、文書の共同編集、セキュリティ監査、オリジナルのAI使用、モデルによって評価されたトークン使用を保持します。会員権、ポイント、価格、コンテンツモニタリング、メールは、コアテーブル、ツール、またはページではありません。将来のメールプラグインは、自身のサーバー、データ、および受け入れテストを所有します。

契約書には、汎用的なツリースロット、さらに多くのビジネスサービス、およびファンド予約プロトコルが実装状況としてまだ記載されている。提案されたAPIは、呼び出すことができるエクスポートではない。

すべての耐久性のあるプラグイン状態はホストが管理します。パッケージは宣言する必要があります。 `doca.storage: "host"`; プラグインはドライバー、ストレージパス、ローカル/リモート設定ではなく、自身のモデル/認可を管理します。管理されたSQLとプライベートオブジェクトはSDK 0.1.7でエクスポートされ、サーバー専用の暗号化認証情報はSDK 0.1.9でエクスポートされます。詳細は [貯蔵契約](plugin-horizontal-scaling.ja.md).
