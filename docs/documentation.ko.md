# 문서 관리

[中文](documentation.zh-CN.md)

문서화는 Docsify 5.0.0을 사용합니다. 마크다운 소스는 그대로 유지됩니다. `docs/`; `docs/site/navigation.json` 공개 페이지와 그 읽기 순서를 정의합니다. 기술 계약 소스 경로는 저장소 및 편집기 기술 참조에 대해 안정적으로 유지됩니다.

## 레이아웃

| 그룹 | 콘텐츠 |
| --- | --- |
| 시작하기 | 빠른 시작, 설정, 사용자 가이드, 문제 해결 |
| 사용자 가이드 | 문서, 공유, 권한, 메모, 지식 |
| 배포 및 운영 | Docker, 스토리지, 확장, 인증, 서비스 자격 증명, 웹호크 |
| 개발 | 소스 설정, 아키텍처, 편집기, 공동 작업, 인터페이스 언어 |
| 플러그인 | 개발, 설치, 공공 서비스, 기여 |
| 참고 | API, 데이터베이스, SDK 및 편집기 계약 |
| 출시 | 버전별 변경 사항, 요구 사항, 및 검증 |
| 프로젝트 | 문서 관리 및 원본 연구/수락 기록 |

현재의 공개 페이지에는 8개의 언어 버전이 있습니다. 기본 소스는 `name.md`언어 접미사, 경로 및 내비게이션 텍스트는 정의되어 있습니다. `docs/site/languages.json`0.3.0 이전에 배포된 것들, 연구 결과, 수락 기록은 원본 버전과 검증 범위를 그대로 유지합니다. 소스 파일의 상단에는 은퇴된 구현 방식과 대체된 제안들을 표시합니다. 구현 목록에는 내보내진 API, 제안, 검증되지 않은 외부 서비스/기기 동작이 구분됩니다.

새로운 변경 사항이 적용됩니다. [층별 SDD 워크플로우](sdd.ko.md). 그 [모듈 인덱스](sdd-module-index.ko.md) 소스, 권위 있는 계약, 재사용 가능한 검사를 연결합니다. 사양은 개별 변경 사항을 설명하며, 현재의 기술적 계약은 기존의 소스 경로를 유지하고, 동작이 변경될 때 같은 PR에서 업데이트됩니다.

## 체크하고 미리 보기

```sh
pnpm install --frozen-lockfile
pnpm docs:check
pnpm docs:dev
```

열기 `http://127.0.0.1:39140/#/en/` 아니면 `http://127.0.0.1:39140/#/zh-cn/`프리뷰는 문서만 읽어주며, Doca를 시작하거나 데이터베이스에 연결하지 않습니다. 소스가 변경된 후 명령을 다시 실행하여 출판 디렉터리를 다시 생성하세요.

`pnpm docs:build` 준비하다 `.cache/docs-site/` 폴더와 같은 것들로 `en/getting-started/` 그리고 `zh-cn/operations/`Markdown 링크를 복사하고 다시 작성합니다. Docsify는 브라우저에서 콘텐츠를 렌더링합니다. 애플리케이션 코드를 컴파일하거나 Markdown을 HTML로 미리 렌더링하지 않습니다. 생성된 디렉터리는 Git에 의해 무시됩니다.

공개 페이지 링크는 현재 언어로 유지됩니다. 언어 링크는 해당 버전이 제공되는 경우 해당 페이지를 표시합니다. 소스 코드, 예제, 연구 링크는 해당 GitHub 파일을 열어줍니다. 페이지에는 편집 소스 링크와 사용 가능한 버전에 대한 링크가 포함됩니다. 번역이 없는 경우 다른 언어로 대체하지 않고 검사에 실패합니다.

`docs:check` Git을 통해 마크다운 저장소를 관리하며, 무시된 새로운 파일과 제외된 파일도 포함됩니다. `tests/fixtures/`이 도구는 저장소 문서 전반에 걸쳐 Markdown/HTML 링크와 헤딩 타겟을 검사하며, 이 저장소의 메인 브랜치 링크도 포함됩니다. 무시된 아티팩트와 날짜가 지정된 외부/태그가 붙은 URL은 가져오지 않습니다. 게시된 헤딩 앵커는 Docsify 규칙과도 추가로 검사됩니다. 이 검사는 현재 릴리스 경로, 편집기 패키지 매트릭스, 모든 데이터베이스 테이블/필드 행(상속된 Schema 인터페이스 포함), 그리고 다섯 가지 이동 가능한 기술 참조를 원본 문서와 비교합니다. TypeScript 타입은 애플리케이션 데이터베이스를 열지 않고 읽습니다. 외부 웹사이트의 가용성과 모든 주장의 의미론적 정확성은 여전히 검토가 필요합니다.

실행하기 `pnpm test:docs` 체크어 레지렉션 케이스의 경우. 계약을 수정한 후, 실행하세요. `node scripts/sync-docs-skills.mjs`; 소스 텍스트를 보존하고 결제 외부에서 사용할 수 있도록 관련 링크를 다시 작성합니다. 옵션인 installed-skills 디렉터리 인자로 설치된 참조도 업데이트됩니다. 예를 들어: `node scripts/sync-docs-skills.mjs /absolute/path/to/installed/skills`설치된 모든 복사본을 관련 기술의 유지보수 규정에 따라 동기화하세요.

## GitHub Pages

그것 `.github/workflows/docs.yml` 워크플로우는 피드백 요청에서 문서를 검토하고 변경 사항을 게시합니다. `main`저장소를 설정하세요. **설정 → 페이지 → 빌드 및 배포 → 소스 → GitHub Actions**이 워크플로우는 사용합니다. `github-pages` 배포 환경 및 그 승인 규칙. Actions에서 수동으로 실행할 수도 있습니다.

예정된 입구는 다음과 같습니다:

- 영어: <https://workhold.github.io/doca/#/en/>
- 중국어: <https://workhold.github.io/doca/#/zh-cn/>

이 주소들은 워크플로우가 성공적으로 배포된 후에 사용할 수 있게 됩니다. README 링크는 해당 언어 관련 페이지로 연결됩니다. 이 사이트는 기본적인 GitHub Pages 도메인을 사용하며, 특별한 도메인 DNS나 저장소 CNAME 파일이 필요하지 않습니다.

내용물을 제공하세요. `.cache/docs-site/` 다른 곳에 게시하기. 해시 라우팅은 저장소 하위 경로와 서버 라우트를 재작성하지 않고 직접 갱신을 지원합니다. 생성된 `.nojekyll` Pages를 통해 호스팅될 때 강조된 네비게이션 파일을 보존합니다.

## 자산과 업데이트

검토된 인증 요약 및 문서 첨부파일은 보관되어 있습니다. [`docs/verification/`](verification/README.md)수락 사례 또는 릴리스에 따라 그룹화됨. 재사용 가능한 스크립트 입력은 여기에 속함 `tests/fixtures/`생성된 로그, 스크린샷, 보고서 및 캐시는 저장됩니다. `artifacts/`이는 Git에 의해 완전히 무시됩니다; 새로운 증거를 보존하기 위해서는 무시 규칙을 변경할 필요가 없습니다.

Docsify 런타임, 검색 플러그인, 라이트/다크 스타일, MIT 라이선스가 포함되어 판매됩니다. `docs/site/assets/vendor/docsify/`. `README.txt` 버전을 기록하고 업스트림 npm tarball의 무결성을 확인합니다. 이러한 리소스들은 문서 사이트 자체에서 로드됩니다. Mermaid 다이어그램은 고정된 Mermaid ESM 버전을 부분적으로 로드합니다. `site.js`그들은 그 CDN에 대한 접근이 필요합니다.

공개 페이지를 추가할 때, 8가지 버전을 모두 만들고 해당 페이지를 추가하세요. `navigation.json`, 그리고 실행하세요 `pnpm docs:check` 그리고 `pnpm docs:build`비공개된 기술/디자인 기록을 연결하세요. [연구](research.ko.md)그리고 리뷰된 검증 요약서가 있습니다. [확인 지수](verification/README.md)코드 예제와 버전 요구사항을 일치시켜야 합니다. 계약을 업데이트할 때는 관련 저장소 지침을 따르고 필요에 따라 패키지화된 참조들을 업데이트해야 합니다. 런타임 자산과 추가 플러그인은 명시적인 버전 선택과 브라우저 검증이 필요합니다.

리リー스의 네비게이션 항목에 있는 네 번째 값은 `true` 8개의 언어 버전이 모두 나올 때. 나중에 출시된 버전 이후에도 그 가치를 유지하세요. 리뷰된 스크린샷은 언어 서브디렉터리에 넣어주세요. `docs/images/` 그러므로 사이트와 README는 일치하는 인터페이스를 참조할 수 있습니다.
