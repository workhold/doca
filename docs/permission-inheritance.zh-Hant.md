# 文件與知識庫許可權繼承

[English](permission-inheritance.md)

本文只描述當前許可權模型。個人授權儲存在 `grants`，組授權獨立儲存在 `resource_group_grants`，根據當前有效成員關係計算，不生成個人授權行。公開連結定義儲存在 `share_links`，連結撤銷事件儲存在 `share_link_revocations`。組邀請、搜尋範圍、交接與清理見[使用者組](user-groups.zh-Hant.md)。

每個組獨立採用最近授權與繼承邊界。個人禁用記錄不抹除組來源；本地組禁用記錄阻斷該組的繼承。知識庫組管理員沿用庫內頁面管理許可權下限。移除成員、退出或解散立即使該組來源失效。所有權交接保留組授權，原所有者仍可能透過組訪問。

<a id="公开阅读基线"></a>

## 公開閱讀基線

公開知識庫（`public` / `authenticated`）統一其所有頁面的閱讀範圍，頁面不能透過獨立可見性或關閉協作者繼承取消這一基線。頁面編輯、評論、管理授權仍按自身及繼承規則計算。關閉知識庫公開後，頁面重新使用自身與祖先的許可權設定。列表查詢與單資源點查執行相同規則。

按資源型別獨立的發現、搜尋及主動收錄規則見 [公開資源、發現與收錄](public-resource-discovery.zh-Hant.md)。

<a id="统一授权来源"></a>

## 統一授權來源

`grants` 按“資源 + 使用者 + 授權來源”儲存記錄：

- `direct`：主動邀請或管理頁直接授權，每個使用者在一個資源上最多一條。
- `link`：領取分享連結得到的授權，以分享 ID 區分來源。
- `parent_override`：當前節點對父級繼承結果的覆蓋或阻斷。

每條授權記錄儲存角色、是否包含後代、來源 ID 以及 `active` / `disabled` 狀態。許可權管理頁按使用者聚合來源並展示最終許可權，來源詳情操作具體記錄。刪除直接授權時，可寫入 disabled 的 `parent_override` 阻止許可權回退；刪除該覆蓋後恢復父級繼承。撤銷連結只刪除對應分享來源，不影響其它來源。

角色與“包含後代”是兩個獨立維度。計算某個後代資源的許可權時必須沿資源層級逐項判斷，不能分別取欄位最大值後拼接出不存在的授權。

<a id="协作者与继承范围"></a>

## 協作者與繼承範圍

知識庫是文件許可權樹根。知識庫文件優先繼承父文件，沒有父文件時繼承所屬知識庫；個人文件沒有父文件和知識庫歸屬，使用獨立許可權。

對命名使用者，從當前節點向上尋找最近的明確決定。當前節點授權覆蓋上級授權，disabled 的 `parent_override` 阻斷上級授權；沒有當前節點決定時才繼續繼承。`include_descendants` 決定授權能否傳播到後代。當前節點的“僅本節點”決定會截斷更上級的同一使用者授權，後代仍可透過自己的授權重新取得許可權。

公開許可權與命名使用者許可權分別計算後取最高值。移除協作者不會把使用者加入公開資源黑名單；匿名使用者的公開許可權最多為閱讀。

<a id="权限设置"></a>

## 許可權設定

`permission_overrides` 以位標記記錄當前節點明確覆蓋的欄位：公開範圍、公開角色、允許申請、公共發現、閱讀者歷史版本和連結分享總開關。未覆蓋欄位從祖先解析；當前節點修改後獨立生效，恢復繼承時清除相應覆蓋位。

關閉繼承不會複製父級設定。當前節點已有覆蓋保持不變，其餘欄位使用自身預設值；重新開啟繼承後繼續解析未覆蓋欄位。具體分享連結、邀請和工單不復制也不繼承，只有連結總開關可繼承。

使用者領取連結時寫入帶分享 ID 的 `link` 授權。修改、停用或過期控制後續領取；已寫入的授權透過成員來源管理顯式調整或撤銷。

文件和知識庫連結可授予閱讀、評論、編輯或管理許可權；只有所有者能建立、調整或撤銷管理許可權連結。

<a id="审批、通知与即时生效"></a>
<a id="审批通知与即时生效"></a>

## 審批、通知與即時生效

許可權申請的請求角色不可變，審批時可選擇實際授予角色與範圍。管理許可權申請只由資源所有者審批，也只有所有者能授予管理許可權。

工單透過受限的 `resource.grant` 操作執行，在同一事務中重新校驗資源、處理人和申請人許可權，並寫入實際角色、範圍、處理結果與事件。資料庫事務和狀態條件保證一個工單隻有一個最終處理結果。

點查與列表查詢使用相同的最近決定、授權範圍和欄位覆蓋規則，不為繼承批次複製授權。許可權變化後重新整理受影響線上房間；讀許可權撤銷立即關閉連線，寫操作繼續逐次鑑權。

<a id="验证"></a>

## 驗證

隔離測試覆蓋多層繼承、降權、阻斷、未來子文件、授權範圍、關閉和恢復繼承、欄位覆蓋、公開基線、連結來源撤銷、邀請接受、審批結果以及 WebSocket 撤權。

管理員可對已停用賬號執行[資源交接](admin-resource-handover.zh-Hant.md)，按預覽確認所有權和保留的授權。該入口讀取管理後設資料，不授予管理員私有正文訪問權。

<a id="共享权限组件"></a>

## 共享許可權元件

Web 的 `apps/web/src/shared/components/permission-grant-row.tsx` 和同目錄樣式統一維護授權行、許可權選擇、來源入口、下級範圍與刪除氣泡。文件、知識庫、知識冊使用 `PermissionDialog`，共享資料夾與組授權也接入同一個 `PermissionGrantRow`。呼叫方只提供身份、允許的角色選項、只讀/忙碌狀態與儲存回撥；元件控制佈局、文案、鍵盤焦點和確認流程。`permissionRoleChoices` 集中宣告宿主資源及共享資料夾的角色分類；自有許可權介面卡仍提供自身已支援的角色。

每條授權統一為兩行：上方身份與操作，下方賬號、來源或成員頭像及子文件範圍。組成員預覽複用 `UserBadge` 的純頭像入口與使用者卡片，「更多」開啟頭像浮層。浮層歸屬透過入口的 `aria-controls` 關聯，操作經 portal 渲染的卡片不會關閉所屬許可權面板。

授權來源明細同樣複用 `PermissionGrantRow`：左側來源名稱，右側許可權及刪除操作，保留原有來源只讀邊界。使用者組許可權高於個人許可權時，`PermissionEffectiveAccess` 將生效角色顯示為加粗藍色，並在文案中明確使用者組來源。

儲存回撥必須返回成功/失敗：失敗保留刪除氣泡，成功後才關閉。來源操作刪除與清除繼承覆蓋使用不同確認文案，清除覆蓋會恢復按上級計算；不得用通用的“取消授權”描述釋放限制。後端仍獨立校驗所有者、管理下限、邀請接受及範圍，不依賴前端元件授權。
