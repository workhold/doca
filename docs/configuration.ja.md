# 設定

TauriデスクトップクライアントはWebフロントエンドを含み、別途設定されたリモートホストに接続します。ローカルのビジネスホストを提供したり、リモートホストのデプロイ設定を変更したりすることはありません。詳細は [デスクトップクライアント](desktop-client.ja.md).

[中文](configuration.zh-CN.md)

選択する `docker.env.example` コンポーズ用と `.env.example` ソース開発のためには、それをリポジトリのルートにコピーしてください。 `.env`彼らは異なる起源とデータベースパスを使用している；どちらも示している `/data/storage` コンテナの永続ファイルボリュームのためです。ソース開発の場合は、ストレージルートを自分のマシン上の絶対的な書き込み可能なディレクトリに変更してください。出所を交換したり、秘密情報をコミットしたりしないでください。

<a id="required-compose-settings"></a>

## 必要なコンポーズ設定

| 変数 | 要件 | 単一サーバー例 |
| --- | --- | --- |
| `DOCA_ORIGIN` | HTTP(S)オリジンとして明示的に設定する必要があります。 | `https://doca.example.com` |
| `DOCA_FILE_STORE_ID` | 空でない必要があります。JSON内のストアを特定する必要があります。 | `local` |
| `DOCA_FILE_STORES_JSON` | 空でない必要があります。物理サーバーを使用した有効なバージョン1の設定です。 | 以下をご覧ください |
| `DOCA_CREDENTIAL_MASTER_KEY` | 起動時必須；正確に64個の16進数文字（32バイト） | 生成するには `openssl rand -hex 32` |

```dotenv
DOCA_ORIGIN=https://doca.example.com
DOCA_FILE_STORE_ID=local
DOCA_FILE_STORES_JSON='{"version":1,"stores":{"local":{"provider":"local","root":"/data/storage"}}}'
```

新しい単一サーバーインストールの場合、 **公開元を変更し、公開例の認証キーを置き換える** 出力と共に `openssl rand -hex 32`必要なファイルストレージ値は既に提供されています。PostgreSQL、Redis、モデルキー、SSO認証情報は条件付きです。既存のデプロイメントは元のマスターキーを保持する必要があります。

認証情報、サブパス、クエリ、フラグメントなしのHTTP(S)オリジンを使用します。ルートのトレーリングスラッシュは正規化されます。プロダクション環境ではHTTPとHTTPSの両方が受け入れられます。プロキシは設定された内容を保持します。 `Host`; 単に送られる要求 `127.0.0.1` ホストチェックに失敗します。ご確認ください。 [健康チェック](deployment.ja.md#start).

<a id="defaults-depend-on-the-entry-point"></a>

## デフォルトはエントリポイントに依存する

| エントリポイント | 起源 | データベース / ファイル | 認証マスターキー |
| --- | --- | --- | --- |
| リポジトリCompose | 必要です `.env` | SQLite `/data/doca.db`; ファイルID/JSONが必要 `.env`; `doca_data` 装着された `/data` | 必要です。永続的なデプロイキーを使用してください。 |
| Composeなしで公開された画像 | HTTP(S)オリジンを指定する必要があります | 画像内でSQLiteとローカルストレージのデフォルトが明確に示されている `/data`; 永続的なマウント `/data` 自分自身 | 必要です。永続的なデプロイキーを使用してください。 |
| ソース開発 | `http://127.0.0.1:39130` | SQLite `./data/v1/doca.db`; ファイルID/JSONが必要です、提供されました `.env.example` | 必要；公開例のキーを置き換える |

ソースファイル・ストレージパーサーには暗黙のデフォルトはありません。画像のデフォルト値はDockerfileの環境値です。ローカルストレージには書き込み可能な永続的なルートが必要です。S3には `bucket`, `region`、ブール値 `forcePathStyle`、そして明示的 `credentials:{accessKeyId,secretAccessKey,sessionToken?}`オプションのエンドポイントは、認証情報、サブパス、クエリ、またはフラグメントを含まないHTTP(S)ルートオリジンでなければなりません。明示的なHTTPエンドポイントでは、RustFSのような信頼できる内部オブジェクトストレージが利用できます。オペレーターがネットワークアクセスを管理し、サイト、アセット、CDNオリジンもHTTP(S)をサポートします。AWSシェル認証情報は、これらのJSONフィールドに代わるものではありません。詳細は [ファイルストレージ](storage.ja.md) RustFS設定例のため。

オブジェクトを保存した後も、ストアIDと物理的な場所は利用可能でなければなりません。設定された現在のストアIDは、記録されたアクティブIDと一致している必要があります。ID、パス、バケットを編集してもデータは移動しません。移行のためのショートカットとしてこれらの値を変更しないでください。

## 条件付き設定とオプションのサーバー

| 変数 | 必要に応じて/デフォルト |
| --- | --- |
| `DOCA_DATABASE=postgres`, `DOCA_DATABASE_URL` | PostgreSQLの選択にはURLが必要です。デフォルトのデータベースはSQLiteです。 |
| `DOCA_DATABASE_POOL_MAX` | プロセスあたりの主要データベース接続数；デフォルトは10 |
| `DOCA_WEBHOOK_DATABASE_URL` | オプションで明示的なPostgreSQL対応データベース；そうでない場合は以下のように派生される |
| `DOCA_REDIS_URL` | クロスインスタンスイベント、プレゼンス、レート制限に必要。設定しない場合はプロセスローカル実装が使用される。 |
| `DOCA_REDIS_PREFIX`, `DOCA_INSTANCE_ID` | プレフィスはデフォルトで `doca`; インスタンスIDはデフォルトでランダムなプロセスIDになります |
| `DOCA_TRUST_PROXY` | カンマで区切られた信頼できるプロキシIP/CIDR値； **デフォルトではプロキシは信頼されない**ループバックを含む |
| `DOCA_PLUGINS_DIR` | 書き換え可能なインストール/キャッシュディレクトリ。Composeはデフォルトで `/data/plugins` |
| `DOCA_PDF_PYTHON` | PDFエクスポート用の固定されたWeasyPrint依存関係を持つPython実行ファイル；デフォルト値 `python3`, `/opt/doca-pdf/bin/python` Docker内で。時代遅れ。 `DOCA_PDF_CHROMIUM` 拒否される |
| `DOCA_PLUGIN_STORE_URL` | HTTP(S) オリジン；デフォルト `https://store.smartdoca.cc` |
| `DOCA_PLUGIN_NPM_REGISTRY` | プレビルドパッケージレジストリ；デフォルト `https://registry.npmjs.org` |
| `DOCA_ASSET_BASE` | オプションのビルドアセットプレフィス；空の場合は無効 `/assets` ドカから |
| `DOCA_AI_IMAGE_MAX_ATTEMPTS_PER_PAGE` | 各ソースページごとに有料画像のリクエストを送信します。設定がない場合はデフォルトで5です。正の安全な小数型整数が必要です。0、空値、または構造化されていない値は起動に失敗します。 |
| `DOCA_AI_IMAGE_SEGMENT_PROFILE` | 信頼できる、厳格なバージョン1のローカルSAM2プロファイルへのオプションの絶対パスです。設定を無効にするとセグメンテーション機能が無効になります。不正な明示的な設定では起動に失敗します。利用できない検証済み実行環境ではツールが利用できません。詳細は [ローカルセグメンテーション](ai-image-segmentation.md) |

画像のリクエスト制限はサーバー起動時に固定されます。例えば、設定する `DOCA_AI_IMAGE_MAX_ATTEMPTS_PER_PAGE=10` ソースまたはComposeで `.env` サーバーを再起動するか、コンテナを再作成する必要があります。すべてのレプリカは同じ制限を使用しなければなりません。再試行、再開始、プロンプトの変更、またはバッチの再登録によって、蓄積された試行回数は削除されません。保留中または不確かな提出されたリクエストはカウントされますが、参照エクスポートやローカル再構成はカウントされません。既存のイメージ、リクエスト記録、使用状況は変更されません。制限を下げると、有料試行受領書の再利用を含む、制限を超えた順序の有料試行受領書を含む、さらなる有料リクエストが拒否されますが、これらの記録はスキップされたり変換されたりすることはありません。バッチバージョン3と有料試行バージョン1は変更されません。古いバッチフォーマットは、移行なしで依然として拒否されます。

欠落した、空の、または構造が崩れたマスターキーは、プラグインのないデプロイも含めて起動を拒否する。ランタイムにはデフォルトのキーがない。新しいインストールのためには、例ファイル内の公開例値を置き換えなければならない。一度生成しておく `openssl rand -hex 32`別々にバックアップし、すべてのレプリカで同じキーを使用する/再起動する。ご覧ください。 [管理された認証情報](plugin-credentials.ja.md).

Webhook配信には常に別のデータベースが使用されます。SQLiteが作成します。 `webhooks.db` メインデータベースの隣に。PostgreSQLはデフォルトで `<main_database>_webhooks`データベースが欠落している場合、作成の試行が行われます。アカウントにデータベース作成の権限がない場合は、その専用データベースを事前に作成し、アクセス権を付与するか、設定してください。 `DOCA_WEBHOOK_DATABASE_URL` アクセス可能な専用データベースに。AIストアは使用する。 `ai.db` コンポーズとザ・ `doca_ai` メインのPostgreSQLデータベース内のスキーマです。PostgreSQLの権限がその初期化を許可している必要があります。外部のAIモデルが設定されていない場合でも、これらのストレージにはバックアップが必要です。

複数のレプリケーションには、共通のPostgreSQL、Redis、およびファイルストレージが必要です。変数を変更しても、既存のデータは移行されません。読み取り専用です。 [水平スケーリング](horizontal-scaling.ja.md) そして [リリース要件](releases/0.2.24.md).

## Composeを通じて環境変数を渡す

`.env` 供給：インターリービングを構成する。すべての変数を自動的にコンテナに転送するわけではない。宣言されている設定のみが `compose.yaml` サービスに到達する。コンテナのバインドアドレス、ポート、SQLite/AIのパス、データディレクトリは現在のファイルに固定されている。これらの値をカスタマイズする際には、環境、ポートマッピング、永続的なマウントを一緒に変更する。

追加の環境変数は、Composeサービスの環境で明示的に渡され、デプロイディレクトリ内で設定されなければならない。 `.env`.

## 管理者設定と変更の適用

システムロゴは以下の下で管理されています **サイトとサービス → サイト情報 → システムロゴ**管理者は最大5MBのPNG/JPEG/WebP画像をプレビューして保存したり、デフォルトのアイコンを復元したりできます。これはナビゲーション、ログイン、文書以外のファビコンに表示されますが、文書タブにはそれぞれのアイコンが保持されます。標準化されたPNGは保存されます。 `settings.site_logo`他のサイト設定と同じ修正を使用しています。歴史的なNULLはデフォルトのアイコンを保持します。詳細は [0.2.24アップグレード要件](releases/0.2.24.md) 既存のインストールを更新する前に。

登録、身元情報提供サービス、認証ゲートウェイ、検索、AIモデル、ウェブホックのサブスクリプションは、それぞれの管理ページを使用します。ファイルサーバー認証情報は環境内に保持され、ストレージページは読み取り専用です。プラットフォームサービス認証情報とプラグイン暗号化認証情報は別のサービスであり、詳細は参照してください。 [サービス認証情報](service-credentials.ja.md).

`docker compose config --quiet` 解決されたシークレットを表示せずに補間を検証する。アプリケーションのJSON、データベースへのアクセス、クラウド認証情報の有効性の検証は行わない。以下で再起動する `docker compose up -d`ログと健康状態を確認し、設定されたサービスを実行します。参照してください。 [デプロイ](deployment.ja.md) そして [開発](development.ja.md).

<a id="login-lifetime"></a>

## ログイン期間

`DOCA_SESSION_TTL_SECONDS` ブラウザの制御、QRログイン、WebViewセッション、およびデータベースの有効期限やセッションクッキーを含む `Max-Age`デフォルトは `86400` 秒（24時間）。 `DOCA_MOBILE_SESSION_TTL_SECONDS` モバイルベアラーセッションとその既存の更新プロセスを管理する。デフォルトは `15552000` 秒数（180日）。どちらも1から2147483647までの小数整数を受け入れます。空値、ゼロ、負値、または構造が正しくない値は起動を拒否します。ComposeExplicitは両方の変数を明示的に渡します。

```dotenv
DOCA_SESSION_TTL_SECONDS=86400
DOCA_MOBILE_SESSION_TTL_SECONDS=15552000
```

デプロイの変更を適用するために再起動する。既に発行されたブラウザセッションは保存された有効期限が保持される。新規ログインは新しい有効期間を使用し、モバイルの更新は設定されたモバイル有効期間を使用する。セッション行や保存されたフォーマットは変換されない。セッションおよび認証フロークッキーは使用される。 `Secure` HTTPSでは、HTTPとは異なります `HttpOnly` そして既存のSameSiteポリシー。HTTPサイトは使用する `ws` リアルタイム接続のために。

承認されたHTTPブラウザアダプターはUUID v4を提供する `crypto.getRandomValues` 時々 `crypto.randomUUID` 欠落しており、SHA-256のみを提供している `crypto.subtle.digest` ピン固定されたまま `@noble/hashes` 時々 `crypto.subtle` 欠落している。ネイティブ実装は存在する限り使用される。ダイジェストはネイティブバイトと一致する。既存のID、スプレッドシートのチェックサム、文書形式は変換されない。これにより他のWebCrypto操作は実行されない。

テキストコピーボタンは1つの共有ヘルパーを使用します。利用可能な場合はネイティブのClipboardを使用し、そうでない場合は承認されたHTTPアダプターが一時的なテキストエリアを通じてコピーします。 `document.execCommand("copy")`フォーカスと選択状態を復元し、失敗を報告します。システムのクリップボードを読み取ったり、失敗したコピーを成功として扱ったりすることはありません。
