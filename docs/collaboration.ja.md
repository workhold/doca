# リアルタイム共同編集と保存

[中文](collaboration.zh-CN.md)

このページではホスト0.2.23の動作について説明しています。ターゲットコンポーネントのAPIや残りの作業は、 [共同編集契約](collaboration-sdk-contract.ja.md); 以前のシングルプロセスおよび一時パッケージの記録があります [研究](research.ja.md).

<a id="integrated-formats"></a>

## 統合フォーマット

リッチテキスト、Markdown、スプレッドシート、キャンバス、スライドが統合されています。ホストが公開用に設定します。 `@smartdoca/slate`, `@smartdoca/markdown`, `@smartdoca/sheet`, `@smartdoca/canvas`、そして `@smartdoca/slides` package.jsonやlockfileによって固定されるパッケージのみです。プライベートのソースディレクトリや古いvendor tarballは不要です。

5つすべては、それぞれ独自のモデル、コーデック、スキーマ、エポック、ビューを保持しながら、輸送、承認、ローカル更新待ちキューを共有する。コンポーネントはマウントする前に権威あるチェックポイント/ベースラインを復元する。ロケール、読み取り専用、選択、保存状態の変更は文書を再構築しない。スプレッドシートはリッチテキストモデルを使用する代わりに、不変のベースラインとプロトコルデータを保持する。

<a id="connection-and-messages"></a>

## 接続とメッセージ

WebSocketは使用する `/api/v1/ws`ブラウザはセッションクッキーと共に同じオリジンでアップグレードします。プロキシはUpgrade/Connectionを転送します。公開リソースでは、その可視範囲内で読み取り専用接続が可能です。各タブは、コンテンツ、通知、プレゼンスのためにホスト接続を再利用します。

Yjs bytesはJSONエンベディング内でBase64を使用する。実際のメッセージとフォーマットの検証は、 [ゲートウェイ](../apps/server/src/services/realtime/gateway.ts) そして [プロトコルチェック](../packages/core/src/modules/collaboration/protocol.ts):

| メッセージ | 現在の目的 |
| --- | --- |
| 準備完了 / 参加 | 接続が準備できました。参加して、コーデック/スキーマ/プロトコルバージョンを交渉してください。 |
| sync-request / sync-response | 権威的な差異、epochId、seq、フォーマットベースライン、およびアクセス；同期応答は保存ACKではない |
| 更新 / 承認 | ローカル編集を送信し、データベースコミット後で該当するメッセージに同意する |
| 存在 / カーソル / カーソル | ユーザーの存在と一時的なセッションごとの選択内容 |
| document.changed / notifications.changed | 内容/詳細の無効化、または保持された通知の読み取り |
| 離れる / エラー | 離脱や報告の許可、プロトコル、接続エラー |

エポックが明確になったら、編集には対応するプロトコル、コーデック/スキーマ、そしてエポックが必要です。ID、接続ID、名前、色はサーバーから提供されます。書き込みやブロードキャストでは現在のアクセス状況を再確認し、クライアントが主張するIDは使用されません。

<a id="save-reconnect-and-history"></a>

## 保存、再接続、履歴

実際の地元コンテンツ取引のみが入力される `update-outbox.ts`初期化、リモートアプリケーション、プレゼンス、スクロール、サイズ変更はコンテンツを送信しません。保留中の編集は元のバイトとメッセージIDを保持します。一致するACKはその更新を削除します。同期応答や不明なACKはキューを決してクリアしません。

サーバーはトランザクション内でコンテンツと派生されたプロジェクションを検証し保存し、その後承認してブロードキャストする。受信内容はリソース、エポック、メッセージIDによって重複を排除し、同じIDであってもバイト数が異なる場合は拒否される。チェックポイントはCRDTのアイデンティティを保持する。独立した歴史記録は独自のフォーマット、系譜、アセットを保持する。詳細はこちら [歴史と復元](document-experience.ja.md#history-and-restore).

現在のホストアダプターは、送信前にIndexedDB内の元のYjsチェックポイント、ベースライン、未認識メッセージを保持します。再接続時には権威ある状態が取得され、元のIDとバイト数が再試行されます。一致する耐久性のあるACKのみがそれらを削除します。キャッシュされたログイン済みドキュメントは、サーバー検出前にページメタデータとレプリカを復元し、最後の知られている権限の下でオフライン編集を許可します。一時的な停止状態でもエディターはマウントされたままです。明示的なセッションまたはリソースの拒否により、キャッシュされたメタデータが隠れ、保留中の作業が保持されます。デスクトップバンドルまたは以前ダウンロードしたWebフロントエンドが停止中でもオフラインドキュメントリストを開くことができます。 [オフライン文書と復元](access-offline-events.md#离线文档入口).

<a id="presence-and-comments"></a>

## 存在とコメント

ユーザー数は重複が排除されています。編集選択は、1つのアカウントの別々のタブを含む接続に属しています。存在状態は一時的であり、コンテンツや履歴の書き込みは発生しません。リッチテキスト、Markdown、スプレッドシート、キャンバス、スライドはそれぞれ独自のアダプターを使用します。読み取り専用ビューでは編集選択は公開されません。

永続的なコメントアンカーは別物です：リッチテキストアンカー、Markdown範囲、安定したスプレッドシートの行/列の識別、およびキャンバス/スライド要素領域はフォーマット固有の検証を使用します。スプレッドシートのコメントは、サポートされる構造変更を通じて安定した記録に従います。一時的なA1選択は永続的なアンカーではありません。詳細はこちらをご覧ください。 [コメントと通知](comments-and-community.ja.md).

<a id="one-instance-and-replicas"></a>

## 1つのインスタンスとレプリケーション

Redisがない場合、ブロードキャスト、プレゼンス、制限はプロセス内に留まる。Redisを使うと、コンテンツの変更、権限の無効化、通知、プレゼンスがインスタンス間で共有される。共有データベースのコンテンツは依然として権威を持つが、Redis Pub/Subは永続的なログではない。設定されたRedisの障害が発生した場合、ローカルバスに静かに切り替わることはない。

レプリカには、共有されたPostgreSQL、ファイルストレージ、そして独立したインストールキャッシュを持つ一貫したプラグインバージョンが必要です。詳細は [水平スケーリング](horizontal-scaling.ja.md)フル負荷状態、ネットワーク障害マトリックス、および実際のデバイスにはターゲット環境の受容が必要です。自動テストでは孤立したデータが使用されます。
