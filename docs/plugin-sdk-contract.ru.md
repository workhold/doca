## Внедрена управляемая система хранения

`@smartdoca/plugin-sdk/storage` Теперь экспортируются устройства для установки `pluginDatabaseToken` (`storage.sql.v1`) и `pluginObjectStorageToken` (`storage.objects.v1`). Соединения, иностранные ключи, общий SQL, upsert и рабочие пространства не экспортируются. Смотрите [API квалификации и развёртывание](plugin-credentials.ru.md)Бизнес-SQL использует один общий базу данных, управляемый хостом, отдельный от основного: один файл SQLite с префиксами таблиц, или один URL/аккаунт PostgreSQL с автоматическими схемами плагинов и общим пулом подключений. Изоляция процессов остается не реализованной. См. также [Настройка хранения и условия удаления перед обновлением](plugin-database-isolation.ru.md).

Логические базы данных используют `plugin:<pluginId>`Принадлежность пользовательских файлов и использование приватных объектов `plugins/<pluginId>`и выпуск ZIP-файлов `host/plugin-releases/<sha256>.zip`Полные неизменяемые байты ZIP хранятся в файловом хранилище, настроенном в среде; общая база данных содержит реестр версии 2, ссылки на архивы и индексы доверенных хешей файлов. ## 1. Решения

Утверждено [Горизонтальное масштабирование и контракт на управление хранилищем](plugin-horizontal-scaling.ru.md) Определяет право владения базой данных, изоляцию пространства имён, хранение данных для пользователей/приватных/тemporary и выполнение в нескольких экземплярах. Пакеты должны объявлять `doca.storage: "host"`Другие или отсутствующие объявления отклоняются перед импортом кода. Выбор локального/дистанционного хранения осуществляется самой платформой. Управляемый SQL и приватные объекты экспортируются в исходнике SDK версии 0.1.7; учетные данные экспортируются в исходнике SDK версии 0.1.9; рабочие пространства остаются неопределенными.

Doca сохраняет продуктовый ядро документа и генериальные платформенные услуги. Независимый бизнес обнаруживается в директории установки. Почта, календарь, членство, расчеты, контроль использования и модерация контента не являются необходимыми продуктами хостинга.

Плагин зависит от отдельно опубликованного SDK и контракта возможностей. Хост внедряет реализацию во время выполнения программы. Не полагайтесь на путь рабочего пространства Doca, приватный модуль хоста, глобальный мост или приватную таблицу хоста. Хост не импортирует источник бизнес-плагина и не требует определенного идентификатора бизнес-плагина для завершения публичного процесса.

Плагины работают внутри надежного серверного процесса. Это граница расширения, а не суммаризатор Node.js. Папка установки отделена от папки программы. Хост загружает только те плагины, которые указывают на текущий диапазон SDK и чьи базы данных соответствуют текущему базовому уровню.

## 3. Установка и обнаружение

Общий хост-база данных содержит нужные реестры и метаданные архива; полные неизменяемые ZIP-архивы хранятся в настроенном хост-файловом хранилище. Каждый экземпляр синхронизирует личные данные. `DOCA_PLUGINS_DIR` По умолчанию `<data-root>/plugins`Перед загрузкой он проверяет все кэшированные файлы и исправляет отсутствующие или поврежденные файлы из общей архивы. При запуске не происходит связи с магазином, не нужно выполнять команду npm install или компилировать TypeScript.

Администратор → Плагины устанавливаются из официального HTTPS магазина или локальных загрузок, проходят обновления, включаются, отключаются и удаляются. Стандартный магазин — `https://store.smartdoca.cc`, перекрытое `DOCA_PLUGIN_STORE_URL`Операции используют проверенные записи, и они вступают в силу после перезапуска каждого экземпляра. Управляющий интерфейс различает глобально заданный выбор от текущего выбора в рамках конкретного экземпляра. Не предусмотрено возможности быстрого удаления маршрутов Fastify.

Предустановленные версии объявляют `doca.manifest`, `doca.server`, опционально `doca.web`обязательное `doca.dataVersion` и `doca.storage: "host"` В файле package.json проверка статического хранения происходит до решения/импорта данных сервера для каждого источника установки и восстановления после запуска. Недостающие или несоответствующие объявления хранения приводят к неудаче без конвертации. Также проверяется диапазон SDK, пути, граф, хеш и точная структура. Установленные обновления требуют неизмененной значения dataVersion. При текущей демонтаже выполняется необходимый процесс очистки данных, и при успехе удаляется отметка; транзакция реестра обеспечивает генерацию и запись информации о долговременной очистке приватного базы данных/объектов, которая выполняется после коммита; процесс очищения кластерных задач остается незавершенным.

Оффлайн папки `<install-root>/<plugin-id>/` Они публикуются в общем реестре при запуске и перемещаются в `.imports/`Файлы времени выполнения находятся в `.releases/<sha256>/`. Не поддерживается никакое manifest npm, ссылки на исходный код или старый путь обнаружения. Файлы программ и данные плагинов остаются отдельными. Исходный код хоста, файл package.json и конфигурация Vite никогда не меняются при установке.

Это [протокол хранения](plugin-store-protocol.ru.md) Определяет структуру пакета, удаленные endpoints, ограничения и семантику множества инстансов. Смотрите [развертывание](plugin-deployment.ru.md) Для перезапуска и восстановления после сбоя.

## 4. Процесс жизни

```text
scan static metadata → check dependencies → import code
→ discover → required service check → initialize → mount → ready
→ stop accepting work → dispose in reverse dependency order
```

Сервисы идентифицируются по стабильному строковому ID и версии, а не по идентичности объекта токена. Хост сначала предоставляет платформенные сервисы. Бизнес-плагин регистрирует сервисы только в своем собственном пространстве имён. Он не может внедрять приватные сервисы хоста. `doca.server.*`Каждый сервис-идентификат имеет одного поставщика. Функции множественного участия используют реестр.

Каждое регистрационное действие возвращает объект, принадлежащий контексту эффекта. Сервисы, задачи, подписки на события и регистрации UI принадлежат одному хост-инстанцию. Не храните их там. `globalThis` или `Symbol.for`Два тестовых приложения в одном процессе не должны влиять друг на друга.

Целевые возможности, некоторые из которых ещё не экспортированы: files.v1, documents.v1, users.v1, permissions.v1, http.v1, ai.v2, ai-usage.v1, search.v1, content.v1, activity.v1, notifications.v1 (экспортированы), events.v1, relational storage плагина, управляемый хостом (экспортировано в SDK 0.1.7), и policies.v1. Реальные идентификаторы соответствуют текущим экспортам. Необходимо версионировать переименование. Эта таблица не является разрешением на передачу нереализованного интерфейса существующему плагину.

## 5. Информация о пользователе и контекст запроса

Запросы HTTP, инструменты ИИ и фоновые задачи используют один надежный контекст выполнения: requestId, principal, pluginId, signal, а также по желанию sessionId, turnId, jobId и callId. Идентичность определяется через аутентификацию хоста или сохраненное разрешение на задачу. Плагин не может создавать пользовательскую идентичность из своего HTTP-тела.

Полный запись пользователя, доступная на сервере, включает стабильный ID, публичный ID, логин, имя отображаемого пользователя, аватар, статус, флаг администратора, проверенные контакты, поля профиля, пользовательские бизнес-поля и метаданные, связывающие идентификаторы, которые могут прочитать звонящий пользователь. Результаты обычных поисковых запросов остаются лишь минимальной проекцией. Объект не содержит хеша пароля, токена сессии, кода верификации, токена OAuth, ключа API модели или секрета хранения. Не возвращайте полный профиль сервера в браузер и не добавляйте его автоматически в предложение модели.

Пользователи продолжают создавать профили, обновлять их и изменять статусы. Ещё не существует записи о удалении пользователя. Фоновый процесс перепроверяет статус пользователя и разрешения на доступ к ресурсам. Потерянный доступ не может быть восстановлен с помощью старого снимка работы.

Потенциальный процесс удаления записывается хостом: отмечается удаление и отмена доступа, плагины очищаются эмпирически и подтверждаются, после чего хост завершает удаление. Это должно охватывать отключенные, не установленные и недоступные плагины, с возможностью повторной попытки и проверенным ручным путем. Таймаут не является успешным. Не используется межбазовый двухфазный коммит. Это должно быть одобрено перед открытием записи удаления пользователем.

## 6. Права доступа и пересечение пользователей

Референс ресурса — `(pluginId, resourceType, resourceId)`Плагин регистрирует свое авторизаторское средство. Хост вызывает его. Сервисы файлов и документов сохраняют собственные ACL. Регистрация плагина не дает права на чтение файлов пользователя.

Плагин определяет бизнес-действия и карты ролей, такие как mailbox.read. Действия плагина не обязательно должны соответствовать действиям редактора документа. Отсутствие авторизатора, отключенный плагин или неопределенные результаты препятствуют доступу. Чтение текста, скачивание приложений, инструменты ИИ и поиск требуют повторной проверки.

Хост сохраняет все правила администратора, связанные и не связанные, а также персональные отключения. Связанные кандидаты — это объединение встроенных источников документов и файлов и активных источников пересечения плагинов. Хост все еще фильтрует статус пользователя, видимость полей и навигацию. "Нет" не требует от плагина расширения правил.

Источник пересечения указывает, какие пользователи сайта могут быть обнаружены благодаря авторизованным деловым отношениям. Участники общей почтовой ячейки или календаря могут быть в этом списке. Почта незнакомца, одна и та же домен электронной почты или имя в тексте сообщения — нет. Плагин не формирует политику директории администратора.

Исходный протокол поддерживает идентификатор источника, версию схемы, кандидатские батчи и курсоры, идентификатор отношений и версию, а также повторный проверку фактов. Плагин сохраняет крупные индексы отношений и их выходные данные. Поиск пользователя не сканирует базу данных плагина. Исчисленные кандидаты повторно проверяются перед их возвратом. Падение источника не расширяет поиск. Отключение плагина немедленно удаляет его источник. Возобновление его работы сначала калибрует версии и действительные отношения.

Возможность поиска не предоставляет разрешения на ведение бизнеса и не раскрывает полный профиль пользователя. Дублирующиеся пользователи из разных источников удаляются перед отображением страниц. Общее количество предварительно фильтрованных пользователей не должно содержать скрытых пользователей.

## 7. Файлы, данные плагина и транзакции

Привязка приложения `(ownerPlugin, ownerType, ownerId, role)`Не создавайте личный магазин приложений или сохраняйте временный подписанный URL в качестве постоянного источника информации. Хост отвечает за очистку управляемого хранилища, координируемую между экземплярами, а не за удаление файловой системы плагина.

При работе с базами данных и файловыми сервисами используйте идемпотентность, компенсацию и калибровку. Нет общей транзакции.

### 7.1 Устойчивое создание файлов

`files.v1.folders.create` и `files.v1.files.create` принять опционально `idempotencyKey`, не пустое, не более 200 символов, без управляющих символов. Объем данных — идентификатор вставленного плагина, текущий пользователь и тип операции. Тот же ключ и те же параметры возвращают первый результат. Тот же ключ и разные параметры вызывают 409. Строка файла или папки и завершенный коммит совместно. Коммиты не истекают. Отключение и удаление не уничтожают их. Повторная запись после удаления результата возвращает 404 и не создает файл заново. Повторная запись и запрос перепроверяют учетную запись и разрешение на запись.

Возвращается результат завершения загрузки `contentIdentity: {sha256, size, mime}`IDempotentый загрузка должна пройти проверку. Хост проверяет загруженные байты. Фingerprint запроса включает директорию назначения, имя и идентификатор содержимого, а не временный uploadId. Копирование использует sourceFileId и не требует contentIdentity. Плагин хранит ключ операции, бизнес-параметры и идентификатор содержимого в своем outbox.

`files.receipts.get(context, {operation, key})` возвращает null или `{status: "pending" | "completed", operation, result}`“В ожидании” означает, что оригинальные параметры могут быть повторно попытаны. Это не означает, что задача все еще выполняется. “Завершено” возвращает исторический отчет. Если ответ неизвестен, прочитайте сообщение о получении, а затем повторите оригинальную операцию создания. Неудача не превращается в сообщение о успехе.

Хост сохраняет ID объекта и параметры хранения, затем записывает байты. Локальные записи выполняются с использованием атомарного замены. В S3 записывается полный объект. При запуске и ежедневном сканировании освобождаются временные объекты, незавершенные задачи, байты из задач, не завершенных более 24 часов, а также временные файлы. Освобождение и повторная загрузка объектов используют один пользователь базы данных и проверяют ссылки на объекты. Регистрированный объект не удаляется как мусор.

## 8. Инструменты ИИ, навыки и их использование

Код SDK версии 0.2.0 экспортирует сервер `ai.continuations.v2`Регистрация источника в рамках установки, ожидание авторизованного инструмента, долговечные контрольные точки, отфильтрованные уведомления о пробуждении и согласование перезапуска. Бизнес-задачи и авторизация остаются в ведении плагина; хост освобождает модель выполнения во время ожидания. Участвуют только явные записи о ожидании версии 1; нет миграции базы данных или исторической конвертации. См. также [контракт продолжения](plugin-ai-continuations.ru.md).

Текущий источник Web SDK экспортирует `PluginWebHost.ai.open` Для запуска личного помощника с промптом/контекстом, авторизованными документами/файлами, опциональной собственной сессией/моделью и явным автоматическим отправкой. Она использует существующие сессии/сообщения хоста и процессы выполнения без необходимости миграции хранилища или адаптера для старого хоста. Смотрите [Контракт на запуск](plugin-assistant.ru.md)Это функция пользовательского интерфейса клиента, а не сервис выполнения ИИ на сервере; доступность npm/native в производственной среде пока не подтверждена.

Плагин может регистрировать инструменты, навыки, цели, рабочие процессы, элементы отображения результатов и проверщики. Инструмент имеет идентификатор в пространстве имен, схемы входных и выходных данных, исполнитель и требования к правам. Навык — это версионированный контент в пакете. Это не способ обхода авторизации инструмента.

Инструмент плагина получает авторизованный профиль пользователя и контекст ассистентского вызова: сессию, транш, задачу, вызов инструмента, идентификатор модели, параметры, сигнал отмены и разрешенные материальные ссылки. Собственный история и каждый запрос не являются стандартным контекстом инструмента. Chat и MCP разделяют авторизацию и выполнение инструмента.

MCP теперь раскрывает установленные инструменты, объявляя `mcp` Раскрытие через тот же исполнителя и текущие проверки пользователя/принятия на работу. Официальные, установленные плагины и активированные личные навыки фильтруются по сервисному гранту и эффективному пользователю. Конфигурация личного и компании сервиса принадлежит хосту, без нового экспорта SDK или доступа к источнику плагина. Смотрите [Сервисы MCP](mcp.ru.md).

В основе нет уровней членства, баллов, цен, квот на подарки или фильтрации моделей по уровню. Хост сохраняет конфигурацию модели, технические тайм-ауты, количество одновременных запросов, ограничения контекста, а также данные о использовании, доступные для просмотра пользователем, моделью, плагином, задачей и вызовом. Каждая модель имеет скорости токенов входа и выхода. При генерации изображений токены начисляются за каждое успешное изображение. Эти скорости преобразуют использование от поставщика в совокупные токены. Они не являются валютой или окончательной ценой.

Каждый запрос провайдера имеет свой ID-звонка и ID-запроса. Неизвестные значения равны null. Не добавляйте 0. Токены кэширования или рассуждений могут уже быть включены в общие значения входных или выходных данных. Не добавляйте их дважды. Система расчетов фиксирует снимок ставки с момента звонка. Устройство пользователя и `ai.usage.recorded` Показывается рейтинговое использование. Баланс хранит сырые метрики поставщиков. Оценки и фактические данные остаются раздельными. Replay не измеряет дважды.

Только вызовы, проходящие через AI-экзектор хоста, находятся в унифицированном метре. Плагин, вызывающий поставщика напрямую, не входит в это обещание.

Плагин управления должен зарезервировать атомарно в своей собственной транзакции и вернуть идентификатор зарезерпа, не имеющий эффекта повторения. Завершение или неудача освобождения или урегулирование происходит через устойчивое повторение попытки. Проверка баланса, вызов, затем списание — это не параллельное контролирование квоты. Неудачный событие использования не стирает хост-ледер. Повторное воспроизведение дублируется по идентификатору вызова и идентификатору попытки.

Политика v1 также охватывает создание документов, загрузку файлов и обмен информацией. Она возвращает результат «разрешено» или «запрещено» вместе с стабильным кодом причины. По умолчанию нет коммерческих ограничений. Плагин политики не может расширить ACL ресурса, статус учетной записи, размер запроса или лимит безопасности выполнения. Исключения из политики не включаются в результат «разрешено». Если отсутствует необходимый плагин контроля, операция невозможна, и ошибка указана явно.

## 9. Страницы, навигация и HTTP

Бизнес-плагин может включать глобальное навигационное меню, собственное дерево или боковую панель, страницы, административные функции, личные настройки, действия меню документов, результаты поиска и отображение результатов ИИ. Позиция использует стабильную позицию, порядок и идентификатор. Не редактируйте ветку маршрута хоста для добавления бизнес-функции.

Целевой веб-сайт — это браузер ESM, стили и ассеты, созданные плагином. Хост загружает версионную URL из активного манифеста. Сборка не должна импортировать `@web/*`локальный хост-источник или нераскрытые базовые импорты. Хост предоставляет объявленный статический директорий, а не весь пакет npm. Несоответствие версий сервера и клиента делает страницу этого плагина недоступной. Отсутствующий рендерер создает общую историческую отображаемую информацию. Ошибка регистрации в интернете остается в пределах границ плагина. Основной рабочий пространство может отображаться, пока загружаются бандлы браузера. Специальные страницы плагина показывают состояние загрузки, пока их маршрут обнаруживается.

http.v1 регистрирует `/api/v1/plugins/<plugin-id>/...` Используется повторное использование аутентификации хоста, проверки Origin и Host, схема запросов, формат ошибок, лимиты скорости и возможность отмены. Публичный webhook должен указывать, как проверяется внешняя идентичность. Нативный код все еще поставляется в составе приложения. Плагины, поддерживающие мобильные устройства, теперь используют ограниченный WebView шелл, описанный в руководстве по интеграции почты v1.

## 10. Удаление членства и модерации

Удаление членства включает страницы администрирования, отображение уровней, API для планов и грантов, карты уровней поставщиков идентичности, квоты на ресурсы, очки ИИ и фильтрацию моделей по уровням. Скрытие страницы при сохранении ограничений по уровням недостаточно. Регистры использования ИИ остаются открытыми. Проект не включает старые коммерческие поля или слои миграции.

Удаление контент-модерации включает точки входа для отчетов, администратора по проверке, поставщиков, задачи сканирования и специальные звонки для проверки в процессах хоста. Согласование регистрации администратором является частью политики учетных записей. Аудит безопасности является ключевым элементом. Ни одно из этих элементов не удаляется, так как контент-модерация также удаляется.

Электронная почта, календарь, членство и модерация — это бизнес-плагины. Краткие заметки были удалены из основного кода и могут вернуться в виде будущего независимого плагина. Тикеты, синхронизация с третьими сторонами, распознаватели и каналы уведомлений могут быть разделены позже, только после одинакового SDK, данных и приема клиента. Не оставляйте обёртку, которая все еще импортирует реализацию приватного хоста.

## 13. Классы доставки

- Контент хоста, сервисы файлов и гайки публичной интеграции сохраняют свои существующие границы. Бизнес-модели, права, повторные попытки и семантика выгрузки остаются в ведении плагина; сохранение данных всегда контролируется хостом.
- Требуемая декларация пакета `doca.storage: "host"` Это проверяется перед импортом кода сервера для установок через ZIP/npm/store, импорта офлайн-директории и восстановления запуска. Недостающие/различные значения не работают. Не поддерживается окружение переменной данных плагина, селектор сервера, легендарный адаптер или имплицитная миграция данных.
- Управляемое реляционное хранение и приватные объекты экспортируются в SDK 0.1.7. Криптографические данные экспортируются в исходном коде SDK 0.1.9; оставается работа по реализации временных функций. Выбор сервера и совместное развёртывание зависят от хоста; плагины никогда не различают локальные и удаленные ресурсы. Точный статус экспорта указан в контракте хранения и в разделе 12.
- Новые управляемые магазины принимают только объявленную структуру; несоответствия приводят к отказу от запуска. Не открывайте пустые магазины для существующих самостоятельно управляемых установок, и не используйте функцию удаления для обхода плана миграции. Старые пакеты/данные остаются нетронутыми; любая конвертация требует отдельного соглашения.
  Управление очисткой приватных баз данных/объектов является обязанностью хоста. При успешном удалении приложения из бизнес-системы регистрационные записи ограничивают работу текущего поколения и отправляют процесс очистки приватных таблиц/объектов с использованием действенных попыток восстановления. Реализованы процессы очистки учетных данных и ограничение работы кластера; процесс откачки задач бизнес-системы остается недоступным. Файлы пользователей и другие референсы бизнес-системы сохраняются. Если функция hook не работает, установка остается неповрежденной; влияние внешних hook невозможно откатить. Все инстансы все еще требуют ручного перезапуска.
- Здоровье, скрытые записи, недавние ошибки в работе и накопленный объем задач суммируются через публичные интерфейсы статуса, а не через плагины, читающие пути хранения хоста.

Не предоставлено: произвольный SQL, транзакции, распределенные между плагинами/хостами, автоматический импорт старых данных/двойные записи, по умолчанию доступ к AI ко всем источникам, или код npm-плагина, динамически выполняемый нативным процессом.
