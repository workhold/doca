# Передача ресурсов администратора

[中文](admin-resource-handover.zh-CN.md)

В **Администрирование → Пользователи**Активный системный администратор открывает **Передать ресурсы** Для заблокированного аккаунта выбирается активный получатель и ресурсы, затем проверяются и подтверждаются фактические изменения. Источный аккаунт остается заблокированным. Обычные пользователи не могут использовать ни один из трех endpoints.

<a id="scope"></a>

## Область применения

Инвентарь считает метаданные управления из существующих записей ресурсов, папок, файлов и прав. Он не считает содержимое документов или личные учетные данные.

- Документы, библиотеки и книги знаний: передача выбранных ресурсов и наследников, принадлежащих источнику. У других лиц сохраняется право собственности; связанный контент указывается отдельно. Прежнее положение владельца библиотеки действует в отношении получателя.
- Изображения документов и приложения: активы, связанные с передачей, и элементы директории с их документом. Их нельзя выбирать отдельно. Оригинальные загрузчики и авторы истории остаются неизменными.
- Обычные папки/файлы: передача наследников и файлов, принадлежащих источнику. Выбранная вложенная папка или независимый файл перемещается в личную корневую папку получателя, если его родительская папка не передается и не принадлежит получателю. Предпросмотр показывает это перемещение.
- Поддержка сохраненных документов/библиотек: явно выбранные активные местные источники грантов становятся получателями прямых грантов и удаляются из источника. Область распространения следует сохранить; токены ссылок не копируются.
- Привилегии для общих папок: объединяйте привилегии в папку получателя без понижения существующего более высокого роля, затем удаляйте выбранную привилегию источника.
- Уничтоженные ресурсы: право собственности может быть передано, в то время как состояние удаления остается нетронутым.

Личные файлы ИИ, частные беседы, учетные данные и деловые записи с плагинами исключены. Существующие связи файлов ИИ/знаковок, обычные защищенные файлы и не распознанные метаданные остаются защищенными. Запрет на передачу файла приложения документа через менеджер файлов не мешает передаче самого документа. Защищенные записи объясняют, почему их нельзя выбрать; защищенные файлы в выбранном каталоге блокируют всю группу.

<a id="preview-and-permission-checks"></a>

## Предварительный просмотр и проверка разрешений

Предпросмотр показывает информацию о владении, разрешениях и изменениях вложений, перемещениях, а также связанных элементах, чья владение остается неизменным. Выбор родительского элемента расширяет список его наследников. Каждый батч может содержать до 500 выбранных записей из инвентаря; расширение может включать больше наследников. Инвентарь и изменения отображаются на страницах по 50 строк.

Существующие разрешения для получателей остаются в силе. Непревзойденные роли узла/потомков, ограничения для детей источника, которые расширяют доступ, а также явные ограничения для получателей вызывают конфликты и блокируют подтверждение. Пересмотрите эти разрешения через существующую систему разрешений или измените выбор. Передача не перекрывает такие ограничения и не копирует несвязанные наследованные права.

Приглашения к источнику или получателю для выбранных документов/папок отменяются, так что последующее принятие не может перезаписать процедуру передачи. Приглашения к документам архивируются в заказы; приглашения к папкам сохраняют свои отмененные строки и заказы. Приглашения других людей остаются нетронутыми. Предпросмотр показывает количество отмененных приглашений. Общественная видимость, определения ссылок и другие сотрудники сохраняют свои существующие настройки; общественный доступ не становится списком блокированных пользователей.

<a id="consistency-and-audit"></a>

## Согласованность и аудит

Инвентарь и предпросмотр используют одинаковые снимки базы данных. Выполнение персистутирует отпечаток, охватывающий соответствующие учетные записи, ресурсы, гранты, приложения и содержимое директорий. Изменение состояния делает подтверждение неактуальным и возвращает код ответа 409. Перезагрузите и снова проведите предпросмотр. Однократные одновременные подтверждения одного батча успешны только один раз.

Одна транзакция закрепляет право собственности, принимает решения о разрешениях, приглашениях, выполнении индексов и проверке безопасности. Существующие политики приема получателей/квот все еще работают. Любой сбой приводит к откату всего батча. Сохраненные объекты не перемещаются и не удаляются. Содержимое документов, их история, авторы и источники загрузки остаются нетронутыми. После коммита активные разрешения обновляются, и соответствующие учетные записи уведомляются.

Это `user.resources_handed_over` Отчеты о аудите безопасности фиксируют реального администратора, источник, получателя, отпечатки пальцев, изменения и связанные предыдущие метаданные. Они исключают несвязанные частные получатели. Выполнение происходит синхронно; это не бэкграндовское задание, которое можно перезапустить. После отключения браузера или потери ответа необходимо пересчитать инвентарь перед попыткой выполнения другого батча.

Эта функция использует существующие таблицы и сохраненные форматы, без изменений схемы или необходимости перекодирования данных из прошлого. Не предусмотрено автоматическое перенаправление прав или отмена разрешений. Исправления, касающиеся подтвержденных деловых решений, требуют пересмотра аудита и текущих прав собственности/разрешений.

## API и верификация

- `GET /api/v1/admin/users/:id/resource-handover`: инвентарь.
- `POST /api/v1/admin/users/:id/resource-handover/preview`: `targetUserId`, `keys`.
- `POST /api/v1/admin/users/:id/resource-handover/execute`Та же selección, плюс предпросмотр `fingerprint`.

Бегать `pnpm exec vitest run tests/resource-handover.test.ts` Для тестирования сервисов/API. Запустите. `pnpm exec tsx scripts/qa-resource-handover.mts` Для реального административного интерфейса в отношении изолированного SQLite/аккаунтов/документов/хранилища. Результаты находятся в `artifacts/verification/resource-handover/`Эти проверки не обеспечивают проверку работы PostgreSQL во время выполнения.
