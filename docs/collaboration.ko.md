<a id="integrated-formats"></a>

## 통합 형식

서식 있는 텍스트, 마크다운, 스프레드시트, 캔버스, 그리고 슬라이드가 통합되어 있습니다. 호스트가 공개된 것을 설치합니다. `@smartdoca/slate`, `@smartdoca/markdown`, `@smartdoca/sheet`, `@smartdoca/canvas`, 그리고 `@smartdoca/slides` package.json과 lockfile에 의해 고정된 패키지입니다. 개인적인 소스 디렉터리나 오래된 vendor tarball은 필요하지 않습니다.

다섯 개의 구성 요소는 각자의 모델, 코덱, 스키마, 에포크, 뷰를 유지하면서 교통, 권한 및 현지 업데이트 대기열을 공유합니다. 구성 요소들은 설치하기 전에 권위 있는 체크포인트/베이스라인을 복원합니다. 로컬 설정, 읽기 전용, 선택 및 저장 상태 변경은 문서를 재구성하지 않습니다. 스프레드시트는 풍부한 텍스트 모델을 사용하는 대신 불변한 베이스라인 및 프로토콜 데이터를 유지합니다.

<a id="connection-and-messages"></a>

## 연결 및 메시지

WebSocket은 사용합니다. `/api/v1/ws`브라우저는 세션 쿠키와 함께 동일한 원산지에서 업그레이드를 수행합니다. 프록시는 Upgrade/Connection을 전달합니다. 공개 리소스는 그 가시 범위 내에서 읽기 전용 연결을 허용합니다. 각 탭은 콘텐츠, 알림, 존재 상태와 관련하여 호스트 연결을 재사용합니다.

Yjs bytes는 JSON 포맷 내에서 base64를 사용합니다. 실제 메시지와 형식 검증은...에 의해 정의됩니다. [게이트웨이](../apps/server/src/services/realtime/gateway.ts) 그리고 [프로토콜 검사](../packages/core/src/modules/collaboration/protocol.ts):

| 메시지 | 현재 목적 |
| --- | --- |
| 준비됨 / 참여함 | 연결 준비 완료, 참여하여 코덱/스키마/프로토콜버전을 협상하세요 |
| sync-request / sync-response | 권한 관련 차이, epochId, seq, 형식 기준선, 그리고 접근 권한; 동기화 응답은 저장 ACK이 아닙니다. |
| 업데이트 / 확인 | 로컬 수정 사항을 제출하고, 데이터베이스 커밋 후에 해당 메시지를 확인하세요. |
| 존재 / 커서 / 커서들 | 사용자 존재 및 임시 세션별 선택 사항 |
| document.changed / notifications.changed | 콘텐츠/상세 정보를 무효화하거나 지속적으로 저장된 알림을 읽기 |
| 놓기 / 오류 | 허가, 프로토콜, 연결 오류에 대한 정보 |

시대가 알려진 후에는 편집 작업에 해당 시대에 적용되는 프로토콜, 코덱/스키마, 그리고 시대 정보가 반드시 포함되어야 합니다. 식별자, 연결 ID, 이름, 색상은 서버에서 제공됩니다. 저장 및 방송 작업 시에는 현재 접근 권한을 다시 확인해야 하며, 클라이언트가 주장하는 식별자는 절대 사용되어서는 안 됩니다.

<a id="save-reconnect-and-history"></a>

## 저장, 재연결, 그리고 기록

실제 현지 콘텐츠 거래만이 포함됩니다. `update-outbox.ts`초기화, 원격 애플리케이션, 존재 상태 표시, 스크롤, 크기 조정은 콘텐츠를 전송하지 않습니다. 대기 중인 편집 내용은 원본 바이트와 메시지 ID를 그대로 유지합니다. 일치하는 ACK는 업데이트를 제거합니다; 동기화 응답과 알 수 없는 ACK는 큐를 깨끗하게 하지 않습니다.

서버는 트랜잭션 내에서 콘텐츠와 파생된 프로젝션을 검증하고 저장한 후 확인하고 브로드캐스트합니다. 수신 내용은 리소스, 에포크, 메시지 ID에 따라 중복을 제거하며, 동일한 ID이지만 바이트가 다른 경우는 거부됩니다. 체크포인트는 CRDT 식별자를 보존하며, 독립적인 역사 기록은 각자의 형식, 계보, 자산을 유지합니다. 자세한 내용은 참조하세요. [역사와 복원](document-experience.ko.md#history-and-restore).

현재의 호스트 어댑터는 전송하기 전에 IndexedDB에 원본 Yjs 체크포인트, 기준값 및 인식되지 않은 메시지를 유지합니다. 재연결 시 권위 있는 상태를 가져와 원본 ID와 바이트를 다시 시도합니다. 일치하는 견고한 ACK만이 이를 제거합니다. 캐시된 로그인 문서는 백엔드 발견 전에 페이지 메타데이터와 복제본을 복원하며, 마지막 알려진 권한에 따라 오프라인 편집을 허용합니다. 일시적인 서비스 중단 시 편집기 모드가 유지됩니다. 명시적인 세션 또는 리소스 거부는 캐시된 메타데이터를 숨기고 대기 중인 작업을 보존합니다. 데스크톱 번들 또는 이전에 다운로드한 웹 프론트엔드는 서비스 중단 시 오프라인 문서 목록을 열 수 있습니다. [오프라인 문서 및 복구](access-offline-events.md#离线文档入口).

<a id="presence-and-comments"></a>

## 存在과 의견

사용자 수는 중복 제거되었습니다; 편집 선택 사항은 한 계정의 별도 탭을 포함한 연결에 속합니다. 존재는 일시적이며 내용/기록 저장은 없습니다. 서식 있는 텍스트, 마크다운, 스프레드시트, 캔버스, 슬라이드는 각각 자체 구현된 어댑터를 사용합니다. 읽기 전용 보기는 편집 선택 사항을 게시하지 않습니다.

영구적인 코멘트 앵커는 별도입니다: 리치 텍스트 앵커, 마크다운 범위, 안정적인 스프레드시트 행/열 식별, 그리고 캔버스/슬라이드 요소 영역은 형식별 검증을 사용합니다. 스프레드시트 코멘트는 지원되는 구조적 변경을 통해 안정적인 기록을 따릅니다; 임시 A1 선택은 영구적인 앵커가 아닙니다. 자세한 내용은 참조하세요. [댓글과 알림](comments-and-community.ko.md).

<a id="one-instance-and-replicas"></a>

## 하나의 인스턴스와 복제본들

Redis가 없으면 브로드캐스트, 존재 여부 확인, 제한 사항은 프로세스 내에 남아 있습니다. Redis를 사용하면 콘텐츠 변경, 권한 무효화, 알림, 존재 여부 확인이 인스턴스 간에 이루어집니다. 공유 데이터베이스 콘텐츠는 여전히 유효한 정보로 유지됩니다. Redis Pub/Sub는 영구적인 로그가 아닙니다. 설정된 Redis 장애가 발생하면 지역 버스로 즉시 전환되지 않습니다.

복제본은 공유된 PostgreSQL, 파일 저장소, 그리고 일관된 플러그인 버전이 필요하며, 독립적인 설치 캐시도 필요합니다. 자세한 내용은 참조하세요. [수평 확장](horizontal-scaling.ko.md)전체 부하, 네트워크 장애 매트릭스, 실제 장치는 타겟 환경의 수용이 필요합니다. 자동화된 테스트는 격리된 데이터를 사용합니다.
