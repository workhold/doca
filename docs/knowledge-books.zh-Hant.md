# 知識冊

[English](knowledge-books.md)

知識冊是編排生成的只讀 Markdown 文件樹。可編輯的文件、知識庫、檔案、資料夾、網頁和經過授權的 `content.v1` 外掛內容是它的來源。多人共同維護來源、流程和驗收規則；個人 AI 助手使用與頁面相同的命令和許可權，不再提供第二個共享機器人，也不共享個人會話或記憶。

<a id="多人共建"></a>

## 多人共建

開啟「知識冊」建立專案，透過「許可權管理」邀請協作者。許可權面板和角色邏輯與個人文件一致：讀者檢視，評論者提交反饋，編輯者維護配置和自己的來源授權，管理員還可以管理許可權、移除其他貢獻者的來源。只有貢獻者可以更改自己來源的範圍。配置、來源和反饋都使用版本校驗，多人同時儲存會返回衝突，不覆蓋他人的修改。

知識冊複用知識庫資源承載許可權。普通文件建立、移動、複製介面不能向其中寫入內容；標題、許可權、回收站等生命週期仍由宿主管理。生成頁面屬於不可修改的成果版本，不作為協同編輯文件儲存。

<a id="配置与运行"></a>

## 配置與執行

1. 設定目標、模型、第一層知識型別和最大目錄深度。
2. 新增來源。短列表以卡片展示；逐個校驗來源及其子內容的原許可權。知識冊管理員身份不授予來源訪問權。
3. 調整 X6 流程圖。拖動節點排版，透過連線或節點面板選擇輸入，修改規則、來源範圍、權重和驗收項。儲存時校驗輸入型別、環路、標識、可達性以及唯一發布節點。
4. 定義驗收標準。所有配置的驗收項必須得到評估，必需項必須透過才能釋出。
5. 發起持久化執行，檢視節點結果並處理人工待辦。排隊不等於已生成成果。

節點包括來源讀取、人工反饋讀取、事實提取、彙總決策、文件樹組織、驗收、人工審閱和釋出。執行凍結配置及輸入版本；普通執行拒絕配置或來源變更。失敗後顯式繼續當前流水線時仍使用它的固定配置，即使後續執行的設定已修改；來源及反饋必須保持一致。釋出前再次校驗來源內容。不支援的格式、過大輸入、提取未完成、偽造引用、模型輸出截斷都會明確失敗，不默默釋出不完整成果。

知識冊卡片為編輯者提供重新命名，為擁有者提供刪除。刪除複用資源回收站及恢復流程，配置、來源和成果保留。從知識冊開啟的助手攜帶本冊作為當前資源，泛化的知識庫意圖不覆蓋當前知識冊。

定時整理按 UTC 的每日或每週週期執行。自動釋出是顯式配置；關閉時，驗收透過後生成釋出待辦。執行失敗保留上一個已釋出版本，併產生異常處理待辦。

<a id="来源组与网络来源"></a>

## 來源組與網路來源

「執行流水線」以左側列表、右側畫布鋪滿子頁面，列表獨立滾動，列出狀態、觸發人或定時任務、開始時間和持續時間。點選立即切換選中項，已有快取先展示，再讀取最新授權資料；過期請求不能覆蓋新選擇。畫布使用精簡介面，不載入完整節點正文和密集溯源。輪詢只更新變化的節點，保留當前視角；離開頁籤或瀏覽器隱藏時停止輪詢。窄屏開啟失敗流水線時先定位失敗節點。選擇一次執行檢視其凍結流程；直接點選節點，在右側抽屜檢視對應日誌、錯誤與人工待辦。點選抽屜遮罩或畫布空白關閉節點詳情。日誌記錄實際的來源、分批、模型請求/輸出字元數和重試，未記錄的歷史日誌不補造。執行中持續重新整理，等待稽核時間計入總持續時間。

AI 助手啟動或重試執行後保留原任務等待後臺執行；後臺完成或人工決定喚醒同一任務，恢復前複驗當前許可權。助手可以說明待審批事項並繼續等待，不會因為收到通知就代替使用者審批。其他安裝外掛可使用同一[公開喚醒服務](plugin-ai-continuations.zh-Hant.md)。

獨立的 5 秒補償巡檢在模型請求執行期間繼續執行，回收 15 秒心跳已失聯 5 分鐘的工作程序，喚醒已經登記等待的助手，併傳送執行失敗、人工稽核、待發布的站內通知。待處理人工任務作為持久化通知來源，按任務 ID、revision 和接收人去重，支援重啟補發及多例項併發。通知記錄中的原執行發起人（仍有編輯許可權時）和當前知識冊管理者，讀者不接收；通知列表和未讀數複驗編輯許可權，可見導航鈴鐺顯示未讀數字，已讀後同步更新；點選進入對應待辦。目前是站內通知，未接入郵件或裝置推送。

此次通知擴充套件已獲得同意，複用當前 notifications 表和資料庫代際，不增加表列或執行遷移。歷史流水線、錯誤、待辦和通知不改寫；啟動補發仍待處理的任務，不補發已解決、已取消的任務。現有嚴格來源格式及資料庫代際拒絕規則不變。宿主和 Web 構建需要一起部署；回退時保留新通知記錄，舊介面可能無法正確顯示其型別。完整節點之外，已驗證的完整規劃、分配、提取、寫作和質量檢查請求儲存為原執行內的批次檢查點；半截流響應不儲存。模型返回後以及節點失敗/完成寫入時複驗工作租約，防止舊模型響應遲到後覆蓋恢復流水線的已完成節點。

一個來源卡片可以繫結多個文件、知識庫、檔案、資料夾、外部連結或外掛配置，也可混合繫結。配置只接受 `{version: 1, items: [...]}`，每項有穩定的 `id`。每組最多 50 項，禁止重複和巢狀；舊單項配置明確拒絕，不轉換歷史資料。組貢獻者必須有每項的原資源許可權。

網頁選擇器支援批次連結和網路搜尋。搜尋使用系統配置的 SearXNG 等搜尋服務，可限制站點。正文校驗、有效來源儲存和流程中的來源讀取統一使用 AI 設定繫結的網頁讀取服務（內建、Firecrawl、Jina 或 Tavily）。帶章節片段的連結透過所選服務返回的 HTML 驗證並擷取準確範圍；Firecrawl 和 Jina 支援此方式，Tavily 需使用整頁連結或改選支援 HTML 的讀取服務。服務失敗會明確報告，不自動切換到其他服務。結果卡片供選擇，摘要不是證據。加入連結前驗證實際正文、所選片段和內容大小，儲存有效來源時服務端再次抓取。任何連結失敗都不會部分儲存。暫停來源保留配置，重新啟用需驗證。私網來源地址、攜帶憑據的 URL、缺失片段和不可讀頁面拒絕使用；向外部服務提交來源連結前仍由宿主校驗公開地址。

通用 `content.v1` 提供方同時可用於原知識庫訂閱和知識冊，沒有另外一套知識冊專用外掛註冊介面。組中可以多次選擇同一提供方的不同配置。繫結或貢獻者失權時阻止新讀取；成果展示仍檢查具體證據引用。

編排畫布左側按來源與人工輸入、AI 知識整理、審閱與釋出分組展示已有節點型別。點選加入節點後配置規則、連線輸入。卡片顯示節點型別、規則摘要及來源／驗收範圍；點陣畫布支援曲線連線、平移、縮放、適應畫布和展開。拖動或修改規則保持當前視角，展開後可按 Escape 收起。畫布工具按鈕左對齊，節點面板可單獨收起，頂部工具欄也可隱藏；畫布保留恢復按鈕。釋出節點保持唯一，儲存仍驗證完整流程。

流程設定直接點選畫布中的節點修改；下方不再重複顯示節點編輯卡片。左側節點面板的圖示、名稱和說明統一左對齊。修改後點選「儲存」。

<a id="人工介入"></a>

## 人工介入

所有人工審閱節點、釋出審批和失敗節點都進入「人工待辦」，同時支援跨知識冊和知識冊內查詢。按型別、狀態過濾，檢視候選正文與驗收結果，然後透過、退回或繼續執行。處理動作使用版本校驗，避免重複審批；輸入已變化的待辦不能批准舊結果。異常待辦透過 `resume` 繼續當前固定流程；獨立的 `retry` 介面仍按當前配置建立新執行。內容重做後，下游人工審批重新進入待辦並增加任務版本。同一待辦再次處理時，原有決定、處理人、意見和時間保留在宿主安全審計中。

通用驗收項只定義一次，各驗收節點透過 `criterionIds` 複用；領域特有範圍保留在節點規則。驗收以執行凍結配置中的描述及明確的例外為準，`grounded` 等 ID 沒有內建的“只能使用 Manual”含義。明確允許準確行業常識時，不能僅因來源沒提到就拒絕；要求來源支援時仍須檢查證據，允許常識也不代表允許技術矛盾或算術錯誤。修改當前配置後，`resume` 仍使用舊執行的凍結規則，應用新規則需要新建重試。

多個節點使用同一個必需驗收項時，每個節點仍獨立評審，任何未透過項預設阻止釋出。對有完整候選正文、完整驗收結論且因必需項失敗而停止的驗收節點，人工待辦提供“接受已知問題並繼續”。必須填寫接受哪些已知問題，再確認當前候選；技術失敗、缺少正文或缺少有效驗收結果不提供此操作。失敗 checks 和節點失敗狀態原樣保留，不改成模型透過；決定、操作者、意見、候選與配置雜湊進入審計和成果溯源。批准後複用該候選，仍執行後續人工節點；未開啟自動釋出時，還要完成釋出審批。單純 `run.publish` 不繞過待辦。

人工放行使用現有待辦的 resolution 記錄 `acceptanceOverride.version=1`，配置、流水線和成果仍為 version 1，不增加 SQL 結構、不轉換舊記錄。沒有這個明確決定的舊 resolution 不授予放行。釋出前重新檢查批准者許可權、來源訪問、輸入快照、當前及凍結配置和原候選；變化後原決定失效。宿主與 Web 應成套更新；回退時先停止新執行，舊程式碼仍能讀取已釋出的同格式成果及失敗 checks，但不會識別新放行決定，不能依靠舊執行器繼續尚未釋出的人工放行。

「AI 操作示例」提供補充來源、合併驗收項和段落糾錯的請求模板，傳送前由使用者修改確認；「我的操作記錄」列出當前使用者與該知識冊有關的個人會話，其他管理員的 AI 對話和記憶不會一起展示。

評論、糾錯、補充和疑問是有版本的編排輸入，可以手動新增，也可以要求個人 AI 助手登記。反饋可以定位到某個成果版本、文件和段落；定位受限成果需要原證據訪問許可權。修改反饋產生新輸入版本，不直接改變成果段落。權重和採用規則由節點配置決定，高權重不能使沒有證據的說法自動成為事實。

<a id="成果与溯源"></a>

## 成果與溯源

預設使用純閱讀模式，只展示渲染後的文件；切換到「審閱」才展示段落反饋、證據數和採用依據。切換隻是頁面檢視，不改變已釋出 Markdown 或溯源。

目錄標題完整換行，章節與頁面層級清晰，展開圖示位於標題前。點選目錄會開啟其下第一個文件，並展開到選中文件；箭頭只控制展開或摺疊。目錄和正文各自滾動，來源、流程和待辦列表也可獨立滾動。

正文提供路徑麵包屑、分級小標題、本頁導航和按目錄順序切換的上一篇／下一篇。寬閱讀區在右側顯示導航，窄閱讀區摺疊在正文上方；導航隨滾動高亮，可以透過鍵盤定位。導航來自實際 Markdown 標題，程式碼塊中的 `#` 不作為標題；沒有標題的正文不生成虛假的段落目錄，原文保持不變。新執行要求彙總與文件樹節點輸出有意義的二、三級標題，歷史成果不被改寫。exmd 已釋出的 `MarkdownPreviewInteraction` 介面負責渲染定位，宿主保留原圖片許可權解析。

新生成內容圍繞實際知識詳解展開：定義、組成關係、執行機制、條件、例外、權衡與有依據的示例；架構與流程使用真實 Mermaid 程式碼塊，不能只寫“圖”的文字說明。學習指引只作簡短引言。普通匯總每批最多處理 40 條知識判斷，文件樹組織按正文規模分批並保留細節。遺漏不同知識判斷、長文沒有小標題、組織時刪光已有 Mermaid 圖都會觸發修復。大章節按當前每頁 200 段限制分篇，不丟棄正文。這些規則只校驗新輸出，不改寫歷史成果。對結構正確但引用或正文量不足的章節，先進行一次同範圍的完整補寫，仍失敗再拆分；結構錯誤和硬預算錯誤仍按完整單位縮小請求。僅剩一個不可再分的知識點時，最後一次有限補寫可把達到估算預算 75% 的內容作為候選交給後續檢查，此前仍按 90% 補寫；整冊字數與深度要求繼續使用實際正文驗收，估算預算不能充抵字數。固定章名與路徑長度進入模型私有輸出約束，並複驗準確值。

顯式目標達到兩萬字的長文先用來源標題和代表性判斷規劃簡短章、節目錄，再每批最多 32 條判斷歸屬到固定節，由程式檢查每條判斷恰好分配一次並彙總。規劃不一次返回全冊判斷的分配表。本批未分配的小節空佔位不會丟失判斷；分配的格式或覆蓋失敗也按完整判斷繼續縮小請求，直到嚴格滿足每條恰好一次，或無法繼續修復時明確失敗。規劃儲存在執行上下文，並可寫入獨立批次檢查點；不增加配置或已釋出成果欄位。撰寫按節分批，每批最多 12 條判斷，並按模型輸出預算預先縮小批次，保留分配到各批的完整字數配額與引用；不可再分的單條判斷仍進入既有的有限補寫與明確失敗流程。正文匯入固定章節；編排沿用已有章名和路徑，不讓每個小批次重新擴張目錄。 撰寫、編排和細節驗收以已引用證據為錨點，在最多 160000 字元內補入同一來源的完整關聯塊；超限時優先保留臨近原文塊，不截斷段落，不引入無關來源。選擇的上下文同樣複驗來源許可權。目標中的深度用於因果推導、完整場景/算例、邊界反例和證據驅動的故障診斷，不以更多目錄項或重複概覽充抵。是否需要各類案例仍由使用者配置的目標和驗收條件決定。長文驗收按更小的章節片段檢查（最多 3000 個 Markdown 字元和 12 條關聯判斷，單個完整段落仍不可截斷），避免協議與數值錯誤被大上下文掩蓋；每片明確標註檢查範圍，在彙總中組合章級義務的實際證據。保留案例前核對協議身份、收發方向與原規範演算法。驗收 JSON 修復保留事實失敗，並要求準確的驗收項標識。標題、關鍵詞和字數不能作為深度透過依據。版本 1 格式與已儲存資料保持不變。

寫作請求觸及輸入上下文、輸出字元保護或模型 Token 上限時，按完整知識判斷或段落繼續拆小請求，彙總透過校驗的結果；不足 40 條判斷的章節也可以分多次生成。截斷或結構無效的多單元 JSON 會丟棄並繼續拆小請求，不反覆請求同一份大輸出；不可拆分的單元只做有限次修復，仍無效時明確失敗。配置、流程和成果仍使用第 1 版格式，已有資料不轉換。單來源組、單次響應和釋出規模保護保留；節點組合來源不再受 120,000 字元的舊上限約束，模型輸入按批次處理。`book_size_limit` 是共用的錯誤分類，不能由此推斷整冊總位元組配額。新錯誤透過已有展示協議的 `data.detail` 保留具體原因，歷史僅存通用程式碼的錯誤不能逆向恢復。大冊儲存與剩餘限制見[儲存評估](knowledge-book-storage-assessment.zh-CN.md)。

提取、寫作、文件樹組織和詳細驗收在單節點內最多兩路獨立批次併發，失敗會取消並等待另一路結束。獨立質量觀察的分層彙總也使用相同的兩路併發上限並保持原順序；只有一條觀察的分組保留完整結論，省去重複模型彙總。已失敗的區域性檢查仍阻止透過，最終整冊檢查仍執行。顯式字數目標先分給寫作分支，再分給批次。正文字元數不包含程式碼和圖表原始碼；圖表數按實際 Markdown 程式碼節點統計，不計外層程式碼塊中的示例。新寫作和編排結果在帶超時限制的隔離工作執行緒中透過已安裝的 Mermaid 解析器檢查，語法錯誤進入有限次修復；這一步不渲染 SVG，也不改寫歷史釋出版。組織時縮減超過 10% 的正文會被拒絕，繼續拆小的請求也執行此限制。驗收先將每個已配置條件拆成區域性與全冊義務，不把來源中的教學目標增加為驗收要求。總字數、完整主題覆蓋和圖表型別是否存在屬於全冊檢查，批次只檢查當前呈現的斷言與圖表。驗收按完整段落攜帶關聯判斷和證據檢查，再用宿主統計、目錄和有界的批次結論檢查全冊要求，不把全文重新交給最終模型請求。任一最終詳細批次失敗都會阻止對應驗收項透過。驗收獨立判斷當前候選正文，舊失敗意見只交給內容修復，不進入新驗收結論；每個驗收項必須完整返回一次。每次模型呼叫，包括全冊彙總，都複驗相關來源許可權。

助手調整節點前先讀取輸入型別規則。同類寫作節點串聯仍不允許，錯誤會指出具體連線。修改配置隻影響後續執行；patch 節點後呼叫 `run.resume` 不會把新引數應用到凍結執行。需要應用新配置時，在明確要求新建重試後使用 `run.retry`。

成果複用 exmd 的只讀渲染，頁面包含文件樹、版本選擇、段落反饋、採用依據和經過校驗的來源引文，不提供 Markdown 原始碼編輯器。

溯源圖完全由實際執行結果生成，連線來源版本、證據、知識判斷、採用決策、段落、文件、節點執行和成果版本，也記錄人工審閱決策。它不能單獨編輯。可以檢視整個網路，或檢視某篇文件的上游關係，點選節點檢查具體依據。預設按來源合併證據、按當前檢視範圍合併知識判斷，同類關係合為標註數量的連線；點選分組檢視原始成員，也可關閉合並檢視細節。只調整展示，不修改成果中儲存的原始關係或證據。

來源全文保留在來源系統和執行時記憶體中。成果、節點日誌和批次檢查點只保留引用片段、雜湊、來源定位及驗證後的結果，不再建立額外的全文副本庫。來源更新不會改寫歷史成果。讀取成果及節點日誌時檢查原來源許可權；外部來源刪除、解綁或提供方不可用時，相關成果停止展示，保留的資料不被刪除。

貢獻者失去知識冊編輯許可權後停止抓取其來源。之前生成的資料可以保留，但保留不等於授予顯示許可權。任意模型上下文來源不可訪問時，合併成果保守地停止展示，包含模型最終沒有引用的輸入。

## 人工與 AI 共用介面

路由字首為 `/api/v1/knowledge-books`：

| 路由                                | 用途                                                   |
| ----------------------------------- | ------------------------------------------------------ |
| `GET /`、`POST /`                   | 列表、新建                                             |
| `GET /:id`                          | 配置、來源、反饋、執行及已釋出成果                     |
| `POST /:id/commands`                | 人工與 AI 共用命令                                     |
| `POST /:id/source-search`           | 檢查編輯許可權後透過已配置服務搜尋網頁                   |
| `POST /:id/source-web-check`        | 驗證連結正文與所選片段                                 |
| `GET /:id/runs/:runId`              | 執行與候選結果                                         |
| `GET /:id/runs/:runId/pipeline`     | 經授權的精簡畫布資料，不返回完整節點正文及溯源         |
| `GET /:id/releases/:releaseId`      | 不可修改的成果版本                                     |
| `GET /human-tasks`                  | 按知識冊、執行、節點、關鍵詞、型別、狀態、偏移查詢待辦 |
| `POST /human-tasks/:taskId/resolve` | 帶預期版本透過、退回、繼續或新建重試                   |

命令包括 `configuration.save`、`configuration.patch`、`workflow.node.patch`、`workflow.node.add`、`source.remove`、`source.save`、`feedback.save`、`feedback.withdraw`、`run.start`、`run.cancel`、`run.resume`、`run.retry`、`run.publish`。配置、來源和反饋儲存必須提供 `expectedRevision`。`packages/core/src/modules/knowledge-books/protocol.ts` 是第 1 版協議定義。AI 的 `knowledge_book` 工具呼叫相同業務函式，個人助手的會話和記憶仍屬於真實使用者。AI 讀取目錄清單後，透過 page 分頁讀取正文和證據，或用 find 定位段落；登記的反饋保留真實操作者和手動/AI 助手入口。來源節點與分析節點權重相乘，同一證據從多個來源節點到達時取最高權重，避免重複輸入抬高可信度。

<a id="旧整理卸载与数据库边界"></a>

## 舊整理解除安裝與資料庫邊界

舊知識庫整理和問答機器人已移除，不再提供整理會話、工作器、設定、指引、條目或生成普通文件的投影。文件、來源訂閱、索引和搜尋保留。知識庫導航移除「來源與訂閱」入口，已有訂閱記錄保留。

當前原始碼資料庫基線為 `doca-2026-10-12-book-payload-storage-v1`。0.1.24 對已釋出 0.1.22 的 `doca-2026-10-09-history-storage-v1` 啟動時自動檢查並對齊結構，在同一 schema 事務中記錄目標代際。全部業務行及釋出指標原樣保留，包括舊 SQL 生成成果；執行時僅支援新版物件引用，不增加舊正文讀取適配，不自動轉換或單獨清理。殘留舊成果可能需要人工處理後才能使用相應知識冊。已有 0.1.23 物件儲存資料原樣保留。見[運維與恢復](knowledge-book-storage-verification.zh-Hant.md)。知識冊目標表保留，舊知識庫整理表及欄位繼續停用。正常啟動拒絕更早、未知及轉換中斷的代際；僅準確的上一歷史基線可按[部署步驟](deployment.zh-Hant.md#从-0113-升级)顯式離線升級歷史儲存。舊檔案繫結保留且繼續拒絕訪問，不恢復舊整理協議；不得刪除已有資料庫來啟動新版。

失敗或取消的執行透過 `run.resume` 繼續當前流水線，保留執行 ID、固定流程、已完成節點和失敗日誌。繼續前複驗來源登記、反饋、原許可權及完整的實時來源清單，包括證據標識、版本和內容雜湊；來源內容增刪或改變時拒絕混用輸入。驗收未透過時，從最近的上游內容生成節點及其下游修復，保留知識抽取和無關分支，把此前驗收結果作為修復依據。重複失敗或後臺執行中斷使用原節點與待辦記錄，保留已記錄的失敗事實及處理意見。只接受當前第 1 版配置，不轉換舊格式、不遷移或刪除資料。

負面驗收意見先複驗其候選頁面與當前已完成內容是否一致。編排已修復候選、隨後驗收遇到介面或結構錯誤時，舊候選的負面意見保留為歷史診斷；續跑複用當前編排並重新驗收，不再次用舊意見覆蓋新內容。對當前候選的真實負面驗收仍觸發內容修復。比較使用已有 v1 頁面內容，不增加儲存欄位或按舊錯誤文案猜測原因。

修復失敗驗收時，只有已審閱候選正文的引用範圍與當前授權上游範圍完全一致、重複頁面標識內容一致，編排才以該候選正文為起點，使意見中的頁面標識能正確定位並保留前一輪修正。帶頁面定位的意見交給對應批次，缺少標識時可用獨特程式碼值定位；無法定位的意見仍檢查是否適用，不靜默丟棄。未受影響的候選批次經結構複驗後保留原段落，不重新改寫。詳細驗收失敗意見附上當前頁面標識，為每個失敗批次保留摘要，避免總長度截斷隱藏後續章節的錯誤；仍按當前證據獨立核實，不將舊意見作為事實依據。前次候選正文不會整冊進入模型請求；完成節點和已存第 1 版格式保持不變。

原 `run.retry` 仍是獨立的新建執行操作。重試保留原執行，只有凍結配置、來源登記、反饋及完整的當前來源清單均一致時，才複用完成節點；來源不可用、增刪塊或內容變更均阻止複用。人工審批節點及其後續節點重新處理。每個複用節點在審計與溯源中記錄原執行。每次廠商模型呼叫之前都複驗貢獻者授權，包括分批提取與格式修復。

公開只讀檢視只顯示渲染成果和溯源，不暴露編輯配置或構造虛假的預設流程。歷史成果遵循原文件歷史許可權。溯源可定位到文件或段落，流程執行和模型上下文關係可單獨開啟。

<a id="正文对象存储"></a>

## 正文物件儲存

節點輸出、執行成果和釋出成果使用宿主現有私有物件儲存。正文字串按同冊雜湊共享，原始 JSON 位元組和第 1 版成果結構完整保留；相同執行/釋出成果共享根清單。資料庫保留嚴格引用、許可權清單、摘要、物件依賴和上傳清理日誌。介面與助手輪詢使用摘要；展開候選成果才讀取正文。快取命中仍復驗當前來源許可權。回收站保留引用，永久刪除釋放引用後由持久化清理回收不再使用的物件。詳見[實施方案](knowledge-book-payload-storage-plan.zh-CN.md)。

分片驗收按原始驗收項限制區域性義務：明確標為教學模擬的自選初始值無須逐字出現在規範算例中，但必須滿足規範條件且計算、欄位及狀態變化正確。缺少整章案例或排障步驟在章級彙總判斷，不要求每個片段重複整章義務；按章合併時保留具體初始狀態、推導、結果和判別證據，不能只保留“深度良好”的結論。

長文細節驗收列出當前完整段落中的逐項斷言，模型須為每項原始標識返回結論，遺漏、重複或未知標識均觸發有限修復。程式根據逐項結論生成原有第 1 版 checks，不寫入新的持久化欄位；總體正面評價不能覆蓋具體失敗。中間提取的判斷若與原文衝突，正文和採納說明必須明確糾正或排除，不能照抄錯誤。

每句斷言只核查一次，以違反的驗收項標識關聯結果；沒有違反項時返回空列表。各驗收項的章節深度觀察單獨彙總，避免為每個驗收項重複整套斷言列表。透過斷言只寫簡短判斷，錯誤保留具體計算或規則衝突。已驗證的 Doubao Seed 2.1 請求原生 JSON 物件輸出，繼續由宿主嚴格檢查業務結構；不接受雙重轉義或思考文字替代物件，介面拒絕時明確報錯，不靜默回退。

逐項檢查使用最多 24000 字元的相關規範塊作為上下文；斷言提示伴隨完整段落，不替代或截斷正文。細節失敗記錄具體段落和原句；能準確定位的段落優先決定修復批次，其他批次複驗後保留。新模型圖源語法失敗時，可為單層方括號標籤補上雙引號，再經真實解析器檢查；節點文字、連線和圖型別保持原義，複雜語法錯誤仍由有限模型修復處理。歷史成果不自動改寫。

針對已確認能力的 Doubao Seed 2.1，實質抽取、撰寫、編排和驗收請求開啟原生思考；目錄規劃和判斷歸屬保持短輸出。普通實質請求使用 medium 思考投入，逐項檢查也使用 medium，由現有固定 SDK 對映到官方引數。引數拒絕會報錯，不自動切換模型或靜默降級。本次不修改提供方已有的 Responses/Chat 和可選 reasoning 摘要適配邏輯。配置中的模型、輸入與輸出預算以及 v1 儲存協議不變。

同一次執行在有界記憶體中保留完整失敗斷言，只有候選正文雜湊與證據／判斷範圍雜湊均匹配時才用於修訂。持久化仍使用原第 1 版驗收摘要，保留可執行的錯誤原因及段落位置。正文已改後發生的技術性驗收失敗，續跑複用該已完成正文，不把舊失敗評價重新套到它上面；來源及許可權繼續複驗。真實模型驗收指令碼先獨佔執行再啟動 HTTP 閱讀服務，避免後臺執行器搶佔測試執行而繞過診斷觀察。

有界逐項驗收先保留已引證據，再按當前段落中的協議、欄位和狀態術語選擇完整相關規範塊，最後補入臨近塊；不引入未關聯來源。每個子句、欄位數量、位寬和計算結果分別核對。

數字形式的條目／欄位數量子句還會作為同一完整段落中的獨立原文片段接受檢查，不能用正確的位元組總和證明欄位數量正確。這些提示僅用於執行，不增加持久化驗收欄位。

教學類比不能建立另一個協議的演算法、狀態遷移或診斷操作建議。這類建議仍須有目標協議的原始依據；同一句中正確的源協議規則不能替無依據的其他協議斷言背書。

逐項檢查存在失敗結論時，可將同一已授權來源的範圍從24000字元擴大到最多100000字元，對不變的段落獨立重檢一次。段落與診斷中的特有術語繼續排序完整規範塊；擴大範圍也能補入翻譯後缺少來源語言匹配詞的規則。補證不依賴拒絕理由的語言、措辭或缺失關鍵詞。配置的模型輸入預算仍是硬限制。兩個嘗試均保留診斷記錄，內容修訂僅採用最終判斷；證據不變則不重檢，不刪除必需驗收項，實際計算矛盾仍須拒絕。這是補入依據後的實質複驗，不是為了修復JSON格式把失敗改為透過。

一次執行的總時限為四小時，使長冊的細緻驗收和有界證據補查可以完成。單請求輸入／輸出保護、顯式取消、十五秒租約心跳和五分鐘中斷恢復繼續生效。續跑複用已完成節點及已驗證的完整請求檢查點，半截流響應不落盤。

批次檢查點採用獨立表和私有物件引用，限原執行、原節點和完全匹配的輸入範圍使用；恢復時重新檢查來源許可權、模型配置、演算法版本和執行租約。否決結論原樣保留，損壞、未知版本或丟失物件明確停止。`DOCA_BOOK_BATCH_CHECKPOINTS=off` 可在當前版本停用批次續跑並保留所有記錄和物件。部署、回收及恢復約定見[生成效能與批次檢查點](knowledge-book-generation-performance.zh-Hant.md)。

第1版驗收摘要超過4000字元時，最多保留24個均勻分佈失敗範圍（含首尾）的具體錯誤與唯一段落定位，並明確列出省略的失敗範圍數量。省略項仍阻止驗收透過；記憶體限制內的完整候選診斷繼續用於同一次執行的修訂。歷史摘要不回寫。

證據檢索保留完整標識，同時匹配空格、連字元、駝峰詞的組成部分及帶數字的事件字首，使常見文字寫法能夠找到同一規範事件；不改寫原文或來源許可權。

片段驗收額外攜帶前後各兩段、合計最多6000字元的完整相鄰上下文，解析前文定義和後續圖表，不增加被審斷言；原始全證據範圍繼續複驗許可權。當前Mermaid語法由真實解析器檢查，合法等價寫法不能僅因形式差異被拒絕，真實語法錯誤則阻止對應已配置圖表／格式驗收項透過。語法透過不能覆蓋語義失敗。

廠商及傳輸暫時異常，包括成功HTTP響應的SDK處理失敗和缺少完成標記的流，在既有三次呼叫上限內重試同一有界請求。丟棄未完成的流文字，重新校驗來源許可權，取消仍立即生效。引數拒絕、鑑權／許可權失敗及請求容量錯誤不按暫時異常重試；不切換模型、引數或響應協議。

中間驗收匯總僅合併當前最多12個檢查結果及其章節身份，使用明確的區域性範圍，不攜帶整冊目標作為該組的透過義務。未出現的其他章節留待後續全冊判斷；該組已有失敗或矛盾仍須保留。最終驗收繼續使用原始條件、完整目錄、統計和全部章節彙總，不能因區域性彙總透過而省略章節要求。

數量子句的檢查提示保留“第”等序號字首及其空格，避免把“第4個報文丟失”誤讀為“四個報文丟失”。完整原段落繼續作為檢查上下文；提示抽取不改寫正文或歷史驗收記錄。
