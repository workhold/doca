# 파일 교환 통합 계약

[中文](editor-file-exchange-contract.zh-CN.md)

이 계약은 Doca 편집기 간의 파일 가져오기/내보내기 및 변환 패키지 업그레이드에 적용됩니다. 기본 콘텐츠와 허용되는 스타일링이 완전한 Office 정확도보다 우선합니다. 기록된 손실은 허용되지만, 중요한 콘텐츠는 사라져서는 안 됩니다. 책임과 수용 요구사항이 모든 패키지가 모든 인터페이스를 이미 구현하고 있다는 것을 의미하지는 않습니다.

<a id="responsibilities"></a>

## 책임

- 패키지는 형식을 식별하고, 모델을 파싱/서식화하며, 변환하며, 자산을 나열하고, 구조화된 경고/오류를 보고하며, 파일 및 압축/이미지 크기 제한을 적용합니다. 독립적인 입력 포인트를 통해 순수한 변환기들을 제공하며, Node/브라우저 요구사항을 명시합니다.
- 호스트는 파일을 선택하고, 리소스를 생성하며, 업로드/다운로드를 허가하고, 피드백을 제공하며, 파일명을 결정하고, 브라우저 다운로드를 실행합니다. 패키지는 플랫폼 API를 호출하거나, 비즈니스 문서를 생성하거나, 다른 저장 채널을 설정해서는 안 됩니다.
- 이전 결과에는 네이티브 모델, 대기 중인 자산, 경고 정보가 포함됩니다. 내보내기 결과에는 Blob, 파일명, MIME 타입, 그리고 경고 정보가 포함됩니다. 통일된 메서드 이름을 가정하는 대신 설치된 버전의 실제 타입을 따르세요.
- 지원되는 유형은 전달된 기능에 따라 결정됩니다. 파일명 수신 필터는 힌트에 불과하며, 파서가 내용을 확인합니다. 제품 UI는 JSON 업로드/다운로드 기능을 제공하지 않습니다. 내부 모델/복구 사본은 이동 가능한 형식과는 별개입니다.

<a id="collaboration-assets-and-security"></a>

## 협력, 자산, 그리고 보안

- 정상적으로 임포트하면 새로운 리소스, 에포크, 그리고 안정적인 식별자가 생성되며, 활발하게 편집된 Y.Doc을 대체하거나 코멘트, 권한, 역사, 또는 아웃박스를 재사용하지 않습니다. 전체적인 대체는 별도의 명시적인 프로토콜이 필요합니다.
- 업로드에 리소스가 필요한 경우, 해당 리스트를 생성하고 자산을 업로드한 후 일회성 초기화를 수행합니다. 서버는 초기화된/열린/수정된 리소스를 거부합니다; 이 엔드포인트는 공동 작업을 우회하는 완전한 저장 방법이 될 수 없습니다.
- 재업로드된 자산은 새로운 문서의 안정적인 ID를 받습니다. 블로브/데이터/임시 서명된 URL이나 가져온 파일에서 얻은 사용자/리소스/권한 ID는 절대 유지해서는 안 됩니다. 외부 자산은 자동으로 가져오지 않으며, 호스트가 지원하는 가져오기 기능은 SSRF, 크기, 원본 제어가 필요합니다.
- SVG와 같은 활성 콘텐츠를 정리합니다. Doca는 캔버스 패키지에 의해 이미 정리된 SVG를 래스터화하고 기존의 이미지 업로드 서비스를 사용하며, 임의의 동일 원본 SVG 실행을 허용하지 않습니다.
- 비즈니스 기록은 공동 작업 계약의 보존 규칙에 따라 관리됩니다. 기록 행을 삭제해도 자산이 참조되지 않은 것이라는 것을 의미하지 않으며, 첨부파일을 삭제하는 것은 정당화되지 않습니다. 내보내기 기능은 현재 내용이나 요청된 보존 버전을 읽어들입니다; 삭제된 버전은 현재 내용을 역으로 표시하는 대신 "찾을 수 없음"을 표시합니다.
- 엑스포트는 현재 리소스 액세스를 강제합니다. 변환 과정에서는 몸체, 선택, 취소, 존재 여부, 저장 상태 등이 변경되지 않으며, ACK를 기다리거나 생성하지도 않습니다. 패키지가 먼저 기본 편집을 필요로 하는 경우, 호스트는 순수한 변환기로 플러시 작업을 숨기는 대신 엑스포트를 호출하기 전에 명시적으로 처리합니다.
- 취소, 실패, 지연된 콜백은 다른 문서/선택에 삽입될 수 없습니다. 서버가 접근을 다시 확인합니다. 중단된 업로드는 서버 자산이 되돌아간 것을 증명하지 못합니다; 문서의 임시 리소스 정리가 이루어집니다.

## PDF로 변환 가능하고 편집 가능한 가져오기

리치 텍스트 PDF 내보내기는 호스트의 기존 로케일/플러그인 환경 아래에서 읽기 전용 포털로 클론된 네이티브 값을 마운트합니다. 공동 작업, 실시간 편집기의 교체, 편집 완료, 체크포인트 작성은 포함되지 않습니다. Markdown 내보내기는 패키지의 미리보기를 동일한 편집기 서체로 마운트합니다. 두 경우 모두 이미지, 공식, 다이어그램의 대기, 계산된 스타일의 복사, 승인된 플랫폼 이미지 및 폰트의 포함, 편집 제어의 제거, 그리고 자체 포함된 보기의 전송을 기다립니다. `POST /api/v1/resources/:id/pdf`비디오/오디오는 허가된 다운로드 링크와 함께 읽을 수 있는 레이블로 변환됩니다. 첨부파일 및 언급 레이블은 여전히 읽을 수 있습니다. PDF 텍스트는 선택 가능 상태를 유지합니다. 페이지들은 측정된 문서 너비를 유지하며 √2의 종이 비율을 사용하고, 24px의 수직 인쇄 여백을 갖습니다. 페이지 번호는 페이지가 없는 화면과는 다를 수 있습니다.

호스트 렌더러는 일회용 파이썬 프로세스에서 핀된 WeasyPrint 70.0을 사용하며, 스크립트 실행은 없고 내장된 데이터 리소스만 사용됩니다. 네트워크 및 호스트-파일 읽기는 거부되며, 누락되거나 손상된 이미지 리소스는 내보내기에 실패합니다. 다시 확인합니다. `read_content` 렌더링 후 읽기 전용/공개 접근 정책을 유지하며, 32 MiB의 입력 데이터, 두 개의 동시 작업, 60초의 마감 기한이 있습니다. AI 캔버스 이미지는 설치된 Canvas SDK SVG 엑스포터를 사용하여 호스트에 적합한 격리된 Node DOM을 통해 작동하며, 네이티브 텍스트 측정 및 resvg 래스터화 기능이 포함되어 있고, 패키지에 포함된 CJK 글꼴도 함께 제공됩니다. 이는 새로운 Node API가 아닌 호스트 어댑터이며, PDF.js 읽기/임포트 및 LibreOffice 변환은 별도로 작동합니다. 재구축된 Docker 런타임은 사용합니다. `node`Python/Pango/CJK 폰트를 포함하며 브라우저는 필요 없고, 호스트 seccomp 파일도 필요하지 않습니다. `DOCA_PDF_CHROMIUM` 거부됨; 소스 설치는 핀된 Python 환경을 설정함 `DOCA_PDF_PYTHON`기존 SDK 역사적 리더들은 원래의 경로를 유지합니다; 데이터베이스/문서 변환이나 브라우저 대체 기능은 도입되지 않습니다. 롤백 시 코드/락/이미지를 복원하면서 배포 설정과 이후의 작성 내용은 그대로 유지됩니다. 브라우저 레이아웃을 보존하기 위해 HTML로 표시된 다이어그램은 PNG 형태로 저장되며, 일반 본문 텍스트는 선택 가능 상태로 유지됩니다. 각 작업에 따른 WOFF2 디코딩을 피하기 위해 CJK 글꼴은 TTF 형태로 제공됩니다. 계산된 colgroup 너비는 개별 열 최소값으로 재적용되지 않습니다.

PDF 가져오기는 편집 가능한 네이티브 콘텐츠를 우선적으로 처리합니다. 배포된 Markdown 파서는 여전히 파일/페이지/이미지의 제한 사항을 검증하고 자산 및 경고 정보를 추출합니다. 그 후 PDF.js 어댑터가 글꼴 크기, 기본 글꼴 종류, 굵은/이탤릭체, 텍스트 색상, 안전한 링크, 크기 기반 제목 계층 구조, 간단한 목록 표시자, 규칙적인 간격의 표 및 순서가 정해진 이미지를 재구성합니다. 서식 있는 텍스트는 그 네이티브 모델을 직접 받으며, Markdown은 이동 가능한 전송 형식을 받습니다. 기존의 자산 재부팅 및 한 번만 수행하는 새로운 문서 초기화는 저장 한계가 됩니다. PDF 배경 채우기, 하이라이트, 벡터 그림, 복잡한 열/표 및 수학적 정보 재구성은 근사치이며, 스캔된 이미지는 OCR 없이 그대로 유지됩니다. 파서의 경고 정보가 표시됩니다. 저장된 모델, 스키마, 기존 형식 변환 또는 마이그레이션 변경 사항은 도입되지 않습니다.

Slate 0.4.25는 ESM/CJS 변환 항목에서 이전 호스트 DOCX 패치를 출시합니다: 직접적인 Word 폰트/크기/색상/배경, 단락 정렬, 명시적인 오프 표시 및 표-셀 표시, 온라인 헤딩 크기, 1.6라인 간격, A4 기본 설정 등이 포함됩니다. 임의로 상속된 Word 스타일, 복잡한 섹션, 정확한 페이지 번호는 검증된 범위 밖에 있습니다. Markdown 0.4.4는 이전 KaTeX/lazy-PDF 수정 사항을 출시합니다. Doca는 편집기 패치 없이 이러한 공식 패키지를 설치합니다. 역사적 패치 파일은 이전 Git 버전에서 복구할 수 있으며, 이를 제거해도 저장된 문서가 변경되거나 공동 작업 형식이 바뀌지 않습니다.

수락: `tests/document-pdf.test.ts` 실제 WeasyPrint PDF 파일, 선택 가능한 중국어 텍스트, 기본적인 PDF 재구성 기능, 실제 DOCX XML/재인입 기능, 그리고 차단된 스크립트/원격 이미지 기능도 지원됩니다. `tests/document-pdf-access.test.ts` 읽기 전용 접근, 취소 및 원본 소스 체크포인트 변경 사항을 커버합니다. `node --import tsx scripts/qa-document-pdf.mts` 개별 브라우저 환경에서 실행, 호스트 컨텍스트 유지 보존 확인 및 Y.Doc 업데이트 없음, 이미지의 내보내기/재인포트, Mermaid/math 및 3페이지 표 검사, 그리고 시각적 결과물 작성 `artifacts/verification/document-pdf/`Poppler를 사용하여 생성된 PDF와 온라인 스크린샷을 함께 확인할 수 있습니다. 사용자 문서나 생산 데이터베이스는 열리지 않습니다.

## 수락 증거

클립보드 작업은 동일한 자산 경계를 따릅니다. 패키지에는 파일/텍스트와 캡처된 삽입 대상이 보고되며, 호스트는 이미지/첨부파일을 업로드하고 내부 링크/접근을 확인한 후 패키지가 일반 편집 거래를 통해 삽입합니다. 비동기 완료는 더 새로운 현재 선택을 사용할 수 없으며, 닫힌/읽기 전용 문서에 작성할 수도 없습니다. 네이티브 스프레드시트의 다줄/탭 붙여넣기는 유지됩니다. 하이퍼링크는 안전한 프로토콜만을 받아들입니다; 내부 문서는 안정적인 ID를 저장하고 배포 도메인 없이 상대 URL을 생성합니다. 현재 스프레드시트 비즈니스 객체는 혼합된 인라인 리치 텍스트 지원 주장 없이 전체 셀을 차지합니다; XLSX 라운드트립은 경고와 함께 읽을 수 있는 레이블로 저하될 수 있습니다.
