# 単一インスタンスと水平スケーリング

[中文](horizontal-scaling.zh-CN.md)

Docaは、追加のインフラが不要な単一インスタンスモードを採用しています。SQLite、ローカルアップロードディレクトリ、およびプロセス内リアルタイムバスは、個人、小規模チーム、または試験環境に適しています。PostgreSQL、共有オブジェクトストレージ、Redisは、複数のアプリケーションレプリカが実行されている場合にのみ設定します。両モードは同じビジネスプロトコルを使用します。SQLiteからPostgreSQLへのデータ転送や二重書きのパスは内蔵されていません。サポートされているデータベースアップグレードは以下の通りです。 [データベースアップグレード契約](database-schema-evolution.ja.md).

<a id="capability-matrix"></a>

## 能力マトリックス

| 能力 | 単一インスタンス | 複数のレプリカ |
| --- | --- | --- |
| データベース | SQLiteまたはPostgreSQL | PostgreSQLでは、すべてのレプリカが同じデータベースを使用する |
| 文書の共同編集と通知 | プロセス内ブロードキャストとプレゼンス | Redis Pub/SubとRedis presence |
| ログイン、アップロード、および公共ボットの制限数 | プロセス内カウンター | Redisカウンター |
| ファイル | ローカル永続ディレクトリ | S3互換のストレージ、またはすべてのレプリカで共有される本当のファイルシステム |
| CDN | オプション | オプション。読み取り速度を向上させるだけで、共有ストレージには代わりにはなりません。 |
| バックグラウンドジョブ | データベースレンタル | 同じリース契約です。どの複製品も仕事を請求でき、失敗した場合は再試行できます。 |
| モバイルプッシュ | データベースアウトボックス | 同じアウトボックスとリース；キューを単一のプロセス内に保持しない |
| スキーマ | 最初の起動により現在のベースラインが作成される | 1つのインスタンスが最初のデプロイ前に空のベースラインを作成する |
| 健康 | `/live` そして `/ready` | `/ready` また、データベースとRedisをチェックします。 |

<a id="single-instance"></a>

## 単一インスタンス

当…時 `DOCA_REDIS_URL` 設定されていない場合でも、リアルタイムイベント、プレゼンス、レート制限はプロセス内に保持されます。Redisは必要ありません。 `pnpm dev`, `pnpm start`そして、1つのComposeコンテナが空のデータベース上で現在のベースラインを作成し、その後、現在のDDLと照合してサポートされている既存の構造を調整する。

このモードでは2つのレプリカを実行しないでください。ロードバランサ上のSticky WebSocketsはしばらくの間問題を隠します。通知、権限の取り消し、オンラインユーザー、およびグローバル制限は依然として分割されています。

<a id="minimum-multi-replica-configuration"></a>

## 最小マルチレプリカ構成

すべてのレプリカには同じ設定が必要です：

```dotenv
DOCA_DATABASE=postgres
DOCA_DATABASE_URL=postgresql://user:password@postgres:5432/doca
DOCA_DATABASE_POOL_MAX=10
DOCA_REDIS_URL=redis://redis:6379
DOCA_REDIS_PREFIX=doca-production
DOCA_TRUST_PROXY=10.0.0.10/32
```

オーケストレーターは設定することができる `DOCA_INSTANCE_ID` ポッドやコンテナ名に合わせて。そうでなければ、各プロセスがランダムなIDを生成する。 `DOCA_REDIS_PREFIX` 同じRedisを共有する環境を分離する必要があります。 `DOCA_TRUST_PROXY` リストには逆プロキシのアドレスやCIDRのみが含まれます。より広い範囲を指定すると、クライアントがIPを偽装し、監査やレート制限を破ることができます。

リリース順序：

1. 空のデータベースに対してインスタンスを1つ起動して、ベースラインを作成します。複数のレプリカが同時に空のデータベースを初期化するのを許さないでください。
2. 同じリリースと設定で他のレプリカを起動します。承認された構造的変更はスキーマロックの下で調整されます。サポートされていない、またはレビューが必要な違いは、部分的な書き込みなしで起動を停止します。
3. ロードバランサーは使用する `/ready` 交通のため `/live` プロセスの健全性のために、WebSocketのアップグレードや通常のドラインが許可される必要があります。
4. ドレインの準備を整え、停止猶予期間内にHTTP/WebSocket接続を切断させる。停止/開始の順序についてはリリース要件に従う。ローリングデプロイメントでは、異なるホストバージョン間の互換性は確立されない。

Redisが設定された後は必ず使用する必要があります。起動時の接続が失敗したり、後でサーバーが停止したり、準備状態チェックが失敗したりしても、静かにローカルバスに切り替わることはありません。これにより、まだ正常に見える複数の単一インスタンスにクラスターが分割されるのを防ぐことができます。

<a id="consistency"></a>

## 一貫性

共同編集はPostgreSQLトランザクションに保存され、承認される。その後、Redisが他のレプリカに通知する。Redisはドキュメントログではない。重複するイベントはプロトコルによって削除される。短い欠落は再接続後にデータベースから修復される。存在期間が終了すると、クラッシュしたインスタンスは消失する。

ファイル認識、テキスト抽出、知識・書籍に関するワークフロー、モバイルプッシュなどでは、データベースジョブやリースが使用されます。発生キーにより、複数のレプリカが同時にスキャンしても1つのビジネスイベントのみが生成されます。ハンドラーはイデミポテントである必要があります。なぜなら、リースが満了した後に別のレプリカが再試行する可能性があるからです。

<a id="capacity"></a>

## 容量

- 全データベース接続数は、レプリカ数×です。 `DOCA_DATABASE_POOL_MAX`PostgreSQLまたはpoolerの制限を超えないようにし、操作やバックグラウンドジョブのためのスペースを確保しましょう。
- ローカルディスクでは複数のホストのアップロードを保持できません。CDNは読み取りのみキャッシュします。オブジェクトはS3や共有ファイルシステムに残ります。既存の名前で指定されたストレージです。 `storage_profile` 利用可能でなければならない。
- Meilisearch、S3、およびメッセージゲートウェイは、すべてのレプリカに同じ設定と同じデータを表示する必要があります。認証情報は共有データベースに保存されます。ネットワークアクセス、許可リスト、キーは依然としてデプロイメントの役割です。
- 共有データベースは、希望するプラグインのリリース情報と不変なZIPファイルを共有ストレージに記録します。各レプリカは、独自の書き込み可能なインストール/キャッシュディレクトリが必要です。`DOCA_PLUGINS_DIR`); スタートアップがアーカイブからそれを検証し復元します。各レプリカの手動再起動後に操作が有効になります。バージョンが一貫している状態を維持してください。 [プラグインデプロイ](plugin-deployment.ja.md).
- Redisは認証、TLS、プライベートネットワーク、メモリ制限、アラート機能を使用すべきです。データベースとオブジェクトストレージにはそれぞれ独自のバックアップが必要です。Redisを失った場合、文書のテキストが失われることはないが、リアルタイム配信、プレゼンス機能、およびグローバル制限が機能しなくなります。
- `/ready` このレプリカがデータベースおよびリアルタイムクラスターに到達できることを証明するだけであり、共同編集、オブジェクトストレージ、検索、メッセージングのエンドツーエンドチェックを代替するものではない。

<a id="still-needs-an-external-rehearsal"></a>

## まだ外部でのリハーサルが必要です

このコードは、文書の更新、カーソル、存在状況、共有制限、および2つのアプリケーションインスタンス間でのデータベースリースやアウトボックスに関する処理をカバーしています。本番運用前には、ターゲットインフラ上でのPostgreSQL、管理型Redis、S3、WebSocketのドレイン、およびローリングアップデートの実行を練習します。障害をシミュレートするには、Redisを停止させたり、ジョブを実行中のレプリカを終了させたり、編集中にアクセスを取り消したり、一致しないデータベースベースラインを提示したり、オブジェクトストレージのタイムアウトを引き起こしたりします。
