# Разработка плагинов

Десктопный клиент Tauri подключается к удаленному хосту Doca. Плагины работают на этом хосте через его директорию установки и публичный SDK; клиент не добавляет мост источников только для десктопа. См. [десктопный клиент](desktop-client.ru.md).

Текущий источник использует SDK **0.2.0**, с `ai.v2` / `ai.continuations.v2`Среды инструментов всегда содержат `jobId`; `sessionId` Представлен только для реальных разговоров. Пересоберите плагины. `sdkRange: "^0.2.0"`; предыдущие диапазоны SDK и контракты на услуги ИИ отклонены без адаптеров. Это изменение источника не является публикацией или развертыванием npm. Смотрите [Разделение выполнения MCP](mcp.ru.md#execution-history-and-upgrade).

Несовместимый диапазон SDK или отсутствующая необходимая зависимость изолируют затронутый бизнес-плагин. Хост и несвязанные плагины запускаются, и в меню Admin → Plugins объясняется причина, после чего требуется обновление. Установленные файлы, архивы, бизнес-данные и учетные данные сохраняются. Старые пакеты не конвертируются, а старый код SDK не выполняется. Новые онлайн-установки все еще отклоняют несовместимые пакеты. Полные офлайн-файлы установки сохраняют свою первоначальную идентичность и подвергаются той же изоляции.


Внешние клиенты ИИ используют [Сервисы MCP](mcp.ru.md)Инструменты должны явно указывать уровень воздействия MCP и продолжать выполнять свои обычные проверки авторизации/приемки; SKILL представляет собой ручную процедуру, а не процедура предоставления авторизации.

0.1.26 использует [Общая бизнес-база данных плагинов](plugin-database-isolation.ru.md)Отдельно от ядра, с автоматическими пространствами имен. Он заменяет базы данных для каждого плагина, выпущенные в версии 0.1.25. Для обновления необходимо обычно удалить приложение на предыдущем хосте и переустановить; данные плагинов не мигрируют.

База документации: хост 0.2.23 / SDK 0.1.11, проверка 28.10.2026. Публикация SDK 0.1.11 приведена ниже; развертывание в производстве и прием на нативных устройствах остаются отдельными процессами. Это основное руководство по разработке, включающее текущий контент, нативные и установочные условия. Связанные документы содержат полные протоколы и исторические записи о приеме. Любая адаптация для совместимости, конвертация старого формата или миграция базы данных требуют предварительного согласия с владельцем проекта.

## Внедрена управляемая система хранения

`@smartdoca/plugin-sdk/storage` Теперь экспортируются устройства для установки `pluginDatabaseToken` (`storage.sql.v1`) и `pluginObjectStorageToken` (`storage.objects.v1`). Подмножество базы данных представляет собой версию схемы 1, с колонками text/int32/double, первичными/уникальными ограничениями, структурированными операциями select/insert/update/remove, а также транзакциями с выполнением кallback-функций один раз. `pluginCredentialToken` (`storage.credentials.v1`, источник SDK 0.1.8) предоставляет зашифрованные учетные данные только для сервера с проверкой ревизии при обновлении и удалении. Соединения, иностранные ключи, общий SQL, upsert и рабочие пространства не экспортируются. Смотрите [API квалификации и развёртывание](plugin-credentials.ru.md)Бизнес-SQL использует один общий базу данных, управляемый хостом, отдельный от основного: один файл SQLite с префиксами таблиц, или один URL/аккаунт PostgreSQL с автоматическими схемами плагинов и общим пулом подключений. Изоляция процессов остается не реализованной. См. также [Настройка хранения и условия удаления перед обновлением](plugin-database-isolation.ru.md).

Логические базы данных используют `plugin:<pluginId>`Принадлежность пользовательских файлов и использование приватных объектов `plugins/<pluginId>`и выпуск ZIP-файлов `host/plugin-releases/<sha256>.zip`Полные неизменяемые байты ZIP хранятся в файловом хранилище, настроенном в среде; общая база данных содержит реестр версии 2, ссылки на архивы и индексы доверенных хешей файлов. Проверенные попадания в кэш не делают повторного скачивания ZIP-файлов. Все экземпляры перезапускаются вручную. Не поддерживаемые пакеты/форматы хранения плагинов отклоняются без автоматической конвертации; существующие данные сохраняются. Обновления основной базы данных производятся отдельно. [Контракт на обновление базы данных](database-schema-evolution.ru.md). Смотрите [точная реализация и ограничения](unified-storage-implementation.md).

## SDK и сервисы хоста

Относитесь к общественному контракту. Не импортируйте. `@server/*`, `@core/*`, `@web/*`, `@db/*`, сестринский источник Doca, или глобальный мост. Идентификаторы сервисов стабильны при использовании в разных установках. Хост внедряет реализацию.

```ts
import { definePlugin } from "@smartdoca/plugin-sdk";
import { filesServiceToken } from "@smartdoca/plugin-sdk/files";
import {
  httpServiceToken,
  usersServiceToken,
} from "@smartdoca/plugin-sdk/platform";
import manifest from "../manifest.json" with { type: "json" };

export default () =>
  definePlugin({
    manifest,
    async uninstall() {},
    injections: {
      required: [filesServiceToken, httpServiceToken, usersServiceToken],
    },
    async mount(context) {
      const files = context.inject(filesServiceToken);
      const users = context.inject(usersServiceToken);
      await context.inject(httpServiceToken).register(manifest.id, [
        {
          method: "GET",
          path: "/folders",
          async handle(request) {
            const user = await users.get(request, request.principal.id);
            const folders = await files.folders.list(
              { principalId: request.principal.id, signal: request.signal },
              { parentId: null },
            );
            return { user, folders };
          },
        },
      ]);
    },
  });
```

Этот маршрут… `/api/v1/plugins/example.attachments/folders`Идентификация происходит из сессии хоста. Операции с файлами снова проверяют разрешения. Сохраняйте стабильный идентификатор файла и связь с владельцем, а не локальный путь на диске. `users.get` Возвращает зарегистрированного пользователя или пользователя, которому администратор разрешает читать информацию, включая контактные данные и поля профиля. Не возвращает хеш пароля или секреты аутентификации. Удаляет из ответа браузера только то, что необходимо для отображения на экране.

Плагины имеют собственные бизнес-модели, авторизацию, логику работы и семантику вывода данных; весь долговечный состояние работает на услуги, управляемые публичным хостом. <a id="host-managed-persistence"></a>

## Персистентность, управляемая хостом

`doca.storage` Должно быть точно так. `"host"`Включая статические плагины. Оно подтверждает соответствие контракту управления хранилищем; это не имя базы данных или селектор сервера. Статическая проверка проводится перед решением/импортом кода сервера. Эта проверка используется при установке ZIP, npm/store, импорте оффлайн-директории, восстановлении общих архивов и инструментах пакетного управления. Не предоставляется никаких значений по отсутствующим полям или старых адаптеров. Декларация является обязательством автора плагина, которое считается надежным, а не сандбэком Node.js или аудитом кода.

Нет переменной окружения environment variable plugin business-data-directory или пути для данных, доступного для выбора плагинов. `DOCA_PLUGINS_DIR` Остается кэш установки хоста, который можно пересобрать, а не бизнес-магазин. Только хост конфигурирует локальное/дистанционное сохранение данных и обеспечивает совместное хранение базы данных/объектов для горизонтального развёртывания. Плагины используют те же методы SDK в обоих случаях и не должны иметь отдельный сервер.

Пользователи загружают файлы, приложения и результаты экспорта. `files.v1` Папки/файлы с стабильными идентификаторами, привязки и разрешениями. Структурированные записи, конфигурация, задачи, указатели и объекты, отправленные на выход, находятся в областье отношений, управляемой хостом. Логическое имя базы данных — `plugin:<pluginId>` И оно связано через доверенное внедрение. Приватные долговечные бинарные файлы используют возможность приватного объекта, управляемого хостом; учетные данные используют возможность учетных данных, управляемых хостом. Приватные объекты экспортируются в SDK 0.1.7; управляемые учетные данные — в исходном коде SDK 0.1.8. Временная работа может использовать будущий рабочий пространство или потоки, управляемые хостом, с ограничениями/очисткой и без долговечной зависимости от пути предыдущей инстанции. См. контракт хранения для требуемых интерфейсов и статуса.

## Структура данных

`doca.dataVersion` Это точный идентификатор бизнес-структуры плагина, а не порядковая версия или доказательство того, что старые файлы можно читать через новый магазин. ## Удалить

Установленный плагин должен реализовывать `uninstall(context)`Стартап отклоняет фабрику без него. Хук обрабатывает отключение/внешнее отменение бизнеса и использует только публичные сервисы хоста. Он должен быть идемпотентным и никогда не открывать или рекурсивно удалять пути хостового хранилища. Статeless-плагин может реализовать пустой хук.

Управление очисткой приватных баз данных/объектов является обязанностью хоста. При успешном удалении приложения из бизнес-системы регистрационные записи ограничивают работу текущего поколения и отправляют процесс очистки приватных таблиц/объектов с использованием действенных попыток восстановления. Все инстансы все еще требуют ручного перезапуска.

Отключить, остановить процесс и `dispose` Отпускать регистрации, таймеры и соединения без удаления долговременных данных. Пользовательские файлы, содержимое документов, связи, используемые другими компаниями, и документы о долговременных файлах не удаляются автоматически при удалении плагина. Любое очищение файлов осуществляется с использованием файлового сервиса и проверяется право собственности, авторизация и оставшиеся ссылки.

## Нативный кэш и приложения

Используйте тот же веб-бандл в вебе и в ограниченном мобильном WebView. `PluginWebHost` от `@smartdoca/plugin-sdk/web` раскрывает `native`, что на вебе равно нулю. Нативные типы экспортируются из `@smartdoca/plugin-sdk/native`.

- `native.storage` поставки `get`, `set`, `remove`, `clear`Строковые значения изолированы сервером, аутентифицированным пользователем и плагином. Лимиты составляют 2 миллиона символов/значение и 20 миллионов/плагин. Выход из аккаунта или удаление аккаунта сбрасывают кэш аккаунта. Плагины могут быть включены или отключены; IndexedDB не мигрируется, а начало работы оффлайн не гарантируется.
- `native.attachments.save/share({path, name, mime})` Скачивает относительный путь плагина-API через аутентифицированный нативный диспарс. Нативные кредензии никогда не попадают в WebView. Переадресации отклоняются, а размер файла ограничен 32 МиБ; временные файлы удаляются.
- В Android функция сохранения возвращает информацию о завершении/отмене действия. В iOS функция сохранения и обмен системными данными может показывать результат, что не подтверждает завершения пользователем действия. Переключение учетных данных или удаление страницы отменяют незавершенные запросы.
- Обязательное привязывание почтового аккаунта происходит через веб-сервис. Оригинальный OAuth не входит в этот процесс.

Текущая версия SDK — 0.1.11; её публикация в npm указана ниже. Тестирование на хосте и сборка не заменяют независимую интеграцию почтовых пакетов или проверку устройств iOS/Android; эти процессы все еще ожидают завершения. Смотрите [нативный протокол](plugin-native.ru.md).

## Элементы документации плагина (2026-10-02, источник SDK 0.1.6)

Опциональный веб-пакет `elements` регистрация и `@smartdoca/plugin-sdk/editor-elements` Это реализовано для богатых атомных встроенных элементов и видов электронной таблицы в виде целых клеток на холсте. Формы конфигурации отправляются через встроенные операции и функцию отмены, принадлежащие хосту; нет публичного произвольного управляющего редактором. Точные неизвестные типы/версии показывают место для ошибки и сохраняют непрозрачный JSON без конвертации, миграции или очистки. По умолчанию не установлены никакие поставщики. Смотрите [Точный элемент контракта](plugin-editor-elements.ru.md) и [Независимый пример отсчета/новостей](../examples/plugin-elements/README.md)Публикация в npm, установка в производственных условиях и прием на нативных устройствах не предполагаются.


Сборка материалов реализована в исходном коде SDK версии 0.1.9: materials.v2 / провайдеры версии 2, отдельные группы результатов сборки материалов, странирование, теги и индексированный поиск. Метаданные сборки никогда не включают участников. Утвержденная версия не содержит адаптера materials.v1 и не предусматривает миграцию существующих файлов/документов. Управление сборкой принадлежит провайдерам, использующим публичную систему хранения данных. См. также… [протокол ресурсов](creation-resources.ru.md).
