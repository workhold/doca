# 플러그인 개발

타우리 데스크톱 클라이언트는 원격 Doca 호스트에 연결됩니다. 플러그인들은 설치 디렉터리와 공개 SDK를 통해 해당 호스트에서 실행되며, 클라이언트는 데스크톱 전용 소스-경로 브리지를 추가하지 않습니다. 자세한 내용은 참조하세요. [데스크톱 클라이언트](desktop-client.ko.md).

현재 소스는 SDK를 사용합니다. **0.2.0**, 함께 `ai.v2` / `ai.continuations.v2`도구 컨텍스트는 항상 포함되어 있습니다. `jobId`; `sessionId` 실제 대화에서만 존재합니다. 플러그인을 재구축하세요. `sdkRange: "^0.2.0"`이전 SDK 범위와 AI 서비스 계약은 어댑터 없이 거부됩니다. 이 소스 변경은 npm 출시나 배포가 아닙니다. 참조하세요. [MCP 실행 분리](mcp.ko.md#execution-history-and-upgrade).

불호합하는 SDK 범위나 사용할 수 없는 필수 종속성으로 인해 영향을 받는 비즈니스 플러그인이 격리됩니다. 호스트 플러그인과 관련 없는 플러그인들이 시작되며, Admin → Plugins에서 이유를 설명하고 업그레이드를 요청합니다. 설치된 선택 항목, 아카이브, 비즈니스 데이터 및 자격 정보는 보존됩니다. 기존 패키지는 변환되지 않고 기존 SDK 코드는 실행되지 않습니다. 새로운 온라인 설치도 여전히 불호합하는 패키지를 거부합니다. 완전한 오프라인 설치 폴더는 원래의 정체성을 유지하며 동일한 격리를 받습니다.


외부 AI 클라이언트가 사용함 [MCP 서비스](mcp.ko.md)도구들은 MCP 노출을 명시적으로 선언해야 하며, 일반적인 승인/허가 검사를 계속 유지해야 합니다. SKILL은 승인 부여가 아니라 수동적인 절차입니다.

0.1.26는 사용합니다. [공유 플러그인 비즈니스 데이터베이스](plugin-database-isolation.ko.md)핵심 부분과는 분리된 형태로, 자동 네임스페이스가 제공됩니다. 이는 0.1.25에서 출시된 플러그인별 데이터베이스를 대체합니다. 업그레이드를 위해서는 이전 호스트에서 일반적인 제거 후 재설치가 필요하며, 플러그인 데이터는 마이그레이션되지 않습니다.

문서 기준: 호스트 0.2.23 / SDK 0.1.11, 2026-10-28에 확인됨. SDK 0.1.11 출시 내용은 아래에 기록되어 있음; 생산 배포 및 네이티브 기기 인수는 별도로 진행됨. 이는 현재 내용, 네이티브 및 설치 계약을 포함한 주요 개발 가이드입니다. 연결된 문서는 전체 프로토콜과 역사적 인수 기록을 제공합니다. 어떤 호환성 어댑터, 구형 형식 변환 또는 데이터베이스 마이그레이션도 프로젝트 소유자와의 사전 합의가 필요합니다.

[中文](plugin-development.zh-CN.md)

구체적인 목표는 구현되지 않은 부분을 포함하여 전체입니다. [SDK 계약](plugin-sdk-contract.ko.md)오래된 회원 관리 시스템, 모니터링 기능, 또는 소스 로딩 호환성 레이어는 유지하지 마세요.

그것 [수평 확장 및 관리된 스토리지 계약](plugin-horizontal-scaling.ko.md) 승인되었습니다. 모든 지속성은 호스트가 관리합니다; 패키지는 명시해야 합니다. `doca.storage: "host"`누락되거나 다른 선언들은 설치, 디렉터리 발견, 시작 시 코드 임포트 전에 거부됩니다. 관리되는 SQL/개인 객체는 SDK 0.1.7에서 내보내지며, 자격 증명은 SDK 소스 0.1.9에서 내보내집니다; 작업 공간은 여전히 부족한 부분입니다.

<a id="implemented-managed-storage"></a>

## 관리형 스토리지를 구현함

`@smartdoca/plugin-sdk/storage` 현재 설치용 제품을 수출하고 있습니다. `pluginDatabaseToken` (`storage.sql.v1`) 그리고 `pluginObjectStorageToken` (`storage.objects.v1`). 데이터베이스 하위 집합은 명시적 스키마 버전 1이며, 텍스트/int32/double 컬럼, 기본/유일 제약 조건, 구조화된 select/insert/update/remove 작업 및 한 번 실행되는 콜백을 포함하는 트랜잭션이 있습니다. `pluginCredentialToken` (`storage.credentials.v1`SDK 소스 0.1.8)은 수정된 값이 확인된 갱신 및 삭제 기능을 갖춘 서버 전용 암호화된 자격 증명을 제공합니다. 참여, 외래 키, 일반적인 SQL, 업사이드 및 작업 공간은 내보내지 않습니다. 자세한 내용은 참조하세요. [자격 증명 API 및 배포](plugin-credentials.ko.md)비즈니스 SQL은 핵심 시스템과는 별개의 공유 호스트 관리 데이터베이스를 사용합니다. 테이블 프렌지가 있는 SQLite 파일이거나, 자동 플러그인 스키마와 공유 연결 풀이 있는 PostgreSQL URL/계정이 있습니다. 프로세스 격리 기능은 아직 구현되지 않았습니다. 자세한 내용은 참조하세요. [저장 설정 및 업그레이드 전 삭제 계약](plugin-database-isolation.ko.md).

논리적 데이터베이스는 사용 `plugin:<pluginId>`, 사용자 파일의 소유권 및 개인 객체 사용 `plugins/<pluginId>`, 그리고 ZIP 파일을 풀어주는 것 `host/plugin-releases/<sha256>.zip`완전히 불변인 ZIP 바이트는 환경에 설정된 파일 저장소에 존재합니다. 공유 데이터베이스에는 레지스트리 버전 2, 아카이브 참조 및 신뢰할 수 있는 파일 해시 인덱스가 저장되어 있습니다. 확인된 캐시 히트는 ZIP 파일을 다시 다운로드하지 않습니다. 모든 인스턴스는 수동으로 재시작됩니다. 지원되지 않는 플러그인 패키지/저장 형식은 자동 변환 없이 거부되며, 기존 데이터는 보존됩니다. 핵심 데이터베이스 업그레이드는 별도로 진행됩니다. [데이터베이스 업그레이드 계약](database-schema-evolution.ko.md). 보기 [정확한 구현 및 제한 사항](unified-storage-implementation.md).

## 설치하고 시작하기

관리자 → 플러그인에서 완전한 사전 빌드된 ZIP 파일을 설치하거나, 직접 넣어도 됩니다. `<plugin-id>/` 리프리즈 디렉터리로 이동 `DOCA_PLUGINS_DIR` 일시 중지된 상태입니다. 각 인스턴스를 다시 시작하세요. 공유 데이터베이스에는 원하는 선택 항목, 아카이브 참조 및 파일 해시 인덱스가 저장되어 있습니다; 완전한 ZIP 바이트는 설정된 파일 저장소에 존재합니다; 인스턴스 내부 캐시는 시작 시 자동으로 동기화됩니다. npm 설치 디렉터리 호환성 경로는 없습니다. 자세한 내용은... [스토어 프로토콜](plugin-store-protocol.ko.md) 그리고 [배포 가이드](plugin-deployment.ko.md).

```json
{
  "name": "@example/attachments",
  "version": "1.0.0",
  "type": "module",
  "doca": {
    "dataVersion": "1",
    "storage": "host",
    "manifest": "./manifest.json",
    "server": "./dist/server.js",
    "web": { "directory": "./web", "entry": "./index.js" }
  }
}
```

`manifest.json` 정적인 JSON입니다. 버전이 일치합니다. `package.json`:

```json
{
  "schemaVersion": 1,
  "id": "example.attachments",
  "version": "1.0.0",
  "displayName": "Attachments",
  "sdkRange": "^0.2.0",
  "dependencies": [{ "id": "doca.files", "range": "^0.1.0" }]
}
```

컴파일된 자바스크립트만 로드됩니다. 전체 의존성 클로저를 실제 파일로 번들하거나 공급업체로 제공해야 합니다. 설치 스크립트, 레지스트리 조회 또는 호스트 컴파일 실행은 필요 없습니다. 경로는 패키지 루트 내에 유지됩니다. `doca.dataVersion` 필요합니다. 그 구조 번호가 변경될 수 있는지는 명시되어 있습니다. [데이터 구조](#data-structure) 아래에.

<a id="sdk-and-host-services"></a>

## SDK 및 호스트 서비스

공공 계약에 따라야 합니다. 수입하지 마세요. `@server/*`, `@core/*`, `@web/*`, `@db/*`소스인 도카의 자식 또는 글로벌 브리지입니다. 서비스 ID는 설치 간에 안정적입니다. 호스트가 구현을 투입합니다.

```ts
import { definePlugin } from "@smartdoca/plugin-sdk";
import { filesServiceToken } from "@smartdoca/plugin-sdk/files";
import {
  httpServiceToken,
  usersServiceToken,
} from "@smartdoca/plugin-sdk/platform";
import manifest from "../manifest.json" with { type: "json" };

export default () =>
  definePlugin({
    manifest,
    async uninstall() {},
    injections: {
      required: [filesServiceToken, httpServiceToken, usersServiceToken],
    },
    async mount(context) {
      const files = context.inject(filesServiceToken);
      const users = context.inject(usersServiceToken);
      await context.inject(httpServiceToken).register(manifest.id, [
        {
          method: "GET",
          path: "/folders",
          async handle(request) {
            const user = await users.get(request, request.principal.id);
            const folders = await files.folders.list(
              { principalId: request.principal.id, signal: request.signal },
              { parentId: null },
            );
            return { user, folders };
          },
        },
      ]);
    },
  });
```

그 경로는 `/api/v1/plugins/example.attachments/folders`식별 정보는 호스트 세션에서 제공됩니다. 파일 작업은 다시 권한을 확인합니다. 로컬 디스크 경로가 아닌 안정적인 파일 ID와 소유자 링크를 저장해야 합니다. `users.get` 로그인한 사용자 또는 관리자만 읽을 수 있는 사용자를 반환하며, 연락처 정보와 맞춤형 프로필 필드도 포함됩니다. 비밀번호 해시나 인증 비밀은 반환되지 않습니다. 브라우저의 응답을 화면에 필요한 내용으로 줄입니다.

## 공공 서비스

| 수입              | 서비스                   | 사용하기                                                                     |
| ------------------- | ------------------------- | ----------------------------------------------------------------------- |
| plugin-sdk/files    | 파일서비스토큰         | 폴더, 파일, 업로드, 콘텐츠, 바인딩, 액세스                   |
| plugin-sdk/platform | 사용자서비스토큰         | 승인된 사용자의 프로필 및 통합 사용자 검색                   |
| plugin-sdk/platform | permissionsServiceToken   | 비즈니스 리소스 권한 및 관계 소스 등록       |
| plugin-sdk/platform | httpServiceToken          | 플러그인 자체 이름공간에 있는 인증된 경로                      |
| plugin-sdk/platform | 정책서비스 토큰      | 생성, 저장, 공유, 전송, AI 호출 전에 접속           |
| plugin-sdk/platform | 이벤트서비스토큰        | 지속적인 이벤트 스트림을 읽어보세요, 포함하여 `ai.usage.recorded`            |
| plugin-sdk/platform | 알림 서비스 토큰 | 노티피케이션을 발행하고 중복되지 않게 취소하기                         |
| plugin-sdk/ai       | aiServiceToken / aiContinuationsServiceToken | JSON Schema와 기술 매뉴얼을 사용하여 AI 도구를 등록하세요.                  |
| plugin-sdk/content  | 콘텐츠서비스토큰       | 통합된 재고 관리, 읽기, 해결, 선택적 검색 및 지식 소스 |
| plugin-sdk/platform | 활동서비스토큰      | 플러그인 소유의 최근 방문, 호스트 집계 및 인증          |
| plugin-sdk/search   | searchServiceToken        | 프로젝션, 재구축 및 승인된 인덱스 쿼리                        |

등록 ID는 플러그인 ID와 점으로 시작됩니다. 경로 네임스페이스는 플러그인 ID와 같습니다. 이러한 등록은 플러그인 생명주기에 따라 이루어지며, 플러그인이 중단되거나 시작에 실패하면 해제됩니다. 자신이 만드는 타이머와 연결은 여전히 사용됩니다. `context.effect` 아니면 `effectAsync`중단해도 저장된 데이터는 삭제되지 않습니다.

디렉터리 소스는 현재 유효한 관계를 반환합니다. 호스트는 관리자의 '모든', '관련', 또는 '아무것도' 정책을 적용하고 유효한 사용자로 필터링합니다. 소스 오류는 가시성을 넓히지 않습니다. 검색 가능하다는 것이 읽을 수 있다는 의미는 아닙니다. 소스는 사용합니다. `schemaVersion: 1`, 페이지 단위로 `related`, 그리고 현재 사실 `verify`플러그인은 자체 관계 인덱스를 유지합니다. 페이징, 타임아웃, 후보 검증은... [메일 전달](plugin-mail-handoff.md).

백그라운드 비즈니스 작업을 위한 경우, SDK source 0.1.10이 제공됩니다. `aiContinuationsServiceToken` registerSource/wait/wake를 위한 것입니다. 필수 인젝션을 선언하세요. `sdkRange: "^0.2.0"`실시간 비즈니스 권한 부여 및 안정적인 운영 ID를 구현한 후, 결과를 커밋한 후 알림을 보냅니다. 호스트는 작업이 완료되거나 새로운 인간의 결정이 내려진 후 원래의 조수 작업을 재개합니다. 참고 [전체 계약 및 예시](plugin-ai-continuations.ko.md).

AI 도구를 등록하세요. `aiServiceToken.registerTool`id, 설명, inputSchema, 그리고 execute입니다. execute는 인증된 사용자, turnId, jobId, callId, signal을 받으며, 실제 대화의 경우에는 세션Id도 함께 받습니다. 파일 권한을 우회할 수는 없습니다. `registerSkill` ID, 이름, 설명, 콘텐츠, 형식을 가져옵니다. 매뉴얼은 호스트 기술 라이브러리에 저장됩니다. 비즈니스 도구는 자체 리소스 권한을 확인하고 플러그인 데이터베이스에 안정적인 작동 ID를 저장하여 재시도가 부작용을 반복하지 않도록 합니다. callId는 호출과 연관됩니다. 새로운 호출이 기존 callId를 재사용한다고 가정하지 마세요. 파일이나 폴더를 생성할 때는 안정적인 값을 전달합니다. `idempotencyKey`업로드도 통과됩니다. `contentIdentity` 반환됨 `uploads.complete`내구성 있는 영수증을 읽어보세요. `files.receipts.get`대기 중인 경우 다시 시도할 수 있습니다. 다른 매개변수는 409입니다. 삭제된 결과는 재생하여 다시 만들 수 없습니다. 전체 프로토콜은 7.1절에 나와 있습니다. [SDK 계약](plugin-sdk-contract.ko.md).

Doca는 회원권, 가격, 포인트, 또는 비즈니스 할당량을 포함하지 않습니다. 모델의 입출력 비율과 이미지당 토큰 수는 공급업체의 원시 사용량을 토큰으로 변환합니다. 이는 가격이 아닙니다. 사용량은 확인되지 않은 요청과 실제 지표를 구분하는 기준입니다. `ai.usage.recorded` 해결 거래 내에 기록되어 있습니다. 최상위 수준 `metrics` 이것이 평가된 사용량입니다. `provider.metrics` 공급업체의 원시 데이터를 유지합니다. 플러그인은 이벤트를 가져옵니다. `events.read(cursor, limit)`커서를 저장하고 각 이벤트 ID를 한 번만 처리합니다. 정책 검사로 인해 호출이 거부될 수 있습니다. 크로스플러그인 예약, 실패 보상, 금전적 일관성에 대해서는 아직 완전한 거래 프로토콜이 없습니다. 하나의 검사는 결제 구현이 아닙니다.

플러그인은 자체적인 비즈니스 모델, 권한, 작업 로직 및 아웃박스 세미나미스를 가지고 있습니다; 모든 지속적인 상태는 공개 호스트가 관리하는 서비스를 사용합니다. 플러그인은 결코 로컬/원격 서버를 선택하거나, 개인 데이터베이스에 연결하거나, 저장소 자격 정보를 읽거나, 시스템 디렉터리에 데이터를 저장하지 않습니다. 관리되는 SQL 및 개인 객체는 SDK 0.1.7에서 내보내지며, 자격 정보는 SDK 소스 0.1.9에서 제공됩니다. `data.v1`/`data.v2` 임시 작업 공간은 내보내지 않습니다. 누락된 기능은 자가 관리 스토어로 대체할 수 없습니다.

<a id="host-managed-persistence"></a>

## 호스트가 관리하는 영속성

`doca.storage` 정확해야 합니다 `"host"`상태가 없는 플러그인을 포함합니다. 이는 관리형 스토리지 계약에 부합함을 선언하며, 데이터베이스 이름이나 서버 선택자가 아닙니다. 정적 검사는 서버 코드를 해결/임포트하기 전에 이를 확인합니다. ZIP, npm/store 설치, 오프라인 디렉터리 임포트, 공유 아카이브 복원 및 패키지 도구는 이 검사를 사용합니다. 누락된 필드 기본값이나 레거시 어댑터는 제공되지 않습니다. 선언은 신뢰할 수 있는 플러그인 작성자의 약속이며, Node.js 샌드박스나 코드 감사가 아닙니다.

플러그인 business-data-directory 환경 변수나 플러그인-selectable 데이터 경로는 없습니다. `DOCA_PLUGINS_DIR` 이것은 호스트의 재구축 가능한 설치 캐시이며, 비즈니스 저장소가 아닙니다. 호스트만이 로컬/원격 지속성을 설정하고 수평 배포를 위한 공유 데이터베이스/객체 저장소를 보장합니다. 플러그인은 두 경우 모두 동일한 SDK 방법을 사용하며 호스트 서버에 분기되어서는 안 됩니다.

사용자가 업로드하고, 첨부파일 및 내보내기 결과물을 사용합니다. `files.v1` 안정적인 ID, 바인딩 및 권한을 가진 폴더/파일들. 구조화된 레코드, 설정, 작업, 커서, 아웃박스는 호스트가 관리하는 관계형 기능에 속합니다. 그의 논리적 데이터베이스 이름은 `plugin:<pluginId>` 신뢰할 수 있는 주입에 의해 제한됩니다. 개인적인 지속적인 바이너리에는 호스트가 관리하는 개인 객체 기능이 사용되며, 자격 증명에는 호스트가 관리하는 자격 증명 기능이 사용됩니다. 개인 객체는 SDK 0.1.7에서 내보내지며, 관리된 자격 증명은 SDK 소스 0.1.8에서 제공됩니다. 임시 작업은 미래의 호스트가 관리하는 작업 작업 공간이나 스트림을 사용할 수 있으며, 제한 및 정리 기능이 있으며 이전 인스턴스의 경로에 대한 지속적인 의존성은 없습니다. 필요한 인터페이스와 상태에 대한 저장소 계약을 참조하십시오.

<a id="data-structure"></a>

## 데이터 구조

`doca.dataVersion` 이는 정확한 플러그인 비즈니스 구조 식별자이며, 순서가 정해진 버전이나 기존 파일이 새로운 저장소를 통해 읽을 수 있다는 증거는 아닙니다. 설치된 업그레이드도 동일한 식별자를 필요로 하며, 실제 구조는 여전히 검증이 필요합니다. 불일치는 명확하게 실패합니다. 자동으로 마이그레이션하거나 다운그레이드하거나, 기존 필드를 채우거나, 기존 디렉터리를 가져오거나, 동시에 읽기/쓰기를 허용하지 마십시오. 기존의 자가 관리 데이터는 변경되지 않으며 빈 관리 데이터베이스 대체용으로 사용되지 않습니다. 향후 구조나 서버 변환은 별도로 승인된 계획, 검증 및 롤백이 필요합니다.

<a id="uninstall"></a>

## 삭제하기

설치된 플러그인은 구현해야 합니다. `uninstall(context)`스타트업은 이를 없이 공장을 거부합니다. 후크는 비즈니스 해제/외부 취소를 처리하며 공개 호스트 서비스만 사용합니다. 이는 중복 작업이 가능해야 하며, 호스트 저장 경로를 열거나 재귀적으로 삭제해서는 안 됩니다. 상태 없는 플러그인은 비어 있는 후크를 구현할 수 있습니다.

관리되는 개인 데이터베이스/객체 정리 작업은 호스트가 담당합니다. 비즈니스 프로그램을 성공적으로 제거할 때, 레지스트리 트랜잭션이 현재 세대를 마감시키고 개인 테이블/객체 정리를 지속적인 재시도로 처리합니다. 자격 증명 정리 및 생성 방지 기능이 구현되었지만, 클러스터 비즈니스 작업의 소비는 여전히 불가능합니다. 사용자 파일 및 기타 비즈니스 참조 정보는 보존됩니다. 호크 기능이 실패해도 설치는 그대로 유지되며, 외부 호크의 효과는 되돌릴 수 없습니다. 모든 인스턴스는 여전히 수동 재시작이 필요합니다.

비활성화, 프로세스 종료 및 `dispose` 영구 데이터를 삭제하지 않고 등록 정보, 타이머 및 연결을 해제합니다. 사용자 파일, 문서 페이로드, 다른 기업에서 사용하는 바인딩 및 영구 파일 기록은 플러그인을 제거해도 자동으로 삭제되지 않습니다. 모든 파일 정리 작업은 파일 서비스를 사용하며 소유권, 권한 및 남은 참조를 확인합니다.

## 웹

`host.ai.open(input)` 수정 가능한 프롬프트/컨텍스트, 승인된 문서 참조, 기존 파일 첨부물을 갖춘 개인 비서를 엽니다. `sessionId` 소유한 대화를 재개합니다; 생략은 새로운 대화를 만듭니다. 명시적일 때만 가능합니다. `autoSend: true` 일반 호스트 작업 큐를 통해 메시지를 전송합니다. 웹과 네이티브 플러그인 컨테이너는 동일한 SDK 인터페이스를 공유합니다. 참조하세요. [매개변수, 제한 사항 및 예시](plugin-assistant.ko.md)소스 지원이란 npm에 공개되거나 네이티브 기기에서 사용될 수 있다는 의미는 아닙니다.

선택적 웹 빌드 default-exports `async host => bundle`. `host` React, apiBase, useEnvironment, navigate, toast, confirm, request, FilePicker, platform, 그리고 ui가 제공됩니다. React는 호스트에서 제공되므로 하나의 렌더러가 있습니다. 다른 의존성들은 번들로 제공됩니다. 호스트는 빈 npm 임포트를 해결하지 않습니다. 번들은 그대로 유지됩니다. `WebPluginBundle` 수출됨 `@smartdoca/plugin-sdk/web`. `manifest.pluginId` 버전이 서버와 일치해야 합니다. 페이지, 내비게이션, 관리자 기능, 설정 기능도 지원됩니다.

진행자가 지정된 디렉터리를 제공합니다. `/api/v1/plugin-assets/{id}/{version}/`. 차가운 시작 시에는 마운트 전에 등록 정보를 로드합니다; 이미 캐시된 문서는 즉시 마운트되며, 발견 과정에서는 백그라운드에서 공유된 라이브 부트스트랩 요청이 사용됩니다. 등록 정보가 도착할 때 네비게이션 및 경로 관찰자가 새로 만들지 않고 갱신됩니다. 서버의 현재 버전된 자산만 로드되며, 시작 메타데이터는 캐시된 플러그인 번들이나 권한 어댑터가 아닙니다. 로드 오류는 격리되어 로그에 기록됩니다. 서버 패키지 파일은 노출되지 않습니다. 기여 렌더링에는 오류 경계가 있습니다. 선택적 명령어/뷰/플레이스먼트는 현재 웹 홈, 문서, 라이브러리 및 파일 위치를 지원합니다. 선택, 삽입, 테마 및 네이티브 위치는 향후 작업입니다; 자세한 내용은 참조하세요. [정확한 방법과 슬롯](plugin-extensions.ko.md).

## 범위와 전달

`search.v1` 프로젝션 및 승인된 인덱스 쿼리를 제공합니다. 새로운 통합 콘텐츠, 글로벌 콘텐츠 검색 및 지식 구독 기능이 사용됩니다. `content.v1` 아래에. 플러그인은 자체적인 비즈니스 데이터와 현재 권한을 가지고 있으며, 호스트는 명시적인 구독, 일정 설정, 블록 지문 및 파생 콘텐츠 접근 확인을 담당합니다.

수락 과정에서는 실제 호스트 빌드, SDK, 그리고 비즈니스 플러그인 tarball을 이 리포지토리 외부에 설치합니다. 전체 의존성 체계를 준비해야 합니다. 설치나 시작 시 소스 링크, 미정의 캐시, 또는 레지스트리 가져오기에 의존해서는 안 됩니다. 웹 자산, 비즈니스 흐름, 취소, 재시도, 재시작을 확인해야 합니다. SDK를 빌드하는 것은 전체적인 수락 과정이 아닙니다.

플러그인 데이터베이스는 선언된 데이터 버전과 일치해야 합니다. 불일치 시 시작이 거부됩니다. 업그레이드나 다운그레이드 스크립트는 없습니다. 제거 요구사항은 여기에 있습니다. [삭제하기](#uninstall) 위에. 사용자 삭제 프로토콜은 제공되지 않습니다. 동적 모바일 WebView 계약은 메일 통합 v1 가이드에 문서화되어 있습니다. 플러그인 선택 데이터 디렉터리는 없습니다; 지속성은 스코프된 호스트 기능을 사용하며, 구현의 부족점은 별도로 문서화되어 있습니다.

<a id="background-identity-checks-and-notifications"></a>

## 배경 신원 확인 및 알림

`users.status(userId)` 반환 `{id, status}` 신뢰할 수 있는 서버 작업의 경우 null입니다. 상태가 활성화되지 않으면 비즈니스 작업을 중단하세요. 활성화된 계정이 있다고 해서 사용자가 비즈니스 리소스를 읽을 수 있다는 의미는 아닙니다.

`notificationsServiceToken` 수출 `notifications.v1`: `publish(pluginId, {recipientId, key, title, body, path, resource: {type, id}})` 그리고 `withdraw(pluginId, {recipientId, key})`호스트는 플러그인 자체의 pluginId만 허용합니다. `key` 비어 있지 않고 최대 200자 이내여야 하며, 플러그인과 수신자마다 개별적으로 분리되어야 합니다. 동일한 매개변수를 다시 재생하면 동일한 결과가 나옵니다. `{id}`다른 매개변수는 409를 반환합니다. 철회된 키는 410를 반환합니다. 플러그인의 아웃박스는 철회하기 전에 발행됩니다.

리소스 유형은 permissions.v1에 등록되어 있으며 구현되어 있습니다. `notification.read`게시, 목록 표시, 읽지 않은 수, 현재 권한을 다시 확인하기를 클릭합니다. 누락된, 비활성화된, 실패한, 또는 시간이 지난 소스는 허용되지 않습니다. 제목과 내용은 일반 텍스트로, 최대 200자와 2000자입니다. `path` 앱 내 경로로, 예를 들어 `/mail/<id>?message=...`원산지도, 해시도 없는 상태입니다. 링크는 이동 전에 호스트 인증 엔드포인트를 통과합니다. 플러그인 페이지와 API는 여전히 자신을 인증합니다.

이 인스턴스에 게시하면 웹 앱이 즉시 업데이트됩니다. 웹 앱은 30초마다 다른 인스턴스를 동기화합니다. 이는 앱 내 알림입니다. SMTP, 모바일 푸시, 데스크톱 알림이 아닙니다.

HTTP 등록은 기본적으로 바디를 1 MiB로 제한합니다. 첨부파일과 같이 더 큰 바디가 필요한 경로는 이 값을 설정할 수 있습니다. `bodyLimit` 바이트 단위로, 최대 32 MiB입니다. 플러그인은 여전히 첨부파일 수, 디코딩된 크기, 비즈니스 총계를 확인합니다.

<a id="unified-content-reading-search-and-knowledge-subscriptions"></a>

## 통합 콘텐츠: 읽기, 검색 및 지식 구독

사용하기 `@smartdoca/plugin-sdk@^0.1.9`. 수입 `contentServiceToken` 그리고 `ContentSource` 타입 from `@smartdoca/plugin-sdk/content`; 토큰을 선언합니다. `injections.required` 마운트하는 동안 소스를 등록합니다. 소스는 등록된 플러그인에 속합니다. 내장 문서와 파일은 동일한 계약을 사용합니다.

| 회원                                        | 계약서                                                                                                                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선언                                   | `id`, `pluginId`, `version: 1`, 지역화된 `title`, `contentTypes`, `purposes`, `capabilities: {search}`, `configSchema`                                                                                     |
| `list(ctx, {config, cursor, limit})`          | 필요. 반환 `{items, nextCursor, snapshot}`각 항목에는 `ref: {sourceId, resourceId, blockId}`, `fingerprint`, `title`, 선택적 `order`, `anchor`, `excerpt`; 여기서는 전체 몸을 반환하지 마세요. |
| `read(ctx, {config, ref, fingerprint})`       | 필요합니다. 권한을 다시 확인한 후 아이템과 함께 반환하세요. `text`사용할 수 없을 경우는 null입니다. 변경된 지문은 충돌이며, 오래된 지문 아래에 새로운 텍스트는 없습니다.                                       |
| `resolve(ctx, ref)`                           | 필요. 접근 권한을 다시 확인하고 반환하세요. `{path, fingerprint}` 또는 null. `path` 이것은 앱 내 위치입니다.                                                                                                     |
| `search(ctx, {config, cursor, limit, query})` | 선택적; 선언하고 함께 구현합니다. 가벼운 페이지를 반환합니다. 지원되지 않는 검색은 전체 스캔으로 전환되지 않습니다.                                                                                  |

`ctx` 인증된 내용이 포함되어 있음 `principalId`, `purpose` (`knowledge`, `analysis`, 또는 `search`) 및 취소 `signal`공급업체는 모든 요청에 현재의 비즈니스 허가를 적용합니다. 분석을 지원하는 소스는 메일 전용 API 없이 미래의 할 일 플러그인을 제공할 수 있습니다. 사용자들은 이를 사용합니다. `sources(ctx, purpose)`그런 다음 서비스 `list/read/search` 와서 `sourceId` 그리고 `purpose`; 서비스 `resolve` 가지다 `{ref, purpose}`그 출처가 명시한 목적만 요청하세요.

페이지 번호는 null로 시작하고 끝납니다. 탐색 과정에서의 모든 페이지는 일관된 스냅샷을 공유해야 하며, 만료가 되면 무시하지 않고 다른 데이터를 계속 사용하는 대신 실패해야 합니다. 이 커서는 전체 허가된 재고를 페이지화하는 용도이며, 지속적인 변경 로그는 아닙니다. `listChanges` 그리고 `readChanges` 이 계약에 따라 요구되거나 수출될 필요는 없습니다. 소스는 내부적으로 자신의 비즈니스 시스템을 동기화할 수 있지만, Doca는 그러한 구현을 요구하지 않습니다.

지식 시스템은 기존의 구독 및 일정 관리 시스템을 활용합니다. 사용자는 출처, 도서관 및 설정 설정을 명시적으로 선택합니다. 호스트는 참조 정보와 블록 지문을 저장하고, 전체 재고 목록을 비교하며, 새로 생성되거나 변경된 블록만을 읽고 분석합니다. 추가적인 전체 출처 본문 복사본을 보관하지 않습니다. 변경되지 않은 블록은 다시 읽을 필요가 없습니다. 완전하고 일관된 재고 목록만이 삭제를 결정할 수 있으며, 실패하거나 부분적인 실행 결과는 이를 인정하지 않습니다. 안정적인 블록 식별은 문서의 전체 수정본이나 위치별 단락 인덱스에 의존해서는 안 됩니다.

삭제, 해제, 취소 또는 사용할 수 없는 소스가 발생할 경우, 파생된 지식은 새로운 정상적인 읽기, 목록, 검색 및 답변 검색에서 제외됩니다. 수동으로 편집된 결과를 포함하여 관리자 처리용으로 콘텐츠가 보존됩니다. 이미 전송된 콘텐츠와 이미 열린 공동 작업 연결은 이 검사로 인해 후회 없이 취소되지 않습니다. 설정 UI는 기본 필드, enums 및 문자열 배열을 지원합니다. 복잡한 설정은 플러그인 자체 UI에 속합니다. 이 통합 기능은 데이터베이스 스키마 마이그레이션, 이중 읽기/쓰기 또는 기존 소스 어댑터를 추가하지 않습니다. SDK는 여전히 내보내집니다. `knowledge.sources.v1`하지만 이는 새로운 통합 기능에 대한 구독 정보가 아니며 자동으로 적용되지도 않습니다. `content.v1`.

제한 사항: 페이지당 재고 항목 100개, 전체 검색 시 100,000개의 항목, 본문 2백만 자, 분석 실행 시 120,000개의 변경된 본문 자료, 20초의 소스 호출 마감 시간. 과도하게 크거나 불완전한 작업은 명시적으로 실패하며, 잘라내고 완료된 것으로 처리하지 마세요. HTTP 엔드포인트는 `/api/v1/content/sources` 그리고 `/api/v1/content/{list,read,resolve,search}`. 보기 [정확한 프로토콜과 제한 사항](plugin-content.ko.md) 요청 형태와 구독 경로를 위한 것입니다.

<a id="native-cache-and-attachments"></a>

## 네이티브 캐시 및 첨부파일

웹과 스코프화된 모바일 WebView 모두에 동일한 Web 번들을 사용하세요. `PluginWebHost` 부터 `@smartdoca/plugin-sdk/web` 노출하다 `native`웹에서는 null입니다. 네이티브 타입은 내보내집니다. `@smartdoca/plugin-sdk/native`.

- `native.storage` 공급품 `get`, `set`, `remove`, `clear`문자열 값은 서버, 로그인된 사용자 및 플러그인에 의해 격리됩니다. 제한치는 2백만 자/값, 2천만 자/플러그인입니다. 로그아웃하거나 계정을 삭제하면 계정의 캐시가 지워집니다. 플러그인은 선택적으로 활성화됩니다; IndexedDB는 마이그레이션되지 않으며 오프라인에서의 냉동 시작은 보장되지 않습니다.
- `native.attachments.save/share({path, name, mime})` 인증된 네이티브 디스패치를 통해 관련 플러그인-API 경로를 다운로드합니다. 네이티브 자격 증명은 WebView에 들어가지 않습니다. 리디렉션은 거부되며 크기는 32 MiB로 제한됩니다. 임시 파일은 정리됩니다.
- 안드로이드 저장는 완료되거나 취소될 수 있습니다. iOS의 저장 및 시스템 공유는 표시될 수 있지만, 사용자가 해당 작업을 완료했음을 증명하지는 않습니다. 계정 전환이나 페이지 삭제는 미완료 요청을 취소합니다.
- 메일 계정 연동은 웹에서 이루어집니다. 네이티브 OAuth는 이 배포 범위에 포함되지 않습니다.

현재 SDK 버전은 0.1.11입니다. npm에 게시된 내용은 아래에 기록되어 있습니다. 호스트 테스트와 빌드는 독립적인 메일 패키지 통합이나 iOS/Android 기기 인증을 대체하지 않습니다. 이 부분은 아직 진행 중입니다. 참고하세요. [네이티브 프로토콜](plugin-native.ko.md).

## 분배 및 항해

완전한 npmtgz 파일은 Plugins → Settings에서 출시용 또는 정확한 패키지/버전 설치를 위해 사용됩니다. 로컬 업로드는 tgz가 아닌 package.json이 있는 ZIP 파일을 사용하며, 둘 다 컴파일된 아티팩트와 전체 런타임 의존성 클로저를 포함합니다. 호스트는 npm install이나 package 스크립트를 실행하지 않습니다. 설치, 업그레이드, 비활성화, 제거는 각 인스턴스가 재시작된 후에 효과가 나타납니다. 제거 동작은 지정된 내용에 따라 이루어집니다. [삭제하기](#uninstall) 위에.

글로벌 네비게이션에는 웹 사용자, 앱 사용자, 웹 관리자 범위가 있습니다. 페이지의 목적과 플랫폼을 명시하되, 관리자 페이지로 사용자 페이지를 제공해서는 안 됩니다. 플러그인 페이지는 출처에 따라 표시되며, 항목은 사이드바와 More에서 모두 나타나서는 안 됩니다. 참고하세요. [배포, WebView 및 내비게이션](plugin-mail-integration-v1.md) 그리고 [스토어 프로토콜](plugin-store-protocol.ko.md).

## 템플릿 및 재료 플러그인

SDK 0.1.5는 선택적 생성 리소스 제공자와 소비자를 추가했습니다. `host.platform.templates/materials`, 그리고 주입함 `TemplatePicker/MaterialPicker`. 보기 [정확한 리소스 프로토콜](creation-resources.ko.md)공급업체는 기본 설치 옵션이 없습니다. 자신의 네임스페이스와 현재 라이프사이클에 따라 등록해야 하며, 비즈니스 소비자들은 자신만의 행동을 승인합니다.

명명된 다중 소스 선택 및 AI 검색을 위해, 0.1.6 소스 수정 버전을 사용하세요: 쿼리와 함께 `providerIds`지역화된 소스 설명과 선택적 검색 모드를 선언하고 구현합니다. `retrieve` 그 선언과 함께. 호스트는 소스 발견, 제한된 결과 집계 및 AI 도구를 제공하며, 제공업체는 자신이 원하는 검색 엔진을 선택할 수 있습니다. 합의된 프로토콜 변경에 따라 기존의 단일 쿼리 필드는 거부됩니다. 소스 메타데이터는 결과 및 피커 콜백에서 사용할 수 있습니다. 보기 [요청된 형태와 한도](creation-resources.ko.md).

## 플러그인 문서 요소 (2026-10-02, SDK 0.1.6 소스)

선택적 웹 번들 `elements` 등록 및 `@smartdoca/plugin-sdk/editor-elements` 풍부한 원자적 인라인 요소와 스프레드시트 전체 셀 캔버스 보기에 대해 구현되어 있습니다. 설정 형태는 호스트가 소유한 네이티브 작업 및 취소 기능을 통해 제출되며, 공개된 임의의 편집기 핸들은 없습니다. 정확한 유형/버전은 오류 위치 표시를 나타내고 불투명한 JSON을 유지하며, 변환, 마이그레이션 또는 정리 작업은 이루어지지 않습니다. 기본적으로는 제로 제공자가 설치되지 않습니다. 참조하십시오. [정확한 요소 계약](plugin-editor-elements.ko.md) 그리고 [독립적인 카운트다운/뉴스 예시](../examples/plugin-elements/README.md)npm 배포, 생산 환경 설치, 네이티브 기기 사용은 보장되지 않습니다.


자료 컬렉션은 SDK source 0.1.9에서 구현됩니다: materials.v2 / 버전 2 제공자, 별도의 자료/컬렉션 결과 그룹, 페이징, 태그 및 인덱스 검색 기능이 포함됩니다. 컬렉션 메타데이터는 회원을 포함하지 않습니다. 합의된 수정 사항에는 materials.v1 어댑터나 기존 파일/문서 마이그레이션이 없습니다. 컬렉션 관리는 공개 호스트 관리 방식의 영속성을 사용하는 제공자에게 속합니다. 자세한 내용은...을 참조하세요. [리소스 프로토콜](creation-resources.ko.md).
