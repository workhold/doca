# 문서, 공유, 그리고 역사

[中文](document-experience.zh-CN.md)

호스트 0.2.23의 소스에 대한 설명입니다. 초기 개발 단계와 일시적인 패키지 기록이 있습니다. [연구](research.ko.md).

<a id="create-and-edit"></a>

## 생성 및 편집

생성 메뉴에는 서식 있는 텍스트, 마크다운, 스프레드시트, 슬라이드, 캔버스가 포함됩니다. 이 다섯 가지 모두 편집기와 독립적인 공동 작업 코덱을 제공합니다. 템플릿은 설치된 제공자를 필요로 하며, 빈 문서 생성은 기본적으로 가능합니다. 개인 문서는 독립적인 페이지이며, 라이브러리 문서는 라이브러리 트리를 사용합니다.

이미지와 첨부파일은 호스트 업로드, 자산 ID, 승인된 다운로드를 사용합니다. 편집은 편집기 권한 이상이 필요하며, 저장 확인은 데이터베이스 커밋 후에 이루어집니다. 원본 체크포인트와 인식되지 않은 편집 내용은 브라우저 저장이 성공할 때 IndexedDB에 남아 있습니다. 다시 열기에는 사용 가능한 로컬 복제본과 애플리케이션 자산이 필요합니다. [오프라인 제한 및 복구](collaboration.ko.md#save-reconnect-and-history) 그리고 저장 오류에 대한 피드백도 있습니다. 도구, 찾기/바꾸기, 존재 여부, 코멘트는 형식에 따라 다릅니다; 참조하세요. [편집기 통합](editor-integration.ko.md).

오프라인 작업 공간 소스가 추가됩니다 **계정 메뉴 → 오프라인 문서** Doca 프론트엔드가 다운로드된 데스크톱 클라이언트와 브라우저로 전송됩니다. 백엔드에 접근할 수 없을 때 홈 화면에 이 목록이 표시됩니다. 마지막 알려진 권한 아래에서 복제본을 열어 수정하고, 연결 및 접근 확인이 회복된 후 동기화합니다. 참조하세요. [오프라인 문서를 활성화하는 방법](access-offline-events.md#离线文档入口).

문서 페이지에서는 스티치 필터 아래에 최근 방문한 항목들을 스크롤할 수 있습니다. 도서관 페이지와 오프라인 문서 디렉터리도 목록이 화면 크기를 초과할 경우 최종 항목까지 스크롤할 수 있습니다.

<a id="sharing-and-permissions"></a>

## 공유 및 권한 설정

공유 패널은 가시성, 초대장, 회원 인증 소스 및 링크를 관리합니다. 변경 사항은 버전 또는 수정 사항을 확인하며, 409 충돌이 발생한 후 다시 갱신합니다. 관리 및 소유권 관련 작업은 각자의 인증 규칙에 따라 진행됩니다. [권한](permission-inheritance.ko.md).

링크를 사용합니다. `#/s/{token}` 로그인된 상태에서 미리보기 및 수락을 위한 기능입니다. 전체 링크 전환, 개별 링크 비활성화/만료, 멤버 소스 취소는 별개의 작업입니다; 한 소스를 제거해도 다른 유효한 소스는 그대로 유지됩니다. 공개 읽기, 발견, 컬렉션, 선호 항목은 별개입니다; 컬렉션을 만들어도 접근 권한이 주어지지 않으며, 시스템 관리자는 자동으로 개인 콘텐츠에 접근할 수 없습니다.

<a id="history-and-restore"></a>

## 역사와 복원

- 문서 메뉴에는 역사 기록, 스냅샷 미리보기, 수동 스냅샷이 제공됩니다. 역사 기록은 일반적으로 편집자의 허가가 필요하며, 읽기 기록 기능을 활성화하면 리소스 읽기 권한에 따라 접근할 수 있습니다.
- 최근 복구된 점들은 상세하게 남아 있으며, 장기적인 기록에서는 10개의 더 오래된 스냅샷당 1개의 점이 유지됩니다. 동일한 목록과 미리보기/복구 기능은 저장 위치를 공개하지 않으면서 모든 유지된 점에 적용됩니다. 의도적으로 샘플링을 통해 나머지 9개의 점은 제거됩니다. [저장 작업](storage.ko.md#history-storage-and-offline-upgrade).
- 복구 가능한 풍부한 텍스트 및 Markdown 스냅샷은 관리자나 소유자에게 복구가 가능합니다. `expectedSeq` 현재 내용을 확인합니다. 충돌이 발생한 후 새로고침하여 오래된 미리보기가 더 새로운 수정 내용을 덮어쓰지 못하도록 합니다.
- 스프레드시트, 슬라이드, 캔버스에는 스냅샷과 읽기 전용 미리보기가 있습니다. 현재는 이를 반환합니다. `canRestore: false` 그리고 복원 조치을 전혀 하지 않습니다.
- 비즈니스 역사와 공동 작업 체크포인트는 별도로 저장됩니다. 복원 기능은 스냅샷의 형식, 계보, 및 자산을 사용하며, 누락된 역사는 현재 콘텐츠로 대체되지 않습니다.
- 방문 및 행동 기록을 확인하여 현재 권한을 다시 확인합니다. 이는 백업이 아니며 저장되지 않은 기록을 복원할 수 없습니다.

<a id="move-copy-and-trash"></a>

## 이동, 복사, 삭제

이동하기 전에 목적지 및 하위 객체의 권한을 확인하고, 승인이 재설정되었는지 확인해야 합니다. 소유권 이전은 소유자가 필요합니다. 복사는 독립적인 리소스와 콘텐츠 식별자를 생성하며, 자산을 다시 바인딩하고, 보조권, 댓글, 취소 기록을 제외합니다. 삭제는 휴지함으로 들어가며, 복원 시 삭제 일괄 및 부모 상태를 존중합니다. 영구 삭제는 명시적인 승인된 정리 작업이며, 모든 공유 저장소 객체를 삭제하는 것을 의미하지 않습니다.

<a id="routes-and-source"></a>

## 경로와 출처

이 경로들은 `/api/v1` 접두사:

| 노선 | 목적 |
| --- | --- |
| `GET /resources/:id/versions` | 역사 목록 |
| `POST /resources/:id/versions` | 수동 스냅샷 |
| `GET /resources/:id/versions/:versionId` | 미리보기 및 현재 콘텐츠 순서 |
| `POST /resources/:id/versions/:versionId/restore` | `{expectedSeq}`지원되는 형식으로 복원하기 |
| `POST /share/redeem` | `{token, accept?, consume?}`링크를 미리 보거나 수락하기 |
| `GET /resources/:id/info` | 통계, 방문 수, 또는 행동 기록 |

보세요 [experience.ts](../apps/server/src/routes/experience.ts), [역사 서비스](../packages/core/src/modules/history/service.ts), 그리고 [편집기 파견](../apps/web/src/features/documents/document-editor.tsx). 달리기 `/api/openapi.json` 서버 검증은 완전한 배포된 API를 정의합니다.
