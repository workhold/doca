# 지식-북 생성 성능 및 배치 체크포인트

[简体中文](knowledge-book-generation-performance.zh-CN.md)

2026-10-19. 사용자는 새로운 체크포인트 테이블과 개인적 지속성 형식에 명시적으로 동의했습니다. 구현은 그 수용 테스트에서 격리된 데이터로 검증되었으나, 프로덕션 배포는 이루어지지 않았습니다. 보고된 150,000자, 8시간의 프로덕션 테스트는 현지에서 진행되지 않았으며, 이러한 테스트는 그 원인을 명확히 설명하지 못하거나 프로덕션 시간을 예측할 수 없습니다.

<a id="execution-improvements"></a>

## 실행 개선

계획된 작성 크기는 유료 요청 전에 모델 출력 예산에 대해 배치별로 청구됩니다. 문자 할당, 정확한 청구 범위, 제한된 수리 및 명확한 실패 처리는 여전히 적용됩니다. 독립적 검토 통합 작업은 기존의 두 명의 작업자 한도 내에서 진행되며, 순서와 모든 부정적인 결과는 유지됩니다. 단일 관찰에는 불필요한 통합 요청이 필요하지 않습니다. 전체 책의 승인 및 필요한 품질 게이트는 계속 적용됩니다.

이전에는 프로세스 재시작에서 완전한 노드만 살아남았습니다. 이제는 개요 작성, 청구 분배, 추출, 작성, 조직화, 품질 검토를 포함한 미완료 노드 내에서도 완전한 검증된 요청이 살아남습니다. 완전한 호스트 분할 결정도 저장되어 있어, 크기가 너무 큰 부모 요청을 다시 요청할 필요가 없습니다. 부분적인 모델 스트림은 절대 저장되지 않습니다.

<a id="approved-persistence-contract"></a>

## 승인된 지속성 계약

- 빈 항목 추가 `knowledge_book_batch_checkpoints` 최신 DDL을 통해 테이블 `schemaEvolution` 기존에 있는 것에서 `doca-2026-10-12-book-payload-storage-v1` 생성. 기존의 행들은 변환되거나 채워지지 않습니다. 역사적 완전 노드 재사용 및 기존의 레거시 바디 경계는 변하지 않습니다.
- 별도의 개인용으로 사용하세요. `knowledge_book_batch_checkpoint_ref` v1 마커와 배치 소유자는 기존의 불변 객체 코덱 및 업로드 저널을 사용합니다. 대용량 결과는 SQL 외부에 저장됩니다. 기존 노드/실행/출시 참조 제약 조건 및 게시된 v1 구성/아티팩트 형식은 변경되지 않았습니다.
- 각 요청을 원래의 실행/노드, 동결된 설정, 노드 입력, 소스 버전/콘텐츠 해시 및 무게, 현재 후보, 비기밀 모델 설정, 알고리즘 버전, 정확한 요청 범위와 연결합니다. `scope_hash`, `plan_hash`, `input_hash` 그리고 `batch_key` 식별 정보를 엄격히 준수하세요. 절대 여러 실행 과정에서 배치들을 복사하지 마세요.
- 유효한 완전한 결과나 완전한 호스트 분할 결정만을 유지합니다. 부정적인 판정과 상세 진단 정보도 보존합니다. 최종 집계, 다이어그램 검증, 소스 인증, 할당량 및 발표 승인은 여전히 적용됩니다.
- 읽기, 생성, 트랜잭션적 설치가 이루어지기 전에 소스 권한과 활성 임대 계약을 다시 확인해야 합니다. 경쟁하는 인스턴스들은 하나의 불변한 승자만을 설치합니다. 업로드 중 취소나 권한/임대 계약 상실은 설치를 방해합니다.
- 내부 `evidenceInventory` 소스 제목/텍스트 사본 없이 소스 로케이터, 버전, 해시, 무게, 권한 참조를 저장합니다. 모델 지문에는 공급자, 모델, 엔드포인트, API 모드/버전, 입출력 예산 및 도구 설정이 포함되며, API 키, 별명, 가격은 제외됩니다.
- 기존의 명시적인 리뷰 흐름을 통해 콘텐츠 수정 작업을 수행하여 새로운 콘텐츠 범위를 확립하고, 기존 체크포인트는 재사용하지 않고 보존됩니다. 같은 범위 내에서 모델이나 알고리즘을 변경할 경우 새로운 실행이 필요합니다. 알려지지 않은 버전, 손상, 유효하지 않은 결과, 또는 누락된 객체는 복구를 중단시킵니다; 이러한 객체는 결코 조용히 재생성이나 변환을 유발하지 않습니다.

이것들은 새로운 개인용 체크포인트이며, 기존 결과 형식에 대한 어댑터는 아닙니다. 배치 체크포인트가 없는 기존 행은 미완료 노드가 새로운 요청을 처리할 때까지 전체 노드의 동작을 유지합니다.

<a id="deployment-retention-and-recovery"></a>

## 배포, 보관 및 복구

데이터베이스와 개인 객체 저장소를 백업하고, 원본 자격 증명 마스터 키를 보존하며, 실행자들을 중단시키고, 모든 실행자와 가비지 컬렉터를 함께 업데이트합니다. 스키마 조정에서는 빈 테이블을 트랜잭션적으로 추가하고, 생성량 증가 없이 그 영향을 기록합니다. 기존 코드가 새로운 참조를 보호할 수 없기 때문에 혼합된 기존/새로운 실행자나 컬렉터는 지원되지 않습니다.

`DOCA_BOOK_BATCH_CHECKPOINTS` 기본값으로 설정됨 `on`; 단지 `on` 그리고 `off` 승인된 값만이 인정되며, 유효하지 않은 값은 데이터베이스를 열기 전에 시작 실패합니다. 변경 후 다시 시작하세요. 현재 바이너리에서는 `off` 모든 체크포인트 행과 객체 핀을 유지하면서 불완전한 노드를 재실행합니다. 품질 게이트를 우회하거나 데이터를 수정하지 않습니다. 실패, 삭제 및 불일치된 스코프는 체크포인트를 삭제하지 않습니다; 영구적인 책 삭제는 기존의 명시적 삭제 경로를 통해 그 참조를 해제합니다.

오프라인 바디 스토리지 롤백은 수정 전 기존 체크포인트를 거부합니다. 바이너리의 다운그레이드, 백업 복원 또는 체크포인트 변환은 별도로 승인된 보존 및 복구 계획이 필요합니다. 이 제한을 우회하기 위해 행, 객체 또는 테이블을 삭제하지 마십시오.

## 확인

완전한 합성 파이프라인이 두 번째 작성 세션을 실패로 처리하고, 전체 실행 환경을 교체한 후 다시 시작됩니다. 총 작성 요청 수는 2개에서 3개로 증가하며, 4개는 아닙니다. 42개의 클레임 모두 수락 및 게시 과정을 거칩니다. 다른 테스트에서는 장기형 계획/할당, 부정적인 진단 결과, 분할 결정 등을 복원합니다. 실제 파일 저장 테스트에서는 한 번의 세션을 커밋하고 SIGKILL로 프로세스를 종료시킵니다. 새 프로세스와 임대 계약을 통해 첫 번째 세션을 0개의 생산자 호출 없이 복원하고, 누락된 세션만 한 번 실행합니다.

실제로 배포된 것 `smartdoca/doca:0.2.3` 이미지는 분리된 SQLite 및 PostgreSQL 17/18 경기 정보를 포함합니다. 업그레이드를 할 때는 기존의 13개 테이블 레코드 해시, 노드/실행/출시 본체 바이트, 출판 포인터 및 생성 정보가 모두 보존됩니다. 새로운 테이블은 비어 있게 시작됩니다. 자세한 내용은… [확인 기록](verification/knowledge-book-checkpoints-2026-10-19/README.md) 명령어, 결과 및 제한 사항에 대해.
