# 플러그인 템플릿과 자료

[中文](creation-resources.zh-CN.md)

계약 기준: SDK `0.1.9`, 계약서 `0.1.7`문서 생성, 공개 플러그인 클라이언트, 호스트 선택기, 그리고 AI는 동일한 리소스 서비스를 사용합니다. 통합하기 전에 실제 패키지 내보내기 및 배포 버전을 확인하십시오. 외부 서비스와 장치는 별도의 승인이 필요합니다.

<a id="existing-data-handling"></a>

## 기존 데이터 처리

구현된 리소스 모델은 관리자 템플릿 관리 항목을 제거합니다. `/api/v1/templates` 그리고 `/api/v1/admin/templates`이전의 templateId 생성 필드와 old-table CRUD 기능도 그대로 유지됩니다. document_templates 테이블, 인덱스, 정의 및 레코드는 변경되지 않습니다. 마이그레이션, 삭제, 변환, 듀얼 읽기/쓰기, 또는 해당 테이블을 제공자로 자동 등록하는 기능은 없습니다. 알 수 없는 이전 필드는 거부됩니다. 기존 문서는 저장된 내용과 자산을 그대로 유지됩니다. 롤백 후 이전 빌드에서는 이전 테이블을 읽을 수 있으며, 새로운 서비스에서 생성된 문서는 여전히 현재의 네이티브 모델을 사용합니다.

호스트는 기본 템플릿이나 자료 제공자를 설치하지 않습니다. `doca.documents.create` 문서 소비자입니다; 이메일 또는 출판 소비자는 비즈니스 플러그인에 속합니다. 저장소, 기업 라이브러리, 원격 서비스, 폴더 래퍼는 설치된 리소스 플러그인이 필요합니다. 이 서비스는 원격 리소스 저장소 프로토콜, 리소스 저장소 관리, 또는 공식 콘텐츠를 직접 구현하지 않습니다.

<a id="services-and-public-boundary"></a>

## 서비스 및 공공 경계

수입 `templatesServiceToken` (`templates.v1`), `materialsServiceToken` (`materials.v2`), 그리고 공급자/소비자 유형 `@smartdoca/plugin-sdk/creation-resources`현재의 최소 SDK 범위를 명시하세요. `^0.1.9` 그리고 주입하여 `injections.required`경량 계약은 플러그인-계약에 존재하며, 호스팅 서비스는 코어의 생성-리소스 모듈에 존재합니다.

- 템플릿: register / providers / tags / search / retrieve / describe / read / registerConsumer / consumers / consume.
- 재료: 등록/공급자/태그/검색/조회/설명/컬렉션 설명/컬렉션 항목/이미지.
- 서버 마운트에 등록하세요; 반환된 disposer는 자동으로 스코프된 생명주기의 소유가 됩니다. 기여 ID는 사용됩니다. `${pluginId}.…`. 제로 프로바이더가 유효합니다.
- 서비스는 데이터베이스 실행 범위에 의해 격리되며, 트랜잭션도 그 범위를 따릅니다. 소스의 중단 또는 해제는 소비된 문서나 파일을 정리하지 않고 기여를 해제시킵니다.
- 소비자는 정확한 계약/콘텐츠 타입 버전 조합, inputSchema를 지정하고 실행합니다. 그들은 비즈니스 권한과 부수적 효과를 가집니다; 호스트는 일치 여부, 매개변수, 계정 상태를 확인합니다. 비즈니스 플러그인은 자체 흐름을 통해 이메일 발송/게시를 승인합니다.

계약 및 콘텐츠 버전은 독립적입니다. 예를 들어 `{contract:{id:'doca.document.rich_text',version:1}, contentType:{id:'doca.native.rich_text',version:1}}`문서 소비자들은 rich_text, markdown, 스프레드시트, 캔버스, 프레젠테이션 기능을 지원합니다. 모든 계약은 v1이며, 프레젠테이션 기본 콘텐츠는 v2이고 다른 것들은 v1입니다. 커스텀 계약/콘텐츠 유형은 플러그인 네임스페이스를 사용하며, 양 당사자 간의 명시적인 합의가 필요합니다. 일부 확장 기능만으로는 소비 가능성을 확립할 수 없습니다.

<a id="provider-contract"></a>

## 공급자 계약

템플릿 제공자는 version:1을 선언하고, 물질 제공자는 version:2 및 컬렉션을 선언합니다. 기타 선언 항목으로는 id/pluginId/title, 지원되는 계약/contentTypes/sorts, 태그/search/describe의 구현 방식과 템플릿 읽기 또는 물질 임포트가 포함됩니다. 각 호출에서는 호스트 주체, requestId 및 취소 신호가 전달됩니다.

검색 입력은 contract/contentType/query/tags/providerIds/sort/cursor/limit입니다. query는 최대 1000자까지 가능합니다. 제공자는 키워드 매칭, 모든 태그의 AND 필터링, 현재 검색 가능성 검사, 요청된 정렬을 수행하며, 데이터 본체 없이 경량 메타데이터를 반환합니다. describe는 숨겨진/삭제된 리소스에 대한 접근 및 수정 검사를 다시 수행하며 null을 반환합니다. 태그는 호출자가 검색할 수 있는 리소스에서만 사용되어야 합니다.

카드에는 재검증이 필요함 `{providerId,id,revision}`제목, 요약, 태그, 업데이트 시간, 계약, 콘텐츠 유형, 매개변수, 라이선스. 템플릿 미리보기가 필수이며, 자료 미리보기, 사용 방법, 인기도는 선택적입니다. 템플릿 미리보기는 일반 아이콘이 아닌 실제 스타일을 보여줍니다. 선택기에서는 카드에 표시되며, 클릭하면 확대되고 필요할 때는 네이티브 미리보기가 로드됩니다. 미리보기는 PNG/JPEG/WebP 데이터 URL만 허용되며, 최대 180000인코딩된 문자입니다. 원격 제공자는 브라우저에 임의의 원격 이미지를 직접 노출하는 대신 미리보기를 가져와서 검증합니다. 매개변수는 SDK의 ObjectConfigSchema 하위 집합을 사용하며, 임의의 JSON Schema는 사용되지 않습니다. 호스트는 알려지지 않은 필드를 거부하고 필수 값, 유형, 열거형, 범위를 검증합니다. 기본 UI는 복합 매개변수에 간단한 입력 또는 JSON을 사용하며, 비즈니스 플러그인은 자체 UI를 구축할 수 있습니다.

태그는 안정적인 ID를 가지고 있습니다. `{zh,en}` 제목. 공유 ID를 사용합니다. `doca.tag.…`예를 들어 doca.tag.report/proposal;와 같은 경우, 개인용 ID는 플러그인 네임스페이스를 사용합니다. 호스트는 표시된 이름 대신 ID를 중복 제거합니다. 보이지 않는 태그를 노출하지 않고 일관된 공개-태그 라벨을 사용하세요.

## 정렬 및 페이징

모든 제공업체는 업데이트된 정보를 지원하며, 사용량/인기도 표시할 수 있습니다. 모든 제공업체에서 업데이트된 항목은 시간순으로 내림차순으로 정렬되고, 이름 항목은 이름순으로 정렬되며, providerId/id가 안정적인 결정 요소로 작용합니다. 호스트는 정렬된 스트림을 병합합니다. 사용량/인기는 반드시 하나의 선택된 제공업체가 필요합니다. 이 수치들은 다른 제공업체 간의 인기나 전 세계 호스트의 사용량을 비교할 수 있는 수치가 아닙니다.

UI 쿼리는 기본적으로 24개 항목으로 설정되며, 최대 48개까지 가능합니다. 각 제공업체의 데이터 읽기에는 최대 24개만 읽힙니다. 선택 후에 데이터가 로드됩니다. 키워드/태그/유형/순서/출처를 변경하면 쿼리가 다시 실행됩니다. 호스트는 로컬 필터링을 위해 전체 카탈로그를 다운로드하지 않습니다.

호스트 커서는 사용자, 정규화된 쿼리, 제공자와 연결된 불투명한 인스턴스 로컬 상태입니다. 이 커서는 15분 동안 유지되며, 만료, 재시작 또는 제공자 변경 시 410 에러가 발생하고 새로운 쿼리가 필요하며, 인스턴스 간 연속성 보장이 없습니다. 제한 사항으로는 만료되지 않은 커서 500개, 제공자 100개, 한 제공자당 10,000개의 항목 탐색, 그리고 집계당 100회의 조회가 있습니다. 각 제공자 호출에는 15초가, 검색에는 30초가 소요됩니다. 캐시된 후보를 반환하기 전에 재검색 접근 및 수정에 대한 설명을 제공해야 합니다. 반복된 커서/리소스, 잘못된 순서, 소스 오류는 빈 성공 대신 실패/complete:false를 생성합니다.

이 브라우징 프로토콜은 고정된 인벤토리, 삭제 동기화 피드, 또는 지속적인 변경 로그가 아닙니다. 이러한 기능이 필요한 제공자는 별도의 계약을 정의합니다. 호스트는 리소스 카탈로그 미러, 사용량 테이블, 또는 리소스 업그레이드 마이그레이션을 지속적으로 저장하지 않습니다.

<a id="reading-importing-and-applying-templates"></a>

## 리딩, 가져오기, 템플릿 적용

템플릿 읽기가 허용됨 `{ref,parameters}` 그리고 돌아옵니다 `{contract,contentType,content,assets}`최대 768 KiB; 호스트가 소스 파일을 추가합니다. 변경된 개정판은 충돌이 발생하며, 기존 개정판 하에서 새로운 콘텐츠를 반환할 수 없습니다.

재료 수입 허용 `{ref,operationKey}`제공자는 접근을 다시 확인하고 files.v1을 사용하여 승인된 파일을 가져오거나 선택하며 결과를 반환합니다. `{fileId}`원격 가져오기는 operationKey을 파일 생성 익명성 키 및 contentIdentity/upload-receipt 프로토콜로 사용합니다. 재시도 시도는 동일한 키를 유지하며, 임시 URL은 영구적인 참조가 아닙니다. 호스트는 현재 파일 ACL을 다시 확인한 후 fileId/name/mime/size/source를 반환합니다.

템플릿 자산은 최대 100개까지 포함됩니다. `{key,ref}` 재료 공급업체를 가리키는 기록들. 콘텐츠는 정확한 내용을 사용합니다. `material:<key>` 문자열; Markdown 이미지는 사용됨 `](material:<key>)`플러그인이 다른 데이터베이스 서비스를 호출할 수 있기 때문에 문서 생성 과정에서 쓰기 트랜잭션 외부의 리소스를 가져오거나 재검사합니다. 트랜잭션 내에서는 등록 인스턴스가 여전히 유효한지 확인하고, 새로운 문서를 위한 호스트 첨부물/파일 참조를 생성하며, 플레이스홀더를 로컬 자산 ID로 대체하고, 권한, 언급, 크기, 현재 형식을 확인한 후 영속성을 초기화합니다. 실패 시 새로운 문서와 그 참조들은 롤백됩니다. 제공자에서 가져온 사용자 파일은 암시적 삭제 없이 그대로 남아 있으며, 일반적인 생명주기를 유지합니다.

템플릿 애플리케이션은 문서를 덮어쓰거나 협업을 변경하지 않고 새로운 리소스만 초기화합니다. 제공자를 제거해도 호스트가 관리하는 바인드 자산이나 생성된 문서는 사라지지 않습니다. 네이티브 미리보기는 자산 의존성 없이 템플릿을 지원하며, 의존성 있는 템플릿은 자산을 암묵적으로 가져오지 않고 제공자 미리보기 이미지를 사용합니다.

`POST /api/v1/resources` 받아들임 `template:{ref,parameters}`마크다운/initialContent와는 상호 배타적이며, 빈 문서 생성 시 템플릿을 생략합니다. 문서 소비자의 templates.consume 입력값은 제목과 선택적 parentId/libraryId로 구성되며(루트에서는 생략), id/title/format을 반환합니다. 일반적인 생성 시에는 resource-create 엔드포인트를 유지합니다. 비즈니스 소비자들은 읽기 또는 소비 기능을 사용할 수 있으며, 자체적인 business-operation idempotency를 가집니다.

<a id="browser-plugins-and-ai"></a>

## 브라우저, 플러그인, 그리고 AI

내부 UI 호출에 인증이 완료됨 `POST /api/v1/creation-resources/{templates|materials}/{operation}`플러그인은 플러그인을 사용합니다. `host.platform.templates` / `host.platform.materials` 기존 플러그인 플랫폼 허용 목록과 범위가 지정된 WebView 정체성을 통해. 임의의 서비스 디스패처는 존재하지 않으며, host.request은 플러그인의 API로 제한됩니다.

호스트가 React를 주입합니다. `host.TemplatePicker` / `host.MaterialPicker` FilePicker와 같습니다. TemplatePicker는 close/contract/contentType?/select(selection,resource)/blank?를 받습니다. 두 번째 콜백 인자는 소스가 포함된 전체 카드입니다. MaterialPicker는 close/contentType?/select(file)/accept?를 받고 선택된 내용과 함께 소스를 반환합니다. Pickers는 선택된 내용/매개변수를 수집합니다. 콜백이나 비즈니스 UI가 이를 처리합니다. 플러그인 Pickers는 다른 플러그인의 ui.openView를 호출하지 않고 자신만의 공개 채널을 사용합니다.

문서 생성에는 항상 빈 문서 생성, 일치하는 플러그인 템플릿, 소스/키워드/태그/순서 필터, 더 로드, 미리보기, 그리고 매개변수가 제공됩니다. 종료는 아무것도 생성하지 않습니다. 빈 문서 생성은 제공자 없이 또는 제공자 실패 시에도 사용할 수 있습니다. 업로드/폴더 대화상자는 자료 라이브러리를 제공하며 선택된 자료를 기존의 업로드/삽입 프로세스에 전달합니다.

AI는 creation_resource_providers / creation_resource_retrieve / creation_resource_search / creation_resource_tags / template_describe / template_read / material_import를 사용합니다. document_create는 템플릿을 받습니다. 템플릿 생성은 AI의 승인, 리소스 범위, 영수증을 포함합니다. material_import는 파일 생성 승인을 유지하며, 이미지 생성 영수증이나 image_insert 자산ID와는 별개의 안정적인 파일Id를 반환합니다. 비즈니스 템플릿은 해당 플러그인 도구를 사용합니다. 호스트는 검색 엔진이나 의미론적 모델을 구현하지 않으며, 검색은 제공자에게 속합니다.

<a id="verification-scope"></a>

## 확인 범위

독립적인 검사에는 제로 제공자 및 오래된 테이블 보존, 기존 경로 거부, 5가지 형식으로의 초기화, 물질적 ACL/바인딩, 태그 중복 제거, 병합/페이징, 제공자 실패, 비활성 계정, 수정값 충돌, 매개변수/소비자, 플러그인 소유권/폐기자, 런타임 격리, 그리고 HTTP 식별자가 포함됩니다. SDK 빌드/독립적 사용에는 새로운 엔트리 포인트, 공개 클라이언트, UI 유형이 포함됩니다. 외부 저장소, 기업 서비스, 물리적 장치는 별도의 통합이 필요합니다.

<a id="multiple-providers-and-retrieval"></a>

## 다양한 제공자와 검색

2026-10-02에 적용된 수정 사항으로 query providerId가 providerIds로 대체되었습니다. 기존의 단일 query 필드는 서비스, HTTP, 클라이언트, AI 도구에 의해 거부되며, 적응이나 암시적 변환이 이루어지지 않습니다. 리소스 참조도 마찬가지입니다. `{providerId,id,revision}` 변경되지 않았습니다. 템플릿 매개변수, 파일, 문서, 비즈니스 데이터, 그리고 document_templates는 마이그레이션되거나 삭제되지 않았습니다. 제공자 선호도에 따른 데이터 저장 방식도 도입되지 않았습니다. 롤백 과정에서는 쿼리 클라이언트도 함께 롤백해야 하며, 인스턴스별 커서의 경우 재시작이나 제공자 변경 후 새 쿼리를 실행해야 합니다.

각 제공자는 안정적인 ID와 플러그인으로 표시된 제목을 가진 하나의 소스입니다. 선택적 이중 언어 설명은 각 언어당 최대 1000자로 제한됩니다. 플러그인은 여러 소스를 등록할 수 있습니다. Doca는 네트워크/스토어/생성 범주로부터 소스 구현을 추론하지 않습니다. omitted providerIds는 모든 일치하는 소스를 선택하고, &#91;&#93;는 아무것도 선택하지 않습니다. 여러 ID는 OR로 사용되며, type/tags와 AND로 결합됩니다. 알 수 없거나 로드되지 않은 ID는 범위를 넓히지 않고 404를 반환합니다. Discovery/list/tags/retrieval은 이 선택 방식을 공유하며, cursors는 중복되지 않은 정렬된 ID를 바인딩합니다. usage/popular은 하나의 명시적인 소스가 필요합니다.

리스트 및 설명: CreationResourceResult 반환 값: 원본 카드와 호스트가 생성한 카드를 포함함 `source:{id,pluginId,title,description?}`플러그인은 소스를 위조할 수 없습니다. 호스트가 읽거나 가져오는 결과에는 소스도 포함됩니다; 제공자는 계약서를 변경하지 않습니다. 소스 메타데이터는 현재 등록 정보를 반영하며, 리소스/문서 콘텐츠에 기록되지 않습니다. UI는 소스 이름, 설명, 카드 소유자를 표시합니다.

`templates.retrieve` / `materials.retrieve` 수락:

```ts
{
  query: "找一份适合向管理层汇报季度经营情况的模板", // 非空，最多 1000 字符
  providerIds: ["example.templates.web", "example.templates.company"], // 可省略
  contract: {id: "doca.document.rich_text", version: 1}, // 可选
  contentType: {id: "doca.native.rich_text", version: 1}, // 可选
  tags: ["doca.tag.report"], // 可选，AND
  mode: "auto", // auto | keyword | semantic | hybrid，默认 auto
  topK: 8, // 默认 8，最多 20
}
```

공급업체가 선언함 `retrieval:{modes:["keyword","hybrid"]}` retrieve(context, input)를 구현해야 합니다. 자동 모드의 경우 선언된 모드를 선택하고 실제 모드를 반환하며, 명시적인 모드는 무시되지 않고 실제로 성능이 저하됩니다. 선언되지 않은 기능은 검색을 수행하는 대신 지원되지 않는 결과를 반환합니다. 제공자는 자체 데이터베이스, Meilisearch, vector, remote 검색 및 그 인덱스, 모델, 키, 동기화 기능을 소유합니다.

프로바이더 리트로우 반환 `{items,mode,hasMore}` 현지 관련성에 따라 정렬됩니다. 후보 항목에는 ref/title/summary/tags/contract/contentType 및 선택적 matchText(최대 500자)가 포함되며, 본문, 축소 이미지, 파라미터 스키마는 제외됩니다. 호스트는 소스/타입/태그/중복/현재 접근/수정 정보를 확인한 후 소스와 현지 순위를 추가합니다. 요약문과 매치 설명은 데이터이며, AI 지시사항은 아닙니다.

각 선택된 소스는 커서 이동 없이 최대 1번의 검색 호출만 받습니다. 하나의 소스는 최대 topK 개의 결과를 반환하며, 여러 소스는 각각 최대 min(topK,5)개의 결과를 반환합니다. 제한 사항: 동시에 4개의 소스, 총 15초, 각 소스당 100000바이트의 응답 크기. 크로스소스 프레젠테이션은 엔진 점수 비교나 전 세계적 관련성 확인 없이 로컬 랭크와 안정적인 ID를 균형 있게 처리합니다. 최종 출력은 최대 topK 개의 소스 결과를 포함합니다. 소스는 성공 여부, 실제 모드, 후보 수, 남은 후보들을 기록합니다. 실패는 안정적이지 않은/실패한/타임아웃 코드를 사용합니다. 완전한 경우는 모든 선택된 소스가 성공한 것을 의미하며, 잘린 경우는 후보들이 생략된 것을 의미합니다. 비어 있는 결과는 범위를 넓히지 않습니다.

기본 피커는 기본적으로 모든 항목을 선택한 상태로 인라인 소스/태그 행을 표시합니다. 소스는 다중 선택을 지원하며, 태그는 단일 선택을 지원합니다. 오버플로우는 가로로 스크롤됩니다. 필터 아이콘을 사용하면 키워드/지능형 검색 및 정렬 기능이 활성화됩니다. 제출 버튼을 누르면 패널이 닫히고 결과 제목 옆에 제거 가능한 쿼리가 표시됩니다. 비어 있는 쿼리는 페이지별 브라우징을 유지합니다. 지능형 검색 기능은 한정된 후보를 반환하며, 자산을 가져오지 않고도 요청에 따라 카드 미리보기를 로드합니다. 실패와 결과 제한은 명확하게 표시됩니다. 소스는 지우를 수 있으며, 태그는 선택된 소스에서만 제공됩니다. 피커는 초기 제공자ID와 onSourcesChange(undefined=모든 항목, &#91;&#93;=아무것도 없음)를 받아, 플러그인이 자신의 AI/비즈니스 쿼리에 선택 항목을 전달할 수 있도록 합니다.

AI는 creation_resource_providers를 통해 이름을 소스 ID로 변환한 후, 키워드나 전체 요청을 creation_resource_retrieve로 전송합니다. 두 종류의 리소스는 도구와 현재 식별자를 공유합니다. 검색에는 사진첩이 없으며, 브라우징 도구는 매개변수 스키마도 제거합니다. 선택 후, 설명/읽기/이미지 가져오기 기능을 통해 세부 정보를 얻습니다. 검사 항목에는 제외 사항, 빈 결과, 지원되지 않는/실패하는 소스, 취소, 접근 재검사, 바인딩된 커서, HTTP, 플러그인 채널, 그리고 실제 AI 도구 호출이 포함됩니다.

<a id="material-collections"></a>

## 물질 수집

실시된 2026-10-03 개정안은 `materials.v2` / MaterialsServiceV2. 제공자는 버전 2와 컬렉션을 요구합니다. 버전 1의 기존 materials.v1 제공자들은 컬렉션이 없으며, 기존의 단일 material 커서도 어댑터, 기본 설정, 이중 읽기, 변환 없이 거부됩니다. 템플릿은 여전히 templates.v1 상태입니다. 파일, 문서 내용, 리소스 참조는 변경되지 않습니다. 호스트 material-비즈니스 테이블이나 데이터 마이그레이션/삭제는 추가되지 않습니다. 롤백 작업은 호스트, SDK, pickers, AI 도구를 조율하고 인스턴스 내부 쿼리를 재시작해야 합니다.

자료는 파일을 복사하지 않고, 같은 소스 내의 0개 또는 여러 컬렉션에 참조를 통해 속해 있습니다. 컬렉션/항목은 상속 없이 별도의 태그를 가지고 있습니다. 제공자는 공개적으로 관리되는 SQL/오브젝트/파일 서비스를 통해 대량 업로드, 컬렉션 관리, 멤버십, 권한 부여, 그리고 비즈니스 데이터의 지속성을 관리하며, 독립적인 데이터베이스를 선택하거나 설치 디렉터리 로딩을 우회할 수 없습니다. 다른 소스와 합쳐진 컬렉션은 이 프로토콜의 범위에 포함되지 않습니다.

물질 카드/수령 후보물은 필요합니다. `collections: CreationResourceRef[]`; &#91;&#93;는 아무것도 없다는 의미입니다. 제공자는 호출자에게 보이는 컬렉션만 반환합니다. 컬렉션 메타데이터에는 ref/title/summary/tags/updatedAt/contracts/contentTypes와 선택적 preview/count/usage/popularity가 포함됩니다. count는 총 재고가 아닌 보이는 멤버를 반영해야 합니다. 컬렉션에는 본문, 매개변수, 라이선스, 또는 내장된 항목이 없습니다. 검색 후보에는 preview/updatedAt/usage/popularity가 생략될 수 있으며 matchText도 포함될 수 있습니다. 호스트는 소스와 검색 시 지역 순위를 추가합니다.

`collections: null` 항목 전용 제공자를 명시적으로 선언합니다. 컬렉션 제공자는 구현합니다. `{tags,search,describe,retrieval?,retrieve?}` 식별자/신호와 함께. 목록 및 컬렉션-검색 지원은 독립적입니다; 자료 검색은 대체될 수 없습니다. 컬렉션 계약/콘텐츠타입은 소비 가능한 멤버 유형을 설명합니다. 유형 필터는 어떤 선언과도 일치하며; 태그는 AND를 사용하고 컬렉션Refs는 OR를 사용합니다. 멤버십 변경은 컬렉션 수정 및 자료-카드 컬렉션Refs를 업데이트합니다. 컬렉션 설명은 접근/버전을 강제하며; 호스트는 멤버 쿼리 및 연속 작업 전후에 다시 확인하고, 멤버 멤버십/접근/수정도 확인합니다.

예시:

```ts
const page = await host.platform.materials.search({
  query: "夏日配色", providerIds: ["example.palette.library"],
  tags: ["doca.tag.color"],           // 只筛素材
  collectionTags: ["doca.tag.theme"], // 只筛素材集
  target: "all",                    // all（默认）| materials | collections
  limit: 24,                        // 各组独立上限，最多 48
  cursors: { materials: null, collections: null },
});
// { materials: {items,nextCursor,complete,failures}, collections: {...} }
const members = await host.platform.materials.collectionItems({
  ref: page.collections.items[0].ref, limit: 24, cursor: null,
  query: "红色", tags: ["doca.tag.color"],
}); // 单一素材分页，不内嵌后续成员
const related = await host.platform.materials.retrieve({
  query: "适合夏日海报的暖色背景", target: "materials",
  collectionRefs: [page.collections.items[0].ref], topK: 8,
});
```

검색/조회 기능은 고정된 자료와 컬렉션 그룹을 반환하며, 각 그룹은 자체적인 완료/실패 및 커서/단절 상태를 가집니다. 멤버들을 섞거나 반복적으로 포함시키지 않습니다. 하나의 대상이 있을 경우 다른 그룹은 비어 있거나 완료된 상태가 되며 검색은 이루어지지 않습니다. 커서는 그룹을 넘어갈 수 없으며, 대상은 단 하나만 계속됩니다. limit/topK은 각 그룹에 별도로 적용됩니다. omit collectionRefs는 모든 자료를 선택하고, &#91;&#93;는 아무것도 선택하지 않습니다. collectionRefs는 명시적인 target:materials가 필요합니다. 명시적인 providerIds는 참조된 컬렉션의 소스 자료를 제외할 수 없습니다(400); 알 수 없는 소스는 404를 반환합니다. tags는 별도로 반환됩니다. `{materials,collections}` groups.collectionDescribe(ref)는 메타데이터만 반환합니다; collectionItems({ref,...})는 기본 쿼리/tags/contract/contentType/providerIds/sort/cursor/limit contract을 사용하여 하나의 물질 페이지를 반환합니다.

리트리트 기능은 소스/타입/항목 및 컬렉션 태그와 함께 쿼리/모드/topK/타겟/컬렉션Refs를 지원합니다. 각 그룹은 최대 4개의 동시 실행을 허용하며, 각 그룹당 최대 20개의 최종 결과를 생성할 수 있습니다. 업데이트된 단일 소스 후보들도 100000바이트 제한을 준수합니다. 컬렉션 검사 포함하여 전체 예산은 15초입니다. 지원되지 않는 컬렉션 검색은 탐색 목록을 제공하지 않고 보고됩니다. 검색/멤버 페이징에는 30초가 소요됩니다. 각 그룹은 독립적인 세션/예산을 가집니다. 서로 다른 종류 간의 관련성 요구사항은 통합되지 않습니다.

물질 선택기에는 Materials/Collections 탭이 있습니다. 컬렉션 내에서는 소스/이름, 페이지 멤버, 키워드/지능형 쿼리 지원 기능이 표시되며 컬렉션으로 돌아갈 수 있습니다. 브라우징/미리보기 기능은 파일을 가져오지 않으며, 항목을 선택하면 가져오기가 시작됩니다. 세부 정보에는 컬렉션의 멤버 수가 표시됩니다. AI 검색 기능은 두 가지 방식을 모두 제공합니다: 컬렉션은 일관된 주제를 지원하고, 항목은 정확한 요청을 지원하며, 반드시 두 번의 쿼리가 필요하지 않습니다. material_collection_describe 및 material_collection_items가 사용 가능합니다. 컬렉션 내 관련 항목은 모든 멤버를 스캔하는 대신 collectionRefs를 사용한 검색을 통해 접근할 수 있습니다.

고립된 체크는 여러/다양한 멤버십, 독립적인 커서/태그, 소스 제외, 멤버 필터링, 컬렉션 접근/수정 변경, 무효한 선언, 멤버십 재체크, 탐색 없이 제한된 검색, 디렉터리 처리자, AI 도구, HTTP 채널, 그리고 독립적인 SDK 아티팩트를 포함합니다. 고립된 브라우저 페이지, 검증된 컬렉션 카드, 멤버 브라우징, 지능적인 컬렉션 쿼리, 사용자 문서를 편집하지 않고 반환된 네비게이션도 가능합니다.
