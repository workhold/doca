# ユーザーグループとグループ権限

[简体中文](user-groups.zh-CN.md)

下のサイドバーにある共有フォルダーには、アバター、名前、所有者が記載されたグループが表示されます。メンバーは全員リストと役割を確認できます。内部グループのIDはページ情報として表示されません。

所有者や管理者は、既存のユーザーディレクトリや7日間の招待リンクを通じて人々を招待します。参加にはログインによる同意が必要で、通常のメンバーが作成されます。有効なグループを共有すると、既存の関連ユーザーディレクトリモードに関係が追加されます。招待の受け入れでは、発行者の現在の役割とアカウント状況がチェックされます。リンクトークンはハッシュとして保存され、取り消しや代替が可能です。

所有者のみが管理者を任命/解任したり、所有権を移転したり、グループを解散したりする。管理者は通常のメンバーを招待・解任するが、他の管理者や所有者を管理することはできない。所有者は去る前に既存の活動中のメンバーに移ることができる；他の人は直接去ることができる。

文書、ライブラリ、ナレッジブックはホストリソースの権限を共有します。共有フォルダとそのファイルもグループ権限を受け取ります。共同作業者を招待すると、権限フィールドの上に名前検索/選択機能を持つ「Person」と「Group」タブが表示されます。メンバーページでは、新しい権限の検索フォームを表示せずに既存の個人/グループの権限を管理できます。プラグインが所有する権限アダプターは、自動的にグループAPIを取得することはありません。

各アクティブグループは、3人のアクティブメンバーをアバターとして提供します。アバターにホバーしたりアクティブにしたりすると、既存のユーザープロファイルカードが開きます。「More (+count)」を選択すると、グリッド式のアバターポップオーバーが開き、グリッド行の高さは変わりません。リストを読むたびに、リソース管理のアクセス権や現在のグループのグリッドが再確認されます。受け入れられない新しいグループ招待は、リストを表示しません。リストの応答には、表示用のアイデンティティとアバターフィールドのみが含まれ、プロファイルカードは既存のプロファイルエンドポイントを使用し、外部グループの管理は行われません。

個人およびグループの資格付与は、2行のコンパクトな行構成を共有します。最初の行にはアバターと名前が、右側には許可選択器と削除アイコンが表示されます。アカウント/ソースのメタデータやグループメンバーのアバターは、2行目を子孫範囲の変更に使用します。個人の行にはソースリストの項目が含まれます。削除にはボタンの横に確認バブルが表示されます。キャンセルは何も記録せず、失敗時はそのバブルとページが保持されます。ライブラリや含まれる文書では、子孫範囲の変更を個別に行うことができます。役割の編集は現在の範囲を保持します。ライブラリの管理画面は子文書に対して読み取り専用のままであり、リソースマネージャーは管理資格付与を変更することはできません。

個人およびグループの情報源は独立しており、明確に確認されているように最も重要な役割を果たしています。グループのみの協力者は個人からの助成金を受け取ることができます。個人情報源がない場合は、対応するグループ行を通じてアクセスを解除できます。他の情報源が個人役割を超える場合、行には実際の役割が表示されます。情報源のリストには、所有権、個人、相続、リンク、グループからの助成金が含まれます。通常の相続による個人アクセスは、文書上で無効化または解除することができます。ライブラリ管理の基準は既存の規則を維持します。共有フォルダは、集計された個人分の記録を保持します。リンク・アクセスマーカーは個人情報源を注記し、グループは別途表示されます。歴史的な個人/リンク記録は人為的に分割されません。リソース管理者のみが、グループから派生した協力者を一覧表示できます。

グループからの資格は個人からの資格とは別であり、継承の制限や範囲に基づいて、現在の活動中のメンバー数をもとに評価されます。すべてのメンバーは、グループの役割に関わらず、与えられたリソース役割を受け取ります。リソースの所有者のみが管理資格を割り当てたり変更したりできます。既存の招待ポリシーが適用されます。新規/増加したアクセスには、招待モードでのグループオーナー/管理者の承認が必要であり、発行者と現在のメンバーの参加制限を再確認する必要があります。

離脱、削除、解消はそのソースを直ち無効にするが、独立したアクセスは有効なままである。接続された共同編集セッションは再認可される。検索/知識プロジェクトは更新され、知識結果は返却前に現在のアクセスを確認される。所有権の移転はグループの許可を維持するが、減少した個人アクセスはグループアクセスを削除しない。無効化されたアカウントの引き渡しには所有するグループが含まれ、受け取り人がすでに活動メンバーであることが必要であり、指紋がプレビュー/実行変更を保護する。

管理者は、ユーザごとのオーバーライド機能を利用して、独立したグループディレクトリポリシを設定できます。初期の適用範囲は参加グループのみです。他の適用範囲では、明示的なドキュメント/ライブラリ/共有フォルダへのアクセス権を持つグループ、またはすべての活動中のグループが追加されます。効果的な継承はカウントされますが、公開性は影響されません。検索では、外部グループメンバーページを開くことなく基本的なメタデータが表示されます。グループがリソースアクセス権を取得すると、そのメンバーはリソース共同作業者となります。リソースマネージャーは効果的な共同作業者を確認でき、ユーザーディレクトリは既存の共有明示権限関係を適用します。新たな承認はサーバ上で再度適用範囲を検証します。適用範囲の削減では、既存の承認/招待を維持し、それらを解除することも可能です。カーソルはアクター、クエリ、ポリシー変更を結びつけます。

解散は、グループの取引機能が停止することを意味します。スタートアップ/毎時のクリーンアップでは、24時間以上で解散したグループの関連性は削除され、バッチごとに最大100件までです。メンバーシップ、招待、リンク、グループの権限は削除されますが、グループの墓石、監査記録、コンテンツ、個人権限は保持されます。

承認されたアップグレードにより、最新のDDLに8つのテーブルが追加されます。 `schemaEvolution`互換性生成を維持する。7つのグループ/ACLテーブルは空の状態から始まる。独立したポリシーは明示的に初期化される。 `system/member/revision=1` 初回インストール時。歴史的な個人/リンクの権限、招待状、公開設定、またはユーザーディレクトリのポリシーは変換されません。存在しないインストールポリシーの行は、無意識に再作成されません。データ、ファイル、設定をバックアップし、すべてのサーバーとWebを一緒に更新します。ダウングレードには、別途保存/復元の検討が必要です。詳細は [検証](verification/user-groups-2026-10-30.md).
