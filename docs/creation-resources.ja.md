# プラグインテンプレートと資料

[中文](creation-resources.zh-CN.md)

契約ベースライン：SDK `0.1.9`契約書 `0.1.7`文書作成、公開プラグインクライアント、ホストピッカー、およびAIは同じリソースサービスを使用する。統合前に実際のパッケージエクスポートとデプロイバージョンを確認する。外部サービスやデバイスには別途承認が必要である。

<a id="existing-data-handling"></a>

## 既存のデータ処理

実装されたリソースモデルでは、管理者のテンプレート管理項目が削除されます。 `/api/v1/templates` そして `/api/v1/admin/templates`旧のtemplateId作成フィールド、および旧テーブルのCRUD機能です。document_templatesテーブル、インデックス、定義、レコードは変更されません。マイグレーション、削除、変換、デュアル読み書き、またはそのテーブルをプロバイダとして自動的に登録することはありません。不明な旧フィールドは拒否されます。既存の文書は保持されている内容とアセットを維持します。ロールバック後、以前のビルドから旧テーブルを読み取ることができます。新しいサービスによって生成された文書は、現在のネイティブモデルを使用し続けます。

ホストはデフォルトのテンプレートや素材プロバイダーをインストールしていません。 `doca.documents.create` 文書の消費者です。メールや出版の消費者はビジネスプラグインに属します。ストレージ、エンタープライズライブラリ、リモートサービス、フォルダラッパーにはインストールされたリソースプラグインが必要です。このサービスは、リモートリソースストアプロトコル、リソースストア管理、または公式コンテンツを実装していません。

<a id="services-and-public-boundary"></a>

## サービスと公共境界

輸入 `templatesServiceToken` (`templates.v1`), `materialsServiceToken` (`materials.v2`）、およびプロバイダ/消費者タイプ `@smartdoca/plugin-sdk/creation-resources`。現在の最小SDK範囲を宣言する、例えば `^0.1.9` そして、注入する `injections.required`軽量コントラクトはプラグインコントラクトに存在し、ホストサービスはコアの創造リソースモジュールに存在する。

- テンプレート：register / providers / tags / search / retrieve / describe / read / registerConsumer / consumers / consume.
- 材料：登録/プロバイダー/タグ/検索/取得/説明/コレクションの説明/コレクション項目/インポート。
- サーバーマウントに登録する。返されるディスポーズャーは自動的にスコープ付きライフサイクルによって所有される。コントリビューションIDは使用される `${pluginId}.…`ゼロプロバイダーは有効です。
- サービスはデータベースの実行範囲によって隔離される。トランザクションはその範囲を継承する。ソースを停止またはアンロードすると、使用された文書やファイルをクリーニングすることなく、貢献内容が解放される。
- ユーザーは正確な契約/コンテンツタイプバージョン組み合わせ、inputSchemaを指定して実行します。彼らはビジネス権限と副作用を所有し、ホストは一致性、パラメータ、アカウント状況を確認します。ビジネスプラグインは自身のフローを通じてメールの送信/出版を承認します。

契約と内容のバージョンは独立している、例えば `{contract:{id:'doca.document.rich_text',version:1}, contentType:{id:'doca.native.rich_text',version:1}}`ドキュメントコンシューマーはrich_text、markdown、スプレッドシート、キャンバス、プレゼンテーションをサポートします。すべての契約はv1です。プレゼンテーションのネイティブコンテンツはv2、その他はv1です。カスタム契約/コンテンツタイプはプラグイン名前空間と双方間の明示的な合意を使用します。単独のマッチング拡張機能だけでは利用可能性は確立されません。

<a id="provider-contract"></a>

## プロバイダー契約

テンプレートプロバイダーはversion:1を宣言します。マテリアルプロバイダーはversion:2とコレクションを宣言します。その他の宣言にはid/pluginId/title、サポートされる契約/contentTypes/sorts、タグ/検索/describeの実装、およびテンプレートの読み込みやマテリアルのインポートが含まれます。各呼び出しではホストプリンシパル、requestId、キャンセル信号が受け取られます。

検索入力はcontract/contentType/query/tags/providerIds/sort/cursor/limitです。queryは最大1000文字です。プロバイダーはキーワードマッチング、すべてのタグのANDフィルタリング、現在の検出性チェック、要求された順序付けを行い、ボディなしで軽量なメタデータを返します。describeは再検索や修正のアクセスを表し、隠された/削除されたリソースに対してはnullを返します。タグは、呼び出者が検出できるリソースからのものでなければなりません。

カードには再確認が必要 `{providerId,id,revision}`タイトル、概要、タグ、更新日時、契約、コンテンツタイプ、パラメータ、ライセンス。テンプレートのプレビューが必須であり、素材のプレビュー、使用方法、人気度はオプションです。テンプレートのプレビューでは、一般的なアイコンではなく実際のスタイルが表示されます。ピッカーはカード上でそれを表示し、クリックすると拡大され、必要に応じてネイティブプレビューが表示されます。プレビューはPNG/JPEG/WebPデータURLのみを受け付け、最大180,000文字のエンコードされた文字数です。リモートプロバイダーは、ブラウザに任意のリモート画像を直接表示するのではなく、プレビューを取得・検証します。パラメータはSDKのObjectConfigSchemaサブセットを使用し、任意のJSON Schemaではありません。ホストは未知のフィールドを拒否し、必要な値、型、列挙型、範囲を検証します。基本UIでは複合パラメータに単純な入力やJSONを使用し、ビジネスプラグインは独自のUIを構築できます。

タグには安定したIDがあります。 `{zh,en}` タイトル。共有IDを使用する `doca.tag.…`例えば、doca.tag.report/proposalのように、プライベートIDはプラグイン名前空間を使用します。ホストは表示名ではなくIDを重複排除します。見えないタグを露出させず、一貫したpublic-tagラベルを使用してください。

<a id="sorting-and-pagination"></a>

## ソートとページング

すべてのプロバイダーが更新された名前をサポートし、使用状況や人気度を宣言することができます。各プロバイダー間では、更新された項目は時間順に、名前の項目は名前順に並べられ、providerId/idが安定した優先順位の決定要因となります。ホストは順序付けられたストリームをマージします。使用状況や人気度を表示するには、必ず1つのプロバイダーを選択する必要があります。その数値は、異なるプロバイダー間の人気度やホスト全体の使用状況を比較するものではありません。

UIのクエリはデフォルトで24項目までで、最大48項目までです。各プロバイダーが取得するデータの数は最大24項目です。選択後にデータが読み込まれます。キーワード/タグ/タイプ/順序/ソースの変更によりクエリが再実行されます。ホストはローカルフィルタリングのために全カタログをダウンロードしません。

ホストクルサーは、ユーザー、正規化されたクエリ、プロバイダーに結びついた不透明なインスタンスローカル状態です。これらは15分間有効です。有効期限が切れた場合、再起動やプロバイダーの変更により410エラーが返され、新しいクエリが必要となり、インスタンス間の継続性は保証されません。制限事項として、有効期限のないクルサーは500件、プロバイダーは100件、1つのプロバイダーあたり10000件のアイテムの探索、および1つの集計あたり100回のフェッチが定められています。各プロバイダー呼び出しには15秒、検索には30秒がかかります。キャッシュされた候補を返す前に、再検索のアクセスと修正について説明する必要があります。繰り返されるクルサーやリソース、正しくない順序、ソースエラーにより、空の成功ではなく失敗やcomplete:falseが発生します。

このブラウザプロトコルは、固定されたインベントリ、削除同期フィード、または永続的な変更ログではありません。これらの機能が必要なプロバイダは、別途契約を定義します。ホストは、リソースカタログのミラー、使用状況表、またはリソースアップグレードの移行情報を永続化しません。

<a id="reading-importing-and-applying-templates"></a>

## テンプレートの読み込み、インポート、適用

テンプレート読み込みが受け入れられる `{ref,parameters}` そして戻る `{contract,contentType,content,assets}`最大768KiB；ホストがソースを追加します。変更されたリビジョンは衝突であり、旧リビジョン下で新しいコンテンツを返すことはできません。

材料の輸入が受け付けられます `{ref,operationKey}`プロバイダーがアクセスを再確認し、files.v1を使用して承認されたファイルをインポートまたは選択し、結果を返す `{fileId}`リモートインポートでは、操作キーをファイル作成のインメパトニティキーおよびコンテンツアイデンティティ/アップロード受信プロトコルとして使用します。再試行時も同じキーが保持され、一時的なURLは永続的な参照ではありません。ホストは現在のファイルACLを再確認し、fileId/name/mime/size/sourceを返します。

テンプレートアセットには最大100個まで含まれます `{key,ref}` 素材提供業者を指す記録。コンテンツは正確な内容を使用する。 `material:<key>` 文字列；Markdown画像は使用される `](material:<key>)`ドキュメントの作成時には、プラグインが他のデータベースサービスを呼び出す可能性があるため、書き込みトランザクション外のリソースを取得/再確認する。トランザクション内では、登録インスタンスがまだ有効であることを確認し、新しいドキュメントのためのホストアタッチメント/ファイル参照を作成し、プレースホルダをローカルアセットIDに置き換え、権限、メンション、サイズ、現在のフォーマットを確認し、永続化を初期化する。失敗した場合、新しいドキュメントとその参照がロールバックされる。プロバイダからインポートされたユーザーファイルは暗黙の削除なしで残り、通常のライフサイクルを維持する。

テンプレートアプリケーションは、文書を上書きしたり共同編集を変更したりすることなく、新しいリソースのみを初期化します。プロバイダを削除しても、ホストが管理する結合されたアセットや生成された文書は削除されません。ネイティブプレビューはアセット依存のないテンプレートをサポートし、依存するテンプレートはアセットを暗黙的にインポートすることなく、プロバイダのプレビュイミクス画像を使用します。

`POST /api/v1/resources` 受け入れる `template:{ref,parameters}`マークダウン/initialContentとは互いに排他的です。空白の作成にはテンプレートを省略します。文書の消費者がテンプレート.consumeする入力は、オプションのparentId/libraryIdを含むタイトルで、rootでは省略され、id/title/formatが返されます。通常の作成ではresource-createエンドポイントが保持されます。ビジネス消費者は読み取りや消費を利用でき、独自のビジネス操作のイメプトニティを持つことができます。

<a id="browser-plugins-and-ai"></a>

## ブラウザ、プラグイン、AI

内部UI呼び出しで認証が行われる `POST /api/v1/creation-resources/{templates|materials}/{operation}`プラグインは使用される。 `host.platform.templates` / `host.platform.materials` 既存のプラグインプラットフォーム許可リストとスコープ付きWebViewアイデンティティを通じて。任意のサービスディスパッチャーは存在せず、host.requestはプラグインのAPIに限定される。

ホストがReactを注入する `host.TemplatePicker` / `host.MaterialPicker` FilePickerのように。TemplatePickerはclose/contract/contentType?/select(selection,resource)/blank?を受け付けます。2番目のコールバック引数はソース付きの完全なカードです。MaterialPickerはclose/contentType?/select(file)/accept?を受け付け、選択された内容を含むソースを返します。ピッカーは選択内容やパラメータを収集します。コールバックやビジネスUIが処理を行います。プラグインのピッカーは、他のプラグインのui.openViewを呼び出すことなく、自身の公開チャネルを使用します。

文書作成では常に空白作成、それに合わせたプラグインテンプレート、ソース/キーワード/タグ/順序フィルター、さらに「もっと読む」、プレビュー、パラメータが提供されます。閉じることで何も生まれません。空白作成は、プロバイダーがいなくても、またプロバイダーが失敗しても利用可能です。アップロード/フォルダダイアログでは資料ライブラリが提供され、選択した資料が既存のビジネスアップロード/挿入フローに送信されます。

AIはcreation_resource_providers / creation_resource_retrieve / creation_resource_search / creation_resource_tags / template_describe / template_read / material_importを使用する。document_createはテンプレートを受け入れる。テンプレートの作成にはAIの承認、リソースの範囲、および受領書が含まれる。材料のインポートではファイル作成の承認が保持され、画像生成の受領書やimage_insertアセットIDとは別の安定したfileIdが返される。ビジネストンプレートは対応するプラグインツールを使用する。ホストは検索エンジンやセマンティックモデルを実装していない。検索はプロバイダーの役割である。

<a id="verification-scope"></a>

## 検証範囲

孤立化チェックには、ゼロプロバイダーと古いテーブルの保存、古いパスへの拒否、5種類の形式での初期化、マテリアルACL/バインディング、タグの重複削除、マージ/ページネーション、プロバイダー障害、非アクティブアカウント、レビジョンの衝突、パラメータ/消費者、プラグインの所有権/ディスポーザー、実行時の孤立化、およびHTTPアイデンティティが含まれる。SDKビルド/独立した消費には、新しいエントリポイント、パブリッククライアント、およびUIタイプが含まれる。外部ストレージ、エンタープライズサービス、物理デバイスには、別途統合が必要である。

<a id="multiple-providers-and-retrieval"></a>

## 複数のプロバイダーと検索

2026-10-02に実施された改訂では、query providerIdがproviderIdsに置き換えられました。古い単数形のqueryフィールドは、サービス、HTTP、クライアント、AIツールによって拒否され、適応や暗黙の変換は行われません。リソース参照 `{providerId,id,revision}` 変更されません。テンプレートパラメータ、ファイル、文書、ビジネスデータ、およびdocument_templatesは移行・削除されません。プロバイダ選択の永続化機能は導入されません。ロールバックではクエリクライアントも回復する必要があります。インスタンスローカルのカーソルは、再起動やプロバイダの変更後、新しいクエリが必要です。

各プロバイダーは、安定したIDとプラグインで宣言されたタイトルを持つ1つのソースです。オプションのバイリンガル説明は、各言語で最大1000文字です。プラグインは複数のソースを登録できます。Docaはネットワーク/ストア/生成カテゴリからソース実装を推測しません。省略されたproviderIdsはすべての一致するソースを選択し、&#91;&#93;は何も選択しません。複数のIDはORを使用し、type/tagsとANDで組み合わせられます。不明またはロードされていないIDは、範囲を拡大せずに404を返します。Discovery/list/tags/retrievalはこの選択を共有し、カーソルは重複を除いたソートされたIDを結合します。usage/popularは1つの明示的なソースが必要です。

Return CreationResourceResultのリストと説明：元のカードに加えてホストが生成したものも含まれる `source:{id,pluginId,title,description?}`プラグインはソースを偽造することはできません。ホストが読み取った/インポートした結果にはソースも含まれます。プロバイダが返す契約書は変わりません。ソースメタデータは現在の登録情報を反映しており、リソース/文書の内容に記録されることはありません。UIはソースの名前、説明、およびカードの帰属情報を表示します。

`templates.retrieve` / `materials.retrieve` 受け入れる：

```ts
{
  query: "找一份适合向管理层汇报季度经营情况的模板", // 非空，最多 1000 字符
  providerIds: ["example.templates.web", "example.templates.company"], // 可省略
  contract: {id: "doca.document.rich_text", version: 1}, // 可选
  contentType: {id: "doca.native.rich_text", version: 1}, // 可选
  tags: ["doca.tag.report"], // 可选，AND
  mode: "auto", // auto | keyword | semantic | hybrid，默认 auto
  topK: 8, // 默认 8，最多 20
}
```

プロバイダーが宣言する `retrieval:{modes:["keyword","hybrid"]}` retrieve(context, input)を実装する。自動の場合、宣言されたモードを選択し、実際のモードを返す。明示的なモードでは、無意識のうちに性能が低下することはない。宣言されていない機能は、検索を実行する代わりにサポートされていない結果を返す。プロバイダーは、データベース/Meilisearch/vector/remoteの検索機能、およびそのインデックス、モデル、キー、同期機能を管理する。

プロバイダーがリトリーバルを取得する `{items,mode,hasMore}` 地域的な関連性に基づいて順序付けられています。候補にはref/title/summary/tags/contract/contentType、およびオプションのmatchText（最大500文字）が含まれますが、本文、サムネイル、パラメータスキーマは除かれます。ホストはソース/タイプ/tags/重複/現在のアクセス/リビジョンを確認した後、ソースと地域ランクを追加します。要約やマッチの説明はデータであり、AIの指示ではありません。

選択された各ソースは、カーソルを使った探索を行わずに、最大1回の検索呼び出しを受けます。1つのソースは最大topK件の結果を返し、複数のソースはそれぞれ最大min(topK,5)件の結果を返します。制限事項：同時実行可能なソースは4件、全体的な時間制限は15秒、各ソースあたりの応答データ量は100000バイトです。クロスソースプレゼンテーションでは、エンジンスコアを比較したり、グローバルな関連性を確認したりすることなく、ローカルランクと安定したIDをバランスよく扱います。最終出力は最大topK件の結果です。各ソースは成功した件数、実際のモード、候補件数、残りの候補件数を記録します。失敗時は安定したunsupported/failed/timeoutコードが使用されます。completeとはすべての選択されたソースが成功したことを意味し、truncatedとは候補件数が省略されたことを意味します。空の結果は範囲を拡大しません。

基本ピッカーでは、デフォルトで全選択が可能なインラインソース/タグ行が表示されます。ソースでは複数選択が可能で、タグでは単一選択のみが可能です。オーバーフロー時は水平方向にスクロールします。フィルターアイコンを使うと、キーワード/インテリジェント検索やソートが可能になります。送信後はパネルが閉じられ、結果タイトルの横に取り外し可能なクエリが表示されます。空のクエリの場合はページングされたブラウジングが続きます。インテリジェント検索では、制限された候補が返され、アセットをインポートせずにカードのプレビューが必要に応じて読み込まれます。失敗や結果の制限は明確に表示されます。ソースはクリア可能で、タグは選択されたソースからのみ取得されます。ピッカーは初期のproviderIdsとonSourcesChange（undefined=all、&#91;&#93;=none）を受け入れ、プラグインが自身のAI/ビジネスクエリに選択肢を渡すことができます。

AIはcreation_resource_providersを通じて名前をソースIDに変換し、その後keywordsまたは完全なリクエストをcreation_resource_retrieveに送信する。両方のリソースはツールと現在のIDを共有する。検索にはサムネイルはなく、ブラウジングツールはパラメータスキーマも削除する。選択後、説明/読み取り/インポートで詳細が得られる。チェック項目には除外、空の結果、サポートされていない/失敗したソース、キャンセル、アクセス再確認、結合されたカーソル、HTTP、プラグインチャンネル、実際のAIツールの呼び出しが含まれる。

## 資料収集

実施された2026-10-03の改訂は以下の通り `materials.v2` / MaterialsServiceV2。プロバイダーにはバージョン2とコレクションが必要です。旧版material.v1、バージョン1のプロバイダーはコレクションが欠落しており、古い単一型のmaterialカーソルは、アダプター、デフォルト設定、二重読み取り、変換なしで拒否されます。テンプレートは依然としてmaterial.v1のままです。ファイル、文書内容、リソース参照は変更ありません。ホストのmaterialビジネステーブルやデータの移行/削除は行われません。ロールバックでは、ホスト、SDK、ピッカー、AIツールが協力し、インスタンス内のクエリを再起動する必要があります。

資料は、ファイルをコピーせずに、同一ソース内の0個または複数のコレクションに参照によって属する。コレクション/アイテムには、継承のない個別のタグがある。プロバイダーは、公開された管理されるSQL/オブジェクト/ファイルサービスを通じて、大量のアップロード、コレクション管理、メンバーシップ、認可、およびビジネスデータの永続化を担当する。独立したデータベースを選択したり、インストールディレクトリの読み込みを回避することはできない。クロスソース間のマージされたコレクションは、このプロトコルの範囲外である。

素材カード/回収候補物が必要 `collections: CreationResourceRef[]`&#91;&#93;は何もないことを意味します。プロVIDERは、呼び出し側が見えるコレクションのみを返します。コレクションのメタデータには、ref/title/summary/tags/updatedAt/contracts/contentTypes、およびオプションのpreview/count/usage/popularityが含まれます。countは、総数ではなく、表示可能なメンバーを反映しなければなりません。コレクションには、内容、パラメータ、ライセンス、または埋め込みされたアイテムは含まれません。検索候補にはpreview/updatedAt/usage/popularityは含まれず、matchTextも含まれることがあります。ホストはソース情報と、検索時にはローカルランクを追加します。

`collections: null` アイテム限定プロバイダーを明確に宣言する。コレクションプロバイダーが実装する。 `{tags,search,describe,retrieval?,retrieve?}` ID/シグナルを伴う。リストやコレクション検索のサポートは独立している；資料の検索は代替できない。コレクション契約/コンテンツタイプは消費可能なメンバータイプを記述する。タイプフィルターは任意の宣言に合致する；タグはANDを使用し、コレクションRefsはORを使用する。メンバーシップの変更はコレクションのリビジョンや資料カードのコレクションRefsを更新する。コレクション説明はアクセス/バージョンを強制する；ホストはメンバークエリや継続操作前後、およびメンバーシップ/アクセス/リビジョンを再確認する。

例：

```ts
const page = await host.platform.materials.search({
  query: "夏日配色", providerIds: ["example.palette.library"],
  tags: ["doca.tag.color"],           // 只筛素材
  collectionTags: ["doca.tag.theme"], // 只筛素材集
  target: "all",                    // all（默认）| materials | collections
  limit: 24,                        // 各组独立上限，最多 48
  cursors: { materials: null, collections: null },
});
// { materials: {items,nextCursor,complete,failures}, collections: {...} }
const members = await host.platform.materials.collectionItems({
  ref: page.collections.items[0].ref, limit: 24, cursor: null,
  query: "红色", tags: ["doca.tag.color"],
}); // 单一素材分页，不内嵌后续成员
const related = await host.platform.materials.retrieve({
  query: "适合夏日海报的暖色背景", target: "materials",
  collectionRefs: [page.collections.items[0].ref], topK: 8,
});
```

検索/取得では、固定された資料やコレクショングループが返され、各グループには独自の完了/失敗状態やカーソル/切り捨て状態があり、メンバーを混在させたり繰り返し埋め込んだりすることはありません。1つのターゲットがある場合、他のグループは空/完了状態となり、検索は行われません。カーソルはグループを越えることはできず、ターゲットは1つだけ続行できます。limit/topKは各グループごとに別々に適用されます。omit collectionRefsではすべての資料が選択され、&#91;&#93;では何も選択されません。collectionRefsでは明示的なtarget:materialsが必要です。明示的なproviderIdsでは参照されるコレクションのソースを除外することはできません（400）。未知のソースは404を返します。tagsは別々に返されます。 `{materials,collections}` groups.collectionDescribe(ref)はメタデータのみを返します。collectionItems({ref,...})は、基準のクエリ/tags/contract/contentType/providerIds/sort/cursor/limit contractを使用して1つのマテリアルページを返します。

リトリーバル機能では、ソース/タイプ/アイテム、コレクションタグ、そしてクエリ/モード/topK/target/collectionRefsがサポートされます。各グループは最大1回、1グループあたり最大4件の同時処理が可能で（両方とも8件）、各グループあたり最大20件の最終結果が得られます。更新された単一ソースの候補も100,000バイトの制限に従います。コレクションチェックを含む全体的な予算は15秒です。サポートされていないコレクションのリトリーバルは、トラバースのリスト表示なしでは報告されません。検索/メンバーのページネーションには30秒かかります。各グループは独立したセッション/予算を持ち、統一されたクロスカテゴリーの関連性の主張はありません。

マテリアルピッカには「Materials/Collections」タブがあります。コレクション内では、ソース/名前、ページのメンバー、キーワード/インテリジェントクエリのサポートが表示され、コレクションに戻ることができます。ブラウズ/プレビューではファイルはインポートされません。項目を選択するとインポートが実行されます。詳細にはコレクションのメンバー数が表示されます。AI検索では両方のグループが返されます：コレクションは一貫したテーマを、項目は正確な要求をサポートし、必須の二重クエリは不要です。「material_collection_describe」および「material_collection_items」が利用可能です。コレクション内の関連項目は、全メンバーをスキャンする代わりにcollectionRefsを使用して検索されます。

孤立化されたチェックには、複数のメンバーシップ、独立したカーソル/タグ、ソースの除外、メンバーフィルタリング、コレクションへのアクセス/改訂の変更、無効な宣言、メンバーシップの再チェック、トラバースなしの有界検索、ディレクトリ処理器の両方、AIツール、HTTPチャネルの両方、そして独立したSDKアーティファクトが含まれます。孤立化されたブラウザページでは、検証されたコレクションカード、メンバーのブラウジング、インテリジェントなコレクションクエリ、ユーザーディスクリプトの編集なしでのナビゲーションが可能です。
