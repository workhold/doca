# 平臺服務憑據

[English](service-credentials.md)

入口：管理員後臺 → 平臺設定 → 服務憑據。當前宿主持有的平臺配置包含：

- 身份認證：具名 SSO Client Secret 和允許的 HTTP(S) 來源；身份源引用憑據名稱。
- 驗證碼閘道器：HTTP(S) 地址、Bearer 金鑰和手機/郵箱渠道。
- 文件搜尋：Meilisearch API 金鑰及允許來源。

檔案後端憑據和 CloudFront 簽名金鑰只透過 `DOCA_FILE_STORES_JSON` 配置，儲存管理頁只讀，不在平臺記錄中編輯。[外掛憑證](plugin-credentials.zh-Hant.md)使用獨立的服務端加密服務和部署主金鑰。

<a id="持久化与配置优先级"></a>

## 持久化與配置優先順序

平臺配置儲存於 `account_settings` 的 `service-credentials` 記錄。現有程式碼只在記錄不存在時，從執行環境初始化身份和訊息配置；之後已有資料庫記錄優先，修改環境變數不會覆蓋已儲存配置。這是現存初始化路徑，本輪如實記錄，未新增介面卡或遷移。當前宿主明確拒絕含舊 storage 形狀的記錄。

資料庫連線、站點地址、監聽埠和檔案儲存仍屬於啟動配置。資料庫連線必須先於持久設定讀取；首次管理員仍透過顯式引導命令初始化。

<a id="接口与密钥处理"></a>

## 介面與金鑰處理

`GET` / `PUT /api/v1/admin/service-credentials` 只允許系統管理員訪問，寫請求驗證 Origin。GET 用 null 替換已有秘密值；PUT 的 null 保留原值，空字串明確清空。不要提交偽遮罩字串。修訂號防止併發覆蓋。審計只記錄動作，不記錄金鑰；端點繼續限制協議、來源和重定向。

服務端儲存訪問第三方服務所需的可用憑據，資料庫及備份按敏感配置保管。金鑰不返回普通使用者、公共 bootstrap、錯誤日誌或管理員 GET 響應。外掛憑證加密不會自動重新加密這些平臺設定。

每個例項在 API 請求前檢查配置修訂號，變更後重新整理介面卡，無需重啟。輪換驗證碼金鑰使未完成挑戰失效。儲存金鑰變更遵循部署方管理的[儲存規則](storage.zh-Hant.md)，保留穩定儲存 ID 和被引用位元組。
