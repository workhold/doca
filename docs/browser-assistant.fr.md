# Assistant de navigateur

[简体中文](browser-assistant.zh-CN.md)

Ouvrez le menu d’accès à la compte → **Assistant de navigateur**, ou `/#/browser-assistant`Capturer le contenu web sélectionné ou l’intégralité de la page chargée avec des images, et utiliser votre assistant Doca AI dans la barre latérale de l’extension.

<a id="install-and-sign-in"></a>

## Installer et se connecter

Créer un profil de capture dans Doca : créer de nouveaux documents dans une destination choisie, ou ajouter des éléments à un document de texte riche / Markdown existant. Configurer le profil par défaut, la règle de titre (`{title}`, `{date}`) et instructions d’IA. Les pages de livre de connaissances générées ne peuvent pas être des cibles d’ajout direct.

Télécharger et extraire l’extension configurée en utilisant le bouton situé au-dessus des onglets de paramètres. Activer le mode développeur dans Chrome/Edge et charger le dossier extrait. Le Manifest V3 nécessite Chromium 116 ou plus récent. Une version ZIP auto-hébergée n’est pas de type distribution à installer par clic ; la publication et la signature pour entreprises ne sont pas disponibles. Recharger les pages ouvertes avant l’installation pour afficher la barre d’outils de droite ; la capture effectuée par l’extension charge également ses scripts sur demande.

L’archive ne contient qu’une adresse Doca, sans identifiants d’accès ni date limite d’activation. Lors de l’ouverture de l’extension, l’inscription Doca existante du navigateur est utilisée. Si vous êtes déconnecté, une page de connexion normale Doca s’ouvre ; connectez-vous et revenez à l’extension. Fermer une fiche Doca ne déconnecte pas. Le déconnexion du site web, son expiration ou sa suspension invalident l’accès via le navigateur associé. Changer d’accès redémarre les profils de cet accès et isole le matériel inachevé ainsi que l’état de l’IA par connexion.

L’extension ne lit ni ne copie jamais les cookies du site web. Une page Doca de même origine fournit un code d’autorisation à utilisation unique de 60 secondes, vérifié par une épreuve SHA-256 et un verificateur aléatoire. Le token restreint échangé dure 10 minutes, reste stocké dans la session de la extension de confiance et est réautorisé automatiquement. Le serveur stocke les hachages et vérifie la session originale du site web à chaque opération. Lorsque les restrictions liées aux cookies empêchent les vérifications côté extension, la page de même origine vérifie le login ; la vérification passive peut réutiliser le proof pendant jusqu’à 30 secondes, tandis que la capture des utilisateurs et les opérations d’IA le vérifient à nouveau.

<a id="capture-ai-and-server-address"></a>

## Capture, IA et adresses serveurs

Pour **Créer un nouveau document**Sélectionnez les documents personnels, une racine de bibliothèque ou un document spécifique dans l’arbre de destination. Le sélecteur suit le dialogue de déplacement du document. Les bibliothèques sont affichées séparément des documents récents ; utilisez « Charger plus de bibliothèques » pour continuer. Reouvrir un profil sauvegardé agrandit et localise sa destination. Les documents en lecture seule restent visibles en tant qu’ancêtres désactivés. Les échecs de chargement peuvent être répétés sans changer la sélection ; les destinations indisponibles empêchent la sauvegarde. La limite existante pour le contour de la bibliothèque est de 10 000 nœuds, avec un avertissement lorsqu’elle est atteinte. Le contenu généré par Knowledge-Book reste en lecture seule. Les cibles d’ajout continuent à utiliser la recherche de documents.

Les pages web normales affichent cinq icônes persistentes sur le côté droit : **Capture cette page, Sélection de capture, Assistant Doca, Ouvrir le site web Doca et Paramètres**Ouvrir le site web de Doca ouvre le site configuré actuellement dans une nouvelle fenêtre, même lorsque vous êtes déconnecté ; une configuration de site invalide ou manquante ouvre les paramètres de l’extension. Il est possible de déplacer le bouton supérieur verticalement pour éloigner la barre d’outils des contrôles de la page web. Sa position locale reste intacte après rechargement, ouverture de nouvelles pages web ou redémarrage du navigateur ; les flèches, Home et End fonctionnent également lorsque le bouton est en focus. La flèche en bas sous les Paramètres fait éclater ou réduire la taille de la barre d’outils ; le bouton réduit peut encore être déplacé. La barre d’outils lit sa position dans la mémoire avant de devenir visible. La sélection de texte ne montre pas d’autre icône ou barre d’outils.

Cliquez sur l’icône de capture pour examiner sa règle et sa destination dans le menu déroulant personnalisé de la bulle de confirmation, puis confirmez. Sélectionnez du texte d’abord pour effectuer la capture de texte. La capture de la page entière inclut le DOM de niveau supérieur chargé en dehors de la fenêtre d’affichage. La règle par défaut est prédéfinie, et les autres règles restent disponibles. Chaque tentative de capture vérifie à nouveau le connexion et les profils actuels. Les échecs temporaires peuvent être répétés ; les profils manquants mènent aux paramètres. Réessayer depuis la bulle ou l’onglet de l’extension permet de réutiliser le matériel original et l’ID de demande sans dupliquer le contenu mis en cache. Le matériel non envoyé reste dans la session actuelle du navigateur et peut devoir être sélectionné à nouveau après la fermeture de tout le navigateur. Après mise à jour ou redémarrage de l’extension, les scripts de page anciens vous demandent de recharger cette page.

L’icône d’assistant Doca ouvre le panneau de droite du navigateur avec la même interface de chat Doca, le sélecteur de modèles, le Markdown, les informations de progression et les approbations. L’ouverture du panneau ne déclenche pas l’utilisation d’un modèle. L’envoi d’un nouveau message lit la page active la plus récente ; les changements de tab, la navigation et les routes dans la page mettent à jour la référence. Réessayer un message conserve son contenu original. Les images non supportées ou indisponibles ne empêchent pas l’IA de lire le texte présenté ; les images indisponibles conservent également les placeholders de source lors du archivage. Les messages d’accueil indiquent les options de sauvegarde, de résumé, d’extraction des points clés et d’organisation du contenu web. Il n’y a pas de case à cocher pour la page d’attachement. L’IA utilise les modèles, les mesures et le flux d’approbation de Doca. Continuer la conversation dans Doca. Les connexions permettent initialement à l’IA d’interagir ; il est possible d’éditer une connexion dans Doca pour changer son nom ou passer à une autre IA. Les politiques d’utilisateur et de modèles restent en vigueur.

Le premier message accepté indique le nom d’une nouvelle conversation, basé sur son nom de page, sa demande et son nom d’hôte, avec un icône de navigateur qui identifie son origine. Les pages nouvellement attachées apparaissent dans les ressources exploitées sur les deux surfaces, s’ouvrant dans une nouvelle fiche avec une entrée par URL. Ces liens ne permettent pas d’accéder aux documents. Après une modification de règle, en rouvrant l’assistant, celui-ci lance un composant pour la règle actuellement sélectionnée, lorsque la conversation mémorisée appartient à une version antérieure. La conversation originale et les messages en attente restent inchangés ; les tâches anciennes ne sont pas silencieusement réintégrées dans une nouvelle règle. Les titres et conversations existants ne sont pas remplis ou réécrits.

La version d’extension actuelle est **0.2.11**L’ouverture de l’extension vérifie la version du paquet fournie par le site Doca configuré. La connexion se met à jour, et la vérification se répète tous les cinq minutes au moins, tant que l’extension est ouverte ; les paramètres permettent également une vérification manuelle. Un paquet plus récent affiche une notification dans la fenêtre pop-up et dans la barre latérale de l’IA, qui renvoie à la page de téléchargement du site. Doca affiche alors la version et le nom complet du fichier. `doca-browser-assistant-<version>.zip`, tiré de l’extension `manifest.json` Indépendamment de la version du serveur. Après avoir mis à jour Doca, téléchargez et réchargentz l’extension dans Chrome/Edge ; une mise à jour du serveur ne remplace pas une extension installée. La capture ordinaire ne nécessite aucun modèle d’IA. La barre latérale d’IA nécessite un modèle configuré et autorisé par le site.

Les vérifications de version ne signalent que les paquets du site plus récents. Elles ne déterminent pas la compatibilité protocolaire ni ne restreignent les opérations. Un point de terminaison manquant, une réponse invalide ou une erreur de réseau affichent une vérification échouée plutôt que de déclarer la compatibilité ou la version la plus récente. La configuration, l’autorisation et les formats de données en attente restent inchangés ; aucune donnée historique n’est migrée ou supprimée. Les extensions existantes nécessitent une mise à jour manuelle avant de pouvoir afficher ces messages.

Si une page HTTP(S) normale n’a pas de récepteur de capture après la navigation ou a été ouverte avant l’installation, Capture charge les scripts inclus dans le paquet dans son cadre principal et réessaye une fois sans recharger la page. L’extension déclare `scripting` En plus de l’accès existant au site HTTP(S) pour cette récupération. Les pages restreintes par le navigateur et l’accès refusé au site fonctionnent toujours mal.

Les nouvelles messages de l’IA sont stockés transactionnellement dans IndexedDB avant que leur contenu ne soit consommé, et sont ciblés par le site Doca, l’utilisateur, la connexion et le profil sélectionné. Les messages envoyés, rejetés ou acceptés apparaissent une seule fois dans la conversation. Seuls les messages qui attendent encore d’être envoyés apparaissent dans la liste en attente ; ils ne restent pas là jusqu’à ce que l’IA réponde. Le redémarrage permet de continuer avec le même ID de message ; un travail déjà accepté par le serveur est réconcilié avant toute nouvelle capture ou soumission de page. Les messages en attente dans localStorage restent inchangés et nécessitent une action explicite comme « Continue » ou « Withdraw », en utilisant le modèle et le champ actuel sélectionnés.

Utilisez l’icône Paramètres de la droite pour ouvrir une page de paramètres indépendante, gérer les règles de capture dans Doca ou modifier. **Adresse du serveur Doca**, par exemple `https://doca.example.com`, sans `/api/v1`autres chemins ou paramètres de requête. Le popup de l’extension conserve également son entrée de configuration. Alternativement, copiez la configuration du site public dans Doca et collez-la dans la section de configuration évolutive de l’extension. La production nécessite HTTPS ; l’HTTP en boucle est autorisé pour le développement. Le format strict est `{ "version": 2, "origin": "https://doca.example.com" }`Le changement de site vérifie l’utilisateur connecté à ce dernier et ne transmet jamais les données en attente du site précédent.

<a id="revoke-and-restore"></a>

## Anéantir et restaurer

Annonce une ou toutes les connexions navigateur dans Doca. Les clés d’accès et les codes restants ne fonctionnent plus, et les tâches liées à l’IA du navigateur sont annulées. Se connecter au site web ne restaure pas une connexion annulée. Choisissez explicitement « Restaurer connexion dans Doca », puis reconnectez l’extension. L’autorisation automatique réutilise l’enregistrement de l’installation et ne peut créer une autre connexion pour contourner l’annulation.

Les documents sauvegardés, les images originales et les conversations restent intacts. La révocation et le déconnexion ne peuvent annuler les transactions effectuées. Les tâches d’IA provenant du site web dans la même conversation restent indépendantes. Les limites des outils de navigateur et des actions effectuées valident la session actuelle du site web ; ce hôte annule les tâches affectées après la déconnexion, tandis que d’autres exécutants vérifient à nouveau l’autorisation au niveau des limites de battement de cœur et d’opération.

<a id="limits-and-upgrade"></a>

## Limites et améliorations

Avant de mettre à jour ou de faire un rollback, arrêtez l’envoi dans la file d’attente et fermez toutes les pages et extensions Doca anciennes. Ne lancez pas les anciens et nouveaux émetteurs ensemble. Conservez localStorage, IndexedDB, les tombstones conservés et tous les données ultérieures. Le rollback désactive l’envoi dans la file d’attente : il ne exporte pas le nouveau store dans localStorage et ne réactive pas un émetteur ancien. Une version ancienne sans une fonctionnalité de désactivation sécurisée de l’émetteur ne peut pas reprendre l’envoi dans la file d’attente. Voir [contrat d’entretien et de rétrogradation approuvé](verification/issue-tracker-2026-10-21/ai-pending-idb.md).

La capture conserve le texte sémantique, les titres, les listes, le code, les liens, les tableaux ordinaires, les attributions de source et les images. Elle ne reproduit pas les CSS/interactions arbitraires, les données non chargées, la pagination, les iframes, les racines ombrages fermées, les listes virtuelles, le canvas ou la vidéo. Les images SVG statiques et les SVG en ligne sont nettoyées et rasterisées localement en PNG transparent ; les scripts et les gestionnaires d’événements sont supprimés. Les SVG nécessitant des ressources externes, l’HTML intégré, l’animation ou une rendu non supporté sont remplacés par un placeholder.

Nouvelles images statiques en PNG, JPEG et WebP de plus de… **4 MiB ou 25 millions de pixels** Les images sont compressées avant l’upload, à un volume maximal de 4 MiB ; leur longueur maximale est de 4096 pixels, et leur taille totale est de 16 millions de pixels. La codage source, l’format PNG/WebP avec alpha et l’orientation d’affichage EXIF sont conservés. Les images plus petites conservent leurs bytes originaux. Les GIF, les WebP animés et les APNG ne sont jamais flattés ; les animations dépassant les limites de 20 MiB ou de 25 millions de pixels sont remplacées par un placeholder dédié. Les images stockées et celles déjà uploadées lors d’une tentative de récupération ne sont pas traitées à nouveau. La taille des fichiers source est limitée à 64 MiB, et la décodage statique à 100 millions de pixels. Le transfert des fichiers SVG est limité à 32 MiB pour limiter les messages d’extension. La sortie SVG est limitée à 4096 pixels sur son longueur maximale et à 16 millions de pixels, puis suit les limites de compression PNG.

Les limites du serveur restent de 20 MiB / 25 millions de pixels par image, 100 images / 100 MiB au total ; le Markdown est limité à 512 KiB. Les nouvelles captures enregistrent les images avant la création d’une tâche. Les images non supportées, illisibles ou non convertibles deviennent des placeholders lisibles à leur position originale, avec une raison et le lien source HTTP(S) original ; les autres images et textes continuent d’être sauvegardés. Les URL de blobs et de données ne sont pas persistés en tant que liens de placeholder. Les erreurs d’autorisation, de quota et de stockage empêchent toujours la sauvegarde. Une fois étalées, le manifeste exact et l’ID de requête restent figés pour les réessayages, et les erreurs de traitement d’image détectées pendant l’upload deviennent des placeholders à la fois au moment du commit. Les erreurs de réseau, d’autorisation, de quota et d’écriture de stockage empêchent toujours la soumission. Les tâches en attente expirent après 24 heures ; la nettoyage ne supprime que les objets non liés.

L’extension 0.2.6 utilise le protocole de capture v1 existant et le format de fichiers raster sans aucune modification de la base de données. Le propriétaire a approuvé de laisser les documents sauvegardés, les images téléchargées et les tâches historiques échouées inchangées : il suffit de mettre à jour/charger à nouveau l’extension et la page source, puis de commencer une nouvelle capture pour une ancienne erreur. Les tâches anciennes ne sont pas converties automatiquement ni reenvoyées ; elles conservent leur date d’expiration normale. Le rollback ne nécessite aucune conversion de données ; les documents et tâches existants restent intacts. Aucun contenu de paiement en étapes ou document historique n’est réécrit automatiquement.

Les outils d’IA offrent des lectures et recherches limitées, permettent de capturer et d’effectuer des modifications de texte riche ou en Markdown dans le cadre des ressources du profil et des permissions du utilisateur actuel. Les réseaux arbitraires, les scripts, les outils de plugin et l’automatisation du navigateur sans restrictions ne sont pas disponibles.

Avant la première sortie, le propriétaire a approuvé le remplacement du design précédent de l’package d’activation et du token de 180 jours. La configuration v1 ancienne, les endpoints d’activation et les tokens sont rejetés sans conversion. Les profils existants, le contenu, les images, les conversations et les enregistrements de credences restent intacts. Le serveur d’actualisation, le Web et l’extension sont mis à jour ensemble ; il faut utiliser la configuration du site public et se connecter à nouveau. Il n’y a pas de fallback d’authentification ancienne ni de contrat de version mixte.

Les fichiers d’extension se trouvent ici `apps/browser-extension`. `pnpm build:browser-extension` regroupe l’interface UI IA partagée localement `generated/` actifs et fonctionne en tant que partie `build`, `dev` et `dev:workspace`. Le serveur packagera ces ressources locales, les fichiers d’extension fixes et la configuration du site public sans charger les scripts distants. Les déploiements source et Docker doivent inclure les ressources construites. La version actuelle de DDL ajoute deux tables vides : website-session/code, aux cinq tables initiales conservées, sans modifier la génération de compatibilité ou remplir les identifiants anciens. L’extension 0.2.6 sauve les images liées et les fichiers SVG séparément de leurs liens cibles, évitant ainsi les structures Markdown imbriquées qui empêchent la conversion de toute la page. L’extension 0.2.10 et Doca 0.2.22 conservent également les placeholders de médias intégrés non supportés, acceptent les avertissements de conversion récupérables, et conservent le texte source littéral si la parsing échoue. Les diagnostics de demande actuels apparaissent à côté du lien vers le document sauvegardé ; auc rapport n’est stocké dans la base de données ou dans la tâche figée. Les tentatives de récupération réussies restent idempotentes et ne reproduisent pas le rapport historique. Le contenu source, l’autorisation, les quotas et les limites de stockage restent valables. Voir [Notes de la version 0.2.21](releases/0.2.21.md).

Les connexions AI du navigateur actif sont protégées ; les sources et les images restent jusqu’à leur délai initial de 24 heures. Une capture expirée est reconstruite une fois à partir du même matériau congelé par l’extension 0.2.10. Aucune nettoyage manuel n’est nécessaire.
