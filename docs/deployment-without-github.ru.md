# Развертывание без доступа к GitHub

[简体中文](deployment-without-github.zh-CN.md)

Бизнес-сервер не нуждается в источнике скачивания, Git, Node.js или pnpm. Сначала установите Docker Engine, плагин Docker Compose, Bash и OpenSSL, затем передайте файлы развёртывания, подготовьте изображение, запустите Doca и инициализируйте администратора. Этот руководство устанавливает Doca 0.3.1 на свежий одноплатформенный сервер с SQLite и локальным хранением файлов. Уже существующие установки должны проверить… [требования к выпуску](releases/0.3.1.ru.md) и сохранять их базы данных, файлы, конфигурацию и главный ключ учетных данных.

<a id="fresh-installation-from-one-yaml"></a>

## Новая установка из YAML-файла

`node scripts/pack-deployment.mjs` также выводит `doca-compose-vVERSION.yaml` и его контрольный сумма. Перенесите YAML-файл и сохраните его как `compose.yaml` В постоянном каталоге развёртывания измените `DOCA_ORIGIN` и ваша генерированная `DOCA_CREDENTIAL_MASTER_KEY`Защитить его `chmod 600 compose.yaml`, затем запустите `docker compose up -d`Нет `.env`Необходимо использовать JSON-файл seccomp или скрипт внешнего администратора. Используйте соответствующий образ версии 0.3.1; отдельный YAML-файл и контрольный сумма также прилагаются к релизу на GitHub.

После того как процесс здоров, запустите. `docker compose exec doca bash docker/admin.sh bootstrap`; использовать `reset-password` Для сброса пароля. Введение пароля скрыто и не попадает в YAML. Этот пример предназначен только для новых установок SQLite/local-storage. Существующие сайты сохраняют свое имя проекта, объемы данных и ключи. Бэкапы включают защищенный YAML. Требования к реверс-прокси остаются такими же, как описано ниже.

## 1. Передача файлов развертывания

Человек, имеющий доступ к репозиторию, клонирует main и создает пакет развертывания:

```sh
git clone --branch main --depth 1 https://github.com/workhold/doca.git
cd doca
node scripts/pack-deployment.mjs
```

Названия архивов и метки изображений ниже используют 0.3.1 в качестве примера. Используйте имена файлов, указанные пакером, и изображение, указанное в созданном файле Compose.

Передача `doca-deploy-v0.3.1.tar.gz` и его `.sha256` Сумма контроля через сервис предприятия, внутреную URL скачивания или удаляемое хранилище. Пакер читает только публичные файлы развертывания и не включает локальные файлы. `.env`Пользовательские данные или изображение контейнера. GitHub Release для соответствующего тега включает бандл и проверочный код.

Поместите оба файла в один и тот же каталог на бизнес-сервере, проверьте и извлеките.

```sh
sha256sum -c doca-deploy-v0.3.1.tar.gz.sha256
tar -xzf doca-deploy-v0.3.1.tar.gz
cd doca-deploy-v0.3.1
```

На macOS используйте `shasum -a 256 -c doca-deploy-v0.3.1.tar.gz.sha256`Выполняйте последующие команды развертывания из этого директория:

```text
doca-deploy-v0.3.1/
  compose.yaml
  docker.env.example
  README.zh-CN.md
  README.md
  LICENSE
  scripts/
    bootstrap-admin.sh
    reset-admin-password.sh
```

Бандл сохраняет переменные окружения и постоянные монтировки, удаляет настройки сборки исходного кода и использует `pull_policy: missing`В переробленном образе содержится runtime в формате PDF/холст; JSON с секцомп не передается. Существующие установки сохраняют свой проект Compose, объемы, конфигурацию и мастер-ключ. Эти изменения требуют переробления образа; опубликованные старые образы все еще соответствуют своим оригинальным требованиям развёртывания.

<a id="copy-compose-and-env-manually"></a>

### Копировать Compose и .env вручную

Для передачи текста сохраните эту конфигурацию одного сервера. `compose.yaml` и использовать соответствующий хост `scripts/` Если нужно, или команду встроенного администратора изображений. Бонд включает дополнительные опциональные настройки; в этом примере используется только SQLite и локальное хранение.

```yaml
services:
  doca:
    image: docker.io/smartdoca/doca:0.3.1
    pull_policy: missing
    restart: unless-stopped
    init: true
    stop_grace_period: 30s
    environment:
      NODE_ENV: production
      DOCA_ORIGIN: "${DOCA_ORIGIN:?Set DOCA_ORIGIN in .env}"
      DOCA_HOST: 0.0.0.0
      DOCA_PORT: "39120"
      DOCA_DATABASE: sqlite
      DOCA_SQLITE_PATH: /data/doca.db
      DOCA_BOOK_BATCH_CHECKPOINTS: "${DOCA_BOOK_BATCH_CHECKPOINTS-on}"
      DOCA_AI_SQLITE_PATH: /data/ai.db
      DOCA_DATA_DIR: /data
      DOCA_FILE_STORE_ID: "${DOCA_FILE_STORE_ID:?Set DOCA_FILE_STORE_ID in .env}"
      DOCA_FILE_STORES_JSON: "${DOCA_FILE_STORES_JSON:?Set DOCA_FILE_STORES_JSON in .env}"
      DOCA_CREDENTIAL_MASTER_KEY: "${DOCA_CREDENTIAL_MASTER_KEY:?Generate and set the key in .env}"
    ports:
      - "127.0.0.1:39120:39120"
    volumes:
      - doca_data:/data

volumes:
  doca_data:
```

Сохраните следующее как `.env`Установите реальное место происхождения браузера и введите главный ключ, полученный на следующем этапе:

```dotenv
DOCA_ORIGIN=https://docs.example.com
DOCA_CREDENTIAL_MASTER_KEY=
DOCA_FILE_STORE_ID=local
DOCA_FILE_STORES_JSON='{"version":1,"stores":{"local":{"provider":"local","root":"/data/storage"}}}'
```

## 2. Настроить среду и прокси

Для создания пакета выполните следующую команду; можно пропустить копирование, если вы уже создали его. `.env` ручным способом:

```sh
cp docker.env.example .env
openssl rand -hex 32
chmod 600 .env
```

Напишите генерированное 64-символьное шестнадцатеричное значение. `DOCA_CREDENTIAL_MASTER_KEY`Заменить публичный пример. Установить `DOCA_ORIGIN` Пользователям из HTTP(S) источника будет открыто. Сгенерируйте ключ один раз, сохраните его безопасно и отдельно, и храните его при повторных запусках. Сохраняйте корень локального хранилища в `/data/storage`Не размещайте учетные данные администратора. `.env`.

Compose подключается только к `127.0.0.1:39120`Так что настройте реверсивный прокси на том же сервере. Для публичного HTTPS Caddy может использовать:

```caddyfile
docs.example.com {
    reverse_proxy 127.0.0.1:39120
}
```

Указать DNS-адрес сервера и разрешить выдачу сертификатов, или использовать существующие корпоративные сертификаты. Для доверенной внутренней сети без доступа в Интернет установите `DOCA_ORIGIN=http://doca.internal`Настроить внутренние записи DNS или хостов клиентов, и использовать этот HTTP-прокси без выдачи публичного сертификата:

```caddyfile
http://doca.internal {
    reverse_proxy 127.0.0.1:39120
}
```

Другие прокси должны сохранять `Host` и передача HTTP и WebSocket-упградов `/api/v1/ws`Бизнес-среда должна предоставить Docker, прокси и их установочные пакеты заранее; они не входят в пакет развертывания.

## 3. Подготовьте изображение.

<a id="docker-hub-is-reachable"></a>

### Docker Hub доступен.

Если GitHub заблокирован, но Docker Hub доступен, загрузите готовую изображение:

```sh
docker compose pull doca
```

<a id="registries-are-also-unreachable"></a>

### Реестры также недоступны.

Поставщик готовит архив изображений на устройстве с доступом к реестру. Сначала необходимо подтвердить архитектуру целевой процессора. В этом примере используется Linux x86-64.`linux/amd64`); для ARM64 используйте `linux/arm64` и обозначите доставленные файлы соответствующим образом:

```sh
docker pull --platform linux/amd64 docker.io/smartdoca/doca:0.3.1
docker image inspect docker.io/smartdoca/doca:0.3.1 --format '{{.Os}}/{{.Architecture}}'
docker save -o doca-image-v0.3.1-linux-amd64.tar docker.io/smartdoca/doca:0.3.1
sha256sum doca-image-v0.3.1-linux-amd64.tar > doca-image-v0.3.1-linux-amd64.tar.sha256
```

Перенесите изображение `.tar` и сложные проверочные коды вместе. Из их директории на бизнес-сервере:

```sh
sha256sum -c doca-image-v0.3.1-linux-amd64.tar.sha256
docker load -i doca-image-v0.3.1-linux-amd64.tar
docker image inspect docker.io/smartdoca/doca:0.3.1 --format '{{.Os}}/{{.Architecture}}'
```

Подтвердите, что загруженный тег существует. `smartdoca/doca:0.3.1` Если архитектура соответствует целевой версии, то возвращаемся в директорию развертывания. Внутренний реестр — еще один вариант доставки: поставщик публикует ту же версию изображения, а бизнес-команда меняет Compose. `image` Имейте в виду адрес внутреннего реестра перед выполнением. Сохраняйте пакет, изображение и скрипты инициализации в одном и том же релизе.

## 4. Начать и инициализировать базу данных

После загрузки изображения запустите программу из директории развертывания:

```sh
docker compose config --quiet
docker compose up -d --pull never --no-build
docker compose ps
```

`--pull never --no-build` Использует локальное изображение; если оно отсутствует, программа не работает, без попыток загрузки в интернете или сборки из исходного кода. При первом запуске создается текущая схема базы данных и директории для файлов/данных AI в пустом состоянии. `doca_data` Объем. Не требуется ручная установка SQL или базы данных. Существующая старая база данных не обновляется автоматически.

Подождите. `docker compose ps` для показа `healthy`Ручной контроль должен осуществляться с использованием Host. `.env`, включая любой нестандартный порт:

```sh
curl -fsS -H 'Host: docs.example.com' http://127.0.0.1:39120/health
```

Ожидайте `{"status":"ok","version":"0.3.1"}`Для внутреннего примера используйте `Host: doca.internal`Запросы типа “bare loopback” не проходят проверку хоста. Исследуйте ошибки запуска. `docker compose logs --tail=100 doca`.

## 5. Инициализировать администратора

После того как сервис работает нормально, запустите его в той же директории развертывания:

```sh
bash scripts/bootstrap-admin.sh
```

Введите логин, пароль длиной не менее 12 символов и подтвердите его; ввод пароля скрыт. Скрипт запускает один раз исполняемый контейнер с подготовленной изображением и той же постоянной томой. Аккаунт создается только в случае отсутствия администратора, а база данных хранит хеш пароля. Не предусмотрены стандартный логин или пароль. Откройте настроенное `DOCA_ORIGIN` и войти.

Чтобы сбросить пароль существующего администратора позже:

```sh
bash scripts/reset-admin-password.sh
```

Это не создает аккаунт. Если база данных заблокирована, выполните `docker compose stop`сбросить пароль, затем `docker compose up -d --pull never --no-build`.

## Сохраняйте данные и передавайте последующие версии.

Используйте `docker compose restart` Для обычных перезапусков. Сохраняйте директорию развёртывания и имя проекта Compose, чтобы все было одинаково. `doca_data` Используется объем диска; изменение любого из них может случайно вызвать создание отдельного пустого сайта. Сделайте резервную копию всех баз данных и файловых хранилищ в постоянном объеме диска, а также защищенных данных. `.env` и главный ключ. `docker compose down -v` Удаляет том, и его нельзя использовать для обычного перезапуска или обновления.

Проанализировать [требования к выпуску](releases/0.3.1.ru.md) Перед обновлением необходимо предоставить соответствующий пакет и изображение. Этот руководство инициализирует новые сайты и не конвертирует существующие данные. Вход по паролю и локальные сервисы документов не требуют доступа к GitHub; внешние сервисы для ИИ, внешний вход, установка плагинов или хранение в облаке должны все еще быть доступными. Проверьте отображение документов на целевом хосте отдельно: само состояние приложения не гарантирует корректность отображения PDF, Canvas и Office. Смотрите.
