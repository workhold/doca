# プラグインのドキュメント要素（SDK 0.1.6ソース）

2026-10-02に、ホストソース0.1.8、SDK 0.1.6、contracts 0.1.6、Web registry 0.1.3で実装されました。これはnpmの公開、生産環境でのインストール、またはネイティブデバイスでの受け入れではなく、ソースのエクスポートや孤立した受け入れを記録します。合意されたストレージポリシーは正確バージョンサポートです：不明なタイプやバージョンはエラーパラメータとして表示され、元のJSON形式が保持されます。アダプター、自動変換、マイグレーション、データリセットは導入されません。既存の内部ドキュメント参照リーダーは変更されません。

<a id="public-registration"></a>

## 公的登録

輸入 `PluginElementContribution`, `PluginElementPayload`, `createPluginElementPayload`, `pluginElementState`, `isPluginElementPayload` そして `validatePluginElementPayload` から `@smartdoca/plugin-sdk/editor-elements`返却可能 `elements` 通常インストールされているWebプラグインバンドルから。ホストは各貢献物を登録する。 `WebPluginRegistry.elements` 所有プラグイン名前空間の下で、バンドルと共にそれを削除する。重複したIDや有効でない宣言は登録を失敗し、バンドルの登録が元に戻される。

```ts
import type { PluginElementContribution } from "@smartdoca/plugin-sdk/editor-elements";

// Return this contribution from the injected Web plugin factory.
const element: PluginElementContribution = {
  id: "example.elements.countdown", pluginId: "example.elements",
  title: { zh: "倒计时", en: "Countdown" }, dataVersion: 1,
  formats: ["rich_text", "spreadsheet"],
  validate: data => typeof data.targetAt === "string" &&
    Number.isFinite(Date.parse(data.targetAt)),
  text: data => `Countdown: ${data.targetAt}`,
  renderEditor: context => /* injected React configuration form */ null,
  render: (payload, context) => /* injected React inline view */ null,
  renderCell: context => { /* draw within context.rect using context.canvas */ },
  refreshIntervalMs: 1000,
};
```

この宣言はエクスポートされたシグネチャを示しています。 [独立した例](../examples/plugin-elements/README.md) 作業フォーム、レンダーラー、インストールファイルが含まれます。プラグインはインジェクテッドホストReactを使用し、自身の依存関係をバンドルします。ホストソースパスをインポートしたり、グローバルエディターブリッジを使用したりしてはなりません。

すべての貢献には地域に根ざしたものが必要です `title`正の整数 `dataVersion`少なくとも1つのサポートされるフォーマット `validate`, `text` そして `renderEditor`. `rich_text` 必要とされる `render`; `spreadsheet` 必要とされる `renderCell`. オプション `onCellClick` ペイロードとパブリックコンテキストを受け取る。オプション `refreshIntervalMs` 1000から60000の間の整数であり、キャンバスビューのみを更新する。

文脈には含まれている `documentId`, `format`, `locale` (`zh` または `en`), `readOnly` そして、一つ `AbortSignal`フォームコンテキストはさらにクローンを提供する `initialData` またはnull、 `submit(data)` そして `cancel()`キャンバスコンテキストはクローンを提供します `payload`キャンバスとクリップされたセル矩形です。設定はホストを通じて送信され、プラグインは変更可能なエディターハンドル、プライベートランタイム、または独立した永続性チャネルを受け取りません。レンダリングエラーは局所的なプレースホルダを生成します。プラグインは自身のイベント/非同期失敗を処理し、シグナルが中止されると作業をキャンセルします。

<a id="stored-content"></a>

## 保存されたコンテンツ

```json
{
  "version": 1,
  "pluginId": "example.elements",
  "type": "example.elements.countdown",
  "dataVersion": 1,
  "data": { "label": "Launch", "targetAt": "2026-10-04T00:00:00.000Z" },
  "text": "Launch · 2026-10-04T00:00:00.000Z"
}
```

`version` それは封筒版です。 `dataVersion` それは、貢献内容の正確なデータバージョンです。 `data` シンプルなJSON構成が含まれています。 `text` テキストベースのユーザー向けの制限された静的プロジェクションです。レンダリング関数、認証情報、一時的なURL、タイマー値、タイマーなどは保存しないでください。不透明なペイロードは、最大32KiBのUTF-8形式で、深さ20、4096ノードのシンプルなJSONオブジェクトでなければなりません。安全でないプロトタイプキーや有限でない/JSONではない値は、保存前に拒否されます。

現在のエンベロープ認識器は、宣言されている6つのフィールドのみを受け付けます。構造的に有効でない未知のエンベロープ、インストール/無効化されたプロバイダ、未知のタイプ、サポートされていないフォーマット、または一致しないバージョンは、サポートされていないプレースホルダを生成します。現在のプロバイダが設定を拒否すると、無効なプレースホルダが生成されます。どちらの状況もデータを書き換えたり削除したりしません。ホストは一致しないプロバイダのレンダラーや設定エディターを呼び出しません。ユーザーはネイティブ編集と元に戻す機能を利用して、サポートされていない要素を明示的に削除できます。正確なプロバイダを再有効にすると、保持された設定が再表示されます。

<a id="native-editor-integration"></a>

## ネイティブエディターの統合

- リッチテキストは、1つの永続的なホスト原子インライン拡張を使用します。 `custom:plugin-element`そして、共有されるコーデックもあります。このコーデックは、ビジネスプラグインがインストールされていなくても、不透明なペイロード全体を保存します。挿入機能ではライブSlate範囲をキャプチャし、編集機能ではIDによってノードを特定します。挿入/設定/削除はネイティブ操作とネイティブundoを使用します。このリリースではインラインアトムをサポートしていますが、任意のブロックレイアウトはエクスポートされません。
- スプレッドシートは公開されています `cellRenderers` キャンバス拡張機能 `custom.docaElement` ネイティブで `ICellData`。細胞の `v` これは静的テキストプロジェクションです。挿入/設定コミットでは現在のセルスタイルが保持され、ネイティブテキストの折り返しがCLIPに設定されるため、プロジェクションが隣接するセルを超えないようになります。挿入操作では、ダイアログで明示的に示されるように、選択中の全体のセルの値/数式/リッチテキスト/カスタムデータが置き換えられます。セルテキスト内には浮動オブジェクトやインライン位置はありません。フォームが開いた状態で行/列の編集が行われると、安定した単一セルのアンカーが保持されます。削除されたり同時に変更されたターゲットは送信に失敗します。ネイティブ範囲コマンドではコピー、削除、元に戻し、共同編集が可能です。
- ダイアログを閉じたり、エディターのコンテキストを変更したり、編集モードを離れたりするとセッションがキャンセルされます。送信時には、アクティブなプロバイダー、ハンドル、読み取り不可状態、ターゲットが再確認されます。レンダリング/レジストリの変更は文書エディターを再マウントすることはありません。プラグインビューを更新しても文書の書き込みは行われません。

既存のRich Schema 3とスプレッドシート Schema 6は、ネイティブなチェックポイントと信頼性の高い共同編集機能を保持しています。要素内容に関しては、第二のJSON自動保存、トランスポート、Yjs再再生機能、ビジネスプラグインデータベースは存在しません。ネイティブなチェックポイントと同じモデルのクリップボードはペイロードを保持しますが、既存のテキスト/Markdown/Office変換の制限は依然として適用されます。Rich Atomic Exportは、既存の変換警告のもとでラベルに低下し、スプレッドシートの利用者はセルの静的値を読むことができます。純粋なテキストのエクスポートは無損失のプラグイン要素バックアップではありません。

<a id="lifecycle-installation-and-rollback"></a>

## ライフサイクル、インストール、ロールバック

デフォルトではエレメントプロバイダーはインストールされていません。プラグインは既存のインストールディレクトリやZIPメカニズムを通じてのみ発見できます。現在の例のマニフェストではSDKが必要です。 `^0.1.7`独立した生産使用前に、このインクリメントを含むSDKとホストを公開/インストールする。そのサーバー工場は業務データを所有しておらず、アンインストールによって文書内容が削除されることはない。

プラグインの無効化/アンインストールは、保持されていない要素ではなくレンダラーを登録解除します。完全に一致するプロバイダを再インストールする際には、データ変換は不要です。永続的なネイティブコーデックを持たない古いホストへのリロードは、これらの文書の編集にはサポートされていません。データベース/チェックポイントのバックアップを保持し、それらにアクセスするには実装ホストを使用してください。ダウングレードリワークや破壊的なクリーンアップは提供されていません。

## 受け入れ

孤立したテストについて `tests/plugin-editor-elements.test.ts` レジストリの所有権/処分/ロールバック、厳格なバージョンとJSON制限、豊富な原子的なクリップボード/削除/元に戻し機能、不透明なCRDTのラウンドトリップ、ネイティブな永続性/ACK再送信/二レプリカのノーリーコー動作、スプレッドシートの安定したアンカー/行挿入/コピー/削除/元に戻し/リロード/収束、読み取り専用の認可と原子的な巨大ペイロード拒否。これらは孤立したデータベースと文書を作成する。SDK検証スクリプトは、ホストパスなしのパックスタイルの独立したJavaScriptおよびNodeNext宣言消費者もチェックする。

ブラウザの受け入れには、独立したデータベースと一時的なインストールによる独立したカウントダウン/ニュース例が使用される。実際のネイティブコンテナやサードパーティのプラグインには、それぞれ独自の受け入れが必要である。一般的なブロック要素、クロスフォーマットの無損失エクスポート、公開された任意のエディター変更コマンドは、今後の課題である。

検証されたブラウザ操作には、豊富な挿入/設定/元に戻す/再実行/再読み込み/読み取り専用機能、シートの設定/挿入/元に戻す/再実行/再読み込み、および削除のみを可能にする設定を持つ未知のタイプのプレースホルダが含まれます。保存後および再読み込み後にシートプロジェクションクリップがチェックされました。最終的な総合検証結果：TypeScriptは通過し、171のテストファイルが通過しました（1,066テストのうち3つがスキップされました）；SDKのビルドおよび独立した使用も通過しました；Webのプロダクションビルドおよび空白文字のチェックも通過しました。

## 性能承認（2026-10-02）

実行する `node --import tsx scripts/benchmark-plugin-elements.mts`Node 24.15.0を使用したこのmacOS arm64マシンで、1,000件の通常段落の平均ネイティブプロジェクションは、2つのオリジナルインラインコーデックで0.513 ms、要素コーデックを追加した場合は0.515 msでした。対応する中央値の差は測定ノイズの範囲内でした。10,000個の占有中の通常セルに対する追加のスパース要素チェックは0.039 msのコストがかかり、100個の設定された要素がある場合は0.111 msのコストがかかりました。100個のカウントダウンペイロードの最初の検証は0.188 msのコストがかかり、100個の例のキャンバスコールバックのクローン化と呼び出しは0.101 msのコストがかかりました。このコールバックベンチマークはモックキャンバスを使用しており、ネイティブペインティングを測定していません。

通常のセルはカスタムプロパティをチェックした後に退出する。リッチな検証はメモ化され、キャンバスの検証はペイロード/プロバイダごとにキャッシュされ、レジストリの変更時に無効化される。単一のコアライズドビュータイマーは、視覚的に見えるタイムドセルを描画することによってのみ再起動され、最小1秒間隔が適用される。隠されたページはそれをキャンセルする。視覚的に見えるタイムドセルがないシートには、定期的な更新タイマーは存在しない。スケジューラテストでは、ゼロのアイドルタイマー、100要素のコアライズ、ビューポートの離脱、隠し、処分が対象となる。ブラウザが60秒以上アイドル状態の文書を観察した結果、新しいコンテンツのシーケンス/履歴は見られず、タイマーは永続化のアウトボックスに入ることはない。

これらの測定結果によると、テストされたケースにおいては、ホストCPUの負荷増加はほとんどない。任意のサードパーティによるレンダリング、外部データの取得、大量の可視要素の数、またはすべてのデバイスに対しては、コストがゼロになるとは限らない。実際の提供業者は、自身のレンダリング/非同期作業量を確認する必要がある。
