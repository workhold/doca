# 플랫폼 서비스 자격 증명

[中文](service-credentials.zh-CN.md)

관리자 메뉴 → 플랫폼 설정 → 서비스 자격 증명을 열어보세요. 현재 호스트가 관리하는 플랫폼 기록에는 다음이 포함됩니다:

- 식별 정보: SSO 클라이언트 시크릿 및 허용된 HTTP(S) 원본을 지정합니다. 식별 제공자는 자격 증명 이름을 의미합니다.
- 인증 게이트웨이: HTTP(S) 엔드포인트, 베이어 시크릿, 그리고 전화/이메일 채널.
- 문서 검색: Meilisearch API 키 및 허용된 출처.

파일 서버 자격 정보와 CloudFront 서명 키는 설정되지 않았습니다. `DOCA_FILE_STORES_JSON`저장 관리 페이지는 읽기 전용입니다. 이 플랫폼 레코드에서는 수정할 수 없습니다. [플러그인 자격 정보](plugin-credentials.ko.md) 별도의 서버 전용 암호화 서비스와 그 배포 마스터 키를 사용하세요.

<a id="persistence-and-configuration-precedence"></a>

## 지속성과 설정 우선순위

플랫폼 설정은 아래에 저장됩니다. `account_settings`, ID `service-credentials`기존 코드는 이 레코드가 없을 때만 런타임 환경의 정체성/메시징 설정을 시드합니다. 이후 저장된 레코드가 우선됩니다. 환경 변수를 변경해도 저장된 설정은 덮어쓰지 않습니다. 이는 기존의 초기화 경로로, 새로운 어댑터나 마이그레이션 없이 여기에 유지되고 문서화되어 있습니다. 퇴역된 저장 형태를 포함한 저장된 레코드는 현재 호스트에 의해 명시적으로 거부됩니다.

데이터베이스 연결, 사이트 원본, 들리는 포트, 파일 저장소는 여전히 시작 설정에 남아 있습니다. 영구 저장된 설정이 읽히려면 데이터베이스가 연결되어 있어야 합니다. 첫 번째 관리자는 여전히 명시적인 bootstrap 명령을 사용합니다.

<a id="api-and-secret-handling"></a>

## API 및 비밀 정보 처리

`GET` / `PUT /api/v1/admin/service-credentials` 시스템 관리자가 필요합니다. 변경 사항은 Origin을 검증합니다. GET 요청에서는 설정된 비밀번호가 null로 대체됩니다. PUT 요청에서는 null이 기존 비밀번호를 유지하고 빈 문자열이 그 비밀번호를 지웁니다. 가짜 마스킹 문자열을 전송하지 마세요. 수정 검사 기능은 동시에 덮어쓰기를 방지합니다. 감사 정보는 비밀번호 값이 아닌 작업 자체를 저장합니다; 엔드포인트 프로토콜, Origin, 리디렉션 제한은 그대로 유지됩니다.

서버는 사용 가능한 제3자 자격 증명을 보관합니다. 데이터베이스와 백업을 중요한 설정으로 취급하세요. 저장된 비밀 정보는 일반 사용자, 공개 부트스트랩, 오류 로그 또는 관리자 GET 응답으로 반환되지 않습니다. 플러그인 자격 증명 암호화는 이러한 플랫폼 설정을 자동으로 다시 암호화하지 않습니다.

모든 서비스 프로세스는 API 요청 전에 설정 개정 사항을 확인하고, 변경 후 재시작하지 않고 어댑터를 갱신합니다. 인증 비밀을 바꾸면 대기 중인 인증 문제가 무효화됩니다. 스토리지 자격 증명 변경은 배포에 의해 처리됩니다. [저장 규칙](storage.ko.md)안정적인 저장 ID와 참조되는 바이트의 보존을 포함합니다.
