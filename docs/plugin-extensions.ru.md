# Публичное чтение и расширения интерфейса

[中文](plugin-extensions.zh-CN.md)

Этот руководитель охватывает сервисы для публичного чтения, а также повторно используемые веб-команды, виды и размещения. Оригинальные добавления для чтения/UI были включены в исходный код SDK. `0.1.4`; элементы документа введены `0.1.6`Для текущего хоста используйте SDK. `0.1.9` и объявить соответствие `sdkRange` такое, как `^0.1.9`Проверьте установленный хост и созданные артефакты SDK перед использованием API; источник реализации не подтверждает, что артефакт npm или процесс развертывания были обновлены.

<a id="public-services"></a>

## Государственные услуги

| Сервис / экспорт | Методы | Цель и границы |
| --- | --- | --- |
| `users.v1` / `@smartdoca/plugin-sdk/platform` | `me`, `searchPage`, `resolveDirectory`, `validateSelection` | Администратор Honor имеет право перекрывать политики директорий “нет/все/связанные”; поиск раскрывает проекции публичного отображения; чтение самопрофилов — отдельно. |
| `permissions.v1` | `registerDirectory` | Внутренние модули и плагины общаются между собой `DirectorySource`Только режим, связанный с источниками, проверяет кандидатов и объединяет идентификаторы пользователей. |
| `documents.read.v1` / `@smartdoca/plugin-sdk/documents` | `get`, `readSnapshot`, `capabilities`, `references` | Метаданные документа, полный сохраненный нативный контент, текущие возможности и ссылки; отдельно от внутренней службы сотрудничества `documents.v1` |
| `libraries.v1` / `@smartdoca/plugin-sdk/documents` | `list`, `children`, `path` | Доступные библиотеки, страницы с пагинацией для детей, а также разрешенные пути к предкам; контент требует отдельного разрешения |
| `files.v1` / `@smartdoca/plugin-sdk/files` | folders/files/uploads/bindings/content/receipts | Структура папок, информация о файлах, разрешенные потоки, связи с прикреплениями, загрузки и квитанции |
| `content.v1` / `@smartdoca/plugin-sdk/content` | `list`, `read`, `resolve`, `search` | Получение и анализ контента, а также использование знаний; не заменяет структуру оригинальных документов |

Токены — `usersServiceToken`, `permissionsServiceToken`, `documentReadServiceToken`, `librariesServiceToken`, `filesServiceToken`и `contentServiceToken`Объявить требования к серверу. `injections.required` и получать реализации через `context.inject(token)`Регистрируйте директорию только при внесении источника отношений. Идентификаторы источников должны принадлежать пространству имен плагинов. Система жизненного цикла отвечает за регистрацию; её диспозер освобождает вклады во время выполнения только.

`DirectorySource` Сохраняется schemaVersion 1 и связанный/проверяемый протокол. Встроенные документы и общие папки также регистрируют источники. Поиск не возвращает никаких кандидатов; используйте `me` Чтение самостоятельно. Все запросы выполняются через активные аккаунты сайта без необходимости обращения к источникам. Связанные агрегаты выполняют активные источники параллельно, проверяют кандидатов и фильтруют статус аккаунта. Кандидаты из источника отклоняются из-за ошибок, повторяющихся курсоров, превышения бюджета или отсутствия регистрации во время выполнения. Пагинационные результаты указывают на частичную неработоспособность источника. `complete: false`У каждого источника есть бюджет в 2 секунды, максимум 40 страниц и максимум 250 кандидатов на странице.

`searchPage({query,cursor?,limit?})` возвращает `{items,nextCursor,complete}`Ограничение составляет от 1 до 100, по умолчанию 20. Курсоры связывают вызывающего процесса, запрос и эффективный режим каталога; каждая страница требует перезапуска. Изменение политики во время пагинации приводит к ответу 409: необходимо начать процесс с первой страницы. `resolveDirectory({ids})` и `validateSelection({ids})` Можно принять не более 100 идентификаторов и снова проверить текущую директорию. Найдение аккаунта не предоставляет права на совместное использование, передачу или управление бизнес-ресурсами. Уже существующие `search` Все равно возвращает массив не более 20 элементов; только доверенный сервер. `list` не подвергается воздействию браузеров.

`readSnapshot({documentId,expectedRevision?})` возвращает `{documentId,format,codec,schemaVersion,revision,epochId,seq,content,assets}`Поддерживаемые форматы: форматированный текст, markdown, электронная таблица, холст и презентация. Контент — это родной формат редактора (строка для Markdown), а не резюме или обновление Yjs. Редакция — это непрозрачный идентификатор контента, включающий реальный контент, кодеки/схемы и факты epoch/seq; он отличается от метаданных версии. Несоответствие ожидаемой редакции возвращает 409. Сохраненный форматированный текст без epoch совместной работы возвращает `epochId: null` Без создания новой эпохи. Недостающий состояние сохраненного объекта возвращает 409 без инициализации. JSON-объект размером более 16 МБ возвращает 413.

Согласованная транзакция восстанавливает сохраненное содержимое без смешивания незаполненных изменений редактора или ввода содержимого, истории или ACK. Ассеты раскрывают только текущие разрешенные стабильные файлId/имя/mime, исключая ключи хранения, физические пути и сохраненные временные URL. Предметные возможности описывают текущие разрешения ресурсов и поддержку снимков; это не подразумевает обслуживание публичного документ-пишевого сервиса.

Список библиотеки/возврат детских книг `{items,nextCursor}`используя текущие 100 страниц хоста. Дети принимают `{libraryId,parentId,cursor?}` с родительским ID null в корне; путь принимает `{resourceId}`Открытие и просмотр являются разными: видимое название может иметь значение role=none, в то время как доступ к содержимому запрещен. Каждая страница снова проверяет доступ, и не представляет собой замерзший список. Неразвязанный проход не может подтвердить, что содержимое было удалено.

<a id="browser-and-app-webview"></a>

## Браузер и приложение WebView

`PluginWebHost.platform` Предоставляет типизированных клиентов для этих приложений:

```js
const page = await host.platform.users.searchPage({ query: "张", limit: 20 });
const self = await host.platform.users.me();
const snapshot = await host.platform.documents.readSnapshot(
  { documentId }, { signal: context.signal },
);
const children = await host.platform.libraries.children({ libraryId, parentId: null });
const folders = await host.platform.files.folders.list({ parentId: null });
```

У пользователя есть клиент, включающий me/searchPage/resolveDirectory/validateSelection; документы и библиотеки предоставляют все вышеупомянутые возможности чтения; файлы предоставляют методы folders.get/list и files.get/list. Запись файлов, потоки содержимого и скачивание приложений используют сервер. `files.v1` Или существующие возможности прикрепления; потоки не являются JSON.

Аутентифицированные звонки используют `POST /api/v1/plugin-platform/{pluginId}/{operation}`Принимаются только операции, выполняемые в пространствах имён installed-plugin и явно указанные. Ввода не может содержать principal, режим или произвольное имя сервиса. Ответы не хранятся в кэше. `host.request` остается ограниченным плагином `/api/v1/plugins/{pluginId}/` API.

Мобильные плагины используют сессии WebView, выданные хостом, ограниченные одним плагином. Публичные вызовы должны оставаться в рамках этого пространства имен; сервер все равно проверяет права текущего пользователя и ресурсов. Плагины не получают нативный токен. Изолированные тесты охватывают границы HTTP-сессии. Эти размещения карт и документов являются реализациями веб-интерфейса; нативные мобильные размещения еще не реализованы или не приняты на устройствах.

<a id="commands-views-and-placements"></a>

## Команды, виды и расположения

Рендеры маршрутов веб-страниц получают данные, принадлежащие хосту. `PageHeader` компонент в их
контекст маршрута. Отрисовка `<context.PageHeader title={title} actions={actions} />`
Разместить контент React в верхнюю панель рабочего пространства рядом с глобальными управляющими элементами.
Хост владеет целевыми устройствами монтирования и удаляет содержимое порталов, когда страница
удаляет. Плагины не должны запрашивать Selectors DOM хоста или импортировать источник хоста. Используйте
Внутристроковый заголовок в мобильном плагине, у которого нет верхней панели рабочего пространства.
Для этого записи необходим хост источника в текущем состоянии; нет адаптера для старого хоста.

`WebPluginBundle` Включает три опциональные коллекции:

- Команды: перекрываемые действия с id/pluginId/title/supportedContexts/execute.
- Просмотры: перезапускаемые просмотры с id/pluginId/title/supportedContexts/render.
- Расположения: записи размещения с id/pluginId/slot/order?/conditions?, ссылкающиеся на ровно одну commandId или viewId. Вид может указывать на представление диалога/drawer/sidebar; в противном случае он отображается в месте размещения.

Названия используются `{zh,en}`ID принадлежат пространству имен плагинов. supportedContexts — это глобальное имя: home/document/library/folder/resources. conditions — фильтры целевых объектов, типы ресурсов, форматы и возможности. Поддержка и видимость — это правила отображения, отдельные от авторизации сервера. Дублирующиеся ID, некорректные места, отсутствующие ссылки и ссылки между плагинами отклоняют весь пакет и аннулируют зарегистрированные вклады.

Элементы команд/просмотра, содержащие только иконки, используют тот же PNG-брендинг, что и настроенный магазин плагинов. Хост предоставляет их через аутентификацию. `GET /api/v1/plugin-icons/<id>` Для запуска установок через store/npm с веб-ресурсами; локальные установки сохраняют общий иконку. Детали магазина проверяются с существующим протоколом магазина, запросы на тот же плагин имеют ожидающий чтение, а успехи/неудачи/неудачи сохраняются только в памяти хоста в течение 60 секунд. Во время загрузки, если иконки магазина отсутствуют или изображение не может быть загружено, запись сохраняет свою общую иконку и остается используемой. Существующие пакеты плагинов, версии SDK и сохраненные данные не меняются; не требуется никакого объявления иконки, конвертации или миграции. Восстановление этого изменения на хосте возвращает предыдущее отображение.

| Реализован веб-слот | Контекст |
| --- | --- |
| global.more | Глобальные действия имеют иконку приложения в верхнем правом углу вместе с навигацией web.more; записи действий/просмотра используют иконки с подписями при наведении; скрываются, когда оба фильтрованных наборы пусты. |
| global.leftMore | Глобальные действия используют тот же список выпадающих значений, что и на странице web.leftMore; скрываются, когда оба фильтрованных наборы пусты. |
| home.cards / home.actions | Карты дома и скорости |
| document.toolbar / document.menu | Идентификатор документа, формат и текущие разрешения; одно и то же действие может выполняться как в обоих случаях. |
| document.sidebar / document.status | Боковая панель и контент информации о статусе; на узких экранах боковая панель располагается вдоль текста документа |
| library.toolbar / library.nodeMenu | Элементы библиотеки и узлы каталога |
| файл.toolbar / файл.rowMenu | Актуальный папка или строка ресурса |
| resource.bulkActions / resource.details | Непустая seleция и расширения для деталей документа |

Контекст включает область/цель/локальность/ресурс?/ресурсы?/возможности/signal, без автоматического предоставления содержимого или полного директория пользователей. Хост предоставляет возможности чтения/комментирования/редактирования/управления отображением ресурсов. Местоположение файлов еще не имеет единой проекции возможностей; отсутствие такой проекции не определяет разрешения на доступ.

Этикетки управления навигацией `web.more` В верхнем правом углу: Дополнительно и `web.leftMore` Как указано выше. Администраторы могут разместить страницу плагина слева только после того, как на сервере разрешена навигация по разделу allowedSlots. `web.leftMore`Встроенные записи пользователей поддерживают оба варианта. `global.leftMore` Это отдельный опциональный клиентский командный/видовой слот, поддерживающий глобальный контекст. Виды без представления расширяются в меню.

Существующие правила, утвержденные 2026-10-02, остаются в силе `web.more` и `global.more` В верхнем правом углу. Существующая конфигурация не мигрируется, а существующие плагины не автоматически занимают левые места. Поле "More" требует явного объявления/конфигурации и не получает автоматического переполнения. Одно поле может явно занимать оба места "More"; другие правила дедупликации/переполнения остаются в силе. Хранилище навигации использует параметр schemaVersion=1. Перед возвратом к хосту без поддержки левых слотов удалите и опубликуйте всю конфигурацию web.leftMore: более старый строгий валидатор не может его конвертировать. Также отмените новые объявления слотов клиента/сервера или откатите плагин.

Этот пример браузера ESM не использует пути источников хоста:

```js
export default host => {
  const pluginId = "example.tools";
  const viewId = "example.tools.preview";
  return {
    manifest: { pluginId, version: "1.0.0", targets: ["web"] },
    views: [{
      id: viewId, pluginId,
      title: { zh: "预览", en: "Preview" }, supportedContexts: ["document"],
      render(context) {
        return host.React.createElement("p", null, context.resource.title);
      },
    }],
    commands: [{
      id: "example.tools.open", pluginId,
      title: { zh: "预览", en: "Preview" }, supportedContexts: ["document"],
      execute(context) {
        host.ui.openView({ viewId, presentation: "dialog", context });
      },
    }],
    placements: ["document.toolbar", "document.menu"].map((slot, index) => ({
      id: `example.tools.placement${index}`, pluginId, slot,
      commandId: "example.tools.open",
    })),
  };
};
```

Просмотры используют экземпляр React-хоста и собирают свои зависимости; хост не решает базовые импорты npm в ESM плагинах. Ошибки в компонентах-дочерних элементах изолированы, обещания команд, отклоненные, показывают обратную связь, а кнопки выполнения отключены. Хендлеры событий, созданные плагинами, и асинхронная работа должны самостоятельно обрабатывать ошибки и отмену.

Команда/сигнал видимости в месте размещения отменяется при изменении контекста или при отсоединении компонента. Открытие диалогового окна переносит контекст в собственную сессию панели, поэтому закрытие вызвавшего его меню не уничтожает её. Закрытие панели, изменение маршрута или открытие другой панели отменяют эту сессию. Старый кнопка закрытия не может закрыть новую панель. Эти операции с ресурсами не предполагают наличия управляющего элемента выбора или контракта записи несохраненной модели.

<a id="capability-boundaries"></a>

## Границы возможностей

Позиции выбора/блокировки/вставки, команды для изменения документа, публичные комментарии/история, приглашения к обмену, публичное выполнение ИИ, область действия полей событий и вклады по темам требуют своих контрактов и реализации. Эта расширение чтения/UI не предоставляет произвольных глобальных изменений CSS/DOM или вводит постоянство разметки, миграции базы данных или конвертацию хранимого формата.

Шаблоны и материалы теперь имеют отдельное разделение [Контракт на создание ресурсов](creation-resources.ru.md)Он использует публичные пакеты, строковые токены, пространства имён плагинов, процессы жизненного цикла и распорядители, аутентифицированный контекст и типизированных клиентов. Он не превращает существующую таблицу document_templates в провайдер. files.v1 и content.v1 сохраняют свою сущность.

<a id="verification-record"></a>

## Запись проверки

Оригинальные изолированные проверки охватывают агрегацию директорий/отключение регистрации/изменения политик, нативные модели и ревизии для всех пяти форматов, разрешенную пагинацию после отклоненных кандидатов, перемещение, откат регистрации, отмену панели и устаревшие управляющие объекты, список разрешений HTTP и отклонение мобильных сессий между плугинами.

`pnpm build:plugin-sdk` Создает релизные артефакты. `node scripts/verify-plugin-sdk.mjs` Копирует артефакты в временные независимые node_modules, выполняет JavaScript и проверяет .d.ts в проекте NodeNext без отображения путей хоста. Он не публикует пакеты npm и не устанавливает в директории пользователей для плагинов.

Изолированный пример был проверен в браузере для карт дома, меню/настройки документа в правом верхнем углу, боковой панели рабочего стола и диалоговых окон с снимками. Два личных плагина и физические мобильные устройства требуют отдельного одобрения. Записанная запись от 2026-10-02 прошла проверку типов, 162 тестовых файла (1021 прошли, 3 пропущены), сборка SDK/независимое использование, сборка Web и проверку пробелов. Это исторические результаты, а не проверки, выполняемые повторно при просмотре этой страницы.

<a id="document-plugin-elements"></a>

## Элементы документа плагинов

Источник SDK `0.1.6` Введен опциональный веб-бандл `elements` и `@smartdoca/plugin-sdk/editor-elements`Он поддерживает атомарные элементы внутреннего форматирования, отображение электронной таблицы целого ядра, а также формы конфигурации. Хост принимает конфигурацию через нативные команды и функцию отмены; плагинам не предоставляются неограниченные управляющие объекты редактора. Неизвестные типы/версии показывают место для ошибки, при этом оригинальный JSON сохраняется без конвертации, миграции или очистки. Ни один провайдер не установлен по умолчанию.
