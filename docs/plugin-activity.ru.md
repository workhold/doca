# Недавняя активность плагина

[中文](plugin-activity.zh-CN.md)

Реализовано 30.09.2026 и публично экспортировано. `@smartdoca/plugin-sdk/platform`Используйте артефакт SDK и хост, содержащий эту интерфейс. Само наличие исходного кода не обеспечивает новую публикацию в npm.

<a id="storage-and-ownership"></a>

## Хранение и владение

Плагины регистрируются через `activityServiceToken` (`activity.v1`Они владеют записями посещений, запросами по истории, текущими разрешениями на работу и процедурами удаления, используя управляемую хостом постоянность данных. Сервис только объединяет источники информации; он не создает никакого бизнес-монитора или специального узла для записи посещений. Используйте [Текущий контракт на управление хранилищем](plugin-horizontal-scaling.ru.md).

Встроенные записи остаются `resource_visits` и `workspace_activity`Это увеличение не изменило таблицу, не изменило историю и не привело к двойному записанию. Страница публичного открытия `/workspace/recent?publicOnly=true` Логика коллекции применяется к встроенным ресурсам. Регистрация активности не включает регистрацию обнаружения, фаворитов, поиска или ИИ.

Удаление снимает регистрации во время выполнения, а запуск/просмотр источника прекращается. Сохраненные записи остаются. Восстановление запросов к данным текущего плагина происходит при перезапуске хоста. Фактическая установка/отключение происходит в соответствии с жизненным циклом хоста.

<a id="registration"></a>

## Регистрация

```ts
import {
  activityServiceToken,
  permissionsServiceToken,
  type ActivitySource,
} from "@smartdoca/plugin-sdk/platform";
```

Объявить оба токена. `injections.required`Хозяин без… `activity.v1` Отклоняет плагин, который требуется; приватные таблицы или старые endpoints не являются заменой. Существующие плагины, которые не используют активность, не требуют новой регистрации. `register(source)` Возвращает диспозер; ограниченное внедрение связывает его с эффектами плагина и освобождает его при остановке или неудаче инициализации.

Регистрируйте одно источник на каждый тип контента, например `example.mail.messages` и `example.mail.threads`:

| Поле | Требования |
| --- | --- |
| `id` | Уникальный источник ID с префиксом плагин, максимум 150 символов |
| `pluginId` | Должно совпадать с идентификатором внедренного плагина |
| `schemaVersion` | Точно `1`Не поддерживаемые версии не могут пройти регистрацию |
| `resourceType` | Зарегистрировано в `permissions.v1`ID элементов определяют тип ресурса. |
| `title` | `en` и `zh`Максимум 100 символов на каждый фильтр/этикетку источника |
| `icon` | `file`, `mail`, `calendar`, `message`, `task`, `book`или `folder` |
| `list(context, input)` | Читабельная страница посещения текущего пользователя |
| `get(context, id)` | Текущий рекорд/название/путь с повторной авторизацией, или ноль |

Идентификаторы и типы ресурсов начинаются с маленькой буквы, а алфавитные и цифровые сегменты разделены точками или знаками дефиса. Каждый экземпляр позволяет не более 64 источников плагинов и отвергает дублирующиеся идентификаторы. Бизнес-ресурсы не ограничены, но должны быть отображены по страницам.

Контекст, созданный хостом, `{principalId, signal}`Основной пользователь приходит из авторизованной сессии, а не из пользователя, выбранного браузером. У элемента такой форма:

```ts
{
  id: "message-123",                  // 唯一资源 ID，1–500 个可见 ASCII 字符
  title: "季度预算讨论",              // 原始内容标题，非空，最长 500 字符
  visitedAt: "2026-09-30T09:20:00.000Z",
  path: "/mail/inbox?message=message-123"
}
```

`id` Содержит от 1 до 500 видимых символов ASCII; заголовок непустой и имеет не более 500 символов. `path` Начинается с символа slash, за которым следует буква/цифра; в этом строке нет символов-оригиналов, хэша, обратных слешов или управляющих символов. Внешние/протокол-относительные адреса запрещены. Необходимо кодировать значения запросов. Названия предприятий сохраняют свой оригинальный текст; названия типов используются… `title.en/zh`.

<a id="pagination"></a>

## Пагинация

`list` принимает `{until, after, limit}` и возвращается `{items, hasMore}`:

1. Возвращается один последний визит на каждого пользователя/источник/ресурс, отсортированный. `visitedAt DESC, id ASC` С порядком ASCII бинарного ID.
2. Используйте строки UTC ISO с миллисекундами, и только `visitedAt <= until`.
3. `after=null` Начинается. В противном случае требуется. `visitedAt < after.visitedAt`или равное время с `id > after.id`Граница остается используемой после удаления её записи.
4. `items.length <= limit`Хозяин в настоящее время запрашивает не более 51 записей. Допускаются короткие страницы. Оставшиеся записи требуют… `hasMore=true` И хотя бы один возвращенный элемент; пустые страницы не означают возможности повторной попытки.
5. Сначала фильтруйте посещения пользователей и текущие разрешения. Хост также проверяет. `activity.read` На каждом элементе можно получать больше, при необходимости. Максимум 20 партий, 1,5 секунды на каждый источник, включая проверку разрешений. Используйте индексы, соблюдайте правила отмены и избегайте полной синхронизации в режиме удаленного доступа внутри запросов.
6. Список никогда не обновляет количество посещений. Количество посещений отслеживается только после успешного открытия бизнес-контента. Звонки и неиспользованные кандидаты могут повторяться.

Ведущий объединяет страницы объемом 50 пунктов по убыванию времени посещения, по возрастанию идентификатора источника, а затем идентификатора ресурса. Встроенный источник `doca`, с `kind:id` Ключи ресурсов. Непрозрачные следующие указатели связывают пользователей/фильтры и сохраняют первый `until`Выбранные источники и потребленные позиции.

Список отражает текущие разрешения, а не статический снимок базы данных. Новые посещения появляются при обновлении; удаление, отмена или обновление времени посещения могут удалить записи из цепочки страниц. Используйте управляемые транзакции для последовательного чтения отдельных страниц.

Ошибка, таймаут, некорректный пагинация/путь или отсутствие прав — сервис отбрасывает весь страницу данного источника и сохраняет другие источники. Неудачные источники остаются пропущенными для последующих страниц такого прохождения и отображаются… `unavailableSources`; повторные попытки обновления. Новозарегистрированные источники также требуют обновления.

## Пример

Это `mount(context)` Пример требует реализации через плагин `mailStore`продолжал пользоваться услугами, управляемыми текущим хостом; `mailStore` Это не экспорт SDK.

```ts
const pluginId = "example.mail";

context.inject(permissionsServiceToken).register({
  pluginId,
  resourceType: "message",
  async authorize(principalId, messageId, action) {
    if (action !== "activity.read") return false;
    return mailStore.canRead(principalId, messageId);
  },
});

const source: ActivitySource = {
  id: `${pluginId}.messages`,
  pluginId,
  schemaVersion: 1,
  resourceType: "message",
  title: { en: "Mail", zh: "邮件" },
  icon: "mail",
  async list({ principalId, signal }, { until, after, limit }) {
    // 业务实现：按用户、当前权限、until、after 过滤，再依协议排序。
    // 可读取 limit + 1 条以判断 hasMore；只返回前 limit 条。
    return mailStore.listRecent(principalId, { until, after, limit, signal });
  },
  async get({ principalId, signal }, id) {
    // 必须确认这个用户有该访问记录，资源仍存在且当前仍可读。
    return mailStore.getRecent(principalId, id, { signal });
  },
};
context.inject(activityServiceToken).register(source);
```

Добавить `activity.read` Чтобы регистрировать право доступа уже существующего пользователя, а не регистрировать тот же тип плагина/ресурса дважды. После того как авторизованная API open-mail плагина успешно считает содержимое, необходимо обновить таблицу посещений с ID пользователя сессии. При удалении необходимо очистить эту таблицу или фильтровать удаленные записи с помощью соединений; хост не может очистить записи, которыми он не владеет.

<a id="host-entry-points-and-authorization"></a>

## Входные точки хоста и авторизация

- `GET /api/v1/workspace/activity`Аутентифицированный смешанный список; принимает встроенные элементы `kind`, плагин `source`и `cursor`. `kind` и `source` это взаимоисключающие. Возвращает `items`, `nextCursor`, `sources`, `unavailableSources`.
- Элементы плагина имеют `kind=plugin`, `sourceId`, `sourceTitle`и `icon`Клавиши UI включают идентификатор источника.
- `href` указывает на `/api/v1/workspace/activity/open?source=...&id=...`Хозяин снова проверяет аккаунт/источник/`activity.read`, призывает `get` Для текущего пути повторно разрешает доступ, затем перенаправляет. Ошибка — 404; он не перенаправляет с использованием исторического снимка.
- Целевые страницы и бизнес-API авторизуются независимо. Доступ к активности не предполагает прикрепления или доступа к связанным документам.

## Принятие и откат

`tests/plugin-activity.test.ts` и `tests/workspace-home.test.ts` Используйте изолированные базы данных/директории установки. Они обеспечивают обработку равнозначного порядка, транзит, продолжение работы с короткими страницами, удаление, доступ для разных пользователей, отмену доступа, отключение регистрации, ошибки/таймауты, небезопасные перенаправления, некорректные указатели, внедрение реальных пакетов и обработку HTTP-запросов.

Эта функция не вносит изменений в постоянные таблицы. История плагинов сохраняется при возврате хоста; плагин, требующий `activity.v1` Отказывается от хозяина, у которого его нет. Не удаляйте бизнес-данные для возврата к предыдущему состоянию.
